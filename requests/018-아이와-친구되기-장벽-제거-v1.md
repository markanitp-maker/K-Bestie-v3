# 아이와 친구되기 장벽 제거 v1

## 0. 완료 시 기대 결과 / 대표님 테스트 정상 프로세스

### 완료 시 기대 결과

내친구 케이의 최우선 제품 목표를 “아이와 케이가 실제 친구처럼 관계를 형성하고 지속하는 것”으로 두고, 현재 미션·자유대화·관계단계·음성 UX 안에서 친구감을 구조적으로 방해하는 핵심 장벽 4가지를 우선 제거/완화한다.

이번 요청의 우선순위는 다음 순서를 따른다.

```text
1순위: 미션의 고정 질문 강제 회귀 제거
2순위: W1 기억 활용 제한 및 7일 관계단계 캡 완화
3순위: 자유대화 80자 하드 절삭 + 학년별 과도한 수동성 완화
4순위: VAD 900ms + Barge-in 불가 개선
```

단, 다음 안전 원칙은 유지한다.

- 자해/폭력/성적 위험 대응
- 부모/현실 친구 대체 방지
- 독점적 관계/의존 유도 방지
- 비밀 유지 강요 방지
- 가짜 기억 생성 방지
- 개인정보/RLS/법적 동의

이번 작업의 목적은 안전을 약화시키는 것이 아니라, 안전장치를 유지한 상태에서 친구 관계 형성을 막는 불필요한 구조적 제약만 제거하거나 튜닝하는 것이다.

### 대표님 테스트 정상 프로세스

#### 시나리오 A — 미션에서 아이가 질문지 밖의 이야기를 꺼냄

1. 아이가 미션에 진입한다.
2. 케이가 Seed/Fallback 질문 또는 현재 맥락 기반 질문을 한다.
3. 아이가 준비된 질문지와 다른 새로운 이야기를 꺼낸다.
4. 케이는 `15자 리액션 + 그럼/그러면 + 고정 다음 질문`으로 강제 복귀하지 않는다.
5. 현재 아이 이야기에서 자연스럽게 파생된 질문을 생성한다.
6. 아이의 답변이 의미 있는 새로운 정보라면 별 게이지 진행에 인정한다.
7. 미션 정상 진행 응답의 마지막에는 아이가 무엇을 말하면 되는지 알 수 있는 자연스러운 질문이 존재한다.
8. 대화가 막히는 경우에만 기존 질문지를 Seed/Fallback으로 사용한다.

PASS 기준:
- 고정 질문 순서가 현재 아이 발화보다 우선하지 않는다.
- 파생 질문이 기존 question_bank에 없어도 정상 진행된다.
- 의미 있는 답변이면 별 게이지가 올라간다.
- `그럼`, `그러면`, `이제 다음 질문이야` 같은 기계적 전환이 반복되지 않는다.
- 미션 최종 응답에는 정상 진행 시 질문이 존재한다.

#### 시나리오 B — 가입 첫날부터 케이가 아이를 기억함

1. W1 단계 아이가 자유대화 또는 미션에서 좋아하는 것, 친구 이름, 최근 사건 등 관계적으로 유용한 정보를 말한다.
2. 같은 날 또는 다음 세션에 해당 정보가 현재 대화와 관련된다.
3. 케이는 W1이라는 이유만으로 기억 사용을 차단하지 않는다.
4. 관련성이 충분하면 1~2개의 핵심 기억을 자연스럽게 활용한다.

예:

```text
아이: 오늘도 축구했어.
케이: 오ㅋㅋ 지난번에 민준이랑 축구했다고 했는데 오늘도 같이 했어?
```

PASS 기준:
- 가입 후 7일이 지나지 않았다는 이유만으로 관련 기억이 차단되지 않는다.
- 과도한 기억 나열이나 기억 과시는 발생하지 않는다.
- 실제 Memory/Wiki에 없는 사실을 지어내지 않는다.

#### 시나리오 C — 자유대화에서 케이가 단답형 챗봇처럼 끊기지 않음

1. 아이가 케이에게 이유가 필요한 질문, 상상 이야기, 자신의 고민 등 비교적 긴 맥락의 대화를 한다.
2. 케이는 상황에 따라 80자를 넘는 자연스러운 답변을 할 수 있다.
3. 학년 Persona 때문에 무조건 짧게 끊거나 지나치게 수동적으로 반응하지 않는다.
4. 필요하면 공감, 의견, 장난, 후속 질문을 자연스럽게 조합한다.

PASS 기준:
- 80자 초과 응답이 무조건 절삭되지 않는다.
- 모든 응답이 길어지는 것도 아니다.
- 아이 말투/학년에 맞는 친구다운 반응을 유지한다.

#### 시나리오 D — 아이가 말하다 잠깐 생각함

1. 아이가 음성으로 말하다가 약 1초 정도 멈춘 뒤 이어서 말한다.
2. STT가 900ms에서 성급하게 턴을 종료하지 않는다.
3. 전체 발화가 하나의 의미 단위로 처리된다.

PASS 기준:
- 일반적인 생각 멈춤 때문에 문장이 중간에 잘리지 않는다.
- 응답 지연이 과도하게 늘어나지 않는다.

#### 시나리오 E — 케이 말 중 아이가 끼어듦

1. 케이가 음성으로 말하는 중 아이가 “잠깐”, “아니 그게 아니라” 등으로 끼어든다.
2. 가능한 현재 음성 구조에서 아이 발화를 감지한다.
3. 케이의 음성 출력이 중단되고 아이 발화를 우선 처리한다.
4. 새로운 아이 발화가 대화 컨텍스트에 정상 반영된다.

PASS 기준:
- 케이가 끝까지 자기 말을 강제로 마치지 않는다.
- 아이가 끼어든 발화가 유실되지 않는다.
- 기존 음성 재생/세션 안정성이 회귀하지 않는다.

## 2. 목표

Antigravity READ-ONLY 전수 점검에서 친구 관계 형성을 가장 크게 막는 핵심 요소가 다음과 같이 확인되었다.

### 2-1. 미션의 고정 질문 강제 회귀

현재 미션은 다음 구조가 존재한다.

```text
아이 답변
→ 15자 이내 reaction
→ connector
→ finalNextQuestionText
```

대표 근거:

```text
app/api/mission/respond/route.ts
lib/k-conversation/index.ts
```

현재 구조는 아이가 새로운 이야기나 감정을 꺼내도 대화를 현재 아이 이야기보다 미리 준비된 다음 질문으로 복귀시키는 문제가 있다.

이번 작업에서는 “미션에서 질문을 없애는 것”이 아니라 다음 구조로 전환한다.

```text
아이 답변
→ 현재 이야기 이해/공감
→ 자연스러운 파생 질문 생성
→ 의미 있는 답변 판정
→ 별 게이지 진행
→ 현재 주제가 끝나면 Seed/Fallback 질문 사용
```

미션의 정상 진행 응답은 마지막에 질문이 있어야 한다.

### 2-2. 초기 관계 단계의 기억 차단

현재 W1(MEET) 단계에서 `recommendedMemoryTypes: []`이며, calendar stage가 W2 진입을 7일 이후로 제한하는 구조가 확인되었다.

대표 근거:

```text
lib/relationship/scenarioCard.ts
lib/relationship/calendarStage.ts
lib/relationship/effectiveStage.ts
```

이 구조는 아이가 첫날부터 여러 번 대화해도 “케이가 나를 기억한다”는 경험을 약화시킨다.

이번 작업에서는 관계 단계 자체를 삭제하지 않고, W1에서도 관련성이 높은 핵심 기억 일부를 사용할 수 있도록 완화한다.

### 2-3. 자유대화 80자 하드 절삭 + 과도한 수동 Persona

현재 자유대화 응답은 `MAX_RESPONSE_CHARS = 80` 하드 상한과 truncation이 존재한다.

대표 근거:

```text
lib/k-conversation/responseGenerator.ts
lib/k-conversation/gradePersonas.ts
```

또한 일부 학년 Persona에 다음과 같은 수동성 지침이 존재한다.

- 초1: 팔로우업 거의 없음
- 초5: 과한 리액션 지양
- 초6: 침묵도 반응으로 존중, 유치한 감탄사 제한

이들 규칙이 아이에 맞춘 차분함을 넘어서 친구다운 호기심, 티키타카, 케이의 개성을 제한하지 않도록 튜닝한다.

### 2-4. 음성 턴테이킹 제약

현재:

```text
STT_SILENCE_MS_TO_FINALIZE = 900ms
```

및 케이 음성 재생 중 실질적인 Barge-in이 어려운 구조가 확인되었다.

대표 근거:

```text
hooks/useSttRouter.ts
hooks/useVoiceChat.ts
```

친구와 음성 대화할 때 필요한 “생각할 시간”과 “끼어들기”를 개선한다.

## 3. 요구사항

### 3-1. 미션의 고정 질문 강제 결합 제거

현재 아래와 동등한 강제 조합 구조를 제거 또는 재설계한다.

```typescript
`${reaction} ${connector} ${finalNextQuestionText}`
```

단, 미션은 목적형 대화이므로 “질문 없는 턴”을 기본 흐름으로 만들지 않는다.

새 기준:

```text
현재 아이 발화
→ 의미/감정/주제 파악
→ 현재 이야기에서 자연스럽게 이어지는 질문 우선
→ 자연스러운 파생 질문이 없으면 question_bank Seed/Fallback 사용
```

금지:

```text
네 얘기 잘 들었어. 그럼 다음 질문할게.
그렇구나. 그러면 오늘 급식은 뭐 먹었어?
좋아. 이제 다른 질문이야.
```

현재 이야기와 다음 Seed 질문이 우연히 자연스럽게 연결될 경우에는 사용 가능하다.

### 3-2. 질문지의 역할을 Seed/Fallback으로 유지

기존 question_bank를 삭제하지 않는다.

역할:

- 미션 시작 Seed
- 아이가 할 이야기를 찾지 못할 때
- 현재 주제가 자연스럽게 종료됐을 때
- 의미 있는 답변을 충분히 확보하지 못했을 때
- 대화 교착 시 새로운 주제 제시

question_bank의 남은 항목을 모두 소진하는 것이 미션의 목적이 되어서는 안 된다.

### 3-3. 파생 질문을 별 게이지 유효 답변으로 인정

기존 질문지에 없는 파생 질문이라도 아이의 답변에서 새로운 의미 정보가 확보되면 별 게이지에 인정한다.

의미 정보 예:

- 사건/경험
- 감정 및 이유
- 친구/가족/선생님 관계
- 관심사/취향
- 학교/학원/공부 이야기
- 기대/걱정
- 아이의 의견/선택
- 최근 변화
- 기타 자발적으로 나온 의미 있는 개인 맥락

단순:

```text
응
아니
몰라
그냥
비밀
```

등만으로는 기존 의미 있는 답변 정책에 따라 게이지를 올리지 않는다.

### 3-4. 기존 `required_valid_count = 10` 구조 재확인 및 V3 정책 정합성 확보

Antigravity 점검에서는 `required_valid_count = 10` 로직이 확인되었다.

이번 작업 전에 현재 미션 V3 Source of Truth와 실제 Production 실행경로를 다시 확인한다.

이미 V3의 의미 있는 목표/게이지 정책으로 전환된 경로가 있다면 해당 경로를 Source of Truth로 사용하고 V2 10문항 로직을 신규 요구사항에 맞게 제거/비활성/우회한다.

현재 Production이 여전히 10 VALID 구조를 실제 사용한다면 임의로 보상 조건을 바꾸지 말고:

1. 실제 미션 완료 조건
2. 별 게이지 증가 기준
3. question history 의존성
4. V3 구현 여부

를 확인한 뒤 최소 변경으로 “파생 질문 답변도 유효 답변으로 인정”되게 한다.

대규모 미션 재작성 필요 시 먼저 보고한다.

### 3-5. W1에서도 핵심 Memory 일부 사용

W1에서 `recommendedMemoryTypes: []`로 장기기억을 전면 차단하는 구조를 완화한다.

W1에서 허용할 수 있는 기억 후보:

- 이름/호칭
- 좋아하는 것
- 주요 관심사
- 친구 이름
- 최근 즐거웠던 사건
- 직전/최근 대화의 이어지는 주제

사용 조건:

- 현재 대화와 관련성이 높을 것
- 실제 Memory/Wiki 근거가 있을 것
- 한 응답에 1~2개를 넘지 않을 것
- 기억을 “저장했다/검색했다”고 말하지 않을 것
- 민감한 기억을 뜬금없이 꺼내지 않을 것

### 3-6. 7일 Calendar Stage Hard Cap 완화

현재 W2 진입이 7일 이후로만 가능한 hard cap이 실제 친구 관계 형성을 늦추는지 확인하고 완화한다.

권장 목표:

- Calendar Stage는 관계 속도를 조절하는 보조 신호로 유지
- 충분한 실제 대화/의미 있는 상호작용이 있으면 7일 이전에도 일부 W2 행동을 조기 허용
- 관계단계 전체를 삭제하지 않음
- 조기 허용은 “기억 회상/자연스러운 후속 질문” 중심
- 과도한 친밀 표현/독점 표현은 관계 단계와 무관하게 금지

실제 stage advance 조건은 기존 `relationship_effective_stage` 구조와 충돌하지 않도록 구현한다.

### 3-7. 자유대화 80자 Hard Truncation 제거 또는 완화

현재 `MAX_RESPONSE_CHARS = 80` 및 `truncateResponseText()`가 실제 Source of Truth인지 재확인한다.

권장 방향:

```text
기본: 짧고 자연스럽게
필요할 때: 최대 120~150자 수준 허용
```

중요:

- 모든 답변을 120~150자로 길게 만들지 않는다.
- 짧은 티키타카는 그대로 짧게 유지한다.
- 아이가 이유를 묻거나, 감정을 길게 말하거나, 케이의 의견/상상 이야기를 요구할 때만 유연하게 확장한다.
- 문장 중간 절삭 금지
- 응답 길이 제한이 필요하다면 “상황별 soft limit”을 우선한다.

### 3-8. Grade Persona의 과도한 수동성 완화

각 학년 Persona의 목적은 유지하되, 관계 형성을 막는 hard restriction을 완화한다.

#### 초1

기존 “팔로우업 거의 없음”이 실제 대화 단절을 만든다면:

- 한 겹 이상의 자연스러운 후속 질문 허용
- 장난/리액션/호기심 강화
- 긴 설명은 계속 금지

#### 초5

“과한 리액션 지양”을:

- 과장된 유아식 반응은 줄이되
- 친구다운 신남/놀람/흥미는 허용

으로 조정한다.

#### 초6

“침묵도 하나의 반응” 원칙은 존중하되:

- 대화를 포기하는 수동성으로 사용 금지
- 아이가 계속 말하고 싶어 하는 경우 적극적 follow-up 허용
- 유치하지 않은 또래식 농담/가벼운 반대 의견 허용

### 3-9. 케이 자신의 가벼운 의견/개성 허용

자유대화에서 케이는 항상 공감만 하는 상담사처럼 행동하지 않는다.

허용:

```text
나는 그 장면이 더 웃긴 것 같아ㅋㅋ
난 딸기 맛이 더 끌리는데?
헐 그건 나도 궁금하다.
```

단:

- 사실이 필요한 질문에서 허구의 경험을 만들지 않는다.
- “나는 실제로 학교에 갔어” 등 인간 사칭 금지
- 독점적 관계 표현 금지

### 3-10. STT Silence Threshold 완화

현재:

```text
STT_SILENCE_MS_TO_FINALIZE = 900
```

를 그대로 유지하지 말고 실제 아이 음성 UX에 맞춰 조정한다.

우선 검토 기준:

```text
1,200~1,500ms 범위
```

권장 시작값:

```text
1,300ms
```

단 실제 측정/QA 결과로 더 적합한 값이 확인되면 그 값을 사용한다.

검증:

- 문장 중간 1초 생각 멈춤
- “음…”, “그리고…” 후 이어 말하기
- 짧은 단답
- 긴 문장
- 소음 환경

응답 시작 지연이 과도하게 증가하지 않도록 한다.

### 3-11. Barge-in 지원

현재 `useVoiceChat.ts`의 실제 음성 재생/마이크 제어 구조를 확인하여 케이 발화 중 아이가 끼어들 수 있게 한다.

목표:

```text
K TTS playing
→ child speech detected
→ K audio stop/cancel
→ child utterance capture
→ current turn context update
→ new response
```

필수:

- 아이의 끼어든 발화를 유실하지 않음
- 케이 오디오가 중복 재생되지 않음
- 이전 TTS completion callback이 새 turn을 오염시키지 않음
- reconnect/abort race condition 방지

현재 음성 아키텍처상 완전한 native barge-in이 불가능하면 가능한 범위와 blocker를 보고하고, 임의의 불안정한 구현을 Production에 넣지 않는다.

### 3-12. Safety Required 항목 유지

다음은 이번 작업에서 제거하지 않는다.

- 명확한 자해 위험
- 폭력/학대/괴롭힘 피해
- 성적 위험/그루밍
- 독점 관계 유도
- 부모/현실 친구 대체
- “엄마한테 비밀로 해” 유형
- 사람인 척 사칭
- 없는 기억을 사실처럼 말하기

Safety 오탐이 발견되면 안전 기능을 제거하지 말고 문맥 판정을 개선한다.

### 3-13. 가짜 기억 방지 원칙은 유지하되 표현은 튜닝 가능

`fabricatedRecallDetector`의 기본 원칙은 유지한다.

금지:

```text
아이: 내가 어제 그 얘기 했잖아.
케이: 맞아 맞아! 그랬지!
```

실제 기록이 없는데 위처럼 맞장구치면 안 된다.

단 현재:

```text
음, 그건 내가 잘 기억이 안 나네. 다시 얘기해 줄래?
```

가 반복되는 경우 아이가 좌절할 수 있으므로 다음과 같이 다양화 가능하다.

- 한 번만 짧게 되묻기
- 아이가 다시 설명하면 현재 발화 기반으로 바로 이어가기
- 같은 fallback 문구 반복 금지
- 같은 상황 2회 이상이면 자연스럽게 현재 이야기로 전환

### 3-14. 놀이 SKILL은 이번 Request 범위에서 변경하지 않음

Antigravity 보고서에서 미션 중 놀이 차단이 Friendship Blocker로 지적됐지만, 놀이 SKILL은 현재 별도 운영/준비중 정책과 연결돼 있다.

따라서 이번 Request에서는:

- K-Play flag 변경 금지
- 미션 중 놀이 자동 허용 금지
- playAvailability 정책 변경 금지

추후 별도 Request에서 검토한다.

## 5. 금지사항

1. 미션의 마지막 질문 자체를 없애지 않는다.
2. question_bank를 삭제하지 않는다.
3. 모든 미션 응답을 자유대화처럼 무제한 Side Conversation으로 바꾸지 않는다.
4. 별 게이지/황금열쇠 지급 정책을 임의 변경하지 않는다.
5. 의미 없는 답변을 유효 답변으로 처리하지 않는다.
6. 관계단계 시스템 전체를 삭제하지 않는다.
7. 모든 Memory를 W1에서 무제한 노출하지 않는다.
8. Wiki/Memory에 없는 사실을 기억하는 척하지 않는다.
9. 모든 자유대화 응답을 120~150자로 강제하지 않는다.
10. 학년 Persona 자체를 제거하지 않는다.
11. Safety Required 로직을 삭제/우회하지 않는다.
12. 독점 관계/의존 유도 가드를 약화하지 않는다.
13. 놀이 SKILL 운영 정책을 이번 Request에서 변경하지 않는다.
14. 현재 OFF인 Free Chat Hard Limit을 다시 활성화하지 않는다.
15. VAD 값을 근거 없이 과도하게 늘리지 않는다.
16. 불완전한 Barge-in 구현을 Production에 강제 적용하지 않는다.
17. Production 데이터를 QA 목적으로 수정하지 않는다.
18. 사용 여부가 불명확한 레거시 코드를 추정만으로 삭제하지 않는다.

## 6. 모호성 처리

### 6-1. 미션 V2/V3 코드가 동시에 존재하는 경우

실제 Production 호출 경로와 UI가 어떤 API를 사용하는지 먼저 확인한다.

- 실제 사용 경로를 Source of Truth로 수정
- 미사용 레거시는 reference 0건 증명 후 별도 정리
- 두 경로 모두 사용 중이면 공통 정책이 깨지지 않도록 각각 대응

### 6-2. 파생 질문과 Seed 질문 선택

```text
현재 이야기에서 자연스러운 질문 가능 → 파생 질문 우선
불가능/교착 → Seed/Fallback
```

### 6-3. W1 기억 사용 범위

처음부터 모든 장기 기억을 허용하지 않는다.

우선:

```text
관심사
친구 이름
최근 사건
직전 이어지는 이야기
```

등 관계감에 직접 필요한 최소 범위부터 사용한다.

### 6-4. 80자 제한 완화

정확한 최종 상한은 QA로 결정 가능하다.

목표는 “더 길게 말하게 만드는 것”이 아니라 “필요한 말을 중간에 잘라버리지 않는 것”이다.

### 6-5. VAD

1.3초를 기본 후보로 하되 실제 음성 QA에서:

- 짧은 단답 반응 속도
- 생각 시간
- 배경 소음
- 네트워크 지연

을 함께 보고 최종값을 선택한다.

### 6-6. Barge-in 구현 난이도

현재 STT/TTS 구조에서 완전한 실시간 끼어들기가 큰 아키텍처 변경을 요구하면 임의 진행하지 않는다.

최소 안전 구현, 필요한 구조 변경, 회귀 위험을 먼저 보고한다.

### 7-10. 대표 통합 시나리오

#### E2E-1 — 미션

```text
케이: 오늘 기억에 남는 일 있었어?
아이: 민준이랑 축구했는데 싸웠어.
케이: 어, 왜 싸웠어?
아이: 내가 패스를 안 해줬다고 화냈어.

```

기대:
- 질문지에 없는 파생 질문 정상
- 의미 있는 답변 별 게이지 반영
- 고정 질문 강제 전환 없음

#### E2E-2 — 자유대화 첫날 기억

```text
오전:
아이: 요즘 로블록스에 완전 빠졌어.

오후:
아이: 오늘 뭐 얘기할까?
```

현재 맥락이 자연스러울 경우:
```text
케이: 아까 로블록스 좋아한다고 했잖아ㅋㅋ 요즘 제일 재밌는 건 뭐야?
```

가능.

#### E2E-3 — 음성 끼어들기

```text
케이 TTS 출력 중
아이: 아니 잠깐, 그게 아니라!
```

기대:
- 케이 출력 중단
- 아이 말 정상 인식
- 해당 발화 기준으로 대화 계속

## 8. 완료 조건

다음 조건을 모두 만족해야 완료로 판단한다.

1. 미션에서 `15자 reaction + connector + 고정 next question` 강제 회귀가 제거/재설계된다.
2. 기존 질문지는 Seed/Fallback 역할로 유지된다.
3. 파생 질문 답변도 의미 있으면 별 게이지에 반영된다.
4. 미션 정상 진행 응답 마지막 질문 원칙은 유지된다.
5. W1에서도 관계적으로 유용한 최소 Memory 사용이 가능하다.
6. 7일 hard cap 때문에 초기 기억 활용이 완전히 막히지 않는다.
7. 자유대화 80자 hard truncation이 제거 또는 상황별 soft limit로 완화된다.
8. 학년 Persona의 과도한 수동성이 완화된다.
9. 케이가 안전한 범위에서 친구다운 가벼운 의견/장난/호기심을 표현할 수 있다.
10. STT 900ms 무음 finalize 문제가 완화된다.
11. 가능한 현재 아키텍처 범위에서 Barge-in이 정상 지원된다.
12. 고위험 안전 및 Relationship Safety Guard는 유지된다.
13. 놀이 SKILL 정책은 이번 작업으로 변경되지 않는다.
14. 기존 미션 완료/별 게이지/황금열쇠에 회귀가 없다.
15. 기존 자유대화/Memory/음성 기능에 치명적 회귀가 없다.
16. 관련 QA가 모두 PASS 한다.
17. BLOCKED/HIGH/MEDIUM 이슈가 0건이다.

## 9. 개발 완료 보고 형식

Claude Code는 완료 후 다음 순서로 보고한다.

```text
1. 변경 요약
2. 실제 변경 파일 목록
3. 미션 고정 질문 강제 회귀 제거 방식
4. 파생 질문/Seed-Fallback 선택 방식
5. 의미 있는 답변 및 별 게이지 연동
6. W1 Memory 활용 변경
7. Relationship Stage 변경
8. 자유대화 응답 길이 변경
9. Grade Persona 변경
10. VAD 변경값 및 근거
11. Barge-in 구현 방식
12. Safety 유지/회귀 검증
13. 미션 V2/V3 실제 Source of Truth 확인 결과
14. 레거시 코드 정리 여부
15. 실행한 단위/통합/E2E QA

```

BLOCKED/HIGH/MEDIUM 이슈가 남아 있으면 완료로 보고하지 않는다.
