# 아이와 친구되기 장벽 제거 v2

## 0. 완료 시 기대 결과 / 대표님 테스트 정상 프로세스

### 완료 시 기대 결과

최근 1개월 Production 실제 아이 대화 전수조사에서 확인된 구조적 문제 중, 별도 긴급 핫픽스로 분리한 `“응, 듣고 있어. 더 얘기해줄래?”` LLM Fallback 장애를 제외한 나머지 핵심 문제를 개선한다.

이번 요청의 핵심 문제는 다음과 같다.

1. 미션의 `reaction + connector + 고정 질문` 강제 회귀
2. 동일/유사 질문의 단기 반복
3. 아이가 이미 말한 내용을 다시 질문하는 기억 실패
4. `귀찮아 / 그만 / 재미없어 / 싫어` 등 지루함·거부 신호를 무시하고 질문을 계속하는 문제
5. `잘 못 들었어 / 다시 말해줘` 계열 반복
6. 미션 완료 직후 관계가 갑자기 끊기는 종료 UX
7. `그랬구나 / 좋았겠다` 등 단조로운 공감 표현 반복
8. 자유대화 80자 Hard Limit / 문장 절삭
9. STT/VAD 전반의 발화 잘림·자모 깨짐 문제
10. 미션·자유대화 사이 기억 연속성 및 “아까 말했잖아” 문제
11. 아이의 친근감/애착 표현을 미션이 무시하고 다음 질문으로 넘기는 문제
12. Safety 오탐은 안전 기능을 제거하지 않고 문맥 판정만 튜닝

별도 Request로 이미 분리된 아래 장애는 중복 구현하지 않는다.

```text
미션 LLM Fallback 긴급 핫픽스 v1
- "응, 듣고 있어. 더 얘기해줄래?" 공용 fallback
- 12~26초 retry latency
- Mission deterministic fallback
- LLM 실패와 mission progress 분리
```

### 대표님 테스트 정상 프로세스

#### 시나리오 A — 미션에서 아이가 다른 이야기를 꺼냄

```text
케이: 오늘 기억에 남는 일 있었어?
아이: 민준이랑 축구했는데 싸웠어.
케이: 어, 왜 싸웠어?
아이: 내가 패스를 안 해줬다고 화냈어.
케이: 그때 너는 좀 억울했어?
```

PASS 기준:
- 현재 아이 발화에서 자연스럽게 파생된 질문 우선
- 기존 question_bank는 Seed/Fallback으로만 사용
- 정상 진행 시 미션 응답 마지막에는 질문 존재
- 파생 질문 답변도 의미 있으면 별 게이지 인정

#### 시나리오 B — 이미 답한 내용을 다시 묻지 않음

```text
아이: 오늘 민준이랑 축구했어.
...
케이: 오늘 누구랑 놀았어?
```

위와 같은 재질문은 차단한다.

PASS 기준:
- same-session 동일 정보 재질문 없음
- Same-day 최근 정보가 활용 가능한 경우 불필요한 재질문 없음
- “그 후 어떻게 됐어?”처럼 변화/후속 상황을 묻는 것은 허용

#### 시나리오 C — 아이가 지루함/거부를 표현함

```text
귀찮아
그만할래
재미없어
싫어
```

PASS 기준:
- 같은 질문을 계속 밀어붙이지 않음
- 반복 거부 시 주제 변경 또는 부드러운 미션 마무리 가능
- 별 게이지 때문에 억지 답변을 강요하지 않음

#### 시나리오 D — 자유대화

```text
아이: 오늘 엄마랑 마트 갔어.
```

케이는 현재 맥락에 따라 짧은 리액션, 후속 질문, 가벼운 의견, 기억 회상을 자연스럽게 선택한다.

PASS 기준:
- 매 턴 질문 강제 없음
- `그랬구나.`만 반복하며 대화가 끊기지도 않음

#### 시나리오 E — 미션 종료

미션 완료 후 바로 홈으로 강제 이탈시키기보다:

```text
미션 완료
→ 케이의 짧은 자연스러운 마무리
→ 보상 표시
→ [더 얘기하기] 또는 [홈으로]
```

형태로 선택권을 제공한다.

PASS 기준:
- 자유대화 자동 강제 전환 없음
- 기존 황금열쇠 보상 정상

## 3. 요구사항

### 3-1. Mission V3 실제 실행경로 재확인

개발 시작 전 반드시 다음 실제 경로를 현재 코드로 추적한다.

```text
아이 미션 UI
→ 실제 호출 API
→ mission v3 turn
→ adapter
→ K Conversation Engine
→ response
→ mission progress
```

완료 기준은 “새 코드 존재”가 아니라 실제 Production 실행경로 적용이다.

### 3-2. 고정 질문 강제 회귀 제거

TO-BE:

```text
아이 발화
→ 현재 주제/감정 이해
→ 자연스러운 파생 질문 가능 여부
   ├─ YES → 파생 질문
   └─ NO → Seed/Fallback question
```

미션 정상 응답은 마지막에 질문을 포함한다.

### 3-3. Question Bank는 Seed/Fallback

질문지는 유지하되 다음에만 사용한다.

- 미션 시작
- 현재 대화 교착
- 아이가 특별한 이야기를 꺼내지 못함
- 현재 주제가 자연스럽게 종료
- 새로운 의미 정보가 부족

질문지 순서가 아이 현재 이야기보다 우선해서는 안 된다.

### 3-4. 파생 질문 답변도 별 게이지 인정

기존 question id가 없어도 새로운 의미 정보가 확보되면 별 게이지 진행을 인정한다.

유효 후보:
- 사건
- 감정/이유
- 관계
- 관심사
- 생각/의견
- 기대/걱정
- 최근 변화

단순 `응/아니/몰라/그냥`만으로는 기본적으로 인정하지 않는다.

### 3-5. 최근 질문/이미 확보된 정보 재질문 방지

질문 선택 전에 다음을 확인한다.

```text
same session
same day
최근 mission question history
관련 Memory/Wiki
최근 question bank 사용 이력
```

변화/후속 상황 질문은 허용한다.

### 3-6. Question Cooldown을 의미 기준으로 보완

exact question뿐 아니라 semantic duplicate, 동일 정보 목적 질문까지 고려한다.

매일 달라질 수 있는 질문은 영구 금지하지 않는다.

### 3-7. 지루함/거부 신호 대응

다음 발화를 boredom/refusal signal로 처리한다.

```text
귀찮아
그만할래
재미없어
싫어
안 할래
패스
그만
```

정책:
1. 같은 질문 즉시 반복 금지
2. 한 번의 거부는 다른 주제로 변경 가능
3. 반복 거부는 부드러운 미션 마무리 가능
4. 별 게이지 때문에 억지 추가 답변 요구 금지
5. 죄책감/압박 표현 금지

### 3-8. `잘 못 들었어 / 다시 말해줘` 반복 방지

별도 긴급 핫픽스의 `응, 듣고 있어...` fallback과 구분한다.

- 동일 문구 연속 반복 금지
- 1차 실패: 짧게 한 번 재확인
- 가능한 경우 들린 핵심 단어를 기반으로 확인
- 2회 이상 실패 시 같은 질문 강요 금지
- 정상 final transcript에서는 pardon fallback 미사용

### 3-9. 기억 실패와 `아까 말했잖아` 방지

fabricated recall 방지 원칙은 유지한다.

same-session / same-day에 실제 발화가 있으면 `기억이 안 난다` fallback으로 보내지 않는다.

### 3-10. 고정 Memory Fallback 반복 금지

```text
음, 그건 내가 잘 기억이 안 나네. 다시 얘기해 줄래?
```

같은 문구를 반복 출력하지 않는다.

- 첫 회 짧은 확인 가능
- 다시 설명하면 현재 발화 기준으로 바로 이어감
- 같은 fallback 두 번째 반복 금지
- 기억이 불확실하면 사실을 꾸며내지 않음

### 3-11. 아이의 친근감/애착 표현을 무시하지 않기

```text
케이 좋아해.
너랑 얘기하는 게 재밌어.
너는 내 친한 친구야.
```

와 같은 표현이 나오면 먼저 자연스럽게 받아준 뒤 미션 질문으로 이어간다.

금지:

```text
나도 네가 제일 좋아.
난 너밖에 없어.
친구들보다 내가 더 좋아.
```

### 3-12. 공감 문구 다양화

같은 reaction 연속 사용을 억제하고 아이 발화 핵심 명사/행동을 짧게 반영한다.

### 3-13. 자유대화 80자 Hard Truncation 제거/완화

현재 실제 실행경로에서 80자 hard limit가 남아 있으면:

- 문장 중간 hard cut 금지
- 기본 응답은 짧게 유지
- 필요할 때 120~150자 수준까지 허용 가능한 soft limit 적용
- 모든 답변을 길게 만들지는 않음

### 3-14. 자유대화 질문 압박과 단답 사이 균형

현재 발화에 따라 REACT / FOLLOW_UP / RECALL / PLAYFUL / OPINION / WRAPUP을 자연스럽게 선택한다.

### 3-15. 미션 완료 UX 개선

권장:

```text
미션 완료
→ 케이 짧은 마무리
→ 황금열쇠/보상
→ [더 얘기하기] [홈으로]
```

자동 자유대화 전환은 금지한다.

### 3-16. STT/VAD는 원인 분리 후 튜닝

대표 재현 테스트를 먼저 수행한다.

```text
"오늘 학교에서… (1초 pause) 떡볶이 먹었어."
"음… 민준이랑 놀았어."
"없어."
"아이스크림 먹었어."
긴 문장 15~20초
```

확인 대상:
- interim/final merge
- Web Speech API 이벤트 순서
- VAD silence finalize
- transcript normalization
- duplicate finalize
- 네트워크 전송 시점

900ms가 주요 원인으로 재현되면 1.2~1.3초 수준부터 단계적으로 튜닝한다.

### 3-17. Safety false positive 문맥 개선

고위험 Safety는 유지한다.

게임/말놀이/단어 문맥의 부분 일치 오탐만 문맥 확인을 강화한다.

### 3-18. 좋은 패턴 보존

- 아이가 말한 구체적 명사 재사용
- 자연스러운 후속 질문
- 짧은 장난/티키타카
- 자발적 자기개방 유도
- 같은 날 기억 이어가기

## 5. 금지사항

1. 미션 질문 자체를 없애지 않는다.
2. 미션 정상 응답 마지막 질문 원칙을 제거하지 않는다.
3. question_bank를 삭제하지 않는다.
4. 모든 질문 반복을 무조건 오류 처리하지 않는다.
5. 날짜별 질문을 영구 차단하지 않는다.
6. 아이가 거부했다고 자동 별 게이지 지급하지 않는다.
7. fabricated recall 방지 원칙을 제거하지 않는다.
8. 없는 기억을 지어내지 않는다.
9. Relationship Safety를 약화하지 않는다.
10. 고위험 Safety를 제거하지 않는다.
11. 모든 자유대화 답변을 길게 만들지 않는다.
12. VAD를 근거 없이 특정 값으로 변경하지 않는다.
13. 미션 완료 후 자유대화를 강제로 시작하지 않는다.
14. 놀이 SKILL 운영 정책을 이번 Request에서 변경하지 않는다.
15. 별도 긴급 LLM Fallback 핫픽스와 동일 코드 변경을 중복 구현하지 않는다.
16. Production DB 데이터를 QA 목적으로 수정하지 않는다.
17. 코드가 존재한다는 이유만으로 완료 판정하지 않는다.

---

## 6. 모호성 처리

### 6-1. 질문 반복 여부

문자열이 같아도 새로운 날짜/상태를 묻는 경우 정상일 수 있다.

판정 기준:
- 새로운 정보 획득 가능성
- 최근 동일 정보 보유 여부
- 아이의 불만/지루함 신호
- semantic duplicate 여부

### 6-2. 아이 거부

한 번의 `몰라`와 반복적인 `그만할래`는 동일 처리하지 않는다.

### 6-3. 기억 불확실

same-session/same-day evidence를 우선 사용하고, 장기 Memory가 불확실하면 현재 아이 발화만으로 이어간다.

### 6-4. STT

VAD 외 Web Speech interim/final merge도 함께 확인한다.

### 6-5. 기존 친구되기 패치와 충돌

기존 구현이 실제 Production 경로에 연결되어 있으면 재사용하고, 코드만 있고 경로가 미연결이면 실제 경로 연결 후 E2E로 증명한다.

## 7. QA

### 7-1. 미션 현재 이야기 우선
- [ ] 새 주제에서 파생 질문 우선
- [ ] 고정 next question 강제 회귀 없음
- [ ] question_bank Seed/Fallback 정상
- [ ] 미션 마지막 질문 존재
- [ ] 파생 답변 별 게이지 정상

### 7-2. 반복 질문
- [ ] same-session 동일 정보 재질문 차단
- [ ] same-day 불필요 재질문 차단
- [ ] 최근 question history 반영
- [ ] semantic duplicate 탐지
- [ ] 날짜별 질문 필요 시 허용
- [ ] “왜 또 물어봐” 대표 케이스 차단

### 7-3. 기억
- [ ] “아까 말했잖아” 상황에서 same-session evidence 사용
- [ ] “2번 말했잖아” 상황에서 동일 fallback 반복 없음
- [ ] 근거 없는 기억 맞장구 없음
- [ ] 같은 날 다른 세션 기억 연결 정상

### 7-4. 지루함/거부
- [ ] 귀찮아
- [ ] 그만할래
- [ ] 재미없어
- [ ] 싫어
- [ ] 안 할래
- [ ] 동일 질문 반복 없음
- [ ] 반복 거부 시 부드러운 마무리 가능

### 7-5. ASR/STT
- [ ] 없어
- [ ] 아이스크림
- [ ] 1초 pause 포함 문장
- [ ] 짧은 단답
- [ ] 긴 발화
- [ ] interim/final/VAD 경로로 실제 원인 확인

### 7-6. “잘 못 들었어” 반복
- [ ] 1회 재확인 가능
- [ ] 2회 이상 동일 문구 반복 없음
- [ ] 정상 final transcript에서 pardon fallback 미발생

### 7-7. 자유대화 길이
- [ ] 짧은 리액션은 짧게 유지
- [ ] 필요한 경우 80자 이상 자연스럽게 응답
- [ ] 문장 중간 hard truncation 없음
- [ ] 장황해지지 않음

### 7-8. 공감 다양성
- [ ] `그랬구나` 3연속 없음
- [ ] `좋았겠다` 3연속 없음
- [ ] 아이 핵심 명사/행동 반영
- [ ] 학년별 말투 자연스러움

### 7-9. 친근감 표현
- [ ] `케이 좋아해`
- [ ] `너랑 얘기하는 게 좋아`
- [ ] `너는 내 친한 친구야`
- [ ] 자연스럽게 받아줌
- [ ] 무관한 질문으로 즉시 넘기지 않음
- [ ] 독점적 관계 강화 없음

### 7-10. 미션 완료
- [ ] 완료 상태 정상
- [ ] 황금열쇠 정상
- [ ] 자연스러운 마무리
- [ ] `[더 얘기하기] / [홈으로]` 정상
- [ ] 강제 자유대화 전환 없음
- [ ] 중복 보상 없음

### 7-11. Safety
- [ ] 자해 신호 정상
- [ ] 폭력/학대 신호 정상
- [ ] 성적 위험 정상
- [ ] 말놀이/게임 단어 오탐 개선
- [ ] Relationship Safety 유지

### 7-12. Production 실행경로 E2E
- [ ] UI → API → engine → response → progress → DB 경로 명시
- [ ] 실제 Production과 동일 경로 검증
- [ ] 코드 변경만으로 PASS 처리하지 않음

## 8. 완료 조건

1. 미션 고정 질문 강제 회귀가 실제 Production 실행경로에서 제거된다.
2. 파생 질문이 질문지보다 우선할 수 있다.
3. 의미 있는 파생 답변이 별 게이지에 반영된다.
4. 동일/유사 질문 반복이 유의미하게 줄어든다.
5. same-session/same-day에 이미 말한 내용을 불필요하게 다시 묻지 않는다.
6. `아까 말했잖아 / 2번 말했잖아` 대표 시나리오가 PASS 한다.
7. boredom/refusal 신호를 무시하고 계속 질문하는 구조가 제거된다.
8. `잘 못 들었어` 계열 동일 fallback 반복이 차단된다.
9. `그랬구나 / 좋았겠다` 반응 도배가 줄어든다.
10. 자유대화 80자 hard truncation이 제거/완화된다.
11. STT/VAD 문제의 실제 원인을 재현 QA로 분리하고 확인된 원인을 수정한다.
12. 미션 완료 후 강제 관계 단절 UX가 개선된다.
13. 아이 친근감 표현을 자연스럽게 받아준다.
14. 관계 독점/의존 유도는 계속 차단된다.
15. 고위험 Safety는 유지된다.
16. 별도 LLM Fallback 핫픽스와 충돌하지 않는다.
17. Dev/E2E QA가 모두 PASS 한다.
18. 실제 Production 실행경로 적용을 증명한다.
19. BLOCKED/HIGH/MEDIUM 이슈가 0건이다.
