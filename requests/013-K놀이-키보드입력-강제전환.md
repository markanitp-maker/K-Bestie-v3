# K놀이 시작 시 키보드 입력 강제 전환 및 종료 후 기존 입력모드 복귀 요청

## 0. 완료 시 기대 결과 / 대표님 테스트 정상 프로세스

### 완료 시 기대 결과
- Dev 자유대화에서 `케이 놀이` 버튼을 눌러 초성게임·끝말잇기·넌센스 퀴즈 중 하나를 선택하면 즉시 텍스트 입력 모드로 전환된다.
- 놀이 Skill 시작 성공 시 키보드 입력창이 자동으로 표시된다.
- 모바일/PWA에서는 가능한 경우 놀이 카드 선택 직후 소프트키보드까지 자동으로 열린다.
- 소프트키보드 자동 팝업이 OS 정책상 차단되는 환경에서도 텍스트 입력창은 반드시 표시되고 즉시 탭 가능한 상태여야 한다.
- K놀이 Active 동안 아이가 실수로 음성 입력 모드로 다시 전환할 수 없다.
- K놀이 중 기존 텍스트 입력창 닫기 `X` 또는 음성 복귀 기능은 숨김 또는 비활성화된다.
- 놀이 시작 전에 사용하던 자유대화 입력 상태를 임시 저장한다.
- `그만`, UI 놀이 종료, 게임 정상 종료 등으로 K놀이가 끝나면 놀이 시작 전 입력모드로 자동 복귀한다.
- 놀이 시작 API가 실패하면 강제 텍스트 모드 상태를 남기지 않고 기존 입력모드로 롤백한다.
- K놀이 종료 여부가 서버에서 클라이언트로 명확하게 전달된다.
- Production K놀이 `준비중` 상태는 본 작업으로 변경하지 않는다.

### 대표님 테스트 정상 프로세스
1. Dev 아이 계정으로 자유대화에 진입한다.
2. 음성 자동모드 상태에서 `케이 놀이` 버튼을 누른다.
3. 끝말잇기를 선택한다.
4. 놀이 선택 즉시 텍스트 입력 화면으로 전환되는지 확인한다.
5. 모바일/PWA에서는 소프트키보드가 자동으로 표시되는지 확인한다.
6. 자동 팝업이 제한되는 기기에서는 텍스트 입력창이 바로 표시되고 한 번 탭하면 키보드가 정상 열리는지 확인한다.
7. 놀이 중 텍스트 입력창 닫기 `X` 또는 음성 입력 복귀 기능을 사용할 수 없는지 확인한다.
8. 텍스트로 끝말잇기를 여러 턴 진행한다.
9. `그만`이라고 텍스트로 입력한다.
10. 놀이가 종료되고 놀이 시작 전 음성 입력 상태로 자동 복귀하는지 확인한다.
11. 수동 음성모드에서도 같은 테스트를 반복하고 수동모드로 정확히 복귀하는지 확인한다.
12. 초성게임·넌센스 퀴즈도 동일하게 테스트한다.
13. Skill 시작 API 실패를 재현하여 기존 입력모드로 롤백되는지 확인한다.

## 2. 목표
현재 K놀이는 음성 입력 STT 오류가 정답 판정·끝말잇기 단어·게임 제어 명령에 직접 영향을 줄 수 있다.

따라서 K놀이 진행 중에는 음성 입력을 사용하지 않고 텍스트 입력을 강제하여 Gameplay Input을 명확하게 만든다.

정상 구조:

```text
자유대화
mode = voice 또는 text
↓
K놀이 버튼
↓
놀이 선택
↓
현재 입력모드 임시 저장
↓
즉시 text mode 전환 + input focus 시도
↓
Skill start API
↓
성공
→ text mode 유지
→ K놀이 진행

실패
→ 기존 입력모드 복귀
```

놀이 종료:

```text
Skill Active
↓
그만 / UI 종료 / 게임 정상 종료
↓
Server Skill.end()
↓
Client에 playSkillEnded 전달
↓
놀이 시작 전 입력모드 복귀
↓
일반 Free Chat
```

최종 목표:

```text
K놀이 Active
→ Gameplay Input = Keyboard Only
```

## 3. 요구사항

### 3-1. 현재 입력모드 구조 재사용
현재 확인된 `app/chat/page.tsx`의 기존 상태를 재사용한다.

- `mode: "voice" | "text"`
- `isAuto`
- `switchToText()`
- `switchToVoice()`
- `textInput`

새로운 독립 입력모드 시스템을 만들지 않는다.

### 3-2. 놀이 시작 전 기존 입력모드 저장
Skill 선택 직전에 현재 자유대화 입력상태를 임시 저장한다.

최소 저장 대상:
- `mode`
- `isAuto`
- 필요한 경우 현재 voice input mode

개념 예:

```text
prePlayInputModeRef
```

실제 명칭은 기존 코드 convention을 따른다.

이 값은 장기 저장이나 DB 저장 대상이 아니다.

현재 Free Chat 화면 lifecycle 내 임시 UI 상태로만 관리한다.

### 3-3. K놀이 카드 선택 시 즉시 텍스트 모드 전환
현재 흐름:

```text
PlaySkillModal
→ 카드 클릭
→ POST /api/play/skill/select
→ 성공
→ onSkillStarted()
```

모바일 소프트키보드의 User Activation 제약 때문에 API 응답 이후에 처음 focus를 시도하는 것만으로는 부족하다.

따라서 놀이 카드의 실제 사용자 click/tap 이벤트에서 가능한 한 즉시:

```text
현재 모드 저장
→ text mode 전환
→ input mount/focus 준비
```

를 시작한다.

이후 Skill start API를 호출한다.

### 3-4. Skill 시작 성공 시 텍스트모드 확정
`POST /api/play/skill/select` 성공 후:

- text mode 유지
- input 표시 확인
- 가능하면 다시 focus
- openingLine은 기존 방식으로 K가 출력

Skill 시작 성공 이후 voice mode로 자동 복귀하면 안 된다.

### 3-5. Skill 시작 실패 시 Rollback
Skill start API가:
- 4xx
- 5xx
- network error
- timeout
- `ok:false`

를 반환하면:

```text
K놀이 미시작
→ 기존 입력모드 복귀
```

해야 한다.

강제로 text mode만 남겨두면 안 된다.

사용자에게는 기존 UI 정책에 맞는 짧은 오류 안내만 표시한다.

### 3-6. Input Focus 구조 개선
현재 input은 inline callback ref:

```tsx
ref={(el) => {
  if (el) el.focus();
}}
```

구조로 확인되었다.

이번 작업에서는 K놀이 자동 focus 제어가 필요하므로 필요하다면 명시적인 input ref로 정리한다.

개념:

```text
textInputRef
```

목적:
- 놀이 시작 시 focus
- render 이후 focus 재시도
- 모바일 user gesture chain에서 focus 시도

단, 불필요하게 전체 input component를 재작성하지 않는다.

### 3-7. 모바일/PWA 소프트키보드 정책
iOS Safari/iOS PWA/Android Chrome에서는 비동기 API 완료 후 `focus()`만 호출하면 software keyboard 자동 팝업이 보장되지 않는다.

따라서:
- 놀이 카드 클릭 시점의 user gesture 안에서 첫 focus 시도
- Skill 성공 후 추가 focus는 보조
- OS가 자동키보드 호출을 차단하더라도 기능 실패로 처리하지 않는다.

PASS 최소 기준:

```text
텍스트 입력창 자동 표시
+
입력 가능 상태
```

소프트키보드 자동 팝업은 지원 환경에서는 동작하도록 최선을 다하되 OS 정책을 우회하는 hack을 사용하지 않는다.

### 3-8. K놀이 Active 상태를 Client가 인지
현재 ChatPage가 K놀이 Active 여부를 UI 관점에서 명확히 알 수 있도록 상태를 둔다.

개념:

```text
activePlaySkillId
또는
isPlayActive
```

실제 구조는 현재 API/상태 convention을 따른다.

이 상태는 다음 UI 제어에 사용한다.

- 음성 복귀 차단
- X 버튼 처리
- 놀이 종료 후 입력모드 복귀
- active 상태 표시

### 3-9. K놀이 중 텍스트 입력창 닫기 차단
현재 text mode에서 `switchToVoice()`를 호출하는 X/닫기 UI가 존재한다.

K놀이 Active 동안에는 이 control을:
- hide
또는
- disabled

처리한다.

아이에게 음성 입력으로 돌아갈 수 있는 경로를 남기지 않는다.

### 3-10. K놀이 중 음성모드 진입 차단
K놀이 Active 동안 어떠한 UI 이벤트에서도:

```text
mode = voice
```

로 바뀌면 안 된다.

필요하다면 `switchToVoice()` 내부에 guard를 둔다.

예:

```text
if (isPlayActive) return
```

실제 구현은 stale closure 등 React state 문제 없이 안전한 구조를 사용한다.

### 3-11. UI 놀이 종료 시 기존 모드 복귀
현재 `PlaySkillModal.tsx`의 `handleEndSkill()` 성공 후 Client가 Skill 종료를 인지할 수 있도록:

```text
onSkillEnded
```

또는 동등 callback을 추가한다.

성공 시:

```text
isPlayActive = false
→ restorePrePlayInputMode()
```

순서로 처리한다.

### 3-12. 음성/텍스트 "그만" 종료 메타데이터 전달
현재 `/api/voice/respond` 응답은 놀이 Skill 종료 여부를 Client에 전달하지 않는다.

서버 Engine 응답에 가능한 기존 metadata가 있는지 먼저 확인하고, 없다면 최소한 다음 중 하나를 반환한다.

```text
playSkillEnded: boolean
```

또는:

```text
activePlaySkillId: string | null
```

Client가 추측으로 Skill 종료 여부를 판정하면 안 된다.

### 3-13. 자연 종료 시 Client 복귀
게임 내부 규칙에 의해 정상 종료된 경우에도 동일하다.

예:

```text
Skill.handleTurn()
→ ended = true
→ Skill.end()
```

서버 응답에서 종료 상태를 Client로 전달한다.

Client:

```text
playSkillEnded = true
→ isPlayActive false
→ restorePrePlayInputMode()
```

### 3-14. 기존 모드 정확히 복귀
놀이 시작 전:

```text
voice + auto
```

였다면 종료 후 `voice + auto`로 복귀한다.

놀이 시작 전:

```text
voice + manual
```

이었다면 종료 후 `voice + manual`로 복귀한다.

놀이 시작 전:

```text
text
```

였다면 종료 후 text mode 유지가 가능해야 한다.

현재 `switchToVoice()`가 항상 manual로 만드는 기존 동작만 사용하면 안 된다.

별도의:

```text
restorePrePlayInputMode()
```

또는 동등 로직을 둔다.

### 3-15. 마이크 Release / Reacquire
놀이 시작 시 text mode 전환 과정에서 기존 `switchToText()`가 수행하는:
- recording finalize
- mic disabled
- microphone release

동작을 유지한다.

놀이 종료 후 이전 mode가 voice라면:
- 이전 `isAuto` 상태 복원
- microphone reacquire

를 기존 안전한 경로를 통해 수행한다.

중복 stream 생성이나 mic lock이 발생하면 안 된다.

### 3-16. Skill 전환 중 text mode 유지
K놀이 중:

```text
WORD_CHAIN
→ K놀이 Modal
→ CHOSUNG
```

으로 전환할 때는 이미 text mode이므로 입력모드 저장값을 덮어쓰면 안 된다.

즉 최초 K놀이 진입 시 저장한 `prePlayInputMode`를 유지한다.

Skill A → Skill B 전환은:

```text
text mode 유지
```

한다.

Skill 전체를 종료할 때만 최초 mode로 복귀한다.

### 3-17. 앱 이탈/네트워크 단절
앱 이탈/강제 종료는 Client UI 자체가 사라지므로 `restorePrePlayInputMode()` 대상이 아니다.

이 경우:
- Client 입력모드 복귀 문제
- Server stale Skill Session cleanup

을 분리한다.

이번 Request에서 서버 Session cleanup 구조를 새로 재설계하지 않는다.

### 3-18. Production 상태 유지
현재 Production K놀이가 `준비중`이라면 그대로 유지한다.

본 작업은 Dev QA 목적이다.

Production에서:
- K놀이 활성화
- Play Skill start 허용
- 준비중 해제

를 수행하지 않는다.

- Skill 시작 실패인데 text mode 강제 상태 유지 금지
- 놀이 종료 여부를 Client 문자열 분석으로 추측 금지
- K 응답 문구에서 `그만` 여부를 parsing하여 UI 복귀시키는 구현 금지
- iOS software keyboard 강제 팝업을 위해 비표준 hack 사용 금지
- Skill A → Skill B 전환 때 prePlayInputMode를 덮어쓰기 금지
- 기존 Free Chat 음성/텍스트 전환 계약 훼손 금지
- Mission 입력 UX 변경 금지
- `/child/play` 수정 금지

## 6. 모호성 처리
- 현재 Engine 응답에 이미 active Skill metadata가 있으면 이를 재사용한다.
- 없다면 최소 metadata만 추가한다.
- `playSkillEnded`와 `activePlaySkillId` 중 실제 구조에 더 자연스러운 하나를 선택한다.
- 입력 focus를 위해 대규모 component refactor가 필요하지 않다면 최소 수정한다.
- iOS/PWA 키보드 자동 popup이 OS 정책으로 불가능한 경우 이를 버그로 우회하지 않는다.
- 자동 popup보다 텍스트 입력 UI가 확실히 표시되는 것을 우선한다.
- 기존 localStorage voice input mode 정책과 충돌하지 않게 한다.
- Production/Dev 환경분기는 현재 프로젝트 Source of Truth를 따른다.
- 예상과 다른 코드가 발견되면 실제 구현을 우선하고 최소 수정한다.
