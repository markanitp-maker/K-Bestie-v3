## 핵심 문제

다음 문제를 서로 분리해서 분석하고 수정한다.

### 문제 A — 화면이 계속 `듣는 중`으로만 표시됨

실제 연결 장애라기보다 다음 가능성이 크다.

- 음성 대화 상태값과 UI 상태 표시가 제대로 연결되지 않음
- 기본 상태가 `듣는 중`으로 고정됨
- STT·LLM·TTS·오디오 재생 단계가 상태 머신에 반영되지 않음
- 오류·재연결·세션 종료 상태도 `듣는 중`으로 잘못 표시됨

### 문제 B — 정상 대화 중 끊김·연결 불안정 안내 노출

정상적으로 아이와 케이가 대화하고 있음에도 다음 문구 또는 유사 경고가 노출된다.

```text
잠시 대화가 끊겼나 봐요. 다시 말해 줄래요.
```

또는:

```text
지금 대화가 잠시 끊겼나 봐요. 다시 한번 말해줄래?
연결 불안정
연결 다소 불안정
```

이 문제는 상태 표시 문제와 별도 원인일 수 있으므로 독립적으로 조사한다.

## 1. 임시 미션 반복 정책

베타 개발이 안정화될 때까지 다음 정책을 적용한다.

### 기본 완료 정책

- 유효 답변 10개를 채우면 미션 완료
- 기존 완료 보상 정상 처리
- 미션 완료 화면 표시
- 유효 답변 수와 진행률 일치
  - 1개 = 10%
  - 10개 = 100%

### 반복 실행 임시 정책

미션 완료 후 사용자가 다시 미션 버튼을 누르면:

- 이전 완료 세션을 이어하지 않음
- 이전 세션 ID를 재사용하지 않음
- 새로운 미션 세션 생성
- 새로운 세션 ID 발급
- 질문 진행률 0으로 초기화
- 현재 질문 번호 초기화
- 미션 대화 히스토리 초기화
- 임시 답변 상태 초기화
- 재질문 횟수 초기화
- 질문 순환 단계 초기화
- 질문 1번부터 새로 시작
- 기본 질문 10개 + 예비 질문 10개, 총 20개 질문 구조 유지
- 개발·테스트 기간에는 같은 날에도 미션 반복 실행 허용

### 보상 정책

대화 재시작과 보상 지급을 분리한다.

- 대화 세션은 반복 생성 가능
- 보상은 기존 일일 보상 정책 유지
- 같은 날 동일 보상이 이미 지급됐다면 반복 미션 완료 시 추가 지급하지 않음
- 반복 테스트 때문에 황금열쇠가 무한 지급되지 않도록 멱등성 유지
- 보상 원장과 화면 잔액 직접 덮어쓰기 금지
- 기존 보상 지급 RPC·원장 구조 재사용

### 미션 재진입 상태 구분

다음을 정확히 구분한다.

- 진행 중 세션:
  - 이어하기 허용
- 완료 세션:
  - 새 세션으로 시작
- 실패 세션:
  - 제품 정책에 따라 새 세션 시작
- 중단·오류 세션:
  - 세션 복구 가능 여부를 확인 후 이어하기 또는 새 시작 분리

완료 세션을 실수로 이어하기 상태로 복원하지 않는다.

## 2. 질문 순환 정책 유지

새 세션에서도 기존 확정 정책을 유지한다.

1. 기본 질문 10개 진행
2. 유효 답변이 부족하면 예비 질문 10개 진행
3. 그래도 부족하면 기본·예비 질문 중 미답변 문항만 순서대로 1회 순환
4. 그래도 부족하면 다음 최종 안내 전달

```text
더 이상 준비된 질문지가 없어서 미션을 완료할 수 없어요. 다시 한번 질문을 진행할게요. 이번에도 답변 못하면 미션은 실패됩니다.
```

5. 최종 안내 후 미답변 문항 마지막 1회 순환
6. 마지막에도 유효 답변 10개 미만이면 미션 실패
7. 유효 답변 10개가 되는 즉시 미션 완료

각 문항 처리:

- 질문과 관련 있는 짧거나 애매한 답변도 유효 답변
- 완전히 엉뚱한 답변·거부·침묵·인식 불가 답변은 유효 답변 아님
- 같은 질문은 한 번만 재질문
- 재질문 후에도 유효하지 않으면 다음 질문으로 이동
- 무효 답변에서 진행률 증가 금지

## 3. 화면 상태 표시 기준

UI 기본값을 `듣는 중` 하나로 고정하지 않는다.

다음 상태를 내부 상태 머신으로 명확하게 분리한다.

```text
connecting
listening
thinking
speaking
reconnecting
error
ended
microphone_denied
```

### 사용자 표시 상태

| 실제 상태 | 화면 문구 | 판정 기준 |
|---|---|---|
| 아이 발화를 받고 있음 | 듣는 중 | 마이크 입력 활성화 + 케이 음성 출력 없음 |
| 케이가 응답을 생성하고 있음 | 생각하는 중 | 아이 발화 종료 후 케이 오디오 시작 전 |
| 케이 음성이 재생 중 | 말하는 중 | TTS 결과 수신 또는 실제 오디오 재생 중 |

### 내부 상태

화면에 크게 표시하지 않더라도 다음 상태를 별도 관리한다.

- 연결 중
- 재연결 중
- 오류
- 세션 종료
- 마이크 권한 없음

### 정상 상태 전환

```text
듣는 중
→ 생각하는 중
→ 말하는 중
→ 듣는 중
```

### 상태 판정 규칙

#### 듣는 중

- 마이크 입력이 실제 활성 상태일 때만 표시
- 아이 음성을 수집할 수 있는 상태여야 함
- 케이 오디오 재생 중에는 표시 금지
- API 응답 대기 중에는 표시 금지
- 재연결 중에는 표시 금지
- 오류 상태에서는 표시 금지

#### 생각하는 중

아이 발화 종료 후 다음 전체 처리 구간을 포함한다.

```text
발화 종료
→ STT 처리
→ LLM 처리
→ TTS 생성
→ 실제 오디오 재생 시작 직전
```

- STT 시작 시 진입
- LLM 응답 생성 중 유지
- TTS 생성 중 유지
- 실제 오디오 재생 시작 시 종료

#### 말하는 중

- 실제 오디오 재생 시작 시 표시
- 재생 중 계속 유지
- 오디오 재생 종료 시 해제
- 다음 듣기 상태로 복귀

### 상태 머신 완료조건

- 항상 `듣는 중`으로 고정되는 현상 제거
- 상태 순서 역전 없음
- 상태가 영구 고정되지 않음
- 오류 발생 후 이전 상태가 남지 않음
- 다음 턴에서 정상 상태 복귀
- 상태 UI가 실제 파이프라인 이벤트와 일치
- 단순 React 렌더링 상태가 아닌 실제 음성 이벤트에 연결

## 4. 미션 대화 화면 레이아웃

미션 대화 화면을 고정형 레이아웃으로 변경한다.

### 상단 고정 영역

다음 항목은 화면 상단에 고정한다.

- 뒤로가기
- 화면 제목
- 연결 상태 또는 상태 표시 영역
- 자동·수동 모드 전환
- 진행률
- 현재 유효 답변 수

### 하단 고정 영역

다음 항목은 화면 하단에 고정한다.

- 현재 케이 말풍선
- 케이 마스코트
- 듣는 중·생각하는 중·말하는 중 상태 배지
- 음성 ON/OFF
- 대화·종료 메뉴

### 중앙 대화 히스토리 영역

- 중앙만 별도 히스토리 영역으로 사용
- 최근 대화 말풍선 최대 3개만 표시
- 새 말풍선 추가 시 가장 오래된 말풍선 제거
- 전체 대화 기록을 길게 쌓지 않음
- 과거 대화 기록 전체 스크롤 UI 금지
- 별도 스크롤바 표시 금지
- 아이 말풍선 비표시 정책 유지
- 현재 케이 말풍선은 하단 고정 영역에서 별도 표시

### 화면 높이

- 전체 컨테이너는 `100dvh` 기준
- iPhone Safari 주소창 변화 대응
- `env(safe-area-inset-top)` 고려
- `env(safe-area-inset-bottom)` 적용
- 작은 화면에서도 상단·하단 영역이 밀려나지 않도록 구성
- 전체 페이지 스크롤 금지
- `body` 또는 페이지 컨테이너 overflow 제어
- 키보드·Safari 하단바·PWA standalone 모드 확인

### 레이아웃 회귀 금지

- 진행률 가림 금지
- 자동·수동 버튼 가림 금지
- 마스코트 잘림 금지
- 말풍선이 상태 배지를 덮지 않음
- iPhone 세로 화면 기준 정상 표시
- Android Chrome 세로 화면 기준 정상 표시

## 5. 끊김 안내 문구 제거

```text
잠시 대화가 끊겼나 봐요. 다시 말해 줄래요.
```

다음 유사 문구도 검색한다.

```text
지금 대화가 잠시 끊겼나 봐요.
다시 한번 말해줄래?
연결이 끊겼어요.
```

### 검색 범위

- 모델 system prompt
- user prompt
- few-shot 예시
- hardcoded fallback
- error toast
- retry banner
- timeout 처리
- STT 실패 처리
- LLM 실패 처리
- TTS 실패 처리
- 오디오 재생 실패 처리
- stale timer
- 이전 턴 오류 상태
- 지연된 callback

### 처리 원칙

- 일시적인 무음만으로 사용자 경고 표시 금지
- 단순 응답 지연만으로 경고 표시 금지
- 이전 턴의 timeout이 현재 정상 턴에 늦게 표시되지 않도록 타이머 정리
- 새 턴 시작 시 이전 오류 상태 정리
- 내부적으로 먼저 재시도 또는 재연결
- 재연결 성공 시 사용자 메시지 없이 대화 계속
- 복구 불가능한 경우에만 짧은 재시도 UI 표시
- 복구 불가능 상태에서 모델이 사과 문구를 말하지 않도록 분리
- 오류 메시지가 케이 대화 말풍선으로 저장되지 않도록 처리
- 질문 진행률과 세션 상태는 보존

### 복구 불가능 오류 UI

복구가 불가능한 경우에만:

- 짧은 오류 문구
- `다시 시도` 버튼
- `미션 나가기` 버튼

오류 원인을 네트워크로 단정하지 않는다.

## 6. 연결 불안정 원인 분석

현재 Dev 테스트 유저는 Live API가 아니라 STT → LLM → TTS 구조를 사용한다.

따라서 Vertex Live Relay 문제로 단정하지 말고 실제 현재 파이프라인을 기준으로 분석한다.

### 분석 대상

```text
마이크 입력
→ VAD 또는 녹음 종료
→ STT
→ LLM
→ TTS
→ 오디오 재생
→ 다음 턴 마이크 활성화
```

### 확인할 가능성

- STT timeout
- LLM timeout
- TTS timeout
- 실제 오디오 재생 실패
- 재생 종료 콜백 누락
- AbortController 교차 취소
- 오래된 timeout callback
- 중복 `onTurnComplete`
- stale React state
- 상태 머신 전환 누락
- 앱 백그라운드 전환
- 화면 잠금
- iPhone Safari 오디오 세션 중단
- 네트워크 Wi-Fi ↔ LTE 전환
- 브라우저 마이크 권한 변경
- 탭 visibility 변경
- PWA suspend/resume
- 서버 응답은 성공했지만 UI 오류 상태가 남는 문제

### 휴대폰 문제 판정 기준

휴대폰 문제라고 판단하려면 다음 중 특정 조건에서 반복 재현되어야 한다.

- 특정 기기
- 화면 잠금
- 앱 전환
- Wi-Fi/LTE 전환
- 백그라운드 전환
- Safari/PWA 특정 모드

화면을 계속 켜 두고 정상 네트워크 상태에서도 반복된다면 휴대폰 문제로 단정하지 않는다.

### 서버·상태 관리 문제 판정 기준

다음이면 서버 또는 상태 관리 문제 가능성이 높다.

- 같은 시점에 API 오류 또는 timeout 존재
- 정상 HTTP 응답 후 UI만 실패 상태
- 오디오 재생 완료 후 listening 복귀 누락
- 이전 턴 timer가 다음 턴에 작동
- 정상 대화 중 error state가 초기화되지 않음
- 동일 현상이 여러 기기에서 재현
