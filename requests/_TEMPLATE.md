## 현재 상태

현재 코드나 장애 상태를 사실대로 적는다.

예시:

- `app/child/play/page.tsx`에는 황금열쇠 필요 개수만 표시되고 현재 보유량은 표시되지 않는다.
- `GET /api/play/balance` API는 이미 존재한다.
- 새로운 잔액 API를 만들 필요가 없다.
- Dev URL: `https://k-bestie-v3-dev.vercel.app`

## 요구사항

무엇을 어떻게 변경할지 구체적으로 작성한다.

가능하면 줄 번호보다는 파일명과 함수·컴포넌트·코드 식별자를 함께 사용한다.

예시:

- `app/child/play/page.tsx`의 `PlayPage` 컴포넌트에서 기존 잔액 API 결과를 사용한다.
- `GAMES.map()` 카드 렌더링 우측 상단의 필요 개수는 `🔑 필요 N개`로 표시한다.
- 화면 헤더에는 `🔑 황금열쇠 N개`를 항상 표시한다.
- 부족 모달에는 `현재 N개 · 필요 M개 · X개 부족`을 표시한다.
- 기존 API와 원장 로직을 재사용하고 유사 기능을 새로 구현하지 않는다.
- 준비 중 상태와 부족 모달이 동시에 표시되지 않게 한다.

## 데이터·환경변수·배포

- DB 변경: 없음 / 있음
- 마이그레이션: 없음 / 있음
- 환경변수 변경: 없음 / 있음
- Dev 배포: 필요 / 불필요
- Production 변경: 금지 / 대표님 별도 승인 필요

  - 자동화 QA: `QA테스트` 계정
  - D/F 회귀검증: `testi01`, `testi02`
  - 김서아·김서현: 대표님 최종 수동 확인만 허용

## 완료조건

- 요구사항을 모두 충족한다.
- `npx tsc --noEmit` 통과
- `npx next build` 성공
- 관련 자동테스트 통과
- `git diff --stat`과 `git diff`로 허용 범위 밖 변경이 없는지 확인
- Dev 배포가 필요한 작업이면 Dev 배포 완료
- 지정된 QA 계정으로 실제 동작 확인
- 기존 기능 회귀가 없는지 확인
- 임시 스크립트·로그·인증정보를 저장소에 남기지 않음
- 커밋 SHA와 Dev URL을 보고

## 검증 시나리오

구체적인 입력과 기대 결과를 작성한다.

예시:

1. QA 계정 황금열쇠가 22개인 상태로 놀이 화면 진입
2. 헤더에서 `황금열쇠 22개` 확인
3. 황금열쇠 3개가 필요한 놀이 진입
4. 정상 차감 시 `22 → 19개`
5. 이어하기에서는 추가 차감되지 않음
6. 잔액이 부족하면 `현재 / 필요 / 부족` 개수가 정확히 표시됨
