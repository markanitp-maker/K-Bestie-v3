## 현재 상태

- 전역 플로팅 버튼은 `components/KChatbotWidget.tsx` 단일 컴포넌트이며, 아이·부모 13개
  화면(`app/child/*`, `app/parent/*`, `app/chat/page.tsx`)에서 `appSurface` prop과 함께
  호출된다. 새 컴포넌트를 만들지 않고 이 컴포넌트를 그대로 수정한다.
- 버튼 라벨은 `문의`, `aria-label`은 `문의하기 열기`다.
- 드래그 이동 기능은 021에서 이미 도입되어 커밋돼 있으나 아래 결함이 있다.
  1. **위치 저장이 실제로 복원되지 않는다.** 저장값은 `xPercent`/`yPercent`를 0~100
     스케일(5/95, 15/50/85)로 쓰는데, 043에서 추가된 복원 clamp가 `Math.min(1, ...)`으로
     0~1 범위를 강제한다. 그 결과 재접속 시 `yPercent`가 항상 1이 되고,
     `getButtonStyles()`의 `yPercent === 15 | 50 | 85` 분기 어디에도 걸리지 않아
     세로 위치(top/bottom)가 아예 지정되지 않는다. 좌우 방향만 남고 세로 위치는 유실된다.
  2. 세로 위치가 상단/중앙/하단 3단계로만 저장되어 "원하는 세로 위치"라는 요구를
     충족하지 못한다.
  3. 드래그 진입 조건이 화면별로 다르다. 아이 화면은 400ms 롱프레스만 허용하고
     10px 이상 스와이프는 드래그도 클릭도 아닌 취소로 처리한다(버튼을 살짝 문지르면
     아무 일도 일어나지 않음). 부모 화면은 10px 이동 임계치를 쓴다.
- 모달(`케이에게 알려주세요`)에는 FAQ 안내 영역이 없다.
- **공식 FAQ URL은 코드베이스·`docs/`·모든 `.env*` 파일 어디에도 존재하지 않는다**
  (`grep -ri "faq"` 및 `.env.local` / `.env.local.example` / `.env.development` /
  `.env.production` 전수 확인 완료). 임의 생성 금지 대상이다.
- Dev URL: `https://k-bestie-v3-dev.vercel.app`

## 요구사항

### 1. 플로팅 버튼 라벨

- `components/KChatbotWidget.tsx`의 트리거 버튼 라벨을 `문의` → `FAQ`로 변경한다.
- `aria-label`을 `FAQ 열기`로 변경한다.
- 아이콘·색상·크기·기본 배치는 그대로 둔다. 새 컴포넌트를 만들지 않는다.

### 2. 드래그 정책 (드래그 vs 탭 구분)

- 드래그 진입 조건을 아이·부모 화면 공통으로 **포인터 이동거리 8px 초과 단일 기준**으로
  통일한다. 롱프레스 타이머(`longPressTimer`)와 아이 화면 전용 스와이프 취소 분기는 제거한다.
  - 8px 이하로 눌렀다 뗌 → 탭 → 모달 오픈
  - 8px 초과 이동 → 드래그 → 이동만 하고 모달은 열리지 않음
- 드래그 종료 후 브라우저가 발생시키는 native `click`은 억제한다. 억제 플래그는 다음
  `pointerdown`에서 반드시 초기화해 "다음 탭이 삼켜지는" 상태가 남지 않게 한다.
- 버튼은 `touch-action: none`을 유지해 드래그 중 페이지 스크롤이 함께 일어나지 않게 한다.

### 3. 스냅 및 가림 방지

- 드래그를 놓으면 가로는 화면 좌/우 가장자리 중 가까운 쪽에 스냅한다
  (버튼 중심의 x가 뷰포트 절반보다 왼쪽이면 `left`, 아니면 `right`).
- 세로는 3단계 고정이 아니라 **뷰포트 높이 대비 비율(0~1)로 자유롭게** 저장한다.
- 세로 위치는 아래 범위를 벗어나지 못하도록 CSS `clamp()`로 제한한다. JS 픽셀 계산
  대신 `env(safe-area-inset-*)`와 `dvh`를 그대로 쓰는 방식이어야 키보드가 올라오거나
  화면이 회전해도 자동으로 다시 안전 범위 안으로 들어온다.
  - 상한(위): `topOffsetPx`(페이지별 헤더 높이 prop) + PC 목업 보정 + `env(safe-area-inset-top)`
  - 하한(아래): 하단 메뉴 영역 90px + 버튼 높이 + `env(safe-area-inset-bottom)`
- `containerMaxWidthPx`가 지정된 화면의 중앙 컬럼 정렬 로직은 좌·우 양쪽에 동일하게 적용한다.

### 4. 위치 저장

- 저장 항목: 좌우 방향(`edge`)과 세로 비율(`yRatio`).
- `localStorage` 키는 스키마가 바뀌었으므로 새 버전 키를 쓴다: `k_faq_button_position_v1`.
  구 키(`k_chatbot_widget_position`)의 손상된 값은 읽지 않는다.
- 복원 시 타입·범위를 엄격히 검증하고 `yRatio`는 0~1로 clamp한다. 값이 손상됐거나
  형식이 다르면 조용히 기본 위치(우측 하단)로 되돌린다.
- 페이지 이동, 새로고침, 재로그인 후에도 저장된 위치가 그대로 복원돼야 한다.

### 5. 모달 FAQ 안내 영역

- 모달 제목/설명(`케이에게 알려주세요`) 아래, 기존 3개 탭(문의하기/건의하기/버그 신고하기)
  위에 FAQ 안내 영역을 추가한다.
  - 제목: `FAQ`
  - 안내 문구: `사용법이 궁금하면 언제든지 확인해 보세요.`
  - 액션 버튼: `FAQ 페이지로 이동`
- 기존 3개 탭과 그 아래 폼(제목/내용/이미지 첨부/제출)의 로직과 디자인은 일절 건드리지 않는다.

### 6. FAQ URL 관리

- FAQ URL은 `NEXT_PUBLIC_FAQ_URL` 환경변수에서 읽는다. 공개 링크이므로
  `NEXT_PUBLIC_` 접두어가 규약상 적합하다(비밀값 아님).
- 값이 `http://` 또는 `https://`로 시작할 때만 유효한 것으로 간주하고
  `<a target="_blank" rel="noopener noreferrer">`로 렌더링한다.
- **값이 없으면 URL을 임의로 만들지 않는다.** 버튼을 `disabled` 상태로 렌더링하고
  `FAQ 페이지 준비 중입니다.` 보조 문구를 함께 노출한다.
  (alert 팝업으로 처리하지 않는다 — 눌리는데 실패하는 버튼보다 명시적 비활성이 낫다.)
- `.env.local.example`에 `NEXT_PUBLIC_FAQ_URL` 슬롯과 "미설정 시 버튼 비활성" 주석을 추가한다.
- 이 항목은 **URL 미확보로 부분 미완료**다. 대표님이 공식 FAQ URL을 확정해 Vercel
  환경변수에 넣으면 코드 변경 없이 활성화된다.
