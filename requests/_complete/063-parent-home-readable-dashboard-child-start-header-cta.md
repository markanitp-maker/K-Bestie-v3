# 063 — 부모 홈 대시보드 가독성 중심 UI 개편 및 ‘아이 시작하기’ 헤더 이동

## 1. 작업 목적

현재 부모 홈 대시보드는 전체적으로 글씨와 아이콘이 작고 정보 밀도가 높아, 부모 사용자가 한눈에 내용을 파악하기 어렵다.

이번 작업의 목표는 다음 두 가지다.

1. 기존 상단의 `아이와 케이 시작하기` 카드 영역을 제거하고, 같은 기능을 최상단 헤더의 `아이 시작하기` CTA 버튼으로 이동한다.
2. 부모 홈 대시보드 전체를 큰 글씨·큰 아이콘·큰 터치 영역 중심으로 재구성하여 부모가 핵심 내용을 한눈에 읽을 수 있게 한다.

이번 작업은 UI/UX 개편이며, 기존 데이터·API·모달·라우팅·아이 선택·리포트·문의 기능은 변경하지 않는다.

---

## 2. 가장 중요한 변경 요약

### 현재 구조

```text
상단 헤더
내친구 케이 | 보호자/아이 선택 | 알림

아이와 케이 시작하기 카드
- 설명
- 아이 시작하기 버튼

오늘의 한마디

8개 인사이트 카드
- 학교·학원 생활
- 친구 관계
- 마음 흐름
- 관심사·취향
- 공부 고민
- 디지털·콘텐츠
- 선생님·어른
- 반복 이야기

하단 네비게이션
```

### 변경 후 구조

```text
상단 헤더
내친구 케이 | [아이 시작하기] | 아이 선택 | 알림

오늘의 한마디

8개 인사이트 카드
- 학교·학원 생활
- 친구 관계
- 마음 흐름
- 관심사·취향
- 공부 고민
- 디지털·콘텐츠
- 선생님·어른
- 반복 이야기

확대된 하단 네비게이션
```

즉, `아이와 케이 시작하기` 카드 전체를 제거하고, 그 기능만 헤더의 강조 CTA로 이동한다.

---

## 3. 구현 전 필수 확인

코드 수정 전에 다음을 먼저 확인한다.

1. 부모 홈 실제 라우트와 메인 컴포넌트
2. 현재 `아이와 케이 시작하기` 카드를 렌더링하는 정확한 파일과 컴포넌트
3. 현재 카드 내부 `아이 시작하기` 버튼의 클릭 핸들러
4. 버튼 클릭 시 열리는 기존 모달 컴포넌트와 상태 제어 방식
5. 부모 공통 헤더 컴포넌트 존재 여부
6. 아이 선택 드롭다운/보호자 이름 표시 구조
7. 알림 버튼 구조
8. `오늘의 한마디` 컴포넌트
9. 8개 인사이트 카드의 실제 데이터 및 클릭 동작
10. 부모 하단 네비게이션 공통 컴포넌트

새 모달이나 새 API를 만들기 전에 기존 `아이 시작하기` 기능을 그대로 재사용할 수 있는지 먼저 확인한다.

---

# 4. `아이와 케이 시작하기` 카드 제거

## 현재

부모 홈 상단에 별도의 큰 카드가 존재한다.

예시 구조:

```text
아이와 케이 시작하기

아이 기기에서 로그인하거나
이 기기에서 바로 시작할 수 있어요.

[아이 시작하기]
```

## 변경

이 카드 전체를 부모 홈 본문에서 제거한다.

삭제 대상:

- 카드 외곽
- 카드 제목
- 카드 설명
- 카드 내부 `아이 시작하기` 버튼
- 카드가 차지하던 margin/padding/spacer

중요:

카드를 `display:none` 또는 `visibility:hidden` 처리하여 빈 공간을 남기지 않는다.

카드가 사라진 공간만큼 `오늘의 한마디`와 아래 인사이트 카드 영역이 자연스럽게 위로 올라와야 한다.

---

# 5. 최상단 헤더에 `아이 시작하기` CTA 추가

## 최종 헤더 구조

```text
[내친구 케이 로고]   [아이 시작하기]   [아이 이름 ▼]   [알림]
```

화면 폭에 따라 요소 간격을 반응형으로 조정하되, 모바일에서도 한 줄 유지가 가능하면 한 줄을 우선한다.

## 위치

`아이 시작하기` 버튼은:

- 로고와 아이 선택 영역 사이
- 또는 기존 아이 선택 이름 바로 왼쪽

에 배치한다.

핵심은 부모가 홈 화면에 들어왔을 때 즉시 찾을 수 있어야 한다는 것이다.

---

# 6. `아이 시작하기` CTA 디자인

이번 CTA는 부모 홈에서 시각적 우선순위가 높은 핵심 버튼이다.

## 색상

브랜드 오렌지 계열을 사용한다.

권장 방향:

```text
background: K Orange
text: white
```

현재 프로젝트에 이미 정의된 `--color-k-orange` 또는 동일 브랜드 컬러가 있으면 그것을 우선 사용한다.

임의의 새로운 오렌지 값을 추가하지 않는다.

## 크기

모바일 기준 권장:

- 높이: 36~42px
- 좌우 padding: 12~16px
- font-size: 13~15px
- font-weight: 700
- border-radius: 10~14px 또는 pill형

터치 영역은 최소 약 44px 수준을 확보할 수 있도록 주변 hit area를 고려한다.

## 강조

허용:

- 약한 shadow
- 약한 hover/pressed 효과
- 선택/터치 시 색상 변화

금지:

- 과도한 glow
- 큰 애니메이션
- 헤더의 다른 기능을 가리는 과도한 크기

---

# 7. 기존 `아이 시작하기` 동작 재사용

헤더의 새 버튼을 누르면 기존 카드의 `아이 시작하기` 버튼과 **완전히 동일한 동작**을 수행해야 한다.

반드시 재사용:

- 기존 모달
- 기존 모달 내용
- 기존 아이 선택/실행 흐름
- 기존 인증/세션
- 기존 callback
- 기존 아이 로그인/진입 처리

새로운 모달을 별도로 만들지 않는다.

기존 클릭 핸들러를 공통 함수로 분리하여 재사용하는 방식은 허용한다.

QA에서는 기존 카드 버튼과 동일한 화면/동작이 열리는지 확인한다.

---

# 8. `오늘의 한마디` 영역 확대

현재 부모 홈의 핵심 정보 카드 중 가장 먼저 보는 영역이므로 가독성을 크게 높인다.

## 목표

```text
오늘의 한마디

아이가 개학 후 일상 및 수업에 대해
아빠와 대화하고 싶어 했습니다.
```

## 변경

- 카드 제목 확대
- 본문 확대
- line-height 확대
- 카드 내부 padding 확대
- 네이비 배경은 유지
- 텍스트 대비 강화

모바일 권장 시작값:

### 제목
- 14~16px 이상
- font-weight: 600~700

### 본문
- 17~20px
- font-weight: 600~700
- line-height: 1.45~1.6

현재 부모 화면의 실제 값과 비교 후 과도하지 않게 조정한다.

---

# 9. 8개 인사이트 카드 전면 가독성 확대

현재 8개 카드의 정보 구조와 클릭 기능은 유지한다.

대상:

1. 학교·학원 생활
2. 친구 관계
3. 마음 흐름
4. 관심사·취향
5. 공부 고민
6. 디지털·콘텐츠
7. 선생님·어른
8. 반복 이야기

## 카드 최종 구조

```text
[큰 아이콘] 학교·학원 생활

개학 후 학교 생활 이야기
```

## 변경 사항

### 아이콘
현재보다 크게.

권장:
- 현재 대비 약 20~35% 확대
- 이모지/아이콘 시각 크기 명확하게

### 카드 제목
현재보다 훨씬 크게.

권장:
- 16~18px
- font-weight: 700

### 카드 설명
부모가 바로 읽을 수 있게 확대.

권장:
- 13~15px 이상
- line-height 1.4~1.5
- 너무 작은 회색 글씨 금지

### 카드 높이
글씨가 커지는 만큼 적절히 증가시킨다.

단, 불필요한 빈 여백을 크게 만들지 않는다.

### 카드 테두리
각 카드 영역이 명확히 구분되도록:

- border 대비 소폭 강화
- radius 유지 또는 조금 키움
- shadow는 약하게

---

# 10. 카드 배치

모바일에서는 2열 구조를 유지한다.

```text
학교·학원 생활     친구 관계
마음 흐름          관심사·취향
공부 고민          디지털·콘텐츠
선생님·어른        반복 이야기
```

요구사항:

- 두 열 너비 동일
- 카드 간 gap 충분히 확보
- 카드 안의 텍스트가 잘리지 않음
- 제목이 2줄까지 가도 레이아웃 유지
- 화면 가로 스크롤 금지

작은 모바일에서는 필요 시 카드 높이가 자연스럽게 증가하도록 한다.

---

# 11. 불필요한 작은 텍스트 최소화

이번 개편의 핵심은 단순 확대뿐 아니라 **작게 반복되는 정보의 시각적 우선순위를 낮추는 것**이다.

부모가 홈에서 바로 봐야 하는 정보:

1. 아이 시작하기
2. 오늘의 한마디
3. 각 인사이트 카테고리 제목
4. 각 카테고리 핵심 한 줄

그 외 작은 설명·중복된 메타정보가 있다면 UI에서 최소화한다.

단, 실제 데이터나 DB를 삭제하지 않는다.

---

# 12. 부모 하단 네비게이션 확대

부모 홈 하단 네비게이션도 동일한 가독성 원칙을 적용한다.

대상:

```text
홈
리포트
케이와 대화
설정
```

## 변경

- 전체 nav 높이 확대
- 아이콘 확대
- 라벨 글씨 확대
- 아이콘과 라벨 사이 간격 확대
- 터치 영역 확대
- 선택 상태를 더 명확하게

부모 공통 하단 네비게이션 컴포넌트라면 부모 홈에만 적용하지 않고 아래 전체에 공통 반영한다.

- 부모 홈
- 리포트
- 케이와 대화
- 설정

화면마다 네비게이션 크기가 달라지면 안 된다.

---

# 13. 헤더 반응형 정책

모바일 360~390px에서도 아래 요소가 한 화면에 안정적으로 들어와야 한다.

```text
로고 | 아이 시작하기 | 아이 이름 | 알림
```

필요하면:

- 로고 폭 축소
- 보호자/아이 이름의 최대 너비 설정
- 이름 말줄임
- 버튼 padding 반응형 처리

를 적용한다.

단:

- `아이 시작하기` CTA를 숨기지 않는다.
- 알림 아이콘을 숨기지 않는다.
- 가로 스크롤을 만들지 않는다.

---

# 14. PC/태블릿 대응

부모 홈은 모바일뿐 아니라 PC/태블릿에서도 자연스럽게 보여야 한다.

## 태블릿/PC

- 부모 홈 콘텐츠 max-width 유지
- 중앙 정렬
- 인사이트 카드는 화면 폭에 따라 2열 또는 기존 데스크톱 구조 유지
- 폰트가 지나치게 작아지지 않음
- 반대로 모바일 글씨를 그대로 과도하게 확대하지 않음

이번 작업의 핵심은 모바일 가독성이지만 기존 PC 화면을 깨면 안 된다.

# 17. QA 시나리오

## 아이 시작하기

1. 부모 홈 진입
2. 기존 `아이와 케이 시작하기` 카드가 완전히 사라졌는지 확인

4. 헤더에 주황색 `아이 시작하기` 버튼 확인

1. 오늘의 한마디 가독성 확인

3. 카드 설명 읽기 쉬운지 확인
4. 카드 클릭 정상
5. 카드 겹침 없음
6. 가로 스크롤 없음

부모 홈 → 리포트 → 케이와 대화 → 설정 이동 후:

- 동일한 nav 높이
- 동일 icon size
- 동일 label size
- 현재 선택 상태 정상
- 모든 터치 정상
