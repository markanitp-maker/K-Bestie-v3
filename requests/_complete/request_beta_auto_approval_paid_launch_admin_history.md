# 베타 자동 승인·정식 오픈 결제 완료 자동 승인 및 관리자 이력 유지

## 1. 목적

부모가 `부모 설정 > 아이 추가`에서 아이 정보를 입력하고 `승인 요청 보내기`를 눌렀을 때 운영 단계에 따라 승인 절차를 자동화한다.

- 베타 기간: 관리자 수동 승인 없이 즉시 자동 승인
- 정식 오픈 후: 결제 완료가 서버에서 검증된 경우 자동 승인
- 기존 관리자 승인 페이지: 그대로 유지
- 자동 승인된 건도 관리자 화면에 승인 완료 이력으로 표시
- 기존 수동 승인·거절·상세 조회 기능 유지

자동 승인이라고 승인 요청 레코드나 관리자 감사 이력을 생략하지 않는다.

---

## 2. 확정 정책

### 베타 기간

1. 부모가 아이 정보 입력
2. `승인 요청 보내기` 클릭
3. 기존 승인 요청 레코드 생성
4. 같은 서버 처리에서 즉시 승인 완료
5. 아이 계정, `child_profiles`, 가족 연결, 법정대리인 동의 기록 생성
6. 아이 상태를 `active/approved`로 전환
7. 부모 화면에 `승인되었습니다` 모달 표시
8. 부모와 아이가 즉시 사용
9. 관리자 승인 페이지에는 `승인 완료`
10. 승인 방식은 `자동 승인(베타)` 표시

### 정식 서비스 오픈 후

1. 부모가 `승인 요청 보내기` 클릭
2. 아이 추가 요청을 `결제 대기` 상태로 저장
3. 결제 안내 모달 표시
4. `결제 페이지로 이동` 버튼 제공
5. 서버에서 결제 성공 검증
6. 검증 성공 시 자동 승인
7. 아이 계정·프로필·가족 연결 활성화
8. 관리자 승인 페이지에는 `승인 완료`
9. 승인 방식은 `자동 승인(결제 완료)` 표시

결제 실패, 취소, 만료 또는 서버 검증 실패 시 승인하지 않는다.

### 기존 관리자 수동 승인

기존 수동 승인·거절·상세 조회 기능은 유지한다. 수동 승인 건은 `수동 승인`으로 표시한다.

## 3. 부모 화면

### 베타 자동 승인 완료 모달

제목:

```text
승인되었습니다
```

본문 예시:

```text
아이 등록이 완료되었습니다.
지금 바로 내친구 케이를 이용할 수 있습니다.
```

버튼:

```text
확인
```

확인 후 다음 영역에 즉시 반영한다.

- 부모 홈 자녀 선택
- 아이 정보 관리
- 아이 승인 요청 현황
- 리포트 자녀 선택
- 케이와 대화
- 미션
- 놀이
- 30일 이벤트
- 아이 로그인

별도 새로고침이나 재로그인이 없어야 한다.

### 정식 오픈 결제 안내 모달

제목 예시:

```text
결제가 필요합니다
```

본문 예시:

```text
아이 등록과 서비스 이용을 위해 결제가 필요합니다.
결제 완료 후 아이 계정이 자동 승인됩니다.
```

주요 버튼:

```text
결제 페이지로 이동
```

보조 버튼:

```text
취소
```

결제 전에는 아이를 활성화하지 않는다.

## 4. 운영 단계 분기

운영 단계는 서버의 단일 설정값으로 관리한다.

권장 예시:

```ts
type ServicePhase = "BETA" | "PAID_LAUNCH";
```

금지:

- 날짜를 여러 파일에 하드코딩
- 클라이언트 요청값으로 운영 단계 결정
- 프런트엔드에서 승인 방식 결정
- Dev와 Production 운영 단계가 의도치 않게 공유되는 구조

권장:

- 서버 전용 환경변수
- 운영 설정 테이블
- 관리자 운영 설정
- 코드 재배포 없이 운영 단계 변경 가능

## 5. 승인 상태 및 승인 방식

기존 상태값을 우선 재사용하고 필요한 경우 최소 확장한다.

권장 상태:

```ts
type ApprovalStatus =
  | "PENDING"
  | "PENDING_PAYMENT"
  | "APPROVED"
  | "REJECTED"
  | "CANCELLED"
  | "PAYMENT_FAILED";
```

권장 승인 방식:

```ts
type ApprovalMethod =
  | "BETA_AUTO"
  | "PAYMENT_AUTO"
  | "ADMIN_MANUAL";
```

화면 표시:

| 내부 값 | 관리자 표시 |
|---|---|
| `BETA_AUTO` | 자동 승인(베타) |
| `PAYMENT_AUTO` | 자동 승인(결제 완료) |
| `ADMIN_MANUAL` | 수동 승인 |

추가 확인 필드:

- `requested_at`
- `approved_at`
- `approved_by`
- `approval_method`
- `payment_id`
- `payment_status`
- `updated_at`

시스템 자동 승인 시 실제 관리자 계정으로 위장하지 않는다.

## 6. 관리자 승인 페이지

기존 관리자 승인 페이지와 데이터 조회 구조를 유지한다.

### 자동 승인 건

베타:

```text
상태: 승인 완료
승인 방식: 자동 승인(베타)
요청일시: YYYY-MM-DD HH:mm
승인일시: YYYY-MM-DD HH:mm
```

결제 완료:

```text
상태: 승인 완료
승인 방식: 자동 승인(결제 완료)
요청일시: YYYY-MM-DD HH:mm
승인일시: YYYY-MM-DD HH:mm
```

### 수동 승인 건

```text
상태: 승인 완료
승인 방식: 수동 승인
승인자: 관리자
```

### 버튼 처리

이미 승인 완료된 자동 승인 건은:

- 승인 버튼 숨김 또는 비활성화
- 거절 버튼 숨김 또는 비활성화
- 상세 조회와 이력 확인은 가능

결제 대기 건은 `결제 대기`로 표시한다. 결제 없이 관리자 수동 승인 가능 여부는 기존 정책이 없다면 임의로 추가하지 않는다.

가능하면 다음 필터를 제공한다.

- 승인 대기
- 결제 대기
- 승인 완료
- 거절
- 자동 승인(베타)
- 자동 승인(결제 완료)
- 수동 승인

---

## 7. 승인 요청 이력

자동 승인이라고 기존 승인 요청 레코드를 생략하지 않는다.

예상 대상:

```text
child_approval_requests
```

처리 원칙:

- 요청 레코드 생성
- 같은 서버 처리에서 승인 상태 전환
- 요청일시와 승인일시 모두 기록
- 관리자 화면에서 조회 가능
- 가입 당시 정보는 감사 이력으로 보존
- 승인 완료 후 부모 화면은 최신 `child_profiles` 정보 표시

---

## 8. 아이 계정 생성 및 활성화

승인 완료 시 다음이 일관되게 생성 또는 연결되어야 한다.

- 아이 Auth 계정
- `child_profiles`
- 가족 연결
- 부모-아이 관계
- 법정대리인 동의 기록
- 이용 권한
- 활성 상태
- 리포트 대상
- 미션 대상
- 놀이 대상
- 30일 이벤트 대상

일부만 생성되는 고아 데이터가 없어야 한다.

---

## 9. 트랜잭션·롤백·멱등성

다음 작업은 가능한 한 하나의 트랜잭션 또는 보상 롤백으로 보호한다.

1. 승인 요청 생성
2. 아이 계정 생성
3. 자녀 프로필 생성
4. 가족 연결
5. 법정대리인 동의 기록
6. 승인 상태 변경
7. 사용 가능 상태 전환

중간 실패 시:

- 승인 완료 상태만 남지 않음
- Auth 계정만 남지 않음
- 프로필만 남지 않음
- 가족 연결 없는 자녀가 남지 않음
- 재시도 시 중복 생성되지 않음

멱등 처리 대상:

- 버튼 연속 클릭
- 네트워크 재시도
- 앱 재전송
- 결제 웹훅 중복 수신
- 서버 타임아웃 후 재실행

권장 멱등 키:

- 승인 요청 ID
- 가족 ID + 아이 로그인 아이디
- 결제 주문 ID
- 결제 transaction ID
- request id

## 10. 결제 검증

정식 오픈 후에는 클라이언트 성공 페이지 이동만으로 승인하지 않는다.

반드시 다음 중 하나를 사용한다.

- 결제 제공자 웹훅
- 서버 결제 승인 API 조회
- 서버 주문 상태 검증

금지:

- `?success=true`만 보고 승인
- localStorage 값으로 승인
- 결제 페이지에서 돌아왔다는 이유로 승인
- 프런트엔드가 `approved=true` 전송

결제 웹훅 서명 검증과 중복 이벤트 방지가 필요하다.

---

## 11. 결제 전 입력 데이터

정식 오픈 후 결제 전 아이 정보는 안전한 대기 상태로 보존한다.

보존 대상:

- 성
- 이름
- 로그인 아이디
- 성별
- 학년
- 관심사
- 법정대리인 동의
- 가족 ID

주의:

- 비밀번호 평문 저장 금지
- 결제 전 Auth 계정 생성 여부는 기존 구조 확인
- 미리 생성한다면 비활성 상태
- 실패·취소·만료 요청의 개인정보 보존 정책 준수

---

## 12. 기존 검증 유지

자동 승인에서도 다음 검증은 유지한다.

- 로그인 아이디 중복
- 비밀번호 정책
- 이름 필수값
- 성별
- 학년
- 관심사
- 법정대리인 동의
- 가족별 아이 수 제한
- 부모 권한
- 다른 가족 ID 주입 차단
- 중학교 1학년 실제 저장 및 콘텐츠 6학년 매핑

클라이언트가 `approval_method`나 운영 단계를 지정할 수 없게 한다.

---

## 13. DB 변경 후보

기존 스키마를 확인한 뒤 필요한 경우 최소 변경한다.

```sql
approval_method text
approved_at timestamptz
approved_by uuid
payment_id text
payment_status text
```

권장 CHECK:

```sql
CHECK (
  approval_method IN (
    'BETA_AUTO',
    'PAYMENT_AUTO',
    'ADMIN_MANUAL'
  )
  OR approval_method IS NULL
)
```

결제 ID는 필요 시 unique index를 적용해 중복 승인을 방지한다.

## 14. 관리자 감사 로그

상태 변경 시 다음을 기록한다.

- 요청 ID
- 이전 상태
- 이후 상태
- 승인 방식
- 시스템 또는 관리자 actor
- 승인 시각
- 결제 참조 ID
- 실패 사유
- 재시도 여부

비밀정보와 개인정보 원문은 로그에 남기지 않는다.

## 15. 테스트 시나리오

### 베타 자동 승인

1. 운영 단계 `BETA`
2. 부모 로그인
3. 아이 정보 입력
4. `승인 요청 보내기` 클릭
5. 승인 요청 레코드 생성
6. 즉시 `APPROVED`
7. `approval_method = BETA_AUTO`
8. `approved_at` 기록
9. 부모 모달 `승인되었습니다`
10. 부모 아이 목록 즉시 표시
11. 아이 로그인 성공
12. 관리자 화면 `승인 완료 / 자동 승인(베타)`

### 베타 중복 클릭

- 승인 요청 1건
- 아이 계정 1건
- 가족 연결 1건
- 최종 승인 완료

### 정식 오픈 결제 전

1. 운영 단계 `PAID_LAUNCH`
2. 아이 정보 입력
3. 버튼 클릭
4. 결제 안내 모달
5. `결제 페이지로 이동`
6. 상태 `PENDING_PAYMENT`
7. 아이 사용 불가
8. 관리자 화면 `결제 대기`

### 결제 성공

1. 서버에서 결제 성공 검증
2. 상태 `APPROVED`
3. `approval_method = PAYMENT_AUTO`
4. 아이 활성화
5. 관리자 화면 `승인 완료 / 자동 승인(결제 완료)`

### 결제 실패·취소

- 승인하지 않음
- 아이 사용 불가
- 관리자 화면에 대기·실패 상태 표시

### 결제 웹훅 중복

- 요청 1건
- 아이 계정 1건
- 승인 1회
- 중복 이벤트는 멱등 처리

### 기존 수동 승인

- 승인·거절·상세 조회 정상
- `approval_method = ADMIN_MANUAL`
- 관리자 화면 `수동 승인`

### 자동 승인 완료 건

- 승인 버튼 숨김 또는 비활성화
- 거절 버튼 숨김 또는 비활성화
- 상세 조회 가능
- 요청·승인 시각과 승인 방식 표시

### 복수 자녀

- 각 요청 독립 처리
- 자녀 간 오매핑 없음

### 실패 롤백

각 단계 강제 실패 후 고아 데이터와 중복 데이터가 없어야 한다.

## 16. Dev·Production

### Dev

- `BETA`와 `PAID_LAUNCH` 모두 테스트
- 테스트 결제 또는 mock 결제 사용
- Production 결제와 분리

### Production

- 베타 기간: `BETA`
- 정식 오픈 시: `PAID_LAUNCH`
- 코드 재배포 없이 설정 변경으로 전환 권장
- 운영 단계 변경 권한 제한
- 변경 이력 기록

## 17. 완료 조건

- 베타 아이 추가 즉시 자동 승인
- 부모 `승인되었습니다` 모달
- 즉시 서비스 사용 가능
- 관리자 승인 페이지에 자동 승인 이력 표시
- 관리자 상태 `승인 완료`
- 승인 방식 `자동 승인(베타)`
- 정식 오픈 후 결제 안내 모달
- `결제 페이지로 이동` 버튼
- 결제 전 승인 금지
- 서버 검증된 결제 성공 후 자동 승인
- 승인 방식 `자동 승인(결제 완료)`
- 기존 수동 승인·거절·상세 조회 유지
- 자동 승인 완료 건 재승인 불가
- 요청·승인 시각 보존
- 중복 클릭·중복 웹훅에 중복 생성 없음
