# 067 — 부모 공통 헤더 `아이 시작하기` 중앙 고정 및 전 탭 공통 노출

## 1. 작업 목적

현재 부모 홈 상단 헤더에 있는 `아이 시작하기` 버튼을 화면 가로 기준 정확한 중앙에 고정하고, 홈 화면뿐 아니라 부모용 주요 탭 전체에서 동일하게 항상 노출되도록 공통 헤더 구조를 정리한다.

적용 대상:

- 홈
- 리포트
- 케이와 대화
- 설정

이번 작업은 UI 배치와 공통화 작업이며, 기존 `아이 시작하기` 기능과 모달 동작은 그대로 유지한다.

---

## 2. 최종 헤더 구조

모든 부모 주요 화면에서 아래 구조를 동일하게 사용한다.

```text
[내친구 케이 로고]      [아이 시작하기]      [아이 이름 ▼] [알림]
                           ↑
                     화면 정중앙 고정
```

핵심은 `아이 시작하기` 버튼이 좌우 요소의 실제 폭과 관계없이 **화면의 정확한 중앙**에 위치해야 한다는 것이다.

---

## 3. `아이 시작하기` 버튼 위치

### 현재 문제

일반적인 `flex justify-between` 구조에서는 왼쪽 로고 폭, 오른쪽 아이 이름 길이, 알림 버튼 폭이 달라질 때 가운데 버튼이 시각적으로 좌우로 밀릴 수 있다.

### 목표

`아이 시작하기` 버튼의 중심점이 항상 viewport 또는 부모 헤더 콘텐츠 영역의 정확한 50% 위치에 있어야 한다.

권장 구현 방식:

### 옵션 A — absolute center

```css
position: absolute;
left: 50%;
transform: translateX(-50%);
```

### 옵션 B — 3-column grid

```css
display: grid;
grid-template-columns: 1fr auto 1fr;
```

- 왼쪽: 로고
- 가운데: 아이 시작하기
- 오른쪽: 아이 선택 + 알림
- 오른쪽 영역은 `justify-self: end`

현재 프로젝트 구조와 반응형 안정성을 확인해 더 안전한 방식을 선택한다.

단순 margin 보정이나 임의 px 오프셋으로 가운데를 맞추지 않는다.

---

## 4. 버튼 디자인

현재 적용된 `아이 시작하기` 강조 스타일은 유지한다.

- 브랜드 오렌지 배경
- 흰색 또는 현재 사용 중인 대비 높은 텍스트
- 굵은 글씨
- 둥근 버튼
- 충분한 터치 영역
- 현재 shadow/pressed 효과 유지 가능

이번 작업에서 버튼을 다시 작게 만들거나 색상을 약하게 만들지 않는다.

---

## 5. 기존 기능 재사용

`아이 시작하기` 버튼 클릭 시 현재 부모 홈에서 정상 동작 중인 기존 모달/시작 흐름을 그대로 호출한다.

새 모달을 만들지 않는다.

반드시 유지:

- 기존 아이 선택/시작 모달
- 기존 상태값
- 기존 인증/세션
- 기존 아이 시작 흐름
- 기존 callback/라우팅

필요하면 클릭 핸들러를 공통 함수 또는 공통 Provider로 정리해 여러 부모 탭에서 재사용한다.

---

## 6. 전 탭 공통 적용

아래 모든 부모 주요 페이지에서 동일한 헤더가 보여야 한다.

### 홈
- 로고
- 중앙 `아이 시작하기`
- 아이 선택
- 알림

### 리포트
- 로고
- 중앙 `아이 시작하기`
- 아이 선택
- 알림

### 케이와 대화
- 로고
- 중앙 `아이 시작하기`
- 아이 선택
- 알림

### 설정
- 로고
- 중앙 `아이 시작하기`
- 아이 선택
- 알림

페이지마다 헤더 구현을 복제하지 않는다.

가능하면 부모 공통 헤더 컴포넌트 하나로 통합하고 각 페이지에서 재사용한다.

## 7. 구현 전 필수 확인

코드 수정 전에 다음을 확인한다.

1. 현재 부모 홈 상단 헤더 구현 파일
2. 부모 리포트 상단 헤더 구현 파일
3. 케이와 대화 상단 헤더 구현 파일
4. 설정 상단 헤더 구현 파일
5. 이미 존재하는 부모 공통 헤더 컴포넌트 여부
6. `아이 시작하기` 버튼 클릭 핸들러와 모달 상태 관리 위치
7. 아이 선택 드롭다운 구현 위치
8. 알림 버튼 구현 위치

이미 공통 헤더가 있다면 해당 컴포넌트를 수정한다.

없다면 최소한의 공통 `ParentTopHeader` 형태로 정리한다.

## 8. 반응형 정책

### 모바일 우선

검증 기준:

- iPhone 390×844
- Android 360×800
- Android 412×915

모바일에서도 한 줄 구조를 우선한다.

```text
로고 | 아이 시작하기 | 아이 이름 | 알림
```

공간이 부족한 경우:

- 로고 max-width 축소
- 아이 이름 max-width 제한
- 아이 이름 말줄임 처리
- 좌우 padding 반응형 축소

가능하다.

하지만 아래 요소는 숨기지 않는다.

- 아이 시작하기
- 아이 선택
- 알림

가로 스크롤도 만들지 않는다.

---

## 9. 아이 이름 길이 대응

아이 이름이 길거나 선택 UI가 넓어져도 중앙 버튼이 밀리면 안 된다.

권장:

```css
max-width: ...
white-space: nowrap;
overflow: hidden;
text-overflow: ellipsis;
```

단, 드롭다운 기능은 유지한다.

---

## 10. 알림 버튼

기존 종 아이콘과 알림 기능을 그대로 유지한다.

이번 작업에서 알림 UI/알림 데이터 구조는 변경하지 않는다.

단, 중앙 CTA 정렬을 위해 오른쪽 영역의 내부 gap을 조정하는 것은 허용한다.

## 13. QA 시나리오

### 중앙 정렬

각 페이지에서 `아이 시작하기` 버튼의 `getBoundingClientRect()`를 측정한다.

계산:

```text
buttonCenterX = left + width / 2
viewportCenterX = window.innerWidth / 2
```

목표:

```text
|buttonCenterX - viewportCenterX| <= 2~3px
```

### 탭별 확인

1. 홈 접속
2. 중앙 정렬 확인
3. 리포트 이동
4. 중앙 위치 동일 확인
5. 케이와 대화 이동
6. 중앙 위치 동일 확인
7. 설정 이동
8. 중앙 위치 동일 확인

### 아이 이름 변경

- 짧은 이름
- 긴 이름

모두 확인한다.

버튼 중앙 위치가 변하면 실패다.

### 버튼 기능

각 탭에서 `아이 시작하기` 클릭 후:

- 기존 모달 표시
- 기존 아이 시작 흐름 정상

확인한다.
