- 병렬 처리: 불가(다른 트랙과 겹치지 않으나 `app/page.tsx`를 다시 손대므로 단독 처리)
- 예상 충돌 파일: 없음(AUTH-SIGNUP-AUTOLOGIN 완료 후 착수하므로)

## 현재 상태(조사 결과)

- **루트 라우팅**: `app/page.tsx`(`HubPage`)는 클라이언트에서 `getUser()` → 실패 시
  `router.replace("/login")`으로 즉시 리다이렉트한다(72-75행). 이 지시서는 그 대신
  GUEST 상태일 때 리다이렉트 없이 랜딩페이지를 그 자리에 렌더링하도록 바꾼다. 다른
  분기(ACTIVE_PARENT/ACTIVE_CHILD/SUSPENDED/DELETED/AUTHENTICATED_INCOMPLETE)는 전혀
  건드리지 않는다.
- **`/login`**: 이미 완전히 동작하는 별도 페이지로 존재한다(`app/login/page.tsx`) —
  카카오/구글 OAuth + 아이 아이디·비밀번호 로그인, 마스코트(`/Images/mascot/mascot-standing.png`),
  `--color-k-navy`/`--color-k-surface` 토큰 사용 중. **새로 만들 필요 없음** — 랜딩페이지의
  "기존 회원 로그인" 버튼은 이 경로로 링크만 한다.
- **베타 신청 메커니즘(중요 발견)**: `app/beta/apply/page.tsx`는 죽은 스텁이다 —
  코드 주석에 "053: 부모 계정 단위 베타 신청 흐름을 제거했다"고 명시돼 있고
  `/onboarding`으로 즉시 리다이렉트만 한다. `POST /api/beta/apply`(`beta_applications`
  테이블)는 아직 라우트 자체는 살아있지만 로그인된 사용자만 호출 가능해 익명 방문자용
  랜딩페이지에서 쓸 수 없고, 현재 이 API를 호출하는 살아있는 UI 진입점이 없다(고아
  상태). 반면 `REQUEST-AUTH-SIGNUP-AUTOLOGIN`이 방금 구현한 실제 "베타 기간" 정책은
  §7.1 — 보호자가 회원가입 후 아이를 등록하면 **자동 승인**된다
  (`lib/plan/autoApproveChildRequest.ts`). 즉 "베타 테스터 신청" = 그냥 `/signup`으로
  가입하는 것이 현재의 진짜 정책이다. 별도 외부 베타 신청 사이트도 코드베이스·환경변수
  어디에도 없음(확인됨). **결론: "베타 테스터 신청하기" 버튼은 `/signup`으로 연결한다.**
  죽은 `beta_applications`/`app/beta/apply` 경로는 부활시키지 않는다.
- **개인정보처리방침/이용약관**: 별도 페이지가 코드베이스에 없다. 다만
  `lib/plan/consentDocument.ts`에 실제로 회원가입 시 보여주는 법정대리인 개인정보
  수집·이용 동의문(`CONSENT_DOCUMENT_TEXT`)이 이미 존재한다 — 이걸 그대로 노출하는
  `/privacy` 페이지를 새로 만든다(문구 창작 아님, 기존 실제 문서 재사용). **이용약관은
  대응하는 실제 문서가 어디에도 없다** — 임의로 작성하지 않고 "준비 중" 처리한다(056의
  FAQ 미설정 처리와 동일 패턴).
- **FAQ**: `NEXT_PUBLIC_FAQ_URL`이 이미 Dev 환경변수에 설정돼 있다
  (`https://beta.k-bestie.co/FAQ`, 056에서 설정) — 그대로 재사용한다.
- **운영주체·연락처**: 코드베이스 어디에도 실제 사업자명/연락처 정보가 없다. 임의
  작성 금지 원칙에 따라 만들지 않고, 이용약관과 마찬가지로 "준비 중"으로 표시한다 —
  대표님이 실제 정보를 주시면 이후 채운다.
- Dev URL: `https://k-bestie-v3-dev.vercel.app`

## 요구사항

### 헤더
- 좌: 로고(`/Images/logo/Logo.png`), 우: "기존 회원 로그인" 버튼(`/login`로 링크)
- 모바일 56-64px / 데스크톱 72px, `position: sticky`, 흰 배경 + 하단 `--color-k-border` 구분선

### 히어로
- 마스코트(`mascot-standing.png`), 제목 "아이의 하루를 이해하는 새로운 방법"
- 설명: "내친구 케이는 아이와 케이의 대화를 부모에게 필요한 요약과 오늘의 대화거리로
  연결하는 AI 소통 서비스입니다."
- 주 CTA "베타 테스터 신청하기" → `/signup`, 보조 CTA "서비스 미리보기" → 페이지 내
  기능 소개 섹션으로 스크롤(anchor)
- 감시/진단/교육 AI 프레이밍 금지 — 소통 지원 서비스로만 표현

### 베타 안내
- 제목 "베타 테스터를 모집합니다", 대상 3개 항목, 제공 내용 4개 항목(무료 이용, 미션+자유대화,
  일일·주간·월간 리포트, 케이와 놀이) 그대로 반영
- **선정 문구를 쓰지 않는다** — 실제 정책이 자동 승인이므로 "회원가입을 완료하시면
  바로 베타를 시작하실 수 있어요" 식으로 정직하게 표현(선착순/심사 뉘앙스 금지)

### 서비스 이용 흐름
- 5단계(보호자 회원가입 → 가족 만들기 → 아이 추가 → 관리자 확인 및 승인 → 아이가
  케이와 대화 시작), "관리자 확인 및 승인" 단계는 "아이 등록 내용을 확인한 뒤 이용할
  수 있어요"처럼 쉬운 말로 표현(실제로는 자동 승인이지만 원문 지시서의 5단계 흐름
  자체는 유지 — 승인이 "즉시" 이뤄진다는 뉘앙스만 살린다)

### 베타 신청
- 버튼 "베타 테스터 신청하기" → `/signup` (별도 폼 없음, 위 조사 결과 참조)

### 푸터
- 개인정보처리방침 → `/privacy`(신규, 실제 동의문 재사용)
- 이용약관 → 비활성 표시 "이용약관 준비 중입니다"(FAQ 미설정과 동일 패턴)
- 문의하기/FAQ → `NEXT_PUBLIC_FAQ_URL`
- 운영주체·연락처 → 비활성 표시 "사업자 정보 준비 중입니다"

### 반응형
- 원문 지시서의 모바일 390×844 / 태블릿 768px+ / 데스크톱 1280px+ 스펙을 그대로 따른다
  (여백, 마스코트 높이, 제목 크기, 카드 열 수 등 원문 수치 참조)

### 기존 로그인 처리
- `/login`은 이미 있으므로 이동 작업 없음. `app/page.tsx`의 GUEST 분기만 랜딩페이지
  렌더로 교체(리다이렉트 제거). 그 외 상태별 분기, OAuth callback, 아이 로그인 API는
  일절 변경하지 않는다.
