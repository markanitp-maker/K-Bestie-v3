# 부모 궁금증 처리 엔진 구현 요청 — 초등학교 6학년 v1.0

## 1. 작업 목적

부모가 케이에게 자유 입력으로 아이에 관한 질문을 남겼을 때, 해당 질문을 초등학교 6학년 발달 단계와 서비스 안전 원칙에 따라 `CRISIS`, `RED`, `GREEN`으로 분류하고, 허용된 질문만 부모 확인 후 아이 미션 대화에 편입하도록 구현한다.

이 문서는 **6학년 전용 명세**다. 현재 개발 중인 4학년 구현은 수정·재설계·롤백하지 않고 기준 인터페이스로 유지한다.

정책 식별값:

```text
policy_version: PQR-G6-1.0
source_grade: 6
applicable_grades: [6]
default_route: RED
production_enabled: false
expert_review_status: PENDING_REVIEW
```

## 2. 구현 불변식

1. 기본값은 `RED`다.
2. 판정 순서는 `CRISIS → RED → GREEN → DEFAULT_RED`로 고정한다.
3. 부모 문장을 아이에게 그대로 전달하지 않는다.
4. Green List에 명확히 매칭될 때만 아이 질문 대기열에 등록한다.
5. 애매한 입력은 Green으로 추정하지 않는다.
6. 아이가 “몰라”, “없어”, “말하기 싫어”, “넘어갈래”라고 하면 꼬리질문 없이 종료한다.
7. 부모 질문에서 파생된 답변은 반드시 재확인하고, 아이가 최종 확인한 내용만 부모에게 전달한다.
8. Crisis 감지·문구는 임상 검증 전 Production에서 활성화하지 않는다.
9. LLM 단독 Green 판정은 금지한다.
10. Green 승인 질문만 Q&A와 미션 질문 대기열에 등록한다.

## 3. 기존 제한 정책 통합

- 아이별 주 3회
- 아이별 하루 최대 1회
- KST 기준
- 주간 기준: 월요일 00:00:00 ~ 일요일 23:59:59
- 초안 모달 열기·취소·Red·Crisis·등록 실패는 차감하지 않음
- Green 질문 최종 승인 및 DB 저장 성공 시에만 차감
- 중복 클릭·네트워크 재시도에도 중복 등록·중복 차감 금지
- 세션당 부모 질문 최대 1개
- 아이 상태가 적절하지 않으면 해당 세션 삽입 생략 가능

## 4. 고정 판정 흐름

```text
부모 입력
→ 인증·부모-아이 권한 확인
→ 대상 아이 학년=6 확인
→ CRISIS 감지
→ RED 패턴·의미 매칭
→ GREEN 화이트리스트 매칭
→ Green 4조건 최종 검증
→ 초안 질문 생성
→ 부모 확인 모달
→ 최종 승인
→ 질문 대기열 등록
```

Green 4조건:

```text
1. 원인·갈등·비밀 캐기 없음
2. 아이가 질문 사실을 알아도 부담·방어가 크지 않음
3. 긍정 또는 중립 정서
4. 유도 프레임 없음
```

## 5. 분류 아키텍처

권장 구조:

```text
정규화
→ Crisis deterministic gate
→ Red deterministic/semantic gate
→ LLM candidate classification
→ Green whitelist validator
→ deterministic final gate
```

LLM은 부모 의도 요약, 후보 area 분류, 질문 개수 추정, 핵심 궁금증 추출, Green 확정 후 문장 재작성만 담당한다. 최종 route는 정책 엔진이 결정한다.


## 6. GREEN LIST

프라이버시 방어와 자율성 의식을 최우선으로 존중하며 감시로 인식될 가능성을 최소화한다.

| green_id | area | 부모 의도 | 부모 확인용 초안 | 아이 실제 질문 |
|---|---|---|---|---|
| G-01 | interest | 요즘 관심사, 빠진 것 | 요즘 가장 관심 가는 것이 있는지 물어볼까요? | 요즘 제일 관심 가는 거 있어? |
| G-02 | school_fun | 학교에서 기억에 남은 순간 | 오늘 학교에서 기억에 남는 순간이 있었는지 물어볼까요? | 오늘 학교에서 기억에 남는 순간 있었어? |
| G-03 | subject_like | 관심 가는 과목 | 요즘 관심 가는 수업이 있는지 물어볼까요? | 요즘 수업 중에 관심 가는 거 있어? |
| G-04 | food_pref | 먹고 싶은 것 | 요즘 꽂힌 음식이 있는지 물어볼까요? | 요즘 꽂힌 음식 있어? |
| G-05 | pride | 뿌듯했던 일 | 최근 뿌듯하게 느낀 일이 있는지 물어볼까요? | 최근에 ‘이건 좀 뿌듯했다’ 싶은 거 있었어? |
| G-06 | content | 콘텐츠·유행 | 요즘 가장 자주 보는 콘텐츠가 무엇인지 물어볼까요? | 요즘 제일 자주 보는 거 뭐야? |
| G-07 | weekend | 주말 계획 | 이번 주말에 하고 싶은 것이 있는지 물어볼까요? | 이번 주말에 하고 싶은 거 있어? |
| G-08 | dream | 관심 있는 진로 | 요즘 해보고 싶은 일이 있는지 물어볼까요? | 요즘 ‘이런 거 해보고 싶다’ 싶은 거 있어? |

공통 Green 규칙:

- 부모 원문 그대로 전달 금지
- 한 번에 질문 1개
- 부모 확인용 문장과 아이 실제 질문 분리 저장
- 아이가 거절하면 즉시 종료
- 기존 미션 완료 조건과 분리
- 부모 개입 사실 비노출

## 6. 6학년 특칙

- 세션 초반에 “말하고 싶지 않은 건 넘어가도 괜찮아” 안내 1회
- 각 질문마다 거부권 문구를 반복하지 않음
- 부모 질문 편입 빈도를 낮춰 감시 인식 최소화
- 아이가 “넘어갈래”라고 하면 해당 질문 재시도 금지
- 외모·몸·식사, 이성 관계, SNS 감시는 강한 Red 게이트
- 외모·식사 반복 우려는 Crisis 승격 검토 대상
- 은유·간접 위기 표현 감지는 임상 검증 최우선 항목

## 7. RED LIST

| red_id | area | 차단 의도 | 부모 코칭 문구 |
|---|---|---|---|
| R-01 | emotion_cause | 기분의 원인 캐기 | 6학년은 원인을 캐물으면 방어부터 할 수 있어요. 케이는 대신 캐묻지 않고, 직접은 ‘무슨 일 있으면 언제든 이야기해’처럼 여지만 열어 주세요. |
| R-02 | peer_conflict | 친구 갈등·따돌림·소외 확인 | 이 나이에는 친구 문제를 캐물으면 오히려 입을 닫을 수 있어요. 판단 없이 들을 준비를 보여 주고, 소외·괴롭힘이 의심되면 담임·상담 선생님과 상의해 주세요. |
| R-03 | academic_pressure | 성적·공부량·중학 대비 추궁 | 성적 압박은 대화를 끊는 원인이 될 수 있어요. 결과보다 노력과 아이가 느끼는 부담에 반응해 주세요. |
| R-04 | secret | 비밀·거짓말 적발 | 케이는 아이 몰래 알아내는 도구가 아니에요. 신뢰를 지키기 위해 이 요청은 전달하지 않아요. |
| R-05 | family_complaint | 가족 불만 확인 | 가족에 대한 아이 마음은 케이가 대신 캐묻지 않아요. 아이가 먼저 꺼낼 여지를 두세요. |
| R-06 | appearance_body | 외모·몸무게·식사량 확인 | 외모·몸·식사 관련은 케이가 대신 캐묻지 않고 리포트에도 수치로 다루지 않아요. 우려되면 전문 상담을 권해요. |
| R-07 | romance | 이성 관계 확인 | 이성 관계는 케이가 대신 캐묻지 않아요. 사생활 존중이 신뢰의 핵심이에요. |
| R-08 | sns_control | SNS 통제·감시 | SNS 사용을 케이가 감시하거나 캐묻지 않아요. 규칙은 아이와 함께 정하시길 권해요. |
| R-09 | fallback | Green 미매칭 전부 | 이 질문은 이 학년 허용 질문에 명확히 해당하지 않아 아이에게 전달하지 않아요. 추궁하지 않는 다른 질문으로 바꾸거나 리포트를 확인해 주세요. |

R-06~R-08은 강한 Red 게이트로 처리한다. 단순 키워드만이 아니라 아이에게 해당 내용을 캐묻거나 감시하려는 부모 의도가 확인되면 Red로 확정한다.

## 8. CRISIS 경로

아래 신호는 Green/Red 판정 전에 가로챈다.

- 자해·자살·죽고 싶다는 표현
- 학대·성적 피해
- 심각한 폭력
- 지속적·심한 따돌림 또는 소외
- 섭식 이상
- 아이 안전에 즉각적인 우려가 있는 표현

처리 원칙:

- 아이 질문 대기열 등록 금지
- 부모 질문 횟수 차감 금지
- 아이에게 우회 질문 금지
- 일반 로그에 원문 저장 금지
- 내부에는 최소 분류 코드만 저장
- `expert_review_status='PENDING_REVIEW'`
- 임상 전문가 승인 전 `production_enabled=false`

## 9. 초안 모달 및 Q&A 연동

Green 확정 시에만 아래 흐름을 실행한다.

```text
Green 확정
→ 부모 확인용 초안 생성
→ 대상 아이·주간 N/3·오늘 N/1 표시
→ 부모 수정·승인
→ 서버 최종 검증
→ 질문 대기열 등록
→ Q&A에 ‘질문 대기 중’ 표시
```

부모 확인용 문장과 아이 실제 질문을 분리 저장한다.

필수 필드:

```text
source='PARENT_QUERY_ROUTER'
source_grade=6
policy_version='PQR-G6-1.0'
router_route='GREEN'
router_rule_id
parent_draft_text
child_question_text
expert_review_status
```

## 10. 미션 연동

- 기존 4학년 구현의 API·DB·Q&A·미션 대기열 인터페이스를 재사용한다.
- 4학년 구현을 공통화한다는 이유로 재설계하지 않는다.
- Green 승인 질문만 미션 질문 대기열에 넣는다.
- 한 미션에 부모 질문 최대 1개
- 기존 미션 유효 답변 10개에 포함하지 않음
- 부모가 시켰다는 사실 비노출
- 아이 답변 후 재확인 필수
- 아이가 최종 확인한 답변만 부모에게 전달
- 아이가 거절하면 즉시 `DECLINED`
- 미확인 STT 결과를 부모에게 전달 금지

## 11. 테스트 요구사항

### 판정 순서

- Crisis+Green → Crisis
- Red+Green → Red
- Green 근거 없음 → Default Red
- LLM confidence 높음+화이트리스트 미매칭 → Red
- LLM Green+Red 패턴 감지 → Red

### 제한

- 주 1·2·3회 성공, 4회 차단
- 같은 날 두 번째 등록 차단
- 취소·Red·Crisis·API 실패 미차감
- 중복 클릭·재시도 중복 등록 0건

### 미션 E2E

1. Green 질문 등록
2. Q&A `질문 대기 중`
3. 다음 미션에서 자연스럽게 질문
4. 부모 개입 문구 미노출
5. 아이 답변
6. 케이 재확인
7. 아이 최종 확인
8. 부모 Q&A `답변 완료`
9. 미션 유효 답변 10개 미포함
10. 다른 가족 데이터 혼입 0건

### 거부 E2E

1. 아이가 “말하기 싫어” 응답
2. 꼬리질문 0회
3. 상태 `DECLINED`
4. 부모에게 거부 사실만 표시
5. 거부 원문·이유 추측 비노출
