
# REQUEST 018 — 대화 데이터 맥락 기반 보정 파이프라인 구축

## 1. 작업 목적

내친구 케이 서비스에서 아이와 케이가 나눈 미션 대화 및 자유대화는 STT 기반 음성 데이터이므로 원문 그대로 리포트 생성에 사용할 경우 발음 오류, 오인식, 문맥 단절로 인해 품질 저하가 발생한다.

따라서 일일 리포트 생성 전에 다음 중간 처리 단계를 추가한다.

```text
Raw 대화 데이터 저장
→ AI 맥락 기반 보정
→ 보정 데이터 저장
→ 보정 데이터 기반 리포트 생성
```

목표:

- 아이 발화의 STT 오류를 문맥 기반으로 보정
- 아이가 말하지 않은 내용을 AI가 생성하지 않도록 제한
- 리포트 품질 향상
- 부모 대시보드 8개 상태 데이터 정확도 향상

---

# 2. 최종 데이터 구조

내친구 케이 리포팅 데이터는 3단계로 분리한다.

## 2.1 Raw 대화 데이터

목적:

STT 원본과 실제 대화 흐름 보존

보관:

- 리포트 생성 완료 후 7일
- 이후 자동 삭제

저장 대상:

- 아이 발화 STT 결과
- 케이 발화
- 대화 순서
- 세션 정보
- 미션 정보
- 자유대화 정보
- timestamp
- session_id
- child_id


예시:

```json
{
  "child_id": "xxx",
  "session_id": "xxx",
  "speaker": "child",
  "raw_text": "친구랑 피구해써 내가 마지막에 사라써",
  "created_at": "2026-07-26T18:10:00"
}
```

---

## 2.2 맥락 보정 데이터

목적:

리포트 생성용 검증 데이터

보관:

- 리포트 생성 완료 후 7일
- 이후 자동 삭제

Raw 데이터를 기반으로 Gemini를 이용해 생성한다.

저장 내용:

- 보정된 문장
- 보정 상태
- 보정 이유
- 신뢰도
- 리포트 사용 가능 여부


예시:

```json
{
  "child_id": "xxx",
  "session_id": "xxx",
  "corrected_text": "친구와 피구를 했고 마지막까지 살아남았다고 이야기함",
  "status": "corrected",
  "report_eligible": true,
  "confidence": 0.91
}
```

---

## 2.3 리포트 데이터

목적:

부모 화면 제공 데이터

보관:

기존 상품별 데이터 보존 정책 적용

생성 기준:

```text
corrected_daily_conversations
        ↓
generateDailyReports
        ↓
daily_reports
```

Raw 데이터와 보정 데이터를 직접 리포트 생성 입력으로 사용하지 않는다.

# 4. Raw 데이터 수집

18:00과 23:59:59 배치 실행 시 다음 데이터를 수집한다.

대상:

- 완료 미션
- 진행 중 미션
- 미완료 미션 중 아이 발화 존재
- 자유대화
- 이어하기 세션


제외:

- 빈 발화
- 시스템 메시지
- 오류 메시지
- 테스트 데이터


중요:

미션 완료 여부만으로 데이터를 버리지 않는다.

아이의 실제 발화가 있으면 Raw 데이터 대상이다.

# 5. AI 맥락 기반 보정 처리

## 처리 방식

Raw 데이터 저장 완료 후 Gemini 기반 보정 실행


입력:

- 아이 STT 원문
- 케이 직전 질문
- 이전 1~3턴 대화
- 현재 미션 질문
- 세션 타입
  - mission
  - free_chat
- 아이별 기존 확정 정보
  - 이름
  - 친구 이름
  - 관심사
  - 자주 사용하는 표현


---

# 6. 보정 AI 규칙

반드시 적용한다.

## 허용

가능:

- 띄어쓰기 수정
- 명백한 발음 오류 수정
- 조사 수정
- 문맥상 확실한 단어 수정
- 고유명사 후보 기반 수정


## 금지

절대 금지:

- 아이가 하지 않은 내용 추가
- 감정 임의 생성
- 친구 관계 추론
- 학교 사건 생성
- 부모가 듣고 싶어 하는 방향으로 변경
- 의미가 달라지는 수정


예:

허용:

```
학교에서 피구했어 → 학교에서 피구했어
사라써 → 살아남았어
```

금지:

```
친구와 사이가 좋아졌다
→ 실제 발화 근거 없음
```

```json
{
  "corrected_text": "",
  "status": "unchanged|corrected|uncertain|rejected",
  "confidence": 0,
  "report_eligible": true,
  "correction_reason": "",
  "uncertain_reason": ""
}
```

---

# 8. 불확실 데이터 처리

확신할 수 없는 경우:

보정하지 않는다.

예:

Raw:

```
민준이가 뭐라고 했어
```

문맥 부족:

```json
{
 "status":"uncertain",
 "report_eligible":false
}
```


불확실 데이터를 부모 리포트에 사실처럼 사용하지 않는다.

---

# 9. 리포트 생성 변경

기존:

```text
대화 데이터
→ 리포트 생성
```

변경:

```text
보정 데이터
→ 리포트 생성
```


리포트 생성기는 반드시:

```text
report_eligible=true
```

인 데이터만 사용한다.
