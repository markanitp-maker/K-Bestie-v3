현재 리포팅 구조를 점검하고 아래 방향으로 수정하라. 기존 REQUEST 017에서 해결된 자유대화 포함, Edge Function 배포, 스케줄 문제는 다시 수정하지 말고 현재 구현 상태를 유지하라. 현재 발견된 핵심 문제는 세션 종료 즉시 생성되는 리포트와 하루 1회 배치 리포트 생성 구조가 동시에 존재하여 daily_reports 생성 기준이 충돌하는 것이다.

목표 구조는 다음으로 변경한다.

아이와 케이 대화
→ 대화 원본 저장
→ 세션 종료 시 리포트 생성 금지
→ 18:00 KST / 23:59:59 KST 하루 2회 대화 데이터 수집
→ Raw 대화 데이터 저장
→ Gemini 기반 맥락 보정 데이터 생성
→ corrected conversation 데이터 저장
→ 새벽 03:00 KST 일일 배치에서 corrected 데이터만 사용하여 daily_reports 생성
→ 부모 대시보드 아이 상태 8개 항목 업데이트

구현 요구사항:

1. 세션 종료 즉시 리포트 생성하는 기존 경로를 제거하거나 비활성화하라.
- app/api/report/generate 등 세션 종료 시 호출되는 즉시 리포트 생성 경로를 확인하라.
- 세션 종료 이벤트에서는 리포트를 만들지 말고 대화 저장만 수행하도록 변경하라.
- 기존 daily_reports 중복 생성 방지 로직은 유지하라.

2. Raw 대화 데이터와 보정 데이터를 분리하라.
- Raw 데이터는 아이와 케이가 주고받은 STT 기반 대화 원본이다.
- Raw 데이터는 리포트 생성 검증 목적으로만 사용한다.
- Raw 데이터와 보정 데이터는 일일 리포트 생성 완료 후 7일 동안 보관하고 자동 삭제한다.
- 최종 리포트 데이터는 기존 상품별 보존 정책을 따른다.

3. 대화 보정 파이프라인을 추가하라.
처리 흐름:
Raw conversation
→ Gemini 맥락 기반 보정
→ corrected conversation 저장

보정 입력:
- 아이 STT 원문
- 케이 직전 질문
- 이전 대화 턴
- 현재 미션 질문
- session_type(mission/free_chat)
- child_id 기반 확정 컨텍스트

보정 규칙:
- 띄어쓰기, 명백한 발음 오류, 문맥상 확실한 오인식만 수정한다.
- 아이가 말하지 않은 사실을 추가하지 않는다.
- 친구 관계, 감정, 학교 사건을 임의 추론하지 않는다.
- 확실하지 않은 내용은 uncertain 처리한다.

4. 리포트 생성 입력을 변경하라.
기존:
대화 원본 또는 세션 종료 생성 데이터

변경:
corrected conversation 중 report_eligible=true 데이터만 사용

리포트 생성:
03:00 KST 배치에서 하루치 데이터를 기준으로 1회 생성한다.

5. 부모 대시보드 업데이트 기준 변경
부모 대시보드 아이 상태 8개 항목은 반드시 새벽 daily_reports 생성 결과를 기준으로 갱신한다.
세션 종료 시 임시 상태값이나 부분 리포트를 부모 화면에 노출하지 않는다.

6. 관리자 수동 실행 기능 유지
관리자 화면의 기능은 다음 구조로 유지한다.

즉시 대화 수집:
Raw 수집
→ 보정 데이터 생성
→ 저장

즉시 리포트 생성:
corrected conversation
→ daily_reports 생성
→ 부모 대시보드 업데이트

특정 아이와 전체 사용자 선택 기능은 유지한다.

7. 기존 코드 영향 분석
수정 전에 반드시 확인하라.

- 세션 종료 리포트 생성 호출 위치
- daily_reports insert/upsert 위치
- 새벽 batch 생성 위치
- 부모 dashboard API 데이터 흐름
- corrected 데이터 저장 위치

불필요한 리팩터링은 하지 말고 리포팅 생성 책임만 하나로 통합하라.

8. 검증 기준

완료 조건:
- 세션 종료 후 daily_reports가 즉시 생성되지 않는다.
- 하루 데이터가 Raw로 저장된다.
- Raw 기반 보정 데이터가 생성된다.
- 새벽 03:00 배치가 corrected 데이터 기반으로 daily_reports를 생성한다.
- 부모 대시보드 8개 항목이 해당 daily_reports 기준으로 표시된다.
- 같은 날짜, 같은 아이의 리포트가 중복 생성되지 않는다.
- Raw 및 corrected 데이터는 리포트 생성 완료 후 7일 뒤 자동 삭제된다.

작업 완료 후 다음 형식으로 보고하라.

1. 기존 즉시 리포트 생성 경로
2. 제거 또는 변경한 파일
3. 현재 최종 데이터 흐름
4. Raw 데이터 저장 위치
5. corrected 데이터 저장 위치
6. daily_reports 생성 위치
7. 부모 대시보드 연결 상태
8. 7일 삭제 정책 적용 여부
9. E2E 검증 결과
10. 남은 BLOCKER 여부
