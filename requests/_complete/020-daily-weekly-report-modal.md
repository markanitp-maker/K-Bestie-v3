# REQUEST 020 — 일일·주간 리포트 카드 상세 모달 구현

## 1. 작업 목적

부모 리포트 화면에서 일일 또는 주간 리포트 카드를 클릭하면 별도 페이지로 이동하지 않고, 선택한 리포트의 상세 내용을 모달 팝업으로 표시한다.

모달에서는 다음 세 가지 탭을 제공한다.

1. 빠른 요약
2. 상세 보기
3. 추천 가이드

---

## 2. 핵심 요구사항

```text
일일 리포트 카드 클릭
→ 선택한 일일 리포트 모달 표시

주간 리포트 카드 클릭
→ 선택한 주간 리포트 모달 표시
```

- 카드의 특정 버튼이 아니라 카드 전체 영역을 클릭 가능하게 한다.
- 페이지 이동과 전체 새로고침은 발생하지 않아야 한다.
- 선택한 리포트의 `report_id`를 기준으로 상세 데이터를 불러온다.
- 모달을 닫으면 기존 탭과 목록 스크롤 위치를 유지한다.

---

## 3. 적용 대상

다음 목록 화면에 모두 적용한다.

- 일일 리포트 목록
- 주간 리포트 목록

일일·주간 탭의 기존 디자인과 목록 구조는 유지한다.

---

## 4. 리포트 카드 클릭 동작

### 4.1 일일 리포트

일일 리포트 카드 클릭 시 다음 값을 기준으로 모달을 연다.

- `reportType: daily`
- `reportId`
- `childId`
- `businessDate`

선택한 일자의 일일 리포트만 표시한다.

### 4.2 주간 리포트

주간 리포트 카드 클릭 시 다음 값을 기준으로 모달을 연다.

- `reportType: weekly`
- `reportId`
- `childId`
- `weekStartDate`
- `weekEndDate`

선택한 기간의 주간 리포트만 표시한다.

최신 리포트를 임의로 다시 선택하거나 일일 데이터를 조합해 주간 리포트처럼 표시하지 않는다.

---

## 5. 모달 UI

모달 상단에 다음 탭과 닫기 버튼을 표시한다.

```text
[빠른 요약] [상세 보기] [추천 가이드]    [X]
```

### 기본 탭

모달을 처음 열었을 때 기본 선택 탭은 `빠른 요약`이다.

### 공통 표시 정보

- 아이 이름
- 일일 리포트 날짜 또는 주간 리포트 기간
- 선택한 탭의 내용
- 우측 상단 닫기 버튼
- 콘텐츠 내부 세로 스크롤

---

## 6. 빠른 요약 탭

부모가 짧은 시간 안에 리포트 핵심을 이해할 수 있도록 요약된 내용을 표시한다.

### 일일 리포트

- 오늘의 한마디
- 주요 감정 또는 마음 상태
- 주요 사건
- 관심사
- 변화 신호
- 오늘의 대화거리

### 주간 리포트

- 이번 주 한마디
- 주간 감정 흐름
- 주요 사건
- 반복된 관심사
- 지난주 대비 변화
- 이번 주 대화 포인트

상세 리포트의 긴 문장을 그대로 반복하지 않는다.

---

## 7. 상세 보기 탭

선택한 리포트의 전체 분석 내용을 표시한다.

### 일일 리포트

- 학교·학원 생활
- 친구 관계
- 마음 흐름
- 관심사·취향
- 공부 고민
- 디지털·콘텐츠
- 선생님·어른
- 반복 이야기
- 주요 변화 신호
- 부모 전달 메시지

### 주간 리포트

- 주간 학교·학원 생활
- 주간 친구 관계
- 주간 마음 흐름
- 주간 관심사·취향
- 주간 공부 고민
- 주간 디지털·콘텐츠
- 선생님·어른 관련 변화
- 반복 주제
- 주요 변화 신호
- 주간 종합 요약

실제 DB와 API에 존재하는 값만 표시한다.

화면에서 분석 내용을 임의 생성하지 않는다.

---

## 8. 추천 가이드 탭

리포트 분석 결과를 바탕으로 부모가 아이와 자연스럽게 대화할 수 있는 가이드를 표시한다.

### 표시 항목

- 아이에게 건넬 첫 문장
- 후속 질문 2~3개
- 피해야 할 질문 또는 표현
- 부모가 관찰할 포인트
- 함께할 수 있는 행동 제안

### 작성 기준

- 심문이나 추궁처럼 느껴지지 않도록 한다.
- 아이의 실제 대화 근거를 사용한다.
- 전문 진단처럼 표현하지 않는다.
- 바로 사용할 수 있는 짧은 문장으로 표시한다.

---

## 9. 데이터 조회 기준

모달은 반드시 사용자가 클릭한 카드의 `report_id`를 기준으로 데이터를 조회한다.

다음 조건을 모두 검증한다.

- `report_id` 일치
- `child_id` 일치
- 리포트 유형 일치
- 일일 날짜 또는 주간 기간 일치
- 정상 완료된 리포트인지 확인
- 다른 아이 데이터 혼합 금지

과거 리포트를 클릭하면 해당 과거 리포트를 표시해야 한다.

최신 리포트로 자동 대체하지 않는다.

---

## 10. API

기존 부모 리포트 API를 우선 재사용한다.

기존 API에서 상세 데이터를 제공하지 않는 경우 프로젝트 규칙에 맞춰 상세 조회 API를 추가한다.

예시:

```text
GET /api/parent/reports/{reportId}
```

요청한 사용자가 해당 아이의 보호자인지 서버에서 검증한다.

클라이언트가 전달한 `child_id`만 신뢰하지 않는다.

---

## 11. 로딩 및 오류 처리

### 로딩 중

모달 프레임을 먼저 표시하고 콘텐츠 영역에 다음 상태를 표시한다.

```text
리포트를 불러오고 있어요.
```

### 조회 실패

```text
리포트를 불러오지 못했어요.
잠시 후 다시 확인해 주세요.
```

### 일부 데이터 부족

부족한 항목에만 다음과 같이 표시한다.

```text
이 항목은 확인할 대화가 충분하지 않아요.
```

`새로운 이야기가 있어요`와 같은 의미 없는 placeholder는 사용하지 않는다.

---

## 12. 모달 닫기

다음 방식으로 모달을 닫을 수 있어야 한다.

- 우측 상단 `X`
- 모달 외부 배경 클릭
- 모바일 뒤로 가기
- 브라우저 뒤로 가기
- 데스크톱 `Escape`

모달을 닫은 뒤 다음 상태를 유지한다.

- 일일·주간 선택 탭
- 현재 월
- 목록 스크롤 위치
- 선택된 아이

---

## 13. 모바일 UX

첨부 이미지와 같은 모바일 화면을 기준으로 구현한다.

- 모달은 화면 안전 영역 안에서 표시한다.
- 하단 내비게이션과 겹치지 않도록 한다.
- 탭과 닫기 버튼은 모달 상단에 고정한다.
- 내용이 길면 모달 콘텐츠 영역만 스크롤한다.
- 모달이 열린 동안 배경 화면 스크롤을 잠근다.
- 모달을 닫으면 기존 목록 위치로 복귀한다.
- 긴 텍스트가 모달 밖으로 넘치지 않도록 한다.

---

## 14. 접근성

- `role="dialog"`
- `aria-modal="true"`
- 모달 제목과 `aria-labelledby` 연결
- 모달이 열리면 내부로 포커스 이동
- 모달 내부 포커스 고정
- 닫은 뒤 클릭했던 리포트 카드로 포커스 복귀
- 탭에 `role="tab"`과 선택 상태 적용
- 키보드 탭 이동과 `Escape` 닫기 지원

---

## 15. 캐시 및 상태 관리

상세 데이터 캐시 키에는 다음 값을 포함한다.

- `childId`
- `reportType`
- `reportId`

다른 아이나 다른 리포트의 데이터가 재사용되지 않도록 한다.

리포트가 관리자 수동 생성 또는 자동 배치로 갱신되면 해당 상세 캐시를 무효화한다.

1. 일일 탭 진입
2. 특정 일일 리포트 카드 클릭
3. 모달 표시 확인

7. 모달 닫기
8. 기존 목록 위치 유지 확인

### 시나리오 B — 주간 리포트

1. 주간 탭 진입
2. 특정 주간 리포트 카드 클릭
3. 선택한 주간 기간의 모달 표시 확인
4. 세 개 탭 정상 전환 확인

### 시나리오 C — 과거 리포트

과거 날짜의 리포트 카드를 클릭한다.

예상 결과:

- 클릭한 과거 `report_id`의 데이터 표시
- 최신 리포트로 교체되지 않음

### 시나리오 D — 다자녀 계정

1. 첫 번째 아이 리포트 열기
2. 모달 닫기
3. 두 번째 아이 선택
4. 두 번째 아이 리포트 열기

예상 결과:

- 다른 아이 데이터 혼합 없음
- 이전 아이 캐시 노출 없음

### 시나리오 E — 긴 상세 내용

예상 결과:

- 모달 내부만 스크롤
- 탭과 닫기 버튼 고정
- 배경 스크롤 잠금

### 시나리오 F — 일부 데이터 부족

예상 결과:

- 존재하는 내용은 정상 표시
- 부족한 섹션만 데이터 부족 표시
- 모달 전체를 실패 처리하지 않음
