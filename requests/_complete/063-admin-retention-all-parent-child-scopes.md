# 관리자 리텐션 전체·부모·아이 3개 기준 전환 구현

## 1. 작업 목적

관리자 `/admin/retention` 페이지에서 리텐션을 다음 3가지 기준으로 전환하여 확인할 수 있도록 구현한다.

```text
전체 리텐션
부모 리텐션
아이 리텐션
```

가족 기준으로 합치지 않는다.

전체 리텐션은 부모 계정과 아이 계정을 각각 독립 사용자로 합산하여 계산한다.

예시:

```text
부모 1명 + 아이 2명
→ 전체 리텐션 사용자 3명
```

---

## 2. 확정 계산 기준

### 전체 리텐션

```text
부모 user_id + 아이 child_id
```

- 부모와 아이를 각각 독립 사용자로 계산
- 가족 단위로 합치지 않음
- 부모 1명과 아이 2명이 있으면 총 3명
- 동일 인물 중복 집계 방지
- 부모 ID와 아이 ID namespace 충돌 방지

### 부모 리텐션

```text
parent user_id
```

- 부모 계정만 계산
- 아이 활동은 부모 리텐션에 포함하지 않음
- 부모의 실제 핵심 활동 기준으로 계산

### 아이 리텐션

```text
child_id
```

- 아이 계정만 계산
- 부모 활동은 아이 리텐션에 포함하지 않음
- 아이의 실제 핵심 활동 기준으로 계산

---

## 3. 화면 구성

조회 기간 필터 아래 또는 핵심 지표 상단에 다음 탭을 추가한다.

```text
전체 리텐션 | 부모 리텐션 | 아이 리텐션
```

### 기본 탭

기본값은 다음으로 한다.

```text
전체 리텐션
```

### 탭 전환

탭을 누르면 다음 모든 데이터를 해당 사용자 유형 기준으로 다시 조회·계산한다.

- 핵심 KPI 카드
- D1
- D3
- D7
- D14가 존재하면 D14
- W2
- DAU
- 코호트
- 사용자 상세 드릴다운
- CSV 다운로드
- 사용자 규모
- 활성 사용자
- 신규 사용자
- 재방문 사용자
- 해당 사용자 유형에 적용 가능한 행동 지표

## 5. 리텐션 정의

### Day 0

각 사용자 유형별 최초 핵심 행동일을 Day 0으로 사용한다.

#### 부모 Day 0

다음 중 최초 발생일:

- 부모 홈 실제 진입
- 일일 리포트 조회
- 주간 리포트 조회
- 월간 리포트 조회
- 오늘의 대화거리 조회
- 부모와 케이 대화
- 서비스 관련 설정 저장

단순 가입일이나 승인 대기일만으로 계산하지 않는다.

#### 아이 Day 0

다음 중 최초 발생일:

- 미션 시작
- 미션 유효 답변
- 미션 완료
- 자유대화 시작
- 자유대화 실제 진행
- 놀이 시작
- 놀이 완료

### D1·D3·D7·D14

각 사용자 유형별 Day 0 이후 해당 날짜에 핵심 행동이 있으면 유지 사용자로 계산한다.

```text
전체 = 부모와 아이를 독립 사용자로 합산
부모 = parent user_id
아이 = child_id
```

### W2

가입 또는 최초 사용 후 8~14일 구간에 핵심 행동이 1회 이상 있으면 W2 유지로 계산한다.

부모와 아이 각각 독립 계산한다.

전체 탭에서는 부모 W2 대상과 아이 W2 대상을 합산한다.

## 6. 활성 사용자 정의

### 부모 활성

다음 중 1개 이상:

- 부모 홈 실제 진입
- 일일·주간·월간 리포트 조회
- 오늘의 대화거리 조회
- 부모와 케이 대화
- 아이 정보 저장
- 보호자 설정 저장
- 기타 부모 핵심 기능

단순 로그인 성공만으로 활성 처리하지 않는다.

### 아이 활성

다음 중 1개 이상:

- 미션 시작
- 미션 유효 답변
- 미션 완료
- 자유대화 시작
- 자유대화 실제 진행
- 놀이 시작
- 놀이 완료

단순 로그인만으로 활성 처리하지 않는다.

### 전체 활성

```text
부모 활성 사용자 수 + 아이 활성 사용자 수
```

가족 단위 dedupe를 하지 않는다.

## 8. API 설계

다음 파라미터 또는 동등한 방식을 사용한다.

```text
scope=all
scope=parent
scope=child
```

예시:

```text
/api/admin/retention/overview?scope=all
/api/admin/retention/overview?scope=parent
/api/admin/retention/overview?scope=child
```

### API 원칙

- 기본값 `scope=all`
- 허용되지 않은 값은 400
- 관리자 권한 서버 검증
- 카드·DAU·코호트·상세·CSV 모두 동일한 scope 사용
- 클라이언트 전용 필터 금지
- 서버 공통 집계 함수 사용
- scope별 분모·분자 일치
- no-store 또는 최신 데이터 정책 유지

## 9. 공통 사용자 키

전체 리텐션에서 부모 ID와 아이 ID가 우연히 동일한 문자열이어도 충돌하지 않도록 namespace를 분리한다.

예시:

```text
parent:<user_id>
child:<child_id>
```

전체 사용자 distinct 계산 시 다음 키를 사용한다.

```text
parent:51bd...
child:e74a...
```

단순 UUID 문자열만 합쳐 distinct 처리하지 않는다.


필요하면 차트에서 다음을 함께 표시한다.

- 아이

### 부모 DAU

부모 활성만 표시한다.

### 아이 DAU

아이 활성만 표시한다.

## 12. 상세 드릴다운

### 전체 리텐션 탭

- 부모와 아이를 모두 표시
- 사용자 유형 컬럼 추가
- 표시값:

```text
부모 | Mark An (markanitp@gmail.com)
아이 | 안서아 (asa@kbestie.local)
```

### 부모 리텐션 탭

- 부모만 표시
- UUID 대신 이름과 로그인 아이디 표시

### 아이 리텐션 탭

- 아이만 표시
- UUID 대신 이름과 로그인 아이디 표시

가족 상세 탭은 별도 운영 정보로 유지할 수 있으나, 리텐션 scope 계산에는 사용하지 않는다.

## 13. CSV 다운로드

현재 선택된 탭과 필터 기준으로 다운로드한다.

파일명 예시:

```text
retention-all-2026-08-03.csv
retention-parent-2026-08-03.csv
retention-child-2026-08-03.csv
```

CSV 필수 컬럼:

- 사용자 유형
- 이름
- 로그인 아이디
- 최초 사용일
- 마지막 활동일
- D1
- D3
- D7
- W2
- 활동일 수
- 내부 테스트 계정 여부

전체 UUID는 기본 CSV에 포함하지 않는다.

운영상 필요하면 마스킹 ID만 별도 컬럼으로 제공한다.

## 19. 작업 금지 사항

- 전체 리텐션을 가족 기준으로 계산하지 않는다.
- 부모와 아이를 한 가족으로 dedupe하지 않는다.
- 전체 탭에서 부모·아이 활동을 한 ID 체계로 충돌시키지 않는다.
- 카드만 scope 적용하고 DAU·코호트·상세·CSV를 누락하지 않는다.
- 클라이언트에서만 필터링하지 않는다.
- 부모 활동을 아이 리텐션에 포함하지 않는다.
- 아이 활동을 부모 리텐션에 포함하지 않는다.
- 내부 테스트 계정 필터를 깨뜨리지 않는다.
- Dev만 구현하고 Production을 누락하지 않는다.
- Production 검증 없이 완료 처리하지 않는다.
