# Request: 아이 홈 이벤트 안내 재열람 버튼 추가

## 1. 대상 프로젝트

- 프로젝트: `K-Bestie-v3` 내친구 케이 앱
- 적용 환경: Development 검증 후 Production 동일 적용
- 대상 화면: 아이 홈 화면
- 관련 기능: 이벤트 안내 팝업, 이벤트 안내 확인 이력

## 2. 배경

현재 이벤트 안내 팝업은 아이가 최초 로그인 후 한 번 확인하면 다시 볼 수 없다.

아이 사용자가 이벤트 1과 이벤트 2의 참여 방법 및 상품권 기준을 다시 확인할 수 있도록, 아이 홈 화면에서 이벤트 안내 팝업을 언제든 재열람할 수 있는 진입 버튼이 필요하다.

## 3. 핵심 요구사항

### 3.1 아이 홈 왼쪽 상단 이벤트 버튼

아이 홈 화면 왼쪽 상단에 이벤트 안내 전용 버튼 1개를 추가한다.

- 아이콘: 종 모양
- 라벨: `이벤트`
- 아이콘만 표시하지 말고 `이벤트` 텍스트를 함께 표시한다.
- 기존 오른쪽 상단의 일반 알림 종 버튼과 혼동되지 않도록 시각적으로 구분한다.
- 로고, 안전영역, 자녀 정보, 로그아웃 버튼 등 기존 UI와 겹치지 않아야 한다.
- 모바일과 PWA에서 충분한 터치 영역을 확보한다.

### 3.2 이벤트 안내 팝업 재열람

왼쪽 상단 `이벤트` 버튼을 누르면 최초 로그인 시 노출됐던 이벤트 안내 모달을 다시 연다.

재열람 팝업에는 아래 두 이벤트 설명을 동일하게 표시한다.

#### 이벤트 1. 케이와 친해지는 30일

- 첫 미션을 끝까지 완료하면 시작
- 30일 동안 완료한 미션 횟수에 따라 상품권 지급
- `10번 이상 완료 → 상품권 1,000원`
- `30번 이상 완료 → 상품권 3,000원`
- `50번 이상 완료 → 상품권 5,000원`
- `60번 완료 → 상품권 10,000원`
- 여러 상품권을 누적 지급하지 않고, 30일 동안 달성한 가장 높은 단계의 상품권 1개만 지급

#### 이벤트 2. 퀴즈 리더보드 도전

- 8월, 9월, 10월마다 월별 퀴즈 점수 순위 운영
- `1등 → 상품권 5,000원`
- `2등 → 상품권 3,000원`
- `3등 → 상품권 1,000원`
- 각 월 종료 후 순위 확정
- 다음 달에는 실제 아이의 월별 점수를 0점부터 새로 시작

### 3.3 개인 진행 상태 미표시

이벤트 안내 팝업은 이벤트 규칙을 설명하는 용도로만 사용한다.

아래와 같은 개인별 진행 상태는 팝업에 표시하지 않는다.

- `지금까지 N/60 완료했어요`
- `현재 달성 선물`
- `다음 단계까지 N번 남았어요`
- 이벤트 시작일, 종료일, 남은 기간
- 현재 퀴즈 순위

개인 진행 상태는 아이 홈의 `케이와 친해지는 30일` 진행 카드에서만 표시한다.

## 4. 확인 이력 정책

### 4.1 최초 자동 노출

- 이벤트 안내 버전별로 최초 1회 자동 노출한다.
- 아이가 `이벤트 확인했어요` 버튼을 누르면 서버에 확인 이력을 저장한다.
- 확인 완료 후 재로그인해도 같은 버전의 팝업은 자동으로 다시 노출하지 않는다.

### 4.2 수동 재열람

- 왼쪽 상단 `이벤트` 버튼을 통한 재열람은 단순 조회다.
- 재열람 시 새로운 acknowledgement 행을 만들지 않는다.
- 기존 확인 상태를 초기화하거나 변경하지 않는다.
- 재열람 팝업을 닫은 뒤 재로그인해도 자동 팝업이 다시 나타나지 않아야 한다.
- `localStorage`만으로 처리하지 말고 기존 서버 저장 확인 이력 정책을 유지한다.

## 5. UI/UX 요구사항

- 이벤트 1과 이벤트 2를 서로 다른 카드 또는 명확한 구분 영역으로 표시한다.
- 각 이벤트에 번호 배지 `1`, `2`를 표시한다.
- 팝업 본문은 모바일에서 내부 스크롤 가능해야 한다.
- 하단 확인/닫기 버튼은 화면 하단에 안정적으로 노출한다.
- 재열람 시 버튼 문구는 `닫기` 또는 기존 `이벤트 확인했어요`를 사용할 수 있으나, 서버 확인 이력을 다시 저장하지 않아야 한다.
- 접근성을 위해 이벤트 버튼에 적절한 `aria-label`을 적용한다.

## 6. 구현 원칙

- 기존 최초 자동 노출 로직을 복제하지 말고 동일한 이벤트 모달 컴포넌트를 재사용한다.
- 자동 노출 여부와 수동 재열람 여부를 별도 상태로 관리한다.
- 기존 일반 알림 기능과 이벤트 재열람 기능을 결합하지 않는다.
- 이벤트 정책과 상품권 금액은 하드코딩이 여러 컴포넌트에 중복되지 않도록 단일 상수 또는 설정에서 관리한다.
- Secret, service role key, 토큰, 비밀번호, 개인정보 원문을 코드·로그·문서·임시파일에 출력하지 않는다.

## 7. Development 검증 시나리오

1. 이벤트 안내 미확인 아이로 로그인한다.
2. 최초 로그인 시 이벤트 안내 팝업이 자동으로 1회 노출되는지 확인한다.
3. `이벤트 확인했어요`를 누른다.
4. 로그아웃 후 재로그인한다.
5. 같은 버전의 이벤트 팝업이 자동 노출되지 않는지 확인한다.
6. 아이 홈 왼쪽 상단의 `이벤트` 버튼을 누른다.
7. 이벤트 안내 팝업이 다시 열리는지 확인한다.
8. 이벤트 1과 이벤트 2가 명확히 구분되어 표시되는지 확인한다.
9. 상품권 금액과 문구가 확정 정책과 일치하는지 확인한다.
10. 개인 진행 상태가 팝업에 표시되지 않는지 확인한다.
11. 팝업을 닫고 다시 로그인한다.
12. 수동 재열람 때문에 자동 팝업이 다시 활성화되지 않았는지 확인한다.
13. 모바일, PWA, 작은 화면에서 버튼·팝업·스크롤·하단 버튼이 겹치지 않는지 확인한다.
14. 기존 오른쪽 상단 일반 알림 기능에 회귀가 없는지 확인한다.

## 8. 완료 기준

- 아이 홈 왼쪽 상단에 종 아이콘과 `이벤트` 라벨이 있는 버튼이 노출된다.
- 버튼을 누르면 동일한 이벤트 안내 팝업을 언제든 재열람할 수 있다.
- 최초 자동 노출은 버전별 1회 정책을 유지한다.
- 수동 재열람은 확인 이력을 변경하지 않는다.
- 팝업에는 이벤트 규칙만 표시되고 개인 진행 상태는 표시되지 않는다.
- 이벤트 1·2와 상품권 금액이 확정 문구대로 표시된다.
- Development 검증 통과 후 Production에 동일 적용한다.
