# app.k-bestie.com 랜딩 페이지 온보딩 UX 변경 요청

## 1. 작업 목적

랜딩 페이지 히어로 영역의 주요 행동 유도 버튼을 `시작하기` 하나로 통합하여 사용자의 선택 피로를 줄이고, 소셜 인증 이후 시스템이 기존 사용자와 신규 사용자를 자동으로 구분하여 로그인 또는 회원가입 흐름으로 연결하도록 한다.

이번 변경은 히어로 영역 CTA만 단순화하는 작업이며, 상단 Header의 `로그인`, `회원가입` 메뉴는 그대로 유지한다.

---

## 2. 적용 대상

- 서비스: 내친구 케이
- 운영 도메인: `https://app.k-bestie.com`
- 대상 화면: 랜딩 페이지
- 대상 영역:
  - 히어로 영역 CTA
  - 상단 Header 메뉴
  - 소셜 인증 진입 및 인증 후 분기 처리
- Dev와 Production 모두 동일한 정책으로 반영한다.

---

## 3. 히어로 영역 버튼 변경

### 3.1 현재 상태

히어로 영역에 다음 버튼 2개가 표시되고 있다.

- `베타 신청하기`
- `서비스 미리보기`

### 3.2 변경 요구사항

위 버튼 2개를 모두 제거하고, 기존 버튼이 있던 동일한 위치에 다음 버튼 1개만 배치한다.

- `시작하기`

### 3.3 레이아웃 유지 조건

- 기존 버튼 영역의 위치와 정렬을 그대로 유지한다.
- 히어로 영역 가운데로 이동하지 않는다.
- 새로운 CTA 영역을 만들지 않는다.
- 우측 이미지 영역을 침범하거나 레이아웃 비율을 변경하지 않는다.
- 기존 모바일·태블릿·PC 반응형 배치를 유지한다.
- 버튼 개수가 2개에서 1개로 줄어들더라도 기존 CTA 컨테이너 안에서 자연스럽게 표시한다.
- 랜딩 페이지의 기존 브랜드 색상, 글꼴, 높이, 모서리, hover·focus 스타일을 재사용한다.

### 3.4 표시 문구

```text
시작하기
```

---

## 4. 상단 Header 메뉴 유지

우측 상단의 다음 메뉴는 삭제하거나 변경하지 않는다.

- `로그인`
- `회원가입`

### 유지 목적

- 기존 계정 사용자는 `로그인`을 명확하게 찾을 수 있어야 한다.
- 신규 사용자는 `회원가입`을 명확하게 찾을 수 있어야 한다.
- `시작하기`의 의미를 바로 이해하지 못하는 사용자에게도 명시적인 진입 경로를 제공한다.

Header의 메뉴 순서, 위치, 반응형 동작, 기존 링크 스타일을 유지한다.

---

## 5. `시작하기` 버튼 동작

`시작하기` 버튼을 클릭하면 로그인과 회원가입 중 하나를 먼저 선택하게 하지 않고 소셜 인증 방식 선택 화면 또는 모달로 이동한다.

### 5.1 소셜 인증 방식

다음 두 가지 방식을 제공한다.

- 카카오로 계속하기
- 구글로 계속하기

현재 서비스의 카카오·구글 OAuth 구현을 재사용한다.

별도의 인증 체계를 중복 생성하지 않는다.

### 5.2 인증 완료 후 자동 분기

소셜 인증 완료 후 서버가 현재 인증 사용자와 내친구 케이 회원 상태를 확인하여 자동으로 분기한다.

| 사용자 상태 | 이동 위치 |
|---|---|
| 기존 활성 보호자 계정 | 보호자 로그인 완료 후 기존 목적지 또는 보호자 홈 |
| 기존 가입 진행 중 계정 | 마지막 미완료 회원가입 단계 |
| Auth 계정은 있으나 서비스 회원정보 없음 | 회원가입 1단계 |
| 신규 소셜 인증 사용자 | 회원가입 1단계 |
| 정지 계정 | 이용 제한 안내 |
| 탈퇴·삭제 계정 | 재가입 정책에 따른 안내 또는 로그인 차단 |

### 5.3 핵심 원칙

- 사용자가 로그인과 회원가입 중 하나를 먼저 고민하거나 선택하게 하지 않는다.
- OAuth 인증 성공만으로 회원가입 완료로 판단하지 않는다.
- `auth.users` 존재 여부만으로 기존 회원이라고 판단하지 않는다.
- 보호자 프로필, 회원 상태, 온보딩 완료 상태를 함께 확인한다.
- 신규 사용자가 회원가입 절차 없이 보호자 홈이나 PWA 설치 화면으로 이동하지 않도록 한다.
- 기존 활성 사용자는 불필요하게 회원가입 화면을 다시 보지 않도록 한다.

---

## 6. Header `로그인` 버튼 동작

상단 `로그인` 버튼은 기존 사용자가 명확하게 로그인할 수 있는 진입점으로 유지한다.

### 동작

1. 카카오·구글 로그인 선택
2. 소셜 인증
3. 계정 상태 확인
4. 기존 활성 계정이면 로그인 완료
5. 회원가입 미완료 계정이면 해당 회원가입 단계로 이동
6. 신규 계정이면 회원가입 1단계로 이동

`로그인` 버튼으로 진입했더라도 실제 계정이 없는 사용자를 오류 처리하지 말고 회원가입 흐름으로 연결한다.

---

## 7. Header `회원가입` 버튼 동작

상단 `회원가입` 버튼은 신규 사용자가 명확하게 회원가입을 시작할 수 있는 진입점으로 유지한다.

### 동작

1. 카카오·구글 인증 방식 선택
2. 소셜 인증
3. 시스템이 기존 계정 여부 확인
4. 신규 또는 미완료 계정이면 회원가입 진행
5. 이미 가입 완료된 활성 계정이면 중복 회원가입을 만들지 않고 로그인 완료 후 보호자 홈으로 이동

이미 가입된 사용자가 `회원가입`을 눌렀다는 이유로 두 번째 보호자 계정, 가족 또는 아이가 생성되면 안 된다.

---

## 8. 자동 로그인 연동

랜딩 페이지에 진입했을 때 유효한 세션과 활성 회원 상태가 모두 확인되는 기존 사용자는 자동 로그인 정책을 유지한다.

### 자동 로그인 조건

- 서버에서 검증된 유효한 인증 세션
- 활성 보호자 계정
- 회원가입 완료 상태
- 정지·탈퇴 상태가 아님
- 보호자와 가족 연결이 정상

### 자동 로그인 시 처리

- 사용자가 보호자 홈으로 직접 진입한 경우 랜딩 페이지로 되돌리지 않는다.
- 랜딩 페이지에 방문한 경우 Header 로그인 상태 또는 서비스 이동 버튼을 기존 정책에 맞게 표시한다.
- 신규 OAuth 인증 사용자나 가입 미완료 계정을 활성 사용자로 오판하지 않는다.

---

## 9. 리다이렉트 및 목적지 보존

인증 전 사용자가 특정 서비스 화면에 접근하려다 로그인 화면으로 이동한 경우 안전한 내부 경로에 한해서 인증 후 원래 목적지를 복원한다.

### 허용 원칙

- 같은 서비스 내부 경로만 허용
- 외부 URL 리다이렉트 금지
- `javascript:` 등 비정상 스킴 금지
- 임의 쿼리스트링을 통한 open redirect 금지
- 신규 회원은 회원가입 완료 후에만 원래 목적지로 이동

원래 목적지가 없으면 기본 보호자 홈으로 이동한다.

---

## 10. 소셜 인증 선택 UI

`시작하기`, Header `로그인`, Header `회원가입`은 동일한 소셜 인증 선택 컴포넌트를 재사용한다.

### 필수 항목

- 카카오로 계속하기
- 구글로 계속하기
- 닫기 또는 뒤로 가기
- 인증 실패 메시지
- 재시도

### UX 기준

- 모바일에서 한 손으로 누르기 쉬운 버튼 높이를 유지한다.
- 카카오와 구글 공식 브랜드 표시 규칙을 따른다.
- `로그인`, `회원가입`을 다시 한 번 선택하게 하는 중간 화면은 만들지 않는다.
- 버튼 연속 클릭으로 OAuth 요청이 중복 실행되지 않도록 한다.
- 인증 진행 중 로딩 상태를 표시한다.

---

## 11. 오류 및 예외 처리

### OAuth 취소

```text
로그인이 취소되었습니다. 다시 시도해 주세요.
```

### 인증 실패

```text
로그인을 완료하지 못했습니다. 잠시 후 다시 시도해 주세요.
```

### 회원 상태 확인 실패

```text
회원 정보를 확인하지 못했습니다. 잠시 후 다시 시도해 주세요.
```

### 가입 미완료

```text
이어서 회원가입을 완료해 주세요.
```

### 중복 요청

- OAuth 버튼을 여러 번 눌러도 인증 요청은 한 번만 실행한다.
- OAuth callback이 중복 호출되어도 회원, 가족, 아이 데이터가 중복 생성되지 않아야 한다.

Supabase, OAuth provider, DB의 원본 오류 문구를 사용자 화면에 직접 노출하지 않는다.

---

## 12. 보안 요구사항

- OAuth callback의 `redirectTo`, `next` 값은 허용된 내부 경로만 사용한다.
- 클라이언트의 세션 존재 여부만으로 회원 상태를 확정하지 않는다.
- 서버에서 인증 사용자를 검증한 후 회원 상태를 조회한다.
- 요청 본문의 `user_id`, `role`, `membership_status`를 신뢰하지 않는다.
- `service_role` 키를 클라이언트에 노출하지 않는다.
- 토큰, 쿠키, 이메일, 전화번호 등 민감정보를 로그에 평문으로 출력하지 않는다.
- 신규 사용자 분기 과정에서 RLS를 우회하지 않는다.
- 기존 사용자 데이터, 가족, 아이, 리포트, 대화, 이벤트 데이터는 변경하거나 초기화하지 않는다.

---

## 13. 분석 이벤트

기존 분석 체계가 있다면 다음 이벤트를 중복 없이 추가하거나 기존 이벤트에 통합한다.

- `landing_start_clicked`
- `header_login_clicked`
- `header_signup_clicked`
- `social_auth_provider_selected`
- `social_auth_completed`
- `existing_user_routed_to_login`
- `new_user_routed_to_signup`
- `incomplete_user_resumed_signup`
- `social_auth_failed`

이벤트에는 비밀번호, 토큰, 전화번호, 이름 등 개인정보를 포함하지 않는다.

---

## 14. 필수 테스트 시나리오

### 14.1 랜딩 페이지 UI

- 히어로 영역의 기존 버튼 2개 제거
- 동일 위치에 `시작하기` 버튼 1개 표시
- 버튼이 가운데 또는 새로운 위치로 이동하지 않음
- 우측 이미지와 레이아웃 유지
- Header `로그인`, `회원가입` 유지
- 모바일·태블릿·PC 반응형 정상

### 14.2 `시작하기` 신규 사용자

1. 세션 없는 신규 사용자가 랜딩 페이지 접속
2. `시작하기` 클릭
3. 카카오 또는 구글 선택
4. 소셜 인증 완료
5. 신규 계정 판별
6. 회원가입 1단계 이동
7. 회원가입 절차 없이 보호자 홈으로 이동하지 않음

카카오와 구글을 각각 검증한다.

### 14.3 `시작하기` 기존 사용자

1. 세션 없는 기존 사용자가 랜딩 페이지 접속
2. `시작하기` 클릭
3. 기존에 가입한 소셜 계정으로 인증
4. 활성 계정 판별
5. 회원가입 화면 없이 보호자 홈 이동
6. 기존 가족·아이·리포트 데이터 유지

### 14.4 가입 미완료 사용자

- Auth만 생성된 사용자
- 약관 동의 완료 사용자
- 보호자 정보까지만 완료된 사용자
- 가족까지만 생성된 사용자
- 아이 등록 전 사용자

각 사용자가 마지막 미완료 단계로 정확히 이동하는지 검증한다.

### 14.5 Header 로그인

- 기존 활성 계정 로그인
- 신규 계정으로 로그인 버튼 진입 시 회원가입 연결
- 가입 미완료 계정의 이어하기
- 정지·탈퇴 계정 차단

### 14.6 Header 회원가입

- 신규 계정 회원가입 진입
- 기존 계정으로 회원가입 버튼 클릭 시 중복 가입 없이 로그인 처리
- OAuth callback 중복 호출 시 중복 가족·아이 생성 없음

### 14.7 자동 로그인

- 유효한 기존 보호자 세션으로 앱 재접속 시 자동 로그인
- 신규 또는 가입 미완료 사용자가 자동으로 보호자 홈에 진입하지 않음
- 로그아웃 후 자동 재로그인되지 않음
- 만료 또는 폐기된 세션은 로그인 화면으로 이동

### 14.8 보안

- 외부 URL redirect 차단
- 위조한 role·user_id·membership_status 무시
- 회원가입 미완료 사용자의 보호자 API 접근 차단
- 다른 가족 데이터 접근 차단
- 로그에 토큰과 개인정보 원문 미노출

## 15. Dev 및 Production 적용 순서

1. 현재 랜딩 페이지, Header, OAuth callback, 회원 상태 판별 구조 조사
2. `베타 신청하기`, `서비스 미리보기` 버튼의 기존 링크와 이벤트 영향 확인
3. 공통 소셜 인증 선택 컴포넌트 확인 또는 최소 범위 통합
4. 회원 상태 자동 분기 로직 점검
5. Dev 구현 및 배포
6. Dev에서 카카오·구글 신규·기존·미완료 계정 E2E 검증
7. 모바일·태블릿·PC UI 검증
