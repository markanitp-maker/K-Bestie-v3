# 078 — Mission Question Engine v2
## 7-Day Rotation + Rapport-Aware Contextual Question Bank Update Request

> 목표: 초등학교 1~6학년 아이가 Mission에서 “매일 똑같은 질문”이라고 느끼지 않도록, **초기 친해지기 전용 흐름 + 월~일 7일 로테이션 + 요일/시간대/기억 기반 질문 + 답변 기반 후속 질문**을 하나의 질문 엔진으로 통합한다.

---

# 0. Production 감사 기준선

현재 확인된 사실:

- `mission_questions` 전체 925개
- active + APPROVED 런타임 대상 846개
- semantic_group 21개
- 신규 아이용 전용 Rapport 질문 Flow 없음
- `RAPPORT_IDENTITY` 6개, 친해지기 성격 질문 약 50개
- 관계 엔진의 `effective_stage`는 현재 Goal 선택 후 계산되어 Mission 질문 선택에 미연결
- 신규 아이도 기존 아이와 동일한 질문 선택 알고리즘 사용
- 동일 사용자 표본에서 첫 질문 주제 반복률 80%, 전체 10 Goal semantic_group 반복률 62%
- 동일 첫 질문을 3일 연속 받은 실제 사례 존재
- 현재 우선순위는 사실상 `periodicity != flexible → P1`, `weekday_affinity → P2`, 일반 질문 → P3
- 이 때문에 토·일에도 “이번 주에…” 질문이 상단을 독점
- 공식 Mission 완료 정책: **Goal 10개 / SATISFIED 5개 시 COMPLETED**

이 Request는 846개 승인 질문을 버리는 작업이 아니다.

> 기존 질문은행은 자산으로 유지하고, **무엇을 언제 고르고 어떻게 이어 묻는지**를 전면 개선한다.

# 2. 핵심 정책

## 2.1 7-Day Rotation

- 월~일 매일 서로 다른 질문 후보군 구성
- 매일 최소 10개 이상 후보
- 실제 Mission Goal은 정확히 10개
- 최근 7일 동일 `question_id` 재사용 금지 원칙
- 최근 7일 동일 `question_family` 강한 감점
- 첫 질문 `question_family`는 7일 내 반복 금지 원칙
- 문장만 바꾼 사실상 동일 질문도 반복으로 취급

예:

`학교에서 제일 기억나는 일 뭐야?`  
`오늘 학교에서 가장 기억에 남는 순간 뭐였어?`

→ 둘 다 `question_family = SCHOOL_HIGHLIGHT`

## 2.2 Rapport-Aware Selection

질문 선택 전에 관계 단계를 계산한다.

```text
evaluateRelationshipStage(child)
→ effective_stage
→ question candidates
→ rapport/day-context/memory weighting
→ repeat/cooldown guard
→ 정확히 10 Goal
```

### 초기 관계
- Rapport/취향/생활패턴 6개 전후
- 오늘 요일/생활맥락 4개 전후
- P0 부모 질문이 있으면 최우선

### 관계 형성 중
- Rapport 3~4개
- 오늘 생활맥락 4~5개
- memory-personalized 1~2개

### 친숙 단계
- 오늘 생활맥락 중심
- 최근 기억 적극 활용
- 자기소개형 질문 비중 축소

# 3. 질문 선택 우선순위

현재:

`주기 질문 P1 → 요일 P2 → 일반 P3`

변경:

`P0 부모 질문 → 관계단계/친해지기 → 오늘 요일·생활맥락 → 최근 관심사/기억 → 주기 질문 → 일반 fallback`

---

# 4. Cooldown / 반복 방지

Cooldown은 질문을 버리는 장치가 아니라 반복 피로를 줄이는 장치다.

1. non-cooldown 후보 우선
2. 10개 미달이면 cooldown 후보를 가장 오래전에 사용한 순으로 backfill
3. 총 Goal은 반드시 10개
4. 같은 session 내 semantic_group 중복 금지
5. 이미 Goal로 확정된 뒤 `/turn` 복원 시 cooldown 재적용 금지

# 5. Metadata 업데이트 제안

| 필드 | 예시 | 목적 |
|---|---|---|
| `question_family` | `GAME_TODAY`, `ACADEMY_TODAY`, `FRIEND_PLAY` | 의미상 같은 질문 반복 방지 |
| `rapport_weight` | 0~3 | 초기 관계에서 친해지기 가중 |
| `time_of_day` | `morning/daytime/evening/any` | 시제 정합 |
| `gate_type` | `none/yes_no/choice` | Gate→Branch 제어 |
| `follow_up_intents` | JSON/array | 후속 질문 방향 |
| `source_question_id` | UUID | 세션 Goal 원본 추적 |
| `prompt_instruction_snapshot` | text | 세션 Goal 안정 복원 |

`weekday_affinity`는 유지하고 재분류한다.

# 6. 질문지 낭독 금지 — 대화 규칙

```text
아이 발화
→ 짧게 받아주기
→ 같은 주제로 1~2회 follow-up
→ 충분히 이야기했으면 Goal 평가
→ 다음 생활 주제로 이동
```

중요한 이야기를 즉시 버리지 않는다.

금지:
> “언니가 소리 질러서 스트레스 받아.”  
> “힘들었겠다. 이번 주 가장 기분 좋았던 일은 뭐야?”

권장:
> “그건 진짜 짜증나고 힘들었겠다. 왜 그런 일이 있었어?”  
> “그때 너는 뭐라고 했어?”

# 14. 10 Goal 구성 불변식

```text
Goal Count == 10
```

반드시 강제한다.

- 후보 10개 미만 → cooled-down oldest backfill
- unique semantic_group 자체가 10개 미만 → 명시적 초기화 오류
- 1~9 Goal 상태로 정상 Mission 시작 금지
- `initialized.length === 10` 검증
- 진행 중 Goal은 session snapshot 기준 SSOT

- 금/토/일 생활맥락 반영
