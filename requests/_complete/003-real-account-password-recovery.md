# 김서아·김서현 실계정 비밀번호 상태 확인 및 안전한 복구

## 작업 정보

- 우선순위: 긴급
- 선행 작업: 없음
- 병렬 처리: 가능
- 개발 작업보다 보안 상태 확인이 우선
- 평문 비밀번호 출력 금지

## 범위

작업 전 `docs/conventions.md`를 먼저 읽고 따른다.

확인·수정 허용:

- 기존 아이 계정 인증 관련 DB와 Auth 메타데이터
- `app/api/auth/` 중 아이 비밀번호 복구와 직접 관련된 파일
- `lib/auth/` 중 아이 비밀번호 복구와 직접 관련된 파일
- 기존 관리자용 비밀번호 초기화 기능이 있다면 해당 경로

수정 금지:

- 부모 계정 비밀번호
- Production DB
- 새로운 임시 비밀번호의 임의 생성 및 평문 보고
- 김서아·김서현의 대화·미션·놀이 세션 초기화
- 인증과 무관한 코드

## 현재 상태

- 과거 자동검증 과정에서 김서아·김서현 실계정 비밀번호가 임시값으로 변경됐다는 보고가 있다.
- 임시값이 과거 보고서에 평문으로 노출됐다.
- 현재 해당 비밀번호가 여전히 유효한지, 복구 또는 변경 강제 상태인지 완료 근거가 없다.
- 이번 작업은 비밀번호 값을 조회하거나 출력하는 것이 아니라 안전한 로그인 복구 상태를 확정하는 작업이다.

## 요구사항

1. 김서아·김서현 실계정의 실제 Auth 식별자를 정확히 확인한다.

2. 다음 상태를 평문 비밀번호 없이 확인한다.
   - 임시 비밀번호 변경 시각
   - 최근 비밀번호 변경 시각
   - `must_change_password` 또는 동등한 강제 변경 상태
   - 기존 안전한 비밀번호 복구 기능 존재 여부
   - 대표님이 현재 정상 로그인 가능한 상태인지

3. 과거 노출된 임시 비밀번호가 여전히 유효하다면 이를 안전하게 무효화한다.

4. 임의의 새 비밀번호를 생성해 채팅·로그·스크립트에 출력하지 않는다.

5. 기존 안전한 복구 절차가 존재하면 그 절차를 사용한다.

6. 기존 복구 절차가 없어서 대표님 결정이 필요하면:
   - 임의 개발하거나 값을 설정하지 않는다.
   - `requests/_blocked.md`에 필요한 결정과 안전한 선택지를 기록한다.
   - 다른 확인 작업은 완료한다.

7. 임시 인증정보가 다음 위치에 남았는지 검색하고 제거한다.
   - Git 추적 파일
   - 미추적 스크립트
   - `/tmp` 로그
   - requests 로그
   - 프로젝트 문서

8. Git 과거 커밋에 평문이 포함된 경우 현재 파일만 수정해 해결됐다고 보고하지 말고 별도 보안 이슈로 기록한다.

## 데이터·환경변수·배포

- Dev DB와 Dev Auth만 사용
- Production 접근: 금지
- 애플리케이션 코드 변경이 없으면 배포 불필요
- 인증 코드 수정이 발생하면 Dev 배포 필요
- 평문 비밀번호·토큰·서비스 키 보고 금지

## 완료조건

- 김서아·김서현 각각 현재 인증 상태 확인
- 과거 노출 임시값의 유효 여부 확인
- 유효한 노출 임시값이 남아 있지 않음
- 대표님이 사용할 안전한 복구 절차 확정
- 평문 비밀번호 출력 0건
- 임시 인증 스크립트·로그 0건
- 코드 변경 시 `tsc`, `next build`, Dev 배포 완료
- Production 미접촉 확인

## 검증 시나리오

1. Auth와 앱 DB 식별자 대조
2. 비밀번호 값이 아닌 변경·강제변경 상태 확인
3. 기존 복구 흐름 존재 여부 확인
4. 대표님 계정에 영향을 주지 않는 방식으로 복구 흐름 검증
5. 저장소와 임시 로그에서 과거 임시값 문자열 검색
6. 평문 노출이 없는 최종 보고 확인

## 공유파일 수정

원칙적으로 공유파일 수정 없음.

인증 공통 파일 수정이 반드시 필요하면 `requests/_blocked.md`에 실제 경로와 수정 이유를 기록하고 승인 전에는 수정하지 않는다.

## 작업 및 리뷰 방식

- 상태 조사와 오케스트레이션: 메인 Claude Code
- 코드 변경이 필요하면 1차 개발: 안티그래비티
- Claude Code 직접 수정 시 별도 `claude-review`
- 민감정보는 에이전트 프롬프트와 로그에도 넣지 않는다.
