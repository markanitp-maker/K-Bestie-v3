# REQUEST 022 — 안서아 친구 관계 메모리 및 8월 3일 리포트 정정

## 1. 작업 목적

Production 부모 리포트에서 안서아의 친구 관계가 다음과 같이 잘못 표시되고 있다.

> 2살 때부터 친했던 친구 예원이 집에 놀러 가서…

부모가 확인한 정확한 정보는 다음과 같다.

- 안서아가 2살 때부터 친하게 지낸 친구: 도원이, 도건이
- 예원이: 최근 함께 놀았던 친구일 수 있으나, 2살 때부터 친한 친구는 아님

잘못된 장기 관계 정보를 LLM Wiki에서 정정하고, 해당 오류가 노출된 2026년 8월 3일 일일 리포트와 부모 대시보드의 친구 관계 항목을 수정한다.

## 3. 부모 확인 정정 정보

다음 내용은 부모가 직접 확인한 정정 사실이다.

```text
안서아가 2살 때부터 친하게 지낸 친구는 도원이와 도건이다.
```

잘못된 정보:

```text
예원이가 안서아의 2살 때부터 친한 친구다.
```

예원이와 최근 함께 놀았다는 사건이 원본 대화 또는 보정 데이터에 실제로 존재한다면 해당 사건은 유지한다.

다음 두 정보를 반드시 분리한다.

```text
장기 관계
- 도원이·도건이: 2살 때부터 친하게 지낸 친구

최근 사건
- 예원이: 특정 날짜에 함께 놀았던 친구일 수 있음
```

예원이와 놀았다는 최근 사건까지 삭제하거나 부정하지 않는다.

## 4. 실행 전 원인 확인

수정 전에 잘못된 관계 정보가 어느 단계에서 생성됐는지 확인한다.

확인 순서:

```text
8월 3일 Raw 대화
→ Context Correction 보정 데이터
→ Memory Batch
→ LLM Wiki Fact·Evidence
→ 일일 리포트 생성 프롬프트 입력
→ daily_reports 저장
→ 부모 API
→ 상세 모달과 대시보드
```

다음 가능성을 구분한다.

1. 아이의 실제 발화가 STT 또는 Context Correction에서 잘못 보정됨
2. 보정 데이터는 정상이지만 Memory Batch가 관계를 잘못 추론함
3. LLM Wiki에는 없지만 리포트 생성기가 단발성 사건을 장기 관계로 확대 해석함
4. 기존 잘못된 Memory Fact가 Retrieval되어 리포트에 반영됨
5. 리포트 DB는 정상인데 API 또는 UI에서 잘못 조합됨

원인을 확인하지 않고 화면 문구만 직접 수정하면 안 된다.

## 5. Raw·보정 데이터 보존

Raw 대화와 Context Correction 데이터는 기존 7일 보존 정책을 유지한다.

- Raw 대화 원문 수정 금지
- 보정 데이터 원문 수정 금지
- 원본 기록 삭제 금지
- 해당 데이터의 보존 기간 임의 연장 금지

Raw와 보정 데이터는 당시 처리 내용을 검증하는 근거로만 사용한다.

부모 정정은 원본 발화를 변경하는 방식이 아니라 별도의 검증된 정정 사실로 기록한다.

## 6. LLM Wiki 관계 정보 정정

다음 테이블과 실제 동일 역할의 저장 구조를 확인한다.

- `llm_wiki_facts`
- `memory_facts`
- `child_memory`
- Evidence 관련 테이블
- Embedding 관련 테이블
- Memory Batch 결과 테이블

### 6.1 잘못된 Fact 처리

다음 의미의 Fact가 존재하는지 검색한다.

```text
예원 = 안서아가 2살 때부터 친한 친구
```

존재한다면 물리 삭제보다 기존 데이터 모델의 무효화 방식을 우선 사용한다.

우선순위:

1. `superseded`
2. `invalidated`
3. `inactive`
4. 동일 의미의 기존 상태 필드
5. 상태 필드가 없다면 최소 범위의 안전한 정정 구조 적용

잘못된 Fact를 Retrieval 대상에서 제외하고 다음 정보를 기록한다.

- 정정 사유: 부모 확인
- 정정 시각
- 정정 실행자
- 기존 Fact ID
- 대체 Fact ID
- 영향받은 리포트 ID
- 감사 로그

이미 생성된 사실을 증거 없이 조용히 덮어쓰지 않는다.

### 6.2 부모 확인 Fact 저장

다음 사실을 부모 확인 정보로 저장한다.

```text
안서아가 2살 때부터 친하게 지낸 친구는 도원이와 도건이다.
```

권장 메타데이터:

```json
{
  "source_type": "parent_correction",
  "confidence": 1.0,
  "verification_status": "parent_verified",
  "relationship_type": "long_term_friend",
  "valid_from": null,
  "supersedes_fact_id": "기존 오류 Fact ID",
  "corrected_at": "현재 시각"
}
```

실제 필드명은 기존 DB 스키마를 따른다.

스키마에 존재하지 않는 필드를 임의로 삽입하지 않는다.

### 6.3 최근 사건 유지

예원이와 함께 놀았다는 최근 사건이 실제 대화 근거를 가지고 있다면 별도 사건 Fact로 유지한다.

예:

```text
2026년 8월 3일 예원이와 함께 놀았다.
```

이 사건을 다음과 같이 확대 해석하면 안 된다.

```text
예원이는 2살 때부터 친한 친구다.
예원이는 가장 오래된 친구다.
예원이는 도원이·도건이보다 더 가까운 친구다.
```

## 7. Evidence 및 Embedding 처리

잘못된 관계 Fact와 연결된 Evidence 및 Embedding을 확인한다.

### 필수 처리

- 무효화된 Fact가 Retrieval 후보로 반환되지 않도록 한다.
- 기존 잘못된 Embedding이 활성 검색 대상에 남지 않도록 한다.
- 부모 정정 Fact의 Embedding을 생성 또는 갱신한다.
- 예원이와 놀았던 최근 사건 Evidence는 유지한다.
- 도원이·도건이 장기 관계와 예원이 최근 사건을 서로 다른 Fact로 분리한다.
- 다른 아이의 친구 관계 데이터가 안서아 메모리에 섞이지 않도록 한다.

Embedding 재생성은 안서아의 해당 정정 Fact에만 한정한다.

전체 사용자 Embedding을 다시 생성하지 않는다.

예원이와 함께 놀았다는 실제 사건은 유지하되 다음과 같이 관계를 왜곡하지 않는다.

허용 예시:

```text

```

실제 대화 근거가 없는 활동이나 감정은 추가하지 않는다.

### 대시보드 15자 요약

대시보드 친구 관계 카드에는 공백 포함 15자 이내의 실제 분석 요약을 저장한다.

예시:

```text
예원이와 즐겁게 놀았어요
```

또는 해당 리포트의 실제 분석 결과에 맞는 다른 문구를 생성한다.

장기 관계 정보가 핵심인 경우:

```text
도원이·도건이와 절친
```

예시를 하드코딩하지 말고 해당 날짜의 실제 대화 근거와 리포트 목적에 맞춰 생성한다.

## 9. 적용 방식

현재 생성기가 영역별 재생성을 지원하지 않고 전체 리포트만 생성할 수 있다면 다음 순서를 따른다.

3. 기존 리포트와 후보 리포트를 필드별 비교한다.
4. 친구 관계와 직접 관련된 필드만 적용한다.
5. 다른 영역 값은 기존 정상값을 유지한다.
6. 적용 성공 후 감사 로그를 남긴다.

전체 사용자 리포트 생성 작업은 실행하지 않는다.
