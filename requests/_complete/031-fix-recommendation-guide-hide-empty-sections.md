# 부모 추천 가이드 데이터 없는 항목 완전 숨김 처리

## 0. 완료 시 기대 결과 / 대표님 테스트 정상 프로세스

### 완료 시 기대 결과
부모 `리포트 > 일간/주간 > 추천 가이드`에서 실제로 보여줄 데이터가 없는 항목은 placeholder 문구로 채우지 않고 섹션 자체를 완전히 숨긴다.

예:
- `부모 대화 실마리` 데이터 있음 → 표시
- `부모가 주의 깊게 볼 변화` 데이터 없음 → 제목/아이콘/본문/카드/여백까지 전체 미표시
- `오늘의 케이 코멘트` 데이터 있음 → 표시

다음 문구는 화면에 노출하지 않는다.
- `이 항목은 확인할 대화가 충분하지 않아요.`
- `대화 정보가 부족해요.`
- `데이터 부족`
- `확인된 내용이 없어요.`
- `분석을 준비 중이에요.`
- `새로운 이야기가 있어요.`

`특이 사항이 없었어요.`로 단순 치환하는 방식도 사용하지 않는다.

### 대표님 테스트 정상 프로세스
1. 부모 계정 로그인
2. `리포트` 진입
3. 일일 리포트 `자세히 보기`
4. `추천 가이드` 탭 선택
5. 데이터 있는 항목은 정상 표시 확인
6. 데이터 없는 항목은 제목부터 완전히 사라졌는지 확인
7. 숨긴 자리의 빈 카드/구분선/큰 여백이 없는지 확인
8. 주간 리포트와 지난 이력보기에서도 동일하게 확인

PASS:
- 실제 데이터가 있는 항목만 표시
- 데이터 없는 항목은 섹션 자체가 없음
- 불필요한 공백 없음

## 1. 작업 목적
현재 추천 가이드에 데이터가 없는 항목도 카드로 렌더링되고 시스템 상태 문구가 노출되고 있다.

대표 확정 정책:
```text
유효 데이터 있음 → 항목 표시
유효 데이터 없음 → 항목 전체 숨김
```

## 2. 적용 범위
- 일일 리포트 상세 모달 > 추천 가이드
- 주간 리포트 상세 모달 > 추천 가이드
- 일일/주간 목록 카드 진입
- 지난 이력보기/달력 진입
- 동일 추천 가이드 공통 컴포넌트 전체

## 3. 데이터 없음 판정
다음은 유효 데이터 없음으로 처리한다.
- null / undefined
- 빈 문자열 / 공백 문자열
- 빈 배열 / 내용 없는 object
- insufficient_data 상태
- placeholder/fallback 문자열

최소 placeholder:
```text
이 항목은 확인할 대화가 충분하지 않아요.
확인할 대화가 충분하지 않아요.
대화 정보가 부족해요.
대화 정보 부족
데이터 부족
정보 없음
확인된 내용이 없어요.
분석을 준비 중이에요.
새로운 이야기가 있어요.
```

동일 의미의 기존 fallback도 실제 코드에서 찾아 공통 처리한다.

## 4. 숨김 범위
데이터 없는 항목은 다음 전체를 렌더링하지 않는다.
- 아이콘
- 제목
- 본문
- 카드 배경
- border/shadow
- 구분선
- 상하 margin/padding
- 빈 wrapper
- 고정 height/min-height
- 섹션 gap

시각적 정렬용 적정 여백은 유지하되, 의미 없이 휑하게 차지하는 공백은 제거한다.

## 5. 실제 사례
변경 전:
```text
💬 부모 대화 실마리
[실제 내용]

👁️ 부모가 주의 깊게 볼 변화
이 항목은 확인할 대화가 충분하지 않아요.

✨ 오늘의 케이 코멘트
[실제 내용]
```

변경 후:
```text
💬 부모 대화 실마리
[실제 내용]

✨ 오늘의 케이 코멘트
[실제 내용]
```

## 6. 실제 의미 있는 “변화 없음”과 구분
실제 대화/분석 근거를 기반으로 한 문장은 표시 가능하다.

예:
```text
최근 일주일 동안 친구 관계에서 특별한 갈등 변화는 관찰되지 않았고 평소와 비슷하게 안정적으로 지냈습니다.
```

이런 문장은 유효 분석이다.

반면:
```text
이 항목은 확인할 대화가 충분하지 않아요.
```
는 시스템 placeholder이므로 숨긴다.

단순 `includes("없")` 같은 방식으로 판정하지 않는다.

## 7. 생성 단계 확인
리포트 생성기가 데이터 없는 항목을 placeholder 문자열로 저장하는지 확인한다.

가능하면 신규 생성분부터:
```json
{"watch_changes": null}
```
또는 현재 schema가 지원하면 availability 상태를 사용한다.

단:
- 대규모 schema 변경 금지
- 과거 Production 리포트 일괄 수정 금지
- 과거 데이터는 UI/API 하위 호환으로 숨김

## 8. 공통 판정
일일/주간/달력/목록마다 조건문을 복사하지 말고 공통 함수/mapper를 사용한다.

## 9. 모든 추천 가이드 항목이 비어 있는 경우
개별 placeholder 카드를 여러 개 만들지 않는다.

추천 가이드 전체에 유효 항목이 하나도 없다면 전체 안내 문구를 최대 1개만 표시한다.
예:
```text
이번 리포트에서 제공할 추천 가이드가 없어요.
```

## 10. 기존 완료 기능 보호
다음은 재설계하지 않는다.
- 모달 제목/X 고정
- `빠른 요약 / 상세 보기 / 추천 가이드` 탭 고정
- 콘텐츠 영역만 스크롤
- 배경 스크롤 차단
- 일일/주간 동일 모달 구조
- 목록/달력 동일 진입 구조

회귀 검증만 한다.

## 11. 금지 사항
- `특이 사항이 없었어요.`로 일괄 치환 금지
- 제목만 남기기 금지
- placeholder 카드 유지 금지
- 빈 wrapper/큰 공백 유지 금지
- 단순 문자열 `없` 기반 오판정 금지
- 과거 Production 리포트 일괄 재생성 금지
- 기존 정상 가이드 내용 삭제 금지

## 12. 필수 테스트
- 일부 항목만 데이터 있는 경우
- 과거 placeholder 저장 리포트
- 실제 의미 있는 “변화 없음” 분석
- 모든 항목 비어 있는 경우
- 일일/주간/달력/목록 진입
- iPhone Safari/PWA
- Android Chrome
- 태블릿 가로/세로

## 13. 완료 기준
- [ ] 데이터 없는 추천 가이드 항목 완전 숨김
- [ ] placeholder 문구 화면 노출 0건
- [ ] `특이 사항이 없었어요.`로 억지 치환하지 않음
- [ ] 아이콘/제목/본문/카드/구분선/여백 전체 숨김
- [ ] 유효 데이터 항목 정상 표시
- [ ] 실제 의미 있는 “변화 없음” 분석 정상 표시
- [ ] 과거 placeholder 데이터도 UI에서 숨김
- [ ] 빈 wrapper/고정 높이/불필요한 공백 없음
- [ ] 일일/주간/목록/달력 동일 적용
- [ ] 기존 모달 UX 유지
- [ ] 타입체크 PASS
- [ ] 빌드 PASS
- [ ] 모바일 E2E PASS
- [ ] BLOCKER/HIGH 0건

## 14. 배포
Development에서 타입체크, 빌드, 일일/주간 추천 가이드 E2E, placeholder 숨김, 실제 유효 분석 유지, 불필요 공백 제거, 모바일 UI, 기존 모달 회귀를 PASS하고 BLOCKER/HIGH 0건이면 추가 승인 대기 없이 Production에 배포한다.

Production 배포 후 실제 부모 모바일 리포트 화면에서 smoke test한다.

## 15. 완료 보고
- 최종 판정: PASS / PARTIAL / FAIL
- 수정 파일
- 항목별 데이터/표시 결과
- placeholder 검사
- 빈 카드/구분선/wrapper/여백 검사
- 모바일 회귀 결과

마지막에 반드시 `맞다 / 아니다`로 답한다.
- 데이터 없는 추천 가이드 항목은 완전히 숨겨지는가?
- placeholder 문구가 더 이상 화면에 나오지 않는가?
- `특이 사항이 없었어요.`로 단순 치환하지 않는가?
- 실제 유효 데이터가 있는 항목은 유지되는가?
- 빈 카드와 불필요한 공백이 제거됐는가?
- 일일·주간·목록·달력 경로에 동일 적용됐는가?
- Production 배포 및 모바일 검증이 완료됐는가?
