# 음성 미션 대화 화면 고정 레이아웃 및 말풍선 길이 대응 수정

## 1. 작업 목적

음성 미션 화면에서 대화 문장이 길어질수록 마스코트, 상태 카드, 자동·수동 버튼, 마이크 버튼 등 하단 UI 전체가 아래로 밀리는 문제를 수정한다.

첨부한 첫 번째 이미지를 정상 기준 화면으로 사용한다.

- 첫 번째 이미지: 정상 레이아웃
- 두 번째·세 번째 이미지: 말풍선과 지난 대화 영역이 길어지면서 하단 UI가 아래로 밀린 비정상 레이아웃

핵심 원칙은 다음과 같다.

> 말풍선 영역 외의 모든 UI 위치와 크기는 고정한다.  
> 대화 내용이 길어지면 위쪽의 지난 대화 영역을 줄이거나 잘라내고, 하단 조작 UI를 밀어내지 않는다.

---

## 2. 정상 기준 화면

첫 번째 첨부 이미지의 위치를 기준으로 다음 요소를 고정한다.

- 상단 진행률 표시
- 문의 버튼
- 케이의 현재 발화 말풍선 하단 기준 위치
- 소리 상태 카드
- 듣기 상태 카드
- 케이 마스코트와 받침대
- 자동·수동 선택 버튼
- 키보드 버튼
- 마이크 버튼
- iPhone 하단 Safe Area 여백

문장 길이나 지난 대화 개수와 관계없이 위 요소들의 위치가 아래로 이동하면 안 된다.

---

## 3. 현재 발생한 문제

두 번째·세 번째 이미지에서는 대화 내용이 길어질수록 다음 현상이 발생한다.

- 지난 대화 문장이 차지하는 높이가 증가함
- 현재 발화 말풍선 높이가 증가함
- 화면 전체가 일반 세로 문서처럼 아래로 확장됨
- 마스코트와 상태 카드가 아래로 밀림
- 자동·수동 버튼이 아래로 밀림
- 마이크 버튼이 화면 하단 밖으로 내려가거나 일부 잘림
- 기기 높이에 따라 주요 조작 버튼 접근이 어려워짐

추정 원인은 다음과 같다.

- 전체 화면이 고정 높이 레이아웃이 아니라 콘텐츠 높이에 따라 늘어나는 구조
- 상위 컨테이너의 `min-height`, `flex-grow` 또는 일반 문서 흐름 때문에 대화 영역 증가가 하단 UI 위치에 영향을 줌
- 지난 대화 영역에 높이 제한과 `overflow` 처리가 없음
- 현재 발화 말풍선의 최대 사용 가능 높이가 정해져 있지 않음
- iPhone Safari/PWA의 `100vh`와 Safe Area 차이가 제대로 처리되지 않음
- 하단 조작 영역이 화면 하단 기준으로 고정되지 않고 대화 콘텐츠 뒤에 배치됨

실제 코드를 확인하여 정확한 원인을 먼저 특정한 뒤 수정한다.

---

## 4. 확정 레이아웃 정책

### 4.1 화면 전체

- 화면은 한 개의 고정된 모바일 뷰포트 안에서 동작해야 한다.
- 화면 전체에 세로 스크롤이 생기지 않게 한다.
- 기본 높이는 `100dvh`를 우선 사용한다.
- 필요한 경우 `100svh` 또는 기존 브라우저 대응 fallback을 추가한다.
- iPhone Safe Area는 다음 값을 반영한다.
  - `env(safe-area-inset-top)`
  - `env(safe-area-inset-bottom)`

### 4.2 고정 영역

다음 영역은 대화 내용과 관계없이 높이와 위치를 유지한다.

1. 상단 진행률 영역
2. 하단 케이 마스코트 및 상태 카드 영역
3. 자동·수동 선택 영역
4. 키보드 버튼
5. 마이크 버튼 영역

대화 내용이 길어져도 이 영역은 아래로 밀리면 안 된다.

### 4.3 가변 영역

대화 문장에 따라 높이가 달라질 수 있는 것은 다음 영역뿐이다.

- 지난 대화 영역
- 현재 발화 말풍선

가변 영역은 고정된 전체 화면 안에서만 높이를 나눠 사용해야 한다.

---

## 5. 대화 표시 우선순위

대화 내용은 다음 순서로 우선 표시한다.

1. 현재 발화
2. 바로 이전 발화
3. 지지난 발화

현재 발화가 가장 중요하다.

### 공간이 충분한 경우

- 현재 발화 표시
- 지난 발화 표시
- 지지난 발화 표시
- 총 3개의 발화를 유지

### 공간이 부족한 경우

- 현재 발화는 반드시 유지
- 지난 발화는 가능한 범위에서 유지
- 지지난 발화부터 상단 영역에서 잘라냄
- 더 부족하면 지난 발화의 상단 일부가 잘릴 수 있음
- 하단 조작 UI는 절대 이동하지 않음

오래된 대화부터 화면 위쪽으로 밀려나고 잘려야 한다.

---

## 6. 현재 발화 말풍선 정책

- 현재 발화 말풍선은 글자 수에 따라 높이를 자동 조절한다.
- 짧은 문장은 불필요하게 큰 고정 높이를 사용하지 않는다.
- 긴 문장은 여러 줄로 자연스럽게 확장한다.
- 말풍선 하단 꼬리와 케이 마스코트 사이의 기준 간격은 유지한다.
- 말풍선이 커질 때 아래쪽으로 확장하여 마스코트를 밀지 말고 위쪽 공간을 사용한다.
- 현재 발화 말풍선의 하단 위치는 고정하고, 높이는 위쪽 방향으로 증가시키는 구조를 우선 적용한다.
- 현재 발화가 사용 가능한 최대 높이보다 더 길 경우:
  - 글자 크기를 임의로 축소하지 않는다.
  - 말풍선 내부만 스크롤 가능하게 하거나,
  - 설정된 최대 높이 안에서 내용을 확인할 수 있는 방식으로 처리한다.
- 현재 발화 때문에 하단 조작 영역이 이동하면 안 된다.

---

## 7. 지난 대화 영역 정책

- 지난 대화 영역은 남은 화면 높이만 사용한다.
- `min-height: 0`과 `overflow: hidden`을 명확하게 적용한다.
- 최신 대화가 아래쪽에 보이도록 정렬한다.
- 영역 높이가 줄어들면 오래된 대화의 상단부터 잘린다.
- 지지난 발화는 공간 부족 시 완전히 숨겨져도 된다.
- 지난 발화는 가능한 한 유지하지만 현재 발화보다 우선하지 않는다.
- 필요하면 상단 잘림 부분에 약한 페이드 효과를 사용할 수 있으나 필수는 아니다.
- 지난 대화가 잘리더라도 전체 화면 스크롤은 만들지 않는다.

---

## 8. 권장 레이아웃 구조

일반 세로 `flex` 콘텐츠 누적 방식 대신 고정 행과 가변 행을 구분한다.

예시 구조:

```text
전체 화면: 100dvh
├─ 상단 진행률 및 문의 영역: 고정
├─ 지난 대화 영역: 남은 공간 사용, overflow hidden
├─ 현재 발화 말풍선: 내용에 따라 자동 높이, 최대 높이 제한
├─ 마스코트 및 상태 카드: 고정
├─ 자동·수동 버튼: 고정
└─ 키보드 및 마이크 영역: 고정 + Safe Area
```

CSS Grid를 사용할 경우 예시:

```css
.mission-screen {
  height: 100dvh;
  min-height: 100dvh;
  overflow: hidden;
  display: grid;
  grid-template-rows:
    auto
    minmax(0, 1fr)
    auto
    auto
    auto;
}
```

실제 프로젝트 구조에 맞게 적용하되, 특정 픽셀값을 무작정 하드코딩하지 말고 현재 정상 화면 비율을 유지한다.

---

## 9. 문의 버튼과 닫기 버튼

첨부 화면마다 문의 버튼 또는 닫기 버튼의 위치가 대화 영역에 따라 달라져 보인다.

- 문의 버튼은 대화 콘텐츠의 일반 문서 흐름에 포함하지 않는다.
- 닫기 버튼도 고정된 상단 영역에 배치한다.
- 두 버튼 때문에 진행률 영역이나 대화 영역의 높이가 달라지지 않게 한다.
- 문의 버튼 노출 상태가 바뀌어도 하단 UI 위치는 동일해야 한다.

## 10. 수정 범위

- 음성 미션 화면 레이아웃
- 자동 모드와 수동 모드 공통
- 듣는 중, 대기 중, 말하는 중, 소리 꺼짐 등 모든 상태
- 일반 Safari
- 홈 화면에 설치된 PWA
- iPhone Safe Area 대응
- 짧은 문장과 긴 문장
- 문의 버튼 표시 상태
- 닫기 버튼 표시 상태

대화 로직, 미션 질문 순환, 음성 처리, 저장 데이터는 변경하지 않는다.

## 11. 재현 시나리오

다음 조건을 각각 재현하여 원인을 확인한다.

### 시나리오 A: 짧은 문장

- 현재 발화 2줄 이하
- 지난 발화 2개
- 첫 번째 첨부 이미지와 동일한 전체 위치 확인

### 시나리오 B: 현재 발화가 긴 경우

- 현재 발화 4~6줄
- 지난 발화 1~2개
- 말풍선만 위쪽으로 커지는지 확인
- 마스코트와 마이크 버튼이 움직이지 않는지 확인

### 시나리오 C: 지난 대화가 긴 경우

- 지난 발화와 지지난 발화 모두 여러 줄
- 지지난 발화가 먼저 잘리는지 확인
- 현재 발화와 하단 UI가 유지되는지 확인

### 시나리오 D: 매우 긴 현재 발화

- 현재 발화가 사용 가능 영역을 초과
- 말풍선 내부 처리 확인
- 전체 화면 스크롤과 하단 밀림이 발생하지 않는지 확인

### 시나리오 E: 상태 전환

- 대기 중
- 듣고 있어
- 말하는 중
- 소리 켜짐
- 소리 꺼짐
- 자동
- 수동

상태가 바뀌어도 전체 UI 위치가 바뀌지 않아야 한다.

## 12. 완료 조건

다음 조건을 모두 만족해야 완료로 판단한다.

- 첫 번째 첨부 이미지의 전체 레이아웃을 정상 기준으로 유지한다.
- 두 번째·세 번째 이미지처럼 하단 UI가 아래로 밀리지 않는다.
- 마스코트, 상태 카드, 자동·수동 버튼, 마이크 버튼 위치가 고정된다.
- 말풍선 높이는 문장 길이에 따라 자동 조절된다.
- 말풍선이 길어지면 위쪽 지난 대화 영역이 먼저 줄어든다.
- 현재 발화는 항상 표시된다.
- 지난 발화는 가능한 한 유지된다.
- 지지난 발화는 공간 부족 시 잘리거나 숨겨질 수 있다.
- 문장이 짧으면 최대 3개의 발화를 유지한다.
- 전체 페이지에 세로 스크롤이 생기지 않는다.
- iPhone Safari와 설치형 PWA에서 동일하게 동작한다.
- 화면 높이가 다른 iPhone에서도 주요 조작 버튼이 화면 안에 유지된다.
- 기존 음성·미션·저장 기능에 회귀 문제가 없다.
