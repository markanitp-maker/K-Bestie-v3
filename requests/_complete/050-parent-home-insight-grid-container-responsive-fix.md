# 050 — 부모 홈 8개 상태 카드의 PC 스마트폰 프레임 반응형 붕괴 수정

Production 과 Dev 서버 모두 반영해

## 1. 작업 목적

부모 홈의 8개 상태 요약 카드는 실제 스마트폰에서는 정상적인 `2열 × 4행`으로 표시되지만, PC 웹의 스마트폰 디바이스 프레임 안에서는 4개의 매우 좁은 열로 강제 배치되어 한국어가 글자 단위로 세로 줄바꿈되고 있다.

현재 비정상 화면에서는 다음 문제가 발생한다.

- 8개 카드 중 첫 번째 행에 4개 카드가 강제로 배치됨
- 카드 하나의 너비가 지나치게 좁아짐
- `학교·학원 생활`, `친구 관계`, `마음 흐름`, `관심사·취향` 등의 카테고리명이 글자 단위로 세로 표시됨
- 12자 이내 요약도 한 글자씩 줄바꿈됨
- 카드의 상태값과 관찰 정보까지 좁은 폭 안에서 붕괴함
- 실제 스마트폰과 PC 스마트폰 프레임이 서로 다른 화면처럼 보임

이번 작업은 부모 홈의 8개 상태 요약 카드를 실제 콘텐츠 컨테이너 폭을 기준으로 반응형 처리하여, PC 스마트폰 프레임과 실제 모바일 모두 동일한 `2열 × 4행` 구조로 보이도록 수정하는 것이다.

---

## 2. 정확한 원인 감사

코드 수정 전에 다음 항목을 확인하여 실제 원인 Selector와 컴포넌트를 특정한다.

- 8개 카드 Grid 컴포넌트 경로
- `grid-cols-2`, `md:grid-cols-4`, `lg:grid-cols-4` 등 Tailwind 분기
- CSS `@media (min-width: ...)` 규칙
- PC Device Frame 전용 클래스
- `isDevicePreview`, `deviceMode`, `data-device` 조건
- `grid-auto-flow`
- `repeat(4, 1fr)` 또는 동등한 4열 규칙
- Container Query 사용 여부
- `container-type`이 PC 프레임 내부에만 있거나 누락됐는지 여부
- Device Frame 외부 `transform: scale()` 영향
- 카드의 `min-width`
- 텍스트의 `word-break`, `overflow-wrap`, `white-space`
- 부모 컨테이너의 실제 `clientWidth`
- PC 프레임 내부와 실제 모바일의 Computed `grid-template-columns`

가장 유력한 원인은 다음 구조다.

```text
바깥 PC 브라우저 폭은 md/lg 이상
→ 데스크톱용 4열 CSS 실행
→ 실제 콘텐츠는 스마트폰 프레임 안의 좁은 폭
→ 4열이 좁은 컨테이너 안에 강제 배치
→ 한국어가 글자 단위로 줄바꿈
```

작업 완료 보고에서 정확한 원인 클래스와 Selector를 명시한다.

## 3. 최종 레이아웃 기준

### 일반 스마트폰 및 스마트폰 프레임

다음 환경에서는 반드시 `2열 × 4행`을 유지한다.

- 실제 모바일 브라우저
- iOS 홈 화면 PWA
- Android 설치형 PWA
- PC 웹의 스마트폰 디바이스 프레임
- Windows PWA의 스마트폰 미리보기
- 내부 콘텐츠 폭 300px~480px

구조:

```text
[학교·학원 생활] [친구 관계]
[마음 흐름]      [관심사·취향]
[공부 고민]      [디지털·콘텐츠]
[선생님·어른]    [반복 이야기]
```

### 태블릿·넓은 콘텐츠

콘텐츠 컨테이너 자체가 실제로 충분히 넓은 경우에만 3열 또는 4열을 검토할 수 있다.

단, 외부 브라우저가 넓다는 이유만으로 스마트폰 프레임 내부를 4열로 바꾸면 안 된다.

---

## 4. Grid 수정 기준

스마트폰 크기의 부모 홈 콘텐츠에서는 다음과 같은 안정적인 2열 Grid를 사용한다.

```css
.parent-insight-grid {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 10px;
  width: 100%;
}
```

Tailwind를 사용하는 경우 동등한 구조를 적용한다.

```text
grid grid-cols-2 gap-2.5
```

다음을 제거하거나 실제 컨테이너 기준으로 교정한다.

```text
md:grid-cols-4
lg:grid-cols-4
xl:grid-cols-4
```

스마트폰 프레임 내부에서 바깥 Window 폭을 기준으로 4열이 적용되지 않도록 한다.

---

## 5. Window Media Query 대신 콘텐츠 폭 기준 사용

PC의 스마트폰 프레임은 바깥 Window가 넓고 내부 콘텐츠는 좁다.

따라서 이 화면은 Window Media Query만으로 열 수를 결정하면 안 된다.

권장 우선순위:

1. 기본 모바일 2열 고정
2. 부모 홈 콘텐츠 최대 너비를 모바일 기준으로 유지
3. 필요한 경우 Container Query 사용

Container Query가 필요한 경우 예시:

```css
.parent-home-content {
  container-type: inline-size;
}

.parent-insight-grid {
  grid-template-columns: repeat(2, minmax(0, 1fr));
}

@container (min-width: 720px) {
  .parent-insight-grid {
    grid-template-columns: repeat(4, minmax(0, 1fr));
  }
}
```

단, 현재 부모 화면이 모바일 1열 중앙형을 기본 정책으로 사용한다면 4열 확장 없이 계속 2열로 유지해도 된다.

---

## 6. Device Frame 책임 분리

PC의 스마트폰 프레임은 다음 기능만 담당해야 한다.

- 외곽 스마트폰 베젤
- 내부 Viewport
- 프레임 내부 스크롤
- 미리보기 배율

Device Frame이 다음 내부 UI를 변경하면 안 된다.

- 8개 카드의 열 수
- 카드 글자 크기
- 카드 Padding
- 카드 높이
- 카테고리명 줄바꿈
- 요약 문구 줄바꿈

최종 구조:

```text
DeviceFrame
└─ ParentHomeContent
   └─ ParentInsightGrid
```

실제 모바일과 PC 프레임은 같은 `ParentHomeContent`와 `ParentInsightGrid`를 사용해야 한다.

---

## 7. 카드 최소 너비 및 축소 처리

Grid 자식 카드에 다음을 적용한다.

```css
.parent-insight-card {
  min-width: 0;
  width: 100%;
  box-sizing: border-box;
}
```

카드 내부의 아이콘·제목·본문·하단 상태 영역에도 필요한 경우 `min-width: 0`을 적용한다.

다음을 금지한다.

- 카드에 좁은 고정 너비 적용
- 4열을 유지하기 위해 글꼴을 과도하게 축소
- 카드 전체를 `transform: scale()`로 축소
- 한 글자 단위 줄바꿈을 허용한 채 완료 처리

---

## 8. 한국어 줄바꿈 정책

카테고리명과 요약 문구가 한글 음절 단위로 세로 표시되지 않도록 한다.

권장:

```css
.parent-insight-card-title,
.parent-insight-card-summary {
  word-break: keep-all;
  overflow-wrap: break-word;
}
```

필요하면 다음도 적용한다.

```css
hyphens: none;
```

금지:

```css
word-break: break-all;
```

또는 카드 폭 부족을 해결하기 위한 무조건적인:

```css
overflow-wrap: anywhere;
```

카드 폭이 정상인 상태에서 자연스러운 어절 단위 줄바꿈을 사용한다.

## 9. 카테고리명

다음 8개 카테고리명을 유지한다.

1. 학교·학원 생활
2. 친구 관계
3. 마음 흐름
4. 관심사·취향
5. 공부 고민
6. 디지털·콘텐츠
7. 선생님·어른
8. 반복 이야기

기준:

- 아이콘과 카테고리명은 같은 상단 행에 표시
- 가능한 한 한 줄
- 폭이 부족하면 최대 2줄
- 한 글자씩 세로 표시 금지
- 글자 크기를 지나치게 축소하지 않음

## 10. 12자 요약 유지

각 카드의 본문은 기존 정책대로 공백 포함 최대 12자 이내의 요약을 유지한다.

유지:

- 실제 분석 데이터
- 데이터 부족 문구
- 말줄임표 미사용
- 단순 문자열 절단 금지
- 카드별 동적 요약

표시 기준:

- 최대 2줄
- 어절 단위 줄바꿈
- 한 글자씩 세로 배치 금지
- 카드 간 높이 균일 유지

이번 작업에서 요약 생성 로직이나 데이터 내용을 변경하지 않는다.

## 11. 카드 하단 정보

다음 하단 정보는 유지한다.

- `특징`
- `살펴보기`
- `데이터 부족`
- 관찰 일수
- 마지막 관찰 시점
- 기록 없음

하단 영역은 다음처럼 배치한다.

```text
[상태]                  [관찰 정보]
```

좁은 카드에서도 두 영역이 세로 한 글자씩 표시되지 않도록 한다.

필요한 경우:

```css
display: flex;
justify-content: space-between;
gap: 6px;
min-width: 0;
```

관찰 정보는 줄바꿈보다 한 줄 유지 또는 자연스러운 축약을 우선한다.

## 12. 카드 높이

2열에서 좌우 카드의 높이가 동일해야 한다.

권장:

- 콘텐츠 기반 최소 높이 유지
- 좌우 카드가 같은 행에서 동일 높이
- 글자 확대 시 자동 확장 허용
- 고정 높이 때문에 내용이 잘리지 않게 함
- 한 글자 줄바꿈 때문에 카드가 비정상적으로 길어지지 않게 함

## 13. 기존 카드 비인터랙티브 정책 유지

8개 상태 카드는 정보 표시 전용이다.

다음을 유지한다.

- 카드 클릭 시 리포트 페이지 이동 없음
- `Link` 없음
- `router.push` 없음
- `onClick` 없음
- `role="button"` 없음
- 클릭 가능 Pointer Cursor 없음
- Hover·Pressed 효과 없음

이번 반응형 수정 과정에서 카드 링크를 다시 추가하지 않는다.

## 14. 실제 모바일 화면 회귀 금지

오른쪽 첨부 이미지의 실제 스마트폰 화면은 현재 정상이다.

따라서 수정 후에도 다음을 유지한다.

- 2열 카드
- 현재 카드 크기
- 현재 정보 순서
- 오늘의 한마디 카드
- 하단 내비게이션
- 자녀 선택
- 문의 버튼
- 데이터 부족 상태

PC 프레임 문제를 수정하면서 실제 모바일 UI를 변경하거나 깨뜨리지 않는다.

## 15. 앞선 버튼 줄바꿈 문제와 공통 원인 감사

같은 부모 화면에서 다음 문제도 확인됐다.

- `변경` 버튼이 `변 / 경` 두 줄로 표시
- `초대` 버튼이 `초 / 대` 두 줄로 표시

이번 8개 카드 문제와 동일하게 다음 원인이 존재하는지 함께 감사한다.

- 바깥 Window 기준 Breakpoint
- 좁은 프레임 안의 데스크톱 CSS
- Flex Shrink
- `white-space` 누락
- 컨테이너 폭과 Media Query 불일치

단, 별도 Request에서 버튼 수정이 이미 진행 중이면 중복 수정하지 않고 원인과 공통 컴포넌트 영향만 확인한다.
