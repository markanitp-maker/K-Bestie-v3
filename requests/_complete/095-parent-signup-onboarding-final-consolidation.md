# 095 — 보호자 회원가입·온보딩 UX 최종 통합

## 상태

- 작업중

## 목표

Production 보호자 회원가입 1~4단계, 1회용 가족 초대 링크, 아이 등록 완료 Handoff, 보호자 홈·설정 재호출 UX를 최종 확정안으로 통합한다.

## 필수 범위

1. 1/4 약관: 기존 필수 동의 유지, Primary 아래 명시적 로그인/시작 화면 `← 이전`.
2. 2/4 기본정보: 보호자 이름·관계만 유지. 휴대전화와 중복 법정대리인 확인 UI/validation/API 필수 처리 제거. 이전은 1/4, 입력 유지.
3. 3/4 가족 만들기: 일반 가입은 가족 만들기만 제공. 이메일 기반 참여 UI 제거. 가족 참여는 auth.user.id 기준 1회용 초대 링크 전용이며 원자 CONSUMED·재사용 차단·성공 시 3/4·4/4 우회 후 보호자 홈.
4. 4/4 아이 등록: 관심사 UI/state/필수 payload 제거, 기존 DB 컬럼·데이터 보존. 지정 필드와 법정대리인 동의만 유지. 이전은 3/4이며 기존 family_id·입력 유지.
5. 모든 이전/다음·새로고침·중복 클릭에서 family/child 중복 0, 기존 저장 데이터 삭제·롤백 금지.
6. 완료 후 공통 아이 시작 Handoff: 안전한 로그인 URL QR, 주소/아이디 복사, 아이 ID prefill, 안전한 아이 로그인 전환, 보호자 홈 이동.
7. 보호자 홈 상시 재호출 및 설정의 아이별 로그인 방법. 다자녀는 선택 후 정확한 자녀 정보만 표시.
8. 기존 OAuth·탈퇴/복구·가족/아이·리포트·대화·아이 인증 구조 및 legacy pending 초대 데이터 보존.

## 완료 게이트

- Dev 타입·테스트·build PASS.
- Dev 실제 브라우저: 정방향·역방향·입력 유지·멱등, 전화번호/중복동의/이메일참여/관심사 제거, Handoff/복사/QR/같은 기기 시작/홈·설정 재호출/다자녀/1회용 초대 재사용 차단 PASS.
- 기존 활성 사용자와 핵심 기능 회귀 0.
- Production 배포 후 동일 smoke PASS, QA 임시 데이터 cleanup.
- 김비서 Discord `sent`, `_done` 이동, dashboard/log 정리.
