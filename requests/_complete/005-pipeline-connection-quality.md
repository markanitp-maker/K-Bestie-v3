## 현재 상태

- 연결 품질 훅과 표시 컴포넌트가 운영 미션 화면에 연결된 상태로 보고됐다.
- 기존 실측 보고에서는 `recordStageResult("llm", ...)`만 호출돼 LLM 구간만 측정했다.
- 화면 문구는 전체 서버 또는 네트워크 연결 문제처럼 보일 수 있었다.
- STT·TTS·오디오 재생 단계는 아직 계측되지 않았다는 보고가 있다.

## 요구사항

1. 파이프라인 단계를 구분해 계측한다.
   - STT 시작·성공·실패·지연
   - LLM 시작·성공·실패·지연
   - TTS 시작·성공·실패·지연
   - 오디오 재생 시작·성공·중단·실패

2. 각 턴의 동일한 `turnId`로 단계 결과를 연결한다.

3. 상태 판정:
   - 정상: 전체 단계 성공
   - 주의: 단일 단계 지연 또는 일시적 실패
   - 불안정: 연속 실패 또는 대화 진행 불가

4. 음성 끄기 상태:
   - TTS와 재생이 의도적으로 생략된 것으로 처리
   - 실패로 계산하지 않음

5. 표시 문구는 실제 관측된 단계에 맞게 작성한다.
   - 네트워크 장애로 단정하지 않음
   - 아이의 말하기 문제로 표현하지 않음

6. 표시와 실제 대화 진행을 분리한다.
   - 품질 표시 오류 때문에 질문 index나 세션이 변경되면 안 됨

7. 개인정보·아이 발화 원문을 품질 로그에 저장하지 않는다.

8. 일시적 화면 표시용 로그와 영구 분석 이벤트를 구분한다.
