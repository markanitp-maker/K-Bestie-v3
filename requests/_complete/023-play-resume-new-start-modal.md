# 놀이 이어하기 모달 버튼 정책 개선 요청

## 문서 정보

- 대상 프로젝트: `/mnt/e/VibeCoding/K-Bestie-v3`
- 요청 유형: UX 개선 / 세션 이어하기 / 황금열쇠 중복 차감 방지
- 적용 환경: Development 우선 적용 및 검증 후 Production 반영
- 영향 대상: 현재 실행 가능한 모든 놀이 앱
  - MBTI
  - 퀴즈마스터
  - 향후 추가되는 독립 놀이 앱
- 제외 대상:
  - 아직 준비 중인 만화책 읽기
  - 아직 준비 중인 헤어스타일

## 배경

현재 놀이 카드 클릭 시 다음 두 종류의 모달이 표시된다.

### 신규 놀이인 경우

- 취소
- 시작하기

이 구조는 정상이다.

### 이전에 진행하던 놀이가 있는 경우

현재는 다음 두 버튼만 표시된다.

- 취소
- 이어하기

그러나 사용자가 기존 진행 내역을 버리고 처음부터 다시 시작하고 싶어도 선택할 수 있는 버튼이 없다.

## 목표

이어하기 가능한 기존 세션이 있을 때 다음 세 개 버튼을 제공한다.

1. 취소
2. 새로 시작하기
3. 이어하기

신규 세션이 없는 경우에는 기존처럼 다음 두 버튼만 유지한다.

1. 취소
2. 시작하기

## 확정 UX 정책

### 1. 신규 세션이 없는 경우

표시 문구:

- 제목: `새로운 놀이를 시작할까요?`
- 설명: `황금열쇠 N개가 소모됩니다`

버튼:

- `취소`
- `시작하기`

동작:

- `취소`: 모달 닫기
- `시작하기`: 신규 놀이 세션 생성 및 황금열쇠 1회 차감 후 놀이 실행

### 2. 이어하기 가능한 세션이 있는 경우

표시 문구:

- 제목: `이전에 하던 놀이가 있어요`
- 설명: `이어할까요, 처음부터 다시 시작할까요?`

버튼:

- `취소`
- `새로 시작하기`
- `이어하기`

동작:

#### 취소

- 아무 변경 없이 모달 닫기
- 기존 세션 유지
- 황금열쇠 차감 없음

#### 이어하기

- 기존 `sessionId`와 저장된 진행 상태를 복원
- 기존 문제 위치 또는 진행 단계부터 재개
- 황금열쇠 재차감 금지
- 신규 세션 생성 금지
- 기존 `progress_state` 유지

#### 새로 시작하기

- 기존 진행 세션을 물리 삭제하지 않는다.
- 기존 세션은 현재 스키마가 허용하는 `expired`, `cancelled`, `abandoned` 등 적절한 종료 상태로 전환한다.
- 기존 세션의 이력과 원장은 보존한다.
- 신규 세션을 생성한다.
- 해당 놀이의 황금열쇠 비용을 정확히 1회만 차감한다.
- 처음 문제 또는 최초 단계부터 시작한다.
- 이어하기용 기존 `progress_state`를 신규 세션에 복사하지 않는다.

## 새로 시작하기 재확인

`새로 시작하기`를 누르면 즉시 실행하지 말고 한 번 더 확인한다.

표시 문구:

- 제목: `처음부터 다시 시작할까요?`
- 설명: `기존 진행 내용은 종료되고 황금열쇠 N개가 새로 소모됩니다.`

버튼:

- `취소`
- `새로 시작하기`

확인 후에만 기존 세션 종료와 신규 예약을 진행한다.

## 황금열쇠 처리 원칙

- 이어하기: 추가 차감 0회
- 새로 시작하기: 해당 놀이 비용 정확히 1회 차감
- 더블클릭 또는 연속 탭: 중복 차감 금지
- 다중 탭 또는 다중 기기 동시 실행: 중복 신규 세션 생성 금지
- 이미 실행 중인 신규 시작 요청이 있으면 버튼 비활성화 및 로딩 상태 표시
- 예약 실패 시 기존 세션 상태와 황금열쇠 잔액이 불일치하지 않도록 트랜잭션 또는 멱등 처리 적용
- 예약만 되고 실행이 확정되지 않은 경우 기존 restore/refund 정책 유지

## 서버 및 세션 처리

### 공통 세션 조회

놀이 카드 클릭 시 다음을 확인한다.

- `child_id`
- `play_type`
- 현재 `in_progress` 세션 존재 여부
- `resume_expires_at`
- 이어하기 가능 여부
- 저장된 `progress_state`

### 이어하기 조건

다음 조건을 모두 만족하는 경우에만 이어하기 가능으로 판단한다.

- 상태가 `in_progress`
- `resume_expires_at`이 현재 시각보다 이후
- 세션 소유자가 현재 아이 계정과 일치
- 해당 놀이 타입과 일치

### 만료된 세션

- `status='in_progress'`이더라도 `resume_expires_at`이 지난 세션은 이어하기 대상으로 표시하지 않는다.
- 신규 시작 전 동일 트랜잭션 안에서 적절한 종료 상태로 전환한다.
- 이미 confirm된 황금열쇠 소비 건은 환급하지 않는다.
- reserve만 되고 confirm되지 않은 건은 기존 복구 정책에 따라 처리한다.

## UI 요구사항

- 모바일 기준 모달 안에서 세 버튼이 잘리지 않아야 한다.
- 권장 배치:
  - 첫 번째 줄: `취소`
  - 두 번째 줄: `새로 시작하기` / `이어하기`
- 또는 충분한 폭에서는 3개 버튼을 한 줄에 배치할 수 있다.
- `이어하기`를 주 버튼으로 표시한다.
- `새로 시작하기`는 경고성 보조 버튼으로 구분한다.
- 태블릿과 PC에서도 동일한 우선순위와 문구 유지
- 기존 디자인 시스템의 색상, 모서리, 그림자, 타이포그래피 사용

## 적용 범위

### 반드시 적용

- MBTI
- 퀴즈마스터
- 향후 `k_play_sessions` 또는 공통 놀이 세션 구조를 사용하는 모든 실행 가능한 놀이

### 적용 제외

- 만화책 읽기
- 헤어스타일

두 놀이는 현재 `준비 중입니다` 안내만 표시하며 세션 생성과 황금열쇠 차감을 하지 않는다.

## 회귀 방지 조건

- MBTI 신규 시작 정상
- MBTI 이어하기 정상
- MBTI 새로 시작하기 정상
- 퀴즈마스터 신규 시작 정상
- 퀴즈마스터 이어하기 정상
- 퀴즈마스터 새로 시작하기 정상
- 완료 callback 정상
- refund callback 정상
- 만료 세션 신규 시작 정상
- 만화책/헤어스타일 황금열쇠 차감 없음
- 다른 아이의 세션을 이어하지 못하도록 소유권 검증 유지

## 필수 테스트 시나리오

### 시나리오 A: 신규 시작

1. 진행 중 세션이 없는 아이로 놀이 카드 클릭
2. `취소 / 시작하기`만 표시되는지 확인
3. 시작하기 선택
4. 황금열쇠가 정확히 1회 차감되는지 확인
5. 신규 세션이 1개만 생성되는지 확인

### 시나리오 B: 이어하기

1. 놀이를 일부 진행한 뒤 이탈
2. 같은 놀이 카드 재클릭
3. `취소 / 새로 시작하기 / 이어하기`가 표시되는지 확인
4. 이어하기 선택
5. 기존 위치부터 복원되는지 확인
6. 황금열쇠가 추가 차감되지 않는지 확인

### 시나리오 C: 새로 시작하기

1. 이어하기 가능한 세션이 있는 상태에서 카드 클릭
2. 새로 시작하기 선택
3. 재확인 모달 표시 확인
4. 최종 확인
5. 기존 세션이 물리 삭제되지 않고 종료 상태로 전환되는지 확인
6. 신규 세션이 생성되는지 확인
7. 황금열쇠가 정확히 1회 차감되는지 확인
8. 첫 문제부터 시작되는지 확인

### 시나리오 D: 더블클릭·다중 탭

1. 시작하기 또는 새로 시작하기를 빠르게 여러 번 클릭
2. 황금열쇠 중복 차감 없음 확인
3. 신규 세션 중복 생성 없음 확인

### 시나리오 E: 만료된 세션

1. `status='in_progress'`이지만 `resume_expires_at`이 지난 세션 준비
2. 카드 클릭
3. 이어하기 모달이 표시되지 않는지 확인
4. 신규 시작 가능 여부 확인
5. 기존 만료 세션이 안전하게 종료되는지 확인

### 시나리오 F: 준비 중 놀이

1. 만화책 읽기 클릭
2. `준비 중입니다`만 표시
3. 황금열쇠 변화 없음 확인
4. 헤어스타일도 동일 검증
