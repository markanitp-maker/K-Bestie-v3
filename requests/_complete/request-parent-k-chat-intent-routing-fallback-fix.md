# 부모–케이 대화 의도 분류 및 No-Result Fallback 개선 요청

## 1. 작업 목적

부모–케이 대화에서 사용자의 모든 입력을 아이 정보 검색 질문으로 처리하여, 일반적인 대화에도 아래 고정 응답이 반복되는 문제를 수정한다.

> 그 부분은 아직 케이가 알고 있는 내용이 없어요. 다음 대화에서 아이에게 자연스럽게 한 번 물어볼까요?

이번 작업의 핵심은 다음 두 가지다.

1. 일반 대화·연결 확인·인사·감사·답변 지적은 LLM Wiki 조회 없이 자연스럽게 대화한다.
2. 실제 아이 정보 질문에만 리포트·보정 대화·LLM Wiki Retrieval을 실행하고, 검색 결과가 없더라도 해당 질문에 한정된 자연스러운 답변을 제공한다.

우선순위는 **P0**이다.

---

## 2. 현재 확인된 문제

### 재현 입력

```text
내 말 잘 들리니
```

### 현재 잘못된 응답

```text
그 부분은 아직 케이가 알고 있는 내용이 없어요.
다음 대화에서 아이에게 자연스럽게 한 번 물어볼까요?
```

### 정상 응답 예시

```text
네, 잘 들려요. 편하게 말씀해 주세요.
```

---

### 재현 입력

```text
야 이런 질문 하면 네 잘 들립니다 라고 해야지
그 부분은 아직 케이가 알고 있는 내용이 없다라고 하면
일단 일반적인 대화는 자연스럽게 이어가야 될 거 아니야
```

### 현재 잘못된 동작

- 사용자 지적을 이해하거나 인정하지 않는다.
- 이전과 동일한 No-Result Fallback을 반복한다.
- 부모–케이 대화 전체가 아이 정보 검색 전용 화면처럼 동작한다.

### 정상 응답 예시

```text
맞아요. 방금 답변은 잘못됐어요.
일반적인 대화는 자연스럽게 이어가야 해요.
지금 말씀해 주세요.
```

---

## 3. 원인 가설

아래 가설을 코드와 런타임 로그로 확인한 뒤 수정한다.

1. 부모 입력 전체를 조건 없이 Vector Retrieval 또는 `search_memory_facts`로 전달한다.
2. Retrieval 결과가 0건이면 질문 의도와 관계없이 고정 Fallback을 반환한다.
3. 일반 대화용 LLM 응답 경로가 없거나 Retrieval No-Result 분기 뒤에 있어 도달하지 못한다.
4. 사용자 피드백·정정·재질문을 별도 의도로 분류하지 않는다.
5. No-Result Fallback과 `아이에게 물어보기` 버튼이 모든 응답 유형에 공통으로 노출된다.

파일명이나 함수명은 추측하지 말고 실제 부모–케이 API Route, Server Action, Intent Router, Retrieval 함수, Prompt, UI 컴포넌트를 추적하여 수정한다.

## 4. 필수 의도 분류

부모 입력을 최소한 아래 네 유형으로 분류한다.

### A. `GENERAL_CONVERSATION`

아이 기록 조회가 필요 없는 일반적인 대화다.

포함 예시:

- 안녕
- 내 말 잘 들리니?
- 고마워
- 지금 대화 가능해?
- 무슨 뜻이야?
- 다시 말해 줘
- 오늘 기분 어때?
- 너는 누구야?

처리 기준:

- LLM Wiki, 리포트, 보정 대화, Vector Retrieval을 호출하지 않는다.
- 부모–케이 페르소나에 맞는 자연스러운 짧은 답변을 생성한다.
- `아이에게 물어보기`, `지금은 넘어가기` 버튼을 노출하지 않는다.

---

### B. `CHILD_INFORMATION_QUERY`

특정 아이의 생활·감정·관계·관심사·사건·최근 변화·날짜별 활동을 묻는 질문이다.

포함 예시:

- 서현이가 어제 뭐 했니?
- 요즘 학교생활은 어때?
- 최근에 친구 때문에 속상해한 적 있어?
- 서현이가 좋아하는 게 뭐야?
- 이번 주에 기분 변화가 있었어?
- 오늘 케이와 무슨 이야기를 했어?

처리 기준:

1. 질문에 시간 표현이 있으면 KST 기준 `business_date` 또는 조회 기간을 먼저 계산한다.
2. 날짜형 질문은 해당 날짜의 Daily Report 또는 `corrected_daily_conversations_v3` 기반 안전한 요약을 우선 사용한다.
3. 장기 성향·관심사·반복 패턴 질문은 `memory_facts`, `memory_evidence`, `memory_embeddings` 기반 Retrieval을 사용한다.
4. 두 경로가 모두 필요한 질문은 날짜 근거와 장기 기억을 함께 사용하되 중복 문장을 제거한다.
5. 다른 아이의 데이터가 섞이지 않도록 `child_id`를 모든 조회 단계에서 강제한다.
6. 부모에게 raw 원문을 그대로 노출하지 않는다.

---

### C. `FEEDBACK_OR_CORRECTION`

사용자가 케이의 직전 답변을 지적하거나 응답 방식을 수정하도록 요구하는 경우다.

포함 예시:

- 그 답변 이상해
- 내 말 안 들려?
- 그런 질문에는 잘 들린다고 해야지
- 왜 똑같은 말만 해?
- 방금 답변 다시 해
- 내가 묻는 말에 답해

처리 기준:

- Retrieval을 실행하지 않는다.
- 문제를 인정하고 대화를 복구한다.
- 직전 사용자 의도를 다시 해석해 올바른 답변을 제공한다.
- 동일한 No-Result 문구를 반복하지 않는다.

정상 응답 예시:

```text
맞아요. 방금 답변은 질문과 맞지 않았어요.
말씀은 잘 들리고 있어요. 편하게 이어서 말씀해 주세요.
```

---

### D. `CHILD_INFORMATION_NO_RESULT`

`CHILD_INFORMATION_QUERY`로 분류됐지만 관련 근거가 실제로 없는 경우다.

처리 기준:

- “케이가 아무것도 모른다”는 인상을 주지 않는다.
- 질문 범위를 한정해 설명한다.
- 확인한 데이터 범위를 간단히 알려준다.
- 아이에게 다시 묻기는 선택 가능한 보조 행동으로만 제공한다.
- 같은 Fallback 문구를 연속 반복하지 않는다.

정상 응답 예시:

```text
제가 확인할 수 있는 어제 기록에는 서현이가 무엇을 했는지 구체적인 내용이 남아 있지 않아요.
학교생활, 친구, 기분 중 궁금한 부분을 말씀해 주시면 그 범위로 다시 확인해 볼게요.
```

버튼 노출 조건:

- `아이에게 물어보기`: `CHILD_INFORMATION_NO_RESULT`일 때만 노출
- `지금은 넘어가기`: `CHILD_INFORMATION_NO_RESULT`일 때만 노출
- 일반 대화, 인사, 연결 확인, 피드백 응답에는 노출 금지

---

## 5. 의도 분류 구현 원칙

### 5.1 단순 키워드만으로 결정하지 않는다

`서현`, `아이`, `학교` 같은 단어가 있다고 무조건 Retrieval로 보내지 않는다.

예시:

```text
서현이 이야기하기 전에 내 말 잘 들리는지 확인할게
```

위 입력은 우선 `GENERAL_CONVERSATION` 또는 `FEEDBACK_OR_CORRECTION`으로 처리해야 한다.

---

### 5.2 고신뢰 규칙과 LLM 분류를 조합한다

권장 순서:

1. 인사·감사·연결 확인·답변 수정 요청 등 명확한 패턴은 로컬 규칙으로 우선 분류
2. 명확하지 않은 경우에만 경량 Intent Classification 실행
3. 분류 결과와 confidence를 기록
4. confidence가 낮으면 Retrieval부터 실행하지 말고 일반 대화 응답으로 안전하게 처리하거나, 아이 정보 질문인지 자연스럽게 확인

의도 분류 출력 예시:

```json
{
  "intent": "GENERAL_CONVERSATION",
  "confidence": 0.98,
  "requiresChildContext": false,
  "requiresTimeRange": false
}
```

---

### 5.3 Retrieval은 명시적으로 허용된 경우에만 호출한다

아래 조건을 모두 만족할 때만 Retrieval을 실행한다.

```text
intent === CHILD_INFORMATION_QUERY
AND authenticated parent-child relationship is valid
AND selected child_id exists
```

`GENERAL_CONVERSATION` 또는 `FEEDBACK_OR_CORRECTION`에서 Retrieval 함수가 호출되면 테스트 실패로 처리한다.

---

## 6. 응답 생성 규칙

### 일반 대화

- 질문에 직접 답한다.
- 짧고 자연스럽게 이어간다.
- 아이 정보가 없다는 문구를 포함하지 않는다.

예시:

| 입력 | 정상 응답 |
|---|---|
| 내 말 잘 들리니? | 네, 잘 들려요. 편하게 말씀해 주세요. |
| 안녕 | 안녕하세요. 서현이에 관해 궁금한 점이나 나누고 싶은 이야기를 말씀해 주세요. |
| 고마워 | 네, 언제든 말씀해 주세요. |
| 다시 말해 줘 | 네. 이해하기 쉽게 다시 말씀드릴게요. |

### 피드백·정정

- 먼저 잘못을 인정한다.
- 같은 오류 응답을 반복하지 않는다.
- 사용자가 처음 원했던 답변을 바로 제공한다.

### 아이 정보 있음

- 근거가 확인된 내용만 답한다.
- 추측을 사실처럼 말하지 않는다.
- 필요하면 “기록상”, “확인된 대화에서는”처럼 근거 범위를 표현한다.
- raw 대화 원문은 노출하지 않는다.

### 아이 정보 없음

- “그 부분” 같은 모호한 표현을 피한다.
- 어떤 날짜·주제에서 정보가 부족한지 명시한다.
- 시스템 장애와 실제 기록 부재를 구분한다.
- Retrieval 오류가 발생한 경우 정상적인 No-Result처럼 위장하지 않는다.

오류 예시:

```text
지금은 기록을 확인하는 과정에서 문제가 생겼어요.
잠시 후 다시 확인해 주세요.
```

실제 정보 없음 예시:

```text
이번 주 기록에서는 친구 관계에 관한 구체적인 내용이 확인되지 않았어요.
```

## 7. 연속 대화 컨텍스트 처리

1. 최근 대화 메시지를 유지하여 “그거”, “아까 말한 것”, “다시 답해 줘”를 이해한다.
2. 직전 응답이 No-Result였더라도 이후 일반 대화까지 No-Result 상태를 전파하지 않는다.
3. 각 사용자 턴마다 의도를 새로 분류한다.
4. `lastIntent`, `lastRetrievalStatus`를 참고할 수는 있지만 현재 입력보다 우선하지 않는다.
5. 사용자가 오류를 지적하면 직전 실패 상태를 초기화하고 복구 응답을 생성한다.
6. 동일한 Fallback이 두 턴 연속 자동 반복되지 않도록 방어 로직을 추가한다.

## 8. UI 개선 요구사항

### 8.1 빠른 행동 버튼

`아이에게 물어보기`, `지금은 넘어가기` 버튼은 다음 조건에서만 표시한다.

```text
intent === CHILD_INFORMATION_QUERY
AND retrievalStatus === NO_RESULT
AND no system error occurred
```

다음 경우에는 표시하지 않는다.

- 일반 대화
- 연결 확인
- 인사·감사
- 사용자의 답변 지적
- Retrieval 시스템 오류
- 정상적으로 아이 정보를 답변한 경우

### 8.2 스크롤 및 입력

- 새 응답이 생성되면 최신 메시지가 보이도록 자동 스크롤한다.
- 입력창은 응답 생성 후 다시 활성화한다.
- 동일한 고정 Fallback과 버튼이 중복 렌더링되지 않도록 message ID 기준으로 방지한다.

## 9. 로깅 및 관측성

개인정보와 대화 원문은 로그에 남기지 않는다.

각 턴마다 아래 항목을 구조화 로그로 기록한다.

```json
{
  "route": "parent-k-chat",
  "requestId": "masked-or-generated-id",
  "childId": "masked",
  "intent": "GENERAL_CONVERSATION",
  "intentConfidence": 0.98,
  "retrievalAttempted": false,
  "retrievalSource": [],
  "retrievalResultCount": 0,
  "responseMode": "GENERAL_CHAT",
  "fallbackReason": null,
  "latencyMs": 0
}
```

필수 구분:

- `NO_DATA`: 정상 조회했으나 관련 정보 없음
- `RETRIEVAL_ERROR`: DB, RPC, Embedding, 권한, 네트워크 오류
- `NOT_APPLICABLE`: 일반 대화라 Retrieval 미실행
- `HAS_RESULT`: 근거 검색 성공

`RETRIEVAL_ERROR`를 `NO_DATA`로 변환하지 않는다.

## 10. 테스트 요구사항

### 10.1 단위 테스트

다음 입력의 의도 분류와 Retrieval 호출 여부를 검증한다.

| 입력 | 기대 Intent | Retrieval |
|---|---|---|
| 내 말 잘 들리니? | GENERAL_CONVERSATION | 호출 금지 |
| 안녕 | GENERAL_CONVERSATION | 호출 금지 |
| 고마워 | GENERAL_CONVERSATION | 호출 금지 |
| 왜 같은 말만 해? | FEEDBACK_OR_CORRECTION | 호출 금지 |
| 그런 질문에는 잘 들린다고 해야지 | FEEDBACK_OR_CORRECTION | 호출 금지 |
| 서현이가 어제 뭐 했니? | CHILD_INFORMATION_QUERY | 호출 |
| 요즘 서현이가 좋아하는 게 뭐야? | CHILD_INFORMATION_QUERY | 호출 |
| 서현이 이야기 전에 내 말 들리는지 확인할게 | GENERAL_CONVERSATION | 호출 금지 |
| 어제 학교에서 무슨 일 있었어? | CHILD_INFORMATION_QUERY | 호출 |
| 다시 답해 줘 | 문맥 기반 FEEDBACK_OR_CORRECTION | 호출 금지 |

---

### 10.2 통합 테스트

#### 시나리오 A: 일반 대화

1. 부모 계정 로그인
2. 케이와 대화 진입
3. `내 말 잘 들리니?` 입력
4. 정상적인 연결 확인 응답 수신
5. Retrieval 관련 DB/RPC 호출 0회 확인
6. 빠른 행동 버튼 미노출 확인

#### 시나리오 B: 사용자 지적 후 복구

1. 테스트 환경에서 의도적으로 잘못된 응답 상황 재현
2. `그런 질문에는 잘 들린다고 해야지` 입력
3. 케이가 잘못을 인정하고 올바른 답변으로 복구
4. 동일 Fallback 반복 없음
5. Retrieval 호출 0회 확인

#### 시나리오 C: 아이 정보 조회 성공

1. 해당 아이의 리포트 또는 Memory 데이터 준비
2. `서현이가 어제 뭐 했니?` 입력
3. KST 날짜 범위가 정확히 계산되는지 확인
4. 근거 기반 답변 확인
5. 다른 아이 데이터 0건 포함 확인
6. raw 원문 미노출 확인

#### 시나리오 D: 실제 정보 없음

1. 관련 날짜·주제 데이터가 없는 테스트 아이 사용
2. 아이 정보 질문 입력
3. 질문 범위를 한정한 No-Result 답변 확인
4. `아이에게 물어보기`, `지금은 넘어가기` 버튼 노출 확인
5. 일반 대화로 이어서 `고마워` 입력
6. 자연스러운 일반 답변과 버튼 미노출 확인

#### 시나리오 E: Retrieval 장애

1. Dev에서 Retrieval 의존성을 실패하도록 모킹
2. 아이 정보 질문 입력
3. `NO_DATA`가 아닌 `RETRIEVAL_ERROR`로 기록되는지 확인
4. “알고 있는 내용이 없다”는 정상 Fallback으로 위장하지 않는지 확인
5. 사용자에게 재시도 가능한 오류 안내 제공

### 10.3 회귀 테스트

- 부모–케이 기존 인증 및 부모–아이 권한 검증 유지
- 자녀 선택 변경 시 올바른 `child_id` 사용
- Daily Report, corrected conversation, Memory Retrieval 정상 유지
- `아이에게 물어보기` 기존 후속 처리 기능 유지
- 음성 입력과 텍스트 입력에서 동일한 Intent Routing 적용
- TTS 재생 버튼이 응답 유형과 무관하게 정상 동작
- 다른 부모가 타 가족 아이 데이터를 조회할 수 없음
- 기존 리포트 화면과 아이용 대화 기능에 영향 없음

## 11. 완료 기준

아래 조건을 모두 만족해야 완료다.

- [ ] `내 말 잘 들리니?`에 자연스러운 일반 대화 응답이 반환된다.
- [ ] 일반 대화에서는 LLM Wiki Retrieval이 호출되지 않는다.
- [ ] 사용자 지적을 인식하고 잘못을 인정한 뒤 대화를 복구한다.
- [ ] 아이 정보 질문에서만 리포트·보정 대화·Memory Retrieval이 실행된다.
- [ ] 실제 정보 없음과 시스템 오류가 구분된다.
- [ ] No-Result Fallback이 질문 범위를 한정해 설명한다.
- [ ] 빠른 행동 버튼이 No-Result 아이 정보 질문에서만 표시된다.
- [ ] 동일 Fallback이 연속으로 반복되지 않는다.
- [ ] 날짜 질문은 KST 기준으로 조회된다.
- [ ] 부모에게 raw 대화 원문이 노출되지 않는다.
- [ ] `child_id` 격리 테스트가 통과한다.
- [ ] 단위·통합·회귀 테스트가 모두 통과한다.
- [ ] TypeScript 타입 검사와 빌드가 통과한다.
- [ ] Development 실제 UI E2E가 통과한 뒤에만 Production으로 배포한다.

1. 현재 Dev/Production 코드, 환경변수 키 이름, 배포 Commit 차이 확인
2. Development에서 문제 재현
3. Intent Routing, Retrieval 조건, Fallback, UI 버튼 조건 수정
4. 단위 테스트 및 통합 테스트 실행
5. Development 배포
6. 부모 테스트 계정으로 실제 UI E2E 수행
7. 로그에서 일반 대화 Retrieval 0회 확인
8. 아이 정보 성공·No-Result·Retrieval Error 세 경우 확인
9. Production 배포 전 변경 파일과 영향 범위 보고
10. Production 배포
11. 안서현 부모 계정에서 아래 문장으로 최종 검증

```text
내 말 잘 들리니?
```

기대 응답:

```text
네, 잘 들려요. 편하게 말씀해 주세요.
```

이어서 입력:

```text
그런 질문에는 잘 들린다고 해야지
```

기대 응답:

```text
맞아요. 방금 답변은 잘못됐어요.
말씀은 잘 들리고 있어요. 편하게 이어서 말씀해 주세요.
```

이어서 입력:

```text
서현이가 어제 뭐 했니?
```

기대 결과:

- 아이 정보 조회 경로 실행
- 데이터가 있으면 근거 기반 답변
- 데이터가 없으면 해당 날짜에 한정된 No-Result 답변
- 시스템 오류가 있으면 오류로 명확히 구분
- 일반 대화 Fallback과 혼용 금지
