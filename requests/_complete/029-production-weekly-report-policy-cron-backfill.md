# REQUEST 029 — Production 주간 리포트 정책·Cron·누락분 전체 복구

## 1. 목적

Production 주간 리포트 기능을 아래 3개 작업으로 정상화한다.

1. 실제 주간 집계 정책이 `토요일 ~ 금요일`인지 확인하고, 다르면 생성기/API/UI 기준을 동일하게 수정한다.
2. Production에서 주간 리포트 Cron이 `매주 토요일 06:00 KST`에 실제 실행되도록 확인하고, 꺼져 있으면 활성화하고, 없으면 생성하고, 잘못돼 있으면 수정한다.
3. 지난 완료 주간 `2026-08-01 ~ 2026-08-07` 주간 리포트가 누락된 전체 사용자를 찾아 누락자 전원의 주간 리포트를 생성한다.

이번 요청은 조사만 하고 끝내지 않는다. 실제 수정, Production 적용, 누락분 백필, 최종 검증까지 완료한다.

---

## 2. 대표 확정 정책

```text
주간 집계: 토요일 ~ 금요일
주간 리포트 자동 생성: 다음 토요일 06:00 KST
```

예:

```text
2026-08-01(토) ~ 2026-08-07(금)
→ 2026-08-08(토) 06:00 생성

2026-08-08(토) ~ 2026-08-14(금)
→ 2026-08-15(토) 06:00 생성
```

현재 날짜 기준:
- 지난 완료 주간: `2026-08-01 ~ 2026-08-07`
- 현재 진행 주간: `2026-08-08 ~ 2026-08-14`

현재 진행 주간은 지금 생성하지 않는다.

---

# PHASE 1 — 실제 Production 주간 정책 확인 및 수정

## 목표
현재 실제 호출되는 주간 집계 로직이 토요일~금요일인지 확인하고, 다르면 수정한다.

## 확인 대상
- `generateWeeklySummary`
- `getWeekBounds`
- `weeklyDates`
- weekly batch entrypoint
- `weekly_summaries`
- 부모 주간 리포트 API
- 부모 주간 리포트 UI
- 현재 주/지난 주 계산 로직

레거시나 미사용 코드는 판단 근거에서 제외한다.

## 확인 내용
다음이 서로 일치하는지 확인한다.
- 생성기 `week_start`
- 생성기 `week_end`
- DB 저장값
- API 조회 기간
- UI 표시 기간

현재 구현이 월~일, rolling 7일, 기타 방식이면 대표 확정 정책인 토~금으로 수정한다.

## 필수 테스트

| 실행 시각 | 기대 week_start | 기대 week_end |
|---|---|---|
| 2026-08-08 06:00 KST | 2026-08-01 | 2026-08-07 |
| 2026-08-15 06:00 KST | 2026-08-08 | 2026-08-14 |
| 2026-08-22 06:00 KST | 2026-08-15 | 2026-08-21 |

가능하면 주간 경계 계산을 공통 함수 하나로 통일한다.

기존 정상 과거 주간 리포트는 일괄 수정·삭제·재생성하지 않는다.

# PHASE 2 — Production 주간 Cron 확인 및 정상화

## 목표
Production에서 실제 주간 배치가 매주 토요일 06:00 KST에 실행되도록 만든다.

## 기대 스케줄

```text
KST: 매주 토요일 06:00
UTC: 매주 금요일 21:00
Cron: 0 21 * * 5
```

## 반드시 실제 Scheduler 확인
migration 파일에 설정이 적혀 있다는 이유만으로 등록됐다고 판단하지 않는다.

실제 Production Supabase `pg_cron` 또는 실제 운영 Scheduler에서 확인한다.

확인 항목:
- Job 존재 여부
- Job name
- active 여부
- cron expression
- endpoint/function
- auth
- 최근 실행 이력
- 다음 실행 예정 시각
- 중복 Job 존재 여부

## 상태별 조치
- Job 존재 + inactive → 활성화
- Job 없음 → 새로 생성
- schedule 오류 → 토요일 06:00 KST로 수정
- endpoint/auth 오류 → 현재 weekly batch 기준으로 수정
- 중복 Job → 정상 Job 1개만 유지

Cron 등록/수정은 멱등하게 처리한다.

## 완료 기준

```text
active = true
schedule = 0 21 * * 5
KST = Saturday 06:00
next expected run = 2026-08-15 06:00 KST
```

# PHASE 3 — 지난 완료 주간 누락자 전체 검색

## 대상 주간

```text
week_start = 2026-08-01
week_end   = 2026-08-07
```

## 목표
특정 사용자 몇 명만 보는 것이 아니라 Production 전체 생성 대상자를 검사한다.

각 사용자마다 확인:
1. 해당 기간 주간 리포트 생성 대상 여부
2. 해당 기간 입력 데이터 존재 여부
3. 동일 `week_start/week_end` 주간 리포트 존재 여부
4. 없으면 누락자로 분류

안서아·안서현·윤도원·윤도건은 반드시 포함해서 결과를 확인하되 이 4명으로 범위를 제한하지 않는다.

개념적 멱등 기준:

```text
child_id + week_start + week_end
```

# PHASE 4 — 누락자 전원 주간 리포트 백필

PHASE 3에서 확인된 누락 대상자만 생성한다.

입력 범위:

```text
2026-08-01 00:00 KST
~
2026-08-07 23:59:59 KST
```

`2026-08-08` 이후 데이터는 포함하지 않는다.

기존 정상화된 주간 리포트 생성 core logic을 재사용한다.

금지:
- 전체 weekly_summaries 삭제 후 재생성
- 기존 정상 리포트 덮어쓰기
- 다른 주차 수정
- 현재 진행 주간 `2026-08-08 ~ 2026-08-14` 선생성
- 특정 4명만 생성하고 종료

백필 재실행 시 중복 생성되지 않아야 한다.

# PHASE 5 — 최종 검증

## 지난 완료 주간
`2026-08-01 ~ 2026-08-07`

생성 대상 사용자 중 최종 누락자 0명이어야 한다.

## 현재 진행 주간
`2026-08-08 ~ 2026-08-14`

현재는 집계 중이어야 하며 weekly summary가 미리 생성되면 안 된다.

## 다음 자동 실행
`2026-08-15 06:00 KST`

이 실행에서 `2026-08-08 ~ 2026-08-14` 주간 리포트가 생성될 준비가 완료되어 있어야 한다.

## 부모 UI
논리적으로 다음 상태가 보여야 한다.

```text
8/8 ~ 8/14
이번 주
집계 중

8/1 ~ 8/7
지난 완료 주간
주간 리포트 표시
```

기존 정상 과거 리포트는 유지한다.
