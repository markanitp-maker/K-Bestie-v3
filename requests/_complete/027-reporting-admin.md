# Request: 관리자 리포팅 수동 실행 현황 필터 기능 추가

## 목적

관리자 페이지의 "리포팅 수동 실행" 화면에서 현재 모든 아이 상태가 한 번에 표시되어 있어, 성공/실패/대기 상태를 빠르게 확인하기 어렵습니다.

실행 결과 상태별 필터 기능을 추가하여 운영자가 오류 대상과 처리 대기 대상을 빠르게 확인할 수 있도록 개선합니다.

---

# 1. UI 변경

위치:

리포팅 수동 실행 화면 우측 상단

현재:

```
검색 영역
```

변경:

검색 영역 우측에 상태 필터 버튼 추가

UI:

```
[전체] [성공] [실패] [대기]
```

기본 선택:

```
전체
```

---

# 2. 필터 동작 정의

## 전체

목적:
전체 사용자 현황 확인

조건:

- 성공
- 실패
- 대기

모든 상태 표시


예:

```
TestA   대기
고나연   완료
고보강   실패
```

---

## 성공

목적:
모든 처리 단계가 정상 완료된 사용자만 확인


조건:

아래 모든 항목이 성공 상태인 경우만 표시

검사 대상:

- 1차 수집 18:00
- 2차 수집 23:59:59
- 보정
- Memory Batch
- 리포트 생성


예:

```
1차 수집 완료
2차 수집 완료
보정 완료
Memory Batch 완료
리포트 완료
```

모든 단계 완료 사용자만 노출


---

## 실패

목적:
오류가 발생한 사용자 확인


조건:

아래 항목 중 하나라도 실패 상태이면 표시

검사 대상:

- 1차 수집 실패
- 2차 수집 실패
- 보정 실패
- Memory Batch 실패
- 리포트 생성 실패


예:

```
1차 수집 완료
2차 수집 실패
보정 대기
Memory Batch 대기
리포트 대기
```

실패 필터에서 표시


---

## 대기

목적:
아직 처리되지 않은 사용자 확인


조건:

아래 항목 중 하나라도 대기 상태이면 표시


검사 대상:

- 1차 수집 대기
- 2차 수집 대기
- 보정 대기
- Memory Batch 대기
- 리포트 대기


예:

```
1차 수집 완료
2차 수집 대기
보정 대기
Memory Batch 대기
리포트 대기
```

대기 필터에서 표시


---

# 3. 상태 판정 우선순위

한 사용자가 여러 상태를 동시에 가지고 있을 경우:

우선순위:

```
실패 > 대기 > 성공
```

단, 필터는 아래 기준으로 동작

- 성공:
  모든 단계 성공

- 실패:
  하나라도 실패 존재

- 대기:
  실패는 없고 하나라도 대기 존재


예:

```
1차 수집 완료
2차 수집 실패
보정 대기
```

결과:

- 전체 표시 O
- 실패 표시 O
- 대기 표시 X
- 성공 표시 X


---

# 4. 데이터 처리

기존 API 데이터를 유지한다.

추가 API 생성 불필요.

Frontend에서 현재 상태 데이터를 기준으로 필터링 처리.


---

# 5. UX 요구사항

- 버튼 선택 상태 명확히 표시
- 선택 변경 시 즉시 리스트 업데이트
- 페이지 새로고침 없이 필터 적용
- 현재 선택 상태 유지


---

# 6. 검증

확인:

1. 전체 선택 시 모든 사용자 표시
2. 성공 선택 시 모든 단계 완료 사용자만 표시
3. 실패 선택 시 하나라도 실패한 사용자 표시
4. 대기 선택 시 하나라도 대기 상태인 사용자 표시
5. 필터 변경 시 데이터 오류 없음
6. 기존 수집/보정/Memory Batch/리포트 실행 기능 영향 없음


---

# 완료 기준

관리자는 리포팅 수동 실행 화면에서:

- 전체 처리 현황 확인
- 완료된 사용자만 확인
- 실패 사용자만 추출
- 아직 처리되지 않은 사용자 확인

이 가능해야 한다.

Dev / Production 동일 적용
