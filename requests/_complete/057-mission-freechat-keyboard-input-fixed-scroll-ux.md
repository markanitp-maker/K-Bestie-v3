# 057 — 미션·자유대화 키보드 입력 UX 개선

## 1. 작업 목적

미션과 자유대화에서 아이가 키보드 입력 모드로 전환했을 때, 케이의 최근 질문을 다시 찾기 위해 화면을 이동하거나 키보드를 반복해서 열고 닫아야 하는 불편을 해결한다.

아이의 사용 의도는 다음과 같다.

> 케이의 질문을 보면서 바로 키보드로 답한다.

따라서 키보드가 열린 상태에서도 입력창은 항상 키보드 바로 위에 고정하고, 그 위의 대화 화면만 스크롤 가능하게 하며, 기본 위치는 케이의 가장 최근 질문 말풍선이 보이도록 한다.

---

## 2. 적용 범위

다음 화면에 동일하게 적용한다.

- 미션 대화
- 자유대화
- 자동 모드
- 수동 모드
- iPhone Safari
- iPhone 설치형 PWA
- Android Chrome
- Android 설치형 PWA

음성 대화 로직, 미션 질문 순환, 자유대화 정책, 저장 로직은 변경하지 않는다.

---

## 3. 현재 문제

현재 키보드 입력 모드에서는 다음 문제가 발생한다.

- 소프트 키보드가 열리면서 화면 높이가 크게 줄어든다.
- 입력창과 전송 버튼이 화면 레이아웃 흐름에 따라 함께 움직인다.
- 케이의 최근 질문 말풍선이 화면 밖으로 밀리거나 가려질 수 있다.
- 아이가 질문을 다시 확인하려면 키보드를 닫거나 대화 화면을 다시 찾아야 한다.
- 키보드가 열린 상태에서 전체 화면이 우측으로 밀리거나 잘리는 문제가 발생한 사례가 있다.
- 입력창을 기준으로 대화 영역과 조작 영역이 명확히 분리되어 있지 않다.

---

## 4. 확정 UX 정책

### 4.1 키보드 입력 모드 진입

키보드 버튼을 누르면 다음 순서로 동작한다.

```text
키보드 입력 모드 전환
→ 입력창에 포커스
→ 소프트 키보드 표시
→ 입력창과 전송 버튼을 키보드 바로 위에 고정
→ 대화 영역 높이를 남은 공간으로 재계산
→ 케이의 가장 최근 질문 말풍선이 보이도록 자동 스크롤
```

### 4.2 입력창 고정

- 텍스트 입력창과 전송 버튼은 하나의 고정 입력 영역으로 묶는다.
- 소프트 키보드가 열리면 입력 영역은 키보드 상단 바로 위에 위치한다.
- 키보드 높이가 달라져도 입력 영역이 키보드에 가려지면 안 된다.
- 입력 영역이 화면 우측으로 밀리거나 잘리면 안 된다.
- 입력창과 전송 버튼의 합산 너비는 화면 안에 들어와야 한다.
- 취소 또는 닫기 버튼이 있다면 같은 입력 영역 안에서 정상 노출되어야 한다.

### 4.3 대화 영역 스크롤

- 입력창 위의 대화 영역만 세로 스크롤 가능하게 한다.
- 페이지 전체가 스크롤되는 구조로 만들지 않는다.
- 대화 영역에는 `min-height: 0`과 `overflow-y: auto`를 적용한다.
- 가로 스크롤은 금지한다.
- 기존 말풍선 폭과 중앙 정렬을 유지한다.

### 4.4 기본 스크롤 위치

키보드가 처음 열릴 때 다음 기준으로 자동 이동한다.

- 가장 최근 케이 질문 말풍선이 입력창 위에 보이도록 한다.
- 질문 말풍선 전체가 가능하면 노출되어야 한다.
- 공간이 부족하면 질문 말풍선의 하단과 입력창 사이가 우선 보이도록 한다.
- 아이가 질문을 다시 찾기 위해 별도로 스크롤하지 않게 한다.

### 4.5 자동 스크롤 발생 시점

자동 스크롤은 다음 경우에만 실행한다.

1. 키보드 입력 모드에 처음 진입했을 때
2. 아이가 메시지를 전송한 직후
3. 케이의 새 질문이 도착했고 사용자가 대화 하단을 보고 있을 때

다음 경우에는 자동 스크롤하지 않는다.

- 아이가 직접 위로 스크롤하여 이전 대화를 보고 있을 때
- 입력 중 커서 위치를 조정하고 있을 때
- 이전 대화를 확인하기 위해 의도적으로 스크롤한 상태

사용자가 하단으로 돌아갈 수 있도록 필요하면 `최신 대화 보기` 보조 버튼을 제공할 수 있으나, 기존 UI를 복잡하게 만들지 않는 범위에서만 적용한다.

## 5. 레이아웃 구조

권장 구조는 다음과 같다.

```text
전체 화면
├─ 상단 헤더/진행률
├─ 대화 스크롤 영역
│  ├─ 지지난 발화
│  ├─ 지난 발화
│  └─ 케이의 최신 질문 말풍선
└─ 키보드 입력 고정 영역
   ├─ 텍스트 입력창
   ├─ 전송 버튼
   └─ 닫기/취소 버튼
소프트 키보드
```

키보드 입력 모드에서는 마스코트, 상태 카드, 자동·수동 버튼 등 기존 음성 조작 UI가 화면 높이 때문에 모두 표시되지 않아도 된다.

우선순위는 다음과 같다.

1. 케이의 최신 질문
2. 입력창
3. 전송 버튼
4. 대화 히스토리
5. 기타 음성 조작 UI

키보드 모드에서 공간이 부족하면 마스코트나 음성 상태 영역을 축소 또는 숨길 수 있으나, 음성 모드로 돌아가면 기존 레이아웃으로 복원되어야 한다.

---

## 6. 모바일 키보드 대응

### 6.1 Visual Viewport

모바일 브라우저에서 키보드가 열리면 `window.visualViewport`를 우선 사용하여 실제 표시 가능 영역을 계산한다.

확인할 값:

- `visualViewport.height`
- `visualViewport.offsetTop`
- `window.innerHeight`

입력 영역의 하단 위치는 실제 키보드 상단을 기준으로 맞춘다.

### 6.2 Safe Area

iPhone PWA와 Safari에서 다음 값을 반영한다.

```css
env(safe-area-inset-bottom)
env(safe-area-inset-left)
env(safe-area-inset-right)
```

Safe Area 때문에 입력창이 지나치게 위로 뜨거나 키보드에 가려지지 않게 한다.

### 6.3 가로 폭 안전 조건

다음 조건을 입력 영역과 대화 영역에 적용한다.

```css
width: 100%;
max-width: 100%;
min-width: 0;
box-sizing: border-box;
overflow-x: hidden;
```

단, `overflow-x: hidden`으로 실제 폭 팽창 문제를 숨기지 말고 먼저 폭 계산 원인을 제거한다.

사용 금지 또는 재검토:

- `100vw`
- `w-screen`
- 화면 폭을 넘는 고정 `min-width`
- 입력창과 버튼 너비 합계가 100%를 넘는 구조
- 키보드가 열릴 때 적용되는 `translateX`
- Grid의 implicit `auto` column
- `shrink-0`로 인한 가로 팽창

입력 행 권장 구조:

```css
.input-row {
  display: flex;
  width: 100%;
  min-width: 0;
}

.input-field {
  flex: 1;
  min-width: 0;
}

.send-button,
.cancel-button {
  flex-shrink: 0;
}
```

## 7. 최근 케이 질문 식별

대화 데이터에서 가장 최근 케이 발화를 정확히 식별한다.

예시 기준:

- `role === "assistant"`
- `speaker === "k"`
- 기존 프로젝트의 케이 메시지 타입

화면에 보이는 가장 최근 텍스트가 종료 안내나 시스템 문구인 경우에도, 아이가 실제로 답해야 하는 최근 케이 질문을 우선 탐색한다.

질문 식별 로직을 새로 추측해 만들지 말고, 기존 미션·자유대화 메시지 데이터 구조를 확인하여 적용한다.

---

## 8. 미션 화면 정책

미션에서는 키보드 모드 진입 시 현재 진행 중인 질문을 기본 위치로 표시한다.

- 현재 미션 질문을 항상 우선 노출
- 지난 답변과 이전 질문은 위로 스크롤하여 확인 가능
- 입력 완료 후 전송하면 기존 유효 답변 분석 및 다음 질문 흐름 유지
- 키보드 입력 때문에 미션 진행률 또는 질문 순서가 변경되면 안 된다.
- 자동·수동 모드 상태는 유지한다.

---

## 9. 자유대화 화면 정책

자유대화에서는 가장 최근 케이 질문 또는 반응을 기본 위치로 표시한다.

- 최근 케이 말풍선 바로 아래에 입력창이 보이도록 한다.
- 지난 대화는 위로 스크롤하여 확인 가능
- 메시지 전송 후 기존 자유대화 응답 생성 흐름 유지
- 키보드 모드를 닫으면 기존 마스코트·말풍선·음성 조작 레이아웃으로 복원
- 하루 횟수·총시간·턴 제한 정책은 이번 작업에서 변경하지 않는다.

---

## 10. 키보드 닫기 및 모드 복원

키보드 입력 모드를 종료하면 다음 상태로 복원한다.

```text
키보드 닫힘
→ 입력 고정 영역 해제
→ 기존 음성 대화 화면 높이 복원
→ 마스코트·상태 카드·자동/수동·마이크 버튼 원래 위치 복원
→ 대화 영역의 최근 위치 유지 또는 최신 발화 표시
```

복원 과정에서 다음 문제가 없어야 한다.

- 화면 우측 쏠림
- 마스코트 위치 변경
- 말풍선 크기 깨짐
- 입력 내용 예상치 못한 삭제
- 전체 페이지 스크롤 위치 튐

---

## 11. 구현 전 점검

코드 수정 전에 다음을 확인한다.

1. 미션과 자유대화의 키보드 입력 UI가 같은 컴포넌트를 쓰는지
2. 입력창·전송·취소 버튼의 실제 컴포넌트
3. 소프트 키보드 높이 대응 코드 존재 여부
4. `visualViewport` 사용 여부
5. 키보드 모드에서 전체 화면과 대화 영역의 높이 계산 방식
6. 최근 케이 질문 메시지를 식별할 수 있는 데이터 필드
7. 기존 자동 스크롤 구현 여부
8. iPhone과 Android의 현재 차이
9. Production에서 발생했던 키보드 진입 후 우측 쏠림 원인의 수정 반영 여부

미션과 자유대화가 다른 컴포넌트를 사용하더라도 동일한 정책을 공통 Hook 또는 공통 유틸로 구현할 수 있는지 검토한다.

---

## 12. 권장 구현 구성

가능하면 다음과 같이 공통화한다.

```text
useKeyboardConversationViewport
- 키보드 열림/닫힘 감지
- visualViewport 높이 계산
- 입력 영역 위치 계산
- 최근 케이 질문 자동 스크롤
- 사용자의 수동 스크롤 상태 추적

KeyboardConversationInput
- 입력창
- 전송 버튼
- 닫기 버튼
- 화면 폭 안전 처리
```

기존 구조를 크게 변경해야 한다면 공통화보다 회귀 위험이 낮은 최소 수정 방식을 우선한다.

## 13. 테스트 시나리오

### 미션

1. 미션 화면 진입
2. 케이 질문 표시 확인
3. 키보드 버튼 선택
4. 입력창 자동 포커스 및 키보드 표시
5. 입력창이 키보드 바로 위에 고정되는지 확인
6. 케이 최신 질문이 입력창 위에 보이는지 확인
7. 위로 스크롤하여 지난 대화 확인
8. 텍스트 입력
9. 전송
10. 다음 질문 정상 연결 확인
11. 키보드 닫기
12. 기존 음성 UI 정상 복원 확인

### 자유대화

1. 자유대화 화면 진입
2. 케이 질문 또는 최근 반응 표시 확인
3. 키보드 입력 모드 진입
4. 최신 케이 말풍선 자동 노출 확인
5. 입력창 고정 확인
6. 이전 대화 스크롤 확인
7. 메시지 전송
8. 케이 응답 수신
9. 하단을 보고 있을 때만 최신 메시지 자동 이동 확인
10. 사용자가 위를 보고 있을 때 강제 스크롤되지 않는지 확인
11. 키보드 닫기 및 음성 UI 복원 확인

### 화면 폭

- 입력창·전송 버튼·닫기 버튼이 모두 화면 안에 표시
- 우측 잘림 없음
- 가로 스크롤 없음
- 키보드 열기 전후 root `left`와 `width`가 동일

## 14. 검증 기기

다음 환경에서 실제 화면 검증을 수행한다.

- iPhone Safari 390×844
- iPhone 설치형 PWA
- Android Chrome 360×800
- Android Chrome 412×915
- Android 설치형 PWA

각 환경에서 다음 좌표를 키보드 열기 전후로 확인한다.

- 화면 root `left`, `width`
- 대화 영역 `top`, `bottom`, `height`
- 입력 영역 `left`, `right`, `bottom`, `width`
- 최신 케이 말풍선 `top`, `bottom`
- 전송 버튼 `right`
- 키보드 상단과 입력 영역 하단 간격

## 15. 완료 조건

다음 조건을 모두 만족해야 완료로 판단한다.

- 미션과 자유대화 모두 입력창이 키보드 바로 위에 고정된다.
- 입력창 위 대화 영역만 세로 스크롤된다.
- 키보드 최초 진입 시 최신 케이 질문이 바로 보인다.
- 아이가 질문을 확인하면서 즉시 입력할 수 있다.
- 사용자가 위로 스크롤하면 위치를 강제로 변경하지 않는다.
- 전송 후 최신 대화로 이동한다.
- 키보드가 열려도 화면이 오른쪽으로 밀리지 않는다.
- 입력창·전송·닫기 버튼이 잘리지 않는다.
- 가로 스크롤이 생기지 않는다.
- 키보드 종료 후 기존 음성 UI가 정상 복원된다.
- 기존 미션·자유대화 기능에 회귀 문제가 없다.
