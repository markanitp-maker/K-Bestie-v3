# REQUEST 021 — 지난 이력보기 달력 선택 시 리포트 상세 모달 표시 수정

## 1. 작업 목적

부모 리포트 화면의 `지난 이력보기` 달력에서 리포트가 있는 날짜를 선택하면, 현재처럼 전체 화면 상세 화면으로 전환하지 말고 선택한 일일·주간 리포트를 모달 팝업으로 표시한다.

목록 카드 클릭과 달력 날짜 클릭은 동일한 리포트 상세 모달을 사용해야 한다.

---

## 2. 현재 문제

현재 모바일 부모 리포트 화면에서 다음 문제가 발생한다.

```text
지난 이력보기 달력 열기
→ 리포트가 있는 날짜 선택
→ 전체 화면 리포트 상세 화면 표시
```

대표님이 확정한 동작은 다음과 같다.

```text
지난 이력보기 달력 열기
→ 리포트가 있는 날짜 선택
→ 달력 바텀시트 닫기
→ 선택한 리포트 상세 모달 표시
```

전체 화면 페이지 이동 또는 화면 전체 교체는 요구사항과 다르다.

---

## 3. 적용 대상

다음 두 화면에 동일하게 적용한다.

- 일일 리포트의 지난 이력보기 달력
- 주간 리포트의 지난 이력보기 달력 또는 기간 선택 UI

다음 진입 경로가 모두 같은 상세 모달을 사용해야 한다.

1. 일일 리포트 목록 카드 클릭
2. 주간 리포트 목록 카드 클릭
3. 일일 달력 날짜 클릭
4. 주간 달력 날짜 또는 기간 클릭

---

## 4. 확정 동작

### 4.1 일일 리포트

```text
일일 탭
→ 지난 이력보기 달력 열기
→ 리포트가 존재하는 날짜 선택
→ 선택 날짜의 report_id 확인
→ 달력 닫기
→ 일일 리포트 상세 모달 열기
```

모달에는 선택한 날짜의 일일 리포트만 표시한다.

### 4.2 주간 리포트

```text
주간 탭
→ 지난 이력보기 달력 또는 기간 선택 UI 열기
→ 리포트가 존재하는 날짜 또는 주간 선택
→ 선택 주간의 report_id 확인
→ 달력 닫기
→ 주간 리포트 상세 모달 열기
```

일일 리포트를 조합해 임시 주간 리포트처럼 표시하지 않는다.

---

## 5. 금지 동작

달력 날짜 선택 시 다음 동작을 사용하지 않는다.

- `router.push`
- `router.replace`
- `window.location`
- 별도 상세 페이지 이동
- 현재 목록 컴포넌트를 전체 화면 상세 컴포넌트로 교체
- URL 변경을 통한 전체 화면 렌더링
- 최신 리포트로 임의 대체

선택한 과거 날짜의 리포트를 눌렀다면 해당 과거 리포트가 모달에 표시되어야 한다.

---

## 6. 상세 모달 구성

기존 리포트 카드 클릭용 상세 모달을 재사용한다.

모달 상단에는 다음 탭을 제공한다.

```text
[빠른 요약] [상세 보기] [추천 가이드] [X]
```

### 기본 탭

모달을 처음 열면 `빠른 요약`을 기본 선택한다.

### 표시 정보

- 아이 이름
- 일일 리포트 날짜 또는 주간 리포트 기간
- 빠른 요약
- 상세 보기
- 추천 가이드
- 우측 상단 닫기 버튼
- 내부 세로 스크롤

목록 클릭용 모달과 달력 클릭용 모달을 별도로 중복 구현하지 않는다.

---

## 7. 공통 모달 오픈 함수

리포트 목록 카드와 달력 날짜 선택이 동일한 모달 오픈 함수를 사용하도록 통합한다.

예시 구조:

```ts
type ReportModalTarget =
  | {
      reportType: "daily";
      reportId: string;
      childId: string;
      businessDate: string;
    }
  | {
      reportType: "weekly";
      reportId: string;
      childId: string;
      weekStartDate: string;
      weekEndDate: string;
    };
```

```ts
openReportModal(target);
```

다음 진입점에서 같은 함수를 호출한다.

- 일일 목록 카드
- 주간 목록 카드
- 일일 달력 날짜
- 주간 달력 날짜 또는 기간

---

## 8. 달력에서 리포트 조회

날짜 선택 시 날짜만 전달하고 최신 리포트를 임의 조회하지 않는다.

다음 조건으로 정확한 리포트를 식별한다.

### 일일

- `child_id`
- `business_date`
- `report_type = daily`
- 정상 완료 상태

### 주간

- `child_id`
- `week_start_date`
- `week_end_date`
- `report_type = weekly`
- 정상 완료 상태

해당 조건으로 찾은 `report_id`를 모달에 전달한다.

---

## 9. 달력과 모달 전환 순서

달력 바텀시트와 리포트 상세 모달이 동시에 겹쳐 표시되지 않도록 한다.

정상 순서:

```text
1. 날짜 선택
2. report_id 확인
3. 달력 바텀시트 닫기
4. 닫힘 애니메이션 또는 상태 반영 완료
5. 상세 모달 열기
```

다음 문제를 방지한다.

- 달력 위에 상세 모달이 겹침
- 배경 오버레이가 두 겹으로 표시됨
- 스크롤 잠금이 해제되지 않음
- 닫기 버튼이 동작하지 않음
- z-index 충돌
- 모바일 뒤로 가기로 두 화면이 한꺼번에 닫힘

필요한 경우 달력 닫힘 완료 후 다음 프레임에서 상세 모달을 연다.

---

## 10. 리포트가 없는 날짜

리포트가 없는 날짜를 선택한 경우 전체 화면으로 이동하거나 빈 모달을 열지 않는다.

다음 안내를 표시한다.

```text
해당 날짜의 리포트가 없습니다.
```

표시 방식은 현재 달력 UI에 맞춰 다음 중 하나를 사용한다.

- 달력 내부 안내
- 토스트
- 바텀시트 하단 안내

리포트가 없는 날짜는 가능하면 비활성 상태로 표시한다.

---

## 11. 선택 가능 날짜 표시

달력의 날짜 상태를 명확히 구분한다.

- 리포트 있음: 선택 가능 및 표시점 노출
- 현재 선택 날짜: 테두리 또는 배경 강조
- 리포트 없음: 비활성 또는 안내 후 실행 중단
- 미래 날짜: 선택 불가
- 다른 월 날짜: 현재 디자인 규칙 유지

표시점이 있는 날짜와 실제 조회 가능한 리포트가 일치해야 한다.

---

## 12. 상태 유지

상세 모달을 닫은 뒤 다음 상태를 그대로 유지한다.

- 일일 또는 주간 선택 탭
- 선택된 아이
- 선택한 월
- 리포트 목록 스크롤 위치
- 달력 열기 전 목록 상태
- 기존 필터 또는 조회 조건

상세 모달 종료 후 목록 전체를 초기화하거나 최상단으로 이동하면 안 된다.

---

## 13. 뒤로 가기 동작

### 달력만 열린 상태

모바일 또는 브라우저 뒤로 가기:

```text
달력 닫기
→ 리포트 목록 유지
```

### 상세 모달이 열린 상태

모바일 또는 브라우저 뒤로 가기:

```text
상세 모달 닫기
→ 리포트 목록 유지
```

상세 모달을 닫았다고 달력이 다시 자동으로 열리면 안 된다.

전체 부모 홈 또는 이전 페이지로 즉시 이동하지 않도록 한다.

---

## 14. 데이터 무결성

상세 모달은 반드시 사용자가 선택한 리포트의 데이터를 표시해야 한다.

검증 조건:

- 선택한 `report_id` 일치
- 선택한 `child_id` 일치
- 선택 날짜 또는 주간 기간 일치
- 일일·주간 리포트 타입 일치
- 다른 아이 데이터 혼합 금지
- 최신 리포트로 임의 교체 금지
- 이전 캐시 데이터 노출 금지

캐시 키에는 최소한 다음 값을 포함한다.

```text
childId + reportType + reportId
```

---

## 15. 로딩 처리

날짜 선택 후 상세 데이터를 불러오는 동안 모달 프레임을 먼저 표시할 수 있다.

```text
리포트를 불러오고 있어요.
```

조회 실패 시 다음 상태를 표시한다.

```text
리포트를 불러오지 못했어요.
잠시 후 다시 확인해 주세요.
```

조회 오류 때문에 전체 화면으로 이동하거나 앱 화면이 비어서는 안 된다.

---

## 16. 모바일 UI 요구사항

- 달력은 기존 바텀시트 형태 유지
- 상세 리포트는 모달 팝업 형태 사용
- 상세 모달은 안전 영역 안에 표시
- 하단 내비게이션과 겹치지 않음
- 탭과 닫기 버튼 상단 고정
- 긴 콘텐츠는 모달 내부에서만 스크롤
- 모달 표시 중 배경 스크롤 잠금
- 달력과 상세 모달의 오버레이 중복 방지
- `X` 버튼은 항상 접근 가능

---

## 17. 기존 기능 영향 방지

이번 작업으로 다음 기능은 변경하지 않는다.

- 일일·주간 탭 디자인
- 리포트 목록 카드 디자인
- 월별 달력 디자인
- 최근 7일 리포트 통계
- 자녀 선택
- 하단 내비게이션
- 리포트 생성 로직
- 빠른 요약·상세 보기·추천 가이드 콘텐츠
- 데이터 보존 정책
- 부모 홈 대시보드

변경 범위는 달력 선택 후 상세 화면을 여는 방식에 한정한다.
