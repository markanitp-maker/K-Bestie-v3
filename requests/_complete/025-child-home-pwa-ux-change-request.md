# 026 — 아이 홈 화면 전면 개편

## 1. 작업 목적

현재 아이 홈 화면을 첨부 레퍼런스 이미지의 구조와 분위기를 기준으로 전면 개편한다.

이번 개편의 핵심은 다음과 같다.

- 아이가 케이를 만나자마자 현재 미션 상태를 이해할 수 있도록 한다.
- 미션을 가장 중요한 행동으로 강조한다.
- 대화와 놀이는 보조 행동으로 단순하게 제공한다.
- 기존 하단 메뉴 바를 완전히 제거한다.
- 별도 아이 설정 화면 및 설정 진입 경로를 제거한다.
- 화면 하단에는 PWA 설치 유도 배너를 배치한다.
- 모바일뿐 아니라 태블릿과 PC에서도 동일한 단일 홈 구조를 유지한다.

---

# 2. 레퍼런스 적용 범위

첨부 이미지에서 앱 내부 UI만 참고한다.

## 구현 대상

- 하늘색 배경과 구름 장식
- 상단 미션 이벤트 진행 정보
- 중앙 케이 마스코트
- 아이 이름 기반 인사 문구
- 현재 미션 안내 말풍선
- 대형 미션 진행 카드
- 대화하기 카드
- 케이와 놀이 카드
- 하단 PWA 설치 배너

## 구현 제외

- 스마트폰 외곽 프레임
- 다이내믹 아일랜드
- 기기 버튼
- iOS 홈 인디케이터
- 상태 표시줄
- 레퍼런스 이미지의 톱니바퀴 설정 버튼

아이 설정 화면은 기존 결정에 따라 제거하므로 톱니바퀴 아이콘을 새로 구현하지 않는다.

# 4. 전체 화면 레이아웃

## 기본 구조

- 모바일 우선 단일 화면
- 기준 높이: `100dvh`
- 기본 너비: `100%`
- 태블릿·PC 최대 콘텐츠 너비: 약 `430px~480px`
- 태블릿·PC에서는 전체 홈 화면을 중앙 정렬
- 문서 전체 가로 스크롤 금지
- 하단 메뉴 공간을 남기지 않는다.
- iOS와 Android의 safe-area를 반영한다.

## 배경

레퍼런스 이미지처럼 상단은 밝은 하늘색, 하단은 따뜻한 아이보리색 계열로 구성한다.

권장 방향:

```css
background:
  linear-gradient(
    180deg,
    #BFE8FF 0%,
    #EAF7FF 38%,
    #FFF9F2 75%,
    #FFF7E9 100%
  );
```

정확한 색상은 기존 Design System v2 토큰에 맞춰 조정하되 다음 브랜드 색상을 기준으로 한다.

- K-Navy: `#10315B`
- K-Orange: `#E25B12`
- K-Mascot Orange: `#F19122`
- K-Sky Blue: `#4298D3`

## 배경 장식

- 케이 마스코트 좌우에 흰색 구름 장식
- 작은 별 또는 반짝임 장식
- 장식은 기능 요소보다 뒤에 위치
- `pointer-events: none`
- 텍스트 가독성을 방해하지 않도록 낮은 투명도 사용
- 작은 화면에서는 일부 장식을 축소하거나 숨길 수 있음
- 무거운 Canvas 애니메이션 사용 금지
- CSS 또는 기존 SVG/PNG 자산 우선 사용

# 5. 상단 미션 이벤트 진행 정보

화면 상단에 흰색 pill 형태의 월간 미션 진행 영역을 배치한다.

## 표시 예시

```text
🔥 미션 진행 이벤트 (8월) – 02 / 62
```

## 데이터 기준

하드코딩 금지.

다음 값은 기존 실제 상태 또는 서버 데이터와 연결한다.

- 현재 월
- 이벤트명
- 현재 완료 횟수
- 전체 목표 횟수

실제 월간 이벤트 데이터가 없는 경우 임의로 `02 / 62`를 표시하지 않는다.

데이터가 없을 때는 다음 중 기존 서비스 정책과 맞는 표현을 사용한다.

```text
🔥 이번 달 미션 진행
```

또는 이벤트 영역 자체를 숨긴다.

## 디자인

- 화면 좌우 약 `16px~20px` 여백
- 높이 약 `36px~42px`
- 흰색 또는 반투명 흰색 배경
- `border-radius: 9999px`
- K-Navy 테두리
- 약한 그림자
- 텍스트 K-Navy
- 글자 크기 약 `13px~15px`
- 중요한 숫자는 굵게 표시
- 전체 진행 정보를 한 줄로 유지
- 작은 화면에서 글자가 잘리면 적절히 축약하되 숫자는 유지

이 영역은 버튼처럼 보이지 않게 하며, 별도 이벤트 상세 페이지가 실제로 존재할 때만 클릭 가능하도록 한다.

# 6. 케이 마스코트 영역

## 자산

- 저장소에 존재하는 공식 3D 케이 마스코트 정본 자산을 사용한다.
- 임시 캐릭터, 레퍼런스 이미지에서 잘라낸 이미지, 신규 생성 이미지를 사용하지 않는다.
- 마스코트 비율과 색상을 임의 변경하지 않는다.
- 이미지 찌그러짐 금지
- `object-fit: contain`

## 배치

- 화면 수평 중앙
- 이벤트 진행 영역 아래
- 인사 문구 위
- 구름 사이에서 케이가 서 있는 구성
- 아래에 연한 타원형 그림자를 적용해 떠 보이지 않도록 한다.

## 크기

반응형 `clamp()`를 사용한다.

예시:

```css
width: clamp(150px, 43vw, 205px);
```

- 작은 화면에서도 잘리지 않아야 한다.
- 화면이 짧으면 마스코트 크기를 우선 축소한다.
- 마스코트 때문에 아래 주요 카드가 화면 밖으로 밀리지 않도록 한다.

# 7. 아이 인사 문구

## 제목

실제 로그인한 아이 이름을 사용한다.

예시:

```text
안녕, 서아야!
오늘은 뭐 하고 놀까?
```

## 이름 조사 처리

기존 프로젝트의 이름·호칭 처리 함수를 사용한다.

이름 뒤에 무조건 `야`를 문자열 결합하지 말고 기존 호칭 규칙이 있다면 그대로 사용한다.

## 스타일

- K-Navy
- 가운데 정렬
- 굵기 `700~800`
- 모바일 기준 약 `24px~30px`
- 줄 간격 약 `1.15~1.25`
- 최대 2줄
- 마스코트와 카드 사이에서 가장 중요한 텍스트 계층으로 표시

# 8. 현재 미션 안내 말풍선

인사 문구 아래에 현재 미션 상태를 설명하는 작은 말풍선을 배치한다.

## 상태별 문구 예시

### 진행 중인 미션이 있는 경우

```text
미션이 진행되고 있어요. 같이 할까?
```

### 오늘 가능한 미션이 있는 경우

```text
오늘의 미션을 시작해 볼까?
```

### 오늘 미션을 모두 완료한 경우

```text
오늘의 미션을 모두 완료했어!
```

### 미션 가능 시간이 아닌 경우

기존 미션 시간 정책에 따른 실제 안내 문구를 표시한다.

## 디자인

- 흰색 배경
- K-Orange 테두리
- K-Navy 텍스트
- 아래 중앙에 삼각형 꼬리
- pill과 말풍선 중간 형태
- 최대 2줄
- 글자 크기 약 `12px~14px`
- 약한 주황색 그림자
- 카드처럼 크게 만들지 않는다.

문구는 실제 미션 상태와 연결해야 하며 임의 타이머로 상태를 흉내 내지 않는다.

# 9. 미션 진행 메인 카드

미션 카드는 홈 화면의 최우선 CTA로 배치한다.

## 위치

- 말풍선 바로 아래
- 화면 좌우 약 `16px~20px` 여백
- 대화와 놀이 카드보다 크게 표시

## 기본 구성

왼쪽:
- 미션 아이콘
- 과녁 또는 기존 공식 아이콘 사용

중앙:
- 제목
- 설명

오른쪽:
- 진행률 badge 또는 화살표

## 문구

### 진행 중인 미션이 있는 경우

제목:

```text
미션 계속하기
```

또는 기존 서비스 용어가 `미션 진행`으로 확정되어 있으면 그대로 사용한다.

설명:

```text
진행 중인 미션을 이어서 해요
```

### 새 미션이 가능한 경우

제목:

```text
미션 진행
```

설명:

```text
오늘의 미션을 시작해요
```

## 진행률

카드 오른쪽 상단에 실제 유효 답변 수를 표시한다.

예시:

```text
3/10
```

중요:

- 현재 질문 번호가 아니라 유효 답변 완료 수를 사용한다.
- 미션 미시작 상태에서는 `0/10` 또는 badge를 숨긴다.
- 완료된 상태에서는 `완료`로 표시할 수 있다.
- 서버 또는 세션에 저장된 실제 진행률을 사용한다.

## 디자인

- K-Orange 중심 그라데이션 또는 단색
- 큰 radius 약 `22px~26px`
- 높이 약 `86px~104px`
- 약한 그림자
- 왼쪽 아이콘 배경은 밝은 주황 파생색
- 제목과 설명은 접근성을 고려한 색상 사용

K-Orange 위 작은 흰색 텍스트의 대비가 부족할 수 있으므로 다음 중 실제 WCAG 대비가 확보되는 조합을 사용한다.

- K-Orange 배경 + K-Navy 텍스트
- 충분히 어두운 K-Orange 파생색 + 흰색 텍스트
- K-Navy 제목 + 충분히 대비되는 설명색

단순히 레퍼런스의 흰색 텍스트를 그대로 복제하지 않는다.

## 동작

카드 전체를 버튼으로 사용한다.

- 미션이 진행 중이면 이어하기
- 새 미션이 가능하면 미션 시작 화면
- 완료 상태이면 완료 화면 또는 기존 정책에 따른 진입
- 클릭 시 황금열쇠가 중복 차감되거나 새로운 세션이 중복 생성되면 안 됨
- 기존 미션 세션·이어하기·시간 제한·보상 정책을 유지

# 10. 대화하기 카드

미션 카드 아래 왼쪽에 배치한다.

## 문구

제목:

```text
대화하기
```

설명:

```text
케이랑 이야기 나눠요
```

## 디자인

- K-Mascot Orange 또는 따뜻한 주황 계열
- 미션 카드보다 낮은 시각적 우선순위
- 둥근 모서리
- 아이콘 배경은 반투명 밝은 색
- 왼쪽 또는 상단에 말풍선 아이콘
- 제목과 설명은 읽기 쉬운 대비 유지
- 카드 전체 터치 가능

## 동작

- 기존 자유대화 진입 경로로 연결
- 기존 세션 제한, 횟수 제한, 휴식 시간 정책 유지
- UI 개편을 이유로 자유대화 로직을 수정하지 않는다.

# 11. 케이와 놀이 카드

미션 카드 아래 오른쪽에 배치한다.

## 문구

제목:

```text
케이와 놀이
```

설명:

```text
재미있는 놀이를 해봐요
```

열쇠 보유량이 있을 경우:

```text
🔑 3개 보유
```

## 데이터 기준

- 황금열쇠 보유량은 실제 현재 아이의 데이터 사용
- 하드코딩 금지
- 로딩 전 임의 숫자 노출 금지
- 조회 실패 시 `0개`로 속이지 말고 적절한 로딩 또는 재시도 상태 표시

## 디자인

- K-Sky Blue 기반
- K-Sky Blue 위 흰색 작은 글자는 접근성 대비가 부족하므로 K-Navy 또는 충분히 어두운 글자색 사용
- 조이스틱 또는 기존 놀이 공식 아이콘 사용
- 카드 전체 터치 가능
- 대화 카드와 같은 높이
- 두 카드 사이 간격 약 `10px~12px`

## 동작

- 기존 놀이 목록 화면으로 연결
- MBTI·퀴즈 등 각 놀이의 기존 황금열쇠 차감 및 handoff 정책 유지
- 준비 중 놀이의 차감 금지 정책 유지

# 12. 대화·놀이 카드 반응형 배치

## 일반 모바일

```text
[대화하기] [케이와 놀이]
```

2열 배치

## 작은 화면 또는 접근성 글꼴 확대

공간이 부족하거나 텍스트가 겹치는 경우:

```text
[대화하기]
[케이와 놀이]
```

1열로 전환할 수 있다.

강제로 글자를 작게 줄이거나 잘라내지 않는다.

# 13. PWA 설치 배너

기존 하단 메뉴 바를 제거한 자리에 PWA 설치 유도 배너를 배치한다.

## 위치

- 화면 최하단
- safe-area 하단 반영
- 홈 콘텐츠와 겹치지 않도록 배치
- 필요 시 `position: sticky` 또는 일반 flow 사용
- 핵심 카드 위를 덮는 무조건적인 fixed overlay 금지

## 구성

왼쪽 텍스트:

```text
모바일 / 태블릿 / PC
```

오른쪽 버튼:

```text
앱 설치하기
```

우측 상단 또는 끝:

```text
X
```

닫기 버튼

## 디자인

- 따뜻한 아이보리 또는 흰색 배경
- 상단에 약한 구분선 또는 그림자
- K-Navy 본문
- K-Orange 설치 버튼
- 버튼은 충분히 큰 텍스트와 굵기를 적용해 대비 확보
- 닫기 버튼 터치 영역 최소 `44x44px`
- 설치 버튼 터치 영역 최소 `44px` 높이
- `aria-label` 적용

## 설치 동작

### Android·지원 브라우저

- 기존 `beforeinstallprompt` 이벤트 사용
- 설치 가능 상태에서만 설치 프롬프트 실행
- 설치 완료 후 배너 숨김
- 이미 standalone 모드이면 배너 숨김

### iOS Safari

`beforeinstallprompt`를 지원하지 않으므로 기존 iOS 설치 안내 플로우가 있다면 연결한다.

안내 예시:

```text
공유 버튼을 누른 뒤 ‘홈 화면에 추가’를 선택해 주세요.
```

### PC

설치 지원 브라우저에서 설치 버튼 제공

### 설치 불가능 환경

- 버튼을 눌러도 아무 반응 없는 상태 금지
- 지원하지 않는 브라우저라는 안내 제공
- 기존 설치 안내 로직이 없다면 최소 안내 모달 구현

## 닫기 정책

- X를 누르면 현재 세션에서 배너 숨김
- 기존 정책이 있다면 localStorage 또는 sessionStorage 사용
- 영구적으로 다시 나타나지 않게 할지 임의 결정하지 않는다.
- 기존 설치 유도 정책에 맞춰 일정 기간 후 다시 표시할 수 있도록 한다.

- 부모 영역 Navigation은 이번 작업 범위에 포함하지 않는다.

# 15. 아이 설정 화면 제거

## 제거 범위

현재 구현된 실제 경로를 먼저 확인한 뒤 다음을 처리한다.

- 아이용 설정 페이지
- 아이 홈의 설정 진입 경로
- 하단 설정 탭
- 아이 화면에서 노출되는 설정 링크

## 유지 범위

부모 화면의 다음 기능은 유지한다.

- 아이 정보 관리
- 보호자 설정
- 구독·플랜 관리
- 개인정보 및 서비스 설정
- 문의·건의·버그 신고 기능

아이 설정 URL에 직접 접근했을 때는 다음 중 기존 라우팅 정책에 맞는 방식으로 처리한다.

- 아이 홈으로 redirect
- 404
- 접근 불가 안내

빈 설정 화면을 남기지 않는다.

# 16. 문의 기능

기존 문의·건의·버그 신고 기능은 삭제하지 않는다.

단, 이번 레퍼런스에는 문의 버튼이 보이지 않으므로 현재 문의 UI가 홈 화면 위에 겹쳐 있다면 다음을 점검한다.

- 주요 미션 카드와 겹치지 않음
- 마스코트를 가리지 않음
- PWA 설치 배너와 겹치지 않음
- 모바일에서 드래그 가능한 기존 정책이 있으면 유지

문의 기능 제거는 이번 작업 범위가 아니다.

# 17. 반응형 및 화면 높이 대응

검증 화면:

- `320x568`
- `360x800`
- `375x667`
- `390x844`
- `430x932`
- `768x1024`
- PC 브라우저

화면 높이가 부족할 때 축소 우선순위:

1. 배경 구름과 별 장식 축소 또는 일부 숨김
2. 마스코트 크기 축소
3. 영역 간 세로 간격 축소
4. 설명 텍스트 줄 수 축소

숨기면 안 되는 요소:

- 미션 진행 메인 카드
- 대화하기 카드
- 케이와 놀이 카드
- 아이 인사
- 실제 입력 가능한 PWA 설치 버튼 또는 설치 안내

필요 시 홈 콘텐츠는 정상적인 세로 스크롤을 허용하되 다음을 지킨다.

- 하단 메뉴 제거
- PWA 배너가 콘텐츠를 덮지 않음
- 첫 진입 시 미션 메인 카드까지 바로 확인 가능
- 가로 스크롤 없음
