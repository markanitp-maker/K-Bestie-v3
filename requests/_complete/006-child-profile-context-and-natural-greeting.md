## 현재 상태

대표님 실기기에서 다음 문제가 확인됐다.

### 사례 1

김서아 계정으로 로그인한 상태에서 케이는 먼저:

`서아야! 오늘도 만나서 반가워.`

라고 이름을 알고 인사했지만, 같은 문장에서 다시:

`안녕, 나는 케이야. 넌 누구니?`

라고 질문했다.

로그인 계정과 프로필 이름을 이미 알고 있으므로 불필요하고 모순된 질문이다.

### 사례 2

아이 이름이 서아라는 답변 이후에도 케이는:

`내 이름을 벌써 잊어버린 것 같아`
`내 이름을 아직 제대로 부르지 못해서 정말 미안해`

같이 말하며 아이 정보를 모르는 것처럼 반응했다.

이는 아이 프로필 정보가 reaction·질문 생성 컨텍스트에 안정적으로 전달되지 않거나, 기존 질문·rewrite·fallback 경로가 프로필 컨텍스트를 무시하고 있을 가능성을 보여준다. 정확한 최초 원인은 코드와 요청 payload를 확인한 뒤 확정한다.

### 목표 아키텍처

여기서 “아이 정보를 항상 학습한다”는 모델 재학습이나 파인튜닝을 뜻하지 않는다.

다음 구조를 사용한다.

```text
로그인한 아이 인증
→ DB의 아이 프로필 조회
→ 세션용 ChildConversationContext 생성
→ 미션 시작·반응 생성·질문 선택 요청에 지속 전달
→ 케이는 이미 알려진 프로필 정보를 다시 묻지 않음
```

아이 프로필이 변경되면 다음 세션 또는 안전한 갱신 시점부터 최신값을 사용한다.

## 요구사항

### 1. 아이 프로필의 단일 원천 확인

현재 DB와 코드에서 아이 기본 정보의 단일 원천을 확인한다.

최소 확인 항목:

- `child_id`
- 전체 이름
- 성
- 이름
- 자연스러운 호칭용 이름
- 학년
- 그 밖에 현재 프로필에 실제로 존재하면서 대화에 사용하도록 승인된 필드

코드나 DB에 존재하지 않는 필드는 새로 추측해 만들지 않는다.

아이 이름 표시와 호칭 규칙은 기존 확정 정책을 유지한다.

예:

- 저장·화면 표시: `김서아`
- 케이 호칭: `서아야`
- 케이가 자신을 소개할 때: `나는 케이야`

### 2. 세션용 프로필 컨텍스트 구성

기존 프로필 조회 로직을 재사용해 세션 시작 시 `ChildConversationContext` 또는 기존 동등 구조를 구성한다.

새 타입이 필요하면 프로젝트의 실제 타입 규칙에 맞게 생성한다.

최소 포함:

```text
childId
displayName
givenName
grade
knownProfileFacts
```

`knownProfileFacts`에는 DB에 실제로 존재하고 대화에 사용할 수 있는 정보만 포함한다.

민감정보·인증정보·부모 연락처는 포함하지 않는다.

### 3. 모든 미션 대화 경로에 동일하게 전달

다음 경로가 동일한 프로필 컨텍스트를 사용하도록 한다.

- 미션 첫 인사
- D안 원본 turn 처리 함수
- reaction API
- fallback
- 다음 질문 선택
- 이어하기 세션
- 음성 ON/OFF
- 세션 재접속

D안 원본 반응 로직을 다시 구현하지 않는다.

프로필 컨텍스트는 D안 공통 turn 함수의 입력으로 전달하되, D안 원본의 반응 생성 방식을 운영 전용 rewrite로 다시 변형하지 않는다.

### 4. 이미 알고 있는 정보 재질문 금지

프로필에 값이 존재하면 다음 질문을 생성·선택·출력하지 않는다.

- `넌 누구니?`
- `이름이 뭐니?`
- `몇 학년이니?`
- 이미 프로필에 존재하는 기본 신원정보를 다시 확인하는 동등 표현

질문 데이터베이스·고정 질문 배열·fallback·첫 인사·LLM prompt 등 모든 경로를 검색한다.

단순 문자열 한두 개만 삭제하지 말고, 알려진 프로필 필드를 다시 묻지 못하도록 구조적으로 차단한다.

### 5. 자연스러운 첫 인사

이름을 알고 있는 아이의 신규 미션 첫 인사는 다음 방향으로 구성한다.

예:

```text
서아야, 오늘도 만나서 반가워! 오늘 하루는 어땠어?
```

또는 해당 미션의 실제 첫 고정 질문을 자연스럽게 연결한다.

금지:

```text
서아야, 반가워. 넌 누구니?
안녕, 나는 케이야. 이름이 뭐야?
몇 학년이야?
```

케이가 매 세션마다 자기소개를 반복할 필요가 있는지 기존 제품 정책을 확인한다. 정책 근거가 없으면 첫 가입·첫 대화와 재방문 인사를 구분한다.

### 6. 이어하기 세션 처리

기존 세션을 이어갈 때는 신규 첫 인사를 다시 넣지 않는다.

이어하기에서는:

- 기존 진행률 유지
- 기존 마지막 질문 또는 다음 질문에서 재개
- 자기소개 반복 금지
- 이름 질문 반복 금지
- 아이의 이전 답변과 현재 질문 흐름 유지

### 7. 아이가 자신의 정보를 질문하는 경우

아이가 자연스럽게 다음과 같이 물을 수 있다.

- `내 이름 알아?`
- `나 몇 학년이지?`
- `내가 누구게?`

프로필에 값이 있으면 케이는 자연스럽게 답한다.

예:

```text
그럼, 서아지! 지금 4학년이고.
```

프로필에 없는 정보는 아는 척하거나 추측하지 않는다.

모르는 정보는 자연스럽게 모른다고 말하거나 필요할 때만 질문한다.

### 8. 프로필 변경 반영

부모가 아이 이름이나 학년을 변경한 경우:

- 다음 신규 세션에서는 반드시 최신값 반영
- 이미 열린 세션의 갱신 정책은 기존 세션 정책을 확인해 일관되게 처리
- 오래된 이름을 세션 캐시에서 무기한 사용하지 않음

### 9. fallback·오류 경로

LLM 오류·timeout·질문 풀 소진·STT 실패에서도 다음을 지킨다.

- 프로필에 있는 이름을 모른다고 말하지 않음
- `넌 누구니?`로 초기화하지 않음
- 첫 질문으로 돌아가지 않음
- 알려진 아이 이름을 잘못된 주체로 해석하지 않음
- 오류 발생 시 아이 탓이나 기억 상실처럼 표현하지 않음

1. 미션을 일부 진행
2. 화면 종료
3. 같은 세션 이어하기
4. 자기소개 반복 없음
5. 이름 질문 없음
6. 기존 진행률과 다음 질문 유지

### 시나리오 C — 아이가 자기 이름 질문

입력:

```text
내 이름 알아?
```

기대:

- 프로필의 이름을 정확히 사용
- 기억하지 못한다는 사과 없음
- 이름을 다시 묻지 않음

### 시나리오 D — 아이가 학년 질문

입력:

```text
나 몇 학년이지?
```

기대:

- 프로필의 학년을 정확히 답변
- 프로필에 없는 값은 추측하지 않음

### 시나리오 E — 아이가 이름을 발화

입력:

```text
나는 서아야
```

기대:

- 이미 알고 있는 이름을 새 정보처럼 오인하지 않음
- `내 이름을 잊어버렸다`는 식의 케이 자기 이름 혼동 없음
- 자연스럽게 다음 대화로 연결

### 시나리오 F — LLM 실패·fallback

1. 안전한 테스트 조건으로 reaction 실패 유도
2. fallback 실행
3. `넌 누구니?` 미출력
4. 이름을 모른다는 문구 미출력
5. 진행 중 질문과 세션 유지

### 시나리오 G — 프로필 변경

1. QA 프로필의 표시 이름을 안전하게 변경
2. 신규 세션 시작
3. 최신 이름 반영
4. 테스트 종료 후 원래 QA 값 복구

## 공유파일 수정

수정 허용 공유파일:

- `app/child/missions/page.tsx`
  - 세션 프로필 컨텍스트 전달
  - 첫 인사와 알려진 정보 재질문 차단
  - 관련 부분만 수정
  - 질문 풀·연결 품질·레이아웃 구조는 변경하지 않는다.

- 실제 조사 결과 프로필 조회에 사용되는 공통 인증 파일
  - 읽기만으로 해결되지 않고 수정이 반드시 필요한 경우에만 변경
  - 수정 전 정확한 경로와 이유를 `_blocked.md`에 기록

그 밖의 공유파일 수정은 금지한다.
