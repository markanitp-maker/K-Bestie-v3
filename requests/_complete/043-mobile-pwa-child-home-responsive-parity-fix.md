# 043 — 실제 모바일 PWA와 PC 스마트폰 미리보기의 아이 홈 UI 일치화

## 1. 작업 목적

동일한 개발 서버의 아이 홈 화면이 실행 환경에 따라 서로 완전히 다른 UI로 표시되고 있다.

현재 비교 대상은 다음과 같다.

### PC 설치형 PWA의 스마트폰 미리보기

- 스마트폰 목업 내부에 아이 홈 표시
- 마스코트가 비교적 작고 적절한 비율
- 인사 문구와 안내 말풍선이 간결함
- 미션 카드는 전체 너비
- 대화하기와 케이와 놀이 카드는 2열
- 전체 콘텐츠 밀도가 높아 주요 메뉴가 한 화면에 가까이 표시됨
- 내부 콘텐츠 영역에 세로 스크롤 적용

### 실제 모바일 설치형 PWA

- 마스코트가 지나치게 큼
- 인사 문구와 말풍선 글자가 지나치게 큼
- 미션·대화·놀이 카드가 모두 전체 너비 1열
- 카드 높이와 내부 여백이 과도함
- 문의 버튼 위치도 PC 미리보기와 다름
- 같은 화면이라고 보기 어려울 정도로 정보 구조가 달라짐

이번 작업은 실제 모바일 PWA의 내부 아이 홈 UI를 PC의 스마트폰 미리보기 내부 UI와 동일한 정보 구조·크기·간격으로 통합하는 것이다.

---

## 2. 가장 중요한 해석

PC 화면에 보이는 스마트폰 외곽 목업과 실제 모바일 PWA를 혼동하지 않는다.

### PC·태블릿·데스크톱 미리보기

- 스마트폰 외곽 프레임 표시 가능
- 프레임 안에 실제 앱 콘텐츠 표시

### 실제 스마트폰 브라우저 및 설치형 PWA

- 실제 기기 자체가 스마트폰이므로 추가 외곽 목업 프레임을 다시 표시하지 않음
- 다만 프레임 내부에서 사용한 앱 콘텐츠의 크기·배치·간격은 동일하게 적용

즉, 실제 모바일에 스마트폰 그림을 한 번 더 씌우는 작업이 아니다.

목표는 다음이다.

```text
PC 스마트폰 목업 내부 콘텐츠
=
실제 모바일 PWA 콘텐츠
```

---

## 3. 선행 원인 감사

CSS를 수정하기 전에 모바일 PWA와 PC PWA가 실제로 동일한 빌드를 사용 중인지 먼저 확인한다.

양쪽에서 다음 정보를 수집한다.

```text
App Build ID
Git Commit SHA 또는 Deployment ID
Active Service Worker Version
Waiting Service Worker Version
Cache Name
window.innerWidth
window.innerHeight
visualViewport.width
visualViewport.height
screen.width
screen.height
devicePixelRatio
display-mode
navigator.standalone
userAgent
```

개발 환경에서만 구조화된 단일 로그 또는 진단 패널로 확인한다.

민감한 환경변수는 출력하지 않는다.

---

## 4. 원인 판정 순서

### 4-1. Build ID가 다른 경우

모바일 PWA가 이전 Service Worker 또는 Cache를 사용 중인 것이다.

이 경우:

1. `040-pwa-new-version-update-notification-fix.md` 구현 상태 확인
2. 모바일 PWA의 Active/Waiting Worker 확인
3. 업데이트 안내가 표시되지 않은 원인 확인
4. 이전 JS·CSS Cache가 계속 제공되는 원인 수정
5. 사용자가 PWA를 삭제하거나 사이트 데이터를 수동 삭제하지 않아도 최신 Build로 전환
6. 최신 Build 적용 후에도 UI가 다른지 다시 비교

캐시 문제를 CSS 문제로 오판해 두 레이아웃을 모두 수정하지 않는다.

### 4-2. Build ID가 동일한 경우

동일 코드에서 실제 모바일과 스마트폰 미리보기가 서로 다른 Layout Branch를 사용 중인 것이다.

다음을 조사한다.

- 스마트폰 미리보기 전용 class
- `deviceMode="smartphone"` 같은 prop
- 미리보기 전용 container width
- Tailwind `sm:`, `md:`, `lg:` 분기
- CSS `@media`
- CSS Container Query
- `display-mode: standalone`
- `navigator.standalone`
- 모바일·데스크톱 조건부 렌더링
- `isMobile`, `isDesktop`, `isPwa` 분기
- 브라우저 User-Agent 분기
- 화면별 별도 컴포넌트
- PC 미리보기에서만 적용되는 `transform: scale()`
- 모바일에서만 적용되는 font-size·padding override

동일한 아이 홈을 두 벌로 유지하지 말고 하나의 공통 레이아웃으로 통합한다.

---

## 5. Viewport 설정 감사

Root Layout 또는 실제 문서의 viewport 설정을 확인한다.

필수 기준:

```text
width=device-width
initial-scale=1
viewport-fit=cover
```

Next.js Metadata API를 사용한다면 현재 프로젝트 방식에 맞게 적용한다.

다음을 방지한다.

- 실제 모바일 PWA에서 CSS viewport가 980px처럼 계산되는 문제
- Windows PWA와 모바일 PWA가 서로 다른 breakpoint에 진입하는 문제
- 확대·축소 설정에 따라 레이아웃이 다른 컴포넌트로 바뀌는 문제
- 물리적 해상도 기준으로 반응형을 계산하는 문제

반응형 판단은 CSS Pixel 기준의 실제 내부 viewport를 사용한다.

## 6. 단일 아이 홈 레이아웃 원칙

다음 요소는 PC 스마트폰 미리보기와 실제 모바일 PWA가 동일한 컴포넌트를 사용해야 한다.

```text
ChildHomeContent
├─ HomeTopActions
│  ├─ LogoutButton
│  └─ FloatingInquiryButton
├─ MascotHero
│  ├─ KBestieMascot
│  ├─ Greeting
│  └─ MissionHintBubble
└─ HomeActionCards
   ├─ MissionCard
   └─ SecondaryActionGrid
      ├─ ConversationCard
      └─ PlayCard
```

다음처럼 별도의 모바일·미리보기 UI를 유지하지 않는다.

```text

```

외곽 Device Frame만 환경에 따라 달라질 수 있고, 내부 `ChildHomeContent`는 동일해야 한다.

## 8. Secondary 카드 2열 고정

대화하기와 케이와 놀이 카드는 다음 조건에서 2열로 표시한다.

- 320px 이상 일반 스마트폰
- 모바일 브라우저
- 모바일 설치형 PWA
- PC 스마트폰 미리보기
- 태블릿에서 스마트폰 보기 선택

권장 구조:

```css
grid-template-columns: repeat(2, minmax(0, 1fr));
```

권장 간격:

```text
8px~12px
```

### 1열 전환 허용 조건

다음 경우에만 1열 전환을 허용한다.

- CSS viewport가 300px보다 작은 극단적인 화면
- 접근성 글꼴 확대 200%에서 실제 겹침이 발생하는 경우
- 카드 최소 터치 영역을 유지할 수 없는 경우

일반적인 360px, 390px, 414px, 430px 모바일에서는 반드시 2열을 유지한다.

## 9. 마스코트 크기 통일

현재 실제 모바일의 마스코트가 PC 미리보기보다 지나치게 크다.

PC 스마트폰 미리보기 내부와 동일한 상대 크기로 조정한다.

권장 기준:

```css
width: clamp(150px, 48vw, 205px);
```

정확한 값은 현재 목업 내부의 실제 렌더링 크기를 측정해 토큰으로 확정한다.

### 금지

- 모바일에서만 `70vw~80vw`로 확대
- 기기 물리 해상도 기준 크기 지정
- 데스크톱 미리보기에서만 별도 scale 적용
- 마스코트 비율 왜곡

---

## 10. Hero 영역 높이 축소

실제 모바일은 마스코트·인사말·말풍선 영역이 과도하게 커서 카드가 아래로 밀리고 있다.

다음을 PC 미리보기 기준으로 맞춘다.

### 마스코트와 인사말 간격

```text
약 16px~24px
```

### 인사말 줄 간격

```text
line-height 1.3~1.45
```

### 인사말 크기

현재 PC 스마트폰 미리보기 내부의 실제 CSS 값을 측정해 공통 토큰으로 사용한다.

권장 범위:

```text
24px~30px
```

모바일에서 별도로 34px 이상 확대하지 않는다.

### 말풍선

- 너비 약 `70%~82%`
- 글자 약 `14px~16px`
- 세로 padding 약 `9px~12px`
- 카드와 자연스럽게 연결
- 현재 실제 모바일처럼 과도하게 크고 넓게 만들지 않음

---

## 11. 미션 카드 크기 통일

실제 모바일의 미션 카드 높이와 글자가 PC 미리보기보다 과도하게 크다.

PC 스마트폰 미리보기 내부 기준으로 통일한다.

권장:

- 카드 높이 약 `96px~112px`
- radius 약 `20px~24px`
- 좌우 padding 약 `16px~20px`
- 아이콘 컨테이너 약 `56px~66px`
- 제목 약 `18px~22px`
- 설명 약 `13px~15px`
- 진행 Badge 약 `52px~64px`
- 전체 너비 유지

데이터는 그대로 유지한다.

```text
미션 시작
미션 계속하기
미션 완료
진행률
```

---

## 12. 대화·놀이 카드 크기 통일

PC 스마트폰 미리보기의 작은 2열 카드 크기를 기준으로 한다.

권장:

- 높이 약 `105px~130px`
- 내부 padding 약 `12px~16px`
- 아이콘 컨테이너 약 `44px~56px`
- 제목 약 `16px~19px`
- 설명 약 `12px~14px`
- 텍스트 최대 2줄
- 넘치는 데이터는 의미가 유지되는 짧은 문구 사용
- 카드 전체 클릭 영역 유지

실제 모바일에서 카드 하나가 거의 전체 화면 너비와 큰 높이를 차지하지 않게 한다.

---

## 13. 내부 콘텐츠 최대 너비

실제 모바일에서도 내부 콘텐츠가 무제한 확대되지 않도록 공통 최대 너비를 둔다.

권장 개념:

```css
.child-home-content {
  width: 100%;
  max-width: 430px;
  margin-inline: auto;
}
```

실제 스마트폰 viewport가 430px 이하인 경우에는 좌우 safe padding을 제외한 전체 너비를 사용한다.

PC 스마트폰 미리보기에서도 동일한 `.child-home-content`를 사용한다.

외곽 Frame Component가 내부 콘텐츠 크기를 다시 임의로 축소하지 않게 한다.

---

## 14. 높이 및 스크롤 정책

### 실제 모바일 PWA

- 앱 Shell 높이 `100dvh`
- 상단·하단 safe-area 반영
- 앱 콘텐츠 영역 내부 세로 스크롤
- body 이중 스크롤 금지
- 가로 스크롤 금지
- 하단 콘텐츠가 iOS 홈 인디케이터에 가리지 않음

### PC 스마트폰 미리보기

- 프레임 내부 viewport에서 세로 스크롤
- 외곽 페이지와 내부가 동시에 스크롤되지 않게 함
- 프레임 내부와 실제 모바일의 콘텐츠 높이 계산식을 가능한 한 공유

모바일과 미리보기에서 스크롤 컨테이너가 다르다는 이유로 카드 레이아웃을 별도로 만들지 않는다.

## 15. 문의 버튼 위치 통일

현재 PC 스마트폰 미리보기와 실제 모바일의 문의 버튼 위치가 다르다.

문의 버튼은 드래그 가능한 기존 정책을 유지하되 다음을 적용한다.

### 기본 위치

동일한 Layout Version에서는 같은 상대적 기본 위치를 사용한다.

예:

```text
우측 중단 또는 카드 상단 우측
```

현재 확정된 제품 기본 위치를 실제 프로젝트에서 확인해 적용한다.

### 저장 좌표

기기마다 저장된 문의 버튼 좌표가 다를 수 있으므로 다음을 확인한다.

- 저장 좌표가 viewport 절대 px인지
- 프레임 내부 좌표인지
- 실제 모바일 좌표인지
- 이전 Layout Version의 좌표인지

좌표 저장 시 다음 Metadata를 포함하거나 동등한 검증을 적용한다.

```text
layoutVersion
viewportWidth
viewportHeight
displayMode
```

Layout Version이 바뀌었거나 현재 viewport에서 유효하지 않은 좌표는 기본 위치로 초기화한다.

현재 viewport와 safe-area 안으로 반드시 clamp한다.

---

## 16. Device Preview 전용 축소 제거

PC 스마트폰 미리보기가 실제 앱을 `transform: scale()`로 축소해 보여주는 구조인지 확인한다.

만약 미리보기에서만 전체 앱을 축소하고 있다면, 보이는 크기가 같더라도 실제 CSS 크기는 서로 다를 수 있다.

### 원칙

- Device Frame 전체를 데스크톱 화면에 맞추기 위한 외부 scale은 허용 가능
- 내부 앱 레이아웃의 CSS Pixel 기준은 실제 스마트폰과 동일해야 함
- 외부 scale 때문에 breakpoint가 달라지면 안 됨
- Device Preview 전용 class가 카드 Grid와 font-size를 변경하면 안 됨

프레임의 표시 배율과 내부 UI 반응형을 분리한다.

---

## 17. 반응형 기준 통합

아이 홈의 레이아웃은 User-Agent가 아니라 내부 CSS viewport 또는 Container Width로 결정한다.

금지:

```text
isMobile ? MobileHome : DesktopHome
isPwa ? LargeHome : CompactHome
navigator.standalone 기준 카드 배치 변경
```

권장:

- 동일 컴포넌트
- 동일 DOM
- CSS Grid/Flex
- Container Query 또는 공통 width token
- 최소한의 breakpoint만 사용

---

## 18. PWA Cache와 업데이트 연동

모바일 PWA가 이전 Build를 사용하고 있는 것이 확인되면 `040` 요청과 연계해 해결한다.

필수 검증:

1. 새 Build 배포
2. 기존 모바일 PWA 실행
3. 새 버전 안내 표시
4. 업데이트 적용
5. App Build ID 변경 확인
6. 최신 CSS Chunk 적용 확인
7. 아이 홈 최신 레이아웃 표시
8. PWA 삭제·재설치 없이 성공

CSS 수정만 배포하고 모바일 PWA가 이전 Cache를 계속 쓰는 상태로 완료 처리하지 않는다.

## 23. 시각 QA 기준

PC 스마트폰 미리보기 내부와 실제 모바일 PWA를 같은 CSS viewport 크기로 맞춰 비교한다.

확인:

- 마스코트 크기 차이 ±5% 이내
- 인사 문구 크기 차이 없음
- 안내 말풍선 크기 차이 없음
- 미션 카드 높이 차이 ±5% 이내
- 대화·놀이 카드 모두 2열
- 카드 간격 차이 ±4px 이내
- 좌우 page padding 차이 ±4px 이내
- 같은 데이터에서 텍스트 줄바꿈 유사
- 문의 버튼 기본 상대 위치 일치
- 가로 스크롤 없음
- 하단 safe-area 정상

외곽 스마트폰 프레임의 표시 여부는 비교 대상에서 제외한다.

비교 대상은 프레임 안쪽 앱 콘텐츠다.

## 25. 완료 기준

다음 조건을 모두 충족해야 완료로 판정한다.

- 모바일과 PC 스마트폰 미리보기의 Build ID가 동일함
- 모바일 PWA가 이전 Service Worker Bundle을 사용하지 않음
- 실제 모바일과 PC 미리보기가 동일한 `ChildHomeContent`를 사용함
- 실제 모바일에 추가 스마트폰 목업 프레임을 표시하지 않음
- 실제 모바일에서도 대화하기·케이와 놀이가 2열로 표시됨
- 마스코트 크기가 PC 미리보기 내부와 일치함
- 인사 문구와 말풍선 크기가 일치함
- 미션 카드 크기와 정보 밀도가 일치함
- 카드 여백과 간격이 일치함
- 문의 버튼 좌표가 현재 viewport 안에 보정됨
- 신규·진행 중·완료 미션 상태에서 레이아웃이 유지됨
- 모바일 브라우저와 설치형 PWA에서 동일하게 표시됨
- PWA 삭제·재설치 없이 새 UI 업데이트가 적용됨
- 기존 미션·대화·놀이·문의·로그아웃 기능에 회귀가 없음
- lint 통과
- typecheck 통과
- 관련 test 통과
- production build 통과
- 실제 모바일 PWA E2E 통과
