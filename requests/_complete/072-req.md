- Worker Orchestrator 구현 완료
- Dev에서 pending → Collection → Correction → Memory → Report 전체 체인 완료 확인

  /api/batch/v3/worker

하지만 Request 071은 아직 완료가 아니다.

현재 vercel.json에 등록한 하루 2회 Worker Cron:
- 08:58 UTC
- 14:58 UTC

은 제거한다.

이유:
Vercel Hobby Cron은 10분 주기 self-healing 요구사항을 충족할 수 없다.
이번 Request의 원래 요구사항은:
- pending 자동 claim
- 누락 downstream 자동 reconcile
- transient failure 자동 recovery
- 사람이 아침마다 확인하지 않아도 됨
이므로 하루 2회 실행으로 축소하면 안 된다.

==================================================
1. Scheduler를 Supabase pg_cron + pg_net으로 이동
==================================================

이미 Production에서 정상 사용 중인 Supabase pg_cron infrastructure를 사용한다.

새 forward migration을 작성해서 Production에서:

*/10 * * * *

주기로 Worker endpoint를 호출한다.

호출 대상:
https://app.k-bestie.com/api/batch/v3/worker
또는 현재 Production canonical domain을 실제 확인해서 사용.

POST 호출.

==================================================
2. Secret 처리
==================================================

BATCH_SECRET을 코드나 migration SQL에 평문 하드코딩 금지.

Supabase Vault 또는 현재 Production의 안전한 secret storage를 사용한다.

권장:

Vault:
- pipeline_worker_url
- pipeline_worker_secret

cron SQL에서는 vault.decrypted_secrets를 조회해서:

Authorization:
Bearer <secret>

형태로 Worker endpoint를 호출한다.

Secret:
- git commit 금지
- 로그 출력 금지
- response 출력 금지

현재 Vercel Production의 BATCH_SECRET과 동일한 값을 Vault에 안전하게 등록한다.

대표에게 secret 값을 채팅으로 요구하지 마라.
가능한 기존 배포/관리 권한을 사용해서 secret을 secure storage 간에 설정하라.
실제 값 조회가 불가능하면 대표에게 값을 공개 요청하지 말고,
Vercel/Supabase Dashboard에서 직접 설정해야 하는 최소 UI 작업만 정확히 보고한다.
