# 관리자 리텐션 상세 드릴다운 사용자 표시값 개선

## 1. 작업 목적

관리자 `/admin/retention` 페이지의 `사용자별 상세 드릴다운` 영역에서 부모·아이·가족을 내부 UUID로 표시하지 않는다.

운영자가 즉시 알아볼 수 있도록 다음 형식으로 표시한다.

```text
이름 (로그인 아이디)
```

예시:

```text
Mark An (markanitp@gmail.com)
안서아 (asa@kbestie.local)
QA 부모 (qa-parent@kbestie.local)
```

UUID는 내부 식별용으로만 유지하고 관리자 기본 화면에는 노출하지 않는다.

---

## 2. 적용 대상

다음 세 탭 전체에 적용한다.

- 부모 상세
- 아이 상세
- 가족 상세

현재 다음과 같이 표시되는 컬럼을 변경한다.

```text
부모 ID
아이 ID
가족 ID
```

변경 후:

```text
부모
아이
가족
```

---

## 3. 표시 규칙

### 부모 상세

1. 이름과 로그인 아이디가 모두 있으면:

```text
부모 이름 (로그인 아이디)
```

2. 이름만 있으면:

```text
부모 이름
```

3. 로그인 아이디만 있으면:

```text
로그인 아이디
```

4. 둘 다 없으면:

```text
마스킹된 UUID
```

---

### 아이 상세

1. 아이 이름과 로그인 아이디가 모두 있으면:

```text
아이 이름 (로그인 아이디)
```

2. 아이 이름만 있으면:

```text
아이 이름
```

3. 로그인 아이디만 있으면:

```text
로그인 아이디
```

4. 둘 다 없으면:

```text
마스킹된 UUID
```

---

### 가족 상세

가족 자체에 별도 이름이 없다면 다음 형식으로 표시한다.

```text
부모 이름 가족 (부모 로그인 아이디)
```

예시:

```text
Mark An 가족 (markanitp@gmail.com)
QA 부모 가족 (qa-parent@kbestie.local)
```

가족명이 실제로 존재하면 다음 형식으로 표시한다.

```text
가족명 (대표 부모 로그인 아이디)
```

가족 상세 행 내부에는 연결된 부모와 아이도 각각 이름과 로그인 아이디로 표시한다.

---

## 4. fallback 정책

표시 우선순위:

```text
이름 + 로그인 아이디
→ 이름
→ 로그인 아이디
→ 마스킹 UUID
```

마스킹 UUID 예시:

```text
51bd779b...
```

전체 UUID는 기본 화면에 노출하지 않는다.

---

## 5. 서버 조회 방식

클라이언트에서 UUID를 받은 뒤 별도 전체 사용자 목록을 다시 조회하여 수동 매핑하지 않는다.

리텐션 상세 API 또는 서버 조회 단계에서 필요한 사용자 정보를 조인하여 반환한다.

확인 대상:

- `parent_profiles`
- `family_members`
- `child_profiles`
- `auth.users`
- 부모·아이 가족 연결 테이블
- 기존 관리자 사용자 목록 조회 로직

---

## 6. 권장 API 응답

### 부모

```json
{
  "parentId": "uuid",
  "parentName": "Mark An",
  "loginId": "markanitp@gmail.com",
  "displayLabel": "Mark An (markanitp@gmail.com)"
}
```

### 아이

```json
{
  "childId": "uuid",
  "childName": "안서아",
  "loginId": "asa@kbestie.local",
  "displayLabel": "안서아 (asa@kbestie.local)"
}
```

### 가족

```json
{
  "familyId": "uuid",
  "familyName": null,
  "primaryParentName": "Mark An",
  "primaryParentLoginId": "markanitp@gmail.com",
  "displayLabel": "Mark An 가족 (markanitp@gmail.com)"
}
```

실제 프로젝트 타입과 명명 규칙에 맞춰 구현한다.

## 9. 내부 테스트 계정 처리

다음 내부 테스트 계정도 ON 상태에서 동일한 형식으로 표시되어야 한다.

### 부모

```text
qa-parent@kbestie.local
markanitp@gmail.com
```

### 아이

```text
testa@kbestie.local
testb@kbestie.local
psa160202@kbestie.local
psh160202@kbestie.local
psd160202@kbestie.local
```

체크박스 OFF에서는 행 자체가 제외되어야 하며, ON에서는 이름과 로그인 아이디로 표시되어야 한다.

## 10. 개인정보 및 보안

- 전체 UUID를 기본 화면에 노출하지 않는다.
- 부모 로그인 아이디와 아이 로그인 아이디를 혼동하지 않는다.
- 관리자 권한을 서버에서 검증한다.
- 일반 부모와 아이는 상세 API에 접근할 수 없어야 한다.
- Service Role Key를 클라이언트에 노출하지 않는다.
- API Key, DB 비밀번호, Token을 로그에 출력하지 않는다.
- 전체 UUID가 tooltip, title, aria-label에 노출되지 않도록 한다.
- 디버그 로그에서도 전체 이메일과 UUID를 불필요하게 출력하지 않는다.

## 11. 삭제·비활성·누락 계정 처리

### 삭제된 부모

```text
삭제된 부모 (51bd779b...)
```

### 삭제된 아이

```text
삭제된 아이 (e74a4ed1...)
```

### 이름 누락

로그인 아이디만 표시한다.

### 로그인 아이디 누락

이름만 표시한다.

### 둘 다 누락

마스킹 UUID를 표시한다.

---

## 12. 중복 이름 처리

동일한 이름을 가진 부모 또는 아이가 있을 수 있으므로 로그인 아이디를 함께 표시한다.

이름만으로 행을 식별하거나 상세 조회를 수행하지 않는다.

조회와 이동은 기존 불변 UUID를 내부적으로 계속 사용한다.

## 18. 작업 금지 사항

- UUID를 계속 기본 표시값으로 사용하지 않는다.
- 이름만으로 사용자나 가족을 식별하지 않는다.
- 클라이언트에서 별도 전체 목록을 받아 수동 조인하지 않는다.
- 부모 이메일을 아이 로그인 아이디로 표시하지 않는다.
- 전체 UUID를 tooltip에 노출하지 않는다.
- 리텐션 계산식이나 필터 로직을 변경하지 않는다.
- 내부 테스트 계정 제외 로직을 깨뜨리지 않는다.
- Dev만 수정하고 Production을 누락하지 않는다.
- Production 화면 검증 없이 완료 처리하지 않는다.
