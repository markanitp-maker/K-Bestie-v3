요청 큐 처리 규칙 추가 및 CLAUDE.md 업데이트 지침 (Claude Code용)
1. 기본 동작
requests/ 폴더에 쌓인 큐(작업 지시서 파일)는 기본적으로 모두 처리하는 것을 원칙으로 한다.
파일명 오름차순(001-.md, 002-.md …)으로 순차 처리하며, _TEMPLATE.md, _log.md, _blocked.md, _dashboard.md 및 _done/·_failed/ 하위 폴더는 처리 대상에서 제외한다.
지시서 처리가 정상 완료되면 해당 파일을 requests/_done/로 이동하고, _log.md에 처리 결과를 한 줄로 기록한다.
requests/에 처리 대상 파일이 남아 있는 한 루프를 계속 돌며, 큐가 완전히 빌 때까지 턴을 종료하지 않는다.
2. 특이사항 발생 시 (_dashboard.md)
지시서를 완료할 수 없는 특이사항이 발생하면 — 예: 대표님의 결정이 필요하거나, 기술적 이슈·의존성 충돌·정보 부족 등 스스로 판단·해결할 수 없는 상황 — 해당 지시서를 _done/으로 옮기지 말고 requests/_dashboard.md를 생성(이미 있으면 이어서 추가)한다.
_dashboard.md에는 각 미완료 건마다 아래 3가지를 반드시 명시한다.
대상 지시서 파일명 (예: 003-결제연동.md)
왜 완료하지 못했는지 (구체적인 사유)
완료하기 위해 추가로 필요한 작업 (대표님 결정 사항이면 선택지와 결정할 항목, 기술 이슈면 필요한 조치·정보)
기록 후 해당 건은 건너뛰고 다음 큐로 진행하며, 처리 가능한 나머지 파일은 계속 정상 처리한다.
3. 마무리 및 보고
큐를 모두 순회한 뒤, _done/으로 이동한 파일 목록과 _dashboard.md에 올린 미완료 건 목록을 각각 요약해 보고한다.
_dashboard.md에 항목이 하나라도 있으면 §15 김비서 보고로 대표님께 확인·결정 필요 사항을 알린다.
4. CLAUDE.md 업데이트 (필수)
위 1~3 규칙을 CLAUDE.md의 "요청 폴더 감시 규칙" 섹션에 반영해 파일 자체를 업데이트한다.
처리 제외 목록에 _dashboard.md를 추가하고, 기존 _blocked.md 관련 규칙과 충돌하지 않도록 정리한다(특이사항 대시보드는 _dashboard.md, 미결정 항목은 기존 _blocked.md 흐름 유지 — 중복되면 하나로 통합).
_dashboard.md의 실제 작성 양식(파일명 / 사유 / 필요조치 3단 마크다운 템플릿)을 섹션에 포함한다.
업데이트 완료 후 변경한 섹션 번호와 수정 내용을 요약 보고하고, 설정 동기화가 필요하면 git 커밋 [설정] 요청 큐 _dashboard 규칙 추가 …v8-Universal… 형식으로 커밋한다.
