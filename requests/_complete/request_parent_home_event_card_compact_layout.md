# 부모 홈 30일 이벤트 카드 가로 2분할 UI 개선

## 1. 작업 목적

부모 홈 화면의 `케이와 친해지는 30일 이벤트` 카드를 현재 세로형 정보 배치에서 가로 2분할 요약형 카드로 변경한다.

현재 카드는 제목 아래에 진행률, 상품권, 다음 단계까지 남은 횟수, 이벤트 남은 일수가 세로로 길게 배치되어 카드 높이가 크다. 이로 인해 아래 인사이트 카드가 화면 하단으로 밀려 부모가 핵심 정보를 한눈에 보기 어렵다.

개선 후에는 카드 높이를 줄이고, 왼쪽에는 현재 진행 상태, 오른쪽에는 남은 목표와 기간을 배치하여 같은 정보를 더 빠르게 읽을 수 있도록 한다.

---

## 2. 대상 화면

- 부모 홈 화면
- 선택된 아이 기준으로 노출되는 `케이와 친해지는 30일 이벤트` 카드
- 모바일 화면 우선
- 태블릿 및 데스크톱 반응형 포함

---

## 3. 현재 문제

현재 이벤트 카드의 정보가 다음 순서로 세로 배치된다.

```text
케이와 친해지는 30일 이벤트
박서아 0/60 완료
현재 달성 상품권: 0원
다음 단계까지 10번 남았어요.
이벤트 종료까지 30일 남았어요.
```

문제점:

- 카드 높이가 불필요하게 큼
- 이벤트 정보가 한 덩어리로 보여 중요 정보 구분이 약함
- 아래 인사이트 카드 노출 영역이 줄어듦
- 모바일 첫 화면에서 스크롤이 길어짐
- 진행 상태와 남은 목표를 빠르게 비교하기 어려움

---

## 4. 목표 UI

카드 상단에는 제목을 한 줄로 유지한다.

```text
케이와 친해지는 30일 이벤트
```

제목 아래 본문은 좌우 2개 영역으로 나눈다.

### 왼쪽 영역

```text
박서아 0/60 완료
현재 달성 상품권: 0원
```

### 오른쪽 영역

```text
다음 단계까지 10번 남았어요.
이벤트 종료까지 30일 남았어요.
```

좌우 영역 사이에는 연한 세로 구분선을 표시한다.

---

## 5. 레이아웃 요구사항

### 5.1 전체 구조

권장 구조:

```tsx
<section className="event-card">
  <h3>케이와 친해지는 30일 이벤트</h3>

  <div className="event-card__content">
    <div className="event-card__summary">
      {/* 아이 이름 + 진행률 */}
      {/* 현재 달성 상품권 */}
    </div>

    <div className="event-card__divider" />

    <div className="event-card__remaining">
      {/* 다음 단계까지 남은 횟수 */}
      {/* 이벤트 남은 일수 */}
    </div>
  </div>
</section>
```

### 5.2 좌우 비율

- 기본 비율: 약 `1:1`
- 각 영역은 동일한 시각적 비중 유지
- 아이 이름이 길어도 오른쪽 영역을 침범하지 않도록 처리
- 최소 너비에서 텍스트 줄바꿈 허용
- 카드 내부 `overflow`로 텍스트를 강제 숨기지 않음

### 5.3 세로 구분선

- 좌우 영역 사이에 연한 회색 또는 기존 디자인 시스템의 divider 색상 사용
- 너무 진한 색상 금지
- 카드 전체 높이보다 약간 짧게 표시
- 카드 상하 패딩 안에서 정렬

예시:

```css
.event-card__divider {
  width: 1px;
  align-self: stretch;
  background: var(--border-subtle);
}
```

### 5.4 카드 높이

- 현재 카드보다 확실히 낮아야 함
- 아래 인사이트 카드가 더 위에서 노출되어야 함
- 정보 손실 없이 세로 여백 축소
- 제목과 본문 사이 간격은 유지하되 과도한 패딩 제거

## 6. 텍스트 스타일

### 제목

- 문구: `케이와 친해지는 30일 이벤트`
- 한 줄 유지
- 기존 부모 홈 카드 제목 스타일과 통일
- 너무 굵거나 크게 키우지 않음

### 왼쪽 1행

예시:

```text
박서아 0/60 완료
```

- 아이 이름과 진행률을 한 줄로 표시
- 아이 이름은 실제 선택된 아이 값 사용
- 진행률 숫자는 기존 이벤트 계산 결과 사용
- 핵심 정보이므로 본문 중 가장 높은 강조도 적용

### 왼쪽 2행

예시:

```text
현재 달성 상품권: 0원
```

- 보조 텍스트 크기
- 금액은 기존 이벤트 보상 계산 결과 사용
- 금액 표기 방식은 기존 정책 유지

### 오른쪽 1행

예시:

```text
다음 단계까지 10번 남았어요.
```

- 남은 완료 횟수를 실제 계산값으로 표시
- 문장 길이는 최대 2줄 이내
- 목표 달성 완료 상태에서는 별도 완료 문구 적용

### 오른쪽 2행

예시:

```text
이벤트 종료까지 30일 남았어요.
```

- 실제 남은 일수 사용
- 종료일 계산 로직 변경 금지
- 0일 이하인 경우 종료 상태 문구 표시

## 7. 반응형 요구사항

### 7.1 일반 모바일

기준:

- 약 360~430px 너비
- 좌우 2분할 유지
- 각 영역 내부 텍스트 최대 2줄
- 텍스트 겹침 금지
- 세로 구분선 유지

### 7.2 소형 모바일

기준:

- 320px 이하

요구사항:

- 좌우 2분할 원칙 유지
- 폰트 크기와 내부 간격을 단계적으로 축소
- 문장이 잘리지 않도록 `line-height` 조정
- 아이 이름이 긴 경우 1줄 말줄임 또는 최대 2줄 처리
- 숫자와 단위가 분리되지 않도록 가능한 범위에서 묶음 유지
- 텍스트가 세로 구분선을 침범하지 않도록 처리

불가피하게 가독성이 깨지는 경우에만 CSS media query로 세로 배치를 허용하되, 기본 설계는 가로 2분할로 유지한다.

### 7.3 태블릿 및 데스크톱

- 카드 폭이 넓어져도 내용이 양 끝으로 과도하게 벌어지지 않도록 최대 내부 너비 적용
- 모바일과 동일한 정보 구조 유지
- 카드 높이를 불필요하게 늘리지 않음

---

## 8. 데이터 요구사항

카드 디자인만 변경하고 기존 이벤트 계산 로직과 DB 구조는 변경하지 않는다.

다음 값은 기존 데이터 원천을 그대로 사용한다.

- 선택된 아이 이름
- 현재 완료 횟수
- 목표 완료 횟수
- 현재 달성 상품권 금액
- 다음 보상 단계까지 남은 완료 횟수
- 이벤트 종료까지 남은 일수
- 이벤트 상태
- 이벤트 시작일 및 종료일

---

## 9. 선택된 아이 변경 처리

부모 홈 상단에서 선택된 아이가 변경되면 이벤트 카드도 즉시 해당 아이 기준으로 변경되어야 한다.

변경 대상:

- 아이 이름
- 진행률
- 현재 달성 상품권
- 다음 단계까지 남은 횟수
- 이벤트 남은 일수
- 이벤트 상태

다음 문제가 없어야 한다.

- 이전 아이 정보가 잠시 남는 현상
- 이름만 바뀌고 숫자가 그대로 남는 현상
- 캐시된 다른 아이 이벤트 데이터 노출
- 새로고침해야 값이 바뀌는 현상

현재 데이터 패칭 방식에 맞춰 필요한 경우 query invalidate, refetch 또는 상태 갱신을 적용한다.

## 10. 상태별 표시 정책

### 10.1 미참여 상태

아직 이벤트가 시작되지 않은 경우:

왼쪽 예시:

```text
박서아 0/60 완료
현재 달성 상품권: 0원
```

오른쪽 예시:

```text
첫 미션 완료 후 시작돼요.
이벤트 시작 전이에요.
```

기존 비즈니스 로직에 이미 정의된 문구가 있으면 그 문구를 우선 사용한다.

### 10.2 진행 중

예시:

```text
박서아 13/60 완료
현재 달성 상품권: 1,000원
```

```text
다음 단계까지 17번 남았어요.
이벤트 종료까지 21일 남았어요.
```

### 10.3 최고 목표 달성

60/60을 달성한 경우:

왼쪽 예시:

```text
박서아 60/60 완료
현재 달성 상품권: 10,000원
```

오른쪽 예시:

```text
최고 목표를 달성했어요.
이벤트 종료까지 4일 남았어요.
```

`다음 단계까지 0번 남았어요`처럼 어색한 문구를 표시하지 않는다.

### 10.4 이벤트 종료

종료된 경우:

왼쪽 예시:

```text
박서아 42/60 완료
최종 달성 상품권: 3,000원
```

오른쪽 예시:

```text
이벤트가 종료됐어요.
최종 결과를 확인해 주세요.
```

기존 종료 상태 문구가 있으면 해당 정책을 따른다.

### 10.5 데이터 조회 실패

- 잘못된 숫자를 임의로 표시하지 않음
- `0/60`으로 조용히 대체하지 않음
- 기존 공통 오류 UI 또는 재시도 상태 적용
- 사용자에게 기술 오류 메시지를 직접 노출하지 않음

## 11. 접근성 요구사항

- 텍스트 대비 WCAG 기준에 맞게 유지
- 세로 구분선만으로 정보를 구분하지 않고 좌우 정보 구조도 명확히 구성
- 스크린리더가 제목 → 현재 상태 → 남은 목표 순으로 읽을 수 있도록 DOM 순서 구성
- 클릭 가능한 카드라면 전체 카드에 적절한 `aria-label` 적용
- 단순 정보 카드라면 불필요한 버튼 역할 부여 금지

새로운 임의 색상값을 직접 추가하지 말고 기존 디자인 토큰을 우선 사용한다.

## 13. 구현 제한

다음 작업은 하지 않는다.

- 이벤트 DB 구조 변경

- 상품권 구간 정책 변경

- 30일 이벤트 집계 원장 변경
- 진행률 계산 방식 변경

- 전체 부모 홈 페이지 리디자인

이번 작업 범위는 이벤트 카드 UI 구조 개선과 필요한 최소 상태 동기화에 한정한다.


## 15. 테스트 시나리오

### 15.1 기본 모바일

1. 부모 홈 접속
2. 이벤트 카드가 가로 2분할로 표시되는지 확인
3. 왼쪽에 이름·진행률·상품권 표시 확인
4. 오른쪽에 남은 횟수·남은 일수 표시 확인
5. 세로 구분선 확인
6. 기존보다 카드 높이가 줄었는지 확인
7. 아래 인사이트 카드가 더 위에서 보이는지 확인

### 15.2 선택된 아이 변경

1. 아이 A 선택
2. 이벤트 정보 기록
3. 아이 B로 변경
4. 이름과 모든 숫자가 아이 B 기준으로 즉시 변경되는지 확인
5. 다시 아이 A로 변경
6. 값이 정확히 복원되는지 확인

### 15.3 진행률 상태

다음 값을 각각 검증한다.

- 0/60
- 9/60
- 10/60
- 29/60
- 30/60
- 49/60
- 50/60
- 59/60
- 60/60

각 상태에서 상품권 금액과 다음 단계 문구가 기존 정책대로 표시되어야 한다.

### 15.4 남은 일수

다음 값을 각각 확인한다.

- 30일
- 21일
- 7일
- 1일
- 0일
- 종료 상태

- 2글자 이름

텍스트가 구분선을 침범하거나 카드 밖으로 벗어나지 않아야 한다.
