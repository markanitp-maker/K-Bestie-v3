# 053 — 가족 중심 온보딩·PWA 설치 우선 안내·다자녀 개별 승인 체계 개편

## 1. 작업 목적

현재 본 앱의 회원가입 이후 흐름에는 베타 신청서와 사용자 승인 과정이 포함되어 있어 다음 문제가 발생한다.

- 별도 베타 모집 사이트에서 이미 신청서와 설문을 받는데 본 앱에서도 다시 신청하게 됨
- 최초 보호자와 추가 보호자의 가입 흐름이 불필요하게 복잡함
- 가족 단위 서비스인데 사용자 승인·가족 승인·아이 승인의 기준이 혼재함
- 추가 보호자가 가족에 참여하려고 해도 베타 신청서로 이동함
- 다자녀 가정에서 아이를 여러 명 계속 추가하고 각각 승인받는 구조가 명확하지 않음
- 회원가입 후 사용자가 주소를 다시 찾아 들어오기 어려울 수 있는데 PWA 설치 안내가 충분히 우선 노출되지 않음

이번 작업에서는 본 앱 안의 베타 신청 절차를 제거하고 다음 구조로 개편한다.

```text
회원가입
→ PWA 설치 우선 안내
→ 가족 만들기 또는 가족 구성원으로 참여하기
→ 가족 연결
→ 아이 1명 이상 자유롭게 추가
→ 아이별 관리자 승인 대기
→ 승인된 아이만 서비스 활성화
→ 승인 시 케어 인사이트 기본 적용
```

# 2. 최종 확정 정책

## 회원가입 직후

회원가입을 완료한 사용자는 베타 신청서로 이동하지 않는다.

다음 두 경로만 제공한다.

```text
가족 만들기
가족 구성원으로 참여하기
```

두 경로 위에는 PWA 앱 설치 안내를 가장 먼저 표시한다.

## 관리자 승인 단위

다음에는 관리자 승인이 필요하지 않다.

- 회원가입
- 가족 만들기
- 보호자 초대
- 가족 구성원 참여

관리자 승인은 아이 추가 시 아이별로 발생한다.

## 아이 추가

- 한 가족에 아이를 1명만 등록하도록 제한하지 않는다.
- 아이를 1명, 2명, 3명 이상 계속 추가할 수 있다.
- 추가된 모든 아이는 각각 독립적인 승인 상태를 가진다.
- 한 아이가 승인되어도 다른 아이가 자동 승인되지 않는다.
- 승인된 아이만 케이 서비스를 이용할 수 있다.

## 기본 플랜

- 아이 추가 시 기본 플랜 값은 `케어 인사이트`로 설정한다.
- 관리자 승인 전에는 실제 서비스가 비활성 상태다.
- 관리자 승인과 동시에 케어 인사이트로 서비스가 활성화된다.
- 승인 후 케어 스타트와 케어 인사이트 사이의 변경은 가능하다.
- 기존 플랜 변경 승인 절차가 있다면 그대로 유지한다.
- 케어 프리미엄은 `준비 중` 상태로 표시하고 선택·적용할 수 없게 한다.
- 케어 프리미엄은 UI뿐 아니라 API·서버에서도 차단한다.

# 3. 별도 베타 모집 사이트와 본 앱의 역할 분리

별도 베타 모집 사이트는 다음 역할만 담당한다.

- 베타 신청서 접수
- 설문조사 접수
- 신청자 선정 검토
- 대표님의 수동 확인

본 앱은 다음 역할을 담당한다.

- 회원가입
- 가족 생성
- 보호자 연결
- 아이 등록
- 아이 서비스 승인 요청
- 아이별 서비스 활성화
- 아이별 플랜 관리

이번 작업에서 별도 베타 사이트 DB와 본 앱 DB를 자동 연동하지 않는다.

다음 방식으로 운영한다.

```text
본 앱 관리자 페이지에서 아이 추가 요청 확인
→ 아이를 추가한 보호자 이메일 확인
→ 가족 생성자 이메일 확인
→ 별도 베타 모집 관리자 페이지에서 이메일 검색
→ 베타 신청 및 설문 완료 여부를 대표님이 직접 확인
→ 본 앱 관리자 페이지에서 아이 승인
```

별도 베타 사이트의 데이터베이스·테이블·API를 본 앱에서 조회하거나 수정하지 않는다.

# 4. 기존 베타 신청 흐름 제거

다음 본 앱 내부 흐름을 제거한다.

- 회원가입 후 베타 신청서 자동 이동
- 본 앱의 `베타 신청하기` 버튼
- 본 앱의 베타 신청서 입력 화면
- 본 앱의 베타 신청 승인 대기 화면
- 사용자 계정 단위 베타 승인 Gate
- 추가 보호자의 중복 베타 신청
- 가족 생성 전 베타 신청 여부 검사
- 가족 참여 전 베타 신청 여부 검사

기존 베타 신청 데이터가 본 앱에 남아 있다면 즉시 삭제하지 않는다.

- 기존 데이터는 운영 기록으로 보존
- 신규 가입 흐름에서는 사용하지 않음
- 기존 Route는 직접 접근 시 새로운 온보딩 화면으로 안전하게 Redirect
- 기존 사용자 접근을 깨뜨리지 않도록 호환 처리

# 5. 회원가입 완료 후 최종 화면

회원가입 성공 후 다음 화면으로 이동한다.

## 화면 구조

```text
내친구 케이를 앱으로 설치해 주세요

홈 화면에 설치하면
주소를 다시 찾지 않고 바로 이용할 수 있어요.

[앱 설치하기]

────────────────────

내친구 케이를 어떻게 시작할까요?

[가족 만들기]
새로운 가족을 만들고 아이를 등록해요.

[가족 구성원으로 참여하기]
이미 만들어진 가족에 보호자로 참여해요.
```

## 화면 순서

1. 앱 설치 안내
2. 가족 만들기
3. 가족 구성원으로 참여하기

가족 선택 영역보다 PWA 설치 안내가 먼저 보여야 한다.

## 금지

- 베타 신청하기 버튼 추가
- 베타 신청서 링크 추가
- 가입 목적을 묻는 추가 설문 추가
- 초대 코드 입력 추가
- 초대 링크 입력 추가
- 사용자가 입력해야 하는 별도 가족 식별번호 추가

---

# 6. PWA 설치 우선 안내

## 기본 원칙

회원가입 직후 사용자가 다시 사이트 주소를 찾지 않아도 되도록 앱 설치 메뉴를 최우선으로 노출한다.

단, PWA 설치 지원 상태가 기기·브라우저마다 다르므로 설치 불가능 상태에서 온보딩 전체를 막지 않는다.

## Android·Chromium

`beforeinstallprompt` 이벤트를 기존 공통 PWA 설치 로직과 연결한다.

```text
[앱 설치하기]
→ 브라우저 설치 Prompt
→ 설치 완료
→ 설치 안내 영역 숨김
```

## iPhone·iPad

iOS에서는 직접 설치 Prompt 호출이 지원되지 않을 수 있으므로 다음 안내를 제공한다.

```text
Safari 하단의 공유 버튼을 누른 뒤
‘홈 화면에 추가’를 선택해 주세요.
```

가능하면 기기별 시각 안내를 제공하되, 신규 이미지 생성이나 과도한 온보딩 단계는 만들지 않는다.

## 이미 설치된 경우

다음 조건에서는 설치 안내 영역을 숨긴다.

- `display-mode: standalone`
- iOS `navigator.standalone`
- 기존 설치 상태를 신뢰할 수 있게 확인한 경우

## 설치 불가·미지원 상태

- 설치 버튼을 눌러도 아무 동작이 없는 상태 금지
- 지원하지 않는 브라우저에서는 브라우저별 간단한 설치 안내 표시
- 설치가 불가능해도 가족 만들기·가족 참여는 계속 진행 가능
- PWA 설치를 완료하지 않았다는 이유로 회원가입 상태를 되돌리지 않음

## 기존 PWA 기능 유지

- Service Worker
- 캐시
- 업데이트 안내
- Build ID
- 새 버전 새로고침
- 개발·운영 아이콘 분리
- Manifest
- Theme Color

기존 기능을 재작성하지 말고 공통 설치 컴포넌트를 재사용한다.

# 7. 가족 만들기

`가족 만들기`를 선택하면 별도 관리자 승인 없이 가족을 즉시 생성한다.

## 흐름

```text
회원가입 완료
→ 가족 만들기
→ 가족 생성
→ 현재 사용자를 최초 보호자·가족 생성자로 연결
→ 아이 추가 화면
```

## 가족 생성자

가족을 만든 사용자는 다음 역할을 가진다.

- 최초 보호자
- 가족 생성자
- 보호자 초대 가능
- 아이 추가 가능

기존 Role·Family Membership 구조가 있다면 재사용한다.

새로운 중복 가족 모델을 만들지 않는다.

## 중복 생성 방지

이미 가족에 연결된 사용자가 다시 가족 만들기를 선택하면 무조건 새 가족을 만들지 않는다.

다음을 먼저 확인한다.

- 사용자의 기존 가족 소속
- Pending 초대
- 기존 가족 생성 이력
- 탈퇴·삭제 상태

이미 유효한 가족이 있다면 해당 가족으로 이동하거나 적절한 안내를 표시한다.

# 8. 가족 구성원으로 참여하기

`가족 구성원으로 참여하기`를 선택하면 현재 로그인 계정으로 받은 보호자 초대를 조회한다.

추가 보호자는 반드시 먼저 회원가입을 완료한 상태여야 한다.

## 초대가 없는 경우

```text
가족 구성원에게 초대를 요청해 주세요

내친구 케이를 이용 중인 가족 구성원에게
아래 회원가입 이메일 주소를 알려주세요.

기존 가족 구성원이 ‘보호자 설정’에서
이 이메일 주소로 초대하면 가족에 참여할 수 있어요.

가입 이메일
parent@example.com

[초대 확인하기]
```

가입 이메일은 현재 로그인한 인증 계정에서 가져온다.

이메일을 별도로 입력받지 않는다.

가능하면 이메일 옆에 복사 버튼을 제공한다.

## 초대가 있는 경우

```text
가족 구성원 초대가 도착했어요

○○○ 님의 가족에 보호자로 참여하시겠어요?

[가족 구성원으로 참여하기]
[거절하기]
```

수락하면 기존 가족의 보호자로 연결한다.

## 기존 보호자의 초대

기존 보호자는 현재 `보호자 설정` 화면에서 이미 회원가입한 보호자의 이메일을 입력해 초대한다.

계정을 찾을 수 없으면 다음처럼 안내한다.

```text
해당 이메일로 가입한 계정을 찾을 수 없습니다.
보호자가 먼저 회원가입을 완료한 뒤 다시 초대해 주세요.
```

## 초대 정책

- 초대 링크 없음
- 초대 코드 없음
- 가입 전 이메일 초대 없음
- 이미 회원가입된 이메일 계정만 초대 가능
- 이메일 대소문자와 앞뒤 공백을 정규화
- 자기 자신 초대 금지
- 이미 같은 가족인 보호자 중복 초대 금지
- 다른 가족에 이미 연결된 사용자의 처리 정책은 기존 규칙 확인 후 충돌 방지
- 수락 전까지 아이 정보 접근 금지
- 거절·취소·만료 상태 보존

# 9. 아이 복수 등록

가족 생성 또는 가족 참여가 완료된 보호자는 아이를 계속 추가할 수 있다.

## 필수 동작

```text
아이 1 추가 → 승인 대기
아이 2 추가 → 승인 대기
아이 3 추가 → 승인 대기
아이 추가 버튼 계속 유지
```

아이 한 명을 등록했다는 이유로 `아이 추가` 버튼을 숨기거나 비활성화하지 않는다.

## 아이별 독립 상태

예시:

| 아이 | 승인 상태 | 서비스 상태 | 플랜 |
|---|---|---|---|
| 첫째 | 승인 완료 | 사용 가능 | 케어 인사이트 |
| 둘째 | 승인 대기 | 사용 불가 | 케어 인사이트 예정 |
| 셋째 | 거절·보류 | 사용 불가 | 미활성 |

## 중복 등록 방지

다자녀 추가는 허용하되 같은 아이를 실수로 중복 등록하는 것은 방지한다.

등록 정보가 기존 아이와 유사한 경우 경고한다.

확인 후보:

- 성
- 이름
- 생년월일
- 학년
- 가족 ID

단순히 같은 이름이라는 이유만으로 등록을 차단하지 않는다.

# 10. 아이 추가 시 승인 요청 생성

아이 프로필 저장이 완료되면 아이별 관리자 승인 요청을 생성한다.

아이 추가와 승인 요청 생성은 가능한 한 하나의 원자적 처리로 구성한다.

중간 실패로 다음 상태가 발생하지 않게 한다.

- 아이는 생성됐지만 승인 요청은 없음
- 승인 요청은 있지만 아이 프로필은 없음
- 같은 아이의 승인 요청 중복 생성

## 아이 생성 직후 상태

```text
승인 상태: 승인 대기
서비스 활성화: false
기본 플랜: 케어 인사이트
```

실제 프로젝트의 기존 컬럼·Enum·상태명을 먼저 확인하여 재사용한다.

기존 구조로 처리할 수 있으면 신규 테이블·컬럼을 만들지 않는다.

---

# 11. 승인 요청에 기록할 보호자 정보

아이 승인 요청에는 아이를 실제로 추가한 보호자와 가족 생성자 정보를 모두 추적할 수 있어야 한다.

## 필수 연결 정보

- 아이 ID
- 가족 ID
- 아이 추가 요청자 User ID

- 요청 시각
- 승인 상태
- 승인 관리자
- 승인 시각
- 거절 사유
- 기본 적용 플랜

## 관리자 표시 정보

사용자·가족 관계를 조회하여 다음을 표시한다.


승인 요청 당시 이메일 추적이 반드시 필요하다면 기존 사용자 참조와 함께 Audit Snapshot을 최소 범위로 검토한다.

이메일 Snapshot을 추가할 경우:

- 인증 계정의 정규화된 이메일 사용
- 민감정보 로그 출력 금지
- 일반 사용자에게 다른 보호자 이메일 과도 노출 금지
- 관리자 권한에서만 조회
- 승인 이력 감사 목적으로만 사용

# 12. 관리자 아이 승인 페이지

관리자 페이지에 `아이 서비스 승인` 메뉴를 제공한다.

## 승인 대기 목록

각 항목에 다음을 표시한다.

```text
아이 이름
학년
가족 정보
아이를 추가한 보호자 이름
아이를 추가한 보호자 이메일
가족 생성자 이름
가족 생성자 이메일
아이 추가 요청 시각
현재 승인 상태
승인 후 기본 플랜
```

## 예시

```text
아이 서비스 승인 요청

아이: 안서아
학년: 4학년

아이 추가 요청자: 안형진
요청자 이메일: parent@example.com

가족 생성자: 안형진
가족 생성자 이메일: parent@example.com

요청 시각: 2026-07-29 16:30
승인 상태: 승인 대기
승인 후 기본 플랜: 케어 인사이트

[ ] 별도 베타 신청 확인
[ ] 설문조사 완료 확인

[승인]
[거절]
```

## 외부 베타 확인 체크

대표님이 별도 베타 모집 페이지를 직접 확인한 뒤 다음 항목을 체크할 수 있게 한다.

- 베타 신청 확인
- 설문조사 완료 확인

두 항목을 모두 확인한 뒤에만 승인 버튼을 활성화하는 방식을 적용한다.

확인 결과는 본 앱의 관리자 승인 Audit 정보로 저장할 수 있다.

별도 베타 사이트의 실제 설문 데이터는 복사하거나 동기화하지 않는다.

## 이메일 편의 기능

- 이메일 한 번 클릭 복사
- 요청자 이메일과 가족 생성자 이메일을 명확히 구분
- 두 이메일이 같으면 중복 문구를 간결하게 표시
- 외부 사이트 자동 이동이나 자동 검색은 이번 범위에 포함하지 않음

# 13. 관리자 승인 동작

## 승인

승인 시 해당 아이만 활성화한다.

```text
아이 승인 상태 → 승인 완료
서비스 활성화 → true
플랜 → 케어 인사이트
승인 관리자 → 현재 관리자
승인 시각 → 현재 시각
```

다른 승인 대기 아이에게 영향을 주지 않는다.

## 거절

거절 시 아이 프로필을 즉시 삭제하지 않는다.

- 승인 상태를 거절 또는 보류로 변경
- 서비스 비활성 유지
- 거절 사유 저장
- 보호자 화면에서 거절·확인 필요 안내
- 필요하면 정보 수정 후 재승인 요청 가능

재승인 정책은 기존 구조를 우선 확인하고, 없으면 중복 아이를 새로 만들지 않고 기존 아이 상태를 다시 `승인 대기`로 전환하도록 구현한다.

## 동시 처리 방지

- 동일 아이 중복 승인 금지
- 두 관리자가 동시에 승인할 때 Race Condition 방지
- 승인 API의 관리자 권한 검증
- 승인 상태 조건부 Update
- 승인 완료 후 중복 서비스 활성화 금지

---

# 14. 아이 승인 전 사용자 화면

승인 대기 아이는 부모 화면에 프로필로 표시할 수 있다.

다만 케이 서비스는 사용할 수 없다.

## 안내 문구

```text
아이 등록을 확인하고 있어요

관리자가 베타 신청과 아이 정보를 확인한 뒤
내친구 케이 서비스를 사용할 수 있어요.
승인이 완료되면 알려드릴게요.
```

## 승인 전 허용

- 아이 정보 확인
- 아이 정보 수정
- 승인 상태 확인
- 가족 관리
- 보호자 초대
- 추가 아이 등록
- 문의하기

## 승인 전 차단

- 아이 미션
- 자유대화
- 케이와 놀이
- Gemini Live 세션
- STT·TTS 대화 세션
- 황금열쇠 적립
- 황금열쇠 차감
- 리포트 생성
- 놀이 Handoff
- 아이 서비스 API

화면만 비활성화하지 말고 서버 API에서도 승인 상태를 검증한다.

## 여러 아이가 섞인 경우

승인된 아이와 승인 대기 아이가 한 가족에 함께 존재할 수 있다.

- 승인된 아이: 정상 서비스 이용
- 승인 대기 아이: 서비스 잠금 및 승인 안내
- 거절 아이: 거절 사유 및 수정 안내

가족 전체를 일괄 차단하지 않는다.

# 15. 아이 승인 후 플랜 정책

## 기본 적용

관리자가 아이를 승인하면 해당 아이의 기본 플랜을 케어 인사이트로 활성화한다.

```text

```

- 케어 스타트
- 케어 인사이트

기존 플랜 변경 요청·관리자 승인 기능이 있다면 유지한다.

## 케어 프리미엄

화면 표시:

```text
케어 프리미엄
```

필수:

- API 직접 호출 차단
- 관리자도 운영 UI에서 임의 적용하지 못하게 차단
- 기존 Premium 사용자가 실제로 존재한다면 회귀 여부를 감사한 뒤 별도 보호 처리

# 16. 기존 사용자·아이 호환 처리

변경 전 이미 서비스를 사용 중인 가족과 아이를 일괄 승인 대기로 되돌리면 안 된다.

## 기존 활성 아이

기존에 정상적으로 서비스를 사용 중인 아이는 승인 완료 상태로 Backfill한다.

기존 플랜도 유지한다.

## 기존 승인 대기 사용자

기존 사용자 승인 구조가 있다면 다음을 감사한다.

- 회원 승인 상태
- 가족 상태
- 아이 상태
- 서비스 활성 상태
- 플랜

기존 데이터 손실 없이 새 아이 승인 모델로 전환한다.

## 기존 베타 신청 데이터

- 삭제하지 않음
- 신규 Gate로 사용하지 않음
- 관리자 기록으로만 유지
- 기존 사용자 로그인 차단 원인이 되지 않도록 함

데이터 마이그레이션이 필요하면 Dev 데이터 Snapshot과 Rollback SQL을 준비한다.

# 30. 롤백 기준

다음 중 하나가 발생하면 Production 배포를 중단하거나 이전 정상 배포로 롤백한다.

- 기존 사용자가 로그인할 수 없음
- 기존 가족 연결이 사라짐
- 기존 아이가 승인 대기로 변경됨
- 보호자 초대가 작동하지 않음
- 승인되지 않은 아이가 서비스를 사용함
- 승인된 아이가 서비스를 사용하지 못함
- 아이 승인 시 가족 전체 상태가 변경됨
- Care Insight가 아닌 잘못된 플랜 적용
- Care Premium이 선택됨
- 관리자 권한 없는 사용자가 승인 API 호출 가능
- RLS로 다른 가족 데이터 노출
- PWA 설치 화면에서 온보딩이 막힘
- Migration 실패
- Production Build 실패

DB Migration은 Rollback SQL 또는 복구 절차를 함께 준비한다.

# 31. 완료 기준

다음 조건을 모두 만족해야 완료다.

- 본 앱의 베타 신청하기·신청서·승인 Gate가 신규 흐름에서 제거됨
- 회원가입 후 PWA 설치 안내가 가장 먼저 표시됨
- 가족 만들기와 가족 구성원으로 참여하기 두 경로가 표시됨
- 가족 만들기는 관리자 승인 없이 즉시 완료됨
- 추가 보호자는 회원가입 후 이메일로 초대받아 가족에 참여함
- 초대 링크·코드가 없음
- 가족에 아이를 여러 명 계속 추가할 수 있음
- 각 아이가 개별 승인 대기 상태를 가짐
- 관리자 페이지에 아이 추가 요청자 이메일이 표시됨
- 관리자 페이지에 가족 생성자 이메일이 표시됨
- 베타 신청 확인·설문 완료 확인 후 승인 가능함
- 승인된 아이만 서비스가 활성화됨
- 승인되지 않은 아이는 서버 API에서도 차단됨
- 한 아이 승인 시 다른 아이 상태가 유지됨
- 아이 승인 시 Care Insight가 기본 적용됨
- Care Start·Care Insight 변경 가능 정책이 유지됨
- Care Premium이 준비 중·선택 불가 상태임
- 기존 활성 사용자·아이에 회귀가 없음
- Android·iOS PWA 설치 흐름이 정상임
- 모바일·태블릿·PC 반응형 정상
- RLS·관리자 권한 검증 통과
- Dev 배포 및 E2E 통과
- 동일 Commit Production 배포 및 Smoke Test 통과
- lint 통과
- typecheck 통과
- 관련 test 통과
- production build 통과
