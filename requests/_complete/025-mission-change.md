## 1. 화면 전체 구조 분석

### 배경

화면 전체는 위쪽의 연한 하늘색에서 아래쪽의 따뜻한 아이보리색으로 이어지는 세로 그라데이션입니다.

* 상단: `#D5ECFF` 계열
* 중앙: `#F4F7F5` 계열
* 하단: `#FFF5E8` 계열
* 화면 가장자리에 구름, 별, 작은 종이 조각 형태의 장식 배치
* 장식은 기능 요소보다 뒤에 위치하고 터치 이벤트를 받지 않음
* 장식 투명도는 낮게 적용하여 텍스트 가독성을 방해하지 않음

실제 구현에서는 무거운 애니메이션이나 Canvas를 사용하지 않고 CSS 및 기존 SVG 자산을 사용해야 합니다.

## 2. 상단 종료 버튼

오른쪽 상단에 단독으로 `X` 버튼이 배치되어 있습니다.

* 크기: 시각적으로 약 24px
* 실제 터치 영역: 최소 44×44px
* 색상: K-Navy 또는 짙은 회색
* 배경: 투명
* 우측·상단 safe area 반영
* 진행 중 종료 시 현재 세션 저장·이어하기 정책을 그대로 적용
* 단순히 화면만 닫고 미션 상태를 초기화하면 안 됨
* 연속 클릭 방지를 적용

스마트폰 프레임에 있는 버튼처럼 보이지만 앱 화면에 포함되는 실제 종료 컨트롤입니다.

## 3. 10단계 별 진행률

종료 버튼 아래에는 흰색 캡슐형 진행률 영역이 있습니다.

### 시각 구성

* 화면 너비의 약 88~92%
* 높이 약 40~44px
* 흰색 배경
* 완전한 pill 형태
* 부드러운 외곽 그림자
* 별 10개를 동일 간격으로 배치
* 완료된 별: 주황색
* 미완료 별: 연한 하늘색
* 완료된 별에는 약한 노란색 광택 또는 외곽 강조
* 레퍼런스 화면은 10개 중 4개 완료 상태

### 데이터 연결

별은 질문 번호가 아니라 **유효 답변 완료 수**를 나타내야 합니다.

* 유효 답변 0개: 주황색 별 0개
* 유효 답변 4개: 주황색 별 4개
* 유효 답변 10개: 모두 주황색
* 짧더라도 질문과 관련 있는 유효 답변은 기존 정책대로 진행률 10% 증가
* 무음·소음·무관 답변·처리 실패는 별을 증가시키지 않음
* 서버 또는 현재 미션 상태에서 유효 답변 저장이 확인된 후 별을 채움
* 화면에서 먼저 별을 채우는 낙관적 업데이트는 사용하지 않음
* 완료 시 기존 미션 완료·보상 플로우로 연결

별이 채워질 때 150~200ms 정도의 가벼운 확대 효과를 사용할 수 있지만 과도한 반짝임은 금지합니다.

## 4. 직전 대화 요약 영역

진행률 아래에는 직전 대화가 작게 나타납니다. 이 영역은 전체 채팅 기록을 보여주는 채팅창이 아닙니다.

### 표시 순서

1. 직전 아이 발화
2. 직전 케이 응답
3. 현재 케이 질문은 별도의 큰 주황색 테두리 말풍선에 표시

### 직전 아이 발화

* 작은 회색 텍스트
* 가운데 정렬
* 최대 2줄
* 현재 질문보다 시각적 우선순위가 낮아야 함
* 너무 길면 말줄임 또는 내부 스크롤이 아니라 2줄 요약 표시
* 사용자 자막은 기존 한국어 우선 정책 유지

### 직전 케이 응답

* 흰색 또는 반투명 흰색의 작은 둥근 말풍선
* 글자 크기 약 12~13px
* 일반 굵기
* 최대 3~4줄
* 그림자는 매우 약하게 적용
* 직전 응답이 없으면 빈 말풍선을 만들지 않음

### 스크롤 정책

* 전체 페이지는 스크롤되지 않음
* 과거 대화가 많아져도 이 영역의 높이는 증가하지 않음
* 최신 직전 발화와 응답만 표시
* 전체 대화 원문은 기존 저장 구조를 유지하되 이 화면에서는 노출하지 않음

## 5. 현재 케이 질문 말풍선

이 화면에서 가장 중요한 정보입니다.

### 시각 구성

* 흰색 배경
* K-Orange 테두리 2~3px
* 모서리 반경 약 18~22px
* 화면 너비의 약 82~86%
* 중앙 정렬
* 좌우 내부 여백 약 18px
* 상하 내부 여백 약 14~16px
* 아래 중앙에 케이를 향하는 삼각형 꼬리
* 약한 주황색 그림자
* 본문은 짙은 갈색 또는 거의 검은색
* 글자 크기 최소 16px
* 굵기 600~700
* 줄 간격 약 1.35~1.45
* 텍스트는 왼쪽 정렬

### 데이터와 동작

* 하드코딩 문구 금지
* 현재 미션의 실제 케이 질문을 표시
* 케이가 음성으로 질문하는 동안에도 동일한 문장을 표시
* 다음 질문으로 넘어갈 때 말풍선 내용만 자연스럽게 교체
* 한두 줄 질문이라도 말풍선 최소 높이를 유지
* 긴 질문은 최대 높이를 설정하고 말풍선 내부만 세로 스크롤
* 글자를 무리하게 축소하여 맞추지 않음
* 질문이 교체될 때 레이아웃이 크게 흔들리지 않도록 높이 변화 제한

현재 질문과 직전 케이 응답을 동일한 영역에 중복 출력하면 안 됩니다.

## 6. 케이 마스코트 영역

현재 질문 말풍선 아래 중앙에 케이 마스코트를 크게 배치합니다.

### 구성

* 프로젝트에 등록된 실제 3D 케이 마스코트 사용
* 레퍼런스의 주황색 알파벳 캐릭터는 사용하지 않음
* 마스코트 뒤에 연한 하늘색 원형 halo 배치
* 마스코트 아래에는 아이보리색 타원형 3D 단상 배치
* 단상은 위쪽 타원과 낮은 원통 옆면으로 구성
* 마스코트가 단상 위에 서 있는 것처럼 그림자 적용
* 마스코트 중심은 화면 수평 중앙
* 작은 화면에서는 마스코트 크기를 줄이되 잘라내지 않음
* 마스코트와 현재 질문 말풍선 꼬리가 시각적으로 연결되어야 함

### 상태 애니메이션

* 듣는 중: 마스코트 주변 또는 마이크 링을 천천히 펄스
* 생각 중: 상태 카드의 점 3개가 순차 애니메이션
* 말하는 중: 기존 립싱크 또는 말하기 애니메이션이 있으면 유지
* 연결 중: 과도한 반복 애니메이션 없이 약한 호흡 효과
* `prefers-reduced-motion`에서는 반복 애니메이션 최소화

마스코트 애니메이션 때문에 질문 말풍선이나 하단 버튼 위치가 움직이면 안 됩니다.

## 7. 마스코트 좌우 보조 영역

### 왼쪽: 소리 켜기·끄기

마스코트 왼쪽에 반투명한 연한 하늘색 카드가 있습니다.

* 음소거 아이콘을 원형 배경 안에 표시
* 아래에 `소리 꺼짐` 또는 `소리 켜짐`
* 버튼 전체 터치 가능
* 케이의 출력 음성만 켜고 끔
* 아이 마이크 권한이나 입력 녹음 상태와 혼동하지 않음
* 음소거 상태에서도 텍스트 질문은 정상 표시
* 상태를 아이콘·텍스트 모두로 표시
* 새로고침 또는 세션 복원 시 기존 음소거 정책에 맞게 복원

### 오른쪽: 현재 대화 상태

마스코트 오른쪽에는 현재 음성 상태를 표시하는 카드가 있습니다.

상태별 표시:

* 아이 발화를 기다리는 중: `듣는 중`
* 케이 답변 생성 또는 턴 전환 중: `생각 중`
* 케이 음성 출력 중: `말하는 중`
* 최초 WebSocket 연결 중: `연결 중`
* 재연결 중: `다시 연결 중`
* 복구할 수 없는 오류: `연결 오류`

아이콘도 상태에 맞춰 변경합니다.

* 듣는 중: 음성 파형 또는 귀
* 생각 중: 점 3개
* 말하는 중: 말풍선 또는 스피커
* 연결 중: 작은 로딩 표시
* 오류: 경고 아이콘

이 카드는 기본적으로 상태 표시용이며 일반 버튼처럼 보이지 않게 합니다. 오류 상태에서만 기존 재연결 동작이 있을 경우 터치 가능한 복구 버튼으로 변경합니다.

## 8. 자동·수동 모드 선택

마스코트 단상 앞쪽, 마이크 버튼 바로 위에 `자동`과 `수동` 버튼이 말풍선 모양으로 배치되어 있습니다.

### 시각 구성

* 두 버튼을 나란히 배치
* 선택 상태: 연한 주황색 배경 + 주황색 테두리
* 비선택 상태: 흰색 배경 + 연한 테두리
* 각 버튼 아래쪽에 작은 말풍선 꼬리
* 최소 터치 높이 40~44px
* 선택 상태를 색상 외에도 테두리·굵기·`aria-pressed`로 구분

### 동작

* 현재 앱에 구현된 자동·수동 입력 의미를 그대로 유지
* 디자인 변경 과정에서 기존 VAD, barge-in, 마이크 시작·종료 로직을 재정의하지 않음
* 모드 변경 중 중복 오디오 스트림을 생성하지 않음
* 케이가 말하는 중 모드가 변경되더라도 세션이 끊기지 않음
* 선택값은 현재 세션 상태와 항상 일치
* UI에만 선택 표시가 바뀌고 실제 오디오 모드가 바뀌지 않는 상태가 발생하면 안 됨

## 9. 중앙 마이크 버튼

최하단 중앙에는 화면에서 가장 큰 주황색 원형 마이크 버튼이 있습니다.

### 시각 구성

* 버튼 본체 약 64~72px
* 외부 원형 링 2~3겹
* 중앙: 진한 주황색 또는 그라데이션
* 아이콘: 흰색 마이크
* 바깥쪽: 연한 주황색 링과 그림자
* 최소 터치 영역 72×72px
* 활성·비활성·눌림·권한 오류 상태를 구분

### 상태 표현

* 듣는 중: 바깥 링이 천천히 확장·축소
* 마이크 일시 중지: 아이콘에 슬래시 또는 비활성 표현
* 생각 중: 중복 제출 방지를 위해 현재 입력 정책에 맞게 제어
* 말하는 중: 자동 모드에서는 barge-in 정책을 유지
* 권한 없음: 클릭 시 기존 마이크 권한 안내 표시
* 연결 오류: 무반응 버튼으로 남기지 말고 현재 오류 상태 안내

마이크 버튼을 눌렀을 때 진행률이 직접 증가하거나 질문이 임의로 넘어가면 안 됩니다.

## 10. 키보드 입력 버튼

왼쪽 아래에는 작은 키보드 아이콘 버튼이 있습니다.

* 흰색 또는 반투명 흰색 배경
* 검은색 또는 K-Navy 키보드 아이콘
* 시각 크기 약 38×30px
* 실제 터치 영역 최소 44×44px
* 접근성 레이블 `텍스트로 답하기`
* 누르면 기존 텍스트 입력 UI를 표시
* 텍스트 입력으로 전환해도 미션 세션과 진행률 유지
* 입력 후 동일한 유효 답변 판정 파이프라인 사용
* 키보드가 열린 동안 마스코트는 축소 가능
* 현재 질문 말풍선과 입력창은 반드시 보이게 유지
* 모바일 키보드가 마이크·전송 버튼을 가리지 않도록 `visualViewport` 또는 적절한 safe-area 처리

## 11. 고정 레이아웃과 반응형 기준

전체 화면은 `100dvh`를 기준으로 구성하고 문서 전체 스크롤을 막습니다.

### 세로 배치 우선순위

공간이 부족할 때 다음 순서로 축소합니다.

1. 장식 요소 축소 또는 숨김
2. 직전 대화 영역 높이 축소
3. 마스코트 크기 축소
4. 단상 높이 축소

다음 요소는 숨기면 안 됩니다.

* 종료 버튼
* 진행률
* 현재 질문
* 현재 음성 상태
* 자동·수동 모드
* 마이크 또는 텍스트 입력 수단

### 화면별 기준

* 320×568 수준의 작은 화면에서도 버튼 겹침 금지
* 360×800, 390×844, 430×932 모바일 검증
* 태블릿·PC에서는 무작정 전체 폭으로 늘리지 않고 모바일형 대화 화면을 중앙에 배치
* 콘텐츠 최대 너비 약 430~480px
* 가로 모드에서는 장식과 마스코트를 축소하되 기능은 유지
* iOS 상·하단 safe area와 Android 내비게이션 영역 모두 반영
