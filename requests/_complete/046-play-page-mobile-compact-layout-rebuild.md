# 046 — 케이와 놀이 실제 모바일 화면 소형 2열 레이아웃 전면 재교정

## 1. 작업 목적

현재 실제 모바일 PWA의 `케이와 놀이` 화면이 첨부된 첫 번째 이미지처럼 표시되고 있다.

현재 구현은 다음 문제가 있다.

- 상단 헤더와 열쇠 영역이 지나치게 큼
- 활성 놀이 카드가 높고 내부 빈 공간이 많음
- `시작할 수 있어요` 배지가 아이콘 및 카드 내용을 가림
- 카드가 필요한 정보에 비해 지나치게 큰 영역을 차지함
- 준비 중 카드도 불필요하게 큼
- `곧 만나요` 이후 하단 케이 안내 영역 사이에 매우 큰 공백이 생김
- 케이 마스코트가 화면 아래에서 잘림
- 미션 안내 말풍선과 CTA가 화면 최하단으로 밀림
- 실제 모바일에서 주요 콘텐츠를 한눈에 확인하기 어려움
- 390px 전후의 모바일 화면을 효율적으로 사용하지 못함

두 번째 첨부 이미지를 실제 모바일 PWA의 최종 기준 화면으로 사용하여 전체 레이아웃을 재교정한다.

이번 작업의 핵심은 단순한 전체 축소가 아니다.

다음 정보 구조를 모바일에 맞게 다시 배치한다.

```text
상단 헤더
열쇠 보유·더 모으기
활성 놀이 2열
준비 중 놀이 2열
케이 마스코트·안내 말풍선·미션 CTA
```

---

## 2. 최종 기준

이번 작업의 절대 기준은 다음 순서다.

```text
실제 모바일 설치형 PWA
>
실제 모바일 브라우저
>
태블릿
>
PC 스마트폰 프레임 미리보기
```

PC 프레임에서만 두 번째 이미지처럼 보이고 실제 모바일에서는 첫 번째 이미지처럼 보이는 상태를 완료로 인정하지 않는다.

두 번째 첨부 이미지의 **프레임 내부 앱 콘텐츠**를 실제 모바일 PWA에서 그대로 구현한다.

실제 모바일에 스마트폰 외곽 목업 프레임을 추가하지 않는다.

## 3. 현재 화면과 목표 화면의 상세 차이

### 3-1. 전체 정보 밀도

현재 화면:

- 카드와 섹션이 화면 높이를 과도하게 사용
- 한 화면에서 열쇠·놀이·준비 중·미션 CTA를 함께 보기 어려움
- 화면 하단에 큰 빈 공간이 존재
- 콘텐츠가 화면 전체에 균등하게 배치되지 않음

목표 화면:

- 각 영역의 높이와 간격을 축소
- 390×844 전후에서 주요 놀이와 하단 미션 CTA가 한 화면 또는 최소 스크롤 안에 표시
- 불필요한 빈 공간 제거
- 각 섹션을 연속된 하나의 콘텐츠 흐름으로 구성

---

### 3-2. 상단 헤더

현재 화면:

- 헤더 높이가 큼
- 뒤로가기, 제목, 로그아웃 버튼 주위 여백이 과도함

목표 화면:

- 두 번째 이미지처럼 높이를 줄인 소형 헤더
- 뒤로가기 왼쪽
- `케이와 놀이` 가운데
- 로그아웃 아이콘 오른쪽
- 모든 요소 세로 중앙 정렬
- 상하 여백 최소화

권장 높이:

```text
56px~64px
```

모바일 Safe Area는 별도로 반영한다.

---

### 3-3. 열쇠 보유 카드

현재 화면:

- 높이가 약 150px 이상으로 과도함
- 열쇠 수량과 더 모으기 버튼 사이 공간이 큼
- 화면 첫 부분을 지나치게 많이 차지함

목표 화면:

```text
[🔑 열쇠 12개]                  [더 모으기 →]
```

한 줄형 소형 카드로 변경한다.

권장:

```text
높이: 62px~76px
좌우 여백: 12px
내부 좌우 padding: 14px~16px
아이콘: 22px~28px
수량 글자: 16px~19px
더 모으기 버튼: 40px~46px
카드 radius: 14px~18px
```

유지:

- 실제 황금열쇠 보유 수량
- 더 모으기 버튼
- 미션 화면 이동
- 데이터 갱신

```text
margin-bottom: 8px~10px
```

`열쇠로 열어요`와 열쇠 카드 사이에 과도한 빈 공간을 두지 않는다.

대상:

- 오늘의 나

권장 Grid:

```css

  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));

```

### 1열 전환 허용 조건

다음 경우에만 1열 전환을 허용한다.

- CSS Viewport 300px 미만
- 운영체제 글꼴 200% 확대에서 카드 내용이 실제로 겹치는 경우

360px, 375px, 390px, 393px, 412px, 414px, 430px에서는 2열이 기본이다.

## 6. 활성 놀이 카드 크기

현재 화면:

- 카드 높이가 약 250px 이상
- 아이콘, 배지, 제목 사이에 큰 빈 공간
- 모바일 카드로는 지나치게 큼

목표 화면:

- 두 번째 이미지처럼 작고 정보가 밀집된 카드
- 카드 안에서 아이콘·필요 열쇠·제목·설명을 모두 빠르게 확인

권장:

```text
높이: 112px~132px
최소 높이: 112px
최대 높이: 138px
padding: 10px~12px
radius: 16px~18px
```

카드 높이를 콘텐츠에 따라 무제한 늘리지 않는다.

좌우 카드 높이는 동일하게 유지한다.

## 8. 아이콘 영역

현재 화면:

- 아이콘 컨테이너가 큼
- 배지와 겹침
- 카드 높이를 불필요하게 증가시킴

목표:

```text
아이콘 컨테이너: 40px~48px
실제 아이콘: 26px~34px
radius: 10px~14px
```

아이콘 영역은 카드 왼쪽 상단에 배치한다.

정본 아이콘 또는 현재 사용 중인 자산을 유지한다.

---

## 9. 열쇠 필요 배지

현재 화면의 다음 문구를 제거한다.

```text
🔒 시작할 수 있어요
```

현재 실제 열쇠가 충분한지 여부와 무관하게, 카드에는 놀이 시작에 필요한 비용을 명확히 표시한다.

퀴즈마스터:

```text
🔑 2개 필요
```

오늘의 나:

```text
🔑 3개 필요
```

권장:

```text
font-size: 11px~13px
font-weight: 700
padding: 5px 8px
한 줄 유지
pill 형태
```

배지는 카드 우측 상단에 위치하되 다음을 만족해야 한다.

- 아이콘을 덮지 않음
- 제목을 덮지 않음
- 두 줄로 깨지지 않음
- 카드 밖으로 나가지 않음

### 카드 잠금 상태

아이의 열쇠가 부족한 경우에도 같은 위치에 다음 상태를 짧게 표시할 수 있다.

```text
🔒 2개 필요
```

또는 현재 확정된 잠금 문구 정책을 따른다.

`시작할 수 있어요`처럼 카드의 큰 영역을 차지하는 상태 배지는 사용하지 않는다.

## 13. 섹션 간 간격

현재 화면은 다음 영역의 간격이 과도하다.

- 열쇠 카드 → `열쇠로 열어요`
- 활성 놀이 → `곧 만나요`
- 준비 중 카드 → 하단 케이 CTA

목표 간격:

| 구간 | 권장 간격 |
|---|---:|
| 헤더 → 열쇠 카드 | 12~16px |
| 열쇠 카드 → 섹션 제목 | 14~18px |
| 제목 → 활성 카드 | 8~10px |
| 활성 카드 → `곧 만나요` | 16~20px |
| `곧 만나요` → 준비 중 카드 | 8~10px |
| 준비 중 카드 → 케이 CTA | 24~40px |

현재 화면처럼 준비 중 카드와 케이 CTA 사이에 수백 px의 빈 공간이 생기면 안 된다.

## 14. 하단 케이 CTA 영역

현재 화면:

- 마스코트가 화면 최하단에 과도하게 크게 배치됨
- 마스코트 하단이 잘림
- 말풍선과 미션 버튼이 화면 끝에 붙음
- 준비 중 카드와 CTA 사이에 큰 공백 존재
- 마스코트와 CTA가 하나의 그룹처럼 보이지 않음

목표 화면:

```text
[케이 마스코트]  [미션 하면 열쇠를 줄게!]
                  [미션하러 가기 →]
```

하단 영역 전체를 하나의 Grid 또는 Flex 그룹으로 구성한다.

권장:

```css
.play-mission-cta {
  display: grid;
  grid-template-columns: minmax(90px, 0.8fr) minmax(150px, 1.2fr);
  align-items: end;
  gap: 12px;
}
```

## 15. 케이 마스코트

현재:

- 약 250px 이상으로 과도하게 큼
- 화면 밖으로 일부 잘림

목표:

```text
너비: 90px~120px
높이: auto
전체 몸이 보이도록 표시
```

권장:

```css
width: clamp(90px, 28vw, 120px);
object-fit: contain;
```

금지:

- 화면 아래에서 Crop
- 비율 왜곡
- `position: fixed`로 화면 바닥에 붙이기
- 카드 영역과 무관한 절대좌표 사용

## 16. 미션 안내 말풍선

문구:

```text
미션 하면 열쇠를 줄게!
```

권장:

```text
높이: 42px~48px
font-size: 12px~14px
font-weight: 700
K-Orange 테두리
흰색 배경
```

말풍선은 마스코트 오른쪽 상단에 배치한다.

버튼과 동일한 너비 계열을 사용해 정렬한다.

문의 버튼이 말풍선을 가리지 않게 한다.

## 17. 미션하러 가기 버튼

문구:

```text
미션하러 가기 →
```

권장:

```text
높이: 44px~50px
font-size: 14px~16px
K-Orange 배경
흰색 텍스트
radius: 14px~18px
```

기존 미션 화면 이동 기능을 유지한다.

미션 진행 중인 경우 기존 정책에 따라 시작 또는 이어하기 화면으로 연결한다.

---

## 18. 전체 콘텐츠 컨테이너

실제 모바일에서 다음 공통 컨테이너를 사용한다.

```css
.play-page-content {
  width: 100%;
  max-width: 430px;
  margin-inline: auto;
  padding-inline: 12px;
  box-sizing: border-box;
}
```

작은 화면에서는 좌우 padding을 `10px`까지 줄일 수 있다.

PC Device Frame 내부에서도 같은 콘텐츠 컴포넌트와 같은 CSS를 사용한다.

Device Frame 전용 CSS가 카드 크기와 Grid를 변경하지 않게 한다.

## 19. 화면 높이와 스크롤

목표:

- 390×844 전후에서 전체 콘텐츠가 한 화면 또는 최소 스크롤로 표시
- 열쇠·놀이·준비 중·미션 CTA를 자연스럽게 연결
- Body와 내부 콘텐츠의 이중 스크롤 금지
- 가로 스크롤 금지
- 하단 Safe Area 반영

콘텐츠가 화면보다 길 경우 자연스러운 세로 스크롤은 허용한다.

단, 큰 빈 공간 때문에 스크롤이 발생하면 실패다.

## 20. 반응형 기준

### 320×568

- 활성 놀이 2열 유지
- 카드 내부 글자와 아이콘이 겹치지 않게 최소값 적용

### 360×800

- 두 번째 이미지와 유사한 정보 밀도
- 활성·준비 중 모두 2열
- 하단 CTA 노출

### 390×844

- 두 번째 이미지의 기본 기준
- 한 화면 또는 매우 짧은 스크롤 안에 전체 흐름 표시

## 22. PWA 최신 빌드 확인

필수 확인:

```text
App Build ID
Active Service Worker Version
Waiting Service Worker Version
CSS Chunk Hash
```

QA 절차:

1. 기존 Build A 모바일 PWA 실행
2. 수정 Build B 배포
3. PWA 삭제 금지
4. 사이트 데이터 수동 삭제 금지
5. 새 버전 안내 표시
6. 새로고침 적용
7. Build B 적용 확인
8. 두 번째 이미지 기준 UI 확인

PWA 삭제·재설치를 해야만 UI가 바뀌면 실패다.

## 23. 문의 버튼

문의 버튼은 실제 모바일에서 다음을 가리지 않아야 한다.

- 로그아웃 버튼
- 활성 놀이 카드
- 열쇠 필요 배지
- 케이 안내 말풍선
- 미션하러 가기 버튼

기존 저장 좌표가 새 레이아웃과 맞지 않으면 `layoutVersion`을 갱신하고 기본 위치로 재설정한다.

현재 Viewport와 Safe Area 안으로 좌표를 Clamp한다.

문의 기능과 드래그 기능은 유지한다.

## 25. 금지 사항

- 첫 번째 화면 전체를 단순 `transform: scale()`로 축소
- 실제 모바일에 스마트폰 목업 프레임 추가
- PC 프레임 전용 별도 UI 유지
- 활성 놀이를 일반 모바일에서 1열로 변경
- 카드 높이를 고정 200px 이상으로 유지
- `시작할 수 있어요` 큰 배지를 그대로 유지
- 아이콘과 배지가 겹치는 구조
- 준비 중 카드와 하단 CTA 사이의 큰 Spacer 유지
- 마스코트를 화면 하단에서 잘라 표시
- 모바일 실기기 확인 없이 완료
- PWA 삭제·재설치 후에만 QA
- 기능 로직과 DB를 불필요하게 변경

## 28. 완료 기준

다음 조건을 모두 만족해야 완료로 판정한다.

- 실제 모바일 PWA가 두 번째 이미지의 정보 구조로 표시됨
- 헤더가 소형으로 정리됨
- 열쇠 카드가 한 줄형 소형 카드로 변경됨
- 활성 놀이가 2열 소형 카드로 표시됨
- 활성 카드 높이가 약 112px~138px 범위임
- `시작할 수 있어요` 대형 배지가 제거됨
- 각 카드 우측 상단에 열쇠 필요 수량이 표시됨
- 퀴즈마스터 설명이 최대 2줄로 표시됨
- 오늘의 나 설명이 최대 2줄로 표시됨
- 준비 중 놀이가 2열 소형 카드로 표시됨
- 준비 중 카드가 클릭되지 않음
- 준비 중 카드와 하단 CTA 사이의 큰 빈 공간이 제거됨
- 마스코트 전체 모습이 표시됨
- 마스코트가 화면 아래에서 잘리지 않음
- 말풍선과 미션 버튼이 하나의 CTA 그룹으로 표시됨
- 390×844에서 전체 흐름이 한 화면 또는 최소 스크롤로 표시됨
- 문의 버튼이 주요 콘텐츠를 가리지 않음
- 모바일 PWA 삭제·재설치 없이 최신 UI가 적용됨
- iOS PWA QA 통과
- Android PWA QA 통과
- 기존 열쇠·놀이·미션 기능에 회귀가 없음
- lint 통과
- typecheck 통과
- 관련 test 통과
