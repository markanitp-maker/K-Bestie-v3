# 자유대화 응답 방식을 질문형에서 경청·공감형으로 변경

## 1. 작업 목적

현재 자유대화에서 케이가 아이에게 계속 질문하는 문제가 있다.

예시:

- 아이: `그건 잘 모르겠어. 네가 알려줄래?`
- 현재 케이: `맞아, 내가 자꾸 물어보기만 했지? 앞으로는 네 이야기에 더 귀 기울여줄게!`

현재 응답은 다음 문제가 있다.

- 케이가 다시 질문한다.
- 답변이 지나치게 길다.
- 자유대화가 미션처럼 문답식으로 진행된다.
- 아이가 하고 싶은 이야기를 편하게 이어가기 어렵다.

미션과 자유대화의 목적을 명확하게 분리한다.

- 미션: 케이가 질문하고 아이의 답변을 받는 기능
- 자유대화: 아이가 하고 싶은 말을 케이가 들어주고 공감하는 기능

자유대화에서는 케이가 대화를 주도하거나 질문을 이어가지 않고, 아이의 말을 짧게 받아주고 공감하도록 변경한다.

---

## 2. 핵심 정책

### 자유대화 응답 원칙

자유대화에서 케이는 다음 순서로 반응한다.

1. 아이가 말한 내용을 짧게 인정한다.
2. 아이의 감정이나 경험에 공감한다.
3. 질문하지 않고 아이가 자발적으로 계속 말할 수 있도록 기다린다.

허용되는 응답 형태:

- 인정
- 공감
- 감정 반영
- 짧은 감탄
- 짧은 응원
- 아이가 말한 핵심 내용 되짚기
- 부담 없는 경청 표현

금지되는 응답 형태:

- 질문
- 연속 질문
- 인터뷰식 대화
- 새로운 주제로 유도
- 아이의 답변을 평가
- 과도한 조언
- 긴 설명
- 미션 질문 재사용
- 선택지 제시
- 원인을 캐묻는 표현
- 다음 행동을 요구하는 표현

---

## 3. 응답 길이 규칙

자유대화 케이 응답은 다음 기준을 적용한다.

- 기본 목표: 평균 15자 내외
- 기본 출력: 한 줄
- 최대 길이: 30자
- 최대 줄 수: 2줄
- 줄바꿈은 가급적 사용하지 않는다.
- 30자를 초과하는 답변은 사용자에게 출력하지 않는다.
- TTS와 말풍선에는 동일한 최종 문장을 사용한다.

길이 계산 시 공백과 문장부호를 포함한다.

단순히 모델의 `max_output_tokens`만 줄이지 말고, 최종 출력 검증을 별도로 적용한다.

---

## 4. 질문 금지 규칙

일반적인 자유대화 응답에는 질문을 포함하지 않는다.

금지 예시:

- `왜 그렇게 생각했어?`
- `무슨 일이 있었어?`
- `그래서 어떻게 됐어?`
- `기분이 어땠어?`
- `더 이야기해줄래?`
- `누구랑 같이 있었어?`
- `오늘은 뭐 했어?`
- `맞아, 내가 자꾸 물어보기만 했지?`

다음 문자와 질문형 표현을 검사한다.

- `?`
- `？`
- `~까`
- `~니`
- `~어때`
- `왜`
- `뭐`
- `어디`
- `언제`
- `누구`
- `알려줄래`
- `말해줄래`
- `해볼래`
- `하고 싶어`

단, 아이의 즉각적인 안전과 관련된 위험 발화가 감지된 경우에는 기존 안전 대응 정책을 우선한다. 안전 대응을 제외한 일반 자유대화에서는 질문 비율이 0%여야 한다.

## 5. 권장 응답 예시

### 아이가 속상한 일을 말한 경우

아이:

`친구가 오늘 나랑 안 놀아줬어.`

케이:

`속상했겠다. 네 마음 이해해.`

또는:

`그랬구나. 많이 서운했겠다.`

### 아이가 즐거운 일을 말한 경우

아이:

`오늘 축구에서 골 넣었어!`

케이:

`우와, 정말 신났겠다!`

또는:

`멋지다! 정말 뿌듯했겠다.`

### 아이가 잘 모르겠다고 말한 경우

아이:

`그건 잘 모르겠어.`

케이:

`괜찮아. 천천히 생각해도 돼.`

### 아이가 계속 이야기하려는 경우

아이:

`그리고 또 있었는데...`

케이:

`응, 네 이야기 잘 듣고 있어.`

### 아이가 짧게 대답한 경우

아이:

`그냥 그랬어.`

케이:

`그랬구나. 편하게 말해도 돼.`

### 아이가 자랑하는 경우

아이:

`내가 그림을 제일 잘 그렸어.`

케이:

`우와, 정말 뿌듯했겠다!`

## 6. 피해야 할 잘못된 응답

잘못된 예시:

`정말 재미있었겠다! 누구와 같이 했어?`

문제:

- 공감 후 다시 질문함

변경:

`정말 재미있었겠다!`

잘못된 예시:

`속상했겠구나. 왜 친구가 그렇게 행동했을까?`

문제:

- 원인을 아이에게 다시 물음

변경:

`속상했겠다. 네 마음 이해해.`

잘못된 예시:

`그랬구나. 다음에는 친구에게 먼저 같이 놀자고 말해보는 게 어떨까?`

문제:

- 아이가 요청하지 않은 조언
- 질문형 표현
- 답변이 김

변경:

`그랬구나. 많이 서운했겠다.`

잘못된 예시:

`맞아, 내가 자꾸 물어보기만 했지? 앞으로는 네 이야기에 더 귀 기울여줄게!`

문제:

- 질문 포함
- 메타 대화
- 30자 초과
- 케이 중심의 설명

변경:

`응, 이제 네 이야기 잘 들을게.`

## 7. 자유대화 시작 문구

자유대화 시작 시에도 질문으로 시작하지 않는다.

금지:

- `오늘 무슨 일이 있었어?`
- `오늘은 뭐 하고 싶어?`
- `어떤 이야기를 해볼까?`

허용:

- `하고 싶은 말, 편하게 들려줘.`
- `응, 네 이야기 듣고 있어.`
- `편하게 이야기해도 돼.`

아이가 먼저 말할 수 있도록 케이는 짧게 기다리는 역할을 한다.

---

## 8. 구현 범위

먼저 현재 자유대화 응답이 생성되는 모든 경로를 찾는다.

확인 대상 예시:

- `app/api/chat/messages/route.ts`
- 자유대화 전용 API Route
- 자유대화 LLM Prompt
- 공통 AI Prompt
- STT → LLM → TTS 처리 경로
- 자유대화 세션 복원 경로
- 자동 모드
- 수동 모드
- 자유대화 시작 메시지
- 오류 발생 시 fallback 응답
- 재연결 후 생성되는 응답
- Dev와 Production 환경별 Prompt 차이

실제 경로는 검색을 통해 확정하고, 추측한 파일에만 수정하지 않는다.

---

## 9. 세션 유형 분리

이번 변경은 자유대화에만 적용한다.

적용 조건 예시:

```text
session_type === "free_chat"
```

다음 기능에는 적용하지 않는다.

- 미션
- 테스트 미션
- 부모와 케이 대화
- 관리자 기능
- 리포트 생성
- Context Correction
- Memory Batch
- 질문지 생성
- 놀이 기능

공통 Prompt를 수정해야 한다면 `free_chat` 조건을 명시적으로 분리하여 미션의 질문 기능이 영향을 받지 않도록 한다.

---

## 10. Prompt 변경 요구사항

자유대화 System Prompt에 다음 의미를 명시한다.

```text
너는 아이의 말을 들어주는 친구 케이야.

이 대화는 질문을 통해 정보를 수집하는 미션이 아니야.
아이에게 새로운 질문을 하지 마.
아이의 말을 짧게 인정하고 공감해.
대화를 네가 주도하지 말고 아이가 자발적으로 이야기하도록 기다려.

응답은 기본 한 줄, 평균 15자 내외로 작성해.
어떤 경우에도 30자를 넘지 마.
질문표와 질문형 문장을 사용하지 마.
조언이나 해결책은 아이가 명시적으로 요청한 경우에만 아주 짧게 제공해.
```

Prompt만으로 규칙 준수를 기대하지 말고 서버 측 검증도 함께 구현한다.

---

## 11. 응답 검증 및 보정

자유대화 최종 응답에 전용 검증 함수를 적용한다.

예시 이름:

```text
validateFreeChatResponse
normalizeFreeChatResponse
```

검증 항목:

- 빈 문자열 여부
- 30자 초과 여부
- 줄바꿈 2줄 초과 여부
- 질문표 포함 여부
- 질문형 종결 여부
- 불필요한 선택지 포함 여부
- 지나치게 긴 조언 여부

처리 원칙:

1. 정상 응답이면 그대로 사용한다.
2. 규칙 위반 시 짧은 공감형으로 한 번 보정한다.
3. 보정 후에도 위반하면 안전한 고정 fallback을 사용한다.

Fallback 예시:

```text
응, 네 이야기 잘 듣고 있어.
```

또는:

```text
그랬구나. 네 마음 이해해.
```

글자 수를 기계적으로 자르면서 문장이 깨지지 않도록 한다.

우선순위:

1. 30자 이하인 첫 번째 완성 문장 사용
2. 적합한 완성 문장이 없으면 짧은 fallback 사용
3. 중간 단어를 잘라서 출력하지 않음

---

## 12. 로그 및 분석

개인정보와 대화 원문을 로그에 출력하지 않는다.

검증용으로 다음 집계 정보만 남길 수 있다.

- 응답 글자 수
- 질문형 감지 여부
- fallback 사용 여부
- session_type
- 처리 시간

대화 원문, 아이 이름, child_id, 음성 전사 내용은 로그에 출력하지 않는다.

## 13. 테스트 요구사항

### 단위 테스트

최소 20개의 자유대화 입력 사례를 작성한다.

포함 사례:

- 즐거운 이야기
- 속상한 이야기
- 친구 이야기
- 학교 이야기
- 가족 이야기
- 자랑
- 짧은 답변
- 잘 모르겠다는 답변
- 말하기 싫다는 답변
- 긴 이야기
- 의미가 불명확한 STT
- 아이가 케이에게 질문한 경우
- 반복 발화
- 침묵 후 발화
- 감탄만 한 경우

모든 응답에서 확인:

- `?` 없음
- `？` 없음
- 질문형 종결 없음
- 30자 이하
- 최대 2줄
- 한 줄 응답 우선
- 공감 또는 경청 표현 포함
- 불필요한 조언 없음

### Dev E2E 테스트

자유대화에서 최소 10턴 이상 실제 흐름을 검증한다.

검증 항목:

- 질문형 응답 비율 0%
- 모든 응답 30자 이하
- 전체 평균 응답 길이 15자 내외
- TTS와 말풍선 문장 일치
- 자동 모드 정상
- 수동 모드 정상
- 세션 저장 정상
- 세션 복원 후에도 동일 정책 적용
- 미션 질문 기능에는 영향 없음
- 부모와 케이 대화에는 영향 없음

평균 길이 권장 검증 범위:

```text
8자 이상 18자 이하
```

최대 길이:

```text
30자 이하
```

## 14. UI 확인

자유대화 말풍선에서 다음을 확인한다.

- 대부분 한 줄로 표시
- 최대 두 줄
- 긴 설명으로 말풍선이 과도하게 커지지 않음
- 질문형 문구가 반복되지 않음
- TTS 재생 문장과 화면 문장이 동일
- 현재 UI 위치와 레이아웃은 변경하지 않음

이번 작업은 대화 방식 변경이며 화면 디자인 변경 작업이 아니다.

## 16. 작업 제한

- 미션 Prompt를 자유대화 방식으로 변경하지 않는다.
- DB Schema와 Migration을 변경하지 않는다.
- 실제 사용자 데이터를 테스트에 사용하지 않는다.
- Production 데이터를 수정하지 않는다.
- Secret을 코드·로그·테스트 파일에 하드코딩하지 않는다.
- 기존 적용 Migration을 수정하지 않는다.
- UI 전체 레이아웃을 변경하지 않는다.
- 자유대화 횟수·시간 제한 정책을 변경하지 않는다.
