# 028 — 아이용 ‘케이와 놀이’ 화면 전면 개편

## 1. 작업 목적

현재 아이용 `케이와 놀이` 화면을 첨부 레퍼런스 이미지의 정보 구조와 디자인을 기준으로 전면 개편한다.

이번 개편의 핵심은 다음과 같다.

- 아이가 현재 보유한 황금열쇠 수를 화면 진입 즉시 확인할 수 있게 한다.
- 지금 사용할 수 있는 놀이와 준비 중인 놀이를 명확히 구분한다.
- 퀴즈마스터와 오늘의 나(MBTI)를 주요 놀이로 노출한다.
- 만화책 읽기와 헤어 꾸미기는 `준비 중` 상태로 표시하고 실행·차감을 차단한다.
- 황금열쇠가 부족한 경우 미션으로 자연스럽게 이동할 수 있게 한다.
- 기존 하단 Navigation은 다시 만들지 않는다.
- 우측 상단에는 아이 홈과 동일한 로그아웃 아이콘 버튼을 사용한다.
- 기존 황금열쇠 차감·이어하기·완료·환불·handoff 정책은 변경하지 않는다.

---

# 2. 레퍼런스 적용 범위

첨부 이미지에서 앱 내부 UI만 참고한다.

## 구현 대상

- 상단 뒤로가기 버튼
- 중앙 화면 제목 `케이와 놀이`
- 우측 상단 로그아웃 아이콘 버튼
- 황금열쇠 보유 현황 카드
- `더 모으기` 버튼
- `열쇠로 열어요` 놀이 목록
- 퀴즈마스터 카드
- 오늘의 나(MBTI) 카드
- `곧 만나요` 준비 중 놀이 목록
- 만화책 읽기 카드
- 헤어 꾸미기 카드
- 하단 케이 마스코트와 미션 유도 말풍선
- `미션하러 가기` 버튼

## 구현 제외

- 스마트폰 외곽 프레임
- 다이내믹 아일랜드
- 상태 표시줄
- 기기 측면 버튼
- iOS 홈 인디케이터
- 레퍼런스의 빨간색 `Logout` 텍스트 버튼

로그아웃은 기존 아이 홈에서 확정한 아이콘 전용 로그아웃 버튼을 재사용한다.

# 4. 전체 화면 레이아웃

## 기본 구조

- 모바일 우선
- 최소 높이 `100dvh`
- 화면 너비 `100%`
- 태블릿·PC에서는 최대 너비 약 `430px~480px`로 중앙 정렬
- 가로 스크롤 금지
- 기존 하단 메뉴 Navigation을 추가하지 않음
- iOS·Android safe-area 반영
- 콘텐츠가 짧아도 하단 마스코트 영역이 자연스럽게 화면 아래쪽에 배치되도록 구성
- 작은 화면에서는 정상적인 세로 스크롤 허용
- 하단 마스코트 영역을 무조건적인 fixed overlay로 만들어 카드 클릭을 가리지 않도록 한다.

## 배경

레퍼런스처럼 따뜻한 아이보리 계열을 기본으로 사용한다.

권장 토큰:

```css
background: var(--background-page);
```

Design System v2의 Warm Neutral 토큰이 존재하면 해당 토큰을 사용한다.

배경에 과도한 그라데이션이나 장식을 추가하지 않는다.

# 5. 상단 헤더

## 구성

왼쪽:

```text
← 뒤로
```

중앙:

```text
케이와 놀이
```

오른쪽:

```text
로그아웃 아이콘
```

## 헤더 디자인

- 높이 약 `52px~60px`
- 흰색 또는 반투명 흰색 배경
- 필요하면 약한 하단 구분선 적용
- 제목 K-Navy
- 제목 굵기 `700`
- 모바일에서 좌우 버튼과 제목이 겹치지 않도록 구성
- 제목은 실제 중앙에 위치해야 하며 좌우 버튼 너비 때문에 밀리지 않도록 한다.

# 6. 뒤로가기 버튼

## 동작

- 기본 이동 위치는 아이 홈
- 브라우저 history가 유효하고 기존 앱 정책상 안전한 경우 history back을 사용할 수 있음
- 외부 놀이 화면이나 인증 화면으로 잘못 이동하지 않도록 확인
- 직접 URL 접근 상태에서도 아이 홈으로 정상 이동할 수 있어야 함

## 디자인

- 왼쪽 화살표 아이콘
- 텍스트 `뒤로`
- K-Navy
- 최소 터치 영역 `44x44px`
- 접근성 이름 `아이 홈으로 돌아가기`

# 7. 로그아웃 버튼

기존 아이 홈에서 확정한 로그아웃 버튼 컴포넌트와 동작을 재사용한다.

## 디자인

- 텍스트 `Logout` 버튼 사용 금지
- 로그아웃 아이콘 전용 버튼
- 최소 터치 영역 `44x44px`
- K-Navy 아이콘
- 원형 또는 둥근 사각형의 반투명 흰색 배경
- 약한 그림자
- `aria-label="로그아웃"`

## 동작

버튼 클릭 시 즉시 로그아웃하지 않고 확인 다이얼로그를 표시한다.

```text
로그아웃할까요?
```

버튼:

```text
취소
로그아웃
```

확인 시:

1. 기존 인증 로그아웃 함수 실행
2. 기존 세션·쿠키 정리 로직 재사용
3. 로그인 화면으로 이동

금지:

- 새로운 로그아웃 API 구현
- Supabase 인증 로직 임의 변경
- 중복 클릭으로 여러 번 로그아웃 요청
- 설정 버튼 또는 설정 링크 재노출

# 8. 황금열쇠 보유 현황 카드

헤더 아래에 현재 아이의 황금열쇠 보유량을 표시한다.

## 표시 예시

```text
🔑 열쇠 1개
```

오른쪽:

```text
더 모으기 →
```

## 데이터 기준

- 실제 로그인한 아이의 황금열쇠 보유량 사용
- 하드코딩 금지
- 조회 실패 시 `0개`로 표시해 사용자를 오도하지 않음
- 로딩 상태와 오류 상태를 구분
- 보유량 변경 후 최신 값으로 갱신
- 다른 자녀의 보유량이 섞이지 않도록 child_id 기준 확인

## 숫자 표시

```text
열쇠 0개
열쇠 1개
열쇠 2개
```

한국어 표시를 자연스럽게 유지한다.

## 디자인

- 화면 좌우 약 `16px~20px` 여백
- 흰색 또는 따뜻한 아이보리 카드
- 둥근 radius
- 약한 주황색 또는 neutral shadow
- 왼쪽에 황금열쇠 아이콘
- 보유량 텍스트 K-Navy
- 오른쪽 `더 모으기` 버튼은 K-Orange 기반
- 버튼 터치 높이 최소 `44px`
- 숫자와 CTA가 작은 화면에서 겹치지 않도록 한다.

---

# 9. `더 모으기` 버튼

## 동작

- 아이 홈 또는 미션 시작 화면으로 이동
- 실제 이동 경로는 기존 미션 진입 정책을 재사용
- 진행 중인 미션이 있다면 기존 이어하기 정책을 유지
- 버튼 클릭만으로 황금열쇠를 추가하지 않음
- 새로운 미션 세션을 중복 생성하지 않음

## 접근성

```text
미션으로 이동해 황금열쇠 모으기
```

와 같이 목적이 명확한 접근성 이름을 적용한다.

# 11. 놀이 카드 공통 구조

각 놀이 카드는 다음 정보를 가진다.

- 놀이 이름
- 대표 이미지 또는 아이콘
- 잠금·이용 가능·이어하기 상태
- 필요한 황금열쇠 수
- 현재 보유 황금열쇠 또는 이용 조건
- 필요 시 진행 상태

## 카드 전체 동작

카드 전체를 터치 가능한 버튼으로 사용한다.

상태에 따라 다음 동작을 수행한다.

### 새로 시작 가능

기존 놀이 시작 확인 플로우 실행

### 이어하기 가능

기존 진행 중 세션으로 복원

### 열쇠 부족

황금열쇠 부족 안내 표시 후 미션으로 이동할 수 있는 CTA 제공

### 로딩 중

중복 클릭 차단

### 오류

연결 실패 또는 시작 실패 안내

---

# 12. 황금열쇠 필요 수량 표시 정책

레퍼런스의 `1/2`, `1/3` 숫자를 그대로 하드코딩하지 않는다.

현재 서비스의 황금열쇠 정책과 놀이 레지스트리의 실제 필요 수량을 사용한다.

현재 공통 정책이 놀이 시작 시 황금열쇠 1개 차감이라면 다음처럼 표시한다.

```text
🔑 1개 필요
```

보유량과 필요량을 함께 표시하는 UI가 필요하다면 실제 값으로 표시한다.

```text
🔑 1/1
```

놀이별 필요 수량이 설정에서 다르게 정의되어 있을 때만 실제 필요 수량을 사용한다.

UI 레퍼런스를 맞추기 위해 황금열쇠 차감 정책을 임의로 `2개`, `3개`로 변경하지 않는다.

# 13. 퀴즈마스터 카드

## 제목

```text
퀴즈마스터
```

## 디자인

- K-Sky Blue 또는 연한 하늘색 카드 배경
- K-Navy 테두리 또는 강조선
- 퀴즈를 상징하는 공식 이미지 또는 아이콘 사용
- 레퍼런스 이미지에서 잘라낸 자산 사용 금지
- 우측 상단에 상태 아이콘 표시
- 하단에 황금열쇠 필요 수량 또는 진행 상태 표시

## 동작

기존 퀴즈마스터 메인 앱 연동 정책을 유지한다.

- 메인 앱에서 start-handoff 수행
- 아이 학년 조회
- 황금열쇠 차감
- handoff token 생성
- 인앱 전체화면 모달 진입
- 외부 실제 배포 URL 노출 금지
- 완료·환불 callback 유지
- 이어하기 재진입 시 중복 차감 금지
- 연결 실패 시 기존 환불 정책 유지

카드 UI 변경을 이유로 퀴즈 엔진·DB·RPC를 수정하지 않는다.

# 14. 오늘의 나(MBTI) 카드

## 표시명

화면에는 친근한 이름으로 다음을 사용한다.

```text
오늘의 나
```

필요하면 작은 보조 문구로 다음을 표시할 수 있다.

```text
나의 성향 알아보기
```

내부 route와 코드에서는 기존 MBTI 식별자를 유지한다.

## 디자인

- K-Sky Blue 또는 밝은 블루 계열
- 거울·표정·성향을 연상시키는 기존 공식 이미지 사용
- 제목 K-Navy
- 상태와 필요 열쇠 수 표시
- 퀴즈마스터 카드와 동일한 크기와 정보 계층 유지

## 동작

기존 메인 앱 네이티브 MBTI 경로를 유지한다.

```text
/play/mbti
```

- iframe 또는 외부 URL 노출 금지
- 진행 중 세션 이어하기 유지
- 시작 시 기존 황금열쇠 차감 정책 유지
- 이어하기 재진입 중복 차감 금지
- 결과 화면과 저장 정책 유지

# 15. 놀이 카드 상태 아이콘

## 이용 조건 미충족

- 닫힌 자물쇠 아이콘
- `열쇠가 더 필요해요` 텍스트 제공
- 색상만으로 잠김 상태를 표현하지 않음

## 이용 가능

- 열린 자물쇠 또는 화살표 아이콘
- `시작할 수 있어요` 또는 기존 CTA 표시

## 이어하기

- 재생 또는 이어하기 아이콘
- `이어하기` 표시
- 저장된 시도 위치에서 복원

## 완료

기존 반복 플레이 정책에 따라:

- 다시 하기
- 완료
- 새로운 세션 시작

중 올바른 상태를 표시한다.

# 17. 준비 중 카드

## 디자인

- 연한 회색·하늘색 계열 배경
- 대표 이미지의 채도 또는 투명도를 낮춤
- 상단 또는 우측에 `준비 중` badge
- 활성 놀이 카드보다 시각적 우선순위를 낮춤
- 제목은 읽을 수 있는 대비 유지
- 카드가 활성 버튼처럼 보이지 않도록 한다.

## 동작

준비 중 카드는 실행할 수 없어야 한다.

절대 금지:

- 시작하기 화면 표시
- 황금열쇠 차감
- handoff token 생성
- 임시 세션 생성
- 외부 앱 연결
- 완료 또는 환불 callback 생성

카드 터치 시 필요한 경우 다음 안내만 표시한다.

```text
열심히 준비하고 있어요.
```

# 22. 황금열쇠 상태 갱신

다음 시점에 황금열쇠 보유량을 최신 상태로 갱신한다.

- 놀이 화면 최초 진입
- 놀이 시작 성공 후
- 놀이 연결 실패 환불 후
- 놀이 완료 후
- 미션 완료 후 화면 복귀
- 브라우저 visibility 복귀가 기존 데이터 갱신 정책에 포함되는 경우

다음 문제를 방지한다.

- 차감 전 숫자가 계속 표시됨
- 환불됐는데 숫자가 갱신되지 않음
- 다른 아이의 열쇠 수 표시
- 로딩 실패를 0개로 오인 표시
- 빠른 연속 클릭으로 이중 차감

# 23. 카드 시작 확인 플로우

놀이를 새로 시작할 때 기존 시작 확인 UI를 사용한다.

필요 정보:

- 놀이 이름
- 필요한 황금열쇠 수
- 현재 보유량
- 이어하기 세션 존재 여부

예시:

```text
퀴즈마스터를 시작할까요?

황금열쇠 1개가 사용돼요.
```

버튼:

```text

시작하기
```

황금열쇠가 부족하면 `시작하기` 대신 다음 CTA를 제공한다.

```text
미션하러 가기
```

준비 중 놀이에는 시작 확인창을 표시하지 않는다.
