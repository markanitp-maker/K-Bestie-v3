# 부모 질문하기 기능 구현 요청

## 1. 작업 목적

부모가 케이에게 아이에 관해 질문했지만 현재 데이터·리포트·LLM Wiki에서 답을 찾지 못한 경우, 부모가 `아이에게 질문하기` 기능을 통해 질문 초안을 확인·승인하고, 케이가 이후 아이와의 미션 대화 중 자연스럽게 질문하여 답변을 수집·재확인한 뒤 부모에게 전달할 수 있도록 전체 기능을 구현한다.

전체 흐름:

```text
부모 질문
→ 케이가 현재 데이터에서 답을 찾지 못함
→ 아이에게 질문하기 버튼 표시
→ 질문 초안 모달
→ 주간 사용 횟수 확인
→ 질문 1개로 정리
→ 부모 최종 승인
→ 아이 질문 대기열 등록
→ 아이 미션 대화 중 자연스럽게 질문
→ 아이 답변 수집
→ 케이가 답변 내용을 다시 확인
→ 아이 최종 확인 또는 답변 거부
→ 부모 Q&A 목록에 상태·답변 표시
→ 필요 시 부모 리포트에 반영
```

우선순위는 **P0 핵심 기능**이다.

## 2. 핵심 정책

### 2.1 부모 질문 횟수 제한

- 부모 가족 계정 기준으로 아이별 주 3회까지 질문할 수 있다.
- 기준 시간대는 KST이다.
- 주간 기준은 월요일 00:00:00부터 일요일 23:59:59까지다.
- 질문 초안 모달에 `이번 주 질문 1/3`, `이번 주 남은 질문 2회`를 표시한다.
- 초안만 열고 취소한 경우 차감하지 않는다.
- 부모가 최종 승인하여 질문 대기열에 등록한 시점에 1회를 차감한다.
- 동일 요청의 중복 전송·네트워크 재시도로 중복 차감되지 않아야 한다.
- 시스템 오류로 등록되지 않은 경우 차감하지 않는다.
- 아이가 답변을 거부하거나 답하지 않더라도 사용 횟수는 복구하지 않는다.
- 주 3회를 모두 사용하면 버튼을 비활성화하고 다음 주 월요일 초기화를 안내한다.

### 2.2 한 번에 질문은 반드시 1개

부모 입력에 질문이 2개 이상 포함되더라도 질문 1개만 등록한다.

예시 입력:

```text
서현이가 요즘 누구랑 친한지, 학교에서 힘든 일은 없는지 물어봐 줘.
```

정상 처리:

1. 시스템이 질문을 분리한다.
2. 한 번에 하나의 질문만 가능하다고 안내한다.
3. 우선순위가 가장 명확한 질문 하나를 초안으로 제시한다.
4. 부모가 수정하거나 승인하도록 한다.
5. 나머지 질문은 자동 등록하지 않는다.

안내 예시:

```text
한 번에 한 가지 질문만 아이에게 전달할 수 있어요.
먼저 아래 질문으로 진행할까요?
```

초안 예시:

```text
요즘 학교에서 가장 친하게 지내는 친구가 누구인지 물어볼까요?
```

질문 수 판단은 물음표 개수만 보지 말고 의미 구조를 함께 판단한다.

## 3. 부모 화면 흐름

### 3.1 아이에게 질문하기 버튼 노출 조건

아래 조건을 모두 만족할 때만 표시한다.

```text
부모 질문 의도 === CHILD_INFORMATION_QUERY
AND 기존 리포트·보정 대화·LLM Wiki에서 근거 있는 답변을 찾지 못함
AND 시스템 오류가 아님
AND 부모-아이 권한 검증 성공
AND 이번 주 질문 가능 횟수 > 0
```

일반 대화, 인사, 감사, 연결 확인, 사용자 피드백, Retrieval 오류, 이미 답한 질문에서는 표시하지 않는다.

### 3.2 질문 초안 모달

버튼을 누르면 즉시 질문을 등록하지 말고 모달을 연다.

```text
제목: 아이에게 이렇게 물어볼까요?

이번 주 질문 1/3

질문 초안:
[요즘 학교에서 가장 친하게 지내는 친구가 누구인지 물어볼까요?]

안내:
한 번에 한 가지 질문만 전달할 수 있어요.
케이는 아이와 자연스럽게 대화할 수 있는 순간에 질문하고,
답변을 다시 확인한 뒤 부모님께 알려드려요.

버튼:
[취소] [질문 등록하기]
```

필수 기능:

- 질문 초안 수정 가능
- 글자 수 제한
- 욕설·비난·유도 질문·민감 질문 필터
- 질문 2개 이상 입력 시 1개 질문으로 다시 정리
- 질문 대상 아이 이름 표시
- 등록 시 주간 횟수 재검증
- 중복 클릭 방지
- 등록 실패 시 횟수 미차감
- 즉시 답변을 받을 수 있다고 안내하지 않음

등록 성공 문구:

```text
질문을 등록했어요.
케이가 아이와 자연스럽게 대화할 수 있는 순간에 물어보고,
답변을 다시 확인한 뒤 알려드릴게요.
```

## 4. 아이 질문 대기열

부모가 승인하면 질문을 즉시 아이 질문 대기열에 저장한다.

최소 상태값:

```text
DRAFT
PENDING
SCHEDULED
ASKED
ANSWER_CAPTURED
CONFIRMING
ANSWERED
DECLINED
EXPIRED
CANCELLED
FAILED
```

상태 의미:

- `DRAFT`: 부모 초안 작성 중
- `PENDING`: 부모 승인 완료, 아직 질문하지 않음
- `SCHEDULED`: 다음 적절한 미션 턴에 질문 예정
- `ASKED`: 케이가 아이에게 질문함
- `ANSWER_CAPTURED`: 1차 답변 수집
- `CONFIRMING`: 답변 재확인 중
- `ANSWERED`: 아이가 최종 확인한 답변 저장 완료
- `DECLINED`: 아이가 답변 거부
- `EXPIRED`: 유효기간 내 질문하지 못함
- `CANCELLED`: 취소
- `FAILED`: 시스템 오류

질문은 등록 즉시 대기열에 들어가지만 대화를 강제로 끊고 바로 질문하지 않는다. 등록 후 7일 이내에 묻지 못하면 `EXPIRED` 처리한다.

## 5. 미션 대화에 자연스럽게 삽입하는 로직

- 기존 미션 흐름을 깨지 않는다.
- 아이가 현재 말하는 주제와 관련성이 있을 때 우선 삽입한다.
- 관련성이 낮으면 미션 중반 또는 종료 전 자연스러운 전환 구간에 1회 삽입한다.
- 한 미션 세션에서 부모 질문은 최대 1개만 묻는다.
- 아이가 피곤하거나 대답을 원하지 않는 신호를 보이면 강요하지 않는다.
- 같은 질문을 반복적으로 재촉하지 않는다.

자연스러운 전환 예시:

```text
그 친구 이야기 들으니까 궁금한 게 생겼어.
요즘 학교에서 가장 친하게 지내는 친구는 누구야?
```

관련 대화가 없는 경우:

```text
오늘 이야기해 줘서 고마워.
그런데 하나 궁금한 게 있어.
요즘 학교에서 가장 친하게 지내는 친구는 누구야?
```

아이에게 부모가 시켰다는 사실을 노출하지 않는다.

금지:

```text
엄마가 물어보라고 했어.
아빠가 궁금해하셔.
부모님이 질문을 보냈어.
```

### 5.1 미션 완료 조건과 분리

- 부모 질문은 기존 미션의 유효 답변 10개 완료 조건에 포함하지 않는다.
- 부모 질문 실패·거부·미응답이 미션 완료를 막으면 안 된다.
- 별도 `parent_question_turn`으로 기록한다.
- 기존 기본 질문·예비 질문·재순환 로직과 분리한다.
- 미션 종료 전 아이 상태가 적절하지 않으면 다음 미션으로 이월할 수 있다.
- 같은 부모 질문은 여러 미션에서 중복 질문하지 않는다.

## 6. 아이 답변 재확인 절차

### 6.1 부모 질문에만 재확인 적용

평상시 미션 질문과 자유 대화의 모든 답변을 재확인하지 않는다.

아래 조건에서만 반드시 재확인한다.

```text
source === PARENT_QUESTION
AND 아이가 1차 답변을 제공함
```

목적:

- STT 오인식 보정
- 긍정·부정 반전 방지
- 이름·장소·사건 정보 오류 방지
- 부모에게 전달되는 답변 신뢰도 확보

### 6.2 재확인 예시

아이:

```text
요즘 지민이랑 제일 친해.
```

케이:

```text
내가 잘 이해했는지 확인할게.
요즘 학교에서 지민이랑 가장 친하게 지낸다는 말이 맞아?
```

아이:

```text
응, 맞아.
```

이때만 최종 답변을 `ANSWERED`로 저장한다.

아이가 수정하면 수정 내용을 다시 확인한 후 최종 저장한다. 1차 STT 원문이 아니라 최종 확인된 내용을 저장한다.

재확인 횟수는 최대 2회로 제한한다. 명확히 확인되지 않으면 부모에게 추측 답변을 전달하지 않는다.

부모 표시 예시:

```text
아이의 답변을 명확하게 확인하지 못했어요.
다음 대화에서 한 번 더 확인할게요.
```

## 7. 아이 답변 거부

아이는 답변을 거부할 수 있다.

예시:

```text
말하기 싫어.
그건 비밀이야.
대답 안 할래.
다음에 말할래.
```

처리 기준:

1. 강요하거나 반복 질문하지 않는다.
2. 아이 선택을 존중하는 짧은 응답을 한다.
3. 상태를 `DECLINED`로 저장한다.
4. 부모 Q&A에는 거부 사실만 표시한다.
5. 이유를 추측하지 않는다.
6. 아이의 거부 문장을 부모에게 원문 그대로 노출하지 않는다.

아이 응답:

```text
알겠어. 말하고 싶지 않으면 이야기하지 않아도 괜찮아.
```

부모 표시:

```text
아이가 이번 질문에는 답변하지 않기로 했어요.
```

## 8. 부모 Q&A 화면

부모용 `케이와 대화하기` 화면에 `Q&A` 버튼을 추가한다.

권장 위치:

```text
[대화] [Q&A]
```

Q&A 화면 각 항목 필수 정보:

- 질문
- 대상 아이
- 등록일
- 이번 주 사용 순서
- 현재 상태
- 답변 또는 상태 설명
- 답변 완료일

대기 예시:

```text
질문:
요즘 학교에서 가장 친하게 지내는 친구가 누구인지 물어봐 주세요.

대상:
안서현

등록:
2026.08.04

상태:
질문 대기 중
```

답변 완료 예시:

```text
상태:
답변 완료

답변:
서현이는 요즘 수아와 가장 친하게 지낸다고 확인했어요.

확인:
2026.08.05
```

답변 거부 예시:

```text
상태:
답변하지 않음

안내:
아이가 이번 질문에는 답변하지 않기로 했어요.
```

상태별 부모 문구:

| 내부 상태 | 부모 표시 |
|---|---|
| PENDING | 질문 대기 중 |
| SCHEDULED | 다음 대화에서 질문 예정 |
| ASKED | 아이에게 질문했어요 |
| ANSWER_CAPTURED | 답변을 확인하고 있어요 |
| CONFIRMING | 아이에게 답변을 다시 확인하고 있어요 |
| ANSWERED | 답변 완료 |
| DECLINED | 아이가 답변하지 않기로 했어요 |
| EXPIRED | 기간 내 질문하지 못했어요 |
| FAILED | 처리 중 문제가 발생했어요 |
| CANCELLED | 질문이 취소됐어요 |

기본 정렬은 최신 등록순이며 필터는 `전체`, `대기 중`, `답변 완료`, `답변하지 않음`을 제공한다.

## 9. 부모 리포트 반영

부모 질문 답변은 아이가 최종 확인한 경우에만 리포트에 반영한다.

```text
status === ANSWERED
AND confirmation_completed_at IS NOT NULL
```

기본 권장안:

1. Q&A 화면에는 즉시 표시
2. 해당 날짜 일일 리포트에는 요약형으로 반영
3. 장기 기억 가치가 있는 경우에만 Memory Batch 후보로 전달

거부·미확인 답변은 리포트나 LLM Wiki에 사실로 저장하지 않는다.

## 10. 데이터 구조 요구사항

기존 스키마를 먼저 확인하고 재사용 가능한 테이블이 있으면 재사용한다. 없으면 아래 개념을 만족하는 구조를 추가한다.

부모 질문 필드 권장안:

```text
id
family_id
parent_user_id
child_id
original_parent_query
draft_question
approved_question
status
week_key_kst
weekly_sequence
source_chat_message_id
scheduled_mission_id
asked_at
answer_captured_at
confirmation_started_at
confirmed_at
declined_at
expired_at
cancelled_at
failure_code
created_at
updated_at
```

부모 질문 답변 필드 권장안:

```text
id
parent_question_id
child_id
raw_transcript_reference
normalized_answer
confirmation_prompt
confirmation_response
confirmed_answer
confirmation_status
stt_confidence
created_at
updated_at
```

보안 원칙:

- raw 오디오 저장 금지 또는 기존 보존 정책 준수
- 대화 원문 직접 노출 금지
- 부모는 자기 가족의 질문만 조회
- 아이별 RLS 강제
- 서비스 역할 키를 클라이언트에 노출 금지

## 11. 주간 제한 구현

주간 제한은 클라이언트 표시만으로 구현하지 않는다. 서버 또는 DB에서 원자적으로 검증한다.

필수 기준:

```text
family_id
child_id
week_key_kst
status NOT IN (DRAFT, CANCELLED, FAILED_BEFORE_REGISTRATION)
```

동일 요청 재시도 방지:

- idempotency key 사용
- 중복 버튼 클릭 방지
- DB unique constraint 또는 RPC 내 원자 처리
- 질문 등록과 주간 카운트 차감을 하나의 트랜잭션으로 처리
- 동시 요청에서도 3회를 초과하지 않음

## 12. 질문 안전성·프라이버시

아래 질문은 그대로 전달하지 않는다.

- 비난·추궁
- 답을 유도하는 질문
- 부모 편을 들도록 요구
- 아이의 사생활을 과도하게 캐묻는 질문
- 성적·신체·친구 관계에 대한 공격적 표현
- 다른 보호자에 대한 평가 요구
- 아이에게 죄책감을 주는 표현
- 복수 질문
- 예/아니오를 강요하는 질문

예시 입력:

```text
너 요즘 엄마 몰래 누구 만나고 다니지?
```

재작성 예시:

```text
요즘 자주 함께 시간을 보내는 친구가 있는지 물어볼까요?
```

안전한 재작성도 부적절하면 등록을 차단한다.

## 13. 알림 정책

답변 완료 시 부모에게 앱 내 알림을 제공한다.

```text
서현이에게 물어본 질문의 답변이 도착했어요.
```

거부 시:

```text
서현이가 이번 질문에는 답변하지 않기로 했어요.
```

알림 클릭 시 Q&A 해당 질문 상세로 이동한다. 푸시 시스템이 없으면 앱 내 배지부터 구현한다.

## 14. 관리자 화면

관리자에서 최소한 아래 항목을 조회한다.

- 질문 ID
- 부모·아이 식별 정보
- 등록일
- 상태
- 주간 사용 순서
- 아이에게 질문한 시점
- 재확인 완료 여부
- 답변 완료·거부·만료 여부
- 오류 코드
- 처리 지연 시간

관리자는 원문 대화 전체가 아니라 운영에 필요한 최소 정보만 조회한다.

관리자 기능:

- 상태 조회
- 실패 건 재처리
- 만료 처리
- 비정상 중복 감지

운영자가 아이 답변을 임의 수정하는 기능은 제공하지 않는다.

## 15. 테스트 요구사항

### 단위 테스트

- 질문 1개 입력 → 초안 1개 생성
- 질문 2개 이상 입력 → 한 질문만 선택
- 초안 취소 → 횟수 미차감
- 질문 등록 → 1/3, 2/3, 3/3 처리
- 네 번째 등록 → 차단
- 다음 주 월요일 KST → 0/3 초기화
- 동시 등록 → 3회 초과 방지
- 네트워크 재시도 → 중복 질문·중복 차감 없음
- 아이 1차 답변 → 바로 ANSWERED 금지
- 아이 최종 확인 → ANSWERED
- 아이 수정 → 수정 답변 재확인 후 ANSWERED
- 아이 거부 → DECLINED
- 재확인 실패 → 미확인 답변 부모 노출 금지
- 부모 질문이 미션 완료 조건에 영향 없음

### 통합 테스트

#### 시나리오 A: 질문 등록

1. 부모가 케이에게 아이 정보를 질문
2. 케이가 근거를 찾지 못함
3. `아이에게 질문하기` 버튼 표시
4. 질문 초안 모달 표시
5. `이번 주 질문 1/3` 표시
6. 부모 승인
7. 질문 대기열 `PENDING` 저장
8. Q&A 목록 `질문 대기 중` 표시

#### 시나리오 B: 다중 질문

1. 부모가 두 가지 질문 입력
2. 한 번에 한 질문만 가능하다고 안내
3. 한 질문만 초안으로 생성
4. 질문 1건만 등록
5. 주간 횟수 1회만 차감

#### 시나리오 C: 미션 중 자연스러운 질문

1. 아이가 미션 시작
2. 기존 미션 질문 정상 진행
3. 자연스러운 전환 시점에 부모 질문 1개 삽입
4. 부모가 시켰다는 표현 없음
5. 부모 질문이 미션 유효 답변 10개에 포함되지 않음

#### 시나리오 D: 답변 재확인

1. 아이가 1차 답변
2. 케이가 요약해 다시 확인
3. 아이가 긍정
4. 최종 답변 저장
5. 부모 Q&A에서 답변 완료 표시
6. 리포트 반영 조건 충족

#### 시나리오 E: 답변 수정

1. 1차 STT 결과 오류
2. 케이가 잘못 요약
3. 아이가 수정
4. 케이가 수정 내용을 다시 확인
5. 최종 확인된 답변만 저장
6. 잘못된 1차 답변 부모 노출 금지

#### 시나리오 F: 답변 거부

1. 아이가 답변 거부
2. 케이가 강요하지 않음
3. `DECLINED` 저장
4. 부모 Q&A에 거부 상태 표시
5. 거부 이유 추측·원문 노출 없음

#### 시나리오 G: 만료

1. 등록 후 7일 동안 질문하지 못함
2. `EXPIRED` 처리
3. 부모 Q&A에 만료 안내
4. 자동 재등록 없음

## 17. 완료 기준

- [ ] 부모가 `아이에게 질문하기` 버튼을 사용할 수 있다.
- [ ] 버튼 클릭 시 질문 초안 모달이 열린다.
- [ ] 모달에 `이번 주 질문 1/3`이 표시된다.
- [ ] 주당 아이별 3회 제한이 서버에서 원자적으로 적용된다.
- [ ] 질문은 한 번에 반드시 1개만 등록된다.
- [ ] 다중 질문 입력 시 한 질문만 선택한 초안을 제시한다.
- [ ] 부모 승인 후 질문 대기열에 즉시 등록된다.
- [ ] 아이 미션 대화 중 자연스러운 시점에 질문한다.
- [ ] 부모가 시켰다는 사실을 아이에게 노출하지 않는다.
- [ ] 부모 질문은 미션 유효 답변 10개에 포함되지 않는다.
- [ ] 부모 질문의 아이 답변은 반드시 재확인한다.
- [ ] 아이가 최종 확인한 답변만 부모에게 전달한다.
- [ ] 아이가 답변을 거부할 수 있다.
- [ ] 거부 시 강요하지 않고 부모에게 상태만 알린다.
- [ ] 부모 `케이와 대화하기` 화면에 Q&A 버튼이 있다.
- [ ] Q&A에서 질문·상태·답변을 확인할 수 있다.
- [ ] 답변 완료·대기·거부·만료·오류가 구분된다.
- [ ] 답변 완료 시 앱 내 알림 또는 배지가 표시된다.
- [ ] 타입 검사, 빌드, 단위·통합·회귀 테스트가 모두 통과한다.
- [ ] Development 실제 UI E2E를 통과한 뒤에만 Production으로 배포한다.
