# 자유대화 10분 진행 후 1분 휴식 기능 구현

## 목적

미션이 아닌 자유대화에서 아이가 연속으로 10분 동안 대화한 뒤 자동으로 대화를 종료하고, 1분 동안 휴식한 후 다시 자유대화를 시작할 수 있도록 구현한다.

현재 자유대화에는 클라이언트 브라우저 기준 10분 타이머만 존재하며, 10분 종료 후 즉시 재진입할 수 있고 새로고침하면 타이머가 초기화되는 문제가 있다.

## 현재 확인된 상태

- 자유대화 경로: `/chat`
- 관련 파일: `app/chat/page.tsx`
- 현재 제한 시간: `10 * 60 * 1000`
- 현재 종료 문구:
  - `오늘 대화는 여기까지야! 너무 재미있었어, 내일 또 이야기하러 와줘`
- 현재 문제:
  - 10분 종료 후 즉시 재진입 가능
  - 새로고침 시 10분 타이머 초기화
  - 브라우저 종료·화면 잠금·앱 이탈 후 시간이 유지되지 않음
  - 여러 기기에서 동시에 자유대화 가능
  - 서버 기준 세션 상태와 휴식 상태가 없음
  - 실제로는 1분 후 다시 사용할 수 있는데 안내 문구가 `내일 또 와줘`로 잘못 표시됨

## 최종 동작

1. 아이가 자유대화를 시작하면 서버 시간 기준으로 자유대화 시작 시각을 저장한다.
2. 자유대화는 연속 최대 10분 동안 진행할 수 있다.
3. 10분이 지나면 음성 입력과 대화를 자동으로 종료한다.
4. 종료 시 케이가 아래 문구를 안내한다.

> 오늘 대화는 여기까지야! 1분 쉬었다가 다시 이야기하러 와줘.

5. 종료 직후부터 정확히 1분 동안 해당 아이의 자유대화 재진입을 차단한다.
6. 1분 휴식 시간이 끝나면 자유대화 버튼을 다시 활성화한다.
7. 휴식 종료 후 새로운 10분 자유대화 세션을 시작할 수 있다.
8. 이 흐름은 하루 동안 반복 가능하다.
9. 기존 미션 대화에는 이 제한을 적용하지 않는다.

## 핵심 구현 원칙

### 1. 서버 시간 기준 관리

클라이언트 `setTimeout`만으로 시간을 관리하지 않는다.

서버 또는 Supabase DB에 최소한 아래 정보를 저장한다.

- `child_id`
- 자유대화 세션 시작 시각
- 자유대화 세션 종료 시각
- 세션 상태
  - `active`
  - `cooldown`
  - `ended`
- 휴식 종료 시각 `cooldown_until`
- 생성 시각 및 갱신 시각

시간 판정은 클라이언트 기기 시간이 아니라 서버 시간 또는 DB의 `now()`를 기준으로 한다.

### 2. 새로고침 및 재접속 복원

자유대화 도중 새로고침하거나 브라우저를 닫았다가 다시 들어와도 새로운 10분이 시작되면 안 된다.

예시:

- 6분 대화 후 새로고침
- 다시 접속하면 남은 시간은 약 4분
- 10분 전체 시간이 지나면 자동 종료
- 이후 1분 휴식 시작

브라우저 백그라운드 전환, 화면 잠금, 앱 이탈 후 복귀도 동일하게 처리한다.

### 3. 여러 기기 동시 사용 방지

같은 아이가 다른 브라우저나 기기에서 자유대화를 시작하더라도 동일한 서버 세션 상태를 사용해야 한다.

이미 활성 세션이 있으면 새 세션을 중복 생성하지 말고 기존 세션의 남은 시간을 반환한다.

휴식 중이면 다른 기기에서도 자유대화에 진입할 수 없어야 한다.

### 4. 자유대화 진입 게이트

`app/child/home/page.tsx`의 자유대화 버튼에서 서버의 현재 상태를 확인한다.

- 활성 세션이 있으면 기존 세션 이어가기
- 휴식 중이면 `/chat` 진입 차단
- 휴식이 끝났으면 새 세션 시작 가능

사용자가 주소창에 `/chat`을 직접 입력해도 서버 또는 페이지 진입 단계에서 동일하게 차단해야 한다.

클라이언트 버튼 비활성화만으로 처리하지 않는다.

### 5. 휴식 중 화면

휴식 중 자유대화 버튼을 누르면 아래와 같이 안내한다.

> 지금은 잠깐 쉬는 시간이야.  
> 00초 뒤에 다시 이야기할 수 있어.

남은 시간을 초 단위로 표시한다.

1분이 끝나면 별도 새로고침 없이 버튼이 자동으로 활성화되어야 한다.

### 6. 10분 종료 처리

10분이 지나면 다음 처리를 순서대로 수행한다.

1. 마이크 입력 중단
2. 진행 중인 음성 인식 또는 응답 요청 정리
3. 자유대화 세션 상태를 `cooldown`으로 변경
4. 서버 기준 `cooldown_until`을 현재 시각 + 1분으로 저장
5. 케이 종료 안내 출력
6. 홈 화면으로 이동하거나 종료 화면 표시
7. 1분 동안 재진입 차단

종료 처리는 여러 번 호출되더라도 중복 세션 종료나 중복 DB 기록이 발생하지 않도록 멱등성을 보장한다.

## API 구성

현재 구조를 먼저 조사한 후 기존 API 패턴을 따르되, 최소한 다음 동작이 필요하다.

### 자유대화 상태 조회

현재 아이의 자유대화 상태를 반환한다.

반환 항목 예시:

```json
{
  "status": "active",
  "startedAt": "2026-07-29T07:00:00.000Z",
  "sessionEndsAt": "2026-07-29T07:10:00.000Z",
  "cooldownUntil": null,
  "remainingSessionSeconds": 240,
  "remainingCooldownSeconds": 0
}
```

### 자유대화 세션 시작

- 기존 활성 세션이 있으면 기존 세션 반환
- 휴식 중이면 시작 거부 및 남은 휴식 시간 반환
- 시작 가능한 상태이면 새로운 10분 세션 생성

### 자유대화 세션 종료

- 10분 만료 또는 정상 종료 처리
- `cooldown_until = 서버 현재 시각 + 1분`
- 중복 종료 요청에도 결과가 일관되도록 처리

## DB 및 보안

- 아이 본인 세션 또는 해당 아이에 접근 권한이 있는 정상 사용자만 상태를 조회하거나 변경할 수 있어야 한다.
- 클라이언트가 임의로 `started_at`, `cooldown_until`, `status`를 조작할 수 없도록 한다.
- 시간 계산은 서버에서 수행한다.
- 기존 자유대화 기록 및 리포트 수집 구조를 깨뜨리지 않는다.
- 기존 DB 테이블로 안전하게 구현할 수 있는지 먼저 확인하고, 신규 테이블이나 컬럼이 필요하면 마이그레이션으로 추가한다.
- Production DB에 직접 수동 변경하지 않는다.
