# 부모 리포트 알림 — 오전 8시 생성 완료 계정만 발송

## 1. 목적

매일 오전 8시(KST)에 부모 리포트 알림 스케줄러를 실행하되, 해당 시점에 실제 생성 완료된 일일 또는 주간 리포트가 존재하는 부모 계정에게만 알림을 발송한다.

오전 8시라는 시간만 기준으로 전체 부모에게 일괄 발송하면 안 된다. 리포트가 생성되지 않았거나 생성에 실패한 경우에는 부모 알림을 발생시키지 않는다.

## 2. 확정 정책

- 발송 시각: 매일 오전 8시(KST)
- 발송 채널: 기존 앱 푸시 알림
- 발송 대상: 생성 완료 리포트가 있는 부모
- 리포트가 없으면 미발송
- 같은 부모에게 오전 8시 알림은 최대 1회
- 주간 리포트와 일일 리포트가 모두 있으면 주간 리포트 우선
- 알림 클릭 시 해당 리포트 또는 새 리포트 목록으로 이동
- 부모의 리포트 알림 설정이 OFF이면 미발송

## 3. 발송 조건

다음 조건을 모두 만족해야 한다.

```text
활성 부모 계정
AND 연결된 아이 존재
AND 발송 대상 날짜의 리포트 존재
AND report.status = COMPLETED 또는 기존 완료 상태
AND generated_at 존재
AND 부모 리포트 알림 설정 ON
AND 동일 리포트 알림 미발송
```

조회 예시:

```sql
WHERE status = 'COMPLETED'
  AND generated_at IS NOT NULL
  AND notification_sent_at IS NULL
```

현재 시스템이 `READY`, `SUCCESS`, `DONE` 등을 완료 상태로 사용하면 기존 값을 재사용한다.

## 4. 미발송 조건

### 4.1 아이 활동 부족

다음 사유로 리포트가 생성되지 않은 경우 알림을 보내지 않는다.

- 아이가 미션을 진행하지 않음
- 자유대화를 진행하지 않음
- 분석 가능한 데이터 부족
- 리포트 생성 최소 조건 미충족

처리:

```text
리포트 없음 또는 NO_DATA
→ 부모 알림 없음
```

부모에게 `리포트가 없습니다`, `아이 활동이 부족합니다` 같은 별도 알림도 보내지 않는다.

### 4.2 시스템 장애

다음 사유로 리포트 생성이 실패한 경우에도 알림을 보내지 않는다.

- Collection 실패
- Context Correction 실패
- LLM 분석 실패
- Report Generation 실패
- DB·Edge Function·Cron 오류
- 외부 API 또는 네트워크 장애

처리:

```text
FAILED 또는 미완료
→ 부모 알림 없음
→ 관리자 모니터링 대상으로만 기록
```

부모에게 시스템 오류나 리포트 실패 사실을 푸시로 알리지 않는다.

## 5. 리포트 상태

필요 시 다음 상태를 사용한다.

```ts
type ReportStatus =
  | "GENERATING"
  | "COMPLETED"
  | "FAILED"
  | "NO_DATA";
```

| 상태 | 의미 | 부모 알림 |
|---|---|---|
| `GENERATING` | 생성 중 | 미발송 |
| `COMPLETED` | 생성 완료 | 발송 대상 |
| `FAILED` | 시스템 오류 | 미발송 |
| `NO_DATA` | 활동·데이터 부족 | 미발송 |

## 6. 일일·주간 우선순위

오전 8시 기준으로 부모당 최대 1건만 보낸다.

1. 주간 리포트가 생성 완료되어 있으면 주간 알림
2. 주간 리포트가 없고 일일 리포트가 있으면 일일 알림
3. 둘 다 없으면 미발송

단순히 가장 최근 리포트를 가져와 오래된 리포트를 다시 발송하지 않는다. 발송 대상 날짜와 리포트 대상 기간을 정확히 확인한다.

## 7. 여러 자녀가 있는 부모

예:

- 아이 A: `COMPLETED`
- 아이 B: 리포트 없음

결과:

- 부모에게 알림 1회
- 알림에는 리포트가 생성된 아이만 포함
- 아이 B의 미생성 사실은 알림에 포함하지 않음

여러 아이의 리포트가 모두 생성되어도 부모 기준 알림은 1회로 통합한다.

## 8. 알림 문구

### 일일

```text
서아의 새 리포트가 도착했어요
어제 아이의 이야기와 오늘 나눌 대화를 확인해 보세요.
```

### 주간

```text
서아의 주간 리포트가 도착했어요
지난 한 주의 변화와 관심사를 확인해 보세요.
```

여러 자녀 통합:

```text
아이들의 새로운 리포트가 도착했어요.
```

푸시 본문에는 민감한 대화 내용, 감정, 친구 이름, 사건 내용을 직접 포함하지 않는다.

## 9. 클릭 이동

단일 리포트 알림:

```text
부모 앱 → 리포트 탭 → 해당 리포트 상세
```

여러 자녀 통합 알림:

```text
부모 앱 → 리포트 탭 → 새로 생성된 리포트 목록
```

푸시 payload에는 리포트 ID 등 최소 라우팅 정보만 넣고 리포트 본문은 포함하지 않는다.

## 10. 오전 8시 처리 흐름

```text
08:00 KST 스케줄러 실행
→ 활성 부모·연결 자녀 조회
→ 부모별 주간 리포트 확인
→ 없으면 일일 리포트 확인
→ COMPLETED 리포트가 있는 부모만 선별
→ 부모 알림 설정 확인
→ 중복 발송 여부 확인
→ 푸시 발송
→ 성공·실패 및 대상 report_id 기록
```

오전 8시 알림 작업은 리포트를 새로 생성하지 않는다. 이미 생성 완료된 리포트만 조회한다.

## 11. 중복 방지

동일 리포트 또는 동일 부모 배치에 중복 알림이 발생하지 않도록 멱등성을 보장한다.

권장 키:

```text
parent_id + report_id + notification_type
```

여러 자녀 통합 알림:

```text
parent_id + notification_date + report_type
```

다음 상황에서도 1회만 발송한다.

- Cron 중복 실행
- 서버 재시도
- 타임아웃 후 재실행
- 수동 재실행
- 푸시 제공자 응답 지연

별도 `report_notification_logs` 테이블 또는 `notification_sent_at`을 사용한다.

## 12. 푸시 실패

리포트는 생성됐지만 푸시 발송만 실패한 경우:

- 관리자 로그에 발송 실패 기록
- 제한된 재시도 적용
- 최대 재시도 횟수 초과 시 종료
- 성공 기록 전에도 중복 알림이 생성되지 않도록 상태 관리

리포트 생성 실패와 푸시 발송 실패를 분리한다.

## 13. 관리자 모니터링

관리자 화면에서 다음을 구분한다.

| 리포트 상태 | 알림 상태 |
|---|---|
| `COMPLETED` | 발송 완료 / 발송 대기 / 발송 실패 |
| `NO_DATA` | 미발송 |
| `FAILED` | 미발송 |
| `GENERATING` | 대기 |

관리자 확인 항목:

- 리포트 생성 여부
- 미생성 원인: 활동 부족 또는 시스템 실패
- 알림 대상 여부
- 알림 발송 시각
- 푸시 실패 사유
- 재시도 상태

부모에게는 미생성 사유를 노출하지 않는다.

## 14. 시간대

- 기준: `Asia/Seoul`
- 실행: 매일 `08:00 KST`
- 서버가 UTC여도 날짜 경계와 대상 리포트 날짜를 KST로 계산
- Dev와 Production Cron 설정 분리 확인

## 15. 테스트 시나리오

### 정상 일일 리포트
- 일일 리포트 `COMPLETED`
- 오전 8시 알림 1회
- 클릭 시 상세 이동
- 발송 이력 기록

### 정상 주간 리포트
- 일일·주간 모두 `COMPLETED`
- 주간 알림만 발송
- 일일 알림 중복 없음

### 아이 활동 없음
- 리포트 없음 또는 `NO_DATA`
- 부모 알림 없음
- 관리자에 `NO_DATA`

### 시스템 장애
- 리포트 `FAILED`
- 부모 알림 없음
- 관리자에 실패 원인

### 생성 중
- 오전 8시 `GENERATING`
- 알림 없음
- 완료되지 않은 리포트를 발송하지 않음

### 여러 자녀 중 일부만 생성
- 생성된 아이만 대상
- 부모 알림은 1회
- 미생성 아이 언급 없음

### 여러 자녀 모두 생성
- 부모 알림 1회
- 클릭 시 새 리포트 목록

### 부모 알림 OFF
- 리포트가 있어도 미발송
- 앱 내 조회는 가능

### 중복 Cron
- 작업 2회 실행
- 알림 1회
- 로그 1건

### 푸시 실패
- 실패 로그 기록
- 제한된 재시도
- 중복 알림 없음

## 16. 완료 조건

- 매일 오전 8시 KST 실행
- 생성 완료 리포트가 있는 부모만 발송
- 리포트 미생성 시 미발송
- 활동 부족 시 미발송
- 시스템 장애 시 미발송
- 부모에게 미생성 안내 없음
- 주간 리포트 우선
- 부모당 최대 1회
- 여러 자녀 통합 처리
- 알림 설정 OFF 반영
- 동일 리포트 중복 발송 없음
- 클릭 시 해당 리포트 이동
- 관리자에서 상태·원인·발송 결과 확인
- Dev 검증 완료
- Production 배포 및 오전 8시 검증 완료
