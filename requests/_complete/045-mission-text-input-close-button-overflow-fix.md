# 045 — 미션 텍스트 입력창 우측 닫기 버튼 잘림 및 모바일 키보드 레이아웃 수정

## 1. 작업 목적

아이 미션 대화 화면에서 왼쪽 하단 키보드 버튼을 눌러 텍스트 입력 모드로 전환하면, 화면 하단에 다음 요소가 표시된다.

1. 텍스트 입력창
2. 전송 버튼
3. 텍스트 입력 모드 닫기 X 버튼

현재 실제 모바일 PWA에서는 가장 오른쪽의 X 버튼이 화면 밖으로 밀려 일부가 잘린다.

첨부 이미지의 빨간 박스 영역처럼 X 버튼의 오른쪽 부분이 화면 경계 밖으로 나가 있어 정상적으로 보이지 않고 터치도 불편하다.

이번 작업에서는 텍스트 입력창·전송 버튼·X 버튼을 모바일 화면 내부에 완전히 들어오도록 재배치하고, iOS 소프트 키보드가 열린 상태에서도 안정적으로 유지되도록 수정한다.

---

# 2. 현재 문제

현재 하단 입력 영역은 다음과 같은 문제를 가진 것으로 보인다.

- 입력창이 `width: 100%` 또는 과도한 고정 너비를 차지함
- 그 오른쪽에 전송 버튼과 X 버튼이 추가됨
- 세 요소의 총 너비가 실제 모바일 Viewport보다 커짐
- 부모 컨테이너가 화면 오른쪽 경계를 넘어감
- X 버튼이 `position: absolute` 또는 `fixed`로 Viewport 바깥에 배치됐을 가능성
- iOS Safe Area가 오른쪽 여백 계산에 반영되지 않음
- Flex 자식인 입력창에 `min-width: 0`이 없어 축소되지 않을 가능성
- 부모의 `overflow: hidden` 때문에 바깥으로 나간 X 버튼이 잘림
- PC 스마트폰 프레임에서는 축소되어 보여 문제가 감춰질 수 있지만 실제 모바일 PWA에서는 잘림이 발생함

CSS 수정 전에 실제 원인을 확인하고, 임시로 X 버튼만 왼쪽으로 이동하는 방식이 아니라 하단 입력 행 전체를 재구성한다.

---

# 3. 적용 대상

대상 화면:

- 아이 미션 대화 화면
- 키보드 텍스트 입력 모드
- 실제 모바일 브라우저
- iOS 홈 화면 PWA
- Android 설치형 PWA
- PC 설치형 PWA의 스마트폰 미리보기
- 태블릿 화면

대상 상태:

- 자동 모드에서 키보드 버튼 클릭 후 수동 모드로 전환된 상태
- 수동 모드에서 텍스트 입력창이 열린 상태
- 소프트 키보드가 닫힌 상태
- 소프트 키보드가 열린 상태
- 텍스트 입력 중
- 텍스트 전송 처리 중
- 화면 회전 및 Viewport 크기 변경 상태

---

# 4. 최종 목표 구조

하단 텍스트 입력 영역은 하나의 행 안에 다음 순서로 구성한다.

```text
┌────────────────────────────────────┐
│ [텍스트 입력창] [전송] [X 닫기]    │
└────────────────────────────────────┘
```

모든 요소는 실제 앱 Viewport 내부에 있어야 한다.

## 필수 조건

- 입력창 왼쪽이 화면 밖으로 나가지 않음
- X 버튼 오른쪽이 화면 밖으로 나가지 않음
- 입력창·전송·X 버튼이 서로 겹치지 않음
- X 버튼 전체 형태가 완전히 보임
- X 버튼 오른쪽에 최소 안전 여백 존재
- 모바일 Safe Area 반영
- 가로 스크롤 없음
- 소프트 키보드가 열려도 같은 행 구조 유지
- 전송 버튼과 X 버튼의 터치 영역이 최소 44×44px 이상
- 작은 화면에서도 입력창이 먼저 유연하게 줄어들고 버튼은 잘리지 않음

---

# 5. 권장 레이아웃 구조

Flex에서 입력창 너비 계산이 계속 불안정하다면 CSS Grid를 우선 사용한다.

권장 개념:

```css
.mission-text-composer {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 56px 52px;
  align-items: center;
  gap: 8px;
  width: 100%;
  max-width: 430px;
  margin-inline: auto;
  box-sizing: border-box;
}
```

실제 수치는 현재 디자인 시스템과 화면을 확인하여 조정하되 구조는 다음과 같아야 한다.

```text
가변 입력창
+
고정 전송 버튼
+
고정 닫기 버튼
```

입력창은 남는 공간만 사용한다.

전송 버튼과 닫기 버튼을 입력창 너비 밖에 추가하는 구조를 금지한다.

---

# 6. 하단 입력 영역 외부 컨테이너

하단 입력 영역 전체는 실제 모바일 Viewport 너비 안에 있어야 한다.

권장 개념:

```css
.mission-text-composer-shell {
  width: 100%;
  padding-left: max(12px, env(safe-area-inset-left));
  padding-right: max(12px, env(safe-area-inset-right));
  padding-bottom: max(12px, env(safe-area-inset-bottom));
  box-sizing: border-box;
}
```

## 필수 원칙

- `width: 100vw`와 좌우 padding을 동시에 적용해 전체 너비가 Viewport보다 커지지 않게 함
- 가능하면 `width: 100%` 사용
- `box-sizing: border-box` 적용
- 앱 내부 최대 너비 기준을 따름
- 오른쪽 Safe Area를 명시적으로 반영
- X 버튼 오른쪽에 최소 `12px~16px`의 실제 여백 확보
- 부모 컨테이너의 좌우 음수 Margin 제거
- `right: -값` 또는 Viewport 밖으로 밀어내는 Transform 제거

---

# 7. 입력창

## 너비

입력창은 남은 너비를 유연하게 사용한다.

필수 CSS 조건:

```css
min-width: 0;
width: 100%;
box-sizing: border-box;
```

Flex를 사용하는 경우:

```css
flex: 1 1 auto;
min-width: 0;
```

Grid를 사용하는 경우:

```css
grid-template-columns: minmax(0, 1fr) auto auto;
```

## 높이

- 기본 높이 약 `54px~64px`
- 전송 및 닫기 버튼과 시각적 높이를 맞춤
- 글자가 늘면 기존 정책에 따라 최대 높이까지 자동 확장 가능
- 입력창이 확장되어도 전송·닫기 버튼을 오른쪽 밖으로 밀지 않음

## Placeholder

기존 문구를 유지한다.

```text
케이에게 텍스트로 답하기...
```

Placeholder가 길다고 입력창의 최소 너비가 강제되지 않도록 한다.

---

# 8. 전송 버튼

## 위치

- 입력창 바로 오른쪽
- X 버튼 바로 왼쪽
- 두 버튼 사이 간격 약 `6px~10px`

## 크기

- 최소 터치 영역 `48×48px`
- 권장 `52px~58px`
- 작은 화면에서도 크기를 지나치게 줄이지 않음
- 아이콘은 버튼 중앙 정렬

## 상태

- 입력 내용 없음: 기존 비활성 정책 유지
- 입력 내용 있음: 활성
- 전송 처리 중: 중복 클릭 차단
- 전송 처리 중에도 버튼 너비가 변하지 않음
- Loading 표시 때문에 X 버튼이 밀리지 않음

---

# 9. X 닫기 버튼

## 역할

이 X 버튼은 미션 전체 종료 버튼이 아니다.

다음 기능만 수행한다.

```text
텍스트 입력창 닫기
```

기존 정책에 따라:

- 텍스트 입력 UI 닫기
- 모바일 소프트 키보드 닫기
- 입력 모드는 수동 상태 유지
- 자동 모드로 임의 복귀하지 않음
- 미션 화면은 그대로 유지
- 미션 세션 종료 금지
- 상단 X 종료 버튼과 기능 혼동 금지

## 배치

- 하단 입력 행의 가장 오른쪽
- 별도의 외부 절대좌표가 아닌 입력 행 내부에 포함
- 버튼 전체가 Viewport 안에 표시
- 버튼 우측에 Safe Area 포함 최소 `12px` 확보

## 크기

- 최소 `48×48px`
- 권장 `52px~58px`
- 원형 또는 둥근 사각형
- X 아이콘 완전 중앙 정렬
- 아이콘 일부 잘림 금지
- 버튼 테두리 및 그림자 전체 표시

## 접근성

```text
aria-label="텍스트 입력창 닫기"
```

상단 미션 종료 버튼과 접근성 이름을 구분한다.

---

# 10. 절대 위치 감사

현재 X 버튼 또는 입력 Composer에 다음 스타일이 있는지 확인한다.

```text
position: absolute
position: fixed
right: 음수 값
translateX()
width: 100vw
left: 0 + 추가 margin
calc(100% + ...)
```

## 원칙

- X 버튼 자체를 Viewport 기준 `fixed` 또는 `absolute`로 배치하지 않음
- Composer 행 내부의 일반 Grid/Flex 요소로 배치
- 하단 Composer Shell만 화면 하단에 고정하거나 기존 Layout 정책 사용
- X 버튼 위치를 기기별 임시 Pixel 값으로 조정하지 않음
- `right: 8px` 하나만 수정하고 완료 처리하지 않음

---

# 11. 부모 컨테이너 Overflow 감사

다음 상위 요소를 확인한다.

- 미션 페이지 Root
- 앱 Viewport
- 텍스트 Composer Shell
- Device Frame Viewport
- 모바일 PWA Root

다음 속성이 X 버튼을 잘라내는지 확인한다.

```text
overflow: hidden
overflow-x: clip
clip-path
mask
border-radius
transform
contain
```

프레임 내부에서 필요한 `overflow: hidden`은 유지할 수 있으나, Composer 전체가 프레임 내부에 들어오도록 너비를 먼저 수정한다.

X 버튼이 잘리지 않게 한다는 이유로 앱 전체의 `overflow: hidden`을 무분별하게 제거하지 않는다.

---

# 12. iOS 소프트 키보드 대응

실제 iOS PWA에서는 소프트 키보드가 열릴 때 Layout Viewport와 Visual Viewport 높이가 달라질 수 있다.

확인 대상:

```text
window.innerHeight
window.visualViewport.height
window.visualViewport.offsetTop
env(safe-area-inset-bottom)
```

## 목표

- 키보드가 열리면 Composer가 키보드 위에 표시됨
- Composer가 키보드 뒤로 가려지지 않음
- X 버튼이 오른쪽으로 밀리지 않음
- 키보드 애니메이션 중 가로 Layout Shift 없음
- 화면이 불필요하게 확대되지 않음
- 입력창 Focus 시 페이지 전체가 옆으로 이동하지 않음

현재 프로젝트에 Visual Viewport 대응 코드가 있다면 재사용한다.

새 Listener를 추가할 경우 반드시 Cleanup하고 중복 등록을 방지한다.

---

# 13. Android 키보드 대응

Android Chrome 및 설치형 PWA에서도 다음을 확인한다.

- `resize` 방식
- `interactive-widget` 설정 여부
- 키보드 표시 후 Composer 위치
- 뒤로가기 버튼으로 키보드만 닫은 경우
- X 버튼으로 Composer를 닫은 경우
- 키보드가 닫힌 뒤 원래 레이아웃 복원

Android에서 정상이라는 이유로 iOS QA를 생략하지 않는다.

# 14. 모바일 우선 크기 기준

## 390px 전후

권장 예시:

```text
좌우 Shell 여백: 12px~16px
입력창: 남은 너비
전송 버튼: 54px~58px
닫기 버튼: 52px~56px
요소 간 간격: 8px
```

## 360px

- 입력창이 우선 축소
- 전송·닫기 버튼은 최소 터치 크기 유지
- Placeholder가 잘릴 수는 있으나 버튼은 잘리면 안 됨

## 320px

권장 조정:

- 좌우 여백 약 `8px~10px`
- 요소 간격 약 `6px`
- 전송 버튼 약 `48px~52px`
- 닫기 버튼 약 `48px~52px`
- 입력창 `min-width: 0`

320px에서도 X 버튼 전체가 표시되어야 한다.

# 15. 입력창이 여러 줄이 되는 경우

텍스트 입력이 길어져 입력창 높이가 커지는 경우:

- 전송·닫기 버튼은 Composer 하단 또는 중앙 기준으로 정렬
- 버튼이 화면 밖으로 밀리지 않음
- 최대 입력창 높이 설정
- 최대 높이 이후 입력창 내부 스크롤
- Composer 전체가 질문 말풍선과 과도하게 겹치지 않음
- 소프트 키보드 위에서 사용할 수 있음

기존 Textarea 자동 확장 정책이 있다면 유지한다.

# 17. 닫기 시 Draft 처리

X 버튼 클릭 시 현재 작성 중인 Draft를 유지할지 삭제할지는 기존 정책을 따른다.

이번 UI 수정에서 Draft 정책을 임의 변경하지 않는다.

기존 정책이 불분명하면 현재 구현 동작을 유지하고 작업 완료 보고에 기록한다.

# 21. 완료 기준

다음 조건을 모두 충족해야 완료로 판정한다.

- 실제 모바일 PWA에서 하단 X 버튼 전체가 표시됨
- X 버튼 오른쪽이 화면 밖으로 나가지 않음
- X 버튼 오른쪽에 최소 12px 수준의 안전 여백이 있음
- 입력창·전송·X 버튼이 하나의 안정적인 행으로 배치됨
- 입력창이 남은 너비만 사용함
- `min-width: 0` 또는 동등한 축소 처리가 적용됨
- 전송 및 X 버튼의 최소 터치 크기가 유지됨
- 320px 모바일에서도 X 버튼이 잘리지 않음
- iOS 키보드가 열린 상태에서도 X 버튼이 잘리지 않음
- Android 키보드가 열린 상태에서도 정상 표시됨
- 가로 스크롤이 발생하지 않음
- 모바일 Safe Area가 반영됨
- X 버튼 클릭 시 텍스트 입력 UI만 닫힘
- X 버튼 클릭 시 미션은 종료되지 않음
- 수동 입력 모드가 유지됨
- 텍스트 전송·진행률·미션 로직에 회귀가 없음
- 실제 iOS 또는 Android PWA 스크린샷 QA 통과
- lint 통과
- typecheck 통과
- 관련 test 통과
- production build 통과
