# 부모 궁금증 처리 엔진(Parent Query Router) v1.0 — 초등학교 4학년 구현 요청

## 1. 작업 목적

부모가 케이에게 자유 입력으로 아이에 관한 질문을 남겼을 때, 해당 질문을 초등학교 4학년 발달 단계와 서비스 안전 원칙에 따라 `CRISIS`, `RED`, `GREEN`으로 분류하고, 허용된 질문만 아이 대화에 편입하도록 구현한다.

이 기능의 목적은 부모의 궁금증을 해소하는 것이지만, 케이가 아이 몰래 정보를 캐내거나 부모 대신 추궁하는 도구가 되는 것을 막는 것이 더 높은 우선순위다.

이번 구현 범위는 **초등학교 4학년만** 해당한다. 다른 학년에는 자동 확장하지 않는다.

---

## 2. 최상위 안전 원칙 — 구현 불변식

아래 규칙은 UI 편의, 응답률, 질문 등록률, LLM 분류 결과보다 항상 우선한다.

1. 부모 입력은 기본적으로 `fail-closed`로 처리한다.
   - 4학년 Green List에 명확히 매칭되는 경우에만 아이 대화에 편입한다.
   - 애매하거나 분류 근거가 부족하면 `RED`로 처리한다.
   - 미분류 입력을 임의로 Green으로 통과시키지 않는다.

2. 부모 요청은 아이 질문의 트리거가 될 수는 있지만, 부모 문장을 아이에게 그대로 전달하지 않는다.
   - 아이에게 전달되는 문구는 항상 케이의 중립적 관심 표현으로 재작성한다.
   - “엄마가 물어봤어”, “아빠가 궁금해해”, “부모님께 말해 줄래?” 등 부모 개입을 노출하지 않는다.

3. 위기 신호는 Green/Red 판정보다 먼저 처리한다.
   - 자해·자살·학대·성적 피해·폭력·심한 소외·섭식 이상 등 위기 신호가 감지되면 아이 질문 대기열에 넣지 않는다.
   - `CRISIS` 경로로 라우팅한다.
   - 위기 감지 규칙과 사용자 노출 문구는 임상 전문가 검증 전 Production에 활성화하지 않는다.

4. 아이가 답변하지 않을 권리를 보장한다.
   - 아이가 “몰라”, “없어”, “말하기 싫어”, “넘어갈래”라고 하면 꼬리질문 없이 종료한다.
   - 거절 이유를 추측하거나 부모에게 원문 그대로 전달하지 않는다.

5. 부모 질문에 대한 아이의 답변은 기존 정책대로 재확인한다.
   - 부모 질문에서 파생된 답변에만 재확인 절차를 적용한다.
   - 아이가 최종 확인한 내용만 부모에게 전달한다.
   - STT 1차 결과를 그대로 부모 답변으로 확정하지 않는다.

## 3. 기존 질문 제한 정책과의 통합

기존 부모 질문 정책을 유지한다.

- 아이별 주 3회
- 아이별 하루 최대 1건
- KST 기준
- 주간 기준: 월요일 00:00:00 ~ 일요일 23:59:59
- 초안 모달을 열거나 취소한 경우 차감하지 않음
- 부모가 최종 승인하고 DB 저장에 성공한 시점에만 차감
- 동일 요청 재시도·중복 클릭으로 중복 차감 금지
- Red 또는 Crisis로 차단된 질문은 횟수 차감 금지
- Green 질문만 질문 대기열과 Q&A 목록에 등록

실제 허용 조건:

```text
weekly_used_count < 3
AND daily_registered_count < 1
```

## 4. 고정 판정 흐름

판정 순서를 변경하지 않는다.

```text
부모 입력
   │
   ├─▶ [1] 인증·부모-아이 권한·대상 학년 확인
   │        └─ 4학년이 아니면 이번 정책 미적용
   │
   ├─▶ [2] 위기 신호 감지?
   │        ├─ YES → CRISIS 경로
   │        └─ NO
   │
   ├─▶ [3] Red List 패턴 또는 의미 매칭?
   │        ├─ YES → RED 경로
   │        └─ NO
   │
   ├─▶ [4] Green List 화이트리스트 매칭?
   │        ├─ YES → GREEN 후보
   │        └─ NO → RED fallback
   │
   ├─▶ [5] Green 4조건 최종 검증
   │        ├─ 모두 충족 → GREEN 확정
   │        └─ 하나라도 실패 → RED
   │
   └─▶ [6] GREEN이면 초안 모달 생성
```

**판정 순서 고정:** `CRISIS → RED → GREEN → DEFAULT_RED`

Green을 먼저 검사하거나, LLM이 Green이라고 판정했다는 이유만으로 Red·Crisis 검사를 건너뛰면 안 된다.

## 5. 분류 아키텍처

### 5.1 권장 구조

LLM 단독 판정은 금지한다.

```text
정규화
→ Crisis deterministic gate
→ Red deterministic/semantic gate
→ LLM candidate classification
→ Green whitelist validator
→ deterministic final gate
```

LLM 역할:

- 부모 의도 요약
- Green 8개 영역 중 후보 1개 선택
- Red 후보 영역 선택
- 질문 개수 추정
- 부모 질문에서 핵심 궁금증 추출
- Green 확정 후 아이용 문장 재작성

최종 `route` 결정은 정책 엔진이 수행한다.

### 5.2 LLM 출력 예시

```json
{
  "candidate_route": "GREEN",
  "candidate_area": "interest",
  "confidence": 0.93,
  "matched_evidence": ["요즘 빠진 것"],
  "detected_risks": [],
  "question_count": 1
}
```

### 5.3 Green 확정 조건

아래 4개 조건을 모두 만족해야 한다.

```text
1. 원인·갈등·비밀 캐기 없음
2. 아이가 질문 사실을 알아도 부담·방어가 크지 않음
3. 긍정 또는 중립 정서
4. 답을 유도하거나 특정 결론을 전제하지 않음
```

추가 조건:

```text
candidate_area ∈ 4학년 Green List 8개
AND crisis_match = false
AND red_match = false
AND question_count = 1
AND whitelist_evidence is not empty
```

## 6. GREEN LIST — 초등학교 4학년 대화 편입 허용

### 6.1 공통 처리 규칙

- Green 질문은 아이에게 전달하기 전에 초안 모달에서 부모 확인을 받는다.
- 부모 원문을 그대로 사용하지 않는다.
- 부모 확인용 질문과 아이 실제 질문을 분리 저장한다.
- 한 번에 한 질문만 허용한다.
- 세션당 부모 질문 최대 1개다.
- 기존 미션 로테이션 안에 자연스럽게 삽입한다.
- 기존 미션 유효 답변 완료 조건에 포함하지 않는다.
- 아이가 거절하면 꼬리질문 없이 종료한다.
- 부모가 시켰다는 사실을 아이에게 노출하지 않는다.

### 6.2 Green 데이터

> 아래 문구는 상담사·임상 검증 전 초안이며, 초기값은 모두 `expert_review_status='PENDING_REVIEW'`로 저장한다.

| green_id | area | 부모 의도 예시 | 부모 확인용 초안 | 아이 실제 질문 | review_flag |
|---|---|---|---|---|---|
| G-01 | interest | 좋아하는 것, 관심사, 요즘 빠진 것 | 요즘 가장 빠져 있는 것이 있는지 물어볼까요? | 요즘 네가 제일 빠져 있는 거 있어? | 적합 |
| G-02 | school_fun | 학교에서 재밌었던 것 | 오늘 학교에서 가장 재밌었던 순간이 무엇인지 물어볼까요? | 오늘 학교에서 제일 재밌었던 순간이 뭐였어? | 적합 |
| G-03 | subject_like | 좋아하는 과목, 해볼 만한 수업 | 요즘 재미있거나 해볼 만한 수업이 있는지 물어볼까요? | 요즘 수업 중에 재미있거나 해볼 만한 거 있어? | 수정 반영 |
| G-04 | food_pref | 먹고 싶은 것, 좋아하는 음식 | 요즘 가장 먹고 싶은 음식이 있는지 물어볼까요? | 요즘 제일 먹고 싶은 거 있어? | 적합 |
| G-05 | pride | 잘한 것, 자랑거리, 뿌듯한 일 | 오늘 스스로 잘했다고 느낀 일이 있는지 물어볼까요? | 오늘 스스로 “이건 좀 잘했다” 싶은 거 있었어? | 적합 |
| G-06 | content | 요즘 보는 영상·게임 | 요즘 자주 보는 영상이나 즐기는 게임이 있는지 물어볼까요? | 요즘 제일 자주 보는 영상이나 하는 게임 있어? | 적합 |
| G-07 | weekend | 주말에 하고 싶은 것 | 이번 주말에 하고 싶은 것이 있는지 물어볼까요? | 이번 주말에 하고 싶은 거 정해둔 거 있어? | 적합 |
| G-08 | dream | 장래희망, 되고 싶은 것 | 요즘 멋있다고 느끼는 직업이나 해보고 싶은 일이 있는지 물어볼까요? | 요즘 멋있다고 느끼는 직업이나 해보고 싶은 거 있어? | 적합 |

문구 구현 규칙:

- child-facing 문구에 `${childName}이가` 같은 3인칭 표현을 쓰지 않는다.
- 이름을 쓸 경우 호격으로만 사용한다.
- 이름 호격 조사가 불확실하면 이름을 생략하고 2인칭으로 말한다.
- 부모 확인용 문장에는 “물어볼까요?”를 사용한다.
- 아이 실제 질문에는 “부모에게 말해 줄래?”를 포함하지 않는다.

## 7. RED LIST — 아이 대화 편입 차단, 부모 코칭

### 7.1 처리 원칙

Red 질문은 아이 질문 대기열에 등록하지 않는다.

Red 경로에서 해야 할 일:

1. 아이에게 그대로 전달할 수 없음을 짧게 설명
2. 부모를 비난하지 않음
3. 왜 위험한지 한 문장으로 안내
4. 가능한 경우 안전한 Green 대체 질문 1개 제안
5. 대체 질문도 자동 등록하지 않고 부모가 새로 확인해야 함
6. 부모 질문 횟수는 차감하지 않음

### 7.2 Red 데이터

| red_id | area | 차단 의도·패턴 | 부모 코칭 문구 | 안전 대안 예시 | review_flag |
|---|---|---|---|---|---|
| R-01 | emotion_cause | 기분의 원인 캐기, “~때문인 것 같은데”, 특정 이유 단정 | 케이가 원인을 대신 캐묻기는 어려워요. 아이의 기분을 미리 정하지 말고 편하게 이야기할 여지를 남겨 주세요. | 오늘 마음에 남은 이야기가 있는지 직접 편하게 물어보세요. | 적합 |
| R-02 | peer_conflict | 친구 갈등·다툼·따돌림 확인 | 케이가 친구 관계를 대신 캐물으면 아이가 마음을 닫을 수 있어요. 걱정이 이어지면 담임이나 상담 선생님과 상의해 주세요. | 요즘 학교에서 재밌었던 순간을 물어볼 수 있어요. | 적합 |
| R-03 | academic_pressure | 성적, 공부량, 숙제, 학원 태도 추궁 | 공부 이야기를 추궁하면 아이가 대화를 피할 수 있어요. 압박보다 아이가 느끼는 난이도나 흥미를 직접 물어보세요. | 요즘 재미있거나 해볼 만한 수업이 있는지 물어볼 수 있어요. | 적합 |
| R-04 | secret | 비밀·거짓말 적발, 숨긴 것 확인 | 케이는 아이 몰래 무언가를 알아내는 도구가 아니에요. 아이와의 신뢰를 지키기 위해 이 요청은 전달하지 않아요. | 대체 질문 자동 제안 없음 | 적합 |
| R-05 | family_complaint | 가족·집안에 대한 불만, 특정 가족 평가 요구 | 가족에 대한 아이 마음을 케이가 대신 캐묻지 않아요. 편안한 자리에서 직접 이야기해 주세요. | 아이와 함께하고 싶은 주말 활동을 물어볼 수 있어요. | 적합 |
| R-06 | fallback | Green 미매칭, 애매한 자유 입력, 근거 부족 | 이 질문은 4학년 Green List에 명확히 해당하지 않아 아이에게 전달하지 않아요. 아이를 추궁하지 않는 관심사·학교의 즐거운 경험·먹고 싶은 것·주말 계획 같은 질문으로 바꿔 주세요. | Green 8개 영역 중 1개 선택 유도 | 적합 |

### 7.3 Red의 안전 대안 처리

Red가 감지됐다고 해당 부모 문장을 자동으로 Green 질문으로 바꿔 바로 등록하면 안 된다.

```text
RED 판정
→ 코칭 표시
→ 선택 가능한 안전 대안 1개 제안
→ 부모가 대안을 선택
→ 별도 Green 검증
→ 초안 모달
→ 부모 최종 승인
```

## 8. CRISIS 경로

### 8.1 우선 감지 범위

- 자해
- 자살
- 죽고 싶다는 표현
- 학대
- 성적 피해
- 심각한 폭력
- 지속적·심한 따돌림 또는 소외
- 섭식 이상
- 아이 안전에 즉각적인 우려가 있는 표현

### 8.2 처리 원칙

- 아이 질문 대기열 등록 금지
- 부모 질문 횟수 차감 금지
- 케이가 아이에게 우회적으로 캐묻지 않음
- 임상 검증된 안내 화면으로 라우팅
- 위기 신호 원문을 일반 로그에 저장하지 않음
- 내부 보안 로그에는 최소한의 분류 코드만 저장
- 반복 감지 시 별도 안전 이벤트로 기록하는 구조 검토

### 8.3 Production 잠금

```text
expert_review_status = 'PENDING_REVIEW'
is_active = false
production_enabled = false
```

임상 전문가 승인 전:

- Crisis 키워드·의미 분류 로직의 Production 사용자 노출 금지
- 임시 일반 안내 문구를 임의 작성하여 노출 금지
- 내부 테스트 환경에서만 검증

## 9. UI/UX 요구사항

### 9.1 GREEN 경로

```text
판정 중
→ Green 확정
→ 초안 질문 모달
→ 부모 수정·승인
→ 질문 등록
```

초안 모달 필수 항목:

```text
아이에게 이렇게 물어볼까요?

대상 아이: 안서현
이번 주 질문 1/3
오늘 질문 0/1

질문 초안:
[요즘 가장 빠져 있는 것이 있는지 물어볼까요?]

한 번에 한 가지 질문만 전달할 수 있어요.
케이는 아이와 자연스럽게 대화할 수 있는 순간에 질문하고,
답변을 다시 확인한 뒤 부모님께 알려드려요.

[취소] [질문 등록하기]
```

### 9.2 RED 경로

Red는 초안 모달로 바로 보내지 않는다.

```text
이 질문은 케이가 아이에게 대신 묻지 않아요.

친구 관계의 원인을 캐묻는 질문은 아이가 부담을 느낄 수 있어요.
대신 아래처럼 부담 없는 질문은 사용할 수 있어요.

[요즘 학교에서 가장 재밌었던 순간이 무엇인지 물어볼까요?]

[닫기] [안전한 질문으로 바꾸기]
```

`안전한 질문으로 바꾸기`를 누르면 Green 재검증 후 초안 모달로 이동한다.

### 9.3 CRISIS 경로

- `아이에게 물어보기` 버튼 비노출 또는 비활성화
- 일반 Q&A 등록 흐름과 분리
- 임상 검증된 별도 안내 UI 사용
- 검증 전 Production에서는 기능 잠금

## 10. 다중 질문 처리

한 번에 한 질문만 허용한다.

부모 입력:

```text
요즘 뭘 좋아하는지, 학교에서 재밌는 건 뭔지, 주말에 뭐 하고 싶은지 물어봐 줘.
```

처리:

1. 질문 3개 감지
2. Green 후보 영역 3개 추출
3. 한 번에 한 질문만 가능하다고 안내
4. 부모가 1개를 선택하게 함
5. 선택한 1개만 초안 모달로 이동
6. 주간·일일 횟수는 실제 등록 1건만 차감

자동으로 임의의 1개를 선택해 등록하지 않는다.

## 11. 질문 대기열·미션 연동

Green 승인 질문만 기존 부모 질문 대기열에 등록한다.

필수 규칙:

- `source='PARENT_QUERY_ROUTER'`
- `source_grade=4`
- `route='GREEN'`
- `green_id` 필수
- `policy_version='PQR-G4-1.0'`
- 부모 원문과 아이 질문 문구 분리 저장
- 부모 원문은 최소 수집·보존 정책 적용
- 아이 실제 질문은 미션 중 자연스러운 시점에 최대 1개 삽입
- 기존 미션 유효 답변 10개에 포함하지 않음
- 아이가 거절하면 꼬리질문 금지
- 답변 후 재확인 필수
- 최종 확인 답변만 부모 Q&A에 표시

## 15. 테스트 요구사항

### 15.1 판정 순서

- Crisis와 Green 키워드가 함께 있어도 Crisis
- Red와 Green 키워드가 함께 있어도 Red
- Green 근거 없음 → default Red
- LLM confidence가 높아도 whitelist 미매칭 → Red
- LLM이 Green이라 해도 Red 패턴 감지 → Red

### 15.2 Green

| 부모 입력 | 기대 |
|---|---|
| 요즘 서현이가 뭐에 빠져 있는지 궁금해 | G-01 |
| 오늘 학교에서 뭐가 제일 재밌었는지 물어봐 줘 | G-02 |
| 요즘 좋아하는 과목이 있는지 궁금해 | G-03 |
| 요즘 먹고 싶은 음식이 있는지 물어봐 줘 | G-04 |
| 오늘 스스로 잘했다고 느낀 게 있는지 물어봐 | G-05 |
| 요즘 자주 보는 영상이나 게임이 궁금해 | G-06 |
| 이번 주말에 하고 싶은 게 있는지 물어봐 | G-07 |
| 요즘 되고 싶은 게 있는지 물어봐 줘 | G-08 |

### 15.3 Red

| 부모 입력 | 기대 |
|---|---|
| 어제 속상해 보였는데 친구 때문인지 캐봐 | R-01 또는 R-02 |
| 누구랑 싸웠는지 알아봐 | R-02 |
| 시험 점수가 왜 떨어졌는지 물어봐 | R-03 |
| 나한테 숨기는 게 있는지 알아봐 | R-04 |
| 엄마를 싫어하는지 물어봐 | R-05 |
| 위 목록과 명확히 매칭되지 않는 애매한 질문 | R-06 |

### 15.4 다중 질문

- Green 2개 이상 → 선택 UI, 자동 등록 금지
- Green+Red → Red
- Green+Crisis → Crisis
- Red 2개 이상 → 가장 높은 위험 규칙 기록, 아이 전달 금지

### 15.5 제한

- 주 1·2·3회 등록 성공
- 4회 차단
- 같은 날 두 번째 질문 차단
- 다음 날 일일 한도 초기화
- 다음 주 월요일 주간 한도 초기화
- 취소·Red·Crisis·API 실패는 횟수 미차감
- 중복 클릭·네트워크 재시도 중복 등록 0건

### 15.6 미션 E2E

1. Green 질문 등록
2. 부모 Q&A `질문 대기 중`
3. 아이 다음 미션에서 자연스럽게 질문
4. 부모 개입 문구 미노출
5. 아이 답변
6. 케이 재확인
7. 아이 최종 확인
8. 부모 Q&A `답변 완료`
9. 미션 유효 답변 10개에 미포함
10. 다른 가족 데이터 혼입 0건

### 15.7 아이 거부 E2E

1. 아이가 “말하기 싫어” 응답
2. 꼬리질문 0회
3. 상태 `DECLINED`
4. 부모에게 “아이가 이번 질문에는 답변하지 않기로 했어요” 표시
5. 거부 원문·이유 추측 비노출

## 19. 추가 설계 의견

### 19.1 기존 주 3회 정책과 하루 1회 정책을 함께 적용

원안의 “하루 최대 1건”만 적용하면 주 7회가 가능해 기존 정책과 충돌한다. 기존 정책을 유지하여 **아이별 주 3회 + 하루 1회**로 구현한다.

### 19.2 아이 질문 문구에서 3인칭 이름 표현 제거

`“요즘 서현이가 제일 빠져 있는 거 있어?”`는 아이에게 직접 말하는 문장으로 어색하다. 아이에게는 `“요즘 네가 제일 빠져 있는 거 있어?”`처럼 2인칭으로 질문한다.

### 19.3 Red를 막힌 화면으로 끝내지 않음

Red 질문은 아이에게 전달하지 않되, 가능한 경우 검증된 Green 대안 한 개를 제시한다. 단, 자동 등록하지 않고 부모가 다시 확인해야 한다.

### 19.4 정책 데이터는 초기에는 관리자 수정형 DB보다 버전 관리 파일 권장

상담사 검토 전 문구와 규칙을 운영자가 즉시 수정할 수 있게 만들면 정책 일관성이 깨질 수 있다. 초기에는 Repository의 버전 관리 정책 번들로 운영하고, 승인 이력과 정책 버전을 남긴다.

### 19.5 Crisis는 골격만 구현하고 Production 노출 잠금

현재 문구와 감지 규칙이 `PENDING_REVIEW`이므로 Production에서 애매한 위기 안내를 임의 제공하지 않는다. 임상 검증 후 별도 승인 절차로 활성화한다.
