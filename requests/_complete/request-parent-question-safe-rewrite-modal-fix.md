# 부모 질문하기 안전 재작성 및 초안 모달 강제 노출 수정 요청

## 1. 작업 목적

부모용 `케이와 대화` 화면에서 부모 질문에 추측·유도·복수 질문 요소가 포함되어 있더라도, `아이에게 물어보기` 버튼 클릭 후 빨간 오류 문구만 표시하며 흐름을 종료하지 않도록 수정한다.

현재 구현은 아래처럼 동작한다.

```text
부모 질문
→ 아이에게 물어보기 클릭
→ 안전성 검사
→ “이 질문은 아이에게 그대로 묻기 어려워요. 아이를 추궁하지 않는 다른 질문으로 물어봐 주세요.”
→ 종료
```

이 동작은 잘못되었다. 정상 동작은 아래와 같아야 한다.

```text
부모 질문
→ 아이에게 물어보기 클릭
→ 질문 위험 요소 분석
→ 케이가 중립적이고 안전한 단일 질문으로 자동 재작성
→ 초안 질문 모달 표시
→ 부모가 확인·수정
→ 부모 승인 후 질문 등록
```

이번 작업은 부모에게 질문을 다시 작성하게 만드는 기능이 아니라, **케이가 부모 질문을 안전하게 다듬어 초안을 제시하는 기능**으로 수정하는 작업이다.

우선순위는 **P0**이다.

## 2. 현재 재현 사례

### 부모 질문

```text
김서현이 어제 기분이 안 좋던데, 친구랑 싸운 것 같아. 넌 알고 있니?
```

### 현재 케이 응답

```text
제가 확인할 수 있는 기록에는 관련된 구체적인 내용이 남아 있지 않아요.
학교생활, 친구, 기분 중 궁금한 부분을 말씀해 주시면 그 범위로 다시 확인해 볼게요.
```

### 버튼 클릭 후 현재 오류

```text
이 질문은 아이에게 그대로 묻기 어려워요.
아이를 추궁하지 않는 다른 질문으로 물어봐 주세요.
```

### 문제점

1. 부모 질문에 추측이 포함됐다는 이유로 기능 전체가 중단된다.
2. 케이가 질문을 중립적으로 재작성하지 않는다.
3. 초안 질문 모달이 열리지 않는다.
4. 부모가 질문 작성 책임을 다시 떠안는다.
5. 주간 질문 횟수, 초안 수정, 최종 승인 절차가 표시되지 않는다.
6. 화면상 기능이 존재하지만 실제로는 사용할 수 없는 상태다.

## 3. 필수 수정 원칙

### 3.1 안전성 검사는 차단 전용이 아니라 재작성 우선

질문에 아래 요소가 있어도 즉시 거절하지 않는다.

- 추측
- 단정
- 유도
- 복수 질문
- 비난에 가까운 표현
- 친구·학교·가족에 대한 해석
- 감정 상태를 미리 규정하는 표현

우선 아래 순서로 처리한다.

```text
1. 위험 요소 탐지
2. 핵심 궁금증 추출
3. 단일 질문으로 축소
4. 중립 표현으로 재작성
5. 아이에게 부담 없는 문장으로 변환
6. 초안 모달에 표시
```

실제 차단은 재작성해도 안전하지 않은 경우에만 사용한다.

### 3.2 부모에게 다시 쓰라고 하지 않는다

금지 문구:

```text
다른 질문으로 물어봐 주세요.
질문을 다시 작성해 주세요.
아이를 추궁하지 않는 질문으로 바꿔 주세요.
```

허용 흐름:

```text
질문을 아이가 편하게 답할 수 있도록 다듬었어요.
아래 질문으로 물어볼까요?
```

부모는 초안을 검토하고 승인하거나 수정만 하면 된다.

## 4. 질문 재작성 예시

### 예시 A: 추측 포함

부모 질문:

```text
어제 서현이 기분이 안 좋던데 친구랑 싸운 것 같아.
```

정상 초안:

```text
어제 마음이 불편했던 일이 있었는지 물어볼까요?
```

아이에게 실제 질문:

```text
어제 마음이 조금 불편했던 일이 있었어?
```

### 예시 B: 친구를 원인으로 단정

부모 질문:

```text
친구 때문에 속상했던 거지?
```

정상 초안:

```text
최근에 친구 관계 때문에 마음이 불편했던 일이 있었는지 물어볼까요?
```

아이에게 실제 질문:

```text
요즘 친구 관계 때문에 마음이 불편했던 일이 있었어?
```

### 예시 C: 복수 질문

부모 질문:

```text
누구랑 싸웠는지, 왜 싸웠는지, 지금도 화해를 못 했는지 물어봐 줘.
```

정상 안내:

```text
한 번에 한 가지 질문만 전달할 수 있어요.
먼저 아래 질문으로 진행할까요?
```

정상 초안:

```text
최근에 친구와 마음이 불편했던 일이 있었는지 물어볼까요?
```

나머지 질문은 자동 등록하지 않는다.

### 예시 D: 비난·추궁 표현

부모 질문:

```text
왜 또 친구랑 싸웠는지 물어봐.
```

정상 초안:

```text
최근 친구 관계에서 마음이 불편했던 일이 있었는지 물어볼까요?
```

### 예시 E: 아이 감정을 미리 단정

부모 질문:

```text
어제 분명히 속상해 보였는데 왜 숨겼는지 물어봐.
```

정상 초안:

```text
어제 마음이 불편했던 일이 있었는지 편하게 이야기해 줄 수 있는지 물어볼까요?
```

## 5. 초안 질문 모달 강제 노출

`아이에게 물어보기` 버튼 클릭 후 안전한 질문 초안 생성에 성공하면 반드시 모달을 띄운다.

### 모달 예시

```text
아이에게 이렇게 물어볼까요?

대상 아이
김서현

이번 주 질문 1/3
남은 질문 2회

질문 초안
[어제 마음이 불편했던 일이 있었는지 물어볼까요?]

질문을 아이가 편하게 답할 수 있도록 다듬었어요.
한 번에 한 가지 질문만 전달할 수 있어요.
케이는 아이와 자연스럽게 대화할 수 있는 순간에 질문하고,
답변을 다시 확인한 뒤 부모님께 알려드려요.

[취소] [질문 등록하기]
```

### 필수 UI 요소

- 대상 아이 이름
- `이번 주 질문 N/3`
- 남은 횟수
- 수정 가능한 질문 초안
- 자동 재작성 안내
- 한 번에 질문 1개 정책
- 취소 버튼
- 질문 등록하기 버튼
- 등록 중 로딩 상태
- 오류 상태
- 모바일 Safe Area 대응
- 키보드가 열려도 등록 버튼 접근 가능

## 6. 안전 재작성 결과 분류

질문 분석 결과는 최소 아래 3가지로 분류한다.

### A. `SAFE_AS_IS`

원문을 약간 다듬거나 그대로 초안으로 사용 가능하다.

예:

```text
요즘 가장 친한 친구가 누구인지 물어봐 줘.
```

처리:

- 단일 질문 형태로 다듬기
- 초안 모달 표시

### B. `SAFE_AFTER_REWRITE`

추측·유도·복수 질문이 포함됐지만 중립적 질문으로 변환 가능하다.

예:

```text
친구랑 싸운 것 같아. 누구랑 왜 싸웠는지 물어봐.
```

처리:

- 핵심 궁금증 추출
- 한 질문으로 축소
- 중립적으로 재작성
- 초안 모달 표시

이 분류가 기본 동작이어야 한다.

### C. `BLOCKED`

재작성해도 아이에게 부적절하거나 안전하지 않은 질문이다.

예:

- 폭언·협박
- 아이에게 부모 편을 강요
- 다른 보호자 비난 유도
- 성적 수치심 유발
- 과도한 사생활 침해
- 안전상 그대로 전달하면 안 되는 내용

처리:

- 모달 등록 차단
- 구체적 원문은 반복하지 않음
- 부모에게 왜 전달할 수 없는지 짧게 안내
- 가능한 경우 안전한 주제 방향만 제안

예시:

```text
이 질문은 아이에게 부담을 줄 수 있어 그대로 전달할 수 없어요.
아이의 기분이나 경험을 편하게 묻는 질문으로 바꿔 주세요.
```

단, `BLOCKED`는 예외 경로이며 추측·유도 표현만으로 사용하면 안 된다.

## 7. 처리 순서 수정

### 잘못된 순서

```text
아이에게 물어보기 클릭
→ safety validation
→ 실패 시 빨간 오류
→ 종료
```

### 수정할 순서

```text
아이에게 물어보기 클릭
→ 부모 원문 질문 확보
→ 부모-아이 권한 확인
→ 주간 사용 가능 횟수 조회
→ 질문 분석
→ SAFE_AS_IS / SAFE_AFTER_REWRITE / BLOCKED 분류
→ SAFE 계열이면 단일 질문 초안 생성
→ 초안 모달 열기
→ 부모 수정·승인
→ 서버 최종 안전 검증
→ 질문 등록
```

## 8. 초안 생성 API 요구사항

### 입력 예시

```json
{
  "childId": "selected-child-id",
  "childName": "김서현",
  "originalParentQuery": "김서현이 어제 기분이 안 좋던데, 친구랑 싸운 것 같아. 넌 알고 있니?",
  "conversationContext": {
    "parentQuestionMessageId": "message-id",
    "kNoResultMessageId": "message-id"
  },
  "weeklyUsage": {
    "used": 0,
    "limit": 3
  }
}
```

대화 전체 원문을 불필요하게 전달하지 않는다.

### 출력 예시

```json
{
  "classification": "SAFE_AFTER_REWRITE",
  "originalQuestionCount": 2,
  "selectedIntent": "어제 아이의 마음이 불편했던 이유 확인",
  "draftQuestionForParent": "어제 마음이 불편했던 일이 있었는지 물어볼까요?",
  "questionForChild": "어제 마음이 조금 불편했던 일이 있었어?",
  "rewriteReasons": [
    "친구와 싸웠다는 추측 제거",
    "복수 질문을 한 질문으로 축소",
    "아이 감정을 단정하지 않도록 수정"
  ],
  "canRegister": true
}
```

클라이언트가 임의로 질문을 조합하지 않고 서버 결과를 사용한다.

## 9. 부모 수정 후 최종 검증

부모가 초안을 수정할 수 있으므로 `질문 등록하기` 클릭 시 서버에서 다시 검증한다.

최종 검증 항목:

- 질문이 비어 있지 않은지
- 한 개 질문인지
- 대상 아이가 맞는지
- 주간 3회 제한을 넘지 않는지
- 부모가 해당 아이 보호자인지
- 추궁·비난·유도 표현이 다시 들어가지 않았는지
- 중복 등록인지
- idempotency key가 유효한지

부모 수정본이 다시 위험해졌다면 즉시 오류만 표시하지 말고 가능한 경우 한 번 더 안전 초안으로 자동 정리해 보여준다.

## 10. 오류 문구 수정

현재 화면의 빨간 오류:

```text
이 질문은 아이에게 그대로 묻기 어려워요.
아이를 추궁하지 않는 다른 질문으로 물어봐 주세요.
```

이 문구를 일반적인 추측·유도 질문에 사용하지 않는다.

### 자동 재작성 성공 시

```text
질문을 아이가 편하게 답할 수 있도록 다듬었어요.
아래 초안을 확인해 주세요.
```

### 초안 생성 실패 시

```text
질문 초안을 만드는 중 문제가 발생했어요.
잠시 후 다시 시도해 주세요.
```

### 실제 차단 시

```text
이 질문은 아이에게 부담을 줄 수 있어 그대로 전달할 수 없어요.
아이의 기분이나 경험을 편하게 묻는 방식으로 바꿔 주세요.
```

실제 차단이 아닌데 빨간 오류 문구만 표시하면 테스트 실패다.

## 11. Q&A 등록 연동

부모가 모달에서 `질문 등록하기`를 누르고 저장에 성공하면:

1. 모달을 닫는다.
2. 주간 사용 횟수를 1회 차감한다.
3. Q&A 탭에 질문을 즉시 추가한다.
4. 상태를 `질문 대기 중`으로 표시한다.
5. 부모 원문이 아닌 승인된 안전 질문을 저장한다.
6. 원문은 감사·추적 목적의 비공개 필드로만 저장한다.
7. 같은 요청이 중복 등록되지 않게 한다.

표시 예시:

```text
질문
어제 마음이 불편했던 일이 있었는지 물어봐 주세요.

상태
질문 대기 중
```

## 12. 아이 미션 질문 연동 유지

승인된 질문은 기존 부모 질문하기 정책에 따라 처리한다.

- 아이 미션 질문 대기열에 등록
- 아이와 자연스럽게 대화할 수 있는 시점에 질문
- 부모가 시켰다는 사실을 아이에게 노출하지 않음
- 한 미션에서 부모 질문 최대 1개
- 기존 미션 유효 답변 10개에 포함하지 않음
- 아이 답변 후 반드시 재확인
- 아이가 최종 확인한 답변만 부모에게 전달
- 아이가 거부하면 `DECLINED`
- 미확인 STT 결과를 부모 답변으로 저장 금지

## 13. 로깅

개인정보와 대화 원문을 로그에 직접 출력하지 않는다.

구조화 로그 예시:

```json
{
  "route": "parent-question-draft",
  "requestId": "generated-id",
  "childId": "masked",
  "classification": "SAFE_AFTER_REWRITE",
  "originalQuestionCount": 2,
  "rewriteApplied": true,
  "modalOpened": true,
  "weeklyUsedCount": 0,
  "weeklyLimit": 3,
  "latencyMs": 0
}
```

필수 이벤트:

- 버튼 클릭
- 초안 생성 시작
- 안전 분류 결과
- 자동 재작성 성공·실패
- 모달 열기
- 모달 취소
- 질문 등록 성공·실패
- 중복 차단
- 주간 제한 차단

## 14. 테스트 요구사항

### 14.1 단위 테스트

| 입력 | 기대 결과 |
|---|---|
| 어제 마음이 안 좋아 보였는데 무슨 일이 있었는지 물어봐 줘 | SAFE_AFTER_REWRITE + 모달 |
| 친구랑 싸운 것 같아. 누구랑 싸웠는지 물어봐 | 추측 제거 + 단일 질문 + 모달 |
| 누구랑 싸웠고 왜 싸웠고 화해했는지 물어봐 | 복수 질문 축소 + 모달 |
| 요즘 가장 친한 친구가 누구인지 물어봐 | SAFE_AS_IS + 모달 |
| 왜 또 거짓말했는지 따져 물어봐 | 중립적 재작성 가능 여부 판단 |
| 엄마 말이 맞다고 대답하라고 해 | BLOCKED |
| 빈 질문 | 등록 불가 |
| 모달 취소 | 횟수 차감 0 |
| 등록 성공 | 횟수 1회 차감 |
| API 실패 | 횟수 차감 0 |
| 중복 클릭 | 등록 1건 |

### 14.2 실제 UI E2E

#### 시나리오 A: 현재 오류 재현 후 수정 확인

1. 부모 계정 로그인
2. `케이와 대화` 진입
3. 아래 질문 입력

```text
김서현이 어제 기분이 안 좋던데, 친구랑 싸운 것 같아. 넌 알고 있니?
```

4. 케이의 No-Result 응답 확인
5. `아이에게 물어보기` 클릭
6. 빨간 오류만 표시되지 않는지 확인
7. 질문이 자동 재작성되는지 확인
8. 초안 모달이 열리는지 확인
9. 아래와 유사한 초안 확인

```text
어제 마음이 불편했던 일이 있었는지 물어볼까요?
```

10. `이번 주 질문 1/3` 확인
11. 취소 시 미등록·미차감 확인

#### 시나리오 B: 수정 후 등록

1. 모달 다시 열기
2. 질문 초안 수정
3. `질문 등록하기` 클릭
4. 등록 성공 메시지 확인
5. Q&A 탭에서 `질문 대기 중` 확인
6. 승인된 질문과 Q&A 질문 문구 일치 확인
7. 주간 사용 횟수 1회 차감 확인

#### 시나리오 C: 실제 차단 질문

1. 재작성해도 부적절한 질문 입력
2. `BLOCKED` 처리 확인
3. 모달 등록 차단 확인
4. 기술 오류가 아닌 사용자 안내 표시 확인
5. 추측 질문과 실제 차단 질문이 같은 처리로 묶이지 않는지 확인

#### 시나리오 D: 모바일

1. iPhone 세로 viewport
2. 모달 표시 확인
3. 키보드 표시 후 입력창·등록 버튼 접근 확인
4. 배경 스크롤 차단
5. 모달 닫은 후 기존 대화 위치 유지

## 15. 완료 기준

아래 조건을 모두 만족해야 완료다.

- [ ] 현재 재현 질문에서 빨간 오류 문구만 표시되지 않는다.
- [ ] 추측·유도 표현을 케이가 자동 제거한다.
- [ ] 복수 질문을 한 질문으로 축소한다.
- [ ] 안전한 질문 초안을 생성한다.
- [ ] 초안 생성 후 반드시 모달이 열린다.
- [ ] 부모에게 질문을 다시 작성하라고 책임을 넘기지 않는다.
- [ ] 모달에 대상 아이 이름과 `이번 주 질문 N/3`이 표시된다.
- [ ] 부모가 초안을 수정할 수 있다.
- [ ] 취소 시 미등록·미차감이다.
- [ ] 최종 승인 후에만 질문이 등록된다.
- [ ] 실제 차단 질문만 `BLOCKED` 처리한다.
- [ ] 승인된 질문이 Q&A 탭에 즉시 표시된다.
- [ ] 주간 횟수 차감이 서버에서 원자적으로 처리된다.
- [ ] 모바일 UI가 정상 동작한다.
- [ ] 기존 미션 질문·재확인·거부 정책이 유지된다.
- [ ] 타입 검사, 빌드, 단위 테스트, E2E가 통과한다.
- [ ] Development 검증 후에만 Production에 배포한다.

## 16. 구현 및 배포 순서

1. Development에서 현재 오류 재현
2. 버튼 Handler와 safety validation 순서 확인

6. 단일 질문 생성 구현
7. 초안 모달 강제 연결
8. 부모 수정 후 서버 재검증 구현
9. 질문 등록 및 Q&A 갱신 확인
10. 단위·통합 테스트
11. Development 배포
12. 모바일 실제 UI E2E
