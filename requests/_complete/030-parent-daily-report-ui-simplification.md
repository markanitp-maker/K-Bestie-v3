# REQUEST 030 — 부모 일일 리포트 화면 단순화 및 주간 표시 기준 통일

## 1. 목적

부모 `리포트 > 일간` 화면에서 불필요한 상태값, placeholder, 월 구분, 감정 장식, 점수 UI, 불필요한 공백을 제거하고 실제 생성된 일일 리포트만 깔끔하게 보여준다.

동시에 상단 `이번 주 리포트` 영역의 주간 기준을 대표 확정 정책과 동일하게 통일한다.

최종 목표:

- `이번 주 리포트`는 항상 토요일~금요일 기준
- 요일 순서는 항상 `토 · 일 · 월 · 화 · 수 · 목 · 금`
- 각 요일 체크는 해당 날짜의 일일 리포트 존재 여부 기준
- 리스트에는 실제 생성된 일일 리포트만 표시
- 불필요한 월 헤더, 빈 날짜, 카운트, bullet, 이모티콘, 별도 점수 제거
- 삭제한 요소가 차지하던 불필요한 공백까지 함께 제거
- 시각적 정렬과 가독성을 위한 적정 여백은 유지하되 의미 없는 빈 공간은 남기지 않는다

---

## 2. 확정 요구사항

1. `이번 주 대화` → `이번 주 리포트`로 변경한다.
2. 오른쪽 `0일 / n일` 숫자 영역은 완전히 제거한다.
3. `이번 주 리포트`의 요일 순서는 rolling 7일이 아니라 고정 주차인 `토 · 일 · 월 · 화 · 수 · 목 · 금`으로 표시한다.
4. 각 요일 체크는 `해당 business_date의 일일 리포트 존재 여부`를 기준으로 한다.
5. 중간의 `8월`, `9월` 같은 월 구분 헤더는 완전히 제거한다.
6. 각 일일 리포트 카드 날짜는 `9일`이 아니라 `8월 9일`처럼 월·일을 함께 표시한다.
7. 오늘 일일 리포트가 아직 생성되지 않았다면 `10일 · 대화 없음` 같은 placeholder를 표시하지 않는다.
8. 일일 리포트 리스트에는 실제 생성된 리포트만 표시한다.
9. 월 헤더, 빈 날짜 placeholder, 카운트 등이 제거된 뒤 남는 불필요한 세로 여백도 함께 제거한다.
10. 리포트 핵심 문장 앞의 파란 점을 제거한다.
11. 감정 이모티콘을 제거한다.
12. 카드 오른쪽에 별도로 표시되는 `1점`, `2점` 등의 점수 UI를 제거한다.
13. 위 요소들이 차지하던 좌우 column, wrapper, margin, padding을 제거한다.
14. 리포트 카드에는 실제 핵심 문장과 요약 문장이 가장 잘 보이도록 정리한다.
15. 전체 화면에서 시각적 정렬을 위한 적절한 여백은 유지하되, 콘텐츠나 기능적 의미 없이 휑하게 차지하는 빈 공간·고정 높이·빈 wrapper·남은 margin/padding은 제거한다.

# 3. `이번 주 리포트` 영역

## 3.1 제목 변경

현재:

```text
이번 주 대화
```

변경:

```text
이번 주 리포트
```

이 영역은 대화 발생 여부가 아니라 `일일 리포트 생성 여부`를 보여주는 영역이다.

---

## 3.2 오른쪽 `0일 / n일` 완전 제거

현재 예:

```text
이번 주 대화                         0일
```

또는:

```text
이번 주 리포트                      6일
```

변경:

```text
이번 주 리포트
```

`0일 / 6일 / n일` 숫자는 계산해 다시 표시하지 않는다.

해당 숫자 영역 자체를 제거하고 오른쪽 빈 공간도 남기지 않는다.

---

## 3.3 주간 기준

현재 날짜 기준 rolling 7일로 요일을 회전시키지 않는다.

예를 들어 월요일이라고:

```text
화 · 수 · 목 · 금 · 토 · 일 · 월
```

처럼 표시하면 FAIL이다.

대표 확정 주간 정책과 동일하게 항상:

```text
토 · 일 · 월 · 화 · 수 · 목 · 금
```

순서로 표시한다.

주간 기준:

```text
week_start = 토요일
week_end   = 금요일
```

예:

```text
2026-08-08(토) ~ 2026-08-14(금)
```

현재 주간이라면 화면 요일 순서는:

```text
토 · 일 · 월 · 화 · 수 · 목 · 금
```

으로 고정한다.

---

## 3.4 체크 표시 기준

각 요일의 체크 여부는 반드시 해당 날짜의 `daily_reports.business_date` 존재 여부를 기준으로 한다.

정상:

```text
해당 날짜 daily_report 존재
→ 체크

해당 날짜 daily_report 없음
→ 미체크
```

사용 금지 기준:

- chat_sessions 존재 여부
- 미션 수행 여부
- raw conversation 존재 여부
- 메시지 개수
- 단순 대화 발생 여부
- 최근 7일 rolling activity

즉 체크의 의미는 오직:

```text
해당 날짜 일일 리포트 생성 완료
```

다.

# 4. 일일 리포트 리스트

## 4.1 실제 생성된 리포트만 표시

리스트에는 실제 `daily_reports`가 존재하는 날짜만 표시한다.

정상:

```text
8월 9일
[리포트]

8월 8일
[리포트]

8월 7일
[리포트]
```

금지:

```text
8월 10일 · 대화 없음

8월 9일
[리포트]
```

리포트가 없는 날짜를 UI에서 임의 생성하지 않는다.

기존 정렬이 `business_date DESC`라면 유지한다.

---

## 4.2 오늘 리포트 없음 placeholder 제거

오늘이 `2026-08-10`이고 오늘 리포트가 아직 생성되지 않았다면 이는 정상 상태다.

따라서 다음을 표시하지 않는다.

```text
10일 · 대화 없음
```

또는:

- 오늘 리포트 없음
- 대화 없음
- 아직 리포트 없음
- 빈 날짜 카드
- 빈 날짜 슬롯
- skeleton처럼 남는 고정 영역

오늘 리포트가 없으면 화면에는 아무것도 추가하지 않는다.

---

# 5. 월 구분 헤더 제거

다음과 같은 별도 월 헤더를 완전히 제거한다.

```text
8월
9월
```

각 카드 자체에 월·일을 표시하므로 월 그룹 헤더는 필요 없다.

월 헤더가 제거된 뒤 해당 영역의 margin/padding도 함께 제거한다.

---

# 6. 일일 리포트 날짜 표시

현재:

```text
9일
8일
```

변경:

```text
8월 9일
8월 8일
```

날짜 기준은 반드시:

```text
daily_reports.business_date
```

를 사용한다.

사용 금지:

- created_at
- 현재 날짜
- 브라우저 timezone 변환값
- UTC date를 다시 Date 객체로 변환해 하루 밀리는 방식

표시는 단순 문자열 기준으로 안전하게 처리한다.

---

# 7. 리포트 카드 장식 제거

현재 예:

```text
● 😟 현재 피곤함을 크게 느끼고...
                                  1점
```

변경:

```text
현재 피곤함을 크게 느끼고 있으며
마음 점수를 1점이라고 말했습니다.
게임을 실컷 하고 싶어 하는 마음이 큽니다.
```

제거 대상:

- 파란 점
- 감정 이모티콘
- 오른쪽 별도 점수
- 관련 wrapper
- 관련 icon column
- 관련 score column
- 관련 margin/padding
- 관련 width/min-width

주의:

본문 문장 자체에:

```text
마음 점수를 1점이라고 말했습니다.
```

처럼 실제 리포트 내용으로 점수가 포함돼 있다면 해당 문장은 유지한다.

삭제 대상은 카드 우측에 별도 UI로 표현되는 점수다.

---

# 8. 좌우 여백 재정리

파란 점, 감정 이모티콘, 오른쪽 점수 UI를 제거한 뒤 본문이 카드 가로폭을 더 넓게 사용하도록 한다.

반드시 함께 제거:

- bullet 영역 width
- emoji 영역 width
- score column width
- 비어 있는 flex/grid column
- 해당 요소의 gap
- 좌우 padding 중 삭제 요소 전용 공간
- 불필요한 min-width

본문이 삭제된 UI 때문에 좁은 폭으로 계속 줄바꿈되면 FAIL이다.

---

# 9. 불필요한 공백 제거 원칙

이번 요청뿐 아니라 해당 화면 전체에서 다음 원칙을 적용한다.

## 유지해야 하는 여백

- 카드 간 시각적 구분을 위한 적정 gap
- 제목과 콘텐츠 사이의 적정 margin
- 모바일 터치 영역 확보를 위한 padding
- 전체적인 정렬과 가독성을 위한 의도된 여백

## 제거해야 하는 공백

- 삭제된 UI가 차지하던 빈 wrapper
- 의미 없는 고정 height/min-height
- 빈 날짜 placeholder가 차지하던 공간
- 월 헤더 삭제 후 남는 margin
- `0일/n일` 삭제 후 남는 우측 공간
- bullet/emoji/score 삭제 후 남는 좌우 column
- 내용이 없는데도 유지되는 빈 카드/섹션
- 휑하게 화면만 차지하는 불필요한 상하 공간

원칙:

```text
의도된 여백은 유지
의미 없는 빈 공간은 제거
```

단순히 요소를 `display:none` 처리하고 부모 container의 높이·padding을 그대로 남기지 않는다.

# 12. 데이터/기능 유지

이번 요청에서 변경하지 않는다.

- daily_reports 원본 데이터
- mood score 저장 데이터
- 감정 분석 원본 데이터
- 상세 리포트 내용
- 일일 리포트 생성 pipeline
- 리포트 Cron
- 주간 리포트 생성 정책 자체
- 다자녀 전환
- 상세 리포트 모달

단, `이번 주 리포트` 상단 표시의 주간 계산은 주간 정책과 동일한 `토요일~금요일` 기준을 사용한다.

# 13. 금지 사항

- `0일`을 `6일`로 바꿔 계속 표시 금지
- 현재 날짜 기준 rolling 7일로 요일 순서 변경 금지
- `화~월`, `월~일` 등 다른 주차 표시 금지
- 월 헤더를 다른 디자인으로 재추가 금지
- 오늘 리포트 없음 placeholder 재추가 금지
- 대화 여부를 요일 체크 기준으로 사용 금지
- 감정 이모티콘을 다른 아이콘으로 치환 금지
- 점수를 badge/chip로 다시 표현 금지
- 파란 점을 다른 bullet로 교체 금지
- 카드 날짜를 created_at 기준으로 표시 금지
- 삭제된 요소의 공간을 빈 상태로 유지 금지
- 의미 없는 고정 height/min-height 유지 금지

# 14. 필수 테스트

## A. 제목

- `이번 주 리포트` 표시
- `이번 주 대화` 미표시
- `0일 / n일` 미표시

## B. 요일 순서

반드시:

```text
토 · 일 · 월 · 화 · 수 · 목 · 금
```

순서인지 확인한다.

현재 날짜가 어떤 요일이어도 순서가 회전하면 안 된다.

## C. 체크 기준

각 날짜별 `daily_reports.business_date` 존재 여부와 체크 상태를 직접 대조한다.

```text
report 존재 → 체크
report 없음 → 미체크
```

## D. 현재 주간 경계

예를 들어 현재 주간이:

```text
2026-08-08 ~ 2026-08-14
```

라면:

```text
토=8/8
일=8/9
월=8/10
화=8/11
수=8/12
목=8/13
금=8/14
```

로 매핑되어야 한다.

## E. 오늘 리포트 미생성

오늘 report가 없을 때:

- placeholder 없음
- `대화 없음` 없음
- 빈 카드 없음
- 빈 공간 없음

## F. 날짜 표시

- `9일` → `8월 9일`
- business_date 기준

## G. 카드 UI

다음 요소 0건:

- 파란 점
- 감정 이모티콘
- 별도 점수

본문 폭 정상 확장 확인.

## H. 공백

삭제된 요소별로 다음 확인:

- 월 헤더 삭제 후 빈 gap 없음
- 오늘 placeholder 삭제 후 빈 gap 없음
- 일수 숫자 삭제 후 우측 빈 column 없음
- bullet/emoji 삭제 후 좌측 빈 column 없음
- score 삭제 후 우측 빈 column 없음
- 카드 높이가 내용 대비 과도하게 크지 않음

## I. 회귀

- 자세히 보기 정상
- 상세 모달 정상
- 일간/주간 탭 정상
- 다자녀 전환 정상
- 리스트 스크롤 정상

## J. 모바일

- iPhone Safari
- iPhone PWA
- Android Chrome
- 태블릿 세로/가로
