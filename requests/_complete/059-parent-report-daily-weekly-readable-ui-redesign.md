# 059 — 부모 리포트 일일·주간 화면 가독성 중심 UI 통합 개편

## 1. 작업 목적

현재 부모 리포트 화면은 정보량이 많고 글씨·아이콘·하단 네비게이션이 작아 부모가 한눈에 읽기 어렵다.

첨부 비교 이미지의 오른쪽 목표 화면을 기준으로, 부모가 꼭 봐야 하는 정보만 크게 보여주는 방향으로 **일일 리포트와 주간 리포트를 동일한 디자인 컨셉으로 통합 개편**한다.

이번 작업의 핵심 원칙:

> 작은 정보 많이 보여주기 → 중요한 정보만 크게 보여주기

일일/주간의 데이터 내용은 다르더라도 아래 UI 언어는 동일하게 적용한다.

- 큰 제목
- 큰 핵심 숫자
- 큰 감정/상태 표시
- 짧은 핵심 요약
- 큰 카드
- 명확한 `자세히 보기`
- 큰 일간/주간 탭
- 큰 하단 네비게이션
- 부모가 스쳐 봐도 이해할 수 있는 정보 구조

기존 리포트 데이터 생성 로직, API, DB, 리포트 원문 내용은 이번 작업에서 변경하지 않는다.

---

## 2. 현재 화면과 목표 화면의 핵심 차이

### 현재 화면

- `일간 / 주간` 탭이 작고 선택 상태가 약함
- 최근 7일 요약 영역의 글씨와 점 표시가 작음
- 보조 설명이 많고 핵심 숫자가 작음
- 일별 카드 내부에 작은 텍스트가 많이 들어감
- 날짜·감정·본문의 시각적 우선순위가 약함
- 카드 사이 간격이 좁아 전체가 빽빽하게 보임
- 부모가 실제로 읽어야 하는 문장이 작음
- 하단 네비게이션 아이콘·글씨·터치 영역이 작음

### 목표 화면

- `일간 / 주간`을 화면 폭을 넓게 사용하는 큰 세그먼트 탭으로 변경
- 주간 대화 일수 등 핵심 숫자를 크게 표시
- 요일별 대화 상태를 큰 원형 상태로 표시
- 불필요한 보조 설명을 최소화
- 날짜/감정/핵심 요약을 크게 보여줌
- 카드 본문은 짧은 요약 위주로 표시
- 상세 정보는 `자세히 보기 >`로 분리
- 카드 간 간격 확대
- 하단 네비게이션까지 크게 확대
- 부모 전체 리포트 화면을 “읽기 쉬운 피드”처럼 구성

## 3. 공통 디자인 시스템

일일 리포트와 주간 리포트 모두 아래 공통 규칙을 사용한다.

### 3.1 글자 크기 우선순위

1. 핵심 숫자 / 핵심 상태
2. 날짜 / 카드 제목
3. 핵심 요약 본문
4. 감정·상태 태그
5. 보조 메타 정보

작은 글씨를 여러 단계로 나누지 말고, 부모가 실제로 읽어야 하는 글씨를 충분히 크게 표시한다.

### 3.2 카드 원칙

- 한 카드에는 하나의 핵심 메시지만 전달
- 카드 내부 텍스트 과밀 금지
- 긴 분석문은 목록 화면에서 제거
- 목록 화면은 2~3줄 핵심 요약 중심
- 상세 내용은 `자세히 보기`로 이동
- 카드 간 여백을 충분히 확보

### 3.3 색상

현재 내친구 케이 부모 화면의 브랜드 색상을 유지한다.

- 네이비: 주요 제목/선택 상태
- 밝은 회색/화이트: 카드 배경
- 감정 태그: 현재 감정 체계의 색상 유지
- 새로운 임의 브랜드 컬러 추가 금지

## 4. 일간 / 주간 탭 개편

### 현재

작은 독립 버튼 형태의 `일간 / 주간` 탭

### 목표

첨부 목표 이미지처럼 화면 가로폭을 넓게 사용하는 세그먼트 컨트롤 형태

```text
┌──────────────┬──────────────┐
│     일간     │     주간     │
└──────────────┴──────────────┘
```

### 요구사항

- 좌우 각 50% 영역
- 선택된 탭은 네이비 배경 + 흰색 글씨
- 비선택 탭은 흰색/밝은 배경 + 네이비 또는 회색 글씨
- 탭 높이와 터치 영역을 현재보다 확대
- 일간/주간 이동 시 레이아웃 점프 최소화
- 동일 컴포넌트를 재사용

## 5. 일일 리포트 화면

### 5.1 상단 요약

일일 탭에서도 상단에 최근 대화 흐름을 한눈에 볼 수 있는 요약을 유지한다.

단, 작은 보조 설명을 줄이고 부모가 바로 이해할 수 있는 숫자와 상태 중심으로 변경한다.

예시:

```text
이번 주 대화
6일

월  화  수  목  금  토  일
●   ●   ●   ●   ●   ●   ○
```

### 표시 원칙

- `이번 주 대화` 크게
- `6일` 등 실제 대화 일수는 훨씬 크게 강조
- 요일 글씨 확대
- 대화한 날 원형 표시 확대
- 범례는 최소화
- “이전 7일보다 몇 회 적어요” 같은 작은 보조 문구는 목록 핵심 정보가 아니라면 제거 또는 상세로 이동

실제 계산값은 기존 데이터 로직을 그대로 사용한다.

---

### 5.2 일별 카드

각 날짜별 리포트 카드는 아래 구조로 통일한다.

```text
8월 8일                    어제

😊 아쉬움 · 15pt

마음 상태를 어두운 검정색으로 표현했고,
먹고 싶었던 치킨 대신 족발집에 가면서
아쉬움을 느꼈습니다.

                         자세히 보기 >
```

※ 위 문구는 레이아웃 예시이며 실제 리포트 데이터는 기존 값을 사용한다.

#### 카드 헤더

- 날짜를 크게 표시
- `어제`, `2일 전` 등 상대 날짜는 작은 badge
- 상대 날짜가 중요하지 않으면 과도하게 강조하지 않음

#### 감정 영역

- 감정 이모지
- 감정명
- 기존 점수/포인트 정보가 실제 존재하면 함께 표시
- 감정 태그는 한눈에 구분되도록 크기 확대

#### 핵심 요약

- 목록 화면에서는 2~3줄 중심
- 기존의 너무 긴 본문은 줄이거나 기존 요약 필드를 사용
- 데이터 내용을 새로 생성하거나 임의로 축약하지 말 것
- 현재 DB/API에 이미 제공되는 요약 필드 중 가장 적합한 값을 우선 사용
- 더 긴 내용은 상세 화면에서 확인

#### 자세히 보기

- 각 카드 우측 하단
- 문구: `자세히 보기 >`
- 터치 영역 충분히 확보
- 현재 존재하는 상세 리포트 화면/API를 재사용
- 상세 화면이 없다면 임의로 새 데이터 구조를 만들지 말고 먼저 보고

## 6. 주간 리포트 화면

주간 리포트도 일일과 **동일한 큰 글씨·큰 카드·짧은 요약 컨셉**으로 변경한다.

### 6.1 주간 상단 핵심 정보

주간 화면 상단에서 부모가 가장 먼저 확인해야 하는 정보를 크게 표시한다.

우선순위 예시:

1. 이번 주 대화 일수
2. 이번 주 전반적인 감정 또는 변화
3. 주요 키워드/사건
4. 부모가 확인하면 좋은 핵심 요약

기존 주간 리포트 데이터에 실제 존재하는 항목만 사용한다.

### 6.2 주간 카드

현재 주간 리포트의 긴 설명을 그대로 작게 나열하지 않는다.

가능하면 다음 형태로 구분한다.

```text
이번 주 기분
[큰 핵심 요약]

친구·학교
[큰 핵심 요약]

관심사·주요 사건
[큰 핵심 요약]

이번 주 부모가 알아두면 좋은 점
[큰 핵심 요약]

자세히 보기 >
```

단, 실제 주간 리포트의 현재 필드 구조를 먼저 확인하고 존재하지 않는 항목을 임의로 추가하지 않는다.

### 카드 원칙

- 섹션 제목 크게
- 본문 크게
- 최대 2~4줄 핵심 요약
- 상세 분석은 별도 상세 영역 또는 기존 상세 화면
- 작은 설명 여러 개 나열 금지

---

## 7. 불필요한 정보 정리

첨부 목표 화면의 핵심은 단순 확대가 아니라 **정보 삭제/정리**다.

다음은 목록 화면에서 우선 제거 또는 축소 검토한다.

- 의미가 약한 작은 보조 설명
- 반복되는 날짜 표현
- 중복된 상태 설명
- 부모가 첫 화면에서 바로 볼 필요가 없는 분석 문장
- 작은 아이콘과 작은 범례의 과도한 사용
- 카드 한 장에 너무 많은 메타데이터

삭제 여부는 실제 데이터 중요도를 확인하여 결정하되, 기존 데이터 자체를 삭제하는 것이 아니라 **목록 화면에서 노출하지 않는 것**이다.

## 8. 하단 네비게이션 전면 확대

이번 작업에는 리포트 본문뿐 아니라 **부모 하단 네비게이션 확대도 포함**한다.

### 현재 문제

- `홈 / 리포트 / 케이와 대화 / 설정` 아이콘이 작음
- 메뉴 글씨가 작음
- 터치 영역이 작음
- 선택 상태가 약함

### 목표

첨부 오른쪽 화면처럼 부모가 쉽게 보고 누를 수 있도록 전체 확대한다.

### 변경 요구사항

- 네비게이션 바 높이 확대
- 아이콘 크기 확대
- 메뉴 글씨 확대
- 아이콘과 글씨 사이 간격 확대
- 각 메뉴의 터치 영역 확대
- 선택 메뉴를 명확하게 강조
- `리포트` 선택 시 네이비 아이콘/글씨 및 상단 표시선 등 기존 목표 이미지의 선택 표현 적용

### 적용 범위

하단 네비게이션이 부모 공통 컴포넌트라면 리포트 화면에만 적용하지 않는다.

아래 부모 주요 화면 전체에 동일하게 적용한다.

- 부모 홈
- 리포트
- 케이와 대화
- 설정

화면마다 하단 네비게이션 크기가 달라지면 안 된다.

## 9. 모바일 우선 반응형

### 주요 기준

- iPhone 390×844
- Android 360×800
- Android 412×915

### 요구사항

- 모든 본문 글씨가 부모가 읽기 충분한 크기
- 카드 좌우 잘림 없음
- `자세히 보기` 터치 용이
- 하단 네비게이션 Safe Area 확보
- 하단 네비게이션 때문에 마지막 카드가 가려지지 않게 content bottom padding 확보
- 가로 스크롤 금지

## 10. PC / 태블릿

부모 리포트를 PC에서도 볼 수 있으므로 단순히 모바일 UI를 과도하게 늘리지 않는다.

### 원칙

- 본문 max-width 유지
- 화면 중앙 정렬
- 카드 최대 너비 제한
- 큰 모니터에서도 글이 너무 길게 한 줄로 늘어나지 않게 함
- 일간/주간 탭 역시 적절한 최대 너비 적용
- 하단 네비게이션이 PC에서 현재 다른 구조를 사용한다면 기존 PC UX를 먼저 확인 후 적용

## 11. 기존 기능·데이터 보존

다음은 변경하지 않는다.

- 일일 리포트 생성 로직
- 주간 리포트 생성 로직
- 리포트 DB
- 리포트 API
- 리포트 보존 정책
- 감정 분석 로직
- 날짜 계산
- 대화 일수 계산
- 부모 인증/가족 권한
- 리포트 상세 데이터
- 기존 Cron/Edge Function

이번 작업은 **표시 UI와 정보 우선순위 개편**이다.

## 12. 구현 전 필수 조사

코드 수정 전에 다음을 확인한다.

1. 부모 리포트 메인 페이지 파일
2. 일간/주간 탭 컴포넌트
3. 최근 7일/주간 대화 요약 컴포넌트
4. 일별 리포트 카드 컴포넌트
5. 주간 리포트 카드/상세 컴포넌트
6. 부모 하단 네비게이션 공통 컴포넌트
7. 일별 카드에서 사용할 수 있는 실제 요약 필드
8. 감정명/점수 데이터의 실제 필드
9. `자세히 보기`가 연결될 기존 상세 화면
10. 모바일·PC별 현재 반응형 CSS

조사 후 기존 화면에서 어떤 정보가 제거되고 어떤 정보가 크게 표시되는지 목록으로 먼저 확인한다.

## 13. 화면 측정 및 비교

첨부 목표 이미지와 실제 Dev 화면을 비교하여 다음을 측정한다.

### 상단 탭

- width
- height
- font-size
- 선택 영역 크기

### 주간 대화 카드

- card height
- 제목 크기
- 핵심 숫자 크기
- 요일 원형 크기

### 일별 카드

- card width / height
- 날짜 font-size
- 감정 태그 크기
- 본문 font-size / line-height
- `자세히 보기` 크기

### 하단 네비게이션

- 전체 높이
- icon size
- label font-size
- 메뉴별 터치 영역
- Safe Area 포함 높이

수정 전/후 값을 보고한다.

2. 일간 탭 선택

4. 요일별 대화 여부 정상 표시
5. 최근 리포트 카드 정상 표시
6. 감정 정보 정상 표시
7. 요약 본문 정상 표시
8. `자세히 보기` 이동 확인

### 주간 리포트

1. 주간 탭 선택
2. 기존 주간 데이터 정상 로딩
3. 큰 글씨/큰 카드 디자인 적용 확인
4. 핵심 내용만 목록에 표시되는지 확인
5. 상세 정보 접근 정상 확인
6. 일간으로 다시 전환 시 정상 복귀

### 하단 네비게이션

부모 홈 → 리포트 → 케이와 대화 → 설정을 순서대로 이동하며:

- 동일한 높이
- 동일한 아이콘 크기
- 동일한 글씨 크기
- 현재 메뉴 선택 표시 정상
- 터치 정상
- 페이지 이동 정상

## 15. 완료 조건

다음 조건을 모두 만족해야 한다.

- 일일/주간 화면이 하나의 디자인 시스템처럼 보인다.
- 작은 글씨 위주의 기존 화면이 개선된다.
- 부모가 핵심 정보부터 바로 볼 수 있다.
- 주간 대화 일수 등 핵심 숫자가 크게 보인다.
- 일별 날짜·감정·요약 글씨가 충분히 커진다.
- 긴 내용은 목록에서 줄고 `자세히 보기`로 분리된다.
- 불필요한 보조 정보가 줄어든다.
- 카드 간 여백이 개선된다.
- 일간/주간 탭이 크고 명확해진다.
- 부모 하단 네비게이션이 전체적으로 확대된다.
- 부모 주요 페이지에서 동일한 네비게이션 UI를 사용한다.
- 기존 리포트 데이터와 기능에 회귀가 없다.
- 모바일에서 가로 잘림이 없다.
