# REQUEST: 디자인 스킬 기반 앱 테마·톤앤매너 개편

## 1. 요청 목적

프로젝트 루트의 `SKILL` 폴더에 업로드된 디자인 스킬을 기준으로, 기존 앱의 기능과 정보 구조는 유지하면서 다음 시각 요소를 일관되게 개편한다.

- 색상 체계
- 테마
- 타이포그래피
- 컴포넌트 스타일
- 화면 분위기
- 전체 톤앤매너

이번 작업은 기능 재개발이 아니라 **기존 앱의 디자인 시스템을 디자인 스킬 기준으로 재정비하는 작업**이다.

---

## 2. 작업 기본 원칙

1. 기존 기능, 인증, 라우팅, 데이터 처리, 상태 관리, 음성 대화 로직은 변경하지 않는다.
2. 기존 화면의 정보 구조와 핵심 레이아웃은 원칙적으로 유지한다.
3. `SKILL` 폴더의 디자인 규칙을 최우선 시각 기준으로 사용한다.
4. 기존 확정 로고, 마스코트, 브랜드 자산은 임의로 다시 생성하거나 변형하지 않는다.
5. 페이지별로 색상값과 스타일을 직접 하드코딩하지 않는다.
6. 디자인 규칙은 공통 디자인 토큰과 공통 컴포넌트에 집중시킨다.
7. 전면 일괄 수정 전에 대표 화면을 먼저 적용해 검증한다.
8. 기존 앱의 동작을 깨뜨릴 가능성이 있는 대규모 구조 변경은 금지한다.

## 5. 3단계: 디자인 토큰 정의

`SKILL`의 디자인 규칙을 현재 앱에서 재사용 가능한 디자인 토큰으로 변환한다.

예시 구조:

```css
:root {
  --color-primary: ...;
  --color-primary-hover: ...;
  --color-primary-active: ...;

  --color-secondary: ...;
  --color-accent: ...;

  --color-background: ...;
  --color-surface: ...;
  --color-surface-elevated: ...;
  --color-border: ...;

  --color-text-primary: ...;
  --color-text-secondary: ...;
  --color-text-disabled: ...;

  --color-success: ...;
  --color-warning: ...;
  --color-error: ...;
  --color-info: ...;

  --radius-sm: ...;
  --radius-md: ...;
  --radius-lg: ...;
  --radius-xl: ...;

  --shadow-sm: ...;
  --shadow-md: ...;
  --shadow-lg: ...;

  --spacing-xs: ...;
  --spacing-sm: ...;
  --spacing-md: ...;
  --spacing-lg: ...;
  --spacing-xl: ...;
}
```

현재 프로젝트가 Tailwind를 사용한다면 CSS 변수와 Tailwind Theme를 연결한다.

디자인 토큰은 가능한 한 다음 중 한곳에서 중앙 관리한다.

- `globals.css`
- `theme.css`
- `tokens.css`
- `tailwind.config.*`
- 기존 Theme Provider

동일한 역할의 색상이나 스타일 토큰을 여러 파일에 중복 정의하지 않는다.

## 7. 5단계: 대표 화면 선적용

전체 화면을 한 번에 변경하지 말고 대표 화면 1~2개를 먼저 선정해 적용한다.

대표 화면은 다음 기준으로 선정한다.

- 공통 컴포넌트가 많이 포함된 화면
- 실제 사용자 사용 빈도가 높은 화면
- 아이 화면 또는 부모 화면의 디자인 특성이 잘 드러나는 화면
- 모바일에서 자주 사용하는 화면

대표 화면 적용 후 아래 항목을 검증한다.

- 디자인 스킬과의 일치 여부
- 기존 기능 정상 동작
- 모바일 반응형
- 텍스트 가독성
- 색상 대비
- 컴포넌트 상태 표현
- 화면 간 일관성
- 기존 브랜드 자산 유지 여부
- 레이아웃 깨짐 여부

대표 화면 검증 완료 후 나머지 화면으로 확장한다.

---

## 8. 부모 화면과 아이 화면 적용 기준

### 8.1 부모 화면

부모 화면은 다음 인상을 우선한다.

- 신뢰감
- 안정감
- 정보 가독성
- 과도하지 않은 친근함
- 명확한 상태 구분
- 정돈된 데이터 표현

### 8.2 아이 화면

아이 화면은 다음 인상을 우선한다.

- 친근함
- 따뜻함
- 쉬운 이해
- 명확한 상호작용
- 적절한 재미
- 과도하게 유아적이지 않은 표현

아이 화면에서도 접근성, 버튼 크기, 텍스트 대비, 터치 영역을 축소하지 않는다.

## 10. 브랜드 자산 사용 규칙

- 기존 확정 로고를 그대로 사용한다.
- 기존 확정 마스코트를 그대로 사용한다.
- 로고의 심볼, 글자, 비율, 색상을 임의로 변경하지 않는다.
- 마스코트의 형태, 얼굴, 비율, 색상을 임의로 변경하지 않는다.
- 새로운 로고나 마스코트를 생성하지 않는다.
- 임시 이미지 생성으로 기존 자산을 대체하지 않는다.
- 자산 경로가 중복되어 있으면 정본 경로를 확인한 뒤 참조를 통합한다.
