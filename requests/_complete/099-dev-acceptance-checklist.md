# 대표님 Dev 최종 확인 체크리스트 작성

## 작업 정보

- 우선순위: 보통
- 선행 작업: 앞선 활성 큐 전체 완료
- 병렬 처리: 불가
- 개발 작업이 아니라 대표님 수동 검증용 최종 문서 작성

## 범위

작업 전 `docs/conventions.md`를 먼저 읽고 따른다.

## 현재 상태

여러 기능이 Dev 배포됐지만 대표님 최종 실기기 확인 여부가 기능별로 분리돼 있지 않다.

확인 대상에는 다음이 포함된다.

- D안 운영 미션
- 질문 기본10+예비10
- 재도전 1회
- 전체 연결 품질 표시
- 미션 레이아웃
- 음성 토글
- 마스코트 애니메이션
- 이름 분리와 호칭
- MBTI 실제 앱 통합
- 황금열쇠 표시·차감·환불
- 리텐션 드릴다운·PDF·PNG

## 요구사항

1. 대표님이 스마트폰에서 따라 할 수 있는 순서로 작성한다.

2. 기능별로 다음을 표시한다.
   - 테스트 계정
   - 진입 경로
   - 입력 또는 행동
   - 기대 결과
   - 실패 시 캡처할 화면과 시각
   - 판정 체크박스

3. 자동화 QA와 대표님 실계정 테스트를 구분한다.

4. 김서아·김서현 계정에서 확인할 항목만 별도 섹션으로 작성한다.

5. 테스트가 데이터에 미치는 영향을 명시한다.
   - 황금열쇠 차감
   - 놀이 세션 생성
   - 미션 진행 기록

6. 아직 완료되지 않은 기능은 체크리스트에 완료 기능처럼 넣지 않는다.

7. 각 항목에 관련 커밋과 requests 파일 번호를 표시한다.

  - `https://k-bestie-v3-dev.vercel.app`

- 실제 비밀번호는 문서에 기록하지 않음

## 완료조건

- 대표님 확인 대상 기능 전부 포함
- 테스트 순서와 기대 결과 명확
- 자동화 검증과 수동 검증 구분
- 데이터 변화 주의사항 포함
- 미완료·차단 기능 제외 또는 명확히 표시
- `docs/dev-acceptance-checklist.md` 커밋 완료

## 검증 시나리오

1. 체크리스트만 보고 로그인부터 결과 확인까지 진행 가능한지 검토
2. 실제 비밀번호나 민감정보 포함 여부 확인
3. 각 기능의 현재 상태와 문서 내용 대조
4. Production URL이 포함되지 않았는지 확인
5. requests 번호와 커밋 SHA 정확성 확인
