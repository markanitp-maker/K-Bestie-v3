# 030 — 부모용 일간 리포트 최근 7일 목록 및 과거 이력 달력 개편

## 1. 작업 목적

부모 화면의 일간 리포트 목록을 첨부 레퍼런스 이미지의 정보 구조와 디자인을 기준으로 개편한다.

이번 개편의 핵심은 다음과 같다.

- 일간 리포트 진입 시 오늘을 포함한 최근 7개 날짜만 기본 표시한다.
- 최근 7일의 전체 대화 흐름을 상단 요약 카드로 보여준다.
- 날짜별 일간 리포트 카드는 핵심 내용만 간결하게 표시한다.
- 각 카드 하단에 있던 대화 횟수·시간대·생성 시각 등의 메타데이터는 전부 제거한다.
- 과거 기록은 기본 목록에 계속 누적하지 않는다.
- `지난 이력 보기`를 누르면 월간 달력이 열린다.
- 달력에서 리포트가 존재하는 날짜를 선택하면 해당 날짜의 일간 리포트를 볼 수 있게 한다.
- 기존 주간 리포트와 부모용 하단 Navigation은 유지한다.
- 스마트폰 외곽 프레임과 상태 표시줄은 구현하지 않는다.

---

# 2. 이전 요청 대비 정정 사항

기존 요청서에서 일간 리포트 카드 하단에 표시하도록 했던 다음 정보를 모두 삭제한다.

## 삭제 대상

- `대화 5회`
- `대화 3회`
- 오전·오후·저녁 등의 시간대
- `20:30 생성` 등의 생성 시각
- 마지막 확인 시점
- 카드 하단 Metadata 영역
- 카드 하단 별도 활동 기록
- 카드 하단 추가 상태 문구
- 카드 하단 구분선 및 보조 정보 행

## 유지 대상

각 카드에는 다음 세 가지 정보만 표시한다.

1. 날짜와 상대 날짜
2. 해당 날짜의 대표 마음 상태 또는 리포트 제목
3. 해당 날짜에 있었던 핵심 내용을 정리한 한 줄 요약

예시:

```text
27일 월요일 · 어제

● 마음이 무거웠어요
친구를 기다렸는데 오지 않아 속상해했어요
```

본문의 한 줄 요약은 삭제 대상이 아니다.

# 3. 기본 조회 기간

일간 리포트 기본 화면은 다음 범위만 조회한다.

```text
오늘을 포함한 최근 7개 캘린더 날짜
```

예를 들어 오늘이 2026년 7월 28일이면 다음 기간을 표시한다.

```text
2026년 7월 22일 00:00:00 KST
~
2026년 7월 28일 23:59:59 KST
```

중요:

- 최근 생성된 리포트 7개가 아니다.
- 리포트 생성 여부와 관계없이 최근 7개 날짜가 기준이다.
- 날짜 계산은 KST를 기준으로 한다.
- UTC 저장 시각을 브라우저 로컬 시간으로 단순 변환하여 날짜가 바뀌는 오류를 방지한다.

# 7. 상단 헤더

기존 부모 공통 헤더를 유지하고 재사용한다.

## 구성

왼쪽:

- 내친구 케이 공식 가로형 로고

오른쪽:

- 현재 선택된 자녀 이름
- 자녀 선택 드롭다운
- 알림 아이콘

## 자녀 변경

자녀를 변경하면 다음 데이터가 모두 새로운 자녀 기준으로 갱신되어야 한다.

- 최근 7일 전체 대화 횟수
- 이전 7일 비교
- 날짜별 상태점
- 최근 7일 일간 리포트
- 과거 이력 달력의 리포트 존재 날짜
- 선택한 날짜의 상세 리포트

자녀 변경 중 이전 자녀의 데이터가 남아 보이지 않도록 즉시 Skeleton 또는 로딩 상태로 전환한다.

Query cache에는 반드시 `child_id`를 포함한다.

# 8. 일간·주간 탭

## 구성

```text
일간
주간
```

## 기본 상태

이 화면에서는 `일간`을 활성화한다.

## 동작

- 일간: 최근 7일 일간 리포트 목록
- 주간: 기존 주간 리포트 화면

기존 주간 리포트 데이터 및 생성 로직은 변경하지 않는다.

## 디자인

활성 탭:

- K-Navy 배경
- 흰색 텍스트
- 굵기 600~700

비활성 탭:

- 연한 Neutral 배경
- K-Navy 텍스트

접근성:

- `role="tablist"`
- `role="tab"`
- `aria-selected`
- 키보드 이동 지원

# 9. 최근 7일 요약 카드

## 제목

```text
최근 7일
```

레퍼런스의 `이번 주`보다 실제 조회 범위를 정확히 표현하는 `최근 7일`을 사용한다.

## 전체 대화 횟수

오른쪽에 최근 7일의 실제 전체 대화 횟수를 표시한다.

예시:

```text
12회
```

이 숫자는 날짜별 리포트 카드에 반복 표시하지 않는다.

## 이전 기간 비교

최근 7일 직전의 7개 날짜와 비교한다.

예시:

```text
이전 7일 8회보다 증가
```

또는:

```text
이전 7일과 비슷해요
```

또는:

```text
이전 7일보다 3회 적어요
```

## 집계 원칙

- 최근 기간과 비교 기간에 동일한 집계 기준 사용
- 대화 세션 수, 미션 수, 발화 수 중 기존 정본 지표 확인
- 리포트 개수와 대화 횟수를 혼동하지 않음
- 일간 카드 하단에는 해당 숫자를 반복 표시하지 않음

# 10. 최근 7일 날짜 상태점

요약 카드 하단에 최근 7일의 요일과 상태점을 표시한다.

예시:

```text
월  화  수  목  금  토  일
●  ○  ●  ○  ○  ●  ○
```

## 상태

### 일간 리포트 존재

- K-Sky Blue 또는 K-Navy 채움 원
- 접근성 문구 `리포트 있음`

### 대화는 있으나 리포트 생성 전

실제 생성 대기 상태를 확인할 수 있을 때만:

- K-Mascot Orange 점
- 접근성 문구 `리포트 준비 중`

### 대화 및 리포트 없음

- 연한 Neutral 원
- 접근성 문구 `리포트 없음`

### 오늘

- 별도 외곽선 또는 `오늘` 접근성 정보
- 색상만으로 구분하지 않음

# 11. 일간 리포트 목록

## 표시 범위

기본 화면에는 최근 7일 안에 있는 일간 리포트만 표시한다.

과거 리포트를 목록 아래에 계속 누적하지 않는다.

## 정렬

최신 날짜부터 내림차순으로 표시한다.

## 월 구분

최근 7일이 두 달에 걸쳐 있으면 월별로 구분한다.

예시:

```text
8월
7월
```

# 12. 일간 리포트 카드 최종 구조

각 일간 리포트 카드는 다음 세 영역으로만 구성한다.

## 1. 날짜

예시:

```text
27일 월요일 · 어제
```

작은 화면에서는:

```text
27일 · 어제
```

## 2. 마음 상태 또는 대표 제목

예시:

```text
● 마음이 무거웠어요
```

```text
● 편안했어요
```

```text
● 평소와 비슷
```

제목은 실제 일간 리포트의 대표 요약 필드를 사용한다.

## 3. 한 줄 요약

예시:

```text
친구를 기다렸는데 오지 않아 속상해했어요
```

```text
로블록스 이야기를 신나게 했어요
```

```text
학교 이야기를 편하게 나눴어요
```

- 최대 1~2줄
- 부모가 이해하기 쉬운 리포트 요약
- 아이의 긴 직접 발화 원문은 표시하지 않음
- 하드코딩 금지

# 13. 카드 하단 정보 전면 삭제

각 카드 아래에는 어떠한 Metadata 행도 만들지 않는다.

다음 형태는 구현하지 않는다.

```text
대화 5회 · 저녁 시점
```

```text
대화 3회 · 오후
```

```text
20:30 생성
```

```text
마지막 확인 1일 전
```

```text
미션 2회 · 자유대화 1회
```

카드 하단에 아이콘·시간·횟수·활동 유형을 나열하지 않는다.

카드의 정보 계층은 반드시 다음으로 끝난다.

```text
날짜
대표 마음 상태
한 줄 요약
```

# 14. 카드 디자인

- 흰색 배경
- 얇은 Neutral 테두리
- radius 약 `14px~18px`
- 약한 그림자
- 내부 padding 약 `14px~16px`
- 카드 사이 간격 약 `8px~12px`
- 날짜는 보조 텍스트
- 마음 상태 제목은 K-Navy와 굵은 글씨
- 한 줄 요약은 본문 색상
- 카드 높이를 불필요하게 크게 만들지 않음
- 하단 Metadata 삭제 후 남는 빈 공간이 없어야 함

## 상태점

제목 왼쪽에 작은 상태점을 표시할 수 있다.

- 일반 흐름: K-Sky Blue
- 살펴볼 흐름: K-Mascot Orange
- 데이터 부족: Neutral
- 시스템 오류: state-error

색상만으로 상태를 판단하게 하지 않는다.

# 15. 카드 클릭 동작

카드 전체를 클릭 가능한 link 또는 button으로 구성한다.

클릭 시 기존 해당 날짜의 일간 리포트 상세 화면으로 이동한다.

전달 기준:

- `child_id`
- `report_id` 또는 report date
- 선택된 자녀
- 복귀 위치

상세 화면에서 뒤로가기를 누르면 다음 상태를 복원한다.

- 일간 탭
- 최근 7일 목록
- 선택된 자녀
- 기존 스크롤 위치
- 달력에서 진입한 경우 확인했던 월

카드 클릭으로 다음을 실행하면 안 된다.

- 리포트 재생성
- LLM 재분석
- raw transcript 조회
- 새 리포트 생성

# 16. 리포트가 없는 날짜 표시

최근 7일 중 연속으로 일간 리포트가 없는 날짜는 하나의 구간으로 표시한다.

예시:

```text
23~24일 · 대화 없음
```

하루만 없는 경우:

```text
24일 · 대화 없음
```

## 상태 구분

실제 데이터로 확인 가능한 경우:

### 대화 없음

```text
23~24일 · 대화 없음
```

### 대화는 있으나 리포트 생성 대기

```text
24일 · 리포트 준비 중
```

### 리포트 생성 실패

```text
24일 · 리포트 확인 필요
```

상태를 정확히 구분할 수 없는 경우:

```text
23~24일 · 리포트 없음
```

대화가 없었다고 확인하지 못한 상태에서 `대화 없음`이라고 단정하지 않는다.

# 17. 지난 이력 보기 버튼

최근 7일 목록 하단에 배치한다.

## 문구


# 21. 달력 데이터 조회

달력을 열 때 해당 월의 전체 리포트 본문을 모두 조회하지 않는다.

달력에는 다음 최소 Metadata만 사용한다.

```text
report_id
child_id
report_date
report_status
summary_state
created_at
```

날짜 선택 후 해당 일간 리포트 상세를 조회한다.

## 성능 기준

- 월 변경 시 해당 월 Metadata만 조회
- 자녀별·연도별·월별 cache key 분리
- 이미 조회한 월은 기존 Query cache 재사용 가능
- 이전 요청이 늦게 도착해 현재 월 화면을 덮지 않도록 처리
- 달력 열기만으로 LLM 호출 금지
- raw transcript 조회 금지
- 해당 월 전체 상세 리포트 일괄 다운로드 금지

# 22. 날짜 선택 동작

리포트가 존재하는 날짜를 선택하면 다음 순서로 처리한다.

1. 선택 날짜 강조
2. 해당 날짜의 정본 report 확인
3. Bottom Sheet 닫기
4. 기존 일간 리포트 상세 화면으로 이동
5. 선택한 날짜의 리포트 표시

동일 날짜에 리포트가 여러 개 존재할 경우 기존 버전 정책에 따라 최신 정상 완료본을 사용한다.

리포트가 없는 날짜는 무반응 버튼으로 만들지 않는다.

기본값:

- `disabled`
- 접근성 정보 `리포트 없음`
