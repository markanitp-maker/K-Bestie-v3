# 스마트폰·태블릿 미리보기 프레임 확대 및 반응형 개선

## 1. 작업 목적

현재 관리자/디자인 미리보기 화면에서 스마트폰 및 태블릿 기기 프레임이 실제 화면 대비 작게 표시되어 내부 UI 확인이 어렵다.

첨부 화면을 기준으로 다음을 개선한다.

- 스마트폰 프레임을 더 크게 표시
- 태블릿 가로 프레임을 더 크게 표시
- 브라우저 화면 크기에 따라 프레임이 가능한 범위까지 자동 확대
- 기기 프레임 내부 콘텐츠 비율과 스크롤 동작은 유지
- 스마트폰/태블릿 전환 버튼과 프레임이 서로 겹치지 않게 정렬

## 2. 현재 문제

### 스마트폰 미리보기

- 프레임 전체 크기가 작아 내부 글자와 버튼이 작게 보임
- 화면 좌우에 불필요한 빈 공간이 많이 남음
- 실제 모바일 UI 배치와 여백을 확인하기 어려움

### 태블릿 미리보기

- 가로형 태블릿 프레임이 브라우저 가용 영역을 충분히 사용하지 못함
- 내부 콘텐츠가 작게 축소되어 상세 UI 검수가 어려움
- 화면 하단과 좌우에 큰 여백이 남음

## 3. 확정 요구사항

### 3.1 스마트폰 프레임

- 현재 크기보다 확실히 크게 확대한다.
- 데스크톱 브라우저에서 세로 높이 기준으로 가능한 최대 크기를 사용한다.
- 프레임의 비율은 현재 스마트폰 비율을 그대로 유지한다.
- 프레임 내부 콘텐츠는 별도 확대/왜곡하지 않고 기존 viewport 비율을 유지한다.
- 프레임이 브라우저 상하 영역을 벗어나지 않도록 최대 높이를 제한한다.
- 화면 중앙에 정렬한다.

권장 기준:

```css
.smartphone-frame {
  height: min(88dvh, 920px);
  width: auto;
  aspect-ratio: 390 / 844;
}
```

실제 프레임 이미지/컴포넌트의 비율에 맞게 값은 조정하되, 현재보다 최소 20~30% 이상 크게 보이게 한다.

### 3.2 태블릿 프레임

- 현재 가로형 프레임보다 크게 확대한다.
- 브라우저 가용 너비의 대부분을 사용한다.
- 좌우 최소 여백만 남기고 중앙 정렬한다.
- 프레임 비율은 현재 태블릿 비율을 유지한다.
- 내부 콘텐츠가 늘어나거나 찌그러지지 않게 한다.

권장 기준:

```css
.tablet-frame {
  width: min(94vw, 1500px);
  height: auto;
  aspect-ratio: 1366 / 900;
}
```

실제 프레임 비율과 현재 컴포넌트 구조를 확인하여 조정한다.

### 3.3 반응형 동작

- 브라우저 창이 작아지면 프레임도 자동 축소한다.
- 브라우저 창이 커지면 정해진 최대 크기까지 자동 확대한다.
- 스마트폰/태블릿 전환 시 페이지 전체가 좌우로 흔들리거나 스크롤 위치가 크게 바뀌지 않게 한다.
- 가로 스크롤이 생기면 안 된다.
- 프레임 하단이 브라우저 화면 밖으로 과도하게 잘리지 않게 한다.

## 4. 프레임 내부 콘텐츠 정책

- 프레임 내부 앱 viewport 크기와 비율은 그대로 유지한다.
- 프레임 외곽만 확대하고, 앱 내부 CSS를 이번 작업에서 변경하지 않는다.
- 확대 때문에 앱 내부 폰트·버튼·카드 비율이 깨지면 안 된다.
- iframe 또는 scale을 사용 중이면 다음을 확인한다.
  - 프레임 외곽 크기와 내부 viewport 크기의 비율
  - transform-origin
  - overflow 처리
  - 확대 후 클릭 좌표와 실제 표시 위치 일치 여부
- 프레임 내부 스크롤바는 기존 동작을 유지한다.
- 외부 페이지에 불필요한 추가 스크롤바가 생기지 않게 한다.

## 5. 전환 버튼 위치

현재 왼쪽의 `태블릿 / 스마트폰` 전환 버튼은 유지한다.

- 프레임과 겹치지 않게 한다.
- 프레임 확대 후에도 좌측에 안정적으로 고정한다.
- 작은 브라우저 폭에서는 프레임 위쪽 또는 하단으로 이동할 수 있게 반응형 처리한다.
- 선택된 기기 버튼은 현재처럼 명확한 활성 상태를 유지한다.

## 6. 구현 전 점검

먼저 다음을 확인한다.

1. 스마트폰/태블릿 프레임을 렌더링하는 정확한 파일과 컴포넌트
2. 현재 프레임 width/height/max-width/max-height 값
3. iframe, transform: scale, CSS zoom 사용 여부
4. 프레임 외곽 이미지와 내부 앱 viewport의 실제 비율
5. 브라우저 가용 영역 계산 방식
6. 스마트폰/태블릿 전환 시 사용하는 상태값과 CSS 클래스

단순히 고정 px 값만 크게 바꾸지 말고, 화면 크기에 따라 자동 조절되는 구조로 수정한다.

## 7. 권장 구현 방식

```tsx
<div className="device-preview-stage">
  <div className={device === "phone" ? "phone-shell" : "tablet-shell"}>
    <iframe className="device-preview-content" />
  </div>
</div>
```

```css
.device-preview-stage {
  width: 100%;
  min-height: calc(100dvh - var(--header-height));
  display: flex;
  align-items: center;
  justify-content: center;
  overflow: hidden;
  padding: 16px 24px;
  box-sizing: border-box;
}

.phone-shell {
  height: min(88dvh, 920px);
  max-width: 92vw;
  aspect-ratio: 390 / 844;
}

.tablet-shell {
  width: min(94vw, 1500px);
  max-height: 88dvh;
  aspect-ratio: 1366 / 900;
}

.device-preview-content {
  width: 100%;
  height: 100%;
  border: 0;
}
```

현재 프로젝트 구조에 맞게 적용하되, iframe 내부 클릭 좌표가 어긋나는 `transform: scale` 방식은 가능하면 피한다.

## 8. 검증 기준

### 스마트폰

- 현재보다 최소 20% 이상 크게 표시
- 브라우저 세로 높이의 약 85~90% 사용
- 중앙 정렬
- 프레임 전체가 화면 안에 표시
- 내부 UI 비율·스크롤·클릭 정상

### 태블릿

- 브라우저 가로 너비의 약 90~94% 사용
- 최대 너비 제한 내에서 중앙 정렬
- 현재보다 내부 UI가 명확하게 크게 보임
- 프레임 좌우 및 하단이 잘리지 않음
- 내부 UI 비율·스크롤·클릭 정상

### 공통

- 1366×768
- 1440×900
- 1920×1080
- 2560×1440

위 해상도에서 각각 확인한다.
