# 037 — 미션 시작하기·이어하기 진입 게이트 추가

## 1. 작업 목적

현재 아이가 미션 화면에 진입하면 별도의 확인 없이 케이가 즉시 말을 시작하고 미션 세션이 진행된다.

이 구조 때문에 아이가 홈 화면에서 미션 카드를 실수로 누른 경우에도 다음 문제가 발생한다.

- 케이가 즉시 첫 질문을 말함
- 마이크 및 음성 세션이 활성화됨
- 미션 세션이 불필요하게 생성됨
- 진행 중 화면에서 다시 나가는 일이 반복됨
- 실제로 시작하지 않은 미션이 이어하기 대상으로 남을 수 있음
- 아이가 준비되지 않은 상태에서 음성이 입력될 수 있음

이를 해결하기 위해 미션 대화 화면 진입 직후에는 미션을 시작하지 않고, 아이가 직접 `시작하기` 또는 `이어하기` 버튼을 눌러야 실제 미션이 시작되도록 변경한다.

---

## 2. 핵심 정책

미션 화면 진입 시 서버의 실제 미션 상태를 확인하여 다음 두 가지 중 하나를 표시한다.

### 진행 중인 미션이 없는 경우

```text
시작하기
```

### 저장된 미완료 미션이 있는 경우

```text
이어하기
```

버튼을 누르기 전에는 다음을 실행하지 않는다.

- Gemini Live 세션 연결 또는 활성 대화 시작
- 케이 첫 질문 TTS
- 마이크 입력
- 자동 VAD 입력
- 미션 제한 시간 또는 대화 시간 측정
- 신규 미션 세션 생성
- 질문 이력 저장
- 진행률 증가
- 황금열쇠 지급 관련 처리

단순 화면 진입은 미션 시작으로 간주하지 않는다.

---

## 3. 적용 화면

대상:

- 아이 미션 대화 화면
- 신규 미션 진입
- 진행 중 미션 재진입
- 미션 화면 직접 URL 진입
- 브라우저 새로고침 후 복원
- PWA 종료 후 재진입

변경하지 않는 기능:

- 유효 답변 10개 완료 기준
- 기본 질문 10개
- 예비 질문 10개
- 미답변 질문 재순환
- 자동·수동 입력 모드
- 키보드 입력
- 음성 상태 표시
- 미션 진행률 저장
- 완료 및 황금열쇠 보상
- 기존 이어하기 데이터 구조
- 질문·답변 저장
- 리포트 수집

---

## 4. 미션 화면 상태 구분

미션 화면 상태를 최소한 다음과 같이 명확히 구분한다.

```text
checking
ready_to_start
ready_to_resume
starting
resuming
active
completing
completed
error
```

실제 프로젝트의 기존 상태명과 구조가 있다면 재사용한다.

### checking

- 서버에서 진행 중 미션 존재 여부 확인
- 시작하기·이어하기를 임의로 먼저 표시하지 않음
- 가벼운 로딩 상태 표시
- 마이크와 입력 기능 비활성

### ready_to_start

- 진행 중 미션 없음
- `시작하기` 표시
- 진행률 0/10
- 케이 음성 출력 없음
- 마이크 비활성

### ready_to_resume

- 미완료 미션 존재
- `이어하기` 표시
- 저장된 진행률 표시
- 저장된 현재 질문 또는 복원 안내 표시 가능
- 버튼을 누르기 전 음성·마이크 비활성

### starting

- 신규 미션 생성 및 첫 질문 준비 중
- 버튼 중복 클릭 차단
- 마이크 비활성

### resuming

- 기존 세션과 질문 복원 중
- 버튼 중복 클릭 차단
- 마이크 비활성

### active

- 정상 미션 대화 상태
- 기존 듣는 중·생각 중·말하는 중 상태 머신 사용

---

## 5. 진행 중 미션 판정 기준

`이어하기` 표시 여부는 클라이언트의 임시 상태가 아니라 서버의 실제 미완료 미션 데이터를 기준으로 결정한다.

다음 조건을 모두 만족하는 세션만 이어하기 대상으로 인정한다.

- 현재 로그인한 아이의 세션
- 미션 완료 상태가 아님
- 기존 세션 만료 정책상 유효함
- 유효 답변 수가 10개 미만
- 복원 가능한 질문·진행 상태가 존재함
- 취소·폐기·오류 종료 상태가 아님

동일 아이에게 복수의 활성 미션이 발견되면 임의로 새 세션을 생성하지 말고 기존 정본 선택 정책 또는 가장 최근 정상 세션을 확인한다.

필요하면 데이터 이상 상태를 기록하고 중복 활성 세션이 생성되지 않도록 한다.

---

## 6. 신규 미션 화면

진행 중인 미션이 없을 경우 현재 질문 말풍선 영역에 `시작하기` 버튼을 표시한다.

## 권장 화면

```text
[진행률 0/10]

[문의]

[미션을 시작할 준비가 됐어?]

┌─────────────────────────┐
│                         │
│        시작하기          │
│                         │
└─────────────────────────┘

[소리 카드] [케이] [시작 전]

          [자동] [수동]

[키보드]     [비활성 마이크]
```

## 문구

버튼:

```text
시작하기
```

선택적 안내 문구:

```text
준비가 되면 시작하기를 눌러 줘!
```

긴 설명이나 별도의 안내 모달을 추가하지 않는다.

---

## 7. 시작 전 입력 상태

`시작하기` 버튼을 누르기 전에는 모든 입력 기능을 비활성화한다.

### 마이크

- 회색 비활성
- 마이크 차단 아이콘
- Pulse 없음
- 음성 프레임 전송 금지
- `disabled` 또는 `aria-disabled="true"`

### 키보드

- 비활성 또는 숨김
- 텍스트 입력창 열기 금지
- 답변 제출 금지

### 자동·수동 버튼

- 기존 기본 선택 상태는 표시할 수 있음
- 미션 시작 전에는 조작 불가능하게 처리
- 시작 전에 모드를 눌러 음성 입력이 활성화되지 않게 함

### 상태 카드

권장 문구:

```text
시작 전
```

또는 기존 상태 체계와 맞는:

```text
준비 중
```

`듣고 있어`, `대기 중`처럼 이미 음성을 받고 있다는 오해를 주는 문구를 사용하지 않는다.

---

## 8. 시작하기 버튼 동작

아이에게 활성 미션이 없는 상태에서 `시작하기`를 누르면 다음 순서로 처리한다.

1. 버튼 즉시 비활성화
2. 중복 클릭 방지
3. 서버에서 활성 미션 존재 여부 재확인
4. 활성 미션이 여전히 없으면 신규 미션 세션 생성
5. 질문 순서 및 세션 상태 초기화
6. 진행률 0/10 확인
7. Gemini Live 또는 기존 음성 대화 세션 준비
8. 첫 질문 준비
9. 케이 첫 질문을 화면에 표시
10. 케이 첫 질문 TTS 출력
11. 말하는 동안 마이크 비활성
12. 첫 질문 음성 종료 후 아이 입력 대기 상태 전환
13. 마이크 주황색 활성

신규 세션 생성과 첫 질문 시작이 여러 번 실행되지 않도록 서버와 클라이언트 양쪽에서 중복을 방지한다.

---

## 9. 시작하기 경쟁 상태 방지

`시작하기` 버튼을 누르는 순간 다른 기기나 탭에서 이미 활성 세션이 생성됐을 수 있다.

이 경우 새 세션을 중복 생성하지 않는다.

처리:

1. 서버에서 활성 세션 재조회
2. 기존 활성 세션 발견
3. 신규 생성 중단
4. 기존 세션을 이어하기 대상으로 전환
5. 해당 세션 복원

가능하면 활성 세션 생성은 Transaction, RPC 또는 동등한 원자적 처리로 보장한다.

UI의 버튼 비활성만으로 중복 생성을 막지 않는다.

---

## 10. 진행 중 미션 재진입 화면

저장된 미완료 미션이 있을 경우 `시작하기` 대신 `이어하기`를 표시한다.

## 권장 화면

```text
[진행률 3/10]

[문의]

[진행 중인 미션이 있어!]

┌─────────────────────────┐
│                         │
│        이어하기          │
│                         │
└─────────────────────────┘

[소리 카드] [케이] [중단됨]

          [자동] [수동]

[키보드]     [비활성 마이크]
```

## 버튼

```text
이어하기
```

## 선택적 안내

```text
하던 미션부터 계속해 볼까?
```

기존 진행률을 0으로 초기화하지 않는다.

---

## 11. 이어하기 버튼을 누르기 전 상태

미완료 세션이 존재하더라도 아이가 `이어하기`를 누르기 전에는 다음을 실행하지 않는다.

- 자동 재연결 후 질문 TTS 재생
- 마이크 활성화
- VAD 입력
- 다음 질문 생성
- 진행 시간 재개
- 답변 저장
- 세션 상태 변경

화면에는 저장된 진행률을 표시할 수 있으나 미션은 일시정지 상태로 유지한다.

---

## 12. 이어하기 버튼 동작

`이어하기` 클릭 시 다음 순서로 처리한다.

1. 버튼 비활성화
2. 활성 미션 상태 서버 재확인
3. 저장된 유효 답변 수 복원
4. 질문 이력 복원
5. 현재 미답변 질문 확인
6. 다음에 받아야 할 질문 상태 복원
7. Gemini Live 또는 기존 음성 세션 연결
8. 현재 질문을 화면에 표시
9. 필요 시 현재 미답변 질문을 케이가 한 번만 다시 말함
10. 음성 출력 종료 후 아이 입력 대기 상태로 전환
11. 마이크 활성화

## 복원 원칙

예를 들어 유효 답변 3개가 저장된 상태라면:

```text
진행률: 3/10
```

에서 시작한다.

다음을 금지한다.

- 처음 질문부터 재시작
- 진행률 0/10 초기화
- 이미 저장된 답변 재저장
- 이미 완료된 질문 다시 처리
- 이어하기 클릭만으로 진행률 증가
- 새로운 질문 세션 중복 생성

---

## 13. 현재 미답변 질문 복원

중단 당시 질문이 이미 화면과 서버에 저장되어 있고 아직 답변이 없는 경우 해당 질문을 복원한다.

이어하기 후에는 그 질문을 새 질문으로 다시 생성하지 않는다.

권장 동작:

- 저장된 현재 질문을 화면에 표시
- 케이가 해당 질문을 한 번만 다시 읽어 줌
- 읽기가 끝나면 아이 답변 대기
- 질문 ID 및 순번 유지
- 같은 질문의 중복 이력 생성 금지

중단 당시 답변 저장은 완료됐지만 다음 질문 생성 직전에 종료된 경우에는 저장된 상태를 기준으로 다음 미답변 질문으로 진행한다.

---

## 14. 화면 진입만으로 세션 생성 금지

다음 경우에는 신규 미션 세션을 만들지 않는다.

- 아이가 홈에서 미션 카드를 누름
- 미션 화면이 렌더링됨
- 미션 상태 조회 중
- `시작하기` 화면을 본 뒤 X를 누름
- 브라우저 뒤로가기
- PWA를 닫음
- 화면을 새로고침했지만 시작 버튼을 누르지 않음

신규 세션은 아이가 실제로 `시작하기`를 누른 뒤 서버 검증을 통과한 경우에만 생성한다.

---

## 15. 시작 전 닫기 버튼

신규 미션 시작 전 X 버튼을 누르면 다음과 같이 처리한다.

- 신규 세션 생성 없음
- 질문 이력 생성 없음
- 진행률 저장 없음
- Gemini Live 대화 시작 없음
- 아이 홈으로 이동
- 미션 카드 상태는 미시작 상태 유지

확인 다이얼로그는 불필요하다.

아직 시작하지 않은 미션이므로 바로 닫을 수 있다.

---

## 16. 진행 중 미션에서 닫기

미션을 시작했거나 이어하기를 통해 활성화한 뒤 X 버튼을 누르면 기존 중단·저장·이어하기 정책을 유지한다.

처리:

1. 현재 확정된 답변 저장 확인
2. 진행률 저장
3. 현재 질문과 질문 이력 저장
4. 오디오 입력 중단
5. 세션 일시중단 상태 처리
6. 아이 홈으로 이동
7. 다음 진입 시 `이어하기` 표시

완료되지 않은 세션을 취소 또는 삭제하지 않는다.

---

## 17. 세션 저장 시점

이어하기가 정확히 작동하도록 최소한 다음 시점에 기존 상태 저장을 보장한다.

- 각 유효 답변 저장 완료 후
- 다음 질문 결정 후
- 현재 질문 표시 후
- 사용자가 X로 종료할 때
- 브라우저 Background 전환 시 기존 정책상 필요한 경우
- 네트워크 연결 종료 직전 가능한 경우

단, 입력 중인 미완성 음성을 유효 답변으로 저장하지 않는다.

---

## 18. 완료된 미션 처리

이미 완료된 세션은 `이어하기` 대상으로 표시하지 않는다.

다음 상태에 따라 기존 완료 정책을 따른다.

### 완료 및 보상 확인 완료

- 신규 미션 가능 정책에 따라 `시작하기` 또는 완료 상태 표시
- 완료 세션을 이어하기로 복원하지 않음

### 완료됐지만 보상 확인 화면을 아직 닫지 않음

기존 황금열쇠 보상 확인 정책에 따라 보상 화면을 복원할 수 있다.

다만 Reward를 다시 지급하거나 완료 TTS를 반복 재생하지 않는다.

### 오늘 미션 재시작 제한이 있는 경우

기존 하루 미션 횟수 및 시간대 정책에 따른 안내를 표시한다.

UI 개편을 이유로 완료된 미션을 임의로 다시 시작할 수 있게 만들지 않는다.

## 20. 로딩 상태

미션 화면 최초 진입 시 활성 세션 존재 여부를 확인하는 동안 다음을 표시한다.

- 마이크 비활성
- 키보드 비활성
- 자동·수동 비활성
- 케이 TTS 출력 금지

조회 실패를 미션 없음으로 간주해 `시작하기`를 표시하지 않는다.

버튼:

```text
다시 시도
```

## 22. 시작 및 이어하기 실패

### 신규 시작 실패

```text
미션을 시작하지 못했어요.
잠시 후 다시 시도해 주세요.
```

- 마이크 활성화 금지
- 신규 세션 중복 생성 금지
- 다시 시도 가능

### 이어하기 실패

```text
진행 중인 미션을 불러오지 못했어요.
잠시 후 다시 시도해 주세요.
```

- 기존 세션을 삭제하지 않음
- 진행률 0으로 초기화하지 않음
- 새 미션 생성으로 자동 대체하지 않음

## 23. 자동·수동 입력 모드

미션 시작 전 자동·수동 버튼은 실제 음성 입력을 활성화하지 않는다.

### 신규 시작

`시작하기`를 누른 뒤 기존 기본 입력 모드 정책에 따라 시작한다.

### 이어하기

기존 세션의 입력 모드를 저장·복원하는 정책이 이미 있다면 그대로 사용한다.

기존 저장 정책이 없다면 현재 프로젝트의 기본 입력 모드를 사용하며 임의로 새로운 저장 필드를 추가하지 않는다.

### 키보드

미션이 활성화된 이후 키보드 버튼을 누르면 기존 정책대로 수동 모드로 자동 전환한다.

시작 전에는 키보드 입력을 열지 않는다.

## 24. 음성 세션 연결 시점

Gemini Live 또는 기존 음성 대화 연결의 전체 기술 구조는 유지한다.

다만 다음을 구분한다.

### 화면 표시를 위한 준비 연결

기존 구조상 기술적으로 사전 연결이 꼭 필요한 경우에도:

- 케이 TTS 출력 금지
- 마이크 음성 전송 금지
- VAD 답변 처리 금지
- 질문 진행 금지

### 실제 미션 활성화

아이의 `시작하기` 또는 `이어하기` 클릭 이후에만 실제 대화 턴을 시작한다.

사전 연결이 필수가 아니라면 버튼 클릭 후 연결하는 것을 우선한다.

불필요한 실시간 세션 점유와 비용 발생을 피한다.

## 25. 진행률 표시

```text
0/10
```

모든 진행 원을 미완료 상태로 표시한다.

### 이어하기

저장된 실제 유효 답변 수만큼 표시한다.

예시:

```text
3/10
```

질문 번호가 아니라 유효 답변 수를 사용한다.

시작하기 또는 이어하기 버튼 클릭만으로 진행률을 증가시키지 않는다.

## 35. 완료 기준

다음 조건을 모두 만족해야 완료로 판정한다.

- 미션 화면 진입만으로 케이가 말하지 않음
- 화면 진입만으로 신규 미션 세션이 생성되지 않음
- 화면 진입만으로 Gemini 대화 턴이 시작되지 않음
- 활성 미션이 없으면 `시작하기`가 표시됨
- 미완료 미션이 있으면 `이어하기`가 표시됨
- 두 버튼이 동시에 표시되지 않음
- 시작 또는 이어하기 전 마이크와 키보드가 비활성임
- 시작 전 X 클릭 시 세션 생성 없이 아이 홈으로 이동함
- `시작하기` 클릭 후에만 신규 세션이 생성됨
- 첫 질문과 TTS가 한 번만 실행됨
- `이어하기` 클릭 후 저장된 진행률이 복원됨
