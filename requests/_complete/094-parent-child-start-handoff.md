# REQUEST: 보호자 온보딩 완료 후 아이 시작 안내(Handoff) 및 보호자 홈 재호출 UX 구현

## 0. 목적

보호자가 회원가입 및 온보딩을 완료한 뒤 바로 보호자 홈으로만 이동하면, 보호자는 곧바로 “그럼 아이는 어디서 어떻게 시작하나요?”라는 의문을 갖게 된다.

따라서 보호자 온보딩 완료 직후에는 **부모 가입 완료 → 아이 첫 사용**으로 자연스럽게 연결하는 전용 Handoff 화면을 제공하고, 보호자가 당시 아이와 함께 있지 않아 `보호자 홈으로 이동`을 선택하더라도 나중에 보호자 대시보드/설정에서 언제든 동일 안내를 다시 불러올 수 있도록 구현한다.

이번 작업의 핵심 목표는 다음 두 가지다.

1. 온보딩 완료 직후 아이가 케이를 시작하는 방법을 즉시 안내한다.
2. 보호자 홈으로 이동한 이후에도 동일한 아이 시작 안내를 언제든 다시 열 수 있게 한다.

---

## 1. 절대 변경 금지 범위

이번 작업은 **아이 시작 안내 UX 추가**에 한정한다.

다음 영역은 실제 결함이 발견되지 않는 한 변경하지 않는다.

- 보호자 OAuth 로그인
- 기존 회원가입 1/4~4/4 단계
- 가족 만들기 / 가족 구성원으로 참여하기 로직
- 아이 등록/승인 로직
- 기존 child 인증 구조
- 기존 아이 아이디/비밀번호 정책
- 회원 탈퇴/복구 로직
- RLS 및 기존 권한 정책
- 리포트/대화/이벤트 데이터 구조
- 기존 Production 사용자 데이터
- 비밀번호 저장 방식

새 인증 체계를 임의로 설계하지 말고 현재 프로젝트의 아이 로그인 구조를 그대로 활용한다.

## 2. 최종 사용자 흐름

### 2.1 새 가족을 만든 보호자

```text
보호자 회원가입
→ 약관 동의
→ 보호자 기본정보
→ 가족 만들기
→ 4/4 아이 등록
→ 자동 승인 완료
→ [신규] 아이 시작 안내 Handoff 화면
   ├─ 이 기기에서 아이 시작하기
   └─ 보호자 홈으로 이동
```

### 2.2 기존 가족에 참여한 보호자

이미 다른 보호자가 가족과 아이를 만들어 둔 상태에서 `가족 구성원으로 참여하기`를 완료한 보호자는 새 아이 등록을 강제하지 않는다.

기존 가족에 활성 아이가 존재하면 회원가입/참여 완료 후 아래처럼 처리한다.

```text
가족 구성원 참여 완료
→ [신규] 아이 시작 안내 Handoff 화면
   ├─ 아이가 1명: 해당 아이 안내 바로 표시
   ├─ 아이가 2명 이상: 아이 선택 후 안내 표시
   └─ 보호자 홈으로 이동
```

## 3. 온보딩 완료 직후 Handoff 화면

현재 아이 등록 성공 화면을 단순히 `승인되었습니다 → 시작하기`로 끝내지 말고, 아래 목적의 안내 화면으로 교체 또는 연결한다.

### 3.1 상단 메시지 우선순위

시각적 우선순위는 반드시 다음과 같이 한다.

#### 보조 문구
`준비가 끝났어요!`

- 현재 시안보다 작게 표시
- 성공 상태를 알려주는 secondary heading 역할

#### 핵심 문구
`이제 아이가 케이를 시작할 차례예요.`

- 이 화면에서 가장 크고 눈에 띄는 텍스트
- `준비가 끝났어요!`보다 명확히 큰 글자와 높은 font-weight 적용
- 모바일에서 2줄까지 허용
- 화면 진입 즉시 핵심 의미가 읽혀야 함

#### 설명 문구
`아이 기기에서 아래 방법 중 편한 방법으로 접속해 주세요.`

## 4. QR 코드 영역

Handoff 화면에 QR 코드를 표시한다.

### 4.1 QR 목적

QR을 찍으면 아이가 사용할 로그인 화면으로 이동해야 한다.

가능하면 현재 프로젝트의 아이 전용 로그인 라우트를 사용한다.

예시:

```text
https://app.k-bestie.com/child
```

현재 프로젝트에 별도 `/child` 라우트가 없다면 기존 로그인 페이지에서 아이 로그인 영역으로 직접 진입하거나 포커스되는 안전한 내부 URL을 사용한다.

### 4.2 QR에 포함 금지

QR에는 아래 정보를 절대 포함하지 않는다.

- 아이 비밀번호
- Supabase access token
- refresh token
- 부모 세션
- 장기 사용 가능한 인증 토큰
- service_role 정보
- 개인정보 원문

1차 구현에서는 **아이 로그인 페이지 URL**까지만 포함하는 것을 기본으로 한다.

현재 구조에서 안전하고 단순하게 지원할 수 있으면 아이 로그인 아이디를 URL query로 prefill할 수 있으나, 서버 권한/세션을 부여해서는 안 된다.

예:

```text
https://app.k-bestie.com/child?login_id=hong123
```

### 4.3 QR 생성 방식

- 외부 유료 QR 생성 서비스 의존 금지
- 현재 Next.js 앱 내부에서 클라이언트 또는 서버 라이브러리로 QR 생성
- QR 이미지를 별도 DB/Storage에 영구 저장할 필요 없음
- 화면 렌더링 시 생성 가능
- 라이브러리 신규 도입 시 가볍고 유지보수 가능한 패키지를 사용

---

## 5. QR을 사용할 수 없는 보호자를 위한 웹주소 안내

QR만 제공하면 안 된다.

QR 아래에 `또는` 구분을 두고 다음 정보를 반드시 함께 제공한다.

### 5.1 웹사이트 주소

제목:

`웹사이트 주소로 접속`

주소:

`app.k-bestie.com`

버튼:

`주소 복사`

### 5.2 추가 안내

`로그인 화면에서 '아이 로그인'을 선택해 주세요.`

아이 전용 라우트가 별도로 존재한다면 해당 주소를 사용해도 되지만, 사용자가 직접 입력하기 쉬운 짧은 주소를 우선한다.

---

## 6. 아이 로그인 아이디 안내

웹주소 안내 아래에 해당 아이의 로그인 아이디를 표시한다.

예:

```text
아이 로그인 아이디

hong123

[아이디 복사]
```

하단 안내:

`비밀번호는 조금 전에 보호자님이 만든 비밀번호를 사용해요.`

### 보안

- 비밀번호를 화면에 다시 평문으로 표시하지 않는다.
- 비밀번호를 QR에 포함하지 않는다.
- 비밀번호를 localStorage/sessionStorage에 저장하지 않는다.
- 기존 비밀번호 변경/재설정 기능을 재사용한다.

## 7. 화면 하단 CTA

### Primary CTA

`이 기기에서 아이 시작하기`

목적:

현재 보호자 기기를 바로 아이에게 넘겨 사용하려는 경우.

동작은 현재 프로젝트의 아이 로그인/계정 전환 구조를 확인하여 **가장 안전한 기존 방식**을 재사용한다.

1차 구현에서 자동 아이 세션 전환 기능이 이미 존재하지 않는다면 새 인증 체계를 크게 만들지 말고 다음처럼 처리해도 된다.

```text
이 기기에서 아이 시작하기
→ 보호자 세션 안전하게 종료 또는 기존 계정 전환 플로우 실행
→ 아이 로그인 화면 이동
→ 아이 아이디 prefill 가능
→ 아이가 비밀번호 입력
→ 아이 홈
```

부모와 아이 세션을 단순 role state 변경만으로 전환하지 않는다.

### Secondary CTA

`보호자 홈으로 이동`

- 보호자가 지금 아이와 함께 있지 않을 수 있으므로 반드시 제공
- `/parent/home`으로 이동
- 이 선택을 해도 아이 시작 안내 기능은 사라지면 안 됨

## 8. 보호자 홈에서 언제든 다시 열기

보호자가 `보호자 홈으로 이동`을 선택하더라도 나중에 동일 안내를 언제든 다시 볼 수 있어야 한다.

### 8.1 보호자 대시보드 상시 진입점

보호자 홈 본문에 다음 목적의 카드/버튼을 추가한다.

예시 문구:

```text
아이와 케이 시작하기

아이 기기에서 로그인하거나
이 기기에서 바로 시작할 수 있어요.

[아이 시작하기]
```

또는

```text
아직 아이가 케이를 시작하지 않았어요.
[아이 시작하기]
```

이 버튼을 누르면 **온보딩 완료 직후 Handoff 화면과 동일한 내용을 모달로 표시**한다.

별도 페이지를 중복 구현하지 말고 재사용 가능한 공통 컴포넌트로 만든다.

예:

```text
ChildStartGuide
ChildStartGuideModal
```

실제 프로젝트 네이밍 컨벤션에 맞게 조정한다.

---

## 9. 보호자 설정에서도 다시 열기

`보호자 설정 → 아이 정보 관리`에서 각 아이별로 다음 액션을 제공한다.

예:

```text
홍길순 (3학년)

[수정하기] [로그인 방법] [아이 삭제]
```

`로그인 방법`을 누르면 해당 아이의 Handoff 안내 모달을 연다.

모달 내용:

- QR
- 웹주소
- 주소 복사
- 해당 아이 로그인 아이디
- 아이디 복사
- 이 기기에서 아이 시작하기

이렇게 하면 새 기기 구매, 로그아웃, PWA 재설치 등의 상황에서도 보호자가 다시 아이 로그인 방법을 찾을 수 있다.

## 10. 자녀가 여러 명인 가족

### 아이 1명

- 바로 해당 아이의 Handoff 안내 표시

### 아이 2명 이상

대시보드의 `아이 시작하기`를 누르면 먼저 아이 선택 UI를 표시한다.

예:

```text
어떤 아이의 로그인 방법을 볼까요?

[서아]
[서현]
```

아이 선택 후 해당 아이의:

- QR
- 웹주소
- 로그인 아이디
- 이 기기에서 아이 시작하기

를 표시한다.

아이별 로그인 아이디가 섞이지 않도록 child_id 기준으로 조회한다.

## 11. 아이 첫 로그인 전/후 대시보드 노출 강도

아이 첫 로그인 여부를 **현재 DB에서 이미 확인 가능한 상태/로그인 기록이 있다면** 활용한다.

### 첫 로그인 전

보호자 홈에서 상대적으로 눈에 잘 띄게 표시한다.

예:

`아직 아이가 케이를 시작하지 않았어요.`

`[아이 시작하기]`

### 첫 로그인 후

강조도는 낮추되 기능은 절대 제거하지 않는다.

예:

`아이 로그인 방법`

`[다시 보기]`

중요:

- 이 기능은 일회성 알림이 아니다.
- 알림센터에만 숨기지 않는다.
- 언제든 다시 찾을 수 있어야 한다.
- 기존 DB에 first login 여부를 판단할 안전한 필드가 없다면 이번 작업을 위해 임의 컬럼을 추가하지 말고 동일한 상시 카드만 제공한다.

## 12. 보호자와 아이 역할 설명

Handoff 화면에 짧게 역할을 구분해 주는 안내를 넣어도 된다.

예:

`보호자님은 리포트와 설정을 확인하고, 아이는 아이 화면에서 케이와 대화해요.`

단, 화면이 과도하게 길어지지 않도록 보조 문구 수준으로 제공한다.

## 13. UI 디자인 기준

기존 내친구 케이 브랜드와 현재 회원가입 UI를 유지한다.

### 권장 구조

```text
[성공 아이콘/컨페티]

준비가 끝났어요!           ← 작게

이제 아이가 케이를
시작할 차례예요.           ← 가장 크게

아이 기기에서 아래 방법 중
편한 방법으로 접속해 주세요.

┌──────────────────────┐
│                      │
│        QR CODE       │
│                      │
└──────────────────────┘

           또는

웹사이트 주소로 접속
app.k-bestie.com      [주소 복사]

로그인 화면에서 '아이 로그인'을 선택해 주세요.

아이 로그인 아이디
hong123               [아이디 복사]

비밀번호는 조금 전에 보호자님이 만든
```

### 스타일

- 기존 K-Navy / K-Orange 계열 활용
- 현재 회원가입 화면의 border radius, spacing, typography 체계 재사용
- 모바일 우선
- PC/태블릿 반응형 지원
- QR이 너무 커서 CTA가 지나치게 아래로 밀리지 않게 조정
- 긴 아이 ID도 깨지지 않도록 overflow 처리
- 복사 버튼은 명확한 성공 피드백 제공
  - 예: `복사됐어요`

## 14. 접근성 및 사용성

- QR만으로 기능을 제한하지 않는다.
- 웹주소를 텍스트로 항상 표시한다.
- 복사 버튼 제공
- 아이 아이디 복사 버튼 제공
- 모든 주요 버튼 터치 영역 충분히 확보
- 색상만으로 상태를 표현하지 않는다.
- 모바일 브라우저/PWA에서 모두 정상 작동
- QR을 다른 기기로 찍기 어려운 동일 기기 사용자에게 `이 기기에서 아이 시작하기` 경로 제공

---

## 15. 데이터 및 보안 규칙

1. QR에 비밀번호 또는 인증 토큰을 넣지 않는다.
2. 보호자 페이지에서 다른 가족의 아이 ID 조회 불가.
3. child_id/family_id를 클라이언트 값만 믿지 않고 서버에서 보호자 가족 소속 검증.
4. 아이 로그인 ID를 보여주는 API가 필요하면 보호자 인증과 family membership 검증 필수.
5. 부모 세션에서 아이 세션으로 단순 role 값 변경 금지.
6. 비밀번호 재노출 금지.
7. 기존 아이 계정 인증 흐름 재사용.
8. 신규 service_role 브라우저 노출 금지.
9. Production 사용자 데이터 변경/초기화 금지.

## 16. 구현 우선순위

### Phase 1 — 이번 작업에서 반드시 완료

1. 온보딩 완료 후 Handoff 화면
2. 핵심 헤드라인 우선순위 수정
   - `준비가 끝났어요!` 작게
   - `이제 아이가 케이를 시작할 차례예요.` 크게
3. QR 표시
4. `app.k-bestie.com` 또는 실제 아이 로그인 주소 표시
5. 주소 복사
6. 아이 로그인 아이디 표시
7. 아이디 복사
8. 비밀번호 안내
9. `이 기기에서 아이 시작하기`
10. `보호자 홈으로 이동`
11. 보호자 홈 `아이 시작하기` 상시 진입점
12. 동일 안내 모달 재호출
13. 보호자 설정 → 아이별 `로그인 방법`
14. 다자녀 선택 처리

### Phase 2 — 이번 작업에서 구현하지 않음

- 1회용 QR 자동 인증
- 비밀번호 없는 QR 로그인
- 장기 trusted device pairing
- 아이 기기 push pairing
- SMS/카카오톡 자동 전송

Phase 2는 별도 Request로 분리한다.

## 17. 필수 테스트 시나리오

### A. 신규 가족 / 아이 1명

```text
보호자 가입 완료
→ 가족 생성
→ 아이 등록
→ 승인 완료
→ Handoff 화면 표시
→ QR 표시 확인
→ 웹주소 표시 확인
→ 아이 ID 표시 확인
→ 보호자 홈 이동
→ 홈의 아이 시작하기 클릭
→ 동일 안내 모달 재표시
```

### B. 같은 기기에서 아이 시작

```text
Handoff
→ 이 기기에서 아이 시작하기
→ 아이 로그인 화면
→ 아이 아이디 확인 또는 prefill
→ 비밀번호 입력
→ 아이 홈
```

보호자 세션 데이터가 아이 화면에 노출되면 FAIL.

### C. 다른 기기에서 QR

```text
부모 Handoff QR 표시
→ 다른 기기에서 QR 스캔
→ app.k-bestie.com 아이 로그인 경로
→ 아이 로그인
→ 아이 홈
```

### D. QR 사용 불가

```text
아이 기기 브라우저에서
app.k-bestie.com 직접 입력
→ 아이 로그인 선택
→ 아이 ID/비밀번호
→ 아이 홈
```

### E. 보호자 홈 재호출

```text
보호자 홈
→ 아이 시작하기
→ Handoff 모달
→ 닫기
→ 홈 유지
→ 다시 열기
→ 정상 표시
```

### F. 보호자 설정 재호출

```text
보호자 설정
→ 아이 정보 관리
→ 로그인 방법
→ 해당 아이 Handoff 모달
```

### G. 다자녀

```text
아이 2명 이상
→ 보호자 홈 아이 시작하기
→ 아이 선택
→ A 선택
→ A 로그인 ID 표시
→ 닫기
→ B 선택
→ B 로그인 ID 표시
```

아이 ID 혼선 0건이어야 한다.

### H. 기존 활성 보호자

기존 사용자의 로그인/홈/리포트 접근에 회귀가 없어야 한다.
