# 음성 인식 결과의 문맥 기반 재해석

## 0. 완료 시 기대 결과 / 대표님 테스트 정상 프로세스

### 완료 시 기대 결과
- 아이가 말한 내용이 음성 인식에서 잘못 전사돼도, **직전 대화 문맥으로 후보를 재해석**해
  케이가 알아듣는다.
- 게임 진행 중에는 그 게임의 어휘·정답 후보를 우선해서 해석한다.
- 미션 진행 중에는 미션 질문의 맥락을 우선해서 해석한다.
- 재해석에 성공하면 케이가 되묻지 않고 자연스럽게 이어간다.
- **재해석이 확실하지 않으면 지어내지 않는다.** 원문을 그대로 두고 되묻는다.
- 원문(raw transcript)은 그대로 보존한다. 재해석 결과와 구분해 저장한다.

### 대표님 테스트 정상 프로세스
1. Dev에서 아이 계정으로 자유대화에 들어간다.
2. 넌센스 퀴즈를 시작한다.
3. 정답과 발음이 비슷하지만 다르게 인식될 만한 답을 말한다.
   (예: 정답이 `송아지`일 때 "소 노래" → "오수 노래"로 전사되는 상황)
4. 케이가 되묻지 않고 아이 의도대로 알아듣는지 확인한다.
5. 게임과 무관한 아무 말이나 했을 때, 억지로 게임 어휘로 끌어다 붙이지 않는지 확인한다.
6. 미션에서도 같은 방식으로 확인한다.
7. 인식이 아주 망가진 경우(뜻을 알 수 없는 말)에는 지어내지 않고 되묻는지 확인한다.

PASS:
- 게임·미션 문맥에서 오인식 재해석 성공 사례 확인
- 문맥과 무관한 발화를 억지 해석한 건 0건
- 원문 보존 확인 (raw와 재해석 결과가 구분되어 저장)
- 재해석 실패 시 지어내지 않고 되묻기

## 1. 상태 / 우선순위 / 대상
- 상태: 신규 구현
- 우선순위: MIDDLE
- 대상: 자유대화 / 미션 / K Play Skill Platform 공통 STT 후처리
- 선행: 1단계(잘린 발화 필터)·2단계(인식 모델 교체)가 이미 적용돼 있다.

## 2. 배경 — 실측 근거

2026-08-17 프로덕션 자유대화 7일치, 아이 발화 789건 기준.

| 지표 | 수치 |
|---|---|
| 케이가 "다시 말해줄래?" 한 건 | 116건 (14.7%) |
| 자모 한 글자만 들어온 건 | 61건 (7.7%) |
| 두 글자 이하 | 231건 |

자모 한 글자는 **1단계에서 캡처 단계로 해결**했다. 복원할 정보 자체가 없기 때문이다.

이 요청서가 다루는 것은 **정보는 남아 있는데 잘못 전사된 경우**다. 실제 사례:

```
[넌센스 퀴즈 진행 중 · 정답 "송아지"]
아이: "소 노래"  → 전사: "오수 노래"   → 케이: "아쉽게도 틀렸어!"
아이: "소 노래"  → 전사: "손 노래"     → 케이: "다시 얘기해줘, 잘 안 들렸거든."
아이: "소 노래"  → 전사: "또 노래"     → 케이: "아쉽지만 '또 노래'도 아니야!"
아이: "소 노래 라고 했는데 자꾸 이소 노래를 글자가 잘 안 들리나 봐"
```

세 번 모두 **"노래"는 정확히 들어왔다.** 넌센스 퀴즈 진행 중이고 정답이 `송아지`라는
맥락이 있으면 "소"를 복원할 수 있다. 지금은 그 맥락을 인식 후처리에 전혀 쓰지 않는다.

## 3. 요구사항

### 3-1. 재해석의 입력
재해석기는 다음을 입력으로 받는다.
- 원문 전사(raw transcript)와 인식 신뢰도
- 현재 대화 모드 (`free_chat` / `mission`)
- **활성 놀이 세션 정보** — 게임 종류, 현재 문제/단어, 힌트 단계
- 직전 케이 발화와 아이 발화 (짧은 창)

### 3-2. 게임 문맥 우선
활성 놀이 세션이 있으면 그 게임의 어휘를 우선한다.
- 넌센스 퀴즈: `canonical_answer`·`accepted_answers`
- 초성게임: `current_chosung` 에 맞는 후보
- 끝말잇기: 이어야 할 시작 글자에 맞는 사전 단어

**단, 정답을 아이에게 알려주는 방향으로 쓰면 안 된다.** 재해석은 아이가 이미 말한
소리를 복원하는 것이지, 아이가 안 말한 답을 채워 넣는 것이 아니다.
발음 거리가 충분히 가까울 때만 복원한다. 기준은 구현 시 명시하고 검증한다.

### 3-3. 미션 문맥
미션 진행 중에는 현재 질문의 주제를 우선한다.
**미션에서는 게임 어휘를 쓰지 않는다.** 미션 중 게임 금지 규칙과 일관되어야 한다.

### 3-4. 지어내기 금지 (가장 중요)
- 재해석 확신이 낮으면 **원문을 그대로 둔다.**
- 원문과 재해석 결과가 크게 다르면 재해석을 버린다.
- 아이가 말하지 않은 내용을 만들어내면 안 된다.
- 재해석은 **후보 치환**이지 문장 생성이 아니다.

### 3-5. 원문 보존
- `chat_messages` 에 저장되는 아이 발화는 무엇을 기준으로 할지 정하고 명시한다.
- **원문과 재해석 결과를 구분해 남긴다.** 어느 쪽이 화면·판정에 쓰였는지 알 수 있어야 한다.
- 기존 컬럼으로 부족하면 최소한의 컬럼만 추가한다. 기존 데이터는 건드리지 않는다.

### 3-6. 성능
- 아이가 말하고 케이가 답하기까지의 체감 지연이 늘면 안 된다.
- 재해석에 LLM 호출을 추가하는 경우, **지연 예산과 실패 시 우회 경로**를 명시한다.
- 재해석이 실패하거나 느리면 **원문으로 그대로 진행**한다. 대화를 막으면 안 된다.

### 3-7. 안전
- 재해석이 안전 판정(safety)을 우회하거나 무디게 만들면 안 된다.
- 재해석 결과가 아니라 **원문 기준으로도 안전 검사가 돌아야 한다.**

## 4. 금지 사항
- 아이 발화 원문 삭제·덮어쓰기 금지
- 정답을 재해석으로 흘리기 금지 (§3-2)
- 확신 없는 재해석 금지 (§3-4)
- 미션에서 게임 어휘 사용 금지 (§3-3)
- 기존 자유대화·미션·놀이 스킬 동작 변경 금지 — 후처리 레이어만 추가한다
- 과거 대화 일괄 재처리 금지

---

## 5. 검증

### 5-1. 재해석 성공
넌센스 퀴즈 진행 중 정답과 발음이 가까운 오인식을 넣어 복원되는지 확인한다.
실제 사례(`소 노래` → `오수 노래`/`손 노래`/`또 노래`)를 고정 테스트로 만든다.

### 5-2. 오작동 방지 (더 중요)
- 게임 중에 게임과 무관한 말을 했을 때 **억지로 게임 어휘로 바꾸지 않는가**
- 아이가 감정·안전 관련 이야기를 했을 때 원문이 훼손되지 않는가
- 정답을 말하지 않았는데 정답으로 바뀌지 않는가 — **정답 오인정 0건**

### 5-3. 회귀
- 재해석 레이어를 꺼도 기존 동작이 그대로인지 (기능 플래그 권장)
- 지연 증가폭 측정
