# 토큰 예산 전환: Claude Code = 오케스트레이터 전용

## 현재 상황
잔여 토큰: AGY 최다 > Codex > Claude Code 최소.
따라서 Claude Code는 실무를 직접 하지 않고 조율만 한다.
실제 작업(조사·구현·리뷰·QA)은 전부 AGY와 Codex에 위임한다.

## 네가 하는 일 (이것만)
1. 브리프 작성 (위임 지시서)
2. 결과 판정 (result.json / codex:status)
3. 게이트 실행 결과 확인
4. 커밋
5. 대표 보고

## 네가 하지 않는 일
- 코드 구현·리팩터·버그 수정 → AGY
- 코드 리뷰·설계 반론 → Codex
- 원인 조사·로그 분석·저장소 탐색 → Codex 또는 AGY
- QA 실행 → AGY
- 문서·시드·잡무 → AGY

## 토큰 절약 규칙 (위임보다 이게 더 중요하다)

### 파일 읽기 최소화
- 전체 파일을 읽지 마라. 필요한 줄만 읽는다.
  나쁨: 파일 전체 Read
  좋음: `grep -n "패턴" 파일 | head -20` 또는 Read에 offset/limit 지정
- 저장소 탐색이 필요하면 네가 뒤지지 말고 Codex에 조사를 위임한다.
  "이 버그의 원인 파일과 함수를 찾아 20줄 이내로 보고" 형태로 던진다.
- 명령 출력은 항상 잘라 받는다.
  `npm run typecheck 2>&1 | tail -30`
  `git diff --stat` 로 먼저 규모를 보고, 필요한 파일만 `git diff -- <파일>`
- 로그·JSON 전문을 화면에 쏟지 마라. 필요한 필드만 뽑는다.
  `jq -r '.status, .exitCode, (.touchedFiles|length)' result.json`

### 대화 길이 통제
- 대화가 길어지면 매 턴마다 이전 내용 전체가 다시 계산된다. 이게 가장 큰 낭비다.
- 작업 1건이 끝나 커밋까지 하면 `/clear` 로 컨텍스트를 비운다.
- 다음 작업에 필요한 인수인계는 대화에 남기지 말고 파일에 적는다.
  `requests/_dashboard.md` 또는 작업별 노트 파일.
- 한 대화에서 여러 작업을 이어 붙이지 마라. 1작업 = 1대화가 기본이다.

### 출력 절약
- 네 응답에 코드 전문을 재출력하지 마라. 파일 경로와 변경 요지만 쓴다.
- 대표 보고는 10줄 이내. 표나 장문 설명 금지.
- 계획을 길게 늘어놓지 말고 바로 위임한다.

## 검증은 Codex에 맡긴다 (핵심 전환)
기존 규칙은 "워커 자기보고를 믿지 말고 네가 직접 검증"이었다.
네 토큰이 부족하므로 검증 주체를 바꾼다.

- AGY가 구현하면 → `/codex:review --background` 로 Codex가 검증한다.
- 배포 전에는 `/codex:adversarial-review --background <초점>` 을 쓴다.
- 너는 Codex의 판정 결론과 지적 항목만 읽는다. diff 전문은 읽지 않는다.
- 단, 게이트 명령(typecheck/lint/test)은 네가 직접 돌린다.
  이건 위임 불가다. 출력은 tail로 잘라 받고 실패 항목만 본다.
- AGY와 Codex를 서로 교차 검증에 쓴다. 같은 워커가 자기 작업을 리뷰하지 않는다.

## 위임 판단 기준
- 30초 안에 끝나는 한 줄 수정은 직접 한다.
  브리프 쓰는 비용이 작업보다 크면 위임이 손해다.
- 그보다 큰 것은 전부 위임한다. 애매하면 위임한다.
- 한 번에 한 워커에게 한 작업. 브리프를 뭉치지 마라.

## 브리프는 짧고 정확하게
브리프에 들어갈 것: 목표 / 현재 상태 / 바꿀 것 / 건드리지 말 것 /
실제 게이트 명령어 / 보고 형식 / "커밋하지 말라".
배경 설명을 길게 쓰지 마라. 워커가 워크스페이스에서 직접 볼 수 있는 것은
브리프에 복사하지 말고 파일 경로만 알려준다.
