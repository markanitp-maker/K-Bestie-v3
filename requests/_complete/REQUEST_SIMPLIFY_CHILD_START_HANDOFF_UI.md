# REQUEST: 회원가입 완료 후 아이 시작 Handoff 화면 단순화 및 재설계

## 0. 작업 목적

첨부 비교 이미지 기준:
- 왼쪽 = 현재 구현 화면
- 오른쪽 = 대표님이 원하는 개선 목표 화면

현재 화면은 QR, 웹주소, 아이 로그인 ID, 복사 버튼, 설명문구, `또는` 구분선 등이 여러 카드로 나뉘어 정보가 과도하고, 사용자가 무엇을 먼저 해야 하는지 바로 이해하기 어렵다.

이번 작업의 목적은 현재 Handoff 화면을 오른쪽 목표 화면처럼 **더 짧고, 더 단순하고, 행동 중심으로 재설계**하는 것이다.

핵심 UX:
> 보호자는 회원가입 완료 사실을 즉시 인지하고, “이제 아이 차례”라는 메시지를 이해한 뒤, QR/웹주소 또는 같은 기기에서 아이 시작 중 하나를 바로 선택할 수 있어야 한다.

---

## 1. 현재 화면 문제점

현재 화면에는 다음 정보가 모두 동시에 노출된다.

- `4 / 4 아이 등록` 단계 표시와 progress bar
- `준비가 끝났어요!`
- `이제 아이가 케이를 시작할 차례예요.`
- QR 코드
- `또는` divider
- 별도 웹사이트 주소 카드
- `주소 복사`
- `로그인 화면에서 '아이 로그인'을 선택해 주세요.`
- 별도 아이 로그인 ID 카드
- `아이디 복사`
- 비밀번호 안내
- `이 기기에서 아이 시작하기`
- 큰 스타일의 `보호자 홈으로 이동`
- 추가 설명 문구

문제:
1. 정보가 너무 많다.
2. QR/주소/아이 ID가 각각 별도 블록이라 시선이 분산된다.
3. 완료 화면인데 기존 회원가입 폼처럼 복잡하게 보인다.
4. `또는` divider와 여러 카드 때문에 세로 길이가 불필요하게 길다.
5. 아이 로그인 ID를 완료 화면에서 다시 크게 보여줄 필요가 없다.
6. 가장 중요한 “이제 아이 차례” 메시지가 다른 요소에 묻힌다.

## 3. 상단 완료 영역

### 3.1 진행 단계 제거

현재 `4 / 4 아이 등록` 및 progress bar는 완료 화면에서 제거한다.

이 화면은 더 이상 회원가입 4단계가 아니라 **회원가입 완료 이후 Handoff 화면**이다.

### 3.2 회원가입 완료 pill

화면 상단 중앙에 작은 pill 형태로 표시한다.

문구:
`회원가입 완료`

스타일:
- K-Navy background
- white text
- 작은 rounded pill
- 과하지 않게

### 3.3 완료 비주얼

대표님 개선 시안처럼 완료 체크 아이콘을 크게 표시한다.

권장:
- 원형 soft glow
- K-Navy check
- light peach/orange accent
- 작은 sparkle 허용
- 과한 animation/confetti 금지

기존 프로젝트 내 완료 아이콘/asset이 있으면 재사용한다.

이 한 문장만 사용한다.

불필요한 추가 설명을 상단에 붙이지 않는다.

## 5. 아이 기기에서 시작하기 카드

QR과 웹주소를 하나의 카드로 통합한다.

### 카드 제목
`아이 기기에서 시작하기`

### QR
카드 중앙에 표시.

QR은 실제 아이 로그인 진입 경로를 가리켜야 한다.

우선:
1. 기존 아이 전용 login route
2. 없으면 기존 로그인 화면에서 아이 로그인 영역으로 바로 진입 가능한 route/query

QR에 절대 포함하지 말 것:
- 아이 비밀번호
- 부모 세션
- access token
- refresh token
- service_role key
- 장기 인증 token

필요하면 안전한 child login ID prefill query 정도만 허용한다.

---

## 6. QR 아래 설명

QR 아래 설명은 한 줄로 통합한다.

`QR을 비추거나, 아래 주소를 열어 주세요`

현재의 다음 문구는 제거:
- `QR을 찍기 어렵다면`
- `또는`
- `웹사이트 주소로 접속`
- `로그인 화면에서 아이 로그인을 선택해 주세요.` 별도 문구

---

## 7. 웹주소 영역

QR 카드 하단에 한 줄 compact row로 배치한다.

예:

```text
[외부링크 icon] app.k-bestie.com        [주소 복사]
```

요구사항:
- 주소는 직접 읽을 수 있어야 함
- `주소 복사` 버튼 제공
- 복사 성공 후 `복사됐어요` toast 또는 짧은 feedback
- 별도 웹사이트 카드로 만들지 말 것

---

## 8. 아이 로그인 ID 카드 제거

현재 화면의 다음 UI는 제거한다.

```text
아이 로그인 아이디
hks2
[아이디 복사]

비밀번호는 조금 전에 보호자님이 만든 비밀번호를 사용해요.
```

제거 대상:
- `아이 로그인 아이디` 별도 card
- login ID 큰 텍스트
- `아이디 복사`
- 비밀번호 설명

중요:
- child login ID 데이터 자체는 삭제하지 않는다.
- 아이 인증 구조는 변경하지 않는다.
- 부모 설정의 아이 로그인 정보 기능도 유지한다.
- 아이 로그인 화면에서 ID prefill이 필요하면 내부적으로 처리 가능하다.

이번 변경은 UI 단순화이지 인증 정책 변경이 아니다.

스타일:

- 강한 Primary CTA

- 자동 안전 전환이 없으면 보호자 세션 정리 후 아이 로그인 화면으로 이동
- 필요 시 아이 ID만 prefill
- 아이가 비밀번호 입력 후 아이 홈

## 15. 보호자 홈 재호출

새 Handoff UI는 공통 component로 구현한다.

예:
- `ChildStartGuide`
- `ChildStartGuideModal`

실제 프로젝트 naming convention을 따른다.

보호자 홈의 `아이 시작하기` 카드/버튼을 누르면 같은 간소화 UI를 modal로 다시 열 수 있어야 한다.

Modal에서는 `회원가입 완료` pill은 생략 가능하다.

핵심:
- `이제 아이 차례예요`
- QR
- 주소 row
- Primary CTA

는 동일하게 유지한다.

---

## 16. 보호자 설정 재호출

`보호자 설정 → 아이 정보 관리 → 로그인 방법`

클릭 시 해당 child 기준으로 동일 Handoff modal 표시.

화면에 아이 ID 별도 card를 다시 추가하지 않는다.

## 17. 다자녀

아이 1명:
- 바로 Handoff 표시

아이 2명 이상:
먼저 아래 선택 UI 표시.

```text
어떤 아이가 시작할까요?

[서아]
[서현]
```

선택 후 해당 child 기준:
- QR
- 아이 로그인 진입
- same-device start

를 처리한다.

다른 아이 정보가 섞이면 FAIL.

## 18. 모바일/태블릿 기준

목표:
**모바일에서 QR 카드 + Primary CTA + 보호자 홈 이동까지 가능한 한 빠르게 한 화면 흐름 안에서 보이게 한다.**

필수:
- QR 과도한 크기 금지
- 불필요한 vertical gap 제거
- iPhone SE 폭에서도 overflow 없음
- CTA가 너무 아래로 밀리지 않음
- 태블릿에서는 max-width 유지
- QR/주소 row는 한 카드 안에서 유지

## 20. 변경 금지 범위

이번 작업은 Handoff UI 단순화에 한정한다.

실제 blocking bug가 없는 한 수정 금지:
- 회원가입 1/4~4/4 입력 흐름
- 가족 만들기
- 가족 1회용 초대 링크
- 아이 등록/승인
- child login DB 구조
- password 정책
- OAuth
- withdrawal/recovery
- membership state machine
- report/chat/event
- RLS
