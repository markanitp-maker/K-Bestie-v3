# 미션 질문 이해 실패 시 1회 설명 후 동일 질문 재진행

## 1. 작업 목적

아이와 케이가 미션 대화를 진행할 때, 아이가 질문에 답하지 않고 질문의 의미를 다시 묻는 경우를 정상적으로 처리한다.

현재 미션 흐름이 정해진 질문을 순서대로 진행하는 구조이더라도, 아이가 다음과 같이 반응하면 이를 단순 무응답·무관 답변·유효하지 않은 답변으로 처리하거나 바로 다음 질문으로 넘기면 안 된다.

- “무슨 뜻이야?”
- “무슨 말이야?”
- “잘 모르겠어.”
- “좀 더 쉽게 말해줘.”
- “다시 설명해줘.”
- “이해가 안 돼.”
- 그 밖에 현재 질문의 의미나 표현을 되묻는 발화

케이는 현재 질문의 의미를 아이의 학년과 눈높이에 맞춰 최대 1회만 쉽게 설명한 뒤, 동일한 질문의 답변을 다시 받아야 한다.

## 2. 적용 범위

다음 미션 경로 전체에 동일하게 적용한다.

- 자동 음성 미션
- 수동 음성 미션
- 텍스트 입력이 존재하는 미션 경로
- STT 결과 처리
- 미션 시작 후 일반 질문 진행
- 세션 복원
- 재접속
- 미완료 세션 이어하기
- 기본 질문 10개
- 예비 질문 10개
- 미답변 질문 재순환

다음에는 적용하지 않는다.

- 자유대화
- 부모와 케이의 대화
- 관리자 기능
- 부모 질문하기 기능의 별도 재확인 절차
- 일반 STT 인식 결과 확인용 되묻기

## 3. 필수 동작 흐름

```text
현재 미션 질문 제시
→ 아이 발화 수신
→ STT 변환
→ 발화 의도 분류
→ 질문 설명 요청인지 확인
→ 설명 요청이면 현재 질문 상태 유지
→ 질문 의미를 쉬운 말로 1회 설명
→ 동일 question_id로 동일 질문 재진행
→ 아이의 다음 발화를 동일 질문의 답변으로 평가
→ 유효 답변이면 저장 후 다음 질문
→ 계속 모르겠음·무응답·무관 답변이면 미답변 처리 후 다음 질문
```

## 4. 질문 설명 요청 판정

아이 발화를 최소한 다음 유형으로 구분한다.

```typescript
type MissionAnswerIntent =
  | "VALID_ANSWER"
  | "CLARIFICATION_REQUEST"
  | "DONT_KNOW"
  | "SILENCE"
  | "IRRELEVANT"
  | "UNSAFE"
  | "ERROR";
```

### `CLARIFICATION_REQUEST`

현재 질문의 뜻, 단어, 표현 또는 답변 방법을 다시 묻는 발화다.

예:

- “무슨 뜻이야?”
- “그게 뭐야?”
- “어떻게 말해야 해?”
- “좀 쉽게 말해줘.”
- “다시 설명해줘.”
- “마음이 움직인다는 게 뭐야?”

단순 키워드 매칭만으로 처리하지 말고, 기존 미션 답변 평가 모델 또는 분류 로직에서 문맥을 함께 판단한다. 다만 명백한 표현은 LLM 호출 실패 시에도 안전하게 처리할 수 있도록 서버 측 보조 규칙을 둘 수 있다.

## 5. 설명 횟수와 상태 관리

질문별 설명은 최대 1회만 허용한다.

필수 상태:

```typescript
clarificationCount: 0 | 1
```

또는 동등한 서버 측 상태를 사용한다.

필수 조건:

- 최초 질문 시 `clarificationCount = 0`
- 설명 요청 감지 시 `clarificationCount = 1`
- 같은 질문을 다시 제시해도 `question_id`는 변경하지 않음
- 질문 순번과 진행률을 증가시키지 않음
- 유효 답변 개수를 증가시키지 않음
- 설명 요청 발화를 유효 답변으로 저장하지 않음
- 새 미션 질문으로 취급하지 않음
- 설명 후 다시 설명 요청이 와도 두 번째 설명은 하지 않음
- 최대 횟수를 초과하면 해당 질문을 미답변으로 처리하고 다음 질문으로 이동

상태는 새로고침·재접속·세션 복원 후에도 유지되어야 하며, 클라이언트 메모리에만 저장해서는 안 된다.

기존 스키마로 안전하게 표현할 수 있는지 먼저 확인하고, DB 변경이 꼭 필요한 경우에만 신규 Forward Migration을 작성한다. 이미 적용된 Migration은 수정하지 않는다.

## 6. 설명 생성 규칙

설명은 질문의 정답을 대신 제공하는 것이 아니라, 질문의 뜻만 더 쉽게 풀어주는 역할이다.

### 필수 규칙

- 아이의 현재 학년과 눈높이에 맞춘다.
- 짧고 쉬운 문장을 사용한다.
- 최대 1~2문장으로 설명한다.
- 설명 후 동일한 질문을 자연스럽게 다시 묻는다.
- 원래 질문의 핵심 의도는 바꾸지 않는다.
- 특정 답을 유도하지 않는다.
- 모범답안을 제시하지 않는다.
- 아이가 실제로 하지 않은 경험을 가정하지 않는다.
- 훈계하거나 평가하지 않는다.
- “얘기 잘 들었어, 들려줘서 고마워!” 같은 고정 감사 문구를 삽입하지 않는다.
- 아이의 STT 결과를 그대로 반복해서 읽어주지 않는다.
- 케이는 아이와 같은 학년·같은 나이의 동갑내기 친구 말투를 유지한다.

### 권장 응답 구조

```text
[쉬운 의미 설명] + [같은 질문을 자연스럽게 다시 질문]
```

### 예시 1

원래 질문:

```text
오늘 학교에서 네 마음이 가장 크게 움직였던 순간은 언제였어?
```

아이:

```text
마음이 움직였다는 게 무슨 말이야?
```

케이:

```text
기쁘거나 속상하거나 놀라는 것처럼 감정이 크게 느껴진 순간을 말하는 거야. 오늘 그런 순간이 있었어?
```

### 예시 2

원래 질문:

```text
오늘 친구와 생각이 달랐던 일이 있었어?
```

아이:

```text
무슨 뜻이야?
```

케이:

```text
너와 친구가 서로 다르게 생각하거나 원하는 게 달랐던 일이 있었는지 묻는 거야. 그런 일이 있었어?
```

## 7. 두 번째 응답 처리

설명을 한 뒤 받은 다음 발화는 동일한 `question_id`의 답변으로 평가한다.

### 유효 답변인 경우

- 기존 유효 답변 판정 규칙 적용
- 짧더라도 질문과 관련 있으면 유효 답변으로 인정
- 답변 저장
- 유효 답변 수 증가
- 진행률 증가
- 다음 질문으로 이동

### 계속 답변하기 어려운 경우

다음 중 하나면 해당 질문을 미답변 처리한 뒤 다음 질문으로 이동한다.

- “모르겠어.”
- “생각 안 나.”
- 설명을 다시 요청함
- 무응답
- 질문과 무관한 답변
- 답변 거부
- 허용된 대기 시간 초과

이때도 케이는 아이를 압박하거나 같은 질문을 반복하지 않는다.

권장 응답:

```text
괜찮아. 그럼 다음 이야기로 넘어가자.
```

고정 문구를 매번 강제하지 말고 기존 리액션 정책에 맞게 짧고 자연스럽게 처리한다.

## 8. 기존 미션 질문 순환과 통합

기존 질문 순환 규칙은 유지한다.

```text
기본 질문 10개
→ 예비 질문 10개
→ 미답변 질문 재순환
→ 유효 답변 10개 완료 시 종료
```

질문 설명 요청은 질문을 소비한 것으로 계산하지 않는다.

설명 후에도 답변을 얻지 못한 경우에만 기존 미답변 처리 규칙에 따라 재순환 대상에 포함한다.

재순환 시에는 이전 질문의 `clarificationCount` 정책을 검토하여 무한 설명 반복이 발생하지 않도록 한다. 동일 미션 세션에서 이미 설명한 동일 질문이라면 다시 설명하지 않는 것을 기본값으로 한다.

## 9. 저장·수집·리포트 정책

### 아이의 설명 요청 발화

- 대화 원장에는 필요 시 턴 기록 가능
- 유효 미션 답변으로 저장 금지
- 유효 답변 수 증가 금지
- 리포트용 핵심 답변으로 사용 금지
- Memory Fact 생성 근거로 사용 금지
- 아이의 성향이나 이해력 평가 근거로 사용 금지

### 케이의 질문 설명 메시지

- 케이 응답 턴으로 기록 가능
- 아이 답변으로 오인 금지
- Collection·Context Correction에서 질문지 설명용 시스템 턴으로 구분
- Daily Report와 Memory Batch의 사실 추출 대상에서 제외

### 설명 후 아이의 실제 답변

- 기존 정상 답변과 동일하게 처리
- 유효성 판정 후 저장
- Collection·Correction·Memory·Report에 기존 정책대로 반영

## 10. 프롬프트 반영

미션 관련 시스템 프롬프트와 답변 평가 프롬프트에 아래 원칙을 반영한다.

```text
아이가 현재 질문의 뜻을 묻거나 더 쉽게 설명해 달라고 하면, 이를 질문에 대한 답변으로 처리하지 않는다. 현재 질문의 핵심 의미를 아이의 학년 수준에 맞춰 짧고 쉽게 한 번만 설명한 뒤 같은 질문을 다시 한다. 정답이나 모범답안을 제시하지 않는다. 설명 횟수는 질문당 최대 1회이며, 다시 설명을 요청하거나 계속 답하지 못하면 해당 질문을 미답변으로 처리하고 다음 질문으로 이동한다.
```

LLM이 상태를 임의로 결정하게 두지 말고, 설명 횟수와 질문 진행 상태는 서버 로직에서 강제한다.

## 11. 오류 및 예외 처리

다음 예외를 처리한다.

- STT가 빈 문자열을 반환한 경우
- STT가 질문 설명 요청을 잘못 인식한 경우
- LLM 분류 API 실패
- 설명 생성 API 실패
- TTS가 꺼진 상태
- TTS 호출 실패
- 세션 복원 중 설명 상태 누락
- 중복 요청
- 동일 아이 답변의 재전송
- 네트워크 재시도
- 브라우저 새로고침
- 자동 모드에서 아이가 케이 설명 도중 끼어든 경우

설명 생성 실패 시 다음 질문으로 즉시 넘기지 말고, 원래 질문을 더 쉬운 사전 정의 방식으로 한 번 재표현하는 안전한 fallback을 둔다.

TTS가 꺼진 상태에서는 기존 정책대로 TTS API를 호출하지 않고 텍스트만 표시한다.

## 12. 멱등성

같은 아이 발화가 네트워크 재시도로 중복 전송되어도 다음 현상이 발생하면 안 된다.

- 설명 횟수가 2회로 증가
- 동일 설명이 중복 표시
- 질문 인덱스 중복 증가
- 유효 답변 수 중복 증가
- 동일 답변 중복 저장
- 다음 질문 두 개가 연속 생성

기존 `turn_id`, `answer_id`, 요청 ID 또는 동등한 키를 활용해 중복 처리를 방지한다.

## 13. 구현 전 감사

수정 전에 다음을 확인하고 실제 코드 기준으로 보고서에 남긴다.

- 미션 질문 생성 위치
- 미션 답변 평가 API
- 다음 질문 이동 조건
- 유효 답변 수 증가 위치
- 기본·예비·재순환 처리 위치
- 자동·수동 입력의 공통 처리 지점
- 세션 저장·복원 구조
- 현재 무응답·무관 답변 처리 방식
- 기존 retry 또는 clarification 관련 코드 존재 여부
- 최근 미션 대화 응답 개선 작업과의 충돌 여부

중복 구현을 피하고 자동·수동 모드가 공유하는 공통 서버 로직에 적용한다.

## 14. 테스트 요구사항

### 단위 테스트

최소 다음 시나리오를 작성한다.

1. 설명 요청 감지
2. 설명 후 동일 `question_id` 유지
3. 설명 시 질문 인덱스 유지
4. 설명 시 유효 답변 수 유지
5. 설명 후 유효 답변 수신
6. 설명 후 “모르겠어” 수신
7. 두 번째 설명 요청 차단
8. 짧지만 관련 있는 답변은 유효 처리
9. 무관 답변 처리
10. 무응답 처리
11. 중복 발화 멱등성
12. 세션 복원 후 `clarificationCount` 유지
13. TTS OFF 상태에서 TTS API 호출 0건
14. 자유대화에는 적용되지 않음
15. 설명 턴이 Memory·Report 사실로 추출되지 않음

### Dev E2E

신규 QA 아이 계정으로 다음을 검증한다.

#### 시나리오 A: 설명 후 정상 답변

```text
케이 질문
→ 아이 “무슨 뜻이야?”
→ 케이 쉬운 설명 1회
→ 동일 질문 재질문
→ 아이 관련 답변
→ 유효 답변 저장
→ 다음 질문 이동
```

#### 시나리오 B: 설명 후에도 모름

```text
케이 질문
→ 아이 “쉽게 설명해줘”
→ 케이 설명 1회
→ 동일 질문 재질문
→ 아이 “모르겠어”
→ 미답변 처리
→ 다음 질문 이동
```

#### 시나리오 C: 설명 반복 요청

```text
케이 질문
→ 아이 설명 요청
→ 케이 설명 1회
→ 아이 다시 설명 요청
→ 두 번째 설명 금지
→ 미답변 처리
→ 다음 질문 이동
```

#### 시나리오 D: 세션 복원

```text
설명 1회 진행
→ 새로고침 또는 재접속
→ 동일 질문과 clarificationCount 복원
→ 설명이 다시 1회 추가되지 않음
```

## 16. 완료 기준

다음 조건을 모두 충족해야 완료로 판정한다.

- 질문 설명 요청을 별도 의도로 분류한다.
- 설명 요청을 유효 답변으로 저장하지 않는다.
- 케이가 학년 수준에 맞춰 질문 의미를 최대 1회 설명한다.
- 설명 후 동일한 `question_id`를 유지한다.
- 설명만으로 질문 인덱스와 진행률이 증가하지 않는다.
- 설명 후 관련 답변을 정상 저장한다.
- 설명 후에도 답하지 못하면 다음 질문으로 이동한다.
- 무한 반복이 없다.
- 자동·수동·세션 복원에서 동일하게 동작한다.
- 소리 끄기 상태에서 TTS API를 호출하지 않는다.
- 설명 메시지가 Memory·Report 사실로 오인되지 않는다.
- 자유대화에는 영향을 주지 않는다.
- `npx tsc --noEmit` 통과
- 관련 단위 테스트 통과
- Dev E2E 통과
- 기존 미션 회귀 테스트 통과

## 17. 작업 환경 및 제한

- 우선 Dev 환경에만 구현한다.
- 실제 사용자 데이터는 수정하지 않는다.
- 신규 QA 계정 또는 테스트 Fixture만 사용한다.
- Production 배포는 하지 않는다.
- 이미 적용된 Migration 파일은 수정하지 않는다.
- DB 변경이 필요하면 Forward Migration만 추가한다.
- Secret을 코드·로그·보고서에 출력하지 않는다.
- 오류 모달이나 검증 로직을 제거해 문제를 숨기지 않는다.
- 기능을 구현했다고 주장하기 전에 실제 E2E 증거를 확보한다.
