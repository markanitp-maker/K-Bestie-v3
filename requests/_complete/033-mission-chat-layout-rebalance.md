# 033 — 미션 대화 화면 세로 공간 재배치 및 레이아웃 균형 개선

## 1. 작업 목적

현재 구현된 아이 미션 대화 화면을 첨부된 두 번째 재배치 레퍼런스를 기준으로 개선한다.

첫 번째 이미지는 현재 실제 구현 화면이고, 두 번째 이미지는 동일한 기능 요소를 유지하면서 세로 여백과 각 요소의 위치를 재조정한 목표 화면이다.

이번 작업은 기능 추가나 대화 로직 변경이 아니라 다음 문제를 해결하는 순수 UI 레이아웃 개선이다.

- 진행률 아래에 과도한 빈 공간이 생기는 문제
- 직전 대화와 현재 질문 영역이 화면 중앙 아래쪽으로 밀리는 문제
- 마스코트와 입력 컨트롤이 하단에 몰리는 문제
- 마이크 버튼이 화면 최하단에 지나치게 붙는 문제
- 좌우 상태 카드와 중앙 마스코트의 시각적 균형이 맞지 않는 문제
- 화면 높이를 충분히 활용하지 못하고 일부 영역에 여백이 집중되는 문제

기존 미션 대화 기능, 상태 머신, 음성 입력, 키보드 입력, 진행률, 황금열쇠 및 완료 정책은 변경하지 않는다.

# 2. 현재 화면과 목표 화면 비교

## 현재 구현 화면의 문제

현재 화면은 다음과 같은 세로 배치 문제를 가지고 있다.

1. 진행률과 문의 버튼 아래부터 직전 아이 발화까지 큰 빈 공간이 존재한다.
2. 직전 대화, 케이 응답, 현재 질문 말풍선이 화면 중앙 아래에 집중되어 있다.
3. 현재 질문 말풍선과 마스코트 사이의 여백이 크다.
4. 마스코트, 소리 카드, 상태 카드가 화면 하단에 몰려 있다.
5. 자동·수동 선택 버튼과 마이크 사이의 간격이 일정하지 않다.
6. 마이크 버튼이 화면 최하단 safe-area에 지나치게 가깝다.
7. 키보드 버튼과 마이크 버튼의 중심 정렬이 맞지 않는다.
8. 화면 전체가 위쪽 빈 영역과 아래쪽 기능 영역으로 단절되어 보인다.

## 목표 화면의 개선 방향

두 번째 레퍼런스처럼 다음 방향으로 재배치한다.

- 진행률 아래의 빈 공간을 줄인다.
- 직전 대화 영역을 위로 이동한다.
- 현재 질문 말풍선을 위로 이동한다.
- 마스코트와 상태 컨트롤 묶음을 위로 이동한다.
- 자동·수동 버튼을 단상과 더 가깝게 배치한다.
- 마이크와 키보드 버튼을 위로 올려 하단 여백을 확보한다.
- 전체 요소 간 간격을 일정한 규칙으로 통일한다.
- 화면 중앙에 빈 공간이 몰리지 않도록 세로 밀도를 균등하게 분배한다.

# 3. 위치 변화 기준

스크린샷 비율을 기준으로 한 대략적인 위치 변화는 다음과 같다.

| 영역 | 현재 위치 | 목표 위치 | 변경 방향 |
|---|---:|---:|---|
| 직전 대화 시작 | 화면 높이 약 35% | 약 27~28% | 약 7~8%p 위로 |
| 현재 질문 시작 | 약 48% | 약 41% | 약 7%p 위로 |
| 마스코트 시작 | 약 66% | 약 59% | 약 7%p 위로 |
| 마이크 중심 | 약 94% | 약 90% | 약 4%p 위로 |

390×844 화면으로 환산하면 다음 정도의 변화다.

- 직전 대화 영역: 약 55~65px 위로 이동
- 현재 질문 말풍선: 약 55~60px 위로 이동
- 마스코트 및 상태 카드: 약 50~60px 위로 이동
- 마이크와 키보드: 약 30~40px 위로 이동
- 마이크 아래 safe-area 포함 여백: 약 25~35px 확보

이 수치는 절대 좌표로 하드코딩하기 위한 값이 아니라 목표 화면의 상대적인 균형을 설명하기 위한 기준이다.

# 5. 화면 전체 레이아웃 원칙

## 기본 컨테이너

- 높이 기준은 `100dvh`
- 너비는 `100%`
- 전체 문서 가로 스크롤 금지
- 일반적인 모바일 화면에서는 문서 전체 세로 스크롤 없이 한 화면에 주요 기능을 표시
- 320×568처럼 매우 짧은 화면에서는 최소한의 세로 스크롤을 허용할 수 있음
- iOS 및 Android safe-area 반영
- 화면 내부 요소를 절대 좌표만으로 배치하지 않음
- CSS Grid 또는 Flex를 사용하여 영역 간 관계를 유지

## 권장 영역 구조

```text
MissionChatPage
├─ TopControls
│  ├─ CloseButton
│  └─ ProgressBar
├─ InquiryButton
├─ ConversationContext
│  ├─ PreviousChildUtterance
│  └─ PreviousKResponse
├─ CurrentQuestionBubble
├─ MascotInteractionArea
│  ├─ SoundControl
│  ├─ MascotStage
│  └─ ConversationStatus
├─ InputModeSelector
└─ BottomInputControls
   ├─ KeyboardButton
   └─ MicrophoneButton
```

문의 버튼은 독립적인 레이아웃 영역을 과도하게 차지하지 않도록 상단 우측에 배치한다.

- 종료 버튼의 레이아웃 영역 때문에 대화 영역 전체가 아래로 밀리지 않게 한다.

# 7. 진행률 카드

진행률 카드는 현재 너비와 기본 디자인을 유지하되 세로 공간을 압축한다.

## 목표 기준

- 화면 좌우 여백 약 12~16px
- 높이 약 38~44px
- 종료 버튼 아래 약 12~18px
- 진행률 아래 다음 콘텐츠까지 약 8~12px

## 유지 사항

- 총 10개 진행 원
- 실제 유효 답변 수와 연결
- 완료 원 K-Orange 또는 K-Mascot Orange
- 미완료 원 연한 K-Sky Blue
- 진행률 데이터와 애니메이션 유지

진행률 아래에 별도의 큰 고정 여백을 두지 않는다.

현재 문의 버튼을 우측에 유지하되 진행률과 대화 영역 사이의 빈 공간을 만들지 않도록 한다.

## 크기

# 9. 직전 대화 영역 재배치

현재 화면에서 가장 큰 불필요한 빈 공간은 문의 버튼 아래부터 직전 아이 발화까지의 영역이다.

이 빈 공간을 대폭 축소한다.

## 목표 위치

390×844 화면 기준으로 직전 대화 영역 시작 위치를 현재보다 약 55~65px 위로 이동한다.

화면 전체 비율 기준:

```text
현재: 화면 높이 약 35%
목표: 화면 높이 약 27~28%
```

## 구성

### 직전 아이 발화

- 가운데 정렬
- Neutral 보조 텍스트
- 최대 1~2줄
- 글자 크기 약 12~14px
- 하단 여백 약 8~12px
- 긴 텍스트가 전체 화면을 아래로 밀지 않도록 최대 높이 제한

### 직전 케이 응답

- 흰색 또는 반투명 흰색 카드
- 화면 너비 약 78~82%
- 가운데 정렬
- 내부 padding 상하 약 10~14px
- 좌우 약 14~18px
- 최대 3줄
- 현재 구현보다 세로 padding을 소폭 축소
- radius 유지
- 약한 그림자 유지

## 간격

```text
직전 아이 발화
↓ 8~12px
직전 케이 응답
↓ 12~16px
현재 질문 말풍선
```

현재처럼 영역 사이에 수십 px의 비정상적인 공백을 두지 않는다.

# 10. 현재 질문 말풍선 재배치

현재 질문 말풍선은 화면에서 가장 중요한 정보이므로 읽기 편해야 하지만, 과도하게 아래로 밀리거나 높이가 커지지 않도록 한다.

## 목표 위치

390×844 화면 기준으로 현재보다 약 55~60px 위로 이동한다.

화면 비율 기준:

```text
현재: 화면 높이 약 48%
목표: 화면 높이 약 41%
```

## 크기

- 화면 너비 약 84~88%
- 좌우 중앙 정렬
- 최소 높이는 유지
- 내부 padding 현재보다 약 10~15% 축소 가능
- 텍스트 크기는 줄이지 않음
- line-height는 약 1.35~1.45 유지
- 최대 4줄 수준에서 안정적으로 표시
- 더 긴 질문은 말풍선 내부 스크롤 또는 기존 긴 질문 정책 사용

## 디자인

- 흰색 배경
- K-Orange 테두리
- 아래 중앙 말풍선 꼬리
- K-Navy 또는 진한 Neutral 텍스트
- 약한 주황색 그림자

## 간격

현재 질문 말풍선과 마스코트 사이의 간격을 현재보다 줄인다.

권장:

```text
말풍선 꼬리 하단
↓ 28~42px
마스코트 상단
```

현재처럼 큰 빈 공간을 두지 않는다.

---

# 11. 마스코트 영역 재배치

## 목표 위치

390×844 화면 기준으로 마스코트와 상태 카드 묶음을 현재보다 약 50~60px 위로 이동한다.

화면 비율 기준:

```text
현재: 마스코트 시작 약 66%
목표: 약 59%
```

## 마스코트 크기

마스코트 자체를 지나치게 축소하지 않는다.

권장:

```css
width: clamp(78px, 24vw, 112px);
```

실제 프로젝트의 기존 마스코트 크기 토큰 또는 컴포넌트를 우선 사용한다.

## 무대

- 마스코트 바로 아래
- 마스코트와 무대 사이에 떠 보이는 큰 간격 금지
- 무대 높이를 현재보다 소폭 축소 가능
- 마스코트 그림자 유지
- 무대가 자동·수동 버튼과 과도하게 떨어지지 않도록 한다.

# 12. 소리 카드와 상태 카드 정렬

## 목표

왼쪽 소리 카드, 중앙 마스코트, 오른쪽 상태 카드를 하나의 시각적 그룹으로 정렬한다.

## 수평 배치

```text
[소리 카드]   [마스코트]   [상태 카드]
```

## 세로 정렬

- 두 카드의 세로 중심을 서로 맞춘다.
- 두 카드의 중심을 마스코트 몸통 중앙 또는 하단 40% 지점과 정렬한다.
- 한쪽 카드만 위나 아래로 치우치지 않게 한다.

## 좌우 여백

- 화면 가장자리에서 약 14~18px
- 마스코트와 카드 사이 최소 약 12~18px
- 320px 화면에서도 겹침 금지

## 카드 크기

- 양쪽 카드의 가로·세로 크기를 동일하게 맞춘다.
- 목표 크기 예시: 약 54~64px 너비, 62~76px 높이
- 아이콘과 상태 문구가 중앙 정렬
- 긴 상태 문구는 두 줄로 만들지 말고 기존 짧은 상태명을 사용

## 상태

- 소리 켜짐/꺼짐
- 듣는 중
- 대기 중
- 생각 중
- 말하는 중
- 연결 중
- 오류

기존 상태 머신과 마이크 활성 정책을 유지한다.

# 13. 자동·수동 선택 버튼 재배치

현재보다 단상과 가까운 위치에 배치한다.

## 목표

- 단상 하단과 자동·수동 버튼 상단 사이 약 0~8px
- 버튼이 단상 바로 앞에 연결된 것처럼 보이게 구성
- 자동 선택 버튼의 말풍선 꼬리 유지
- 두 버튼 수평 중심 정렬

## 크기

- 버튼 높이 약 42~48px
- 자동·수동 버튼 사이 간격 약 6~10px
- 글자 크기와 접근성 터치 영역 유지
- 화면 폭에 따라 버튼이 지나치게 커지지 않도록 한다.

## 주의

- 버튼 위치 변경으로 실제 모드 전환 로직을 수정하지 않는다.
- 키보드 입력 시 수동 전환 정책 유지
- 선택 상태와 실제 입력 모드 일치

# 14. 하단 입력 컨트롤 재배치

## 마이크 버튼

현재 마이크 버튼은 화면 최하단에 지나치게 가깝다.

390×844 기준으로 현재보다 약 30~40px 위로 이동한다.

화면 비율 기준:

```text
현재 마이크 중심: 화면 높이 약 94%
목표 마이크 중심: 약 89~90%
```

## 마이크 크기

- 기존 크기 유지 또는 미세 조정
- 약 68~82px
- 최소 터치 영역 72×72px
- 자동·수동 버튼과 마이크 사이 약 20~30px
- 하단 safe-area 포함 여백 약 28~40px

## 키보드 버튼

- 마이크 버튼의 세로 중심과 최대한 맞춘다.
- 좌측 약 14~20px
- 크기 약 44~54px
- 마이크보다 약간 작게 유지
- 하단 위치가 마이크보다 과도하게 높거나 낮지 않게 한다.

## 하단 정렬 예시

```text
[키보드]             [마이크]
```

키보드 버튼은 왼쪽 하단, 마이크는 화면 중앙에 유지한다.

오른쪽에 별도의 빈 버튼이나 불필요한 균형용 요소를 추가하지 않는다.

---

# 15. 목표 세로 간격 기준

390×844 화면에서 다음 간격을 기본 목표로 한다.

| 구간 | 권장 간격 |
|---|---:|
| 종료 버튼 → 진행률 | 10~18px |
| 진행률 → 문의 버튼 | 8~12px |
| 문의 버튼 → 직전 아이 발화 | 24~36px |
| 아이 발화 → 이전 케이 응답 | 8~12px |
| 이전 케이 응답 → 현재 질문 | 12~16px |
| 현재 질문 → 마스코트 | 28~42px |
| 마스코트 → 단상 | 0~6px |
| 단상 → 자동·수동 버튼 | 0~8px |
| 자동·수동 버튼 → 마이크 | 20~30px |
| 마이크 → 하단 safe-area | 28~40px |

이 값은 `clamp()`와 viewport 높이에 따라 유동적으로 적용한다.

모든 값을 고정 px로만 하드코딩하지 않는다.

# 16. 화면 높이별 대응

## 390×844 이상

- 두 번째 레퍼런스와 동일한 세로 배치
- 문서 전체 스크롤 없이 주요 요소 표시
- 마이크 아래 충분한 safe-area 확보

## 360×800

- 영역 간 간격을 약 10~15% 축소
- 마스코트 크기를 소폭 축소
- 질문 말풍선 글자 크기는 유지

## 375×667

- 문의 버튼과 대화 영역 사이 간격 축소
- 직전 응답 카드 padding 축소
- 마스코트 및 단상 크기 축소
- 마이크는 하단 safe-area 위에 유지

## 320×568

축소 우선순위:

1. 장식 요소 숨김
2. 상단 및 영역 간 여백 축소
3. 직전 대화 최대 줄 수 축소
4. 마스코트 크기 축소
5. 단상 높이 축소

숨기면 안 되는 요소:

- 종료 버튼
- 진행률
- 현재 질문
- 마스코트
- 상태 표시
- 자동·수동 선택
- 마이크
- 키보드 입력 수단

모든 요소를 억지로 한 화면에 압축해 글자가 지나치게 작아지는 경우에는 최소한의 세로 스크롤을 허용한다.

# 17. CSS 구현 원칙

## 절대 위치 최소화

다음 요소를 제외하고 전체 레이아웃을 절대 좌표로 구현하지 않는다.

- 우측 상단 종료 버튼
- 문의 버튼이 기존 정책상 Floating인 경우
- 말풍선 꼬리
- 장식용 배경 요소

대화 영역, 마스코트, 입력 컨트롤은 Grid 또는 Flex Flow 안에서 배치한다.

## 권장 CSS 변수

```css
:root {
  --mission-top-gap: clamp(8px, 1.6dvh, 16px);
  --mission-section-gap: clamp(10px, 1.8dvh, 18px);
  --mission-context-gap: clamp(8px, 1.2dvh, 12px);
  --mission-question-mascot-gap: clamp(28px, 4dvh, 42px);
  --mission-mode-mic-gap: clamp(20px, 3dvh, 30px);
  --mission-bottom-safe-gap:
    calc(env(safe-area-inset-bottom) + clamp(20px, 3dvh, 32px));
}
```

실제 토큰 구조에 맞게 이름을 조정한다.

## `100vh` 금지

모바일 브라우저 주소창에 따른 잘림을 막기 위해 `100dvh`를 기본으로 사용한다.

필요하면 `svh` fallback을 검토한다.
