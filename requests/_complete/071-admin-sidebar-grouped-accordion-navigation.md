# Request: 관리자 사이드바 메뉴 그룹화 및 아코디언 구조 개편

## 1. 작업 목적

현재 관리자 사이드바에 모든 메뉴가 한 단계로 길게 나열되어 있어 탐색이 어렵고 스크롤이 과도하게 발생한다.

비슷한 기능을 상위 그룹으로 묶고, 상위 타이틀을 클릭하면 하위 메뉴가 펼쳐지거나 접히는 아코디언 구조로 개편한다. 데스크톱 사이드바와 모바일 관리자 드로어에 동일하게 적용한다.

## 2. 확정 메뉴 구조

```text
대시보드
├─ 전체 현황
├─ 매출·가입자 상세
├─ 나갈 돈·비용 상세
└─ LLM 사용 현황

사용자 관리
├─ 부모 계정 관리
├─ 아이 계정 관리
├─ 계정 복구 승인
├─ 요금제 변경 요청
└─ 아이 승인 요청

고객 접수
├─ 문의 접수
├─ 건의 접수
└─ 버그 접수

리포팅·분석
├─ 리포팅 수동 실행
└─ 사용자 리텐션

이벤트·보상
├─ 이벤트 현황
├─ 미션 이벤트
├─ 퀴즈 리더보드
└─ 상품권 지급 관리

운영 도구
├─ 푸시 발송 테스트
├─ 회원가입 유입 링크 관리
├─ 회원가입 유입 현황
└─ 휴지통
```

## 3. 기존 메뉴 반영 원칙

- 실제 현재 코드와 라우트를 먼저 확인하고 존재하는 메뉴만 배치한다.
- 구현되지 않은 메뉴를 빈 페이지나 임시 라우트로 추가하지 않는다.
- `베타 신청 관리`는 앞서 확정한 정책대로 사이드바에서 제거한다.
- 기존 베타 신청 데이터는 삭제하지 않는다.
- 문의·건의·버그가 이미 분리 구현됐으면 각각 표시한다.
- 아직 통합 메뉴만 존재하면 임의로 세 개처럼 보이게 하지 말고, 분리 작업 완료 후 그룹에 연결한다.

## 4. 사용자 관리 중복 메뉴 처리

앞서 확정한 사용자 관리 통합 작업이 완료된 경우 아래 독립 메뉴는 중복 표시하지 않는다.

```text
계정 복구 승인
→ 부모 계정 관리 > 계정 복구 요청 탭

요금제 변경 요청
→ 부모 계정 관리 > 요금제 변경 요청 탭

아이 승인 요청
→ 아이 계정 관리 > 승인 대기 탭
```

통합이 아직 완료되지 않았다면 기존 메뉴를 유지하되 `사용자 관리` 그룹 아래에 배치한다.

## 5. 상위 그룹 동작

- 상위 그룹은 페이지 이동 링크가 아니라 토글 버튼으로 구현
- 클릭 시 하위 메뉴 펼침·접힘
- 펼침 상태에서는 아래 방향 화살표
- 접힘 상태에서는 오른쪽 방향 화살표
- 현재 접속한 하위 메뉴가 속한 그룹은 자동 펼침
- 선택된 하위 메뉴는 기존 파란색 활성 스타일 유지
- 활성 하위 메뉴가 있는 상위 그룹도 구분되게 표시
- 키보드 Enter·Space로 토글 가능
- `aria-expanded`, `aria-controls` 등 접근성 속성 적용

## 6. 펼침 상태 정책

여러 그룹을 동시에 펼칠 수 있게 한다.

상태 유지 기준:

- 현재 선택 메뉴가 포함된 그룹은 항상 펼침
- 사용자가 직접 열고 닫은 상태는 브라우저 세션 동안 유지
- `sessionStorage` 또는 기존 UI 상태 관리 방식 사용
- 새로고침 후 최소한 현재 선택 메뉴의 그룹은 자동 펼침
- SSR hydration 오류가 발생하지 않게 구현

## 7. 메뉴 설정 구조

메뉴를 JSX에 반복 하드코딩하지 말고 공통 설정 배열에서 관리한다.

권장 구조:

```ts
type AdminMenuItem = {
  label: string;
  href: string;
  badgeKey?: string;
  aliases?: string[];
};

type AdminMenuGroup = {
  id: string;
  label: string;
  items: AdminMenuItem[];
};
```

실제 프로젝트 라우트와 메뉴명을 확인한 뒤 적용한다. 예시 경로를 추측해서 하드코딩하지 않는다.

## 8. 현재 경로 활성 판정

상세 페이지와 쿼리스트링에서도 올바른 메뉴가 활성화돼야 한다.

예:

```text
/admin/users/parents
/admin/users/parents/123
/admin/users/parents?tab=recovery
```

위 경로는 모두 `부모 계정 관리`를 활성화할 수 있어야 한다.

단순 `pathname === href`만 사용하지 말고 prefix 또는 aliases 기반 판정을 적용한다.

## 9. 메뉴별 그룹 목적

### 대시보드
전체 운영 현황, 매출·비용, AI 모델 현황 확인

### 사용자 관리
부모·아이 계정, 승인·복구·요금제 요청 관리

### 고객 접수
문의, 건의, 버그 접수 처리

### 리포팅·분석
리포팅 수동 실행과 리텐션 분석

### 이벤트·보상
이벤트, 미션 이벤트, 퀴즈 리더보드, 상품권 관리

### 운영 도구
푸시 테스트, 회원가입 유입 관리, 휴지통 등 운영 보조 기능

## 10. 배지 표시

기존 미처리 건수 배지가 있으면 하위 메뉴에 유지한다.

예:

```text
문의 접수 3
건의 접수 1
버그 접수 2
```

하위 메뉴가 하나도 없는 그룹은 표시하지 않는다.

## 11. 디자인 기준

### 상위 그룹
- 하위 메뉴보다 글자 굵기를 높임
- 그룹 간 간격 제공
- 우측 펼침·접힘 아이콘
- 전체 행 클릭 가능
- hover, focus, active 상태 제공

### 하위 메뉴
- 상위 그룹보다 들여쓰기
- 선택된 메뉴는 기존 파란색 배경 유지
- 긴 메뉴명은 잘리지 않게 처리
- 사이드바 폭은 기존 AdminShell 정책을 우선하되 약 220~240px 권장

## 12. 모바일 관리자 드로어

- 동일한 그룹 구조 적용
- 그룹 펼침·접힘 가능
- 하위 메뉴 선택 시 드로어 닫힘
- 상위 그룹 토글 시 드로어 유지
- 현재 페이지 그룹 자동 펼침
- 내부 스크롤 가능
- iOS safe-area 대응
- 마지막 메뉴까지 접근 가능

## 13. 데스크톱 사이드바 스크롤

권장 구조:

```text
상단 관리자 타이틀: 고정
메뉴 그룹 영역: 스크롤
하단 계정/로그아웃 영역: 필요 시 고정
```

페이지 본문 스크롤과 사이드바 스크롤이 서로 간섭하지 않게 한다.

## 14. 권한별 메뉴 표시

- 기존 관리자 권한 필터 유지
- 권한 없는 하위 메뉴 숨김
- 하위 메뉴가 모두 숨겨지면 상위 그룹도 숨김
- 사이드바 숨김만으로 접근 제어하지 않음
- URL 직접 접근 시 서버 권한 검사 유지

## 19. 보안 및 작업 제한

- Production Service Role Key 평문 하드코딩 금지
- API Key, 비밀번호, Token 로그 출력 금지
- Secret 임시 파일 저장 금지
- 메뉴 숨김만으로 권한 제어하지 않음
- 기존 관리자 API 권한 검사 제거 금지
- 기존 데이터 수정·삭제 금지
- 존재하지 않는 라우트를 추측해 연결 금지
