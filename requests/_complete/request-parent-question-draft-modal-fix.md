# 부모 질문하기 기능 수정 요청 — 초안 질문 모달 필수 구현

## 1. 작업 목적

부모용 `케이와 대화` 화면에서 케이가 아이 관련 질문에 답하지 못했을 때 표시되는 `아이에게 물어보기` 버튼을 누르면, 질문이 즉시 등록되거나 아무 반응 없이 끝나는 것이 아니라 반드시 **초안 질문 확인 모달**이 열리도록 수정한다.

현재 화면에는 아래 기능이 이미 보인다.

- `대화 / Q&A` 탭
- 케이의 정보 없음 응답
- `아이에게 물어보기` 버튼
- `지금은 넘어가기` 버튼

그러나 `아이에게 물어보기` 버튼 클릭 후 요구했던 초안 질문 모달이 표시되지 않는다. 이는 부모 질문하기 기능의 핵심 확인 절차가 누락된 상태다.

우선순위는 **P0**이다.

## 2. 현재 재현 상태

### 재현 질문

```text
어제 서아 기분이 왜 속상한 거야?
```

### 케이 응답

```text
제가 확인할 수 있는 기록에는 관련된 구체적인 내용이 남아 있지 않아요.
학교생활, 친구, 기분 중 궁금한 부분을 말씀해 주시면 그 범위로 다시 확인해 볼게요.
```

### 화면 상태

- `아이에게 물어보기` 버튼이 표시됨
- `지금은 넘어가기` 버튼이 표시됨
- `Q&A` 탭이 표시됨

### 오류

`아이에게 물어보기` 버튼을 클릭해도 아래 필수 절차가 실행되지 않는다.

```text
부모 원문 질문
→ 아이에게 전달할 단일 질문 초안 생성
→ 초안 질문 모달 표시
→ 부모 확인·수정
→ 최종 승인
→ 질문 대기열 등록
```

버튼 클릭 즉시 질문을 등록하거나, 모달 없이 상태만 변경하거나, 아무 반응이 없는 구현은 모두 실패다.

---

## 3. 반드시 구현할 정상 흐름

```text
1. 부모가 케이에게 아이 관련 질문을 한다.
2. 리포트·보정 대화·LLM Wiki에 근거가 없을 때만 `아이에게 물어보기` 버튼을 표시한다.
3. 부모가 버튼을 누른다.
4. 부모의 직전 질문을 기준으로 아이에게 전달할 질문 초안을 생성한다.
5. 초안 질문 모달을 연다.
6. 부모가 질문을 확인하거나 수정한다.
7. 서버에서 단일 질문 여부, 주간 횟수, 권한, 안전성을 다시 검증한다.
8. 부모가 `질문 등록하기`를 눌렀을 때만 질문을 대기열에 저장한다.
9. 저장 성공 후 Q&A 탭에 `질문 대기 중`으로 표시한다.
```

## 4. 초안 질문 모달 UI

### 4.1 모달 기본 구성

모달에는 아래 항목을 반드시 포함한다.

```text
아이에게 이렇게 물어볼까요?

이번 주 질문 1/3

질문 초안
[어제 속상한 일이 있었는지 물어볼까요?]

한 번에 한 가지 질문만 아이에게 전달할 수 있어요.
케이는 아이와 자연스럽게 대화할 수 있는 순간에 질문하고,
아이의 답변을 다시 확인한 뒤 부모님께 알려드려요.

[취소] [질문 등록하기]
```

### 4.2 표시 항목

- 대상 아이 이름
- 이번 주 사용 순서: `1/3`, `2/3`, `3/3`
- 남은 횟수
- 수정 가능한 질문 초안 입력창
- 한 번에 질문 1개만 가능하다는 안내
- 아이 답변을 재확인한 뒤 전달한다는 안내
- 취소 버튼
- 질문 등록하기 버튼
- 등록 중 로딩 상태
- 오류 메시지 영역

### 4.3 모바일 요구사항

- iPhone 세로 화면 기준으로 화면 안에 모달이 완전히 보여야 한다.
- 키보드가 올라와도 질문 입력창과 등록 버튼에 접근할 수 있어야 한다.
- 배경 스크롤을 막는다.
- 모달 내부 내용이 길면 모달 내부만 스크롤한다.
- 닫기 버튼 또는 취소 버튼을 명확히 제공한다.
- 모달을 닫으면 원래 대화 위치를 유지한다.
- Safe Area를 준수한다.

## 5. 질문 초안 생성 규칙

### 5.1 부모 원문을 그대로 복사하지 않는다

부모의 질문을 아이에게 자연스럽고 부담 없는 한 문장으로 변환한다.

부모 원문:

```text
어제 서아 기분이 왜 속상한 거야?
```

초안 예시:

```text
어제 마음이 속상했던 일이 있었는지 물어볼까요?
```

아이에게 실제 질문할 때의 표현 예시:

```text
어제 마음이 조금 속상했던 일이 있었어?
```

### 5.2 부모가 시켰다는 사실을 아이에게 노출하지 않는다

금지:

```text
엄마가 물어보라고 했어.
아빠가 궁금해하셔.
부모님이 질문을 보냈어.
```

허용:

```text
하나 궁금한 게 있어.
어제 마음이 속상했던 일이 있었어?
```

### 5.3 질문은 반드시 한 개

부모 질문에 여러 질문이 포함되어 있어도 초안은 한 개만 만든다.

부모 입력:

```text
어제 왜 속상했는지, 누구랑 다퉜는지, 학교에서 무슨 일이 있었는지 물어봐 줘.
```

정상 모달 안내:

```text
한 번에 한 가지 질문만 전달할 수 있어요.
먼저 아래 질문으로 진행할까요?
```

초안:

```text
어제 마음이 속상했던 이유가 있었는지 물어볼까요?
```

나머지 질문은 자동 등록하지 않는다.

### 5.4 질문 안전성

초안 생성 시 아래 표현을 제거하거나 재작성한다.

- 비난
- 추궁
- 답을 유도하는 표현
- 죄책감을 주는 표현
- 아이가 부모 편을 들도록 요구하는 표현
- 친구·학교·가족을 공격적으로 평가하게 하는 표현
- 한 문장 안의 복수 질문

## 6. 모달 상태 관리

필수 상태 예시:

```text
isDraftModalOpen
draftQuestion
originalParentQuery
selectedChildId
weeklyUsedCount
weeklyLimit
isGeneratingDraft
isSubmitting
draftError
submitError
```

### 6.1 버튼 클릭 시

`아이에게 물어보기` 클릭 시 아래 순서를 보장한다.

```text
1. 직전 부모 질문과 대상 child_id 확보
2. 부모-아이 권한 확인
3. 주간 사용 횟수 조회
4. 질문 초안 생성
5. 생성 성공 후 모달 열기
```

초안 생성에 시간이 걸리면 버튼 또는 모달에 로딩 상태를 표시한다.

### 6.2 모달 열기 실패

초안 생성 API가 실패해도 아무 반응 없이 끝내지 않는다.

표시 예시:

```text
질문 초안을 만드는 중 문제가 발생했어요.
잠시 후 다시 시도해 주세요.
```

실패 시 질문을 등록하거나 횟수를 차감하지 않는다.

### 6.3 모달 취소

- DB 등록 없음
- 주간 횟수 차감 없음
- Q&A 목록 추가 없음
- 대화 메시지 추가 없음
- 초안 상태 초기화

### 6.4 최종 등록

`질문 등록하기` 클릭 시에만 서버 요청을 실행한다.

서버에서 다시 확인할 항목:

- 인증된 부모인지
- 해당 아이의 보호자인지
- 이번 주 3회를 초과하지 않는지
- 질문이 한 개인지
- 질문이 비어 있지 않은지
- 금지 표현이 없는지
- 동일 요청이 중복 등록되지 않았는지

## 7. 주간 3회 제한

### 7.1 표시

초안 질문 모달에 반드시 표시한다.

```text
이번 주 질문 1/3
남은 질문 2회
```

### 7.2 차감 시점

횟수는 아래 시점에만 차감한다.

```text
부모가 모달에서 `질문 등록하기`를 눌러
질문 대기열 저장이 성공한 시점
```

아래 경우 차감 금지:

- 모달 열기
- 초안 생성
- 질문 수정
- 취소
- 등록 API 실패
- 권한 오류
- 중복 요청 차단
- 네트워크 오류로 저장되지 않은 경우

### 7.3 3회 사용 완료

버튼 클릭 시 모달 대신 아래 안내를 표시할 수 있다.

```text
이번 주 질문 3회를 모두 사용했어요.
다음 주 월요일부터 다시 질문할 수 있어요.
```

주간 기준은 KST 월요일 00:00부터 일요일 23:59:59까지다.

## 8. 질문 등록 후 동작

등록 성공 후:

1. 모달을 닫는다.
2. 성공 메시지를 표시한다.
3. Q&A 탭에 새 항목을 즉시 반영한다.
4. 상태를 `질문 대기 중`으로 표시한다.
5. 동일 질문이 중복 표시되지 않게 한다.
6. 대화 화면의 원래 위치를 유지한다.

성공 메시지 예시:

```text
질문을 등록했어요.
케이가 아이와 자연스럽게 대화할 수 있는 순간에 물어보고,
답변을 다시 확인한 뒤 알려드릴게요.
```

즉시 답변을 받을 수 있다고 안내하지 않는다.

## 9. Q&A 탭 연동

등록된 질문은 Q&A 탭에 즉시 표시한다.

필수 표시 정보:

```text
질문
대상 아이
등록일
이번 주 사용 순서
상태
답변 또는 상태 안내
```

등록 직후 예시:

```text
질문
어제 마음이 속상했던 일이 있었는지 물어봐 주세요.

대상
박서아

상태
질문 대기 중

등록
2026.08.04
```

상태 문구:

| 내부 상태 | 부모 화면 |
|---|---|
| PENDING | 질문 대기 중 |
| SCHEDULED | 다음 대화에서 질문 예정 |
| ASKED | 아이에게 질문했어요 |
| CONFIRMING | 아이에게 답변을 다시 확인하고 있어요 |
| ANSWERED | 답변 완료 |
| DECLINED | 아이가 이번 질문에는 답변하지 않기로 했어요 |
| EXPIRED | 기간 내 질문하지 못했어요 |
| FAILED | 처리 중 문제가 발생했어요 |

## 10. 아이 미션 연동 유지

이번 수정으로 기존 부모 질문 전체 정책이 훼손되면 안 된다.

- 승인된 질문만 아이 질문 대기열에 등록
- 미션 중 자연스러운 시점에 한 번 질문
- 부모가 시켰다는 사실 비노출
- 한 미션에 부모 질문 최대 1개
- 부모 질문은 미션 유효 답변 10개에 포함하지 않음
- 아이 1차 답변 후 반드시 재확인
- 아이가 `맞아` 등으로 최종 확인한 답변만 부모에게 전달
- 아이가 거부하면 강요하지 않고 `DECLINED`
- 미확인 STT 결과를 부모에게 사실로 전달 금지

## 11. 구현 점검 항목

현재 코드에서 아래 항목을 실제로 확인한다.

1. `아이에게 물어보기` 버튼의 `onClick`
2. 클릭 이벤트가 연결된 Handler
3. 직전 부모 질문을 보존하는 상태 또는 메시지 ID
4. 선택된 아이 ID 전달
5. 질문 초안 생성 API
6. 모달 컴포넌트 존재 여부
7. 모달 open/close 상태
8. 질문 등록 API
9. 주간 횟수 조회·차감 RPC
10. Q&A 목록 갱신
11. 모바일 Portal, z-index, overflow 설정
12. Dev와 Production 배포 차이

버튼만 렌더링하고 Handler가 비어 있거나, 질문 등록 API를 직접 호출하는 구조라면 수정한다.

## 12. 테스트 요구사항

### 12.1 단위 테스트

- 버튼 클릭 → 초안 생성 함수 호출
- 초안 성공 → 모달 open
- 초안 실패 → 오류 안내
- 모달 취소 → 등록 API 호출 0회
- 모달 취소 → 횟수 차감 0회
- 등록 클릭 → 등록 API 1회
- 등록 성공 → 모달 close
- 등록 성공 → Q&A 목록 갱신
- 등록 실패 → 모달 유지
- 등록 실패 → 횟수 차감 없음
- 복수 질문 → 단일 질문 초안
- 3/3 사용 상태 → 신규 등록 차단
- 중복 클릭 → 등록 1건
- 다른 아이로 전환 후 클릭 → 현재 선택된 child_id 사용

## 13. 완료 기준

아래 항목이 모두 충족되어야 완료다.

- [ ] `아이에게 물어보기` 클릭 시 초안 질문 모달이 열린다.
- [ ] 버튼 클릭만으로 질문이 즉시 등록되지 않는다.
- [ ] 모달에 대상 아이 이름이 표시된다.
- [ ] 모달에 `이번 주 질문 N/3`이 표시된다.
- [ ] 부모 직전 질문을 기준으로 자연스러운 초안이 생성된다.
- [ ] 복수 질문은 한 질문으로 정리된다.
- [ ] 부모가 초안을 수정할 수 있다.
- [ ] 취소 시 질문이 등록되지 않는다.
- [ ] 취소 시 횟수가 차감되지 않는다.
- [ ] 최종 승인 후에만 질문 대기열에 저장된다.
- [ ] 등록 성공 후 Q&A 탭에 즉시 표시된다.
- [ ] 등록 실패 시 횟수를 차감하지 않는다.
- [ ] 모바일에서 모달·키보드·버튼이 정상 동작한다.
- [ ] 중복 클릭과 네트워크 재시도에도 질문이 중복 등록되지 않는다.
- [ ] 기존 미션 질문·재확인·거부 정책이 유지된다.
- [ ] TypeScript 검사, 빌드, 단위 테스트, E2E가 통과한다.
- [ ] Development 실제 검증 후에만 Production에 배포한다.
