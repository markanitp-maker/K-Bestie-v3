# 미션 질문 이해 실패 시 쉬운 설명 및 동일 질문 1회 재질문

## 1. 작업 목적

현재 미션 진행 중 아이가 질문을 이해하지 못하거나 다시 설명해 달라고 말해도, 케이가 해당 질문을 건너뛰고 다음 질문으로 넘어가는 문제가 있다.

미션은 케이가 질문하고 아이의 답변을 받는 기능이므로, 아이가 질문을 이해하지 못한 경우에는 바로 다음 질문으로 넘어가면 안 된다.

앞으로는 다음과 같이 처리한다.

1. 케이가 미션 질문을 한다.
2. 아이가 질문을 이해하지 못한 반응을 보이면 같은 질문을 쉬운 말로 한 번 설명한다.
3. 쉬운 설명 뒤 동일한 질문을 다시 한 번 묻는다.
4. 재질문에 정상 답변하면 해당 질문의 유효 답변으로 저장한다.
5. 재질문에도 모르겠다고 하거나 답변이 없거나 무관한 답변이면 해당 질문을 미답변 처리하고 다음 질문으로 넘어간다.

## 2. 핵심 대화 흐름

### 정상 답변

```text
케이: 오늘 학교에서 가장 기억에 남는 일은 뭐였어?

아이: 체육 시간에 축구한 게 제일 기억나.

처리:
- 유효 답변 저장
- 다음 질문으로 이동
```

### 질문을 이해하지 못한 경우

```text
케이: 오늘 학교에서 가장 기억에 남는 일은 뭐였어?

아이: 무슨 말인지 모르겠어.

케이: 오늘 학교에서 있었던 일 중
제일 생각나는 일을 말해달라는 뜻이야.
오늘 뭐가 제일 기억나?

아이: 체육 시간에 축구한 거.

처리:
- 원래 질문의 유효 답변으로 저장
- 다음 질문으로 이동
```

### 설명 후에도 모르는 경우

```text
케이: 오늘 학교에서 가장 기억에 남는 일은 뭐였어?

아이: 무슨 말인지 모르겠어.

케이: 오늘 학교에서 있었던 일 중
제일 생각나는 일을 말해달라는 뜻이야.
오늘 뭐가 제일 기억나?

아이: 잘 모르겠어.

케이: 괜찮아. 그럼 다음 이야기로 넘어갈게.

처리:
- 현재 질문 미답변 처리
- 다음 질문으로 이동
```

### 설명 후에도 답변이 없는 경우

```text
케이: 오늘 학교에서 가장 기억에 남는 일은 뭐였어?

아이: 다시 말해줘.

케이: 오늘 학교에서 있었던 일 중
제일 생각나는 일을 말해달라는 뜻이야.
오늘 뭐가 제일 기억나?

아이: 무응답 또는 침묵

처리:
- 기존 무응답 판단 시간 적용
- 현재 질문 미답변 처리
- 다음 질문으로 이동
```

## 3. 질문별 상태 흐름

각 질문은 다음 상태로 관리한다.

```text
QUESTION_ASKED
    ↓
정상 답변
    → ANSWER_ACCEPTED
    → 다음 질문

질문 이해 실패
    → CLARIFICATION_REQUIRED
    → 쉬운 설명 + 동일 질문 재질문
    → QUESTION_REASKED

QUESTION_REASKED
    ↓
정상 답변
    → ANSWER_ACCEPTED
    → 다음 질문

모르겠음 / 무응답 / 무관 답변
    → UNANSWERED
    → 다음 질문
```

한 질문에서 쉬운 설명과 재질문은 최대 1회만 허용한다.

무한 반복이나 같은 질문의 연속 재생을 금지한다.

## 4. 질문 이해 실패 감지

다음과 같은 아이 발화를 질문 이해 실패로 분류한다.

### 대표 표현

- `무슨 말이야?`
- `무슨 뜻이야?`
- `잘 모르겠어.`
- `이해가 안 돼.`
- `다시 말해줘.`
- `쉽게 말해줘.`
- `뭐라고?`
- `잘 못 들었어.`
- `그게 뭐야?`
- `어떻게 말해야 해?`
- `질문이 어려워.`
- `모르겠는데.`
- `뭘 말해야 돼?`

STT 오류나 짧은 표현도 고려한다.

예:

- `몰라`
- `뭔 말`
- `다시`
- `뭐라고`
- `이해 안돼`
- `어려워`

단순히 답을 모르는 경우와 질문 자체를 이해하지 못한 경우를 가능하면 구분한다.

### 질문 이해 실패

```text
무슨 뜻인지 모르겠어.
질문이 어려워.
다시 설명해줘.
```

처리:

```text
쉬운 설명 + 동일 질문 1회 재질문
```

### 질문은 이해했지만 답을 모르는 경우

```text
기억이 안 나.
잘 모르겠어.
생각나는 게 없어.
```

첫 응답에서 이것이 명확하다면 바로 미답변 처리할 수 있다.

단, `잘 모르겠어`처럼 두 의미가 모두 가능한 발화는 아이에게 불리하게 판단하지 말고 질문 이해 실패로 간주하여 쉬운 설명 기회를 한 번 제공한다.

## 5. 쉬운 설명 생성 규칙

쉬운 설명은 원래 질문의 의미만 쉽게 풀어서 설명해야 한다.

허용:

- 어려운 단어를 쉬운 단어로 교체
- 긴 문장을 짧게 분리
- 질문의 범위를 구체적으로 설명
- 초등학생이 이해할 수 있는 예시 한 개 제공
- 동일한 답변 목적을 유지한 재질문

금지:

- 원래 질문과 다른 주제 추가
- 새로운 후속 질문 추가
- 답변을 유도하거나 정답 암시
- 특정 답을 강요
- 아이가 하지 않은 말을 가정
- 설명 중 여러 질문을 동시에 제시
- 질문의 분석 목적 변경
- 부모나 리포트 목적 노출

### 예시 1

원래 질문:

```text
오늘 하루 중 가장 인상 깊었던 순간은 언제였어?
```

쉬운 설명과 재질문:

```text
오늘 있었던 일 중에서
제일 기억에 남는 일을 말해달라는 뜻이야.
오늘 뭐가 제일 기억나?
```

### 예시 2

원래 질문:

```text
친구와 의견이 달랐던 일이 있었어?
```

쉬운 설명과 재질문:

```text
친구랑 생각이 서로 달랐던 일이 있었는지 묻는 거야.
그런 일이 있었어?
```

### 예시 3

원래 질문:

```text
오늘 스스로 뿌듯했던 일은 무엇이야?
```

쉬운 설명과 재질문:

```text
오늘 네가 잘했다고 느낀 일을 말해달라는 뜻이야.
오늘 잘했다고 느낀 일이 있어?
```

## 6. 동일 질문 유지 원칙

쉬운 설명 후 재질문은 새로운 질문으로 계산하지 않는다.

반드시 다음 값을 유지한다.

- 동일한 `question_id`
- 동일한 질문 순번
- 동일한 기본/예비 질문 구분
- 동일한 mission phase
- 동일한 질문 사용 이력
- 동일한 답변 연결 대상
- 동일한 display sequence 범주

재질문 때문에 다음 값이 증가하면 안 된다.

- 질문 진행 개수
- 유효 답변 개수
- 질문 사용 횟수
- 기본 질문 소진 개수
- 예비 질문 소진 개수
- 미션 완료 진행률

별도 추적이 필요하다면 다음과 같은 상태만 추가한다.

```text
clarification_count: 0 | 1
clarification_status:
- not_needed
- explained
- answered_after_explanation
- unanswered_after_explanation
```

기존 테이블이나 세션 메타데이터로 관리할 수 있는지 먼저 감사한다.

DB Schema 변경은 불가피한 경우에만 수행한다.

## 7. 유효 답변 처리

### 첫 질문에 정상 답변

- 유효성 분석
- 유효 답변이면 저장
- 유효 답변 개수 +1
- 다음 질문으로 이동

### 쉬운 설명 후 정상 답변

- 원래 `question_id`의 답변으로 저장
- 유효성 분석
- 유효 답변이면 저장
- 유효 답변 개수 +1
- 다음 질문으로 이동
- 설명 문장 자체는 아이 답변으로 저장하지 않음

### 쉬운 설명 후 실패

다음 응답은 현재 질문을 미답변으로 처리한다.

- 모르겠다는 명확한 응답
- 답변 없음
- 침묵
- 질문과 전혀 관계없는 답변
- 질문을 다시 이해하지 못한 응답
- 대화 거부
- 넘어가 달라는 요청

처리:

```text
현재 질문 미답변
→ 유효 답변 개수 증가 없음
→ 다음 질문
```

## 8. 기존 질문 순환 정책과 연결

현재 확정된 질문 순환 정책을 유지한다.

```text
1. 기본 질문 10개
2. 유효 답변이 부족하면 예비 질문 10개
3. 그래도 부족하면 기본+예비 질문 중 미답변 질문만 순서대로 1회 재순환
4. 이후 종료 멘트
```

이번 변경과 연결되는 규칙:

- 쉬운 설명 후에도 답하지 못한 질문은 `미답변 질문`으로 기록한다.
- 미답변 질문 재순환 단계에 포함할 수 있다.
- 재순환 단계에서도 쉬운 설명 기회는 질문별 전체 미션 기준 최대 1회를 권장한다.
- 동일 질문이 재순환되었다고 설명 횟수를 다시 초기화하지 않는다.
- 재순환 시에는 처음부터 쉬운 표현으로 질문하는 방안을 우선한다.
- 유효 답변 10개를 받으면 즉시 미션 완료 처리한다.

### 재순환 예시

첫 질문 시:

```text
원 질문
→ 이해 실패
→ 쉬운 설명
→ 다시 모르겠음
→ 미답변
```

재순환 시:

```text
이전에 사용했던 쉬운 질문 문장으로 1회 질문
→ 정상 답변이면 저장
→ 실패하면 최종 미답변
```

재순환에서 다시 설명과 재질문을 반복하여 미션이 길어지는 것은 금지한다.

## 9. 무응답 처리

현재 자동·수동 마이크의 무응답 판단 로직을 먼저 확인한다.

무응답 시 다음 기준을 적용한다.

### 최초 질문 후 무응답

음성이 전혀 감지되지 않은 경우:

- 기존 재청취 또는 마이크 복구 정책이 있다면 그대로 적용
- 통신·마이크 오류와 아이의 침묵을 구분
- 시스템 오류라면 질문 실패로 처리하지 않음
- 정상적으로 듣고 있었지만 아이가 답하지 않은 경우 미답변 처리

최초 질문에 무응답이라고 해서 무조건 질문 이해 실패 설명을 제공하지 않는다.

### 아이가 다시 설명을 요청한 후 무응답

```text
쉬운 설명 + 동일 질문 재질문
→ 정상 청취 상태에서 무응답
→ 미답변
→ 다음 질문
```

무응답으로 다음 질문으로 넘어갈 때 케이는 짧게 안내한다.

예:

```text
괜찮아. 다음 이야기로 넘어갈게.
```

## 10. 무관 답변 처리

질문과 관련 없는 답변이 나왔을 때 즉시 이해 실패로 판단하지 않는다.

기존 답변 유효성 분석 결과를 활용한다.

### 최초 질문의 무관 답변

- 발화가 질문을 잘못 이해한 결과인지 분석
- 이해 실패 가능성이 높으면 쉬운 설명 제공
- 단순한 주제 이탈이면 짧게 받아준 뒤 질문을 쉬운 말로 한 번 재질문

예:

```text
케이: 오늘 학교에서 제일 기억에 남는 일은 뭐였어?

아이: 나는 공룡 좋아해.

케이: 공룡을 좋아하는구나.
지금은 오늘 학교에서 있었던 일 중
제일 기억나는 일을 말해줘.
```

### 재질문 후 무관 답변

- 현재 질문 미답변 처리
- 아이의 발화를 잘못된 답이라고 비난하지 않음
- 다음 질문으로 이동

## 11. 케이의 말투

설명과 재질문은 아이를 다그치지 않는 말투를 사용한다.

허용:

- `쉽게 말하면`
- `이런 뜻이야`
- `천천히 생각해도 돼`
- `괜찮아`
- `예를 들면`
- `잘 모르겠으면 넘어가도 돼`

금지:

- `아까 물어봤잖아`
- `왜 대답을 안 해?`
- `집중해서 들어`
- `다시 잘 생각해봐`
- `정확히 대답해`
- `틀렸어`
- `그게 아니야`
- 반복 답변 강요
- 평가하거나 훈계하는 표현

## 12. 구현 대상 경로 감사

코드 수정 전 미션 질문 처리 경로를 전체 감사한다.

확인 대상 예시:

- `app/api/mission/start/route.ts`
- `app/api/mission/respond/route.ts`
- `app/api/mission/respond-lean/route.ts`
- `app/api/mission/answer/route.ts`
- `app/api/mission/answer-lean/route.ts`
- `app/api/mission/reaction-lean/route.ts`
- `app/api/mission/stt/route.ts`
- `app/api/child/test-mission/start/route.ts`
- 미션 질문 생성 모듈
- 질문 순환 모듈
- 답변 유효성 분석 모듈
- 자동 마이크 처리
- 수동 마이크 처리
- 미션 세션 복원
- 테스트 미션
- Premium Live 미션
- 일반 STT → LLM → TTS 미션
- fallback 응답
- 네트워크 재연결 후 현재 질문 복원

실제 파일과 실행 경로는 검색으로 확정한다.

추측한 일부 API만 수정하지 않는다.

- 이해 실패 감지
- 쉬운 설명 TTS
- 동일 질문 재질문
- 자동 마이크 재활성
- 답변 처리

모든 단계에서 마이크 상태와 UI 상태가 정상 전환되어야 한다.

### 수동 모드

- 질문 재생
- 아이가 마이크 버튼을 눌러 답변
- 이해 실패 감지
- 쉬운 설명 TTS
- 동일 질문 재질문
- 다시 마이크 입력 가능
- 답변 처리

설명 후 마이크 버튼이 사라지거나 비활성 상태로 고정되면 안 된다.

## 14. UI 및 TTS

질문을 이해하지 못한 경우 다음 순서가 화면과 음성에서 동일해야 한다.

```text
아이 발화 표시
→ 케이의 쉬운 설명 말풍선
→ 설명 TTS
→ 동일 질문의 쉬운 재질문 말풍선
→ 재질문 TTS
→ 듣기 상태
```

설명과 재질문을 한 문장으로 자연스럽게 합쳐도 된다.

예:

```text
오늘 학교에서 있었던 일 중
제일 기억나는 걸 말해달라는 뜻이야.
오늘 뭐가 제일 기억나?
```

확인:

- 화면 문장과 TTS 문장 일치
- 이전 질문이 갑자기 사라지지 않음
- 질문 번호가 증가하지 않음
- 진행률이 증가하지 않음
- 설명 중 마이크가 켜지지 않음
- TTS 완료 후 마이크 활성화
- 동일 설명이 중복 재생되지 않음
- 페이지 새로고침 후 상태 복원

---

## 15. 세션 저장 및 복원

질문 설명 도중이나 재질문 후 페이지를 이탈할 수 있다.

세션 복원 시 다음 상태를 정확히 유지한다.

- 현재 `question_id`
- 원래 질문
- 쉬운 설명 문장
- 쉬운 재질문 문장
- clarification_count
- 현재 질문 상태
- 유효 답변 수
- 질문 진행 순번
- 기본/예비/재순환 단계
- 재질문 대기 여부

복원 시 설명 횟수가 초기화되어 같은 설명이 무한 반복되면 안 된다.

예:

```text
설명까지 완료
→ 페이지 종료
→ 재접속
→ 동일 질문의 재질문 대기 상태로 복원
```

질문을 새 질문으로 다시 생성하지 않는다.

## 16. LLM Prompt 변경

미션 응답 분석 Prompt에 다음 의미를 반영한다.

```text
아이의 응답이 질문에 대한 답변인지,
질문을 이해하지 못한 반응인지,
질문은 이해했지만 답을 모르는 것인지 구분하라.

분류:
- valid_answer
- clarification_needed
- unknown_answer
- irrelevant_answer
- no_answer
- skip_requested
- unsafe_response

clarification_needed인 경우:
원 질문의 의미를 바꾸지 말고
초등학생이 이해할 수 있는 쉬운 표현으로 한 번 설명한 뒤
동일한 답변 목적의 질문을 다시 제시하라.

새로운 질문이나 추가 질문을 만들지 마라.
```

가능하면 구조화된 응답을 사용한다.

예:

```json
{
  "classification": "clarification_needed",
  "isValidAnswer": false,
  "clarification": "오늘 있었던 일 중 제일 기억나는 일을 말해달라는 뜻이야.",
  "rephrasedQuestion": "오늘 뭐가 제일 기억나?"
}
```

추측 API나 존재하지 않는 모델 기능을 사용하지 않는다.

현재 SDK와 모델 호출 구조를 먼저 확인한다.

---

## 17. 서버 측 방어 로직

LLM 분류 결과만 신뢰하지 말고 서버 상태로 최대 재질문 횟수를 강제한다.

필수 조건:

```text
clarification_count >= 1
```

이면 추가 설명과 재질문을 금지한다.

두 번째 실패 시:

```text
UNANSWERED
→ 다음 질문
```

동시 요청이나 중복 응답으로 설명이 두 번 생성되지 않도록 한다.

확인:

- idempotency
- 동일 turn 중복 처리 방지
- 네트워크 재전송 방지
- TTS 완료 콜백 중복 방지
- 자동/수동 입력 중복 방지
- 새로고침 후 중복 질문 방지

---

## 18. 데이터 저장 원칙

대화 원문과 상태 저장 구조를 감사한 뒤 다음을 보장한다.

- 원 질문 메시지 저장
- 아이의 이해 실패 발화 저장
- 케이의 설명 메시지 저장
- 케이의 재질문 메시지 저장
- 재질문 후 아이 답변 저장
- 모든 메시지의 시간 순서 유지
- `display_sequence` 연속 유지
- Collection V3에서 순서대로 수집
- Context Correction에서 source ID 유지
- Daily Report에서 설명 문장을 아이 답변으로 오인하지 않음
- Memory Batch에서 케이의 설명을 아이의 기억 사실로 저장하지 않음

질문 설명 메시지에는 가능한 경우 명확한 message metadata를 사용한다.

예:

```text
message_type: mission_question_clarification
question_id: 기존 질문 ID
clarification_attempt: 1
```

기존 metadata 구조가 있으면 재사용한다.

## 19. Collection·Correction·Report 영향 확인

이번 변경 후 파이프라인에서 다음을 확인한다.

### Collection

대화 순서:

```text
케이 원 질문
아이 이해 실패
케이 쉬운 설명 및 재질문
아이 재답변
```

순서가 유지되어야 한다.

### Context Correction

- 아이의 이해 실패 발화 보존
- 케이의 설명과 재질문 보존
- 재답변을 원 질문의 답변으로 연결
- 새로운 사실 추가 금지

### Memory Batch

- 케이 설명을 아이 사실로 추출하지 않음
- 아이의 최종 유효 답변만 기억 후보로 사용
- `모르겠어` 같은 미답변을 사실로 저장하지 않음

### Daily Report

- 이해 실패 자체를 부정적으로 평가하지 않음
- 케이 설명 문장을 아이 발화로 오인하지 않음
- 최종 유효 답변이 있으면 해당 답변을 사용
- 최종 미답변이면 없는 내용을 생성하지 않음


## 23. 작업 제한

- 자유대화 Prompt를 수정하지 않는다.
- 미션 질문 내용을 임의로 전면 교체하지 않는다.
- 질문당 설명을 2회 이상 제공하지 않는다.
- 재질문을 새로운 질문으로 계산하지 않는다.
- 유효 답변 기준을 임의로 강화하지 않는다.
- 실제 사용자·아이 ID를 테스트에 사용하지 않는다.
- Production 데이터를 테스트에 사용하지 않는다.
- Secret을 코드·로그·테스트 파일에 하드코딩하지 않는다.
- 기존 적용 Migration을 수정하지 않는다.
- DB 변경이 필요하면 최신 timestamp의 Forward Fix만 추가한다.
- Production 배포는 별도 승인 전 진행하지 않는다.
