# Request — 카카오 인앱브라우저 외부 브라우저 전환 안내 + 가입 후 PWA 설치

## 1. 목적

카카오톡으로 전달된 내친구 케이 링크는 카카오 인앱브라우저에서 열릴 수 있다.

카카오 인앱브라우저에서는 PWA 설치 및 일부 인증 흐름에 제약이 있으므로,
카카오 인앱브라우저가 감지되면 사용자가 Safari/Chrome 등 외부 브라우저로 이동할 수 있도록
OS별로 명확하게 안내한다.

카카오의 별도 심사 권한이 필요한 External Web 기능은 이번 작업 범위에서 제외한다.

---

## 2. 최종 사용자 흐름

### 가족 구성원 초대

카카오톡 초대 링크
→ 카카오 인앱브라우저
→ 외부 브라우저 이동 안내
→ Safari / Chrome
→ 로그인 또는 회원가입
→ 가족 연결
→ 필수 온보딩 완료
→ PWA 설치 제안
→ 서비스 이용

### 신규 가입 / 마케팅

카카오톡 가입 링크
→ 카카오 인앱브라우저
→ 외부 브라우저 이동 안내
→ Safari / Chrome
→ 신규 회원가입
→ 필수 온보딩 완료
→ PWA 설치 제안
→ 서비스 이용

---

## 3. 핵심 원칙

- 웹 코드로 외부 브라우저 자동 실행을 100% 보장한다고 구현하지 않는다.
- `WEB_ACTION_TYPE_SUPPORTED` 등 카카오 심사형 권한을 전제로 하지 않는다.
- 비공식 Kakao Scheme을 필수 경로로 사용하지 않는다.
- 사용자가 실제 카카오 UI에서 `다른 브라우저로 열기`를 선택하도록 안내한다.
- URL 복사는 최후 fallback으로만 제공한다.
- PWA 설치는 회원가입 전에 요구하지 않는다.

---

## 4. Kakao In-App Browser 감지

KakaoTalk User-Agent를 기준으로 인앱브라우저를 감지한다.

예:

```text
KAKAO_IN_APP
NORMAL_BROWSER
PWA_STANDALONE
```

Kakao In-App Browser가 아니면 안내 화면 없이 정상 서비스로 진입한다.

---

## 5. 카카오 인앱브라우저 안내 화면

기존:

`새 브라우저에서 다시 시작해 주세요`

화면을 수정한다.

### 제목

`Safari 또는 Chrome에서 계속해 주세요`

### 설명

`회원가입과 앱 설치를 안정적으로 진행하려면 외부 브라우저에서 열어 주세요.`

---

## 6. Android 안내

카카오 인앱브라우저에서 사용자가 실제 UI를 통해 외부 브라우저로 이동하도록 안내한다.

예:

```text
1. 오른쪽 아래 메뉴(⋮)를 눌러 주세요.
2. '다른 브라우저로 열기'를 선택해 주세요.
```

가능하면 실제 Android KakaoTalk UI를 기준으로
화면 내 간단한 이미지/화살표 안내를 제공한다.

문구는 실제 최신 카카오톡 버전에서 확인 후 확정한다.

---

## 7. iPhone 안내

iPhone에서는 Safari 강제 실행을 시도하지 않는다.

카카오톡 현재 UI에서 제공하는 외부 브라우저 이동 기능을 안내한다.

예:

```text
1. 카카오 브라우저의 주소/메뉴 영역을 눌러 주세요.
2. '다른 브라우저로 열기' 또는 Safari에서 열기를 선택해 주세요.
```

실제 iPhone KakaoTalk 최신 버전에서 메뉴 위치와 문구를 확인한 뒤
실제 화면 기준으로 안내한다.

---

## 8. 잘못된 버튼 제거

현재:

`브라우저에서 계속하기`

버튼을 눌렀는데 URL만 클립보드에 복사되는 UX는 제거한다.

실제로 브라우저가 열리지 않는다면
`브라우저에서 계속하기`라는 버튼명을 사용하지 않는다.

대신 화면에서 외부 브라우저 이동 방법 자체를 Primary 안내로 제공한다.

---

## 9. URL 복사 fallback

외부 브라우저 이동 메뉴를 찾지 못하는 사용자를 위해 하단에만 제공한다.

버튼명:

`주소 복사하기`

동작:

현재 가입/초대 URL을 클립보드에 복사.

복사 후:

`주소를 복사했어요. Safari 또는 Chrome 주소창에 붙여 넣어 주세요.`

URL 복사는 Primary Flow가 아니다.

---

## 10. 가입 context 유지

가족 초대 링크의 경우 외부 브라우저에서 다시 열더라도 다음 정보가 유지돼야 한다.

- invite token
- family invite
- 사용자 역할
- intended redirect

개인정보를 URL에 직접 넣지 않는다.

기존 초대 token 구조를 우선 재사용한다.

---

## 11. 회원가입 후 PWA 설치

외부 브라우저에서 다음 과정이 끝난 후 PWA 설치를 제안한다.

### 부모

회원가입/로그인
→ 부모 기본 정보
→ 아이 등록 또는 가족 연결
→ 설치 제안

### 아이

로그인/가입
→ 가족 연결
→ 아이 프로필 확인
→ 설치 제안

설치는 필수가 아니다.

`나중에`를 선택해도 정상 서비스 이용이 가능해야 한다.

---

## 12. Android PWA 설치

`beforeinstallprompt`가 제공되면:

`앱 설치하기`
→ 브라우저 설치 prompt

이벤트가 없으면 메뉴 기반 설치 가이드를 제공한다.

---

## 13. iPhone PWA 설치

Safari에서:

```text
공유
→ 홈 화면에 추가
→ 추가
```

방식으로 안내한다.

실제 현재 iOS 버전에 맞게 화면 문구를 검증한다.

---

## 14. 설치 후 알림

PWA 첫 실행:

로그인 세션 복원
→ 정상 홈
→ 기존 Notification Onboarding
→ 사용자가 `알림 받기` 선택
→ OS 알림 권한 요청

설치와 알림 권한을 동시에 요구하지 않는다.

## 16. 수용 기준

- AC-01: Kakao In-App Browser를 감지한다.
- AC-02: 일반 Safari/Chrome에서는 안내 화면이 나오지 않는다.
- AC-03: Android에 실제 카카오 UI 기반 외부 브라우저 이동 안내가 나온다.
- AC-04: iPhone에 실제 카카오 UI 기반 외부 브라우저 이동 안내가 나온다.
- AC-05: URL 복사만 하면서 `브라우저에서 계속하기`라고 표시하지 않는다.
- AC-06: URL 복사는 Secondary fallback이다.
- AC-07: 가족 invite context가 외부 브라우저에서도 유지된다.
- AC-08: 신규 가입 흐름도 동일하게 동작한다.
- AC-09: 회원가입 전 PWA 설치를 요구하지 않는다.
- AC-10: 가입/가족 연결 완료 후 PWA 설치를 제안한다.
- AC-11: 설치하지 않아도 서비스 이용 가능하다.
- AC-12: Android KakaoTalk 실기기 PASS.
- AC-13: iPhone KakaoTalk 실기기 PASS.
- AC-14: 기존 회원가입/로그인/자동로그인 회귀 없음.
