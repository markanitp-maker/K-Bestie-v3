# REQUEST 027 — 상세 리포트 데이터 부족 항목 완전 숨김 처리

## 1. 작업 목적

부모 일일·주간 리포트의 `상세 보기` 탭에서 실제로 전달할 분석 내용이 없는 항목까지 제목과 데이터 부족 안내 문구가 표시되고 있다.

현재 잘못된 예:

```text
미래·진로·꿈
이 항목은 확인할 대화가 충분하지 않아요.

선생님·어른
이 항목은 확인할 대화가 충분하지 않아요.

반복되는 이야기
이 항목은 확인할 대화가 충분하지 않아요.
```

대표님이 원하는 상세 리포트는 모든 분석 항목을 억지로 채우는 리포트가 아니다.

아이의 실제 대화에서 부모에게 전달할 수 있는 정보가 확인된 항목만 보여주고, 확인할 수 없는 항목은 존재 자체를 화면에서 숨긴다.

최종 원칙:

```text
실제 분석 내용 있음
→ 제목 + 분석 내용 표시

실제 분석 내용 없음
→ 제목 + 본문 + 구분선 + 여백 + 컨테이너 전체 숨김
```

부모에게 알려줄 수 있는 정보만 알려주고, 알려줄 수 없는 정보까지 `모른다`, `데이터가 부족하다`고 나열하지 않는다.

---

## 2. 적용 대상

다음 화면에 동일하게 적용한다.

- 일일 리포트 상세 모달
- 주간 리포트 상세 모달
- 일일 리포트 목록 카드에서 연 상세 모달
- 주간 리포트 목록 카드에서 연 상세 모달
- 지난 이력보기 일일 달력에서 연 상세 모달
- 지난 이력보기 주간 선택에서 연 상세 모달
- `상세 보기` 탭

이번 요청의 직접 수정 대상은 `상세 보기` 탭이다.

`빠른 요약`과 `추천 가이드`의 데이터 구조 및 콘텐츠 생성 방식은 이번 요청에서 변경하지 않는다.

## 3. 기존 완료(DONE) 기능 보호

다음 상세 모달 UX는 이미 구현 완료(DONE) 상태다.

이번 작업에서 다시 구현하거나 구조를 변경하지 않는다.

### 완료된 기능

- 모달 제목 + `X` 닫기 버튼 상단 고정
- `빠른 요약 / 상세 보기 / 추천 가이드` 탭 상단 고정
- 제목 영역 바로 아래 탭 고정
- 탭 아래 콘텐츠 영역만 세로 스크롤
- 본문 스크롤 중 제목과 탭 계속 표시
- 탭 배경 불투명 처리
- 탭과 본문 z-index 처리
- 배경 페이지 스크롤 차단
- 목록 카드와 달력 선택이 동일한 상세 모달 사용
- 일일·주간 리포트 동일 모달 구조 사용
- 모바일에서 긴 본문 내부 스크롤
- 탭 전환 시 해당 탭 콘텐츠 시작 위치 표시

이번 REQUEST 027에서는 위 기능을 수정하지 않는다.

단, 데이터 부족 섹션을 숨긴 결과로 기존 완료 기능이 깨지지 않았는지만 회귀 검증한다.

- 공부 고민

- 미래·진로·꿈
- 선생님·어른
- 반복되는 이야기

DB 컬럼명, JSON key, API field, TypeScript 타입은 실제 현재 구현을 먼저 확인한 후 정확히 매핑한다.

## 5. 숨김 대상 데이터

다음 값은 실제 분석 정보가 아니므로 상세 리포트에서 해당 섹션 전체를 숨긴다.

- `null`
- `undefined`
- 빈 문자열
- 공백만 존재하는 문자열
- `이 항목은 확인할 대화가 충분하지 않아요.`
- `이 항목은 확인할 대화가 충분하지 않아요`
- `확인할 대화가 충분하지 않아요.`
- `확인할 대화가 충분하지 않아요`
- `대화 정보 부족`
- `데이터 부족`
- `정보 없음`
- `확인된 내용이 없어요`
- `분석을 준비 중이에요`
- `새로운 이야기가 있어요`
- 동일 의미의 placeholder / fallback 문구

마침표, 앞뒤 공백, 줄바꿈 차이 때문에 같은 placeholder가 유효 데이터로 처리되지 않도록 normalization 후 판정한다.

## 6. 반드시 표시해야 하는 데이터

다음은 데이터 부족이 아니라 실제 대화에서 확인된 분석 결과다.

따라서 정상 표시해야 한다.

예:

```text
공부나 숙제에서 특별히 어려운 점은 없다고 답했습니다.
```

```text
학교생활에서 힘든 부분은 없다고 이야기했습니다.
```

```text
친구 관계에서 특별한 갈등은 없다고 말했습니다.
```

반드시 다음 두 상태를 구분한다.

```text
해당 주제에 대해 실제 대화함
+ 아이가 "어려움 없음 / 문제 없음"이라고 답함
→ 유효 분석
→ 표시
```

```text
해당 주제에 관한 대화 자체가 없음
또는 분석할 근거가 부족함
→ 데이터 부족
→ 섹션 전체 숨김
```

문장에 `없음`, `부족`, `어려움 없음` 등의 단어가 포함됐다는 이유만으로 숨기지 않는다.

## 7. UI 렌더링 기준

데이터 부족으로 판정된 섹션은 다음 요소를 전부 렌더링하지 않는다.

- 섹션 제목
- 섹션 아이콘
- 본문
- 안내 문구
- 상단 여백
- 하단 여백
- 구분선
- 빈 카드
- 빈 컨테이너

### 잘못된 화면

```text
디지털 관심사와 콘텐츠 취향
[실제 분석]

----------------------

미래·진로·꿈
이 항목은 확인할 대화가 충분하지 않아요.

----------------------

선생님·어른
이 항목은 확인할 대화가 충분하지 않아요.

----------------------

반복되는 이야기
이 항목은 확인할 대화가 충분하지 않아요.
```

### 정상 화면

```text
디지털 관심사와 콘텐츠 취향
[실제 분석]
```

이후 표시할 유효 섹션이 없다면 그 자리에서 상세 리포트가 끝나야 한다.

## 8. 섹션 순서

일부 항목이 숨겨져도 남은 유효 항목의 기존 순서는 변경하지 않는다.

예:

원래 순서:

```text
학교·학원 생활
친구 관계
감정 힌트
관심사
공부 고민
디지털 콘텐츠
미래·진로·꿈
선생님·어른
반복되는 이야기
```

`미래·진로·꿈`, `선생님·어른` 데이터가 없다면:

```text
학교·학원 생활
친구 관계
감정 힌트
관심사
공부 고민
디지털 콘텐츠
반복되는 이야기
```

순서로 자연스럽게 연결한다.

## 9. 공통 availability 판정

일일/주간/목록/달력 진입 경로마다 서로 다른 placeholder 판정 코드를 만들지 않는다.

공통 함수 또는 공통 mapper를 사용한다.

권장 개념:

```ts
function isMeaningfulReportSection(content: unknown): boolean {
  if (typeof content !== "string") return false;

  const normalized = content.trim().replace(/\s+/g, " ");

  if (!normalized) return false;

  const placeholders = new Set([
    "이 항목은 확인할 대화가 충분하지 않아요.",
    "이 항목은 확인할 대화가 충분하지 않아요",
    "확인할 대화가 충분하지 않아요.",
    "확인할 대화가 충분하지 않아요",
    "대화 정보 부족",
    "데이터 부족",
    "정보 없음",
    "확인된 내용이 없어요",
    "분석을 준비 중이에요",
    "새로운 이야기가 있어요"
  ]);

  return !placeholders.has(normalized);
}
```

실제 프로젝트 구조와 기존 utility 패턴을 우선한다.

문자열 판정 로직을 여러 UI 컴포넌트에 복사해서 만들지 않는다.

## 10. API 단계 상태 처리

현재 API 구조를 먼저 확인한다.

가능하면 API 단계에서 상세 섹션의 availability를 명확하게 구분한다.

예:

```ts
type DetailedReportSection = {
  key: string;
  title: string;
  content: string | null;
  availability: "available" | "insufficient_data";
};
```

응답 예:

```json
{
  "key": "future_dreams",
  "title": "미래·진로·꿈",
  "content": null,
  "availability": "insufficient_data"
}
```

UI:

```text
availability = available
→ 렌더링

availability = insufficient_data
→ 렌더링하지 않음
```

단, 이번 수정 때문에 불필요한 대규모 DB Schema 변경을 만들지 않는다.

현재 문자열 구조만으로 안정적으로 처리할 수 있다면 최소 변경을 우선한다.

## 11. 리포트 생성기 확인

현재 일일·주간 리포트 생성기가 데이터가 없는 영역에 다음처럼 placeholder를 실제 분석 데이터로 저장하는지 확인한다.

```json
{
  "future_dreams": "이 항목은 확인할 대화가 충분하지 않아요."
}
```

이 구조라면 신규 리포트부터는 가능한 한 다음처럼 저장하도록 수정한다.

```json
{
  "future_dreams": null
}
```

또는 현재 Schema가 availability를 지원한다면:

```json
{
  "future_dreams": null,
  "future_dreams_availability": "insufficient_data"
}
```

중요:

- 과거 Production 리포트를 일괄 수정하지 않는다.
- 과거 리포트를 일괄 재생성하지 않는다.
- 신규 리포트가 더 이상 placeholder를 분석문으로 저장하지 않도록 한다.
- 기존 리포트는 UI/API 하위 호환 처리로 숨긴다.

## 12. 과거 리포트 하위 호환

과거 Production 데이터에는 이미 다음과 같은 문자열이 저장되어 있을 수 있다.

```text
이 항목은 확인할 대화가 충분하지 않아요.
```

과거 일일·주간 리포트를 열더라도:

```text
placeholder 저장값
→ 데이터 부족으로 판정
→ 섹션 전체 숨김
```

처리한다.

과거 DB 데이터를 직접 수정할 필요는 없다.

## 13. 모든 상세 항목이 없는 경우

상세 리포트 전체에서 실제 표시 가능한 섹션이 하나도 없는 경우에만 화면 전체 차원의 안내를 한 번 표시한다.

예:

```text
이번 리포트에서 제공할 상세 분석이 없어요.
```

다음과 같이 개별 영역을 여러 번 출력하지 않는다.

```text
학교 정보 없음
친구 정보 없음
관심사 정보 없음
...
```

## 14. 빠른 요약 / 추천 가이드

이번 요청의 직접 수정 대상은 `상세 보기`다.

다음은 기존 기능을 유지한다.

- 빠른 요약
- 추천 가이드

다만 이 두 탭에서도 명백한 데이터 부족 placeholder가 실제 콘텐츠 카드처럼 렌더링되고 있다면 동일한 원칙으로 그 콘텐츠 블록만 숨긴다.

이 과정에서 빠른 요약이나 추천 가이드의 생성 구조를 새로 설계하지 않는다.

## 15. 기존 DONE 상단 고정 UX 회귀 검증

이번 수정 후 다음 기존 완료 기능이 그대로 유지되는지 확인한다.

### 모달 구조

```text
[8월 6일 일간 리포트]              [X]   ← 고정

[빠른 요약] [상세 보기] [추천 가이드]    ← 고정

상세 리포트 콘텐츠                        ← 이 영역만 스크롤
```

### 반드시 유지

- 제목 고정
- X 버튼 고정
- 탭 고정
- 콘텐츠만 스크롤
- 본문이 탭 뒤로 비치지 않음
- 모달 배경 페이지 스크롤 차단
- 상세 항목 수가 줄어도 레이아웃 깨짐 없음
- 콘텐츠 끝까지 정상 스크롤 가능
- 하단에 불필요한 큰 빈 공간 없음

## 16. 실제 대표 재현 사례

현재 모바일 일일 리포트 상세 화면에서 다음 세 항목이 데이터 부족 상태로 노출되고 있다.

```text
미래·진로·꿈
이 항목은 확인할 대화가 충분하지 않아요.

선생님·어른
이 항목은 확인할 대화가 충분하지 않아요.

반복되는 이야기
이 항목은 확인할 대화가 충분하지 않아요.
```

해당 날짜에 실제 분석 데이터가 없다면 수정 후 다음 세 항목은 화면에서 완전히 사라져야 한다.

다음 요소가 하나라도 남으면 FAIL이다.

- 제목
- 안내 문구
- 구분선
- 빈 여백
- 빈 컨테이너

## 17. 필수 테스트 시나리오

### 시나리오 A — 일부 항목만 데이터 있음

조건:

- 감정 있음
- 관심사 있음
- 공부 고민 있음
- 미래·진로·꿈 없음
- 선생님·어른 없음
- 반복 이야기 없음

예상 결과:

- 감정 표시
- 관심사 표시
- 공부 고민 표시
- 미래·진로·꿈 완전 숨김
- 선생님·어른 완전 숨김
- 반복 이야기 완전 숨김
- placeholder 없음
- 빈 구분선 없음
- 빈 여백 없음

### 시나리오 B — 실제 “문제 없음” 분석
