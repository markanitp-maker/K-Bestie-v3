# 032 — 미션 대화 입력 상태 및 완료 UX 개선

## 1. 작업 목적

아이 미션 대화 화면에서 현재 음성 처리 상태와 마이크 버튼의 활성 상태가 일치하도록 개선하고, 키보드 입력 시 음성 입력이 동시에 들어오는 문제를 방지한다.

또한 미션 완료 시 상단에 별도의 완료 안내 영역을 중복 표시하지 않고, 케이의 마지막 인사 말풍선과 음성만으로 자연스럽게 미션을 종료하도록 변경한다.

이번 작업의 핵심은 다음 세 가지다.

1. 케이가 생각하거나 말하는 동안 마이크 버튼을 회색 비활성 상태로 표시하고 실제 음성 입력도 차단한다.
2. 키보드 입력 버튼을 누르면 자동 모드에서 수동 모드로 반드시 전환한다.
3. 미션 완료 시 상단 완료 제목과 별도 안내 배너를 제거하고 케이의 마지막 인사로 통합한다.

---

# 2. 적용 화면

대상:

- 아이 미션 대화 화면
- 자동 음성 입력 모드
- 수동 음성 입력 모드
- 키보드 텍스트 입력
- 미션 완료 상태

변경하지 않는 기능:

- 미션 질문 구성
- 기본 질문 10개 및 예비 질문 정책
- 유효 답변 판정
- 유효 답변 10개 완료 기준
- 미션 진행률 저장
- 황금열쇠 지급 로직
- 미션 이어하기
- 대화 저장
- 리포트 수집
- Gemini Live 연결 및 세션 복원 구조

# 3. 현재 문제

## 문제 1 — 케이가 말하거나 생각하는 중에도 마이크가 활성 상태로 보임

현재 자동 모드에서는 케이가 다음 상태일 때도 하단 마이크 버튼이 주황색으로 표시된다.

- 케이가 답변을 생성하는 중
- 케이가 음성으로 말하는 중
- 턴 전환 처리 중

이 때문에 아이는 현재 말해도 되는 상태로 오인할 수 있다.

마이크 UI 상태와 실제 음성 입력 가능 상태가 일치하지 않는다.

## 문제 2 — 키보드 입력과 자동 음성 입력이 동시에 작동할 수 있음

자동 모드 상태에서 왼쪽 하단 키보드 버튼을 누르고 타이핑하면 자동 음성 입력이 계속 활성화될 수 있다.

아이가 타이핑하면서 말하거나 주변 소리가 들어오면 다음 문제가 발생할 수 있다.

- 텍스트와 음성이 동시에 입력됨
- 동일 답변이 중복 제출됨
- 의도하지 않은 음성이 답변으로 저장됨
- 다음 질문으로 잘못 넘어감
- 유효 답변 수가 중복 증가할 가능성

## 문제 3 — 미션 완료 안내가 중복 표시됨

현재 미션을 완료하면 상단에 다음과 같은 별도 완료 영역이 추가된다.

```text
오늘의 미션을 완료했어요!
```

```text
오늘의 미션을 모두 완료했어!
황금열쇠를 받았어. 내일 또 만나자!
```

동시에 아래의 케이 말풍선에서도 종료 인사가 표시되기 때문에 완료 안내가 중복된다.

# 4. 마이크 활성 상태 원칙

마이크 버튼의 시각 상태와 실제 음성 입력 가능 상태는 반드시 동일해야 한다.

## 활성 상태

케이가 아이의 답변을 받을 준비가 된 경우에만 마이크 버튼을 주황색으로 표시한다.

대상 상태:

- `listening`
- `waiting_for_user`
- `ready_for_input`
- 프로젝트의 기존 상태명 중 아이 입력을 실제로 허용하는 상태

표시:

- K-Orange 계열 원형 버튼
- 흰색 일반 마이크 아이콘
- 기존 듣기 Pulse 효과
- 버튼 클릭 또는 자동 입력 가능
- 접근성 상태 `음성 입력 가능`

## 비활성 상태

다음 상태에서는 마이크 버튼을 회색으로 표시하고 실제 음성 입력을 차단한다.

- `thinking`
- `processing`
- `speaking`
- `connecting`
- `reconnecting`
- `error`
- `completing`
- `completed`
- 다음 질문으로 전환하는 중
- 텍스트 답변 제출 처리 중

표시:

- Neutral Gray 배경
- 마이크 비활성 또는 마이크 차단 아이콘
- Pulse 애니메이션 제거
- 클릭 불가
- `disabled` 또는 `aria-disabled="true"`
- 접근성 상태 `지금은 음성 입력을 사용할 수 없음`

단순히 버튼 색만 회색으로 바꾸지 말고 해당 상태에서는 로컬 마이크 음성 프레임을 Gemini Live 또는 서버로 전송하지 않아야 한다.

# 5. 상태별 마이크 UI 매핑

| 실제 대화 상태 | 화면 상태 문구 | 마이크 버튼 | 음성 전송 |
|---|---|---|---|
| 아이 답변 대기 | 듣는 중 또는 대기 중 | 주황색 활성 마이크 | 허용 |
| 아이 음성 수신 중 | 듣는 중 | 주황색 활성 및 Pulse | 허용 |
| 아이 답변 처리 중 | 생각 중 | 회색 비활성 마이크 | 차단 |
| 케이 답변 생성 중 | 생각 중 | 회색 비활성 마이크 | 차단 |
| 케이 음성 출력 중 | 말하는 중 | 회색 비활성 마이크 | 차단 |
| 다음 질문 전환 중 | 생각 중 | 회색 비활성 마이크 | 차단 |
| 최초 연결 중 | 연결 중 | 회색 비활성 마이크 | 차단 |
| 재연결 중 | 다시 연결 중 | 회색 비활성 마이크 | 차단 |
| 연결 오류 | 연결 오류 | 회색 비활성 마이크 | 차단 |
| 미션 완료 처리 중 | 완료 처리 중 | 회색 비활성 마이크 | 차단 |
| 미션 완료 | 완료 | 회색 비활성 마이크 | 차단 |

상태 문자열을 임의 타이머로 생성하지 말고 기존 세션 상태 머신을 단일 Source of Truth로 사용한다.

# 6. 자동 모드 동작

자동 모드에서는 케이가 아이의 답변을 기다리는 상태에서만 VAD 기반 자동 입력을 활성화한다.

## 입력 허용

다음 조건을 모두 만족할 때만 음성 입력을 허용한다.

- 입력 모드가 `자동`
- 세션 연결 정상
- 케이 음성 출력이 끝남
- 답변 처리 중이 아님
- 다음 질문이 화면에 준비됨
- 미션이 완료되지 않음
- 텍스트 입력창이 열려 있지 않음

## 입력 차단

케이가 생각하거나 말하기 시작하면 즉시 다음을 수행한다.

1. 마이크 버튼을 회색 비활성 상태로 변경
2. 입력 가능 Pulse 중지
3. VAD 입력 Gate 닫기
4. 신규 음성 프레임 전송 중단
5. 이미 확정된 아이 답변은 정상 처리
6. 동일 턴의 추가 음성을 새 답변으로 제출하지 않음

미션 화면에서는 케이가 말하는 중인 상태에서 아이 음성을 새로운 답변으로 받지 않는다.

UI만 비활성처럼 보이고 실제 입력은 계속되는 상태를 금지한다.

---

# 7. 수동 모드 동작

기존 수동 입력 정책을 유지하되 마이크 활성 가능 시점은 자동 모드와 동일한 대화 상태를 따른다.

## 입력 가능 상태

- 케이가 아이의 답변을 기다리는 중
- 세션 연결 정상
- 미션 미완료
- 텍스트 입력창이 닫혀 있음

## 입력 불가 상태

- 생각 중
- 말하는 중
- 연결 중
- 재연결 중
- 완료 처리 중
- 완료 상태

케이가 생각하거나 말하는 동안 수동 마이크 버튼을 눌러도 신규 음성 입력이 시작되지 않아야 한다.

---

# 8. 키보드 버튼 클릭 시 자동으로 수동 모드 전환

왼쪽 하단의 키보드 버튼을 누르면 현재 입력 모드와 관계없이 반드시 `수동` 모드로 전환한다.

## 처리 순서

키보드 버튼 클릭 시 다음 순서를 원자적으로 처리한다.

1. 현재 자동 음성 입력 중단
2. VAD 자동 수신 Gate 닫기
3. 신규 마이크 음성 프레임 전송 차단
4. 입력 모드를 `수동`으로 변경
5. 화면의 자동·수동 선택 UI를 `수동` 활성 상태로 갱신
6. 실제 오디오 입력 모드 전환 완료 확인
7. 텍스트 입력 UI 열기
8. 텍스트 입력창에 Focus 이동

텍스트 입력창을 먼저 열고 나중에 수동 모드로 바꾸는 방식은 금지한다.

---

# 9. 키보드 입력 중 마이크 정책

텍스트 입력 UI가 열려 있는 동안에는 음성 입력을 동시에 받지 않는다.

## 필수 동작

- 입력 모드 `수동` 유지
- 자동 VAD 비활성
- 마이크 오디오 전송 비활성
- 마이크 버튼 회색 또는 텍스트 입력 중 상태로 표시
- 아이가 타이핑하는 동안 주변 음성을 답변으로 처리하지 않음
- 텍스트 답변만 제출 가능

## 텍스트 입력 종료 후

텍스트 입력창을 닫아도 자동 모드로 임의 복귀하지 않는다.

입력 모드는 계속 `수동`으로 유지한다.

자동 모드로 돌아가려면 사용자가 직접 `자동` 버튼을 선택해야 한다.

---

# 10. 텍스트 답변 처리

텍스트로 입력한 답변도 음성 답변과 동일한 미션 처리 파이프라인을 사용한다.

동일하게 적용할 항목:

- 질문 관련성 확인
- 유효 답변 판정
- 진행률 증가
- 답변 저장
- 다음 질문 이동
- 미션 완료 판정
- 리포트 데이터 수집

## 중복 제출 방지

텍스트 제출 시 다음을 보장한다.

- 같은 턴의 음성 답변과 텍스트 답변이 동시에 저장되지 않음
- 전송 버튼 연속 클릭 차단
- 제출 처리 중 입력창 비활성
- 답변 처리 완료 전 다음 제출 차단
- 진행률 중복 증가 금지

---

# 11. 미션 완료 화면 정리

유효 답변 10개가 저장되어 미션 완료 조건이 충족되면 상단에 별도의 완료 제목이나 완료 안내 카드를 추가하지 않는다.

## 삭제 대상

다음 UI를 제거한다.

```text
오늘의 미션을 완료했어요!
```

다음과 같은 별도의 상단 완료 메시지 영역도 제거한다.

```text
오늘의 미션을 모두 완료했어!
황금열쇠를 받았어. 내일 또 만나자!
```

삭제 범위:

- 완료 전용 상단 제목
- 완료 전용 보조 설명
- 완료 전용 흰색 Pill 또는 Banner
- 기존 질문·대화 영역 위에 추가되는 중복 완료 카드
- 동일 완료 문구의 중복 출력

## 유지 대상

- 10개 모두 채워진 진행률
- 케이의 최종 말풍선
- 케이의 최종 음성
- 기존 미션 종료 및 화면 복귀 정책
- 황금열쇠 지급 처리
- 문의 버튼
- 마스코트

---

# 12. 미션 완료 최종 인사

미션 완료 시 기존 현재 질문 말풍선 영역을 케이의 마지막 인사 말풍선으로 전환한다.

## 최종 문구

```text
오늘 미션을 모두 완료했어! 황금열쇠를 받았어. 다음에 또 보자!
```

다음 위치에 한 번만 표시한다.

- K-Orange 테두리의 케이 말풍선
- 케이 마스코트 위 기존 현재 질문 영역

별도의 상단 완료 제목이나 안내 Banner에는 표시하지 않는다.

## 음성 출력

케이는 위 최종 문구를 한 번만 음성으로 말한다.

다음을 방지한다.

- TTS 중복 재생
- 동일 완료 문구 두 번 출력
- 완료 Effect 재실행
- 화면 재렌더링으로 인한 음성 재생 반복
- 세션 복원 시 완료 인사 반복

---

# 13. 황금열쇠 지급 확인과 완료 문구

`황금열쇠를 받았어`라는 문구는 실제 황금열쇠 지급이 성공한 뒤에만 출력한다.

## 정상 처리 순서

1. 10번째 유효 답변 저장 성공
2. 미션 완료 상태 저장
3. 황금열쇠 지급 또는 보상 Transaction 성공
4. 중복 보상 방지 확인
5. 진행률 10/10 표시
6. 최종 인사 말풍선 표시
7. 최종 인사 음성 출력
8. 기존 종료 또는 복귀 플로우 진행

## 보상 처리 실패

미션은 완료됐지만 황금열쇠 지급이 확인되지 않은 경우 `황금열쇠를 받았어`라고 거짓 안내하지 않는다.

이 경우 임시 최종 문구:

```text
오늘 미션을 모두 완료했어! 이야기해 줘서 고마워. 다음에 또 보자!
```

보상 오류는 기존 재시도 또는 운영 복구 정책으로 처리한다.

화면에는 필요 시 다음과 같은 중립적 안내를 제공한다.

```text
황금열쇠 지급을 확인하고 있어요.
```

황금열쇠 지급 성공 후 보상 상태를 갱신하되 최종 인사를 다시 재생하지 않는다.

# 14. 완료 상태의 입력 제어

# 15. 마지막 인사 표시 중 상태

최종 인사를 케이가 음성으로 출력하는 동안 상태는 다음과 같이 표시한다.

- 상태 카드: `말하는 중`
- 마이크 버튼: 회색 비활성
- 음성 입력: 차단
- 키보드 입력: 차단
- 자동·수동 전환: 차단

최종 음성 재생이 끝난 뒤에는 기존 미션 종료 UX를 따른다.

이번 작업에서 종료 후 자동 이동 시간이나 닫기 방식은 임의로 변경하지 않는다.

# 16. 진행률 정책

진행률은 기존 정책대로 유효 답변 수를 나타낸다.

- 0개: 0/10
- 3개: 3/10
- 9개: 9/10
- 10개: 10/10

질문 번호를 진행률로 사용하지 않는다.

미션 완료 시 10개 진행 원은 모두 완료 상태로 표시한다.

완료 시 새로운 진행률 Banner를 추가하지 않는다.

# 17. 문의 버튼

기존 문의·건의·버그 신고 버튼은 유지한다.

다음 요소와 겹치지 않아야 한다.

- 진행률
- 종료 버튼
- 완료 최종 인사
- 케이 말풍선
- 상태 카드

완료 상태에서도 문의 버튼을 사용할 수 있는 기존 정책이 있다면 유지한다.

# 18. 상태 관리 원칙

마이크 버튼·상태 카드·실제 오디오 입력은 하나의 상태 머신을 기준으로 동작해야 한다.

권장 파생값 예시:

```text
canAcceptVoiceInput =
  sessionConnected
  AND missionNotCompleted
  AND textInputClosed
  AND (
    conversationState == listening
    OR conversationState == waiting_for_user
    OR conversationState == ready_for_input
  )
```

```text
shouldDisableMic =
  NOT canAcceptVoiceInput
```

실제 프로젝트의 상태명에 맞춰 구현한다.

UI 컴포넌트마다 별도의 Boolean을 임의 관리해 다음 상태가 발생하지 않게 한다.

- UI는 주황색인데 실제 마이크 전송은 차단됨
- UI는 회색인데 실제 음성은 전송됨
- 자동 UI인데 내부 입력 모드는 수동
- 키보드가 열렸는데 VAD가 계속 작동
- 완료됐는데 마이크가 다시 활성화됨

# 19. 비동기 상태 전환 및 Race Condition 방지

## 케이 말하기 시작 직전 아이 음성

- 이미 확정된 답변만 처리
- 새로운 턴 답변으로 중복 저장 금지

- 아직 확정되지 않은 자동 음성 Segment는 기존 취소 정책에 따라 폐기
- 텍스트 입력 시작 후 음성 답변 제출 금지

## 10번째 답변과 추가 음성 동시 발생

- 완료 Transaction 시작 시 입력 Gate 즉시 닫음
- 10번째 답변 이후 신규 답변 저장 금지
- 황금열쇠 중복 지급 금지

## 완료 화면 재렌더링

- 완료 TTS 1회만 재생
- 완료 메시지 1회만 표시
- Reward RPC 1회만 호출
