# 중학교 1학년 선택·저장·표시 및 초등학교 6학년 콘텐츠 매핑

## 1. 작업 목적

가입, 아이 추가, 자녀 정보 수정 화면에서 `중학교 1학년`을 선택할 수 있도록 추가한다.

사용자가 선택한 실제 학년은 부모 화면과 자녀 프로필에 `중학교 1학년`으로 정확히 저장·표시한다. 다만 현재 미션 질문지와 퀴즈 콘텐츠가 초등학교 1~6학년까지만 준비되어 있으므로, 중학교 1학년 사용자의 미션·퀴즈 콘텐츠 선택 시에는 내부적으로 초등학교 6학년 콘텐츠를 사용한다.

### 사용자에게 표시되는 실제 학년

- 가입 화면: `중학교 1학년` 선택 가능
- 부모 설정의 아이 추가 화면: `중학교 1학년` 선택 가능
- 부모 설정의 아이 정보 수정 화면: `중학교 1학년` 선택 가능
- 부모 설정, 관리자 화면, 프로필 카드 등 학년 표시 영역: `중학교 1학년`으로 표시
- DB의 자녀 현재 학년: 중학교 1학년을 구분할 수 있는 실제 값으로 저장

### 내부 콘텐츠 학년

중학교 1학년 사용자가 다음 기능을 이용할 때는 초등학교 6학년 콘텐츠를 사용한다.

- 미션 기본 질문·예비 질문

### 중요 원칙

실제 저장된 학년 값을 초등학교 6학년으로 덮어쓰지 않는다.

다음 두 개념을 분리한다.

- `실제 학년`: 중학교 1학년
- `콘텐츠 적용 학년`: 초등학교 6학년

## 3. 학년 값 설계

현재 프로젝트의 기존 학년 타입과 DB 컬럼 형식을 먼저 확인한다.

### 권장 방식

기존 구조가 숫자형이라면 다음 중 프로젝트 전체와 가장 호환되는 방식을 선택한다.

```ts
type SchoolGrade = 1 | 2 | 3 | 4 | 5 | 6 | 7;
```

- `1~6`: 초등학교 1~6학년
- `7`: 중학교 1학년

표시 함수:

```ts
function formatSchoolGrade(grade: number): string {
  if (grade === 7) return "중학교 1학년";
  return `초등학교 ${grade}학년`;
}
```

현재 UI가 `1학년`, `2학년` 형식으로 표시된다면 기존 초등학교 표시 형식은 유지하고 중학교 1학년만 별도 표시한다.

```ts
function formatGradeLabel(grade: number): string {
  return grade === 7 ? "중학교 1학년" : `${grade}학년`;
}
```

### 문자열 또는 enum 구조인 경우

기존 DB와 타입 구조가 문자열 또는 enum이라면 명확한 값을 사용한다.

```ts
type SchoolGrade =
  | "ELEMENTARY_1"
  | "ELEMENTARY_2"
  | "ELEMENTARY_3"
  | "ELEMENTARY_4"
  | "ELEMENTARY_5"
  | "ELEMENTARY_6"
  | "MIDDLE_1";
```

임의로 문자열 `"중1"`, `"7학년"`, `"middle1"`을 여러 위치에서 혼용하지 않는다.

### 금지 사항

- 실제 DB 학년을 6으로 저장하고 UI에서만 중학교 1학년으로 위장 표시
- 화면별로 서로 다른 값 사용
- 가입 화면만 추가하고 API·DB 검증을 누락
- 숫자 7을 기존 코드에서 무조건 초등학교 7학년처럼 표시
- 미션·퀴즈 코드 곳곳에 `grade === 7 ? 6 : grade`를 중복 작성

## 4. 공통 콘텐츠 학년 매핑 함수

콘텐츠 학년 변환은 공통 함수 하나로 관리한다.

권장 예시:

```ts
export function getEffectiveContentGrade(
  schoolGrade: number
): 1 | 2 | 3 | 4 | 5 | 6 {
  return schoolGrade >= 7 ? 6 : (schoolGrade as 1 | 2 | 3 | 4 | 5 | 6);
}
```

enum 방식이라면 다음과 같이 구현한다.

```ts
export function getEffectiveContentGrade(
  schoolGrade: SchoolGrade
): ElementaryGrade {
  if (schoolGrade === "MIDDLE_1") {
    return "ELEMENTARY_6";
  }

  return schoolGrade;
}
```

공통 함수 위치는 기존 학년 관련 유틸리티 구조를 따른다.

예시 후보:

```text
lib/grade.ts
lib/utils/grade.ts
app/api/_lib/grade.ts
```

프런트엔드와 서버 모두에서 사용할 필요가 있다면 서버 전용 경로가 아닌 공용 모듈로 둔다.

## 7. DB 점검 및 마이그레이션

### 7.1 숫자 컬럼

`child_profiles.grade`와 관련 승인 요청 테이블의 `grade`가 정수 컬럼이고 CHECK 제약조건이 `1~6`이라면 `1~7`로 확장한다.

예시:

```sql
ALTER TABLE child_profiles
DROP CONSTRAINT IF EXISTS child_profiles_grade_check;

ALTER TABLE child_profiles
ADD CONSTRAINT child_profiles_grade_check
CHECK (grade BETWEEN 1 AND 7);
```

관련 테이블도 실제 스키마를 확인해 동일 원칙으로 반영한다.

예상 대상:

- `child_profiles`
- `child_approval_requests`
- 가입 임시 저장 테이블
- 가족 구성원 또는 자녀 기본정보 테이블
- 테스트 계정 생성 함수

### 7.2 enum 컬럼

PostgreSQL enum이면 `MIDDLE_1` 또는 프로젝트 규칙에 맞는 값을 추가한다.

마이그레이션은 Dev에서 먼저 검증하고 Production에 동일하게 적용한다.

### 7.3 기존 데이터

기존 1~6학년 데이터는 변경하지 않는다.

중학교 1학년으로 수정한 사용자만 새 값을 저장한다.

## 8. 미션 적용

중학교 1학년 사용자가 미션을 시작할 때 다음 순서로 처리한다.

```ts
const schoolGrade = childProfile.grade;
const contentGrade = getEffectiveContentGrade(schoolGrade);
```

이후 질문지 조회, 프롬프트 구성, 기본·예비 질문 선택에는 `contentGrade`를 사용한다.

```ts
const questions = await getMissionQuestions({
  grade: contentGrade,
  missionType,
  cycleType,
});
```

### 확인 대상

- 미션 시작 API
- 질문지 조회 RPC
- 기본 질문 10개
- 예비 질문 10개
- 질문 재순환
- 미션Ⅰ·미션Ⅱ
- 방학·학기 시간대 로직
- 자동·수동·Premium 미션
- 학년별 프롬프트
- 답변 분석 및 분류 코드에서 학년을 사용하는 부분

### 프롬프트 주의사항

아이에게 직접 말할 때 `6학년이니까`라는 잘못된 표현이 노출되지 않도록 한다.

- 프로필 문맥: 실제 학년 `중학교 1학년`
- 질문 난이도 선택: 초등학교 6학년 콘텐츠
- 사용자 노출 문구: 중학교 1학년

내부 콘텐츠 매핑 사실을 아이나 부모에게 불필요하게 노출하지 않는다.

## 9. 퀴즈마스터 적용

중학교 1학년 사용자가 퀴즈마스터를 실행할 때 handoff 또는 세션 생성에 사용하는 콘텐츠 학년은 6으로 전달한다.

```ts

```

### 적용 대상

- 메인 앱의 퀴즈마스터 실행 API
- handoff token payload
- 퀴즈 세션 생성
- 문제은행 조회
- 이어하기
- 리더보드 또는 결과 저장
- 학년 잠금
- 관리자 퀴즈 데이터 조회

### 저장 기준

퀴즈 결과에 실제 사용자 학년과 콘텐츠 적용 학년을 모두 구분할 필요가 있다면 다음처럼 분리한다.


기존 스키마 변경이 불필요한 경우에는 사용자 프로필의 실제 학년은 `child_profiles`에서 유지하고, 퀴즈 세션에는 콘텐츠 학년 6만 전달한다.

- 아이 추가 화면에 중학교 1학년 선택지 추가
- 아이 정보 수정 화면에 중학교 1학년 선택지 추가
- API와 DB에 실제 중학교 1학년 값 저장
- 부모·아이·관리자 화면에 중학교 1학년 표시
- 승인 요청 현황에도 최신 중학교 1학년 정보 표시
- 미션은 초등학교 6학년 콘텐츠 사용
- 퀴즈마스터는 초등학교 6학년 문제 사용
- 실제 프로필 학년을 6학년으로 덮어쓰지 않음
- 공통 콘텐츠 학년 매핑 함수 사용
- 학년 매핑 로직 중복 없음
- 기존 초등학교 1~6학년 회귀 테스트 통과
- Dev 검증 완료
- Production 배포 및 실제 계정 검증 완료
- 개인정보 및 비밀정보가 로그·커밋·임시파일에 포함되지 않음
