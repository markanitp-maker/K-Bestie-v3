# 029 — 부모 홈 화면 ‘대화 가이드’ 중심 전면 개편

## 1. 작업 목적

현재 부모 홈 화면을 첨부 레퍼런스 이미지의 정보 구조와 분위기를 기준으로 전면 개편한다.

부모 홈은 아이의 대화 원문이나 복잡한 분석 데이터를 나열하는 화면이 아니라, 부모가 아이의 최근 흐름을 짧게 파악하고 실제 대화를 시작할 수 있도록 돕는 `대화 가이드` 화면으로 구성한다.

이번 개편의 핵심은 다음과 같다.

- 선택된 자녀의 최근 대화·리포트 정보를 한 화면에서 요약한다.
- 가장 먼저 부모가 오늘 사용할 수 있는 한마디를 보여준다.
- 학교생활, 친구 관계, 마음 흐름, 관심사 등 주요 영역을 카드 형태로 정리한다.
- 각 카드에는 현재 상태, 최근 관련 대화량, 마지막 관찰 시점을 표시한다.
- 아이의 대화 원문은 부모 홈에 노출하지 않는다.
- 실제 리포트와 분석 데이터가 없는 상태에서 내용을 임의로 생성하지 않는다.
- 부모용 하단 Navigation은 유지한다.
- 스마트폰 외곽 프레임과 상태 표시줄은 구현하지 않는다.

---

# 2. 레퍼런스 적용 범위

첨부 이미지에서 앱 내부 UI만 참고한다.

## 구현 대상

- 상단 공식 내친구 케이 로고
- 선택된 자녀 이름과 자녀 전환 드롭다운
- 알림 버튼
- `대화 가이드` 화면 제목
- `오늘의 한마디` 요약 카드
- 2열 인사이트 카드 영역
- 카드별 상태 badge
- 관련 대화 수와 마지막 관찰 시점
- 부모용 하단 Navigation
- 모바일 화면 내부 스크롤

## 구현 제외

- 스마트폰 외곽 프레임
- 다이내믹 아일랜드
- iOS 상태 표시줄
- 기기 버튼
- iOS 홈 인디케이터
- 이미지에 포함된 가상 시간과 통신 아이콘
- 레퍼런스에 있는 임의 이름과 임의 데이터

`김서현`, `대화 6회`, `1년 전` 등의 값은 레퍼런스용 표현이므로 하드코딩하지 않는다.

# 3. 부모 홈 화면의 역할

부모 홈 화면은 다음 질문에 빠르게 답해야 한다.

1. 오늘 아이에게 어떤 말을 건네면 좋은가?
2. 아이가 최근 학교와 친구 관계를 어떻게 이야기하고 있는가?
3. 최근 아이가 자주 이야기하는 관심사와 고민은 무엇인가?
4. 부모가 지금 개입해야 하는 영역이 있는가?
5. 더 자세한 내용은 어느 리포트에서 볼 수 있는가?

부모 홈은 심리 진단 화면이 아니다.

다음과 같은 확정적 진단 표현을 임의로 만들지 않는다.

- 우울함
- 불안 장애
- 학교 부적응
- 친구 관계 문제 확정
- 특정 질환 또는 심리 상태 진단

데이터가 충분하지 않은 경우 `확인된 내용이 아직 적어요`, `최근 대화에서 뚜렷한 변화는 보이지 않아요`처럼 중립적으로 표시한다.

# 5. 전체 레이아웃

## 기본 구조

- 모바일 우선
- 최소 높이 `100dvh`
- 화면 너비 `100%`
- 부모용 하단 Navigation 유지
- 태블릿·PC에서는 최대 콘텐츠 너비 약 `430px~520px`
- 태블릿·PC에서는 중앙 정렬
- 콘텐츠 영역은 세로 스크롤 허용
- 가로 스크롤 금지
- iOS·Android safe-area 반영
- 하단 Navigation 높이만큼 콘텐츠 하단 padding 확보

## 배경

- 기본 배경은 Warm Neutral 또는 매우 연한 하늘색 계열
- 카드 배경은 흰색
- 페이지 전체에 과도한 그라데이션과 장식 사용 금지
- 부모 화면은 아이 홈보다 차분하고 정보 중심으로 구성

권장:

```css
background: var(--background-page);
```

Design System v2 토큰을 우선 사용한다.

# 6. 상단 헤더

## 구성

왼쪽:

- 내친구 케이 공식 가로형 로고

오른쪽 영역:

- 현재 선택된 자녀 이름
- 드롭다운 아이콘
- 알림 아이콘

## 로고

- 공식 정본 자산 사용
- 비율 왜곡 금지
- 임의 색상 변경 금지
- 고정 높이 약 `22px~28px`
- 모바일에서 지나치게 크지 않도록 적용

## 헤더 스타일

- 높이 약 `56px~64px`
- 흰색 또는 반투명 흰색
- 필요하면 약한 하단 구분선 적용
- 스크롤 중 상단 고정이 기존 부모 Layout 정책과 맞으면 sticky 사용
- 콘텐츠를 덮는 fixed 방식은 피한다.

# 7. 자녀 선택 드롭다운

부모에게 연결된 자녀가 여러 명일 수 있으므로 현재 선택된 자녀를 명확하게 표시한다.

## 표시 예시

```text
안서아 ▼
```

## 동작

- 클릭 시 부모에게 연결된 자녀 목록 표시
- 자녀 선택 시 부모 홈의 모든 데이터가 선택된 자녀 기준으로 갱신
- 다른 자녀의 리포트나 상태가 섞이지 않도록 한다.
- 선택 상태는 기존 child selection store 또는 context를 재사용
- 새로고침 후에도 기존 선택 정책에 따라 유지
- 자녀가 한 명이어도 현재 대상이 누구인지 표시

## 주의

- 레퍼런스의 `김서현` 하드코딩 금지
- 부모 이름과 자녀 이름을 혼동하지 않음
- 성과 이름 표시 방식은 현재 자녀 프로필의 정본 값을 사용
- 선택 변경 중 이전 자녀의 카드 내용이 잠시 남아 있지 않게 로딩 상태 표시

## 접근성

- `aria-label="자녀 선택"`
- 키보드 탐색 가능
- 열림·닫힘 상태 전달
- 드롭다운 focus trap 또는 메뉴 접근성 기준 준수

# 8. 알림 버튼

## 디자인

- 종 모양 아이콘
- K-Mascot Orange 또는 K-Navy
- 최소 터치 영역 `44x44px`
- 새로운 알림이 있으면 작은 badge 표시
- badge는 숫자 또는 점과 접근성 텍스트를 함께 제공

## 동작

- 기존 알림 화면 또는 알림 패널과 연결
- 기존 기능이 없는 경우 아이콘만 임의로 추가하지 말고 현재 알림 데이터·route 존재 여부를 먼저 조사
- 알림 기능이 구현되지 않은 경우 이번 작업에서 무리하게 전체 알림 시스템을 새로 만들지 말고 비활성 또는 구현 보류 상태를 보고

## 접근성

```text
알림 2개
```

처럼 현재 상태를 접근성 이름으로 제공한다.

# 9. 화면 제목

## 제목

```text
대화 가이드
```

옆에 작은 책 또는 대화 가이드 아이콘을 배치할 수 있다.

## 스타일

- K-Navy
- 굵기 `700~800`
- 크기 약 `22px~26px`
- 화면 좌우 여백 약 `16px~20px`
- 아이콘은 장식 목적으로 과도하게 강조하지 않음

## 부제

필요하면 다음과 같은 짧은 설명을 추가할 수 있다.

```text
아이와 자연스럽게 대화를 시작해 보세요.
```

다만 화면 높이를 과도하게 차지하지 않도록 최대 1줄로 제한한다.

# 10. `오늘의 한마디` 카드

부모 홈에서 가장 먼저 보여야 하는 핵심 정보다.

## 목적

아이의 최근 대화와 최신 리포트를 기반으로 부모가 오늘 실제로 사용할 수 있는 한마디 또는 대화 방향을 제공한다.

## 표시 예시

```text
오늘의 한마디

친구와의 약속을 잘 지키려는 모습이 보여요.
오늘은 마음을 헤아려 준 점을 칭찬해 주세요.
```

위 문구는 예시이며 하드코딩하지 않는다.

## 데이터 기준

다음 순서로 정본 데이터를 사용한다.

1. 최신 일일 리포트의 `오늘의 대화거리`
2. 최신 리포트의 부모 전달 메시지
3. 최신 주간 리포트의 대화 가이드
4. 데이터가 없을 경우 중립적인 빈 상태

아이와 케이의 raw 대화 원문을 직접 표시하지 않는다.

## 빈 상태

최신 리포트나 분석 데이터가 없는 경우:

```text
아직 오늘의 대화 가이드가 준비되지 않았어요.
아이가 케이와 이야기를 나누면 이곳에 알려드릴게요.
```

## 디자인

- K-Navy 배경
- 흰색 또는 충분히 대비되는 밝은 텍스트
- radius 약 `18px~22px`
- 내부 padding 약 `18px~20px`
- 약한 그림자
- 제목은 작은 크기
- 본문은 제목보다 크게 표시
- 본문 최대 3~4줄
- 텍스트가 길면 전체 페이지 높이는 늘어날 수 있으나 카드 내부의 가로 잘림 금지
- 강한 감정 경고나 위험 상태는 이 카드에서 브랜드 문구로 덮지 않고 별도 상태 표시를 사용

# 11. 인사이트 카드 영역

`오늘의 한마디` 아래에 주요 영역을 2열 카드로 배치한다.

## 기본 영역

1. 학교·학원 생활
2. 친구 관계
3. 마음 흐름
4. 관심사·취향
5. 공부 고민
6. 디지털·콘텐츠
7. 선생님·어른
8. 반복 이야기

실제 리포트 데이터 구조상 지원되지 않는 영역이 있다면 임의 분석을 추가하지 않는다.

먼저 기존 리포트의 다음 항목과 매핑 가능 여부를 확인한다.

- 기분
- 친구
- 학교
- 관심사
- 사건 키워드
- 변화 신호
- 오늘의 대화거리
- 부모 전달 메시지
- 반복 키워드 또는 대화 주제
- 대화 분류 metadata

지원되지 않는 항목은 다음 중 하나로 처리한다.

- 데이터가 있는 카드만 노출
- `아직 확인된 내용이 적어요` 상태 노출
- 기존 데이터 파이프라인에 영향을 주지 않는 범위에서 집계

UI를 채우기 위해 LLM 분석을 새로 호출하거나 임의 데이터를 생성하지 않는다.

# 12. 인사이트 카드 공통 구조

각 카드는 다음 요소로 구성한다.

## 상단

- 영역 아이콘
- 작은 카테고리명

예시:

```text
학교·학원 생활
```

## 중앙

- 현재 요약 문구

예시:

```text
전반적으로 만족
```

또는:

```text
최근 관련 이야기가 적어요
```

## 하단

왼쪽:

- 상태 badge 또는 상태 점
- 상태 텍스트

오른쪽:

- 관련 대화 수
- 마지막 확인 시점

예시:

```text
좋아요       대화 5회 · 1일 전
```

## 카드 크기

- 2열에서 동일한 높이 유지
- 최소 높이 약 `108px~132px`
- 텍스트가 길어도 카드끼리 심하게 높이가 달라지지 않도록 문구 길이를 제한
- 중요한 정보는 말줄임으로 숨기지 않고 세부 화면에서 확인 가능하게 구성

# 13. 상태 체계

상태를 단순히 색상으로만 구분하지 않는다.

권장 상태:

## `좋아요`

최근 대화에서 긍정적이거나 안정적인 흐름이 관찰된 경우

예시:

```text
좋아요
```

## `특징`

좋고 나쁨의 평가가 아니라 반복되는 관심사나 특성이 관찰된 경우

예시:

```text
특징
```

## `살펴보기`

부모가 부담 없이 한 번 더 대화해 볼 필요가 있는 경우

예시:

```text
살펴보기
```

## `확인 필요`

데이터 오류, 충분하지 않은 분석 또는 운영 확인이 필요한 경우

예시:

```text
확인 필요
```

## `데이터 부족`

최근 관련 대화가 충분하지 않은 경우

예시:

```text
데이터 부족
```

`위험`, `문제`, `이상` 같은 강한 표현은 실제 정책과 근거 없이 사용하지 않는다.

# 14. 상태 색상

## 좋아요

- K-Sky Blue 또는 별도의 success semantic token
- 텍스트와 아이콘 함께 표시

## 특징

- K-Navy 또는 중립적인 하늘색
- 좋고 나쁨의 의미를 부여하지 않음

## 살펴보기

- K-Mascot Orange 또는 warning semantic token
- 부모가 아이를 추궁하도록 유도하는 빨간색 경고 표현 금지

## 확인 필요

- 기존 state-warning 또는 state-error 토큰
- 데이터 오류와 아이 상태를 혼동하지 않게 문구 구분

## 데이터 부족

- Neutral 계열
- 회색 점과 텍스트

상태색은 Design System v2 semantic token을 사용한다.

# 23. 관련 대화 수

각 카드 하단에 해당 영역과 관련된 최근 대화 수를 표시한다.

예시:

```text
대화 5회
```

## 기준

- 어떤 기간의 대화 수인지 명확하게 정의
- 권장 기준: 최근 7일
- 기존 리포트 집계 기준이 있으면 해당 기준 사용
- 모든 카드가 동일한 기간 기준을 사용
- raw 데이터 보존 기간 정책을 위반하지 않음

기간을 화면에 직접 표시할 필요가 있다면:

```text
최근 7일 · 대화 5회
```

## 금지

- 전체 미션 질문 수를 대화 수로 표시
- 중복 저장된 transcript를 여러 회로 계산
- 데이터가 없는데 `0회`로 단정
- 7일 보존이 끝난 raw 데이터를 새로 조회하여 재집계

가능하면 리포트에 저장된 집계 결과를 사용한다.

- 사용자 로컬 시간대 기준
- 한국 서비스 기준 KST 처리 확인
- 데이터 없음은 `기록 없음`으로 표시
- `1년 전` 같은 레퍼런스 값 하드코딩 금지

# 25. 카드 클릭 동작

## 기본 원칙

카드에 연결할 실제 상세 화면 또는 리포트 영역이 존재하면 클릭 가능하게 한다.

예시:

- 학교 카드 → 리포트의 학교 관련 상세
- 친구 카드 → 리포트의 친구 관련 상세
- 마음 흐름 카드 → 리포트의 기분·변화 신호 상세

## 상세 화면이 없는 경우

- 카드가 버튼처럼 보이지 않게 처리
- 임의의 빈 상세 페이지 생성 금지
- 클릭 시 아무 반응 없는 카드 금지

## 접근성

클릭 가능한 카드에는 다음과 같이 목적이 명확한 이름을 적용한다.

```text
학교·학원 생활 자세히 보기
```

# 26. 아이의 대화 원문 보호

부모 홈에는 다음 정보를 표시하지 않는다.

- 아이와 케이의 전체 대화 원문
- 아이의 발화를 직접 인용한 긴 문장
- 세션 transcript
- 음성 파일
- 원본 녹음
- raw 데이터
- corrected transcript 전체

부모 홈에는 다음만 표시한다.

- 요약
- 흐름
- 관심사
- 변화 신호
- 오늘 사용할 대화 가이드
- 부모 개입 가이드

아이의 사생활을 보호하면서 부모가 대화를 시작할 수 있는 수준으로 제한한다.

# 27. 부모 개입 가이드

`오늘의 한마디` 또는 특정 카드에서 부모에게 말을 거는 방법을 제안할 경우 다음 원칙을 따른다.

## 권장

```text
오늘 학교에서 제일 재미있었던 일은 뭐였어?
```

```text
그림 그리는 게 요즘 재미있어 보이더라.
어떤 그림을 그리고 싶어?
```

## 금지

```text
케이한테 친구랑 싸웠다고 말했다며?
```

```text
왜 요즘 수학이 어렵다고 했어?
```

부모가 아이를 추궁하거나 감시하는 느낌이 들지 않게 한다.

# 28. 데이터 갱신

다음 시점에 부모 홈 데이터를 갱신한다.

- 부모 홈 최초 진입
- 자녀 변경
- 새로운 리포트 생성 후
- 앱이 background에서 foreground로 복귀할 때 기존 정책상 필요한 경우
- 관리자 즉시 수집 또는 즉시 리포트 실행 후
- 사용자 수동 새로고침이 기존 화면에 존재하는 경우

## 주의

- 컴포넌트마다 동일 API 중복 호출 금지
- 화면 진입 때마다 불필요한 LLM 분석 호출 금지
- 이미 생성된 리포트와 집계 결과 우선 사용
- raw 데이터를 클라이언트로 내려받아 브라우저에서 분석 금지

# 29. 로딩 상태

## 화면 최초 로딩

- 헤더와 화면 제목은 먼저 표시
- `오늘의 한마디` 카드 skeleton
- 인사이트 카드 8개 영역 skeleton
- 레이아웃 shift 최소화
- 전체 화면을 spinner 하나로 가리는 방식은 피한다.

## 자녀 변경

- 선택한 자녀 이름은 즉시 갱신
- 카드 데이터는 skeleton 또는 loading 상태
- 이전 자녀 데이터가 새 자녀 데이터처럼 보이지 않게 즉시 제거

# 30. 빈 상태

## 대화 또는 리포트 없음

`오늘의 한마디`:

```text
아직 대화 가이드가 준비되지 않았어요.
아이가 케이와 이야기를 나누면 이곳에서 알려드릴게요.
```

인사이트 카드:

```text
최근 확인된 이야기가 아직 없어요.
```

## 신규 자녀

부모가 해야 할 행동을 안내한다.

```text
아이가 케이와 첫 대화를 시작하면
대화 가이드가 만들어져요.
```

필요하면 아이 홈 또는 미션 안내로 연결하되 부모가 아이 계정으로 임의 전환되는 동작은 기존 인증 정책을 따른다.

# 31. 오류 상태

## 리포트 조회 실패

```text
대화 가이드를 불러오지 못했어요.
잠시 후 다시 시도해 주세요.
```

재시도 버튼 제공

## 일부 카드 데이터 실패

전체 화면을 오류 처리하지 않고 해당 카드만 중립적 오류 상태로 표시한다.

```text
이 항목을 불러오지 못했어요.
```

## 권한 오류

```text
이 자녀의 리포트를 확인할 권한이 없어요.
```

다른 부모나 다른 가족의 자녀 데이터가 노출되지 않도록 서버와 RLS에서 확인한다.

# 32. 부모용 하단 Navigation

레퍼런스와 같이 부모용 하단 Navigation을 유지한다.

## 메뉴

1. 홈
2. 리포트
3. 케이와 대화
4. 설정

실제 기존 메뉴명과 route를 확인해 일치시킨다.

## 디자인

- 흰색 또는 매우 연한 Neutral 배경
- 상단 구분선
- safe-area 반영
- 활성 메뉴는 K-Orange 또는 K-Navy
- 비활성 메뉴는 Neutral
- 아이콘과 텍스트 모두 표시
- 최소 터치 영역 `44x44px`
- 현재 홈 메뉴를 활성 상태로 표시

## 주의

- 아이 홈에서 제거한 하단 Navigation 정책을 부모 화면에 적용하지 않는다.
- 부모 화면의 설정 기능은 유지한다.
- 하단 Navigation이 콘텐츠를 덮지 않도록 하단 padding 확보
- 스크롤 시 화면에 고정하는 기존 정책이 있으면 유지

- 필요하면 카드 영역을 2열 또는 제한된 3열로 구성하되 모바일 정보 계층 유지
- 바깥 영역은 Neutral 배경

# 35. 접근성

- 모든 버튼 터치 영역 최소 `44x44px`
- 카드가 클릭 가능하면 의미 있는 link 또는 button 사용
- `div onClick`만 사용하는 구현 금지
- 자녀 선택 드롭다운 키보드 접근 가능
- 알림 버튼 접근성 이름 제공
- 카드 상태를 텍스트로 제공
- 아이콘은 의미가 없으면 `aria-hidden`
- focus 표시 유지
- 화면 제목 heading 구조 적용
- 동적 데이터 갱신 시 필요한 경우 `aria-live` 적용
- `prefers-reduced-motion` 지원

# 36. 성능

- 부모 홈 진입 시 카드별로 개별 LLM 호출 금지
- 기존 생성 리포트 데이터 재사용
- 동일 API 중복 호출 금지
- 이미지와 아이콘은 기존 최적화 컴포넌트 사용
- 카드 렌더링을 위해 전체 raw transcript 다운로드 금지
- 자녀 전환 시 이전 요청 취소 또는 stale response 차단
- 필요 시 query cache 사용

# 37. 보안 및 권한

- 로그인한 부모에게 연결된 자녀 데이터만 조회
- child_id를 클라이언트에서 바꾸는 것만으로 다른 자녀 데이터를 조회할 수 없어야 함
- 서버·RLS에서 부모-자녀 관계 검증
- 관리자 권한과 부모 권한 혼동 금지
- raw 대화 원문을 부모 홈 API 응답에 포함하지 않음
- 자녀 전환 시 cache key에 child_id 포함
- 브라우저 로그에 아이 민감정보 출력 금지

# 39. 코드 작업 원칙

- 먼저 현재 부모 홈 route와 관련 컴포넌트를 조사한다.
- 부모용 Layout과 하단 Navigation 구조를 확인한다.
- 현재 리포트 데이터의 source of truth를 확인한다.
- 현재 선택 자녀 store 또는 context를 재사용한다.
- 기존 미커밋 변경을 보존한다.
- 관련 없는 파일 포맷팅 금지
- 전체 색상 자동 치환 금지
- 레퍼런스 이미지를 잘라 UI 자산으로 사용하지 않는다.
- 카드 내용을 하드코딩하지 않는다.
- 테스트를 위해 production 데이터에 가짜 리포트를 추가하지 않는다.
