# 042 — 미션·퀴즈마스터·MBTI 화면의 스마트폰/태블릿 프레임 복구

## 1. 작업 목적

현재 아이 홈 화면은 스마트폰 프레임(디바이스 목업 프레임)이 적용되어 보이는데,
다음 화면으로 진입하면 프레임이 사라지고 일반 웹 브라우저 전체 화면처럼 표시되고 있다.

문제 대상 화면:
- 미션 대화 화면
- 퀴즈마스터
- MBTI

대표님 의도는 모든 주요 아이용 인터랙션 화면이 **스마트폰 또는 태블릿 프레임 안에서 일관되게 보이는 것**이다.

따라서 이번 작업은 각 기능 화면의 UI/로직을 바꾸는 것이 아니라,
**사라진 디바이스 프레임을 공통 래퍼로 다시 복구**하는 작업이다.

---

## 2. 현재 문제 요약

현재 상태:

### 정상 예시
- 아이 홈 화면: 스마트폰 프레임이 적용되어 있음

### 비정상 예시
- 미션 화면: 프레임 없이 일반 브라우저 창처럼 표시됨
- 퀴즈마스터: 프레임 없이 일반 페이지처럼 표시됨
- MBTI: 프레임 없이 일반 페이지처럼 표시됨

즉, 화면 내용은 나오지만 “디바이스 프레임 쉘”이 빠져 있다.

---

## 3. 최종 목표

다음 화면들이 모두 **동일한 디바이스 프레임 시스템** 안에서 렌더링되어야 한다.

### 적용 대상
1. 아이 홈
2. 미션 대화
3. 퀴즈마스터
4. MBTI
5. 향후 아이용 놀이 화면 공통 확장 가능 구조

### 목표 결과
- 모바일 비율 화면은 스마트폰 프레임 적용
- 태블릿 비율 화면은 태블릿 프레임 적용
- 프레임 안쪽에 실제 앱 화면이 들어감
- 프레임 바깥에 일반 브라우저 배경이 보이더라도 앱 본문은 프레임 내부에만 표시
- 각 페이지별로 따로 프레임을 구현하지 않고 공통 컴포넌트로 관리

---

## 4. 핵심 요구사항

### 4-1. 공통 디바이스 프레임 컴포넌트 복구

스마트폰/태블릿 프레임을 각 페이지마다 따로 넣지 말고,
공통 래퍼 컴포넌트로 복구 또는 재구성한다.

예시 구조:

```text
DeviceFrameShell
 └─ DeviceViewport
     └─ page content
```

권장 역할:

- `DeviceFrameShell`
  - 외곽 프레임(베젤, 라운드, 노치/상단 영역, 그림자)
- `DeviceViewport`
  - 실제 앱 화면이 렌더링되는 내부 영역
  - 스크롤도 이 안에서만 발생

---

### 4-2. 화면별 개별 구현 금지

다음처럼 페이지별로 프레임 마크업을 중복 작성하지 않는다.

- mission page에만 별도 프레임
- quiz page에만 별도 프레임
- mbti page에만 별도 프레임

반드시 **공통 프레임 컴포넌트**를 사용한다.

---

### 4-3. 프레임 적용 대상 화면

반드시 아래 화면에 적용한다.

#### 미션
- 시작 전
- 진행 중
- 완료 후
- 이어하기 상태
- 자동/수동 모드
- 키보드 입력 모드
- 문의 버튼 포함 상태

#### 퀴즈마스터
- 문제 풀이 화면
- 진행률 표시 화면
- 제출하기 / 다음 버튼 포함 상태
- 결과/완료 상태가 있다면 해당 화면도 포함

#### MBTI
- 문제 진행 화면
- 이미지 포함 문항 화면
- 선택지 화면
- 결과 화면이 있다면 결과 화면까지 포함

---

## 5. 프레임 종류 규칙

### 5-1. 스마트폰 프레임
다음 조건에서는 스마트폰 프레임을 사용한다.

- 모바일 비율
- 세로형 일반 아이 화면
- 아이 홈 / 미션 / 퀴즈 / MBTI 기본값

### 5-2. 태블릿 프레임
다음 조건에서는 태블릿 프레임을 사용한다.

- 태블릿 해상도 또는 태블릿 비율
- 내부 viewport가 너무 좁아지지 않도록 별도 태블릿 목업 사용 가능

### 5-3. 전환 기준
실제 구현에서는 현재 프로젝트의 반응형 기준을 활용하되,
“브라우저 창이 크다”는 이유만으로 그냥 프레임을 제거하지 않는다.

즉,
- PC에서 보더라도
- 에뮬레이터에서 보더라도
- PWA에서 보더라도

아이용 화면은 여전히 **디바이스 프레임 안**에서 보여야 한다.

---

## 6. 프레임 내부 레이아웃 원칙

프레임은 단지 바깥 껍데기만 입히는 것이 아니라,
내부 앱 viewport가 올바르게 동작해야 한다.

### 필수 조건
- 내부 콘텐츠는 프레임 안쪽에서만 렌더링
- 내부 스크롤은 viewport 내부에서만 발생
- `100dvh`/`100vh` 사용 시 프레임 밖으로 튀어나가지 않게 보정
- safe-area, 상하 padding, 하단 버튼 영역이 프레임 안에서 정상 표시
- 노치 영역과 겹치지 않게 처리
- 프레임 바깥 body가 스크롤되지 않게 정리

### 금지
- 프레임은 있는데 콘텐츠가 바깥으로 넘치는 상태
- 프레임 안쪽 콘텐츠 높이가 잘못 계산되어 하단 버튼이 잘리는 상태
- 미션 말풍선, MBTI 선택지, 퀴즈 버튼이 프레임 밖으로 나가는 상태

---

## 7. 현재 문제의 가능한 원인 조사

구현 전 아래를 먼저 점검한다.

1. 아이 홈만 감싸는 전용 Layout이 따로 있는지
2. 미션/퀴즈/MBTI는 다른 Layout을 타면서 프레임 래퍼를 빠뜨렸는지
3. `iframe`, modal, full-screen container 등으로 프레임을 우회하는 구조인지
4. 페이지별 `overflow`, `height`, `position: fixed` 처리 때문에 프레임이 제거되었는지
5. PWA/브라우저/데스크톱 모드에 따라 조건부로 프레임을 꺼버리는 로직이 있는지
6. 최근 공통 레이아웃 개편 과정에서 frame wrapper가 child-home에만 남고 나머지에서 누락되었는지

원인을 정확히 찾고 최소 수정으로 복구한다.

## 8. 화면별 세부 요구사항

### 8-1. 미션 화면
미션 화면은 현재 일반 브라우저 중앙 정렬 화면처럼 보이는데,
반드시 스마트폰 프레임 내부에 들어가야 한다.

유지해야 할 요소:
- 진행률 바
- X 닫기 버튼
- 문의 버튼
- 말풍선
- K 마스코트
- 자동/수동 버튼
- 마이크 버튼
- 키보드 버튼
- 상태 카드(소리 켜짐, 말하는 중, 듣고 있어 등)

단, 이 요소들의 기능은 바꾸지 않는다.
**오직 프레임 복구 및 내부 viewport 정렬만 수행**한다.

---

### 8-2. 퀴즈마스터
현재는 일반 웹 폼처럼 보여서 디바이스 경험이 깨진다.

반드시 프레임 안에서:
- 상단 로고/마스코트
- 문제 번호
- 진행률 바
- 질문
- 보기 4개
- 제출하기
- 이전/다음 영역

이 모두가 하나의 스마트폰/태블릿 디바이스 화면처럼 보여야 한다.

---

### 8-3. MBTI
현재는 긴 웹페이지처럼 보여서 프레임 몰입감이 없다.

반드시 프레임 안에서:
- 상단 로고
- 진행률
- 마스코트
- 메인 이미지
- 질문
- 선택지

가 보이도록 하고,
세로 스크롤이 있더라도 **프레임 내부 스크롤**이어야 한다.

- 기존 버튼/카드 스타일

- 상단 노치/다이내믹 아일랜드 형태 유지 가능
- 내부 화면은 흰색/브랜드 배경 그대로 유지
- 가벼운 그림자 적용

- 모바일과 태블릿에서 전혀 다른 디자인 체계 적용
- 실제 앱 내용 대신 단순 이미지 목업으로 대체
