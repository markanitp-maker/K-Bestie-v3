# 048 — 미션·자유대화 케이 발화 3단계 타임라인 긴급 수정 및 Dev·Production 배포

## 1. 작업 우선순위

이 요청은 현재 Production 배포 과정에서 발견된 사용자 노출 버그에 대한 긴급 Hotfix다.

현재 진행 중인 관련 없는 UI 작업보다 우선 처리한다.

처리 순서:

1. 현재 미커밋 변경과 배포 상태 확인
2. 미션·자유대화 공통 원인 감사
3. 코드 수정
4. 자동 검증
5. Dev 배포
6. 실제 모바일 PWA Dev QA
7. 이상이 없으면 즉시 Production 배포
8. 실제 모바일 PWA Production Smoke Test
9. Build ID와 Service Worker 적용 상태 확인

DB Migration, 데이터 삭제 또는 기존 대화 기록 변환이 필요한 작업으로 확대하지 않는다.

---

# 2. 버그 현상

현재 미션 대화와 자유대화 화면에는 최근 대화 내용이 세 영역으로 표시된다.

화면 기준:

```text
3번: 화면 상단의 가장 약한 보조 문구
2번: 가운데의 작은 흰색 말풍선
1번: 아래쪽 K-Orange 테두리의 큰 말풍선
```

원래 디자인 의도는 세 영역 모두 케이가 말한 내용을 시간순으로 보여주는 것이다.

하지만 현재 실제 화면에서는 다음처럼 표시된다.

```text
1번: 현재 또는 최근 케이 발화
2번: 이전 케이 발화
3번: 아이 발화
```

이 동작은 잘못됐다.

아이 발화는 1·2·3 영역 어디에도 표시하지 않는다.

---

# 3. 최종 확정 정책

1·2·3 영역은 화자별 채팅 영역이 아니다.

세 영역 모두 케이가 사용자에게 실제로 말한 내용만 보여주는 최근 3단계 타임라인이다.

| 영역 | 표시 내용 | 시각적 우선순위 |
|---|---|---|
| 1번 | 케이의 현재 발화 또는 가장 최근 완료 발화 | 가장 강하게 강조 |
| 2번 | 케이의 바로 이전 완료 발화 | 중간 강조 |
| 3번 | 케이의 두 단계 이전 완료 발화 | 가장 약하게 표시 |

최종 의미:

```text
3번 = 케이가 두 번 전에 말한 내용
2번 = 케이가 바로 전에 말한 내용
1번 = 케이가 현재 또는 가장 최근에 말한 내용
```

---

동일한 정책을 다음 두 화면에 모두 적용한다.

---

# 5. 화면 표시 규칙

## 케이 발화가 1개인 경우

```text
1번: 최근 케이 발화
2번: 미표시
3번: 미표시
```

2번과 3번을 위한 빈 Wrapper나 고정 높이를 남기지 않는다.

## 케이 발화가 2개인 경우

```text
1번: 최근 케이 발화
2번: 이전 케이 발화
3번: 미표시
```

## 케이 발화가 3개 이상인 경우

```text
1번: 최근 케이 발화
2번: 이전 케이 발화
3번: 두 단계 이전 케이 발화
```

항상 최근 3개만 화면에 표시한다.

그 이전 케이 발화는 화면에서 밀려나지만 기존 대화 기록과 서버 저장 데이터에서는 삭제하지 않는다.

---

# 6. 케이가 현재 말하는 중일 때

스트리밍 중인 케이 발화와 이미 완료된 케이 발화를 구분한다.

권장 상태:

```text
activeKUtterance
finalizedKUtterances
```

케이가 현재 말하는 중이면:

```text
1번 = 현재 스트리밍 중인 케이 발화
2번 = 직전에 완료된 케이 발화
3번 = 그 이전에 완료된 케이 발화
```

스트리밍 Chunk가 들어올 때마다 2번과 3번을 계속 밀면 안 된다.

동일 케이 Turn의 Partial Transcript는 1번 내용만 갱신한다.

---

# 7. 케이 발화 완료 처리

케이 발화가 최종 완료되면 해당 Turn을 한 번만 확정 기록한다.

완료 후:

```text
1번 = 방금 완료된 케이 발화
2번 = 기존의 가장 최근 완료 발화
3번 = 기존의 두 번째 최근 완료 발화
```

다음 케이 Turn이 시작되기 전까지 같은 구조를 유지한다.

권장 개념:

```text
recentKUtterances = [
  가장 최근 완료 발화,
  한 단계 이전 완료 발화,
  두 단계 이전 완료 발화
]
```

실제 프로젝트에 이미 메시지 배열이나 Transcript History가 있으면 중복 상태를 새로 만들지 말고, 케이 발화만 필터링한 파생값을 우선 사용한다.

---

# 8. 아이 발화 표시 금지

다음 데이터는 화면의 1·2·3 영역에 절대 표시하지 않는다.

- 아이 음성 STT 결과
- 아이 텍스트 입력
- 아이 발화의 실시간 Partial Transcript
- 아이 발화의 최종 Transcript
- 문맥 보정된 아이 발화
- `role=user`, `speaker=child` 또는 동등한 메시지

아이 발화를 숨긴다는 이유로 데이터 처리를 삭제하면 안 된다.

아이 발화는 기존대로 다음 용도에 사용한다.

- 케이 응답 생성
- 현재 대화 문맥
- 유효 답변 판정
- 미션 진행률
- 대화 저장
- 세션 복원
- 리포트 생성
- 문맥 보정
- 운영 품질 검증

정책:

```text
아이 발화
→ 내부 처리·저장에는 유지
→ 아이 화면의 1·2·3 타임라인에는 미노출
```

---

# 9. 케이 발화 판정 기준

최근 케이 발화 배열에는 사용자가 실제로 보거나 들은 케이의 대화 문장만 포함한다.

포함:

- 케이가 실제로 음성 출력한 문장
- 케이가 실제로 화면에 출력한 최종 응답
- 현재 스트리밍 중인 케이의 사용자 대상 발화
- 케이의 질문
- 케이의 공감·반응
- 케이의 재질문
- 케이의 시작 인사
- 케이의 완료 인사

제외:

- 아이 발화
- System Prompt
- Developer Prompt
- Function Call Arguments
- Function Call Result
- Google Search 또는 Tool 내부 결과
- 내부 추론·분류 결과
- VAD 상태 문자열
- `연결 중`, `재연결 중` 등 기술 상태
- 디버그 로그
- 저장 성공·실패 메시지
- 사용자에게 실제 출력되지 않은 임시 후보 문장
- 중단되어 실제 음성 출력되지 않은 생성 초안

---

# 10. Native Audio·Transcript 중복 방지

동일한 케이 발화가 다음 경로에서 중복으로 전달될 수 있는지 감사한다.

- Native Audio Transcript
- Text Response
- TTS에 전달한 원문
- 서버 Relay Transcript
- WebSocket 완료 이벤트
- React 상태 복원
- 세션 저장 응답

동일 Turn이 두 번 기록되어 다음처럼 보이면 안 된다.

```text
1번: 같은 케이 문장
2번: 같은 케이 문장
3번: 이전 문장
```

가능한 경우 다음 정본 ID를 사용해 중복을 제거한다.

우선순위:

1. 서버 Response ID
2. Gemini Turn ID
3. Message ID
4. Conversation Turn Sequence
5. 프로젝트의 기존 Assistant Message ID

안정적인 ID가 없는 경우에만 Session ID, Turn Index 및 정규화된 본문을 이용한 보조 중복 방지를 검토한다.

본문 문자열 비교만으로 서로 다른 정상 발화를 과도하게 제거하지 않는다.

---

# 11. 스트리밍 상태 전환 기준

다음 흐름을 보장한다.

```text
케이 Turn 시작
→ activeKUtterance 생성
→ Partial Chunk는 activeKUtterance만 갱신
→ 1번에 실시간 표시
→ Turn 완료 이벤트
→ 동일 Turn ID로 한 번만 Finalize
→ finalizedKUtterances 최근 목록에 추가
→ activeKUtterance 제거
```

다음을 방지한다.

- Chunk마다 타임라인이 한 칸씩 밀림
- 첫 글자만 별도 발화로 기록됨
- Partial과 Final이 각각 별도 발화로 기록됨
- TTS 종료 이벤트와 Transcript 완료 이벤트가 각각 추가됨
- React Strict Mode로 동일 발화가 두 번 추가됨
- WebSocket 재연결 후 최근 문장이 중복 복원됨

---

# 12. Barge-in 및 중단 발화

아이의 끼어들기로 케이 발화가 중단된 경우 실제 사용자에게 출력된 범위를 기준으로 처리한다.

원칙:

- 사용자가 실제로 들은 케이 발화 Transcript가 확보되면 해당 범위를 최근 발화로 유지
- 사용자에게 전혀 출력되지 않은 생성 초안은 최근 발화에 추가하지 않음
- 중단된 Turn을 Final Transcript와 Partial Transcript로 중복 추가하지 않음
- Barge-in이 발생해도 아이 발화는 1·2·3 영역에 표시하지 않음

현재 시스템에서 출력된 범위를 정확히 판정할 수 없다면 기존 사용자 노출 Transcript Source of Truth를 사용하고, 임의로 전체 생성 문장을 표시하지 않는다.

# 14. 세션 복원 및 이어하기

미션 이어하기와 자유대화 세션 복원 시 최근 케이 발화 타임라인을 복원한다.

## 우선 원칙

기존 저장된 대화 기록에서 케이 발화만 필터링하고 시간순으로 정렬한 뒤 최근 3개를 사용한다.

예시 개념:

```text
conversationHistory
→ role=assistant 또는 speaker=k 필터
→ 사용자에게 실제 노출된 메시지만 필터
→ 시간순 정렬
→ 최근 3개 추출
```

아이 메시지는 복원 과정에서도 화면 타임라인에 포함하지 않는다.

## 신규 세션

복원할 케이 발화가 없으면 빈 상태로 시작한다.

케이의 첫 실제 발화가 시작되면 1번부터 표시한다.

## DB 변경 원칙

기존 대화 이력에서 복원할 수 있다면 신규 컬럼이나 테이블을 추가하지 않는다.

정말 기존 데이터만으로 복원할 수 없는 경우에는 DB 변경 전에 원인과 최소 변경안을 먼저 보고하고, 이번 긴급 Hotfix 범위를 불필요하게 확대하지 않는다.

# 15. 미션·자유대화 공통 구현

미션과 자유대화에 동일한 오류가 있으므로 케이 발화 타임라인 계산을 공통화한다.

권장 구조:

```text
useRecentKUtterances()
KUtteranceTimeline
```

또는 현재 프로젝트 구조에 맞는 공통 Selector·Utility·Component를 사용한다.

권장 입력:

```text
messages
activeAssistantTranscript
activeTurnId
```

권장 출력:

```text
currentKUtterance
previousKUtterance
olderKUtterance
```

화면별로 서로 다른 필터링 규칙을 중복 구현하지 않는다.

단, 이번 긴급 수정 때문에 미션·자유대화 전체 상태 머신을 대규모로 리팩터링하지 않는다.

- 관련 없는 Request 동시 반영
- Dev 검증 없이 Production 직접 배포

Production 배포 전 변경 Diff를 확인하고 Hotfix 범위를 벗어난 수정이 없는지 검토한다.

---

# 19. Dev 배포 절차

1. 현재 Branch와 미커밋 변경 확인
2. 관련 파일만 최소 수정
3. Unit 및 Component Test 추가·수정
4. lint 실행
5. typecheck 실행
6. 관련 test 실행
7. production build 실행
8. Dev 프로젝트 배포
9. Dev Build ID 기록
10. 모바일 PWA에서 업데이트 적용
11. 미션 실제 대화 QA
12. 자유대화 실제 대화 QA
13. 아이 발화 미노출 확인
14. 케이 발화 3단계 순서 확인
15. 중복 발화 없음 확인

Dev QA가 PASS하기 전 Production을 배포하지 않는다.

단, 긴급 Hotfix이므로 Dev PASS 후 불필요한 대기 없이 Production으로 진행한다.

---

# 20. Production 배포 절차

Dev 검증 PASS 후 다음 순서로 진행한다.

1. 배포 대상 Commit 고정
2. Dev에서 검증한 동일 Commit인지 확인
3. Production 프로젝트와 환경변수 대상 확인
4. Production 배포
5. Production Deployment ID 및 Build ID 기록
6. Production Domain 정상 연결 확인
7. 기존 모바일 PWA 실행
8. 새 버전 업데이트 안내 확인
9. 사용자 승인 후 최신 Build 적용
10. Production 미션 Smoke Test
11. Production 자유대화 Smoke Test
12. 아이 발화 미노출 확인
13. 케이 발화 순서 확인
14. 음성·저장·진행률·보상 회귀 없음 확인

Dev와 다른 코드를 Production에 별도로 수정하여 배포하지 않는다.

---

# 21. PWA 업데이트 검증

이번 수정은 모바일 PWA에 반드시 반영되어야 한다.

QA 절차:

1. 이전 Build가 설치된 모바일 PWA 준비
2. 새 Dev 또는 Production Build 배포
3. PWA 삭제 금지
4. 사이트 데이터 수동 삭제 금지
5. PWA 실행 또는 Foreground 복귀
6. 업데이트 안내 표시 확인
7. 새로고침 선택
8. Active Service Worker 변경 확인
9. App Build ID 변경 확인
10. 최신 케이 발화 타임라인 확인

PWA를 삭제·재설치해야만 수정 화면이 나오면 배포 완료가 아니다.

---

# 22. 롤백 기준

다음 중 하나가 발생하면 Production 배포를 중단하거나 즉시 이전 정상 Deployment로 롤백한다.

- 케이 발화가 화면에 전혀 표시되지 않음
- 동일 케이 발화가 중복 표시됨
- 타임라인 순서가 뒤바뀜
- 미션 진행률이 증가하지 않음
- 아이 답변이 서버에 저장되지 않음
- 자유대화 응답이 멈춤
- TTS가 출력되지 않음
- WebSocket 재연결 실패 증가
- 미션 완료 또는 보상 처리 오류
- Production Build 오류
- 모바일 PWA가 무한 Reload
- 신규 치명적 오류 발생

롤백 시 데이터 롤백이나 DB 복구가 필요하지 않도록 코드 Hotfix 범위로 유지한다.

# 23. QA 시나리오

## 미션 — 첫 케이 발화

1. 신규 미션 시작
2. 케이 첫 질문 출력
3. 1번에 첫 케이 발화 표시
4. 2번·3번 미표시
5. 아이가 답변
6. 아이 발화 화면 미표시
7. 내부 답변 저장 정상

## 미션 — 케이 발화 2개

1. 두 번째 케이 발화 출력
2. 1번에 두 번째 발화
3. 2번에 첫 번째 발화
4. 3번 미표시
5. 아이 발화 없음

## 미션 — 케이 발화 3개 이상

1. 세 번째 케이 발화 출력
2. 1번에 세 번째 발화
3. 2번에 두 번째 발화
4. 3번에 첫 번째 발화
5. 네 번째 발화 시 각각 한 단계 이동
6. 아이 발화 없음

## 자유대화

미션과 동일하게 다음을 확인한다.

- 첫 케이 발화
- 두 번째 케이 발화
- 세 번째 케이 발화
- 네 번째 이후 이동
- 아이 음성 발화 미표시
- 아이 텍스트 입력 미표시
- 케이 응답 정상
- 대화 저장 정상

## 스트리밍

- Partial Chunk 5회 이상
- 1번만 점진적으로 갱신
- 2번·3번 이동 없음
- Final 완료 시 한 번만 확정
- 중복 없음

## 재질문

예시:

```text
케이: 다시 한 번 말해줄래?
아이: 방금 뭐라고 했냐면...
케이: 아하, 그런 이야기였구나.
```

표시:

```text
1번: 아하, 그런 이야기였구나.
2번: 다시 한 번 말해줄래?
3번: 그 이전 케이 발화
```

아이의 `방금 뭐라고 했냐면...`은 화면에 표시하지 않는다.

## Barge-in

- 케이 발화 중 아이가 끼어듦
- 중단된 케이 발화 중복 없음
- 아이 발화 미표시
- 다음 케이 발화 정상 이동

## 이어하기·복원

- 미션 3개 이상 케이 발화 후 종료
- 다시 진입
- 이어하기 전·후 최근 케이 발화 복원
- 아이 발화가 3번에 섞이지 않음
- 순서 유지

## 재연결

- 네트워크 일시 끊김
- WebSocket 재연결
- 최근 발화 중복 추가 없음
- 기술 상태가 타임라인에 표시되지 않음

# 25. 자동화 테스트

가능한 범위에서 다음 테스트를 추가한다.

## Selector 또는 Utility Test

입력:

```text
assistant A
user 1
assistant B
user 2
assistant C
```

출력:

```text
current = assistant C
previous = assistant B
older = assistant A
```

## Partial Test

입력:

```text
assistant A finalized
assistant B partial 1
assistant B partial 2
assistant B final
```

검증:

- B가 한 번만 추가
- Partial마다 A가 여러 칸 밀리지 않음

## 중복 이벤트

동일 Turn ID의 Final 이벤트를 두 번 전달한다.

검증:

- 한 번만 기록

## 복원

- 케이 발화 0개
- 1개
- 2개
- 3개
- 4개 이상

# 26. 완료 기준

다음 조건을 모두 만족해야 완료로 판정한다.

- 미션 1·2·3 영역이 모두 케이 발화만 표시함
- 자유대화 1·2·3 영역이 모두 케이 발화만 표시함
- 아이 음성 발화가 화면에 표시되지 않음

- 아이 발화는 내부 문맥·저장·리포트에 유지됨

- 동일 Turn이 중복 표시되지 않음
- Barge-in 후 중복이 없음
- 세션 복원 후 순서가 유지됨
- 미션과 자유대화가 같은 필터링 규칙을 사용함
- 미션 진행률·완료·황금열쇠 로직에 회귀가 없음
- 자유대화 음성·텍스트·저장 로직에 회귀가 없음
- Dev 배포 및 실제 모바일 PWA QA 통과
- Dev와 동일 Commit의 Production 배포 완료
- Production 모바일 PWA Smoke Test 통과
- PWA 삭제·재설치 없이 최신 Build 적용 성공
- lint 통과
- typecheck 통과
- 관련 test 통과
- production build 통과
