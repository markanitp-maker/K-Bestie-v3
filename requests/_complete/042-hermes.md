현재 Claude/agy/codex 작업이 멈추거나 하위 작업자가 실패해도 김비서 Discord 보고가 누락되는 문제가 있다.

“Claude가 알아서 보고하라”는 프롬프트 규칙만으로는 해결되지 않는다.
보고 책임을 Claude 밖의 상시 감시 프로세스로 분리하는 로컬 감시·알림 시스템을 구현해.

목표:
- Claude Code, agy, codex, claude-review 작업이 시작·완료·실패·무응답 상태가 되면 상태를 기계적으로 판정한다.
- Claude가 멈추거나 보고 명령을 빼먹어도, 감시기가 직접 김비서 Discord에 알린다.
- 정상 완료 후 일정 시간 안에 보고 확인 기록이 없으면 감시기가 누락 완료 보고를 대신 보낸다.
- 같은 사건은 중복 발송하지 않는다.
- 사람에게 보내는 Discord 본문은 자연스러운 한국어만 사용한다.

먼저 기존 `resilient-coding-agent` 스킬과 `monitor.sh`, 현재 CLAUDE.md §14 규칙을 읽고 재사용 가능한 부분을 확인해.
그 뒤 아래 범위 안에서 최소 구현한다.

필수 구조:
1. 작업 레지스트리
- 작업 ID, 프로젝트명, 작업 종류(agy/codex/claude-review), tmux 세션명, 시작 시각, 로그 경로, 재시도 횟수, 현재 상태를 기록한다.
- 비밀값·프롬프트 전문·사용자 데이터는 기록하지 않는다.

2. 상시 감시기
- Claude Code 본체와 별개 프로세스로 실행돼야 한다.
- 1분 주기로 tmux 세션 생존 여부, 로그 변화, `__TASK_DONE__` 마커, 종료 코드, 마지막 활동 시각을 확인한다.
- 다음 이벤트를 판정한다.
  - 작업 시작
  - 정상 완료
  - 실패·크래시
  - 정해진 시간 이상 무응답
  - 재시도 한도 초과
  - 완료됐지만 보고 확인이 없는 누락 상태

3. Discord 알림
- 아래 Hermes 명령으로만 김비서에게 직접 보낸다.
  `/mnt/c/Users/Home/AppData/Local/Programs/Python/Python313/Scripts/hermes.exe -p secretary send --to discord:1517194137604980866`
- 전송 결과에 `sent`가 있는지 확인한 뒤에만 해당 사건을 “보고 완료”로 기록한다.
- 전송 실패 시 한 번 재시도하고, 그래도 실패하면 로컬 상태에 남겨 다음 감시 주기에 재시도한다.
- 동일 작업·동일 사건은 한 번만 보낸다.

알림 본문 예시:
대표님, [K-Bestie-v3] 작업 상태: 중단

✅ 확인된 상태
- agy QA 작업이 3회 연속 실패했습니다.

🟡 다음 조치
- 자동 재시도 한도를 초과해 메인 Claude 판단이 필요합니다.

👤 대표님 확인
- 없음

4. 완료 보고 보정
- 작업자가 정상 보고를 보냈으면 레지스트리에 확인 처리할 수 있어야 한다.
- 작업이 끝난 뒤 90초 안에 확인 처리가 없으면 감시기가 “완료됐으나 작업자 보고가 누락됨”이라고 대신 보고한다.
- 감시기는 작업 결과를 지어내지 말고, 확인 가능한 상태만 알린다.

5. 안전 제약
- K-Bestie 앱 코드·DB·Vercel·Supabase·환경변수·실계정 데이터는 건드리지 않는다.
- 새 감시 도구는 프로젝트의`.claude/ops/` 또는 별도 로컬 도구 폴더에만 둔다.
- Windows 작업 스케줄러·서비스 등록·부팅 자동실행은 아직 하지 않는다. 먼저 현재 세션에서 수동 실행 가능한 PoC를 만든다.
- 자동 재시작은 기존 CLAUDE.md 규칙 범위 안에서만 하고, 배포·DB·외부 발송은 자동 수행하지 않는다.

검증:

  2) 일정 시간 출력이 멈추는 작업

- 테스트 종료 후 가짜 tmux 작업은 전부 정리한다.
