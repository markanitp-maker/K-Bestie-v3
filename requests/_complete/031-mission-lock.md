Production 미션 시간제·완료 잠금·황금 열쇠 자동 지급

## 1. 작업 목표

Production에만 다음 미션 운영 정책을 적용한다.

- 미션-I과 미션-II를 정해진 시간에만 이용할 수 있게 한다.
- 완료한 미션은 같은 시간대에 다시 진행할 수 없게 한다.
- 미션 완료 즉시 황금 열쇠를 자동으로 한 번만 지급한다.
- 완료 화면에서 기존 `다시 진행하기`, `미션 나가기`, `받기` 버튼을 제거한다.
- 개발 서버의 기존 동작은 변경하지 않는다.
- 부모 화면과 부모 기능은 작업 범위에 포함하지 않는다.

## 2. 작업 저장소

- 작업 대상: `E:\VibeCoding\kbestie-clean-handoff`
- 원본 보존 대상: `E:\VibeCoding\K-Bestie-v3`

- 기존 사용자 변경과 무관한 파일은 커밋하지 않는다.

## 3. 미션 운영 시간

모든 시간 판정은 서버가 계산한 한국시간(KST, Asia/Seoul)을 기준으로 한다.

| 구분 | 이용 가능 시간 |
|---|---|
| 미션-I | 매일 12:00 이상~17:00 미만 |
| 미션-II | 매일 19:00 이상~23:00 미만 |

경계값은 다음과 같이 처리한다.

- 12:00:00부터 미션-I 이용 가능
- 17:00:00부터 미션-I 이용 불가
- 19:00:00부터 미션-II 이용 가능
- 23:00:00부터 미션-II 이용 불가
- 00:00~11:59:59, 17:00~18:59:59, 23:00~23:59:59에는 미션 이용 불가
- 브라우저 시간이나 클라이언트가 전달한 시간은 권한 판정에 사용하지 않는다.

## 4. 화면 상태와 문구

현재 시간과 완료·진행 상태에 따라 다음 문구를 표시한다.

### 미션-I 시간

- 시작 가능: `미션-I 진행 가능`
- 진행 중: `미션-I 진행 중`
- 이미 완료: `미션을 이미 완료하였습니다. 다음 미션을 기다리세요.`

### 미션-II 시간

- 시작 가능: `미션-II 진행 가능`
- 진행 중: `미션-II 진행 중`
- 이미 완료: `미션을 이미 완료하였습니다. 다음 미션을 기다리세요.`

### 미션 시간 외

- `미션 시간이 아닙니다.`

현재 시간대에 해당하지 않는 미션을 URL 직접 접근, 새로고침, API 직접 호출, 과거 localStorage 값으로 시작하거나 재개할 수 없어야 한다.

## 5. 완료 및 재도전 정책

- 미션-I을 완료하면 같은 날 미션-I은 다시 진행할 수 없다.
- 다음 이용 가능 미션은 같은 날 19시의 미션-II다.
- 미션-II를 완료하면 같은 날 미션-II는 다시 진행할 수 없다.
- 다음 이용 가능 미션은 다음 날 12시의 미션-I이다.
- 미션을 완료하지 못했더라도 해당 시간대가 종료되면 더 이상 진행하거나 재개할 수 없다.
- 미션-I을 놓치거나 완료하지 못했어도 미션-II 이용 가능 여부에는 영향을 주지 않는다.
- 완료 판정은 아이 ID, KST 날짜, 미션 구분을 기준으로 서버에서 확인한다.
- 새로고침, 뒤로 가기, 다중 탭, 중복 요청으로 완료 상태를 우회할 수 없어야 한다.

## 6. 황금 열쇠 자동 지급

미션 완료가 서버에서 확정되는 순간 황금 열쇠를 자동 지급한다.

필수 조건:

- 아이가 별도의 `받기` 버튼을 누르지 않아도 된다.
- 같은 미션 완료에 대해 황금 열쇠는 정확히 한 번만 지급한다.
- 새로고침·중복 완료 요청·네트워크 재시도로 중복 지급되지 않아야 한다.
- 가능하면 기존 완료 처리와 보상 지급을 하나의 원자적 처리 또는 기존 idempotency 구조로 묶는다.
- 보상 지급 실패 시 완료만 기록되거나 중복 보상이 발생하지 않도록 기존 데이터 구조를 먼저 분석한다.
- DB 스키마나 RLS 변경이 필요하면 임의로 실행하지 말고 변경 이유와 범위를 먼저 보고한다.

## 7. 미션 완료 화면

Production의 완료 화면은 다음 요소만 표시한다.

- 완료 안내
- `황금 열쇠를 받았습니다`
- `닫기` 버튼

다음 요소는 Production 완료 화면에서 제거한다.

- `다시 진행하기`
- `미션 나가기`
- `받기`
- 재도전 선택 팝업
- 추가 보상 수령 단계

`닫기` 버튼을 누르면 아이 홈 화면으로 이동한다.

황금 열쇠는 `닫기`를 누를 때 지급하는 것이 아니라 미션 완료 확정 시점에 이미 자동 지급되어 있어야 한다.

## 8. Production 전용 적용

- 시간 제한, 완료 후 재도전 잠금, 자동 보상, 단순화된 완료 화면은 Production에서만 활성화한다.
- 로컬 개발 서버에서는 기존 미션 운영 방식과 기존 완료 화면을 그대로 유지한다.
- `NODE_ENV=production`만으로 구분하지 않는다. Vercel Preview도 production build이기 때문이다.
- 명시적인 서버 환경변수 또는 기존 환경 설정 체계를 사용해 기능을 분리한다.
- 예시 변수명: `MISSION_SCHEDULE_ENFORCED=true`
- Production에서만 기본 활성화하고 개발 환경에서는 미설정 또는 `false`로 유지한다.
- 클라이언트 UI만 숨기지 말고 미션 시작·재개·완료 API에서도 동일한 정책을 검증한다.
- 환경변수 값이나 비밀값을 소스 코드·Git·로그·채팅에 출력하지 않는다.

## 11. 작업 및 배포 순서

1. 기존 미션 시작·진행·완료·보상 처리 경로를 추적한다.
2. 기존 완료 기록과 황금 열쇠 지급 구조를 확인한다.
3. Production 전용 기능 플래그를 설계한다.
4. 서버 기준 KST 시간 판정과 완료 잠금을 구현한다.
5. 아이 화면 상태 문구와 완료 화면을 수정한다.
6. 자동 보상 중복 방지 검증을 추가한다.
7. 관련 테스트를 작성하고 실행한다.
8. `npx tsc --noEmit`을 실행한다.
9. `npm run build`를 실행한다.
10. 의도한 파일만 커밋하고 작업 브랜치에 push한다.
11. Vercel Preview에 배포한다.
12. Preview에서 로그인부터 완료 화면까지 직접 브라우저 QA를 수행한다.
13. 실패 시 무한 재배포하지 말고 최초 실패 원인을 확인해 수정한다.
14. 모든 검수가 PASS하면 결과와 커밋 SHA, Preview URL, 테스트 결과를 보고한다.
15. 최종 보고 문구를 `Preview 검수 완료, Production으로 배포할까요?`로 끝내고 승인을 기다린다.
16. 대표님의 명시적 승인 전에는 Production 배포를 실행하지 않는다.
17. 승인 후 Production 배포와 최소 스모크 테스트를 수행하고 결과를 보고한다.
