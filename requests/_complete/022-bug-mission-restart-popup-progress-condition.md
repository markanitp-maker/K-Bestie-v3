# BUG: 미션 재시작 팝업이 진행 중(0~9/10) 상태에서도 노출됨

- 상태: TODO
- 유형: BUG FIX
- 우선순위: HIGH
- 대상: 자녀 미션 대화 화면(`app/child/missions/page.tsx`)

## 배경

`requests/020-bug-child-profile-name-empty.md` 끝에 헤더 구분 없이 붙어 있던 문단을
대표님 지시로 분리해 별도 버그로 등록한다(2026-07-27). 원본 문단:

> 미션 재시작 팝업 노출 조건을 수정하라. 현재 0/10 진행 중인 미션 시작 상태에서도
> "다시 한번 해볼까?" 팝업이 표시되는 버그가 있다. 팝업은 미션 진행 중/중단
> 상태에서는 절대 표시하지 않는다. 표시 조건은 해당 아이의 미션이 실제 완료
> 상태(10/10, completed_at 존재)인 경우에만 다음 미션 재진입 시 노출하도록
> 변경한다. 미완료 세션(0~9/10)은 기존 이어하기 또는 정상 진행 흐름을 유지한다.

## 문제 현상

미션 진행률이 0~9/10인 상태(아직 완료되지 않은 미션)에서도 "다시 한번 해볼까?" 류의
재시작 확인 팝업이 표시된다.

## 정상 동작(완료 조건)

- 미션 진행률 0~9/10(진행 중/중단 상태): 재시작 팝업 절대 표시 안 함. 기존
  이어하기 또는 정상 진행 흐름 그대로 유지.
- 미션 완료 상태(10/10, `completed_at` 존재)에서 다음 미션 재진입 시에만 재시작
  확인 팝업 노출.
- UI 변경이 아니라 미션 진행 상태(state) 조건 로직만 수정한다.
- 회귀 테스트 진행(기존 이어하기/진행 흐름에 영향 없어야 함).

## 조사 메모 및 대표님 확정 방향 (2026-07-27)

- 코드베이스 전체(`app/`, `components/`)에서 "다시 한번 해볼까", "재시작 팝업" 등을
  검색한 결과, 정확히 일치하는 문구는 `app/child/missions/page.tsx`의
  `showRetryButton` 오버레이("다시 한번 해볼까?") 단 하나였다. 이 오버레이는
  진행률과 무관하게 같은 턴에서 STT 전사가 연속 2회 실패했을 때만 뜨는 에러 복구
  UI다(011 지시서에서 의도적으로 도입, 진행률 기반이 아니라 STT 실패 기반).
- 대표님 확정: "0/10에서도 뜬다"는 관찰은 이 STT 에러복구 기능이 설계대로 동작한
  것(첫 답변을 두 번 못 알아들은 경우)일 가능성이 높다는 점을 확인 후, **두 가지로
  분리해 처리**하기로 확정.
  1. STT 에러복구 팝업(`showRetryButton`)은 그대로 유지하되, 문구를
     "다시 한번 해볼까?" → **"케이랑 접속이 끊겼네?"** 로 변경(미션 재시작 의미로
     오해되지 않도록). 버튼은 "다시 시도"/"미션 나가기" 그대로 유지, "다시 시도"는
     현재 세션·진행 상태를 유지한 채 음성 입력만 재연결한다.
  2. "미션 완료(10/10) 후 같은 라운드에 재진입 시에만 재시작 확인 팝업 노출"은
     지금까지 코드에 아예 없던 별도 신규 기능으로 확정 — 새로 구현한다. 미완료
     세션(0~9/10)에는 어떤 팝업도 추가하지 않고 기존 이어하기/진행 흐름을 그대로
     유지한다.
  두 로직은 서로 완전히 분리되어야 한다(대표님 명시 지시).

## 구현 완료 내역(2026-07-27)

1. `app/child/missions/page.tsx`: `showRetryButton` 오버레이 문구를
   "케이랑 접속이 끊겼네?"로 변경(버튼 라벨/동작 변경 없음).
2. `app/api/mission/start/route.ts`: 오늘 이미 COMPLETED인 라운드에
   `confirmRestart:true` 없이 재진입하면 새 세션을 만들지 않고
   `{ requiresConfirmation: true, alreadyCompletedToday: true, roundType }`만
   반환하고 즉시 종료. 진행 중(IN_PROGRESS)/미완료 세션 분기는 전혀 변경하지 않음.
3. `app/child/missions/page.tsx`: 새 phase `confirm_restart_after_completion`
   추가 — 서버가 `requiresConfirmation`을 반환하면 이 phase로 멈추고 "오늘 미션은
   이미 완료했어요!" + "다시 할래요"/"미션 나가기" 확인 UI를 보여준다. "다시
   할래요"는 `confirmRestartRef`(한 번만 소비되는 ref)를 true로 설정하고
   `restartTrigger` state를 증가시켜 같은 초기화 `useEffect`를 재실행,
   `confirmRestart:true`로 재요청해 새 세션을 만든다. URL 쿼리 대신 ref+state
   조합을 쓴 이유: URL에 남기면 이후 재진입 때도 계속 true로 남아 두 번째부터
   확인을 건너뛰는 버그가 생기기 때문.

## 검증 시나리오

1. 미션 신규 시작(0/10) → 재시작 팝업 미노출 확인.
2. 미션 진행 중(1~9/10, 앱 재진입 포함) → 재시작 팝업 미노출, 정상 이어하기 확인.
3. 미션 완료(10/10, completed_at 존재) 후 다음 미션 재진입 → 재시작 확인 팝업 노출 확인.
4. 기존 에러 복구 오버레이(`showRetryButton`)가 있다면 이번 수정으로 오작동/회귀가
   없는지 별도 확인.
