# 035 — 미션 완료 후 황금열쇠 보상 확인 화면 추가

## 1. 작업 목적

아이 미션이 정상적으로 완료되고 황금열쇠 지급까지 성공하면, 현재 미션 대화 화면 위에 별도의 황금열쇠 보상 확인 화면을 표시한다.

보상 화면에는 다음 요소를 제공한다.

- 우측 상단 닫기 `X` 버튼
- 황금열쇠 공식 아이콘 또는 이미지
- `황금열쇠 +1` 보상 문구
- 하단 `닫기` 버튼

사용자는 우측 상단 `X` 또는 하단 `닫기` 버튼을 눌러 미션 화면을 종료하고 아이 홈으로 돌아갈 수 있어야 한다.

---

# 2. 기존 완료 UX와의 관계

기존 결정에 따라 다음과 같은 상단 중복 완료 배너는 다시 추가하지 않는다.

```text
오늘의 미션을 완료했어요!
```

```text
오늘의 미션을 모두 완료했어!
황금열쇠를 받았어. 내일 또 만나자!
```

미션 완료 안내는 다음 두 단계로만 구성한다.

1. 케이의 마지막 인사 말풍선과 음성
2. 황금열쇠 보상 확인 화면

상단 진행률 아래에 별도의 완료 제목이나 긴 안내 문구를 추가하지 않는다.

---

# 3. 최종 완료 흐름

미션 완료 시 다음 순서로 처리한다.

1. 10번째 유효 답변 저장 성공
2. 유효 답변 수 10/10 확인
3. 미션 완료 상태 저장
4. 황금열쇠 지급 Transaction 실행
5. 황금열쇠 지급 성공 확인
6. 케이 마지막 인사 말풍선 표시
7. 케이 마지막 인사 음성 출력
8. 마지막 음성 재생 종료
9. 황금열쇠 보상 확인 화면 표시
10. 사용자가 `X` 또는 `닫기` 선택
11. 미션 세션 정리
12. 아이 홈 화면으로 이동
13. 아이 홈의 황금열쇠 수량 최신값 갱신

황금열쇠 지급 성공을 확인하기 전에 보상 화면을 먼저 보여주면 안 된다.

---

# 4. 케이 마지막 인사

황금열쇠 지급이 정상 완료된 경우 기존 현재 질문 말풍선 영역에 다음 문구를 한 번만 표시한다.

```text
오늘 미션을 모두 완료했어! 황금열쇠를 받았어. 다음에 또 보자!
```

케이는 같은 문구를 한 번만 음성으로 출력한다.

다음을 방지한다.

- 동일 문구 중복 표시
- TTS 중복 재생
- 재렌더링으로 인한 반복 재생
- 보상 화면과 완료 문구 동시 중복 출력

보상 확인 화면은 최종 음성 출력이 끝난 뒤 표시한다.

---

# 5. 황금열쇠 보상 화면 구조

```text
┌──────────────────────────────┐
│                          [X] │
│                              │
│       [황금열쇠 이미지]       │
│                              │
│        황금열쇠 +1            │
│                              │
│       미션을 완료했어요        │
│                              │
│          [닫기]               │
└──────────────────────────────┘
```

`미션을 완료했어요` 보조 문구는 카드 내부에서 짧게 사용할 수 있으나 필수는 아니다.

핵심 정보는 반드시 다음 두 가지다.

```text
황금열쇠 아이콘
황금열쇠 +1
```

---

# 6. 표시 방식

## 권장 방식

미션 화면 위에 중앙 보상 Modal 또는 전체 화면 Overlay로 표시한다.

- 배경에 반투명 Overlay 적용
- 뒤쪽 미션 화면의 입력 기능 차단
- 화면 중앙에 보상 카드 배치
- 모바일 safe-area 반영
- 태블릿·PC에서는 카드 최대 너비 제한
- 스마트폰 외곽 프레임은 구현하지 않음

## 금지

- 브라우저 기본 `alert()` 사용
- Toast만 잠깐 표시하고 종료
- 화면 최상단에 작은 배너로 표시
- 황금열쇠 아이콘 없이 텍스트만 표시
- 보상 카드 뒤에서 음성 입력이 계속되는 상태
- 자동으로 너무 빨리 닫혀 아이가 보상을 확인하지 못하는 UX

---

# 7. 보상 카드 디자인

## 카드

- 흰색 또는 따뜻한 아이보리 배경
- 둥근 모서리 `20px~28px`
- 약한 그림자
- 화면 좌우 여백 최소 `24px`
- 모바일 최대 너비 약 `320px~360px`
- 내부 요소 가운데 정렬

## 배경 Overlay

- K-Navy 또는 검정 기반의 낮은 투명도
- 뒤쪽 화면이 보이되 주요 조작은 불가능하게 처리
- Overlay 클릭으로 닫을지는 기존 Modal 정책을 따른다.
- 아이가 실수로 닫는 것을 막기 위해 기본값은 Overlay 클릭 닫기 비활성 권장

---

# 8. 황금열쇠 이미지

프로젝트에 존재하는 공식 황금열쇠 자산을 사용한다.

## 기준

- 레퍼런스 이미지를 잘라서 사용하지 않음
- 임시 Emoji만으로 대체하지 않음
- 공식 황금열쇠 PNG, SVG 또는 기존 Reward 컴포넌트 우선 사용
- 비율 왜곡 금지
- 임의 색상 변경 금지
- `object-fit: contain`

## 권장 크기

```text
80px~120px
```

작은 화면에서는 `clamp()`로 축소한다.

## 애니메이션

보상 화면 최초 표시 시 다음 정도의 가벼운 애니메이션을 적용할 수 있다.

- 황금열쇠가 0.85배에서 1배로 확대
- `+1`이 아래에서 부드럽게 등장
- 전체 애니메이션 약 250~400ms

과도한 회전, 반복 점멸, 긴 애니메이션은 사용하지 않는다.

`prefers-reduced-motion`에서는 애니메이션을 제거하거나 최소화한다.

---

# 9. 보상 문구

메인 문구:

```text
황금열쇠 +1
```

또는 디자인 구조상 다음처럼 분리할 수 있다.

```text
황금열쇠
+1
```

## 스타일

- K-Navy 제목
- `+1`은 K-Orange 또는 K-Mascot Orange
- 굵기 `700~800`
- 숫자가 명확하게 보이도록 크게 표시
- 색상뿐 아니라 `+1` 텍스트로 실제 지급 수량 표현

## 보조 문구

선택적으로 다음 문구를 표시할 수 있다.

```text
미션을 완료했어요!
```

또는:

```text
열쇠가 보관함에 추가되었어요.
```

한 카드 안에 긴 완료 설명을 반복하지 않는다.

---

# 10. 우측 상단 닫기 버튼

## 아이콘

- `X` 닫기 아이콘
- 텍스트 `Logout` 또는 다른 아이콘 사용 금지

## 디자인

- 카드 우측 상단
- 최소 터치 영역 `44x44px`
- K-Navy 또는 진한 Neutral 아이콘
- 원형 투명 또는 연한 Neutral 배경
- `aria-label="보상 화면 닫기"`

## 동작

클릭 시:

1. 중복 클릭 차단
2. 완료 세션 종료 처리
3. 필요한 Local Audio 및 입력 Gate 정리
4. 아이 홈으로 이동
5. 황금열쇠 보유량 재조회 또는 Cache 갱신

---

# 11. 하단 닫기 버튼

## 문구

```text
닫기
```

## 디자인

- 카드 하단 중앙
- K-Navy 배경
- 흰색 텍스트
- Pill 또는 둥근 사각형
- 최소 높이 `48px`
- 최소 너비 약 `140px`
- 굵기 `600~700`
- 최소 터치 영역 충족

## 동작

우측 상단 `X` 버튼과 완전히 동일한 종료 함수를 사용한다.

두 버튼이 서로 다른 경로로 이동하거나 서로 다른 세션 정리 로직을 사용하면 안 된다.

권장:

```text
handleCloseRewardCompletion()
```

하나의 공통 Handler를 사용한다.

---

# 12. 닫기 후 이동 위치

기본 이동 위치:

```text
아이 홈 화면
```

아이 홈으로 돌아오면 다음이 최신 상태로 보여야 한다.

- 황금열쇠 기존 수량 +1
- 미션 완료 상태
- 미션 카드 완료 또는 다음 가능 상태
- 현재 진행 중 세션 없음

브라우저 History Back만 사용해 이전 미션 상태가 그대로 보이는 문제가 발생하지 않도록 한다.

기존 아이 홈 Route와 완료 후 이동 정책을 확인해 명시적인 Route 이동을 우선 검토한다.

---

# 13. 완료 상태 입력 차단

미션 완료가 확정되는 즉시 다음을 차단한다.

- 자동 VAD 입력
- 수동 마이크 입력
- 키보드 입력
- 텍스트 제출
- 자동·수동 모드 변경
- 다음 질문 생성
- 추가 답변 저장

보상 화면이 열린 상태에서는 다음 UI가 동작하지 않아야 한다.

- 뒤쪽 마이크 버튼
- 키보드 버튼
- 소리 버튼
- 자동·수동 버튼
- 문의 버튼을 제외한 미션 입력 기능

문의 버튼도 Overlay 아래에서 클릭되지 않도록 한다.

---

# 14. 마이크 완료 상태

미션 완료 후 보상 화면이 나오기 전까지 마이크는 회색 비활성 상태를 유지한다.

## 상태

- 배경 Neutral Gray
- 마이크 차단 아이콘
- Pulse 없음
- 클릭 불가
- 음성 프레임 전송 차단

보상 화면이 열린 뒤에는 뒤쪽 마이크가 보이더라도 실제로 조작할 수 없어야 한다.

---

# 15. 황금열쇠 지급 실패 또는 지연

황금열쇠 지급이 확인되지 않은 경우 `황금열쇠 +1` 화면을 표시하지 않는다.

## 지급 처리 중

다음과 같은 별도의 중립 상태를 사용할 수 있다.

```text
황금열쇠를 확인하고 있어요.
```

- 마이크 및 모든 입력 차단 유지
- 중복 Reward 요청 금지
- 기존 Retry 또는 Transaction 확인 로직 사용

## 지급 실패

```text
미션은 완료했어요.
황금열쇠 지급을 확인하지 못했어요.
잠시 후 다시 확인해 주세요.
```

이 경우 다음 버튼을 제공할 수 있다.

```text
닫기
```

하지만 카드에는 다음을 표시하지 않는다.

```text
황금열쇠 +1
```

운영 복구 또는 기존 보상 재시도 정책에 따라 처리한다.

---

# 16. 중복 지급 방지

다음 상황에서도 황금열쇠는 한 번만 지급되어야 한다.

- 닫기 버튼 연속 클릭
- X 버튼과 하단 닫기 버튼을 빠르게 연속 클릭
- 완료 화면 재렌더링
- 네트워크 재연결
- 브라우저 Background 후 복귀
- 완료된 미션 화면 새로고침
- 완료 화면 재진입
- TTS 종료 이벤트 중복 발생

보상 Transaction의 Idempotency와 기존 중복 방지 키를 유지한다.

UI 상태만으로 중복 지급을 방지하지 않는다.

---

# 17. 보상 화면 중복 표시 방지

동일 미션 세션에서 보상 화면은 한 번만 표시한다.

필요한 상태 예시:

```text
isMissionCompleted
isRewardConfirmed
hasShownCompletionMessage
hasPlayedCompletionTts
isRewardModalOpen
hasClosedRewardModal
```

실제 프로젝트 상태 구조에 맞춰 최소한으로 구현한다.

다음 문제를 방지한다.

- 최종 TTS가 끝날 때마다 보상 화면 재표시
- 상태 변경마다 Modal이 닫혔다 다시 열림
- 아이 홈에서 뒤로가기로 돌아왔을 때 다시 표시
- 화면 복원 시 이미 확인한 보상 카드 재표시

# 18. 접근성

## 보상 Modal

- `role="dialog"`
- `aria-modal="true"`
- 제목 연결
- 설명 연결
- Focus Trap 적용
- 최초 Focus는 하단 `닫기` 버튼 또는 닫기 `X`
- ESC 동작은 기존 Modal 정책에 맞춰 지원
- Screen Reader에 `황금열쇠 1개를 받았습니다`를 한 번만 전달

## 황금열쇠 이미지

이미지가 장식이 아니라 보상 의미를 가지므로 적절한 대체 텍스트를 제공한다.

```text
황금열쇠 보상
```

## 숫자

Screen Reader에서 `플러스 원`이 아니라 다음 의미로 전달되도록 접근성 이름을 제공한다.

```text
황금열쇠 1개 획득
```
