# REQUEST 025 — 일일 리포트 모달 날짜 표시 오류 수정

## 1. 작업 목적

부모 일일 리포트 목록에서 특정 날짜의 리포트 카드를 클릭했을 때, 상세 모달 제목에 클릭한 날짜가 아닌 다음 날 날짜가 표시되는 오류를 수정한다.

현재 재현 사례:

```text
8월 5일 리포트 카드 클릭
→ 상세 모달 제목: 8월 6일 일간 리포트
```

정상 동작:

```text
8월 5일 리포트 카드 클릭
→ 상세 모달 제목: 8월 5일 일간 리포트
```

## 2. 확정 기준

일일 리포트 상세 모달의 날짜는 사용자가 클릭한 `report_id`의 `business_date`를 기준으로 표시한다.

다음 값은 모달 제목 기준으로 사용하지 않는다.

- `created_at`
- `updated_at`
- 리포트 생성 시각
- 현재 날짜
- 브라우저 로컬 날짜
- UTC 변환 후 계산한 날짜
- 최신 리포트 날짜

## 3. 현재 의심 원인

다음 방식 때문에 날짜가 하루 증가했을 가능성을 우선 점검한다.

```ts
new Date("2026-08-05")
```

`YYYY-MM-DD` 문자열을 JavaScript `Date` 객체로 직접 변환하면 UTC 기준으로 해석된 뒤 Asia/Seoul 변환 과정에서 날짜 오프셋 문제가 발생할 수 있다.

다음 가능성도 함께 확인한다.

- `created_at`을 KST로 변환해 제목에 사용
- 클릭한 카드의 `business_date` 대신 최신 리포트 날짜 사용
- 모달 상태에 이전 또는 다음 리포트 날짜가 남음
- 목록 카드와 상세 API의 `report_id` 불일치
- 달력 선택과 목록 카드 클릭이 서로 다른 날짜 변환 함수를 사용
- 캐시 키가 날짜만 사용되어 다른 리포트 응답이 재사용됨

## 4. 적용 범위

다음 모든 일일 리포트 진입 경로에 적용한다.

- 일일 리포트 목록 카드 클릭
- 지난 이력보기 달력 날짜 클릭
- 빠른 요약 탭
- 상세 보기 탭
- 추천 가이드 탭
- 모바일 Safari
- iOS PWA
- Android Chrome
- 태블릿 화면

세 개 탭을 전환해도 모달 제목의 날짜가 바뀌면 안 된다.

## 5. 데이터 흐름 점검

다음 경로를 순서대로 추적한다.

```text
리포트 목록 카드
→ 선택한 report_id
→ 선택한 business_date
→ 상세 모달 상태
→ 상세 API 요청
→ API 응답 business_date
→ 모달 제목 표시
```

각 단계에서 동일한 날짜가 유지되는지 확인한다.

필수 검증값:

- 클릭한 카드의 `report_id`
- 클릭한 카드의 `business_date`
- 상세 API가 반환한 `report_id`
- 상세 API가 반환한 `business_date`
- 모달이 사용한 날짜 값
- 화면에 표시된 제목

## 6. 날짜 처리 원칙

`business_date`가 `YYYY-MM-DD` 형식이면 날짜 계산 없이 문자열 기준으로 표시한다.

권장 방식:

```ts
function formatBusinessDate(date: string): string {
  const [year, month, day] = date.split("-").map(Number);

  if (!year || !month || !day) {
    return "";
  }

  return `${month}월 ${day}일`;
}
```

다음 방식은 사용하지 않는다.

```ts
new Date(businessDate)
```

```ts
new Date(`${businessDate}T00:00:00Z`)
```

```ts
toLocaleDateString()
```

단순 표시 목적에서는 타임존 변환이 필요 없다.

## 7. 모달 제목

일일 리포트 모달 제목은 다음 형식으로 표시한다.

```text
M월 D일 일간 리포트
```

예:

```text
8월 5일 일간 리포트
```

기존 화면 용어가 `일일 리포트`로 통일되어 있다면 프로젝트 전체 표기 기준을 먼저 확인한다. 이번 작업에서는 날짜 오류를 우선 수정하되 같은 화면 안에서 `일일`과 `일간`이 혼용되지 않도록 기존 확정 표기를 따른다.

## 8. report_id 기준 조회

모달은 반드시 사용자가 선택한 카드의 `report_id`를 기준으로 연다.

```ts
openReportModal({
  reportType: "daily",
  reportId,
  childId,
  businessDate
});
```

상세 API에서도 다음을 검증한다.

- 요청한 `report_id` 존재
- 요청한 리포트의 `child_id`가 현재 선택 아이와 일치
- `report_type = daily`
- API 응답의 `business_date`가 DB 값과 일치

선택 날짜만 전달한 뒤 최신 리포트를 다시 검색하는 방식은 사용하지 않는다.

## 9. 목록 카드와 달력 공통화

다음 두 진입점이 같은 모달 오픈 함수와 날짜 포맷 함수를 사용해야 한다.

- 목록 카드 클릭
- 지난 이력보기 달력 날짜 클릭

정상 흐름:

```text
카드 또는 달력 선택
→ report_id 및 business_date 확정
→ 공통 openReportModal 호출
→ 동일 상세 API 조회
→ business_date 그대로 제목 표시
```

## 10. 탭 전환 상태

빠른 요약, 상세 보기, 추천 가이드 탭은 동일한 리포트 데이터를 사용한다.

탭 전환 시 다음 동작을 금지한다.

- 최신 리포트 재조회
- `business_date` 재계산
- 현재 날짜로 초기화
- 다른 `report_id`로 변경
- 모달 제목만 별도 상태로 재생성

모달이 열린 동안 `report_id`와 `business_date`는 고정한다.

## 11. 캐시 키

상세 리포트 캐시 키에는 최소한 다음 값을 포함한다.

```text
childId + reportType + reportId
```

날짜만 캐시 키로 사용하지 않는다. 다른 아이나 다른 리포트의 응답이 재사용되지 않도록 한다.

## 12. 과거·월 경계·연도 경계 검증

다음 날짜를 추가 검증한다.

- 같은 달의 연속 날짜
- 월말
- 다음 달 1일
- 연말
- 다음 해 1월 1일
- 윤년 2월 29일
- 미래 날짜 선택 불가
- 리포트가 없는 날짜

예:

```text
8월 31일 카드
→ 8월 31일 리포트

9월 1일 카드
→ 9월 1일 리포트
```

UTC/KST 변환 때문에 다음 달 또는 다음 해로 넘어가면 안 된다.

## 13. 오류 처리

상세 API가 반환한 `business_date`와 클릭한 카드의 날짜가 다르면 모달을 정상 표시하지 말고 오류를 기록한다.

권장 안내:

```text
리포트 날짜를 확인하지 못했어요.
잠시 후 다시 확인해 주세요.
```

오류 로그에는 다음만 기록한다.

- 마스킹된 `report_id`
- 기대 `business_date`
- API `business_date`
- `child_id` 마스킹값
- 실행 환경

개인정보와 리포트 내용은 기록하지 않는다.
