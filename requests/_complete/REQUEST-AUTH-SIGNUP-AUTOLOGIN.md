# 내친구 케이 회원가입 및 자동 로그인 정상화

## 1. 작업 목적

현재 보호자 계정이 실제로 생성되지 않았거나 보호자·가족·아이 정보 등록이 끝나지 않은 상태에서도 로그인 세션만 있으면 자동 로그인되어 PWA 설치 화면 또는 서비스 화면으로 이동하는 문제가 있다.

다음 정책으로 인증·회원가입·자동 로그인 흐름을 전면 정비한다.

1. 계정과 유효한 세션이 없는 사용자는 로그인 화면을 표시한다.
2. 카카오·구글 인증은 성공했지만 내친구 케이 회원가입이 완료되지 않은 사용자는 반드시 회원가입 페이지로 이동한다.
3. 보호자·가족·최초 아이·필수 동의 등록까지 완료된 사용자만 활성 회원으로 전환한다.
4. 기존 활성 회원에게 유효한 세션이 있으면 자동 로그인한다.
5. 아이는 보호자가 발급한 아이 아이디·비밀번호로만 로그인한다.
6. PWA 설치 안내는 회원가입 완료 및 로그인 이후에만 표시한다.
7. 기존 사용자·아이·리포트·대화·이벤트·황금열쇠 데이터는 절대 삭제하거나 초기화하지 않는다.
8. Dev와 Production에 동일한 정책과 기능을 적용한다.

## 2. 핵심 원칙

### 2.1 인증과 회원가입 완료를 분리한다

Supabase Auth 사용자 또는 OAuth 세션이 있다는 사실만으로 내친구 케이 회원가입 완료자로 판단하지 않는다.

최소한 다음 상태를 별도로 판별한다.

- `GUEST`
  - 유효한 인증 세션 없음
- `AUTHENTICATED_INCOMPLETE`
  - 카카오·구글 인증 사용자는 존재함
  - 보호자 프로필, 동의, 가족 또는 최초 아이 등록이 완료되지 않음
- `ACTIVE_PARENT`
  - 보호자 프로필 완료
  - 필수 약관 동의 완료
  - 가족 연결 완료
  - 최소 1명의 아이 등록 완료
  - 회원가입 완료 상태
- `ACTIVE_CHILD`
  - 활성 상태의 보호자가 발급한 아이 계정
- `SUSPENDED`
  - 관리자 또는 운영 정책에 의해 이용 정지
- `DELETED`
  - 탈퇴 또는 soft-delete 상태

기존 테이블과 컬럼으로 상태를 안정적으로 판별할 수 있으면 이를 재사용한다.

기존 구조로 불가능한 경우에만 다음과 같은 상태값을 기존 회원 테이블에 추가하거나 최소 범위로 확장한다.

- `membership_status`
- `onboarding_step`
- `onboarding_completed_at`
- `suspended_at`
- `deleted_at`

동일 역할의 기존 컬럼이 있으면 중복 생성하지 않는다.

## 3. 최종 라우팅 정책

### 3.1 최초 앱 진입 시

서버에서 인증 토큰을 검증한 뒤 애플리케이션 회원 상태를 조회한다.

| 인증 및 회원 상태 | 이동 위치 |
|---|---|
| 유효한 세션 없음 | 로그인 페이지 |
| 인증됨 + 회원정보 없음 | 회원가입 1단계 |
| 인증됨 + 가입 진행 중 | 마지막 완료 단계부터 회원가입 재개 |
| 활성 보호자 | 보호자 홈 |
| 활성 아이 | 아이 홈 |
| 이용 정지 | 이용 제한 안내 |
| 탈퇴·삭제 | 세션 종료 후 로그인 페이지와 안내 메시지 |

클라이언트 `localStorage` 값만으로 로그인 여부나 역할을 결정하지 않는다.

서버 측 보호 라우트에서는 검증되지 않은 `getSession()` 결과의 사용자 객체만으로 권한을 허용하지 않는다. 현재 설치된 Supabase SDK 버전을 확인하고 공식 권장 방식인 `getClaims()` 또는 서버 확인이 필요한 경우 `getUser()`를 사용한다.

### 3.2 OAuth 콜백 처리

카카오 또는 구글 인증 콜백 성공 후 다음 순서로 처리한다.

1. 인증 사용자 식별
2. 기존 내친구 케이 보호자 회원 연결 여부 확인
3. 기존 활성 보호자이면 보호자 홈으로 이동
4. 가입 미완료 사용자이면 `/signup`으로 이동
5. 프로필은 있으나 가족이 없으면 가족·아이 등록 단계로 이동
6. 가족은 있으나 아이가 없으면 최초 아이 등록 단계로 이동
7. 필수 동의가 최신 버전이 아니면 동의 갱신 단계로 이동
8. 정지·탈퇴 계정이면 홈 진입 차단
9. OAuth 오류가 발생하면 로그인 화면으로 돌아가 이해하기 쉬운 오류 표시

OAuth 인증 직후 회원가입이 끝나지 않았더라도 세션 자체를 불필요하게 삭제하지 않는다. 해당 세션을 회원가입 온보딩에만 사용하고, 활성 회원 전환 전에는 보호자 홈·리포트·관리 기능 접근을 차단한다.

## 4. 로그인 화면 수정

현재 디자인과 브랜드 스타일을 유지하면서 다음을 반영한다.

### 4.1 보호자 영역

기존 버튼을 유지한다.

- 카카오로 로그인
- 구글로 로그인

버튼 하단에 다음 안내와 링크를 추가한다.

- 안내: `처음 이용하시나요? 보호자 회원가입을 진행해 주세요.`
- 버튼 또는 링크: `보호자 회원가입`

회원가입 버튼을 누르면 소셜 인증 방식을 선택하게 한다.

로그인 버튼을 눌렀으나 해당 소셜 인증 계정이 내친구 케이 회원가입을 완료하지 않은 상태라면 오류로 처리하지 않고 회원가입 페이지로 연결한다.

### 4.2 아이 영역

현재 아이 로그인 방식을 유지한다.

- 아이 아이디
- 비밀번호
- 로그인 버튼

아이 회원가입 버튼은 제공하지 않는다.

안내 문구는 다음과 같이 정리한다.

`아이 계정은 보호자가 회원가입 후 만들어 줄 수 있어요.`

### 4.3 계정 전환

공용 기기에서 보호자와 아이가 번갈아 사용할 수 있도록 다음 기능을 제공한다.

- 보호자 화면: `아이 계정으로 전환`
- 아이 화면: `보호자 계정으로 전환`
- 전환 시 현재 역할의 인증 세션과 민감한 캐시를 안전하게 정리
- 이전 사용자 정보가 다음 사용자 화면에 노출되지 않도록 처리
- 전환을 단순 클라이언트 역할 변경으로 구현하지 말고 실제 인증 상태를 변경

## 5. 보호자 회원가입 화면

모바일 우선의 단계형 온보딩으로 구현한다.

권장 단계는 총 4단계다.

### 5.1 1단계: 약관 및 개인정보 동의

#### 필수 동의

1. 서비스 이용약관 동의
2. 보호자 개인정보 수집·이용 동의
3. 아이 개인정보 수집·이용 동의
4. 만 14세 미만 아이의 법정대리인 동의
5. 보호자가 해당 아이의 법정대리인이거나 적법한 동의 권한을 보유하고 있다는 확인

#### 선택 동의

1. 마케팅 정보 수신 동의
2. 이벤트·혜택 알림 동의

필수 동의와 선택 동의를 한 체크박스로 묶지 않는다.

각 동의 기록에 다음 정보를 저장한다.

- 동의 종류
- 약관 또는 동의서 버전
- 동의 여부
- 동의 일시
- 사용자 ID
- 가족 또는 아이 ID
- 동의 당시 IP
- user agent
- 인증 수단
- 철회 일시
- 재동의 여부

기존 동의 테이블과 캐치시큐 연동 구조가 있으면 반드시 재사용한다.

동의 원문 전체를 회원 테이블에 중복 저장하지 말고 문서 버전과 동의 증빙을 연결한다.

### 5.2 2단계: 보호자 기본정보

필수 항목:

- 보호자 이름
- 소셜 로그인 이메일
- 휴대전화 번호
- 아이와의 관계
  - 어머니
  - 아버지
  - 법정대리인
  - 기타 법정대리인
- 법정대리인 확인

처리 기준:

- 소셜 로그인에서 확인한 이메일은 기본 표시하고 임의 수정 여부는 기존 인증 정책에 따른다.
- 휴대전화 번호는 OTP 또는 기존 본인확인 수단으로 확인한다.
- 전화번호 원문을 로그에 출력하지 않는다.
- 주소, 주민등록번호, 학교명, 직장명 등 서비스 제공에 필요하지 않은 정보는 수집하지 않는다.
- 보호자 생년월일을 일반 입력란으로 추가하지 않는다.
- 본인확인 사업자를 사용하는 경우 반환되는 CI·DI 등의 저장 필요성을 검토하고 불필요하면 저장하지 않는다.

회원가입 도중 새로고침하거나 브라우저를 닫더라도 완료 단계부터 안전하게 재개할 수 있어야 한다.

### 5.3 3단계: 가족 생성

최초 가입 시 보호자 1명 기준으로 가족을 자동 생성한다.

기본 가족명은 내부 표시용으로 자동 생성하며, 가입 과정에서 별도 입력을 강제하지 않는다.

예:

`안형진님의 가족`

기존 가족 생성 로직이 있으면 재사용한다.

다음 조건을 보장한다.

- 같은 보호자가 재시도해도 가족이 중복 생성되지 않음
- OAuth 콜백 중복 호출에도 가족이 중복 생성되지 않음
- 보호자와 가족 연결이 원자적으로 저장됨
- 실패하면 일부 데이터만 남지 않도록 트랜잭션 또는 보상 처리 적용

### 5.4 4단계: 최초 아이 등록

아이 입력항목은 아래 항목만 사용한다.

#### 필수 입력항목

- 성
- 이름
- 성별
- 아이 로그인 아이디
- 비밀번호
- 비밀번호 확인
- 학년
- 관심사
- 법정대리인 동의 확인

#### 추가 금지 항목

- 생년월일
- 주민등록번호
- 학교명
- 학급
- 주소
- 전화번호
- 이메일
- 프로필 사진 강제 등록
- 기타 서비스 제공에 불필요한 개인정보

성별은 기존 DB enum과 UI 정책을 우선 재사용한다. 기존 정책이 없으면 다음 값을 사용한다.

- 남자
- 여자
- 선택하지 않음

학년은 초등학교 1학년부터 6학년까지 제공한다.

관심사는 현재 서비스에서 사용하는 기존 관심사 목록을 재사용한다. 새로운 별도 관심사 분류 체계를 중복 생성하지 않는다.

아이 로그인 아이디는 전체 서비스에서 중복되지 않아야 하며 입력 중 중복확인을 제공한다.

아이 비밀번호는 다음 조건을 적용한다.

- 평문 저장 금지
- 평문 로그 출력 금지
- 브라우저 저장소에 평문 저장 금지
- 기존 아이 인증 구조가 Supabase Auth이면 기존 방식을 유지
- 별도 인증 테이블이면 서버 측 강한 해시를 사용
- 현재 해시 방식과 호환성을 확인한 뒤 기존 아이 로그인을 깨뜨리지 않음

## 6. 가입 완료 처리

보호자 정보, 필수 동의, 가족, 최초 아이 등록이 모두 성공했을 때만 회원가입을 완료한다.

완료 시 다음 상태를 저장한다.

- 보호자 역할: `PARENT`
- 회원 상태: `ACTIVE`
- 온보딩 완료 시각
- 현재 온보딩 버전
- 가족 연결
- 최초 아이 연결
- 동의 기록
- 법정대리인 확인 상태

가입 완료 처리는 멱등성을 보장한다.

완료 버튼을 여러 번 누르거나 네트워크 재시도로 동일 요청이 반복돼도 다음 데이터가 중복 생성되면 안 된다.

- 보호자 프로필
- 가족
- 가족 구성원
- 아이
- 아이 계정
- 동의 기록
- 승인 요청

성공 후 기존 OAuth 세션을 유지한 상태로 보호자 홈으로 이동한다.

다시 로그인 화면을 보여 주거나 사용자가 소셜 로그인을 한 번 더 하도록 요구하지 않는다.

## 7. 아이 승인 정책 연동

기존 확정 정책을 그대로 반영한다.

### 7.1 베타 기간

보호자가 최초 아이 또는 추가 아이를 등록한 후 `승인 요청 보내기`를 누르면 다음과 같이 처리한다.

1. 승인 요청 생성
2. 자동 승인
3. 모달 표시: `승인되었습니다`
4. 아이 계정 즉시 사용 가능
5. 관리자 페이지에도 승인 완료 상태로 표시
6. 관리자 승인 관리 화면과 기록은 그대로 유지

단순히 프런트 화면만 승인으로 표시하지 말고 실제 DB 승인 상태와 관리자 화면도 동일하게 반영한다.

### 7.2 정식 서비스 오픈 후

아이 등록 또는 추가 과정에서 결제가 필요한 정책이 활성화되면 결제 페이지 이동 안내 모달을 표시한다.

서비스 단계 전환은 날짜를 여러 화면에 하드코딩하지 않는다.

기존 운영 설정 또는 단일 서버 설정값을 사용한다.

예:

- `BETA`
- `PAID`

기존 서비스 단계 설정 구조가 있으면 이를 재사용한다.

## 8. 기존 사용자 자동 로그인

다음 조건을 모두 만족하는 사용자만 자동 로그인한다.

1. 서버에서 검증된 유효한 인증 세션
2. 활성 보호자 또는 활성 아이 계정
3. 삭제·정지 상태가 아님
4. 역할과 실제 회원 데이터가 일치
5. 필수 회원가입 절차 완료
6. 해당 역할에 연결된 가족 또는 보호자가 정상 상태

브라우저 클라이언트는 공식 SDK 설정에 따라 세션 저장 및 토큰 자동 갱신을 사용한다.

Next.js SSR 환경에서는 현재 프로젝트 구조에 맞춰 `@supabase/ssr` 기반 브라우저·서버 클라이언트와 토큰 갱신용 Proxy 또는 현재 공식 권장 구조를 적용한다.

자동 로그인은 세션을 무기한 고정하는 기능이 아니다.

다음 상황에서는 로그인 화면으로 이동한다.

- Refresh token 만료 또는 폐기
- 명시적 로그아웃
- 비밀번호 또는 보안 정책에 의한 세션 폐기
- 관리자 이용 정지
- 회원 탈퇴
- 서버 검증 실패
- 계정 데이터 불일치

---

## 9. 기존 불완전 계정 복구

이번 문제로 인해 이미 다음과 같은 불완전 사용자가 존재할 수 있다.

- `auth.users`에는 있지만 보호자 프로필이 없음
- 보호자 프로필은 있지만 가족이 없음
- 가족은 있지만 가족 구성원 연결이 없음
- 가족은 있지만 아이가 없음
- 필수 동의 기록이 없음
- 온보딩 완료 표시만 잘못 설정됨

마이그레이션 전에 Dev와 Production을 각각 점검하여 수량과 유형을 보고한다.

복구 정책:

1. 실제 데이터가 정상적으로 존재하는 기존 보호자는 활성 회원으로 유지
2. 아이·리포트·대화 데이터가 연결된 기존 사용자를 신규 가입자로 오판하지 않음
3. 인증 사용자만 있고 서비스 데이터가 없는 사용자는 회원가입 미완료로 전환
4. 일부 단계만 존재하면 해당 단계부터 재개
5. 자동 보정이 위험한 데이터는 수정하지 말고 관리자 검토 목록으로 분리
6. 기존 사용자와 가족을 삭제한 뒤 재생성하는 방식 금지
7. 이메일만 같다는 이유로 두 계정을 자동 병합하지 않음
8. 카카오·구글 중복 계정 가능성을 조사하고 안전한 계정 연결 정책 적용

## 10. PWA 설치 화면 노출 조건

첨부 화면의 `내친구 케이에 오신 것을 환영해요` PWA 설치 안내는 로그인 또는 회원가입 페이지가 아니다.

다음 조건에서만 표시한다.

- 회원가입 완료
- 활성 보호자 또는 활성 아이 로그인
- 서비스 홈 접근 권한 확인
- 해당 기기가 PWA 설치 대상
- 사용자가 기존에 설치 안내를 완료하거나 일정 기간 미루지 않음

다음 화면에서는 절대 표시하지 않는다.

- OAuth 콜백
- 회원가입 진행 중
- 약관 동의 화면
- 보호자 정보 입력 화면
- 아이 등록 화면
- 로그인 오류 화면
- 정지·탈퇴 안내 화면

`나중에 할게요`를 선택하면 정상 홈으로 이동시킨다.

PWA 설치 여부가 회원가입 완료 상태나 로그인 상태를 변경해서는 안 된다.

---

## 11. 보안 및 RLS

다음 보안 기준을 적용한다.

1. `service_role` 키를 브라우저 코드에 포함하지 않는다.
2. 비밀번호, 토큰, OTP, CI·DI, API 키를 로그에 출력하지 않는다.
3. 보호자는 본인이 속한 가족과 아이 데이터만 조회·수정할 수 있다.
4. 아이는 본인의 허용된 데이터만 접근할 수 있다.
5. 다른 가족 UUID를 직접 요청해도 조회·수정이 거부되어야 한다.
6. 회원가입 미완료 사용자는 보호자 홈·리포트·대화·결제·관리 API를 호출할 수 없다.
7. 관리자 권한은 기존 관리자 검증 정책을 유지한다.
8. 사용자 입력만으로 역할·가족 ID·승인 상태를 지정하지 못하게 한다.
9. 민감한 회원 생성과 가족 연결은 서버에서 처리한다.
10. OAuth `redirectTo`, `next` 값은 허용된 내부 경로만 사용한다.
11. Dev와 Production OAuth callback URL을 각각 명확히 분리한다.
12. 캐시된 SSR 응답으로 다른 사용자의 세션이 노출되지 않도록 인증 페이지 캐시 정책을 점검한다.

## 12. UX 및 오류 메시지

기술 용어와 Supabase 오류 원문을 사용자에게 직접 노출하지 않는다.

예시:

- 신규 사용자:
  - `내친구 케이를 처음 이용하시네요. 회원가입을 진행해 주세요.`
- 가입 진행 중:
  - `이어서 회원가입을 완료해 주세요.`
- 로그인 세션 만료:
  - `안전한 이용을 위해 다시 로그인해 주세요.`
- 중복 아이 아이디:
  - `이미 사용 중인 아이디예요. 다른 아이디를 입력해 주세요.`
- 정지 계정:
  - `현재 이용이 제한된 계정입니다. 문의하기를 이용해 주세요.`
- OAuth 취소:
  - `로그인이 취소되었습니다. 다시 시도해 주세요.`
- 일시적인 서버 오류:
  - `잠시 후 다시 시도해 주세요. 입력한 내용은 안전하게 보관되어 있습니다.`

회원가입 단계에는 진행 상태를 표시한다.

예:

`1 / 4 약관 동의`

모바일 키보드가 표시되어도 다음 버튼과 입력란이 가려지지 않도록 한다.

## 13. 필수 테스트 시나리오

### 13.1 보호자 신규 가입

1. 세션이 없는 신규 사용자가 앱에 접속
2. 로그인 화면 표시 확인
3. 신규 카카오 계정으로 로그인
4. 보호자 홈이 아닌 회원가입 화면 이동 확인
5. 약관 동의
6. 보호자 정보 입력 및 휴대전화 확인
7. 가족 자동 생성
8. 최초 아이 등록
9. 베타 자동 승인
10. 가입 완료 후 보호자 홈 이동
11. 앱 종료 후 재접속
12. 자동 로그인 및 보호자 홈 이동 확인

구글 로그인도 동일하게 수행한다.

### 13.2 가입 중단 및 재개

각 단계에서 다음을 테스트한다.

- 새로고침
- 브라우저 종료
- 네트워크 단절
- OAuth 콜백 재호출
- 완료 버튼 중복 클릭

재로그인 후 마지막 미완료 단계부터 재개되어야 하며 데이터가 중복 생성되면 안 된다.

### 13.3 기존 보호자

- 기존 보호자 세션 유지 상태에서 앱 재접속
- 회원가입 페이지가 표시되지 않음
- 보호자 홈으로 자동 이동
- 기존 가족·아이·리포트·대화·이벤트 데이터 유지

### 13.4 불완전 보호자

다음 유형별로 정확한 단계로 이동하는지 확인한다.

- Auth만 있음
- 보호자 프로필만 있음
- 가족까지만 있음
- 아이 등록 전
- 필수 동의 미완료
- 가입 완료 플래그 불일치

### 13.5 아이 로그인

- 올바른 아이 아이디·비밀번호
- 잘못된 비밀번호
- 존재하지 않는 아이디
- 승인 전 아이
- 정지된 아이
- 보호자가 탈퇴 또는 정지된 아이
- 앱 재실행 시 아이 자동 로그인
- 보호자 계정으로 전환
- 공용 기기에서 이전 아이 데이터 미노출

### 13.6 로그아웃

- 보호자 로그아웃
- 아이 로그아웃
- 쿠키 및 인증 저장소 정리
- 뒤로 가기로 보호 화면 재진입 불가
- 재접속 시 로그인 화면 표시
- 로그아웃 직후 자동으로 이전 계정이 다시 로그인되지 않음

### 13.7 PWA

- 신규 사용자에게 가입 전 PWA 설치 화면 미노출
- 가입 완료 후 PWA 설치 화면 노출
- `나중에 할게요` 선택 후 정상 홈 이동
- 이미 설치한 사용자에게 반복 노출되지 않음
- PWA에서 앱을 종료했다가 다시 열어도 기존 활성 회원은 자동 로그인

### 13.8 권한 및 보안

- 다른 가족 ID를 사용한 API 요청 차단
- 회원가입 미완료 계정의 보호자 API 접근 차단
- 아이 계정의 보호자 리포트 접근 차단
- 클라이언트에서 역할값 변조 시 차단
- 만료·폐기 토큰으로 접근 차단
- Production 로그에 비밀번호·토큰·OTP·전화번호 원문이 남지 않음

## 14. Dev 및 Production 적용 순서

1. 기존 인증·회원·가족·아이·동의·승인·PWA 구조 조사
2. Dev와 Production 데이터 구조 차이 확인
3. 기존 불완전 계정 유형과 수량 보고
4. 수정 설계 및 마이그레이션 작성
5. Dev 적용
6. Dev 전체 시나리오 검증
7. 기존 사용자 회귀 테스트
8. Production 백업 및 롤백 계획 확인
9. Production 마이그레이션 적용
10. Production 배포
11. 실제 신규 카카오·구글 가입 검증
12. 실제 기존 보호자·아이 자동 로그인 검증
13. 배포 후 오류 로그 및 중복 데이터 확인

운영 테스트가 필요하면 기존 QA 전용 가족과 계정을 사용하고 리텐션 제외 정책을 유지한다.

## 15. 완료 승인 기준

다음 조건을 모두 충족해야 완료로 판단한다.

- [ ] 세션이 없는 사용자는 항상 로그인 페이지로 이동
- [ ] 신규 소셜 인증 사용자는 회원가입 페이지로 이동
- [ ] Auth 사용자 생성만으로 보호자 홈 접근 불가
- [ ] 보호자·동의·가족·최초 아이 완료 후에만 활성 회원 전환
- [ ] 기존 활성 보호자는 자동 로그인
- [ ] 기존 활성 아이는 자동 로그인
- [ ] 가입 중단 사용자는 마지막 단계부터 재개
- [ ] 가입 재시도에도 가족·아이·동의 데이터 중복 없음
- [ ] 베타 아이 등록은 자동 승인되고 관리자에도 승인 완료 표시
- [ ] PWA 설치 화면은 가입 완료 후에만 표시
- [ ] 명시적 로그아웃 후 자동 재로그인되지 않음
- [ ] 정지·탈퇴 계정은 자동 로그인되지 않음
- [ ] 다른 가족 데이터 접근이 RLS로 차단됨
- [ ] 기존 실제 사용자 데이터와 리포트가 보존됨
- [ ] Dev 검증 완료
- [ ] Production 검증 완료
- [ ] BLOCKED/HIGH 보안 이슈 0건
- [ ] 변경 파일·DB migration·환경변수·테스트 결과·배포 URL·롤백 방법 보고 완료

기존 정상 사용자, 불완전 계정, 중복 가능 계정을 각각 어떻게 처리했는지 작성한다.
