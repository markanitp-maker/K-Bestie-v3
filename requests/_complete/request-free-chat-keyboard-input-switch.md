# 자유 대화 키보드 입력 전환 기능 개선

## 1. 작업 목적

자유 대화 화면에서 왼쪽 하단의 키보드 버튼을 누르면 현재 자동 음성 모드가 수동 모드로 전환되고, 즉시 텍스트 입력창이 나타나도록 수정한다.

현재 자유 대화 화면은 자동·수동 음성 입력만 제공하고 있으며, 키보드 버튼을 눌렀을 때 아이가 바로 텍스트로 입력할 수 있는 흐름이 명확하지 않다.

이번 작업의 목적은 아이가 음성 대신 키보드로 이야기하고 싶을 때 별도 화면 이동 없이 동일한 자유 대화 세션 안에서 자연스럽게 텍스트 입력으로 전환하도록 만드는 것이다.

---

## 2. 최종 동작 정책

### 2.1 기본 상태

- 자유 대화 진입 시 기존 정책에 따라 자동 음성 모드가 기본값이다.
- 자동 모드에서는 VAD·자동 녹음·STT 경로가 동작한다.

### 2.2 키보드 버튼 클릭

왼쪽 하단의 키보드 버튼을 누르면 다음 순서로 전환한다.

1. 자동 음성 모드 해제
2. 음성 모드를 수동으로 변경
3. 진행 중인 자동 청취·VAD·녹음 중단
4. 활성화된 MediaStream·MediaRecorder·오디오 타이머 정리
5. 하단에 텍스트 입력창과 전송 버튼 표시
6. 입력창 자동 포커스
7. 모바일 환경에서는 소프트 키보드 표시

키보드 모드로 전환된 동안 자동 녹음, VAD, STT 호출은 발생하지 않아야 한다.

---

## 3. UI 요구사항

### 3.1 입력창 위치

- 기존 하단 마이크 버튼 영역을 기준으로 텍스트 입력창을 표시한다.
- 입력창은 화면 하단에 고정한다.
- 키보드가 열려도 입력창은 항상 보이도록 한다.
- 입력창 위의 대화 영역은 스크롤 가능해야 한다.
- 키보드가 열릴 때 케이의 가장 최근 말풍선이 기본적으로 보이도록 스크롤 위치를 조정한다.

### 3.2 입력창 구성

필수 구성:

- 텍스트 입력 필드
- 전송 버튼
- 키보드 닫기 또는 음성 입력 복귀 동작
- 입력 중 상태 표시
- 전송 중 중복 입력 방지

### 3.3 모드 표시

키보드 버튼 클릭 후:

- 자동 버튼의 선택 상태를 해제한다.
- 수동 버튼을 선택 상태로 변경한다.
- 키보드 입력창이 열린 상태임을 UI로 명확히 표시한다.
- 자동 모드가 백그라운드에서 계속 동작하지 않도록 한다.

---

## 4. 텍스트 메시지 전송 정책

텍스트 입력은 기존 자유 대화의 동일한 대화 처리 경로를 사용한다.

유지해야 하는 값:

- `child_id`
- `conversation_id`
- `turn_id`
- `display_sequence`
- 사용자 역할 구분
- 자유 대화 세션 연결
- LLM Wiki Retrieval
- 케이 응답 생성
- 메시지 저장
- Collection·Context Correction 대상 필드

텍스트 입력에서는 STT 단계만 생략한다.

처리 순서:

1. 아이가 텍스트 입력
2. 빈 문자열 및 공백 입력 차단
3. 사용자 메시지 1건 저장
4. LLM Wiki 관련 기억 조회
5. 자유 대화 응답 정책에 따라 케이 응답 생성
6. 케이 메시지 1건 저장
7. 화면에 응답 표시
8. 소리 켜기 상태인 경우에만 TTS 생성·재생
9. 입력창 초기화
10. 다음 입력 가능 상태 복귀

---

## 5. 자유 대화 응답 정책 유지

키보드 입력에서도 기존 자유 대화 응답 정책을 동일하게 적용한다.

- 일반 지식·상식·학습 질문에 답변하지 않는다.
- LLM Wiki에 저장된 해당 아이의 기억만 사용한다.
- 관련 기억이 있으면 최대 2줄, 30글자 이내로 답변한다.
- 기억이 없으면 추측·설명·정보 전달·훈계를 하지 않는다.
- 긴 설명, 훈계, 정보 전달은 금지한다.
- 모르는 내용은 다음 표현을 사용한다.

`잘 모르겠는데, 너가 알려줄 수 있어? 내가 안 잊어버리고 기억할게`

음성 입력과 키보드 입력의 응답 정책이 달라지면 안 된다.

---

## 6. 음성 모드 복귀 정책

키보드 입력창을 닫거나 마이크 버튼을 누르면 자동 모드가 아니라 수동 음성 모드로 복귀한다.

복귀 시:

1. 키보드 입력창 닫기
2. 모바일 소프트 키보드 닫기
3. 수동 모드 선택 상태 유지
4. 수동 마이크 버튼 표시
5. 자동 VAD는 다시 시작하지 않음
6. 사용자가 수동 마이크를 눌렀을 때만 녹음 시작

입력 중인 텍스트가 남아 있을 경우 임의로 삭제하지 않는다.

텍스트가 남은 상태에서 모드 전환이 요청되면 입력 내용을 유지한 채 입력창만 닫거나, 명확한 확인 UI를 제공한다. 확인 없이 입력 내용을 폐기하면 안 된다.

---

## 7. 상태 관리 요구사항

자동 음성·수동 음성·키보드 입력이 동시에 활성화되지 않도록 상태를 단일화한다.

권장 모드 상태:

- `auto_voice`
- `manual_voice`
- `keyboard`

필수 확인 항목:

- 키보드 모드에서 VAD 실행 금지
- 키보드 모드에서 MediaRecorder 실행 금지
- 키보드 모드에서 STT 호출 금지
- 자동→키보드 전환 시 기존 스트림 정리
- 키보드→수동 음성 전환 시 자동 모드 재활성화 금지
- 전송 중 중복 submit 방지
- 같은 `turn_id` 중복 저장 방지
- 음성 입력과 텍스트 입력의 동시 처리 방지
- 화면 이탈 시 스트림·타이머·이벤트 리스너 정리

---

## 8. 오류 처리

다음 상황에서 사용자 입력을 잃지 않고 재시도할 수 있어야 한다.

- LLM API 실패
- DB 저장 실패
- TTS 실패
- 네트워크 단절
- 응답 timeout
- 화면 전환
- 앱 백그라운드 전환

원칙:

- TTS 실패 시 텍스트 응답은 유지한다.
- LLM 실패 시 입력 내용을 복구하거나 재전송 가능하게 한다.
- 처리 실패 후 `isSubmitting` 상태가 풀려야 한다.
- 새로고침 없이 다시 입력할 수 있어야 한다.
- 기술적인 내부 오류와 비밀정보는 사용자 화면에 노출하지 않는다.

## 9. 접근성 및 모바일 대응

### iPhone Safari / PWA

- 키보드 표시 시 입력창이 가려지지 않아야 한다.
- Visual Viewport 변화 대응
- 입력창 자동 포커스 동작 확인
- 화면 확대·축소 없이 입력 가능
- 앱 전환 후 복귀 시 입력 상태 유지
- 마이크와 키보드 전환 반복 시 오디오 세션 교착 방지

### Android Chrome

- 소프트 키보드 표시 시 입력창 고정
- 뒤로가기 버튼으로 키보드만 먼저 닫히는지 확인
- 키보드 닫힘 후 수동 음성 모드 유지

### 데스크톱 Chrome

- 키보드 버튼 클릭 후 입력창 포커스
- Enter 전송
- Shift+Enter 줄바꿈 정책 명확화
- 중복 Enter 입력 방지

## 10. 검증 시나리오

### 10.1 기본 전환

1. 자유 대화 진입
2. 자동 모드 활성 상태 확인
3. 왼쪽 키보드 버튼 클릭
4. 자동 모드 해제 확인
5. 수동 모드 선택 확인
6. 입력창 표시 확인
7. 모바일 키보드 표시 확인
8. 자동 녹음·VAD 중단 확인

### 10.2 텍스트 입력

1. 텍스트 입력
2. 전송
3. 사용자 메시지 1건 저장
4. 케이 응답 1건 생성
5. 중복 저장 없음
6. LLM Wiki Retrieval 적용 확인
7. 자유 대화 응답 길이·금지 규칙 적용 확인
8. 소리 켜기 시 TTS 1회 재생
9. 소리 끄기 시 TTS 호출 0건

### 10.3 음성 복귀

1. 키보드 입력창 닫기
2. 수동 음성 모드 유지
3. 자동 VAD 미실행 확인
4. 마이크 버튼 클릭
5. 수동 녹음 정상 시작
6. STT·LLM·TTS 정상 처리

### 10.4 연속 전환

아래 흐름을 5회 이상 반복한다.

`자동 음성 → 키보드 → 텍스트 전송 → 수동 음성 → 키보드`

확인:

- 상태 교착 없음
- 중복 호출 없음
- 스트림 누수 없음
- 입력 내용 유실 없음
- 메시지 순서 정상
- 앱 강제 종료 없음

### 10.5 화면 및 키보드

- 키보드가 열려도 입력창 고정
- 대화 화면 스크롤 가능
- 케이의 최근 말풍선이 기본 노출
- 긴 텍스트 입력 시 입력창 높이 처리 정상
- 키보드 닫기 후 레이아웃 복원 정상
