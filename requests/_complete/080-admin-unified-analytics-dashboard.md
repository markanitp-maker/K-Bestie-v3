# Request: 관리자 `통합 분석 대시보드` 구축 — 리포팅 분석 + 사용자 리텐션 통합

> 완료: 2026-08-08 | main `7cd5a43` | Dev `dpl_7iRb9j9vnyrLRgjdHUFnxnnYVRnF` | Production `dpl_63avwSuVBHGWzSGB3hL6D42TkXTA`

## 0. 작업 목적

현재 관리자에는 `리포팅 수동 실행`과 `사용자 리텐션`이 서로 분리되어 있어, 아이 활동 → 리포트 생성 → 부모 확인 → 재방문이라는 실제 서비스 운영 흐름을 한 화면에서 보기 어렵다.

이번 작업에서는 `리포팅 분석`과 `사용자 리텐션`을 하나의 **통합 분석 대시보드**로 묶는다.

핵심 목표:

```text
아이 활동
→ 수집
→ 보정
→ Memory Batch
→ 리포트 생성
→ 부모 확인
→ 재방문 / 리텐션
```

위 흐름을 한 페이지에서 확인할 수 있게 한다.

기존 `리포팅 수동 실행` 기능은 운영 도구로 계속 유지하되, 분석용 화면은 통합한다.

---

## 1. 최종 관리자 IA

사이드바는 아래처럼 정리한다.

```text
리포팅·분석
├─ 통합 분석 대시보드
└─ 리포팅 수동 실행
```

기존 `사용자 리텐션` 독립 메뉴는 제거하거나 통합 대시보드로 redirect한다.

권장 통합 라우트:

```text
/admin/analytics
```

기존 리텐션 라우트가 있다면:

```text
/admin/retention
→ /admin/analytics?section=retention
```

또는 현재 프로젝트 라우팅 정책에 맞게 redirect한다.

---

## 2. 통합 분석 페이지 구조

페이지는 아래 순서로 구성한다.

```text
1. 공통 조회 필터
2. 핵심 KPI 카드
3. 행동 퍼널 / 리포트 생성 흐름
4. 리텐션 차트
5. 리포팅 품질 현황
6. 상세 드릴다운 표
```

한 화면에 너무 많은 정보를 무작정 붙이지 말고, 섹션별 시각적 계층을 명확히 한다.

---

## 3. 공통 조회 필터

상단 필터는 페이지 전체 섹션에 동일하게 적용한다.

조회 기간:

```text
오늘
최근 7일
최근 14일
최근 30일
이번 달
지난달
직접 기간
```

직접 기간:

```text
시작일 [YYYY-MM-DD]
종료일 [YYYY-MM-DD]
[조회]
```

기준 시간대:

```text
Asia/Seoul
```

대상 범위:

```text
전체
가족
부모
아이
```

내부 테스트:

```text
제외
포함
테스트만
```

기본값:

```text
최근 7일
전체
내부 테스트 제외
```

모든 KPI, 그래프, 표, CSV가 동일한 필터 값을 사용해야 한다.

---

## 4. 핵심 KPI 카드

상단에는 운영 판단에 꼭 필요한 KPI만 노출한다.

권장 카드:

```text
전체 활성 사용자
활성 가족
미션 완료율
리포트 생성률
D1 리텐션
D3 리텐션
D7 리텐션
부모 동시 활성 가족
```

카드 수가 너무 많아지지 않도록 6~8개 수준으로 유지한다.

카드 클릭 시 해당 상세 섹션 또는 드릴다운 필터로 이동 가능하게 한다.

---

## 5. 활성 사용자 정의

기존 리텐션 계산 기준을 재사용하되 조회 기간과 KST 기준을 통일한다.

전체 활성 사용자:

```text
부모 user_id + 아이 child_id를 독립 사용자로 합산
```

가족 단위 dedupe 금지.

내부 테스트 제외 기본.

리텐션 원천 데이터와 동일한 정의를 사용한다.

---

## 6. 행동 퍼널 / 리포트 생성 흐름

다음 단계를 한눈에 보여주는 퍼널 또는 단계형 차트를 추가한다.

```text
접속
→ 미션 시작
→ 미션 완료
→ 자유대화/놀이 활동
→ 대화 수집
→ 보정 완료
→ Memory Batch 완료
→ 리포트 생성
→ 부모 리포트 확인
```

단계별 값:

```text
대상 수
완료 수
완료율
실패 수
```

모든 단계가 동일한 기간/대상 필터를 사용한다.

---

## 7. 리텐션 차트 영역

기존 사용자 리텐션 화면의 핵심 차트를 통합한다.

필수:

```text
일별 활성 사용자 추이 (DAU)
부모/아이 활성 추이
가입 코호트 리텐션
가족 동시 활성 추이
```

리텐션 지표:

```text
D1
D3
D7
D14
W2
```

미완성 코호트는 기존 정책대로 제외한다.

당일 데이터 때문에 리텐션이 0으로 떨어지는 현상이 다시 발생하지 않도록 분석 기준일 정책을 재사용한다.

---

## 8. DAU 차트

기본 표시:

```text
부모 활성
아이 활성
전체 활성
```

선택적으로 series on/off 가능.

오늘 데이터를 포함할지 여부는 리텐션과 분리해서 처리한다.

권장:

```text
DAU는 현재 기간 기준 실제 활동
리텐션 계산은 완료된 코호트 기준
```

UI에 기준을 명확히 표시한다.

---

## 9. 가입 코호트 테이블

기존 코호트 리텐션 표를 재사용한다.

예:

| 가입 주차 | 모수 | D1 | D3 | D7 | D14 |
|---|---:|---:|---:|---:|---:|

색상 heatmap 유지 가능.

모수 0인 경우 `-` 표시.

미래 시점 지표를 0으로 표시하지 않는다.

## 10. 리포팅 품질 현황

리포팅 파이프라인의 운영 상태를 별도 섹션으로 보여준다.

단계:

```text
1차 수집 18:00
2차 수집 23:59:59
보정
Memory Batch
리포트 생성
```

각 단계별:

```text
대상 수
성공 수
실패 수
대기 수
성공률
```

예:

```text
1차 수집
대상 14명
성공 12
실패 1
대기 1
성공률 85.7%
```

---

## 11. 리포팅 상태 필터

리포팅 품질 섹션에는 기존 확정 필터를 적용한다.

```text
전체
성공
실패
대기
```

정의:

### 성공

모든 단계 성공.

### 실패

하나라도 실패.

### 대기

실패는 없고 하나라도 대기.

우선순위:

```text
실패 > 대기 > 성공
```

## 12. 리포트 생성률 정의

리포트 생성률은 아래처럼 명확히 정의한다.

```text
리포트 생성 완료 사용자 수
/
리포트 생성 대상 사용자 수
× 100
```

대상 사용자가 없는 경우:

```text
-
```

로 표시.

## 13. 부모 리포트 확인률

가능하면 부모 리포트 조회 이벤트를 기준으로 다음 지표를 추가한다.

```text
리포트 확인 부모 수
리포트 생성 대비 확인률
```

실제 조회 이벤트 원천이 현재 존재하는지 확인 후 구현한다.

없으면 임의 추정하지 말고 `신규 계측 필요`로 보고한다.

## 21. 리포팅 수동 실행은 유지

`리포팅 수동 실행`은 분석 페이지에 흡수하지 않는다.

이유:

```text
통합 분석 = 조회/판단
리포팅 수동 실행 = 운영 액션
```

사이드바에는 계속 별도 메뉴로 유지한다.

## 26. 성능

한 페이지에서 여러 API를 동시에 호출해 로딩이 길어지지 않게 한다.

권장:

- 공통 필터 기반 서버 집계
- 병렬 fetch
- 캐시 가능한 read-only 데이터는 짧은 TTL 캐시 검토
- N+1 금지
- 차트별 불필요한 full table scan 방지

Production 현재 데이터가 작더라도 향후 사용자 증가를 고려한다.

---

## 27. 오류 처리

각 섹션이 독립적으로 실패해도 전체 페이지가 crash하지 않게 한다.

예:

```text
리텐션 차트 로딩 실패
→ 해당 섹션만 오류 표시

리포팅 품질 API 실패
→ 해당 섹션만 오류 표시
```

React 전체 페이지 client-side exception 금지.

모든 배열 렌더링은 empty array fallback.
