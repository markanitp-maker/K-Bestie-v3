# 자유 대화 자동·수동 음성 무응답 장애 수정

## 1. 작업 목적

개발 서버와 프로덕션에서 모두 발생하는 자유 대화 음성 장애를 진단하고 수정한다.

현재 자유 대화 화면에서 자동 모드와 수동 모드 모두 사용자가 마이크로 말해도 케이의 응답이 전혀 생성되지 않는다. 화면은 `듣고 있어` 또는 `케이가 이야기를 준비하고 있어요...` 상태에 머물 수 있으며, STT·LLM·TTS·재생·메시지 저장 중 어느 단계에서 중단되는지 사용자에게 표시되지 않는다.

이번 작업은 임시 우회가 아니라 자유 대화 한 턴의 전체 경로를 추적해 근본 원인을 수정하고, 개발 서버와 프로덕션에서 회귀 검증까지 완료하는 것이 목적이다.

---

## 2. 장애 현상

- 대상: 자유 대화 기능
- 환경: 개발 서버, 프로덕션
- 모드: 자동 마이크, 수동 마이크 모두
- 재현:
  1. 자유 대화 화면 진입
  2. 자동 또는 수동 모드 선택
  3. 마이크 활성화 후 사용자 발화
  4. 발화 종료
- 실제 결과:
  - 사용자 발화 후 케이 응답 없음
  - 음성 출력 없음
  - 텍스트 응답 없음
  - 오류 안내 없음
  - 화면이 듣기 또는 준비 상태에 멈출 수 있음
- 기대 결과:
  - 발화 감지
  - 녹음 종료
  - STT 처리
  - 사용자 메시지 저장
  - LLM 응답 생성
  - 케이 메시지 저장
  - TTS 생성 및 재생
  - 다음 발화를 받을 수 있는 정상 상태 복귀

## 3. 작업 범위

### 3.1 전체 호출 경로 추적

자유 대화 한 턴의 실제 실행 경로를 코드 기준으로 확인하고, 각 단계의 시작·성공·실패 여부를 추적한다.

1. 마이크 권한 및 오디오 스트림 생성
2. 자동 모드의 VAD 또는 발화 종료 감지
3. 수동 모드의 녹음 시작·종료 이벤트
4. 녹음 데이터 Blob 또는 PCM 생성
5. 클라이언트에서 서버 API·Server Action·Edge Function 호출
6. 인증 세션 및 `child_id` 전달
7. STT 요청과 변환 결과
8. 자유 대화 LLM 요청과 응답
9. TTS 요청과 오디오 응답
10. 사용자·케이 메시지 DB 저장
11. 클라이언트 상태 업데이트
12. 음성 재생 완료 후 다음 턴 복귀

네트워크 요청이 아예 발생하지 않는지, 요청은 발생하지만 4xx·5xx·timeout이 발생하는지, 응답은 성공했지만 UI 상태 또는 오디오 재생에서 중단되는지 구분해서 원인을 확정한다.

### 3.2 자동·수동 모드 분리 진단

자동과 수동이 공통으로 사용하는 처리 함수와 각각 별도로 사용하는 이벤트 경로를 확인한다.

- 자동 모드:
  - VAD 시작·종료 이벤트
  - 무음 감지 임계값
  - 중복 submit 방지 상태
  - 발화 종료 후 실제 처리 함수 호출 여부
- 수동 모드:
  - 버튼 상태와 실제 MediaRecorder 상태 일치 여부
  - 녹음 종료 시 `onstop` 또는 동등 이벤트 실행 여부
  - 생성된 오디오 크기가 0이 아닌지
  - 수동 종료 후 실제 처리 함수 호출 여부
- 공통:
  - `isRecording`, `isListening`, `isProcessing`, `isPlaying`, `isSubmitting` 등의 상태가 교착되지 않는지
  - 이전 요청의 AbortController·timeout·cleanup이 다음 턴을 차단하지 않는지
  - React effect cleanup 또는 Strict Mode 이중 실행이 세션·스트림·이벤트 리스너를 끊지 않는지

### 3.3 환경별 차이 확인

개발 서버와 프로덕션에서 모두 실패하므로 공통 코드 문제를 우선 의심하되, 아래 환경 차이도 함께 확인한다.

- Vercel 환경변수 누락·오타·Preview/Production scope 불일치
- Vertex AI·STT·TTS 관련 인증 또는 서비스 계정 권한
- API route runtime 설정
- Node.js runtime과 Edge runtime 호환성
- 리전·엔드포인트·모델명 불일치
- 브라우저의 HTTPS·마이크 권한·오디오 자동재생 제한
- CORS·CSP·프록시·rewrite 문제
- Supabase 인증 세션 또는 RLS 차단
- 배포 후 이전 클라이언트 번들·PWA service worker 캐시 잔존

환경변수 이름과 존재 여부만 확인하고 값은 출력하지 않는다. 서비스 계정 키, API 키, 비밀번호, 토큰, Supabase service role key 등 비밀정보는 로그·코드·문서·임시파일에 평문으로 남기지 않는다.

## 4. 수정 원칙

1. 자유 대화 기능만 수정하고 미션 대화, Premium Gemini Live, 놀이 기능, 리포트 파이프라인 동작을 변경하지 않는다.
2. 자유 대화는 기존 확정 방식인 비Live `STT → LLM → TTS` 경로를 유지한다. 장애 해결을 이유로 Gemini Live 방식으로 전환하지 않는다.
3. 사용자·케이 메시지 저장 구조를 임의 변경하지 않는다.
4. 기존 `turn_id`, `display_sequence`, update-in-place 또는 현재 확정된 메시지 정렬 정책을 유지한다.
5. Collection·Context Correction이 자유 대화 메시지를 수집할 수 있도록 기존 저장 필드와 수집 대상 조건을 깨뜨리지 않는다.
6. 중복 발화 제출, 중복 LLM 응답, 중복 메시지 저장, 중복 TTS 재생을 방지한다.
7. 요청 실패 시 상태를 반드시 초기화하여 재시도가 가능해야 한다.
8. 오류를 무시하거나 빈 `catch`로 삼키지 않는다.
9. 사용자 화면에는 기술 스택이나 민감한 내부 오류를 노출하지 않고, 재시도 가능한 안내를 표시한다.
10. 기존 UI 디자인을 전면 변경하지 않는다.

## 5. 필수 구현 사항

### 5.1 단계별 진단 로그

개발 환경에서 아래 식별자를 포함하는 구조화 로그를 추가한다.

- `conversation_id` 또는 세션 식별자
- `turn_id`
- `child_id`는 전체 값을 출력하지 말고 마스킹
- 모드: `auto` 또는 `manual`
- 단계:
  - `recording_started`
  - `recording_stopped`
  - `audio_ready`
  - `stt_started`
  - `stt_completed`
  - `user_message_saved`
  - `llm_started`
  - `llm_completed`
  - `assistant_message_saved`
  - `tts_started`
  - `tts_completed`
  - `audio_play_started`
  - `audio_play_completed`
  - `turn_completed`
- 실패 시:
  - HTTP status
  - 내부 오류 코드
  - 실패 단계
  - 소요 시간
  - 재시도 가능 여부

음성 원본, 전체 전사문, 전체 아이 발화, 전체 모델 응답, 토큰, 키, 비밀번호는 로그에 기록하지 않는다. 프로덕션에서는 필요한 최소 오류 로그만 남긴다.

### 5.2 상태 머신 정상화

자유 대화 상태 전이를 코드에서 명확하게 관리한다.

권장 상태:

`idle → listening/recording → processing_stt → generating → synthesizing → playing → idle`

모든 성공·실패·취소·화면 이탈 경로에서 다음을 보장한다.

- 녹음 스트림 정리
- 타이머 정리
- 이벤트 리스너 정리
- AbortController 정리
- `isProcessing` 계열 상태 초기화
- 마이크와 버튼 상태 복원
- 중복 요청 잠금 해제

단순 boolean 조합으로 교착이 반복된다면 기존 구조를 크게 훼손하지 않는 범위에서 단일 상태 값 또는 reducer로 정리한다.

### 5.3 API 오류 처리

STT·LLM·TTS·DB 저장 단계 각각에서 다음을 구현한다.

- 명시적 timeout
- `response.ok` 확인
- 비정상 JSON·빈 응답 검증
- 단계별 오류 코드
- 안전한 사용자 안내
- 재시도 가능 상태 복귀
- 동일 턴 중복 저장 방지

STT 결과가 빈 문자열이거나 유효 발화가 없을 경우 LLM을 호출하지 말고, 사용자가 다시 말할 수 있도록 상태를 복구한다.

### 5.4 오디오 재생 안정화

- TTS 응답의 MIME type과 실제 디코딩 방식 일치 여부 확인
- Blob URL 생성·해제 시점 확인
- `audio.play()` Promise rejection 처리
- iOS Safari의 사용자 제스처 및 autoplay 제한 대응
- 재생 실패 시 텍스트 응답은 유지하고 마이크를 다시 사용할 수 있도록 복구
- 이전 오디오 재생 객체가 다음 턴을 막지 않도록 종료·정리

### 5.5 PWA·캐시 확인

수정 배포 후에도 이전 번들이 남아 장애가 지속되지 않도록 다음을 확인한다.

- service worker 업데이트 정책
- 캐시 버전
- 오래된 JS chunk 참조
- 강제 새로고침 없이도 신규 배포가 반영되는지
- 필요 시 기존 정책과 충돌하지 않는 안전한 캐시 갱신 처리

## 6. 검증 시나리오

개발 환경에서 아래 테스트를 먼저 완료하고, 모두 통과한 뒤 프로덕션에 동일 수정 사항을 배포한다.

### 6.1 자동 모드

1. 자유 대화 진입 후 자동 모드 선택
2. 3초 이상 정상 발화
3. 발화 종료 자동 감지
4. 사용자 발화가 한 번만 저장
5. 케이 텍스트 응답이 한 번만 생성
6. TTS가 한 번만 재생
7. 재생 후 다시 듣기 상태 복귀
8. 연속 5턴 성공
9. 짧은 발화·무음·주변 소음에서도 교착 없음
10. 케이 재생 중 사용자 발화 처리 정책이 기존 설계대로 동작

### 6.2 수동 모드

1. 수동 모드 선택
2. 녹음 시작
3. 사용자 발화
4. 녹음 종료
5. STT·LLM·TTS 정상 처리
6. 연속 5턴 성공
7. 빠른 시작·종료 반복에도 중복 요청 없음
8. 처리 중 버튼 중복 입력에도 중복 저장 없음

### 6.3 실패 복구

각 단계의 실패를 개발 환경에서 모의하거나 안전하게 재현한다.

- 마이크 권한 거부
- 0바이트 오디오
- STT timeout
- LLM 4xx·5xx 또는 빈 응답
- TTS 실패
- DB 저장 실패
- 오디오 재생 실패
- 화면 이탈
- 네트워크 일시 단절

모든 경우 사용자에게 재시도 가능한 안내가 나오고, 새로고침 없이 다음 시도가 가능해야 한다.

### 6.4 데이터 검증

- 사용자 메시지와 케이 메시지가 각 턴당 정확히 한 건씩 저장
- `turn_id` 연결 정상
- `display_sequence` 연속 유지
- 생성 시각과 역할 구분 정상
- Collection 대상 필드 유지
- 동일 턴 중복 레코드 없음
- 실패한 턴에 반쪽 데이터가 남는 경우 기존 정책에 따라 복구 또는 상태 표시

### 6.5 회귀 검증

- 미션 자동·수동 음성 기능 영향 없음
- Premium Gemini Live 기능 영향 없음
- 자유 대화 횟수·시간 제한 정책 유지
- 자유 대화 종료·복원 기능 유지
- Collection 1·2 수집 영향 없음
- Context Correction 및 Daily Report 입력 영향 없음
- 부모 화면과 관리자 화면 영향 없음

## 8. 배포 절차

1. 현재 개발 서버와 프로덕션 장애를 코드·로그·네트워크 기준으로 재현
2. 원인 확정
3. 수정
4. 로컬 정적 검사 및 테스트
5. 개발 서버 배포
6. 개발 DB에서 자동·수동·실패 복구·데이터 저장 검증
7. 관련 테스트 데이터 원상 복구
8. 회귀 검증
9. 프로덕션 배포
10. 프로덕션에서 실제 계정으로 자동·수동 각 3턴 스모크 테스트
11. 프로덕션 데이터 중복·오류 로그 확인
12. 결과 보고

프로덕션 DB를 직접 수정하거나 임의 테스트 데이터를 대량 생성하지 않는다. 필요한 테스트는 승인된 테스트 계정과 최소 데이터로 수행한다.
