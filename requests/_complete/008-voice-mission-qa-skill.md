## 현재 상태

대표님과 협의된 음성 미션 QA 기준은 다음과 같다.

### 유효 답변

질문과 관련된 답변이면 다음 경우도 유효 답변으로 인정한다.

- 짧은 답변
- 다소 애매하지만 질문과 관련된 답변
- 한두 단어로 된 답변

유효 답변이면:

1. 케이가 답변 내용에 맞게 자연스럽게 반응
2. 미션 진행률 10% 증가
3. 다음 질문으로 이동

추가 설명을 강제로 요구하거나 같은 질문을 다시 묻지 않는다.

### 유효하지 않은 답변

다음은 유효 답변으로 인정하지 않는다.

- 질문과 완전히 관련 없는 답변
- 명시적인 답변 거부
- 침묵 또는 무응답
- 의미를 파악할 수 없는 답변

처리 방식:

1. 같은 질문을 자연스럽게 한 번만 재질문
2. 재질문에도 유효 답변이 없으면 진행률을 올리지 않음
3. 다음 질문으로 이동

### 질문 순환 정책

미션은 유효 답변 10개를 받아야 완료된다.

질문 순서는 다음과 같다.

1. 기본 질문 10개 진행
2. 유효 답변이 부족하면 예비 질문 10개 진행
3. 그래도 부족하면 기본·예비 질문 중 미답변 문항만 순서대로 1회 순환
4. 그래도 부족하면 다음 최종 안내를 전달

```text
더 이상 준비된 질문지가 없어서 미션을 완료할 수 없어요. 다시 한번 질문을 진행할게요. 이번에도 답변 못하면 미션은 실패됩니다.
```

5. 최종 안내 후 남은 미답변 문항을 마지막으로 1회 순환
6. 마지막 순환 후에도 유효 답변이 10개 미만이면 미션 실패

유효 답변이 10개가 되는 즉시 남은 질문 수와 관계없이 미션을 완료한다.

### 음성 처리 상태

한 턴의 전체 흐름을 다음 순서로 검증한다.

```text
아이 발화
→ 음성 입력 종료
→ STT
→ LLM 응답 생성
→ TTS 생성
→ 실제 음성 재생
→ 다음 질문 대기
```

K 옆 상태 표시는 실제 처리 단계와 일치해야 한다.

```text
듣고 있어요
생각하고 있어요
말하고 있어요
```

### 응답 시간

다음 시간을 실제로 측정한다.

- 아이 발화 종료 시각
- STT 완료 시각
- LLM 응답 완료 시각
- TTS 생성 완료 시각
- 케이 음성 재생 시작 시각
- 케이 음성 재생 종료 시각

최소 핵심 지표:

```text
아이 발화 종료 → 케이 음성 재생 시작
```

응답 속도 합격 기준은 이 스킬에서 임의로 정하지 않는다.

측정값을 초 단위로 기록하고, 지연이 발생한 실제 단계를 구분해 보고한다.

### 2. QA 시작 전 정본 확인

QA 시작 전에 반드시 다음을 확인한다.

1. 대상 요청서의 요구사항
2. 현재 미션 정책
3. 현재 배포 커밋
4. 테스트할 Dev URL
5. 테스트 계정
6. 기존 미션 세션과 진행률
7. 질문 20개 구성 상태
8. 테스트 후 복구가 필요한 데이터

코드만 보고 실동작을 추측하지 않는다.

### 3. 턴별 테스트 매트릭스

최소 다음 입력 유형을 각각 검증한다.

| 유형 | 예시 | 유효 답변 | 기대 처리 |
|---|---|---:|---|
| 정상적인 관련 답변 | 질문에 구체적으로 답함 | 예 | 관련 반응, 10% 증가, 다음 질문 |
| 짧은 관련 답변 | 응, 좋아, 친구랑 놀았어 | 예 | 관련 반응, 10% 증가, 다음 질문 |
| 애매하지만 관련된 답변 | 그냥 그랬어 | 예 | 유효 처리, 10% 증가, 다음 질문 |
| 완전히 엉뚱한 답변 | 질문과 무관한 주제 | 아니요 | 1회 재질문 후 다음 문항 |
| 명시적 거부 | 말하기 싫어 | 아니요 | 1회 재질문 후 다음 문항 |
| 침묵·무응답 | 발화 없음 | 아니요 | 1회 재시도 후 다음 문항 |
| 인식 불가능 | 의미를 파악할 수 없음 | 아니요 | 1회 재질문 후 다음 문항 |

각 턴에서 확인할 항목:

- 아이 발화가 한 번만 제출됐는가
- STT 결과가 실제 발화와 일치하는가
- 유효·무효 분류가 정책과 일치하는가
- 케이 반응이 아이 답변 내용과 관련 있는가
- 진행률이 정확히 증가하거나 유지되는가
- 같은 질문을 두 번 넘게 재질문하지 않는가
- 다음 질문이 중복되지 않는가
- 질문 순서가 정책대로 유지되는가

### 4. 진행률 검증

유효 답변 수와 진행률은 반드시 일치해야 한다.

```text
유효 답변 0개 = 0%
유효 답변 1개 = 10%
유효 답변 2개 = 20%
...
유효 답변 9개 = 90%
유효 답변 10개 = 100% 및 미션 완료
```

유효하지 않은 답변에서는 진행률이 증가하면 안 된다.

같은 답변의 중복 제출로 진행률이 두 번 증가하면 안 된다.

### 5. 질문 풀 검증

신규 미션 시작 시 다음을 확인한다.

```text
기본 질문 10개
예비 질문 10개
총 20개
```

검증 항목:

- 기본 질문 10개 존재
- 예비 질문 10개 존재
- 동일 질문 중복 없음
- 세션에 질문 순서 저장
- 이어하기에서 기존 질문 순서 유지
- 앱 재접속 시 질문 풀이 사라지지 않음
- 9/10 상태에서도 다음 질문 존재
- 질문 부족을 연결 장애로 표시하지 않음

### 6. 질문 순환 E2E

다음 전체 시나리오를 반드시 실행한다.

#### 시나리오 A — 기본 질문만으로 완료

- 기본 질문 10개에 모두 유효 답변
- 매 답변마다 10% 증가
- 10번째 답변 직후 완료

#### 시나리오 B — 예비 질문 사용

- 기본 질문 일부를 거부하거나 무응답
- 기본 질문 종료 후 예비 질문으로 이동
- 유효 답변 10개가 되면 즉시 완료

#### 시나리오 C — 미답변 문항 1차 순환

- 기본·예비 질문 20개 종료 시 유효 답변 10개 미만
- 미답변 문항만 추출
- 미답변 문항을 원래 순서대로 1회 재진행
- 이미 유효 답변을 받은 문항은 다시 질문하지 않음

#### 시나리오 D — 최종 순환

- 1차 미답변 순환 후에도 유효 답변 10개 미만
- 확정된 최종 안내 문구 출력
- 남은 미답변 문항을 마지막으로 1회 진행
- 유효 답변 10개가 되면 완료
- 마지막에도 10개 미만이면 실패

#### 시나리오 E — 이어하기

- 일부 질문 진행 후 앱 종료
- 같은 세션으로 재접속
- 유효 답변 수와 진행률 유지
- 사용한 질문·남은 질문 유지
- 현재 질문 또는 정확한 다음 질문부터 재개
- 첫 질문이나 0%로 초기화되지 않음

### 7. 케이 반응 검증

유효 답변을 받으면 케이는:

1. 아이가 말한 내용에 맞는 짧고 자연스러운 반응
2. 다음 고정 질문 1개

순서로 말한다.

금지:

- 아이 답변과 관련 없는 상투적 반응만 출력
- 다음 질문을 두 개 이상 출력
- 이미 답한 질문 반복
- 아이가 답했는데 답하지 않은 것으로 처리
- 아이 답변을 임의로 왜곡
- 진행률 증가 전에 다음 질문으로 넘어가 데이터 저장 누락

유효하지 않은 답변에서는 아이를 혼내거나 압박하지 않는다.

### 8. 상태 표시 검증

상태 표시는 실제 이벤트에 연결해야 한다.

#### 듣고 있어요

- 마이크 입력을 실제로 받고 있을 때만 표시
- 케이 음성 재생 중에는 표시하지 않음

#### 생각하고 있어요

- 아이 발화가 종료되고 STT·LLM·TTS 처리 중일 때 표시
- 케이 음성 재생이 시작되면 종료

#### 말하고 있어요

- 실제 오디오 재생 시작 시 표시
- 실제 오디오 재생 종료 시 해제

검증 항목:

- 상태 순서가 뒤바뀌지 않음
- 상태가 영구 고정되지 않음
- 실제 처리보다 먼저 다음 상태를 표시하지 않음
- 실패 후에도 잘못된 상태가 남지 않음
- 다음 턴에서 다시 `듣고 있어요`로 복귀

### 9. 연결 경고 검증

정상적인 대화 중에는 상단에 다음 경고가 불필요하게 표시되면 안 된다.

```text
연결 불안정
연결 다소 불안정
```

단순한 시간 경과만으로 경고를 표시하지 않는다.

다음 근거를 구분해 기록한다.

- 실제 단계 실패
- API 오류
- timeout
- 오디오 재생 실패
- 단순 응답 지연
- UI 상태 판단 오류

대화가 정상적으로 계속되는 상황에서 경고가 나오면 `FAIL`이다.

### 10. 결과 판정

각 시나리오는 다음 중 하나로만 판정한다.

```text
PASS
FAIL
BLOCKED
NOT TESTED
```

실행하지 않은 시나리오를 PASS로 처리하지 않는다.

필수 시나리오에 `FAIL`, `BLOCKED`, `NOT TESTED`가 하나라도 있으면 전체 QA를 PASS로 보고하지 않는다.

```text
실제 결과
PASS/FAIL/BLOCKED/NOT TESTED
```

### 12. 테스트 계정

자동 QA는 전용 QA 계정만 사용한다.

```text
부모: QA테스트
자녀: QA테스트(5학년)
```

실제 가족 계정은 자동 테스트에 사용하지 않는다.

금지:

- 김서아·김서현 자동 로그인
- 비밀번호 변경
- 세션 삭제
- 프로필 변경
- 황금열쇠 변경
- 미션 데이터 초기화

실제 가족 계정은 대표님 수동 확인용으로만 남긴다.

### 13. 대표님 확인 항목

자동 QA 완료 후 대표님에게는 최대 5개만 전달한다.

형식:

```text
[대표님 확인 필요]

1. 접속 위치
2. 사용할 계정
3. 말할 내용
4. 정상적으로 보여야 할 결과
5. 문제가 생기면 캡처할 화면
```

장문의 내부 테스트 로그를 대표님 확인사항에 그대로 붙이지 않는다.

## 작업 및 리뷰 방식

- 먼저 현재 저장소의 기존 스킬 구조와 공식 형식을 확인한다.
- 1차 작성은 agy 또는 메인 Claude Code가 수행한다.
- 메인 Claude Code가 직접 작성하거나 수정하면 별도 `claude-review`가 읽기 전용 검증한다.
- 스킬 본문이 지나치게 길어지면 상세 테스트 표는 `references/`로 분리한다.

- dry run은 코드·DB를 변경하지 않는 읽기 전용으로 수행한다.
