# 031 — 부모용 주간 리포트 목록 및 과거 주간 이력 달력 개편

## 1. 작업 목적

부모 화면의 주간 리포트 목록을 첨부 레퍼런스 이미지의 정보 구조와 디자인을 기준으로 전면 개편한다.

이번 개편의 핵심은 다음과 같다.

- 주간 리포트의 한 주 기준을 `토요일부터 금요일`로 명확하게 표시한다.
- 현재 진행 중인 이번 주 집계 상태를 목록 최상단에서 보여준다.
- 가장 최근에 완성된 지난주 리포트는 전체 너비의 대표 카드로 강조한다.
- 그 이전의 완료된 주간 리포트는 2열 카드로 간결하게 보여준다.
- 기본 화면에는 현재 집계 중인 주와 최근 완료된 주간 리포트 최대 5개만 표시한다.
- 더 오래된 기록은 기본 목록에 누적하지 않는다.
- `지난 기록 보기`를 누르면 날짜 단위 달력이 아니라 `주간 리포트 단위 달력`을 표시한다.
- 달력의 각 행은 토요일부터 금요일까지 한 주를 의미한다.
- 완료된 주간 리포트가 있는 주를 선택하면 해당 주간 리포트 상세로 이동한다.
- 아이와 케이의 대화 원문은 목록과 달력에 노출하지 않는다.
- 기존 일간 리포트 화면과 부모용 하단 Navigation은 유지한다.
- 스마트폰 외곽 프레임과 상태 표시줄은 구현하지 않는다.

# 2. 주간 리포트 기간 기준

## 한 주 정의

주간 리포트의 한 주는 다음 기준으로 확정한다.

```text
토요일 00:00:00 KST
~
금요일 23:59:59 KST
```

예시:

```text
2026년 7월 18일 토요일
~
2026년 7월 24일 금요일
```

화면에서는 다음처럼 표시한다.

```text
7월 18일~24일
```

월을 걸치는 경우 시작 월과 종료 월을 모두 표시한다.

```text
6월 27일~7월 3일
```

## 시간대

- 모든 주간 경계 계산은 KST 기준으로 처리한다.
- DB의 timestamp가 UTC라면 KST로 변환한 뒤 주간 범위를 결정한다.
- 브라우저 로컬 시간대에 따라 주간 범위가 달라지지 않도록 한다.
- 금요일 자정 전후 데이터가 다음 주로 잘못 포함되지 않도록 검증한다.

# 3. 기본 목록 표시 범위

주간 탭 진입 시 기본적으로 다음 항목만 표시한다.

1. 현재 집계 중인 이번 주 상태 카드 1개
2. 가장 최근에 완료된 지난주 리포트 1개
3. 그 이전에 완료된 주간 리포트 최대 4개

즉 기본 화면의 최대 구성은 다음과 같다.

```text
현재 집계 중인 주 1개
+
완료된 주간 리포트 최대 5개
```

오래된 주간 리포트를 화면 아래에 계속 누적하거나 무한 스크롤로 불러오지 않는다.

과거 리포트는 `지난 기록 보기`에서 달력을 통해 탐색한다.

완료된 리포트가 5개보다 적으면 존재하는 리포트만 표시하고 임의 데이터를 만들지 않는다.

# 6. 전체 레이아웃

## 기본 구조

- 모바일 우선
- 최소 높이 `100dvh`
- 화면 너비 `100%`
- 콘텐츠 영역 세로 스크롤 허용
- 가로 스크롤 금지
- 부모용 하단 Navigation 유지
- 하단 Navigation 높이와 safe-area만큼 콘텐츠 하단 여백 확보
- 태블릿·PC에서는 최대 콘텐츠 너비 약 `430px~520px`
- 태블릿·PC에서는 중앙 정렬
- 부모 화면은 아이 화면보다 장식이 적고 정보 중심으로 구성

## 배경

- 매우 연한 Warm Neutral 또는 연한 Sky 계열 배경
- 카드 배경은 흰색
- 전체 화면에 과도한 그라데이션 사용 금지
- 기존 Design System v2의 `background-page`, `background-surface` 토큰 우선 사용

# 7. 상단 헤더

기존 부모 공통 헤더를 재사용한다.

## 구성

왼쪽:

- 공식 내친구 케이 가로형 로고

오른쪽:

- 선택된 자녀 이름
- 자녀 선택 드롭다운 아이콘
- 알림 버튼

## 자녀 전환

자녀를 변경하면 다음 항목이 모두 새로운 자녀 기준으로 갱신되어야 한다.

- 현재 주 집계 상태
- 현재 주 대화 횟수
- 최근 완료된 주간 리포트
- 과거 주간 리포트 목록
- 달력의 주간 리포트 상태
- 선택된 주간 리포트
- 선택 월의 주간 리포트 개수

자녀 변경 직후 이전 자녀의 리포트를 화면에서 제거하고 Skeleton 또는 Loading 상태로 전환한다.

Query cache와 상태 관리 key에는 반드시 `child_id`를 포함한다.

# 8. 일간·주간 탭

## 구성

```text
일간
주간
```

## 기본 상태

이 화면에서는 `주간`을 활성화한다.

## 동작

- 일간: 기존 최근 7일 일간 리포트 화면
- 주간: 이번 요청의 주간 리포트 목록

일간 화면의 목록·달력·데이터 로직은 변경하지 않는다.

## 디자인

활성 주간 탭:

- K-Navy 배경
- 흰색 텍스트
- 달력 아이콘
- 굵기 600~700

비활성 일간 탭:

- 연한 Neutral 배경
- K-Navy 텍스트
- 일간을 의미하는 아이콘

## 접근성

- `role="tablist"`
- 각 탭에 `role="tab"`
- `aria-selected`
- 키보드 방향키 이동
- 활성 상태를 색상 외에 텍스트 및 속성으로 전달

# 9. 현재 집계 중인 이번 주 카드

주간 탭의 첫 번째 요소로 현재 진행 중인 주의 집계 상태를 표시한다.

## 기간

실제 현재 날짜가 속한 토요일부터 금요일까지의 기간을 표시한다.

예시:

```text
7월 25일~31일
```

## Badge

```text
이번 주
```

## 집계 상태

예시:

```text
집계 중 · 4일째 · 대화 2회
```

## 완료 예정 안내

예시:

```text
금요일 밤에 완성돼요
```

실제 주간 리포트 생성 정책과 일치하는 문구를 사용한다.

리포트 생성 시각이 금요일 밤으로 설정되어 있지 않다면 UI를 맞추기 위해 임의로 해당 문구를 하드코딩하지 않는다.

## 데이터 연결

다음 값은 실제 데이터와 연결한다.

- 현재 주 시작일
- 현재 주 종료일
- 현재 주 진행 일수
- 현재 주 대화 횟수
- 주간 리포트 집계 상태
- 예상 완료 시점

## 진행 일수

토요일을 1일째로 계산한다.

예시:

```text
토요일: 1일째
일요일: 2일째
월요일: 3일째
화요일: 4일째
수요일: 5일째
목요일: 6일째
금요일: 7일째
```

KST 날짜를 기준으로 계산한다.

## 대화 횟수

- 기존 주간 리포트에서 사용하는 정본 집계 기준을 확인한다.
- 세션 수, 미션 수, 자유대화 수, 메시지 수 중 임의로 선택하지 않는다.
- 기존 서비스에서 `대화 횟수`로 정의한 값과 동일한 기준을 사용한다.
- 중복 transcript나 재연결 세션을 여러 회로 계산하지 않는다.

## 디자인

- 흰색 또는 매우 연한 Sky 배경
- 점선 또는 얇은 dashed border
- radius 약 `14px~18px`
- 그림자는 최소화
- 집계 중 Hourglass 아이콘
- 기간과 상태는 K-Navy
- 보조 안내는 Neutral 텍스트
- 완료된 리포트 카드보다 낮은 시각적 우선순위

## 클릭 동작

아직 완성되지 않은 이번 주 카드는 기본적으로 상세 리포트 링크로 사용하지 않는다.

현재 집계 중인 데이터를 보여주는 별도 Preview 화면이 기존에 실제로 존재할 때만 연결한다.

Preview가 없다면 버튼처럼 보이지 않게 한다.

# 10. 이번 주 데이터가 없는 경우

현재 주에 대화가 한 번도 없는 경우에도 집계 카드는 유지한다.

예시:

```text
집계 중 · 4일째
아직 이번 주 대화가 없어요
```

또는:

```text
아이가 케이와 이야기하면 주간 리포트에 반영돼요
```

`대화 0회`를 오류처럼 강하게 표시하지 않는다.

# 11. 지난주 대표 리포트 카드

현재 집계 중 카드 아래에 가장 최근 완료된 주간 리포트를 전체 너비로 표시한다.

## 기간

예시:

```text
7월 18일~24일
```

## Badge

가장 최근에 완료된 주인 경우 다음 Badge를 표시한다.

```text
지난주
```

## 상태 문구

카드 우측 상단에 상태점과 부모용 상태 문구를 표시한다.

예시:

```text
● 살펴볼 점이 있어요
```

```text
● 편안한 한 주였어요
```

```text
● 평소와 비슷했어요
```

## 핵심 요약

주간 리포트의 가장 중요한 흐름을 한 문장으로 표시한다.

예시:

```text
친구 이야기에서 속상함이 늘었어요
```

위 문구는 예시이며 실제 주간 리포트의 정본 요약 필드를 사용한다.

## 주제 태그

하단에 실제 주간 핵심 키워드 또는 관심사 태그를 최대 2개 표시한다.

예시:

```text
[로블록스] [친구]
```

## 디자인

- 전체 너비
- 흰색 배경
- radius 약 `16px~20px`
- 얇은 Neutral 테두리
- 이전 주 카드보다 약간 강한 그림자
- 기간·요약 제목 K-Navy
- Badge는 K-Mascot Orange 또는 상태에 맞는 토큰 사용
- 카드 전체 클릭 가능
- 터치 영역 최소 44px 이상

# 12. 과거 주간 리포트 2열 카드

지난주 대표 카드 아래에는 그 이전 완료 리포트 최대 4개를 2열 Grid로 표시한다.

## 카드 구성

각 카드에는 다음 정보만 표시한다.

1. 기간
2. 상태점과 상태 문구
3. 핵심 요약
4. 주제 태그 최대 2개

예시:

```text
7월 11일~17일

● 살펴볼 점이 있어요
친구 이야기에서 속상함이 늘었어요

[로블록스] [친구]
```

## 표시하지 않는 정보

완료된 주간 리포트 카드에는 다음 정보를 추가하지 않는다.

- 대화 횟수
- 생성 시각
- 오전·오후·저녁
- 미션 횟수
- 자유대화 횟수
- 마지막 확인 시점
- 카드 하단 Metadata 행

현재 주 집계 카드의 `대화 2회`는 진행 상황 정보이므로 유지하지만, 완료 리포트 카드에는 반복 표시하지 않는다.

## 디자인

- 2열 Grid
- 카드 간 간격 약 `8px~12px`
- 동일한 높이를 기본으로 유지
- 카드 최소 높이 약 `150px~180px`
- 흰색 배경
- 얇은 Neutral 테두리
- radius 약 `14px~18px`
- 약한 그림자
- 카드 하단에 태그 배치
- 태그가 카드 아래쪽에 정렬되도록 내부 Flex 구조 사용 가능

## 작은 화면

320px 폭 또는 접근성 글꼴 확대 시 텍스트가 겹치면 1열로 전환한다.

텍스트를 과도하게 축소하거나 핵심 요약을 숨기지 않는다.

---

# 13. 주간 리포트 상태 체계

상태는 아이를 진단하거나 평가하는 표현이 아니라 부모가 대화 방향을 잡도록 돕는 수준으로 제한한다.

## `살펴볼 점이 있어요`

최근 주간 흐름에서 부모가 부담 없이 한 번 더 대화해 볼 주제가 있는 경우

- K-Mascot Orange 상태점
- 추궁이나 위험 경고로 보이지 않게 표현

## `편안한 한 주였어요`

긍정적이거나 편안한 흐름이 주로 나타난 경우

- K-Sky Blue 상태점

## `평소와 비슷했어요`

이전 흐름과 비교해 뚜렷한 변화가 크지 않은 경우

- Neutral 또는 연한 Blue 상태점

## `데이터가 아직 적어요`

주간 분석에 필요한 데이터가 부족한 경우

- Neutral 상태점
- 리포트가 정상 생성됐더라도 데이터가 적다는 사실을 명확히 표시

## 금지 표현

실제 전문적 진단 없이 다음과 같이 표시하지 않는다.

- 위험해요
- 문제가 있어요
- 불안 장애
- 우울 상태
- 친구 관계 이상
- 학교 부적응
- 심각합니다

# 14. 핵심 요약 문구 기준

각 카드의 핵심 요약은 실제 주간 리포트의 요약 필드를 사용한다.

가능한 정본 데이터 우선순위:

1. 주간 리포트 대표 요약
2. 주간 변화 신호 요약
3. 부모 전달 메시지의 요약형 문구
4. 기존 주간 리포트 카드용 Summary

목록 UI를 채우기 위해 클라이언트에서 LLM을 새로 호출하지 않는다.

아이와 케이의 raw 대화 원문을 직접 표시하지 않는다.

아이의 발화를 긴 문장으로 직접 인용하지 않는다.

# 15. 태그 표시 기준

4. 기존 정규화된 Category

# 18. 주간 리포트 생성 실패 상태

운영 재처리 후 정상 리포트가 생성되면 자동으로 완료 상태로 갱신한다.

# 20. 주간 이력 달력의 핵심 원칙

이 달력은 일반적인 날짜 선택 달력이 아니다.

각 행 전체가 하나의 주간 리포트 기간을 의미한다.

요일 순서는 다음과 같이 고정한다.

```text
토  일  월  화  수  목  금
```

한 행 예시:

```text
18  19  20  21  22  23  24
```

위 행은 다음 주간 리포트를 의미한다.

```text
7월 18일 토요일
~
7월 24일 금요일
```

개별 날짜가 아니라 행 전체를 주간 리포트 선택 단위로 사용한다.

# 23. 월별 주간 행 생성 기준

선택 월에 표시할 주간 행은 다음 기준으로 생성한다.

```text
해당 주의 금요일인 week_end_date가 선택 월에 포함되는 주
```

예를 들어 2026년 7월 화면에는 다음 주가 포함될 수 있다.

```text
6월 27일~7월 3일
7월 4일~10일
7월 11일~17일
7월 18일~24일
7월 25일~31일
```

첫 번째 행의 토요일부터 화요일까지는 6월 날짜지만, 주 종료일인 7월 3일이 7월에 포함되므로 7월 화면에 표시한다.

같은 주간 리포트를 6월과 7월 양쪽에 중복 표시하지 않는다.

주간 리포트의 소속 월은 `week_end_date`인 금요일의 월을 기준으로 한다.

# 24. 달력 주간 행 디자인

각 주간 행은 둥근 사각형 Row로 표시한다.

## 기본 행

- 흰색 배경
- Neutral 테두리
- 토요일부터 금요일까지 7개 날짜를 동일 간격 배치
- 최소 터치 높이 48px 이상

## 선택된 주

- 매우 연한 K-Sky Blue 배경
- 왼쪽에 K-Navy 강조선
- 행 전체에 선택 상태 적용
- `aria-selected="true"`

## 월 밖 날짜

예: 7월 화면의 `6월 27일~30일`

- 연한 Neutral 텍스트
- 같은 주간 Row에는 포함
- 개별 날짜는 비활성 버튼으로 만들지 않고 행 전체가 선택 단위

## 미래 날짜

미래 날짜가 포함된 진행 중 주는 흐린 Neutral 색상으로 표시할 수 있다.

단 현재 집계 중인 주의 행 자체는 진행 상태 확인을 위해 표시한다.

# 25. 주간 상태 Marker

상태 Marker는 해당 주의 종료일인 금요일 칸에 표시한다.

## 완료·편안한 흐름

- K-Sky Blue 점

## 완료·살펴볼 점 있음

- K-Mascot Orange 점

## 완료·평소와 비슷함

- Neutral 또는 연한 Blue 점

## 집계 중

- Hourglass 아이콘

## 리포트 없음

- Marker 없음

## 생성 실패

- state-warning 또는 작은 경고 아이콘
- 부모에게 과도한 위험 경고처럼 보이지 않도록 함

Marker만으로 상태를 전달하지 않고 행의 접근성 이름에 상태를 포함한다.

예시:

```text
2026년 7월 18일부터 24일까지, 주간 리포트 있음, 살펴볼 점이 있어요
```

# 26. 달력 행 선택 동작

## 완료된 리포트가 있는 주

행 전체를 선택 가능하게 한다.

클릭 시:

1. 선택 행 강조
2. 해당 주간 리포트 ID 확인
3. Bottom Sheet 닫기
4. 기존 주간 리포트 상세 화면으로 이동
5. 선택한 주의 리포트 표시

## 현재 집계 중인 주

- 상세 Preview가 존재하지 않으면 상세 이동 금지
- `집계 중` 상태만 접근성 정보로 전달
- 클릭 가능한 완료 리포트처럼 보이지 않게 함

## 리포트 없는 주

- 기본적으로 선택 불가
- `주간 리포트 없음` 접근성 정보 제공

## 생성 실패 주

기존 오류 상세 또는 안내 화면이 있으면 연결한다.

없다면 행 선택 시 다음 안내를 표시할 수 있다.

```text
이 주의 리포트를 아직 준비하지 못했어요.
잠시 후 다시 확인해 주세요.
```

---

# 27. 달력 하단 월 요약

달력 아래에 선택 월의 완료된 주간 리포트 개수를 표시한다.

예시:

```text
7월 · 주간 리포트 4개
```

## 집계 기준

- `week_end_date`가 선택 월에 속한 완료 상태의 주간 리포트만 계산
- 현재 집계 중인 주는 완료 개수에서 제외
- 생성 실패 리포트는 완료 개수에서 제외
- 동일 주 중복 버전은 정본 리포트 1개로 계산

## 안내 문구

```text
토요일부터 금요일까지를 한 주로 봐요
```

위 문구는 달력 하단에 고정적으로 표시한다.

---

# 28. 달력 데이터 조회

달력을 열 때 모든 주간 리포트 본문을 조회하지 않는다.

월별 달력에는 다음 최소 Metadata만 사용한다.

```text
weekly_report_id
child_id
week_start_date
week_end_date
status
summary_state
created_at
completed_at
```

상세 본문은 사용자가 완료된 주를 선택한 뒤 조회한다.

## 성능 원칙

- 월 변경 시 해당 월 주간 Metadata만 조회
- 자녀별·연도별·월별 Query cache 분리
- 이미 조회한 월은 cache 재사용 가능
- 이전 월 요청이 늦게 도착해 현재 월 데이터를 덮지 않도록 Stale Response 차단
- 달력 열기만으로 LLM 호출 금지
- Raw Transcript 조회 금지
- 전체 상세 리포트 일괄 다운로드 금지

# 29. 월 경계 및 연도 경계 처리

다음 경우를 정확하게 처리한다.

## 월 경계

6월 27일~7월 3일
```

7월 주간 리포트로 분류한다.

## 연도 경계

2026년 12월 26일~2027년 1월 1일
```

2027년 1월 주간 리포트로 분류한다.

## 윤년

2월 29일이 포함된 주를 정상 계산한다.

## 주간 범위 생성

클라이언트와 서버에서 서로 다른 주간 범위를 계산하지 않도록 공통 날짜 유틸리티 또는 서버 정본 기준을 사용한다.

# 30. 일간 리포트와 주간 리포트 분리

일간 탭과 주간 탭은 동일한 리포트 화면 안에 존재하지만 데이터와 탐색 단위는 분리한다.

## 일간

# 36. 아이·부모·사업 관점 기준

## 아이 관점

- 아이와 케이의 대화 원문을 부모 목록에 노출하지 않는다.
- 친구 이름, 선생님 이름, 학교명 등 민감한 직접 식별 정보를 카드에 표시하지 않는다.
- 한 번의 대화를 아이의 지속적인 문제로 단정하지 않는다.
- 부모가 아이를 추궁하게 만드는 문구를 사용하지 않는다.

## 부모 관점

- 현재 주가 아직 완성되지 않았다는 사실을 명확하게 이해할 수 있어야 한다.
- 지난주와 이전 기록의 중요도를 한눈에 구분할 수 있어야 한다.
- `살펴볼 점`은 위험 경고가 아니라 자연스러운 대화의 힌트로 표현한다.
- 오래된 기록은 목록을 끝없이 스크롤하지 않고 달력으로 쉽게 찾을 수 있어야 한다.

## 사업·운영 관점

- 기존 생성된 주간 리포트를 재사용해 추가 LLM 비용을 발생시키지 않는다.
- 주간 생성 실패와 집계 중 상태를 구분해 운영 문의를 줄인다.
- 플랜별 최종 리포트 보존 기간을 준수한다.
- UI 개편을 이유로 리포트 생성 배치나 데이터 구조를 임의 변경하지 않는다.

# 37. 보안 및 권한

부모는 본인과 연결된 자녀의 주간 리포트만 조회할 수 있어야 한다.

서버 또는 RLS에서 다음을 검증한다.

- 로그인한 부모 사용자
- 선택된 `child_id`
- 부모와 자녀의 연결 관계
- 주간 리포트 소유 관계
- 플랜별 리포트 접근 및 보존 기간
- 상세 리포트 ID 접근 권한

## 금지

- 클라이언트의 `child_id` 변경만으로 다른 가정 데이터 조회
- 주간 리포트 ID 직접 변경으로 무단 조회
- 달력 Metadata를 통한 다른 아이의 리포트 날짜 노출
- API 응답에 Raw Transcript 포함
- 브라우저 Console에 민감한 리포트 전체 출력
- 다른 자녀의 Query cache 혼입

# 38. 플랜별 보존 기간

- 삭제된 Raw 데이터를 이용해 과거 리포트를 클라이언트에서 재생성하지 않는다.

- 플랜이 변경된 경우 기존 최종 리포트 접근 정책을 현재 서비스 정본 기준에 맞춘다.

- 이전 완료 리포트 최대 4개가 2열로 표시됨
- 기본 목록에는 완료 주간 리포트 최대 5개만 표시됨
- 완료 카드에는 대화 횟수·시간·생성 시각 Metadata가 표시되지 않음
- 상태 문구와 핵심 요약이 실제 주간 리포트와 연결됨
- 태그가 실제 주간 데이터와 연결됨
- Raw 대화 원문이 표시되지 않음
- 과거 리포트가 기본 목록에 무한 누적되지 않음
- `지난 기록 보기` 클릭 시 주간 단위 달력이 열림
- 달력 요일 순서가 토요일부터 금요일임
- 달력 한 행이 하나의 주간 리포트 기간으로 동작함
- 월 경계 주간이 금요일 기준 월에 한 번만 포함됨
- 완료 주 선택 시 해당 주간 리포트 상세로 이동함
- 집계 중 주와 리포트 없는 주가 완료 주처럼 선택되지 않음
- 선택 월의 완료 주간 리포트 개수가 정확함
- `토요일부터 금요일까지를 한 주로 봐요` 안내가 표시됨
- 선택된 자녀 데이터만 표시됨
- 부모·자녀 권한이 서버 또는 RLS에서 검증됨
- 기존 일간 리포트 화면이 정상 유지됨
- 기존 주간 생성 배치와 상세 화면에 회귀가 없음
- 부모용 하단 Navigation이 유지됨
- 모바일·태블릿·PC QA 통과
- 접근성 검증 통과
- lint 통과
- typecheck 통과
