# Request: 관리자 미션 푸시 발송 테스트 대상 선택 UX 개선

## 목적

현재 관리자 페이지의 "미션 푸시 발송 테스트" 기능은 아이 UUID를 직접 입력해야 테스트할 수 있어 운영자가 사용하기 어렵습니다.

관리자 운영 화면에서는 UUID 입력 방식이 아닌 사용자 검색 및 선택 방식으로 변경합니다.

---

# 1. 기존 방식 제거

현재:

```
테스트할 아이 계정 ID (UUID)

[ UUID 입력창 ]

[미션 1 즉시 발송]
[미션 2 즉시 발송]
```

변경:

- UUID 직접 입력 방식 제거
- UUID 입력 필드 제거


---

# 2. 사용자 검색 버튼 추가

변경 UI:

```
테스트 대상 아이

[선택된 아이 이름/아이디 표시 영역]

[아이 검색]
```


동작:

"아이 검색" 버튼 클릭 시 사용자 선택 모달 표시


---

# 3. 아이 선택 모달 구현

모달 제목:

```
푸시 테스트 대상 선택
```


검색 영역:

```
[이름 또는 아이디 검색]
```


리스트 표시:

컬럼:

| 항목 |
|---|
| 아이 이름 |
| 로그인 아이디 |
| 학년 |
| 부모 계정 |


예:

```
안서아
asa160202
4학년
markanitp@gmail.com


안서현
ash160202
4학년
markanitp@gmail.com
```


---

# 4. 선택 동작

관리자가 아이 선택:

1. 모달 닫힘
2. 선택한 아이 정보 표시


예:

```
선택된 아이

안서아 (asa160202)
```


이후:

```
[미션 1 즉시 발송]
[미션 2 즉시 발송]
```

버튼 활성화


---

# 5. 발송 API 변경

기존:

```
UUID 직접 입력 → API 호출
```


변경:

```
아이 선택
→ child_id 전달
→ 기존 푸시 발송 로직 실행
```


주의:

- 기존 실제 푸시 발송 로직 변경 금지
- 대상 선택 UX만 변경
- child_id 기준으로 처리


---

# 6. UX 요구사항

- UUID 노출 금지
- 운영자가 이름 기준으로 쉽게 찾을 수 있어야 함
- 검색 가능해야 함
- 선택 완료 후 대상 확인 가능해야 함
- 잘못 선택 방지를 위해 선택된 아이 이름/아이디 표시


---

# 7. 검증

확인:

1. 관리자 페이지 접속 정상
2. UUID 입력창 제거 확인
3. 아이 검색 버튼 노출 확인
4. 검색 모달 정상 동작
5. 이름/아이디 검색 가능
6. 아이 선택 후 미션1 발송 가능
7. 아이 선택 후 미션2 발송 가능
8. 기존 푸시 발송 기능 영향 없음


---

# 완료 기준

관리자는 UUID를 몰라도:

```
아이 검색
→ 아이 선택
→ 미션1/미션2 즉시 발송 테스트
```

가 가능해야 한다.
