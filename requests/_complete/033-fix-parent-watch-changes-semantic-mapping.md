# 부모가 주의 깊게 볼 변화 오분류 제거 및 반복 이야기 매핑 분리

## 0. 완료 시 기대 결과 / 대표님 테스트 정상 프로세스

### 완료 시 기대 결과
부모 `리포트 > 일간/주간 > 추천 가이드`에서 `recurring_stories` 값이 더 이상 `부모가 주의 깊게 볼 변화`로 노출되지 않는다.

현재 잘못된 예:
```text
👁️ 부모가 주의 깊게 볼 변화
지금은 방학이라 학교에 가지 않는다는 점과 미션이 안 끝난다는 이야기를 반복했습니다.
```

수정 후:
- `부모가 주의 깊게 볼 변화` 카드는 현재 시점에서는 숨김
- `recurring_stories`는 해당 카드에 절대 바인딩하지 않음
- 앱/미션/UI 오류·진행 불만은 부모 리포트 분석에서 제외
- 기존 정상 리포트/다른 카드에는 영향 없음

### 대표님 테스트 정상 프로세스
1. 부모 계정 로그인
2. `리포트 > 일간` 진입
3. `자세히 보기 > 추천 가이드` 선택
4. 기존 `부모가 주의 깊게 볼 변화` 카드가 사라졌는지 확인
5. `방학`, `게임`, `미션이 안 끝남` 같은 단순 반복 정보가 변화 카드로 표시되지 않는지 확인
6. 다른 추천 가이드 카드가 정상 표시되는지 확인
7. 주간 리포트와 지난 이력보기에서도 동일하게 확인

PASS:
- 잘못된 변화 카드 미노출
- recurring_stories와 변화 카드 연결 제거
- 앱/미션 시스템 불만 미노출
- 빈 카드/불필요한 여백 없음

## 1. 상태 / 우선순위
- 상태: 신규 수정
- 우선순위: HIGH
- 대상: 부모 리포트 추천 가이드
- 직접 원인: UI semantic mapping 오류
- 구조적 원인: 실제 변화(Delta) 분석 데이터가 없는 상태에서 recurring_stories를 변화 카드로 사용

## 2. 확인된 Root Cause

Production 진단 결과:

```text
Source Data
→ 정상

Prompt
→ recurring_stories = 당일 반복 이야기

LLM
→ 반복 이야기를 정상 생성

DB
→ daily_reports.recurring_stories에 정상 저장

API
→ 정상 전달

UI
→ recurring_stories를
   "👁️ 부모가 주의 깊게 볼 변화"로 잘못 표시
```

즉 LLM이 `변화`를 잘못 생성한 것이 아니라, UI가 `반복 이야기` 데이터를 `부모가 주의 깊게 볼 변화`라는 다른 의미의 카드에 잘못 연결한 것이 직접 원인이다.

---

## 3. 핵심 수정 1 — 잘못된 매핑 제거

다음 연결을 제거한다.

```text
daily_reports.recurring_stories
→ 부모가 주의 깊게 볼 변화
```

확인 대상:
- `components/ReportDetailModal.tsx`
- `app/parent/report/[id]/page.tsx`
- 동일 key를 사용하는 다른 리포트 컴포넌트
- API mapper/fallback

다음 형태가 있으면 제거한다.

```ts
watchOut = report.recurring_stories
```

또는:

```ts
report.recurring_stories || ...
```

를 `부모가 주의 깊게 볼 변화`에 사용하는 모든 경로.

---

## 4. 핵심 수정 2 — 변화 카드 임시 숨김

현재 시스템에는 실제 이전 상태 대비 변화(Delta)를 계산하는 전용 데이터가 없다.

따라서 별도 `parent_watch_changes` 또는 동등한 실제 변화 분석 필드가 구현되기 전까지:

```text
👁️ 부모가 주의 깊게 볼 변화
```

카드를 렌더링하지 않는다.

중요:
- recurring_stories로 대체 금지
- 다른 필드 fallback 금지
- `특이 사항이 없었어요` 같은 대체 문구 금지
- 데이터 부족 placeholder 금지

카드 자체를 숨긴다.

---

## 5. 핵심 수정 3 — recurring_stories 의미 보존

`recurring_stories` 자체는 기존 의미를 유지한다.

의미:
```text
당일 대화에서 아이가 반복해서 언급한 주제
```

이번 요청에서:
- DB 컬럼 삭제 금지
- 기존 데이터 삭제 금지
- 기존 리포트 일괄 수정 금지

다만 부모 추천 가이드의 `주의 깊게 볼 변화` 카드에는 사용하지 않는다.

---

## 6. 핵심 수정 4 — 앱/미션/시스템 불만 리포트 분석 제외

다음 유형은 부모 리포트 분석에서 의미 있는 아이 상태/관심/변화로 취급하지 않는다.

예:
- 미션이 안 끝난다
- 미션 게이지가 안 오른다
- 별이 안 올라간다
- 단어가 두 번 출력된다
- 버튼이 안 된다
- 화면이 이상하다
- 앱이 느리다
- 케이 기능 오류/서비스 사용 불편

현재 Daily Report prompt 또는 recurring_stories 생성 지침에 제외 가드를 추가한다.

원칙:
```text
서비스 자체의 UI/기능/미션 진행 오류·불만
→ 부모 리포트 분석에서 제외
```

단, 아이가 서비스 불만을 말한 사실 자체를 raw/corrected conversation에서 삭제하지 않는다.

---

## 7. 단순 일상 사실과 변화 구분

다음은 `부모가 주의 깊게 볼 변화`가 아니다.

- 방학이라 학교에 안 감
- 로블록스를 좋아함
- 만화책을 자주 읽음
- 같은 게임 이야기를 반복함
- 평소 하던 활동을 계속함
- 같은 취향을 반복 언급함

실제 변화 카드가 향후 다시 활성화되려면 최소 다음 조건이 필요하다.

```text
이전 상태/최근 며칠 데이터 존재
+
오늘 상태와 비교
+
의미 있는 Delta 확인
→ 변화 카드 생성
```

현재는 이 로직이 없으므로 카드 숨김을 유지한다.

---

## 8. REQUEST 031과의 관계

REQUEST 031의 정책:

```text
데이터 없음
→ 추천 가이드 항목 전체 숨김
```

을 그대로 유지한다.

이번 REQUEST 033은 그보다 앞단의 semantic mapping 오류를 수정한다.

즉:
- 031: 빈 데이터/placeholder 숨김
- 033: 잘못된 recurring_stories 매핑 제거

둘 다 적용되어야 한다.

---

## 9. UI 공백 처리

`부모가 주의 깊게 볼 변화` 카드 제거 후:
- 빈 wrapper 제거
- 빈 카드 제거
- 상하 margin/padding 제거
- 구분선 제거
- 고정 height/min-height 제거

대표 UI 원칙:
```text
정렬과 가독성을 위한 여백은 유지
의미 없는 빈 공간은 제거
```

## 11. 향후 변화 기능과 분리

향후 실제 `부모가 주의 깊게 볼 변화` 기능을 다시 만들 경우 별도 필드를 사용한다.

권장 개념:
```text
parent_watch_changes
```

입력:
- 최근 3~7일 또는 이전 리포트
- 오늘 리포트
- last-known insight

판정:
```text
실제 변화 있음 → content
변화 없음 → null
```

이번 REQUEST에서는 해당 기능을 새로 개발하지 않는다.
