# 케이↔성장정보 연동 v1

## 0. 완료 시 기대 결과 / 대표님 테스트 정상 프로세스

### 완료 시 기대 결과

내친구 케이가 미션 또는 자유대화 중 아이와 자연스럽게 대화하다가 키/몸무게 정보를 확인할 수 있고, 아이가 답한 값은 곧바로 공식 성장기록에 반영하지 않고 `pending` 상태로 저장한다.

부모가 부모 홈의 기존 `키 / 몸무게` 성장 카드를 클릭하면 성장정보 상세 모달 상단에 `새로운 성장정보가 있어요` 영역이 표시되고, 아이가 말한 값을 부모가 확인한 뒤 `[반영]` 또는 `[무시]`를 선택할 수 있어야 한다.

예:

```text
새로운 성장정보가 있어요

서현이가 키 142cm라고 말했어요.
2026-08-19 대화에서 확인

[반영] [무시]
```

부모가 `[반영]`을 선택한 경우에만 `growth_measurements`의 공식 측정값으로 저장한다.

부모가 `[무시]`를 선택한 경우 공식 성장기록에는 반영하지 않는다.

아이 화면에는 성장도표, BMI, 백분위, 또래 비교 등 신체 비교 정보를 노출하지 않는다.

### 대표님 테스트 정상 프로세스

#### 시나리오 A — 자유대화에서 명확한 키 정보 획득

1. 아이가 자유대화에 진입한다.
2. 케이가 현재 대화 맥락상 자연스럽게 키를 질문한다.
3. 아이가 `나 142cm야`처럼 명확한 값을 답한다.
4. 시스템이 `height_cm = 142`를 추출한다.
5. 값은 공식 `growth_measurements`에 바로 저장되지 않는다.
6. 아이 발화 기반 `pending growth candidate`로 저장된다.
7. 부모가 부모 홈에서 키/몸무게 성장 카드를 클릭한다.
8. 성장정보 상세 모달 상단에 다음과 유사한 안내가 표시된다.

```text
서현이가 키 142cm라고 말했어요.
성장기록에 반영할까요?
```

9. 부모가 `[반영]`을 선택한다.
10. 공식 `growth_measurements`에 `142cm`가 저장된다.
11. 성장 카드의 최신 키와 성장 상세 화면이 정상 갱신된다.

PASS 기준:
- 대화 답변 → 추출 → pending 저장 → 부모 승인 → 공식 성장기록 반영의 전체 체인이 정상 동작한다.
- 부모 승인 전에는 공식 성장도표/BMI 계산에 사용되지 않는다.
- 부모 승인 후에만 최신 성장정보에 반영된다.

#### 시나리오 B — 부모가 무시

1. 아이가 `몸무게 38kg이야`라고 명확히 말한다.
2. pending candidate가 생성된다.
3. 부모 성장정보 모달에 안내가 나타난다.
4. 부모가 `[무시]`를 선택한다.
5. 해당 candidate는 dismissed/rejected 상태가 된다.
6. `growth_measurements`에는 공식 측정값이 생성되지 않는다.
7. 같은 candidate가 계속 반복 노출되지 않는다.

PASS 기준:
- 무시한 값이 공식 기록에 들어가지 않는다.
- 동일 pending이 재노출되지 않는다.

#### 시나리오 C — 불확실한 아이 답변

아이:

```text
140쯤?
잘 모르겠는데 40kg인가?
엄마가 138이라고 했던 것 같아.
아마 42kg?
```

PASS 기준:
- 불확실 발화를 공식 성장기록으로 자동 저장하지 않는다.
- 명확한 값으로 오판정하지 않는다.
- 정책에 따라 pending 자체를 생성하지 않거나 `low confidence` 상태로만 저장한다.
- 부모 승인 전 공식 성장기록에는 절대 반영하지 않는다.

#### 시나리오 D — 아이가 단위를 잘못 말함

예:

```text
키 14cm
몸무게 400kg
키 142kg
몸무게 38cm
```

PASS 기준:
- 비현실적 범위 또는 잘못된 단위 조합을 차단한다.
- 공식 성장기록 및 정상 pending으로 저장하지 않는다.

## 2. 목표

현재 성장정보 v1은 부모 직접 입력만 공식 Source of Truth로 사용한다.

AS-IS QA 결과:

```text
① 케이가 키/몸무게 질문        FAIL
② 아이 답변에서 값 추출        FAIL
③ 추출값 DB 저장              FAIL
④ 부모 직접 입력 기반 화면 반영 PASS
```

현재 `growth_measurements`의 유일한 쓰기 경로는 부모 직접 입력이며, migration `20260818230000_child_growth_profiles_and_measurements.sql`에서 v1은 `parent_manual`만 허용하고 케이 대화 자동 추출을 명시적으로 범위 밖으로 두고 있다.

이번 요청은 다음 연결을 신규 구현하는 것이 목표다.

```text
케이 대화
→ 아이가 키/몸무게 답변
→ 구조화 추출
→ 신뢰도/단위/범위 검증
→ pending 성장정보 후보 저장
→ 부모 성장정보 모달에 표시
→ 부모 [반영] 또는 [무시]
→ [반영]일 때만 공식 growth_measurements 저장
→ 부모 성장카드/성장도표 갱신
```

핵심 정책:

> 아이 발화는 “후보 정보”다.  
> 부모 확인을 거친 값만 “공식 성장기록”이 된다.

## 3. 요구사항

### 3-1. 케이가 키/몸무게를 자연스럽게 질문할 수 있어야 함

미션과 자유대화 모두 키/몸무게를 질문할 수 있다.

단, 방식은 각 모드 정책을 따른다.

#### 미션

미션에서는 마지막에 질문이 필요하므로, 현재 대화와 자연스럽게 연결될 때 키/몸무게 질문을 사용할 수 있다.

예:

```text
아이: 나 요즘 엄청 큰 것 같아.
케이: 오ㅋㅋ 진짜? 최근에 키 재봤어?
```

또는 성장 관련 Seed/Fallback 질문이 필요한 경우 사용할 수 있다.

단, 미션의 기존 의미 있는 답변/별 게이지 정책과 충돌하지 않도록 한다.

#### 자유대화

자유대화에서는 키/몸무게 질문을 강제하지 않는다.

아이의 발화와 관련 있을 때만 자연스럽게 질문한다.

예:

```text
아이: 바지가 다 짧아졌어.
케이: 진짜 많이 컸나 보다ㅋㅋ 요즘 키 재봤어?
```

금지:

```text
뜬금없이: 너 키 몇이야?
뜬금없이: 몸무게는 몇 kg야?
```

### 3-2. 케이 질문 빈도 제한

케이가 반복적으로 신체정보를 묻지 않도록 한다.

- 최근 동일 정보가 이미 존재하는 경우 다시 묻지 않음
- 최근 pending candidate가 있는 경우 다시 묻지 않음
- 최근 부모 확인 완료 값이 있는 경우 불필요하게 재질문하지 않음
- 아이가 불편해하거나 대답을 회피하면 반복 추궁하지 않음

정확한 재질문 기간은 기존 성장정보 업데이트 정책과 현재 코드 구조를 확인해 최소 변경으로 결정한다.

고정 기간을 새로 만들 필요가 있는 경우 구현 전에 이유를 보고한다.

### 3-3. 아이 발화에서 구조화 값 추출

다음 형태를 인식할 수 있어야 한다.

#### 키

```text
142cm
142센티
142센티미터
키 142
나는 142야
```

단, 문맥상 `키`를 의미하는 것이 명확해야 한다.

#### 몸무게

```text
38kg
38킬로
38킬로그램
몸무게 38
나는 38kg이야
```

추출 결과는 최소 다음 정보를 포함한다.

```text
child_id
measurement_type = height | weight
value
unit
source_message_id 또는 source conversation reference
spoken_at
confidence
raw_text/reference
status = pending
```

개인정보 최소화 원칙에 따라 전체 대화 원문을 별도 중복 저장하지 말고, 기존 message reference로 추적 가능한 경우 해당 ID를 우선 사용한다.

### 3-4. 명확성/신뢰도 판정

아이 발화는 최소 다음으로 구분한다.

```text
high_confidence
low_confidence
invalid
```

#### high_confidence 예

```text
나 키 142cm야.
몸무게 38kg이야.
어제 쟀는데 141.5cm였어.
```

#### low_confidence 예

```text
140쯤?
40인가?
엄마가 138이라고 했던 것 같아.
아마 42kg.
```

#### invalid 예

```text
키 14cm
몸무게 400kg
키 142kg
몸무게 38cm
```

high confidence만 일반 pending 승인 후보로 노출하는 것을 기본으로 한다.

low confidence는 공식 성장기록에 자동 반영할 수 없다.

low confidence를 부모에게 표시할 필요가 있다면 반드시 `불확실한 값`임을 분명히 표시하고, 부모가 실제 값을 직접 수정 입력하도록 유도한다.

### 3-5. 현실적인 값 범위 검증

서버 측에서 키/몸무게 값의 비현실적 범위를 차단한다.

단, 임의의 의학 기준을 코드에 추측으로 넣지 않는다.

현재 서비스 대상 연령과 공식 성장정보 범위를 확인하여 합리적인 기술 validation 범위를 정의한다.

validation은 건강 상태 판단이 아니라 명백한 입력 오류 방지 목적이다.

### 3-6. pending 성장정보 저장소 신규 구현

아이 발화에서 얻은 값을 공식 `growth_measurements`에 바로 넣지 않는다.

별도 pending 저장소를 사용한다.

권장 예:

```text
growth_measurement_candidates
```

필드 예:

```text
id
child_id
measurement_type
value
unit
source_type
source_message_id
spoken_at
confidence
status
reviewed_by
reviewed_at
created_at
updated_at
```

status 예:

```text
pending
confirmed
dismissed
expired
```

실제 명칭과 schema는 기존 DB naming convention에 맞춘다.

### 3-7. Source 구분

현재 migration의 `growth_measurements.source`는 `parent_manual`만 허용한다.

부모가 아이 발화 candidate를 승인했을 경우 공식 기록의 source를 부모 직접 입력과 구분해야 한다.

권장:

```text
parent_manual
parent_confirmed_child_report
```

또는 현재 naming convention에 맞는 동등한 값.

`k_conversation_confirmed`처럼 케이가 승인한 것으로 오해할 수 있는 source는 사용하지 않는다.

공식 측정값으로 확정하는 주체는 부모다.

### 3-8. 부모 성장정보 모달 상단에 pending 영역 추가

기존 부모 홈 `GrowthCards.tsx`의 키/몸무게 카드 진입 흐름을 유지한다.

카드 클릭 후 기존 성장정보 상세 모달 상단에 pending candidate가 존재하는 경우 다음 영역을 표시한다.

예:

```text
새로운 성장정보가 있어요

서현이가 키 142cm라고 말했어요.
오늘 대화에서 확인했어요.

[반영] [무시]
```

몸무게 예:

```text
서현이가 몸무게 38kg이라고 말했어요.

[반영] [무시]
```

### 3-9. 부모 [반영]

부모가 `[반영]`을 누르면:

1. pending candidate 상태 확인
2. 이미 처리되지 않았는지 확인
3. 부모 권한 확인
4. 공식 `growth_measurements` insert
5. `source = parent_confirmed_child_report`
6. candidate status = confirmed
7. reviewed_by / reviewed_at 기록
8. 성장정보 최신값 재조회
9. 키/몸무게 카드 갱신
10. 성장 상세 그래프/백분위/BMI 재계산

가능하면 부모가 반영 직전에 값과 측정일을 수정할 수 있도록 한다.

특히 아이가 말한 날짜가 명확하지 않은 경우 `spoken_at`을 실제 측정일로 단정하지 않는다.

### 3-10. 측정일 처리

아이 발화 시점과 실제 측정일은 다를 수 있다.

예:

```text
아이: 지난주에 키 쟀는데 142였어.
```

따라서:

- 아이가 측정 시점을 명확히 말하면 해당 날짜 후보 사용 가능
- 측정 시점이 불명확하면 부모 승인 시 측정일을 확인/선택
- 대화일을 무조건 measured_at으로 저장하지 않음

### 3-11. 부모 [무시]

부모가 `[무시]`를 누르면:

```text
status = dismissed
reviewed_by = parent
reviewed_at = now
```

처리한다.

공식 `growth_measurements` insert는 하지 않는다.

같은 candidate를 다시 노출하지 않는다.

### 3-12. 중복 후보 방지

동일하거나 사실상 동일한 pending candidate를 중복 생성하지 않는다.

예:

```text
아이: 나 142cm야.
케이: 142cm구나!
아이: 응 142.
```

위 대화에서 height=142 candidate가 2개 이상 생성되면 안 된다.

중복 판단 시 최소 다음을 고려한다.

- child_id
- measurement_type
- value
- 최근 시간 범위
- source conversation/message

### 3-13. 아이 화면 미노출

아이 화면에서는 다음을 노출하지 않는다.

- 성장도표
- BMI
- 백분위
- 평균 대비 크다/작다
- 정상/비정상
- 과체중/저체중 등의 판정

케이는 아이에게 숫자를 평가하지 않는다.

금지 예:

```text
너 평균보다 작아.
몸무게가 많이 나가네.
살 좀 빼야겠다.
정상 체중이 아니야.
```

### 3-14. 관계 안전 및 신체 이미지 보호

키/몸무게 질문은 관계 형성을 해치지 않도록 한다.

특히 몸무게는 키보다 더 민감하게 취급한다.

- 반복 질문 금지
- 아이가 대답하기 싫어하면 즉시 중단
- 체중 평가 금지
- 외모 평가 금지
- 식이/다이어트 유도 금지
- 다른 아이와 비교 금지

### 3-15. 기존 성장정보 v1과 통합

현재 확인된 기존 흐름:

```text
GrowthCards.tsx
→ GET /api/parent/growth/{childId}
→ loadGrowthState()
→ growth_measurements
→ measured_at 내림차순 최신값
```

신규 parent-confirmed 값은 기존 공식 성장정보 조회 흐름을 그대로 사용하도록 한다.

별도의 병렬 Source of Truth를 만들지 않는다.

최종 공식 Source of Truth는 계속 `growth_measurements`다.

### 3-16. 개인정보/RLS

pending candidate는 부모만 조회/승인/무시할 수 있어야 한다.

아이 계정에서 직접 조회할 수 없어야 한다.

권장 RLS:

- SELECT: owner_parent / parent
- INSERT: 서비스 서버/허용된 backend 경로
- UPDATE: owner_parent / parent 또는 service_role
- DELETE: 정책에 따라 parent/service_role

Production의 기존 역할/가족 RLS convention을 그대로 따른다.

### 3-17. 감사 추적

부모 승인/무시 이력을 확인할 수 있도록 한다.

최소:

```text
candidate created_at
source message/conversation
status
reviewed_by
reviewed_at
official measurement id (confirmed 시)
```

### 3-18. 미션 별 게이지와 분리

키/몸무게를 답했다고 해서 자동으로 별 게이지를 올리는 별도 규칙을 새로 만들지 않는다.

기존 친구되기 엔진의 “의미 있는 답변 판정” 규칙에 의해 정상적으로 유효 답변인지 평가한다.

성장정보 추출 성공 여부와 별 게이지는 독립적으로 처리한다.

## 5. 금지사항

1. 아이 발화를 즉시 공식 `growth_measurements`에 저장하지 않는다.
2. 부모 승인 전 성장도표/BMI/백분위 계산의 공식 값으로 사용하지 않는다.
3. `memory_facts`에 존재할 수 있는 일반 기억을 공식 성장정보로 간주하지 않는다.
4. `spoken_at`을 무조건 실제 측정일로 사용하지 않는다.
5. 불확실한 값을 high confidence로 저장하지 않는다.
6. 비현실적 단위/범위를 저장하지 않는다.
7. 아이에게 정상/비정상, 과체중/저체중 등 평가 표현을 하지 않는다.
8. 아이 화면에 성장도표/BMI/백분위를 노출하지 않는다.
9. 부모가 무시한 candidate를 반복 노출하지 않는다.
10. 동일 발화/동일 값으로 candidate를 중복 생성하지 않는다.
11. 성장정보 기능을 위해 회원가입 입력항목을 추가하지 않는다.
12. 기존 `parent_manual` 기록을 훼손하거나 source를 소급 변경하지 않는다.
13. 별 게이지/황금열쇠 정책을 변경하지 않는다.
14. 친구되기 엔진의 미션/자유대화 정책을 깨지 않는다.
15. Production 데이터를 QA 목적으로 수동 수정하지 않는다.

## 6. 모호성 처리

### 6-1. 아이가 값만 말한 경우

```text
케이: 키 재봤어?
아이: 142.
```

현재 질문 문맥이 명확하면 height=142cm 후보로 해석 가능하다.

문맥이 불명확하면 추측하지 않는다.

### 6-2. 소수점

```text
141.5cm
38.2kg
```

기존 growth_measurements precision 규격을 확인하고 동일 규격으로 처리한다.

### 6-3. 여러 값이 한 발화에 존재

```text
지난번엔 140이었고 지금은 142야.
```

현재값이 명확하면 142를 후보로 사용할 수 있다.

불명확하면 부모 직접 확인 대상으로 처리한다.

### 6-4. 키와 몸무게를 한 번에 말함

```text
키 142cm고 몸무게 38kg이야.
```

각각 독립 candidate로 저장할 수 있다.

단, 부모 UI에서 동시에 검토 가능한 구조를 고려한다.

### 6-5. 부모가 값을 수정 후 반영

부모가 candidate 값을 수정하면 최종 공식 기록은 부모가 수정한 값을 저장하고 source는 `parent_confirmed_child_report`로 유지한다.

필요한 경우 원본 candidate 값과 최종 confirmed 값을 별도로 감사 가능하게 유지한다.

### 6-6. 이미 최신 공식 값과 동일

공식 최신값과 candidate가 동일하고 측정 시점도 새 정보가 없다면 중복 공식 기록을 만들지 않는다.

## 7. QA

### 7-1. 케이 질문

- [ ] 미션에서 자연스러운 맥락일 때 키 질문 가능
- [ ] 자유대화에서 자연스러운 맥락일 때 키 질문 가능
- [ ] 몸무게 질문을 반복적으로 강제하지 않음
- [ ] 아이가 거부하면 재질문하지 않음
- [ ] 뜬금없는 신체정보 질문이 반복되지 않음

### 7-2. 키 추출

- [ ] `키 142cm야` → 142cm
- [ ] `142센티` → 142cm
- [ ] `나는 142야` + 명확한 키 질문 문맥 → 142cm
- [ ] `140쯤` → low confidence
- [ ] `아마 138` → low confidence
- [ ] `14cm` → invalid 또는 validation 차단
- [ ] `142kg` → 키 값으로 저장 금지

- [ ] `몸무게 38kg` → 38kg
- [ ] `38킬로야` → 38kg

- [ ] `400kg` → invalid
- [ ] `38cm` → 몸무게로 저장 금지

## 8. 완료 조건

다음 조건을 모두 만족해야 완료다.

1. 케이가 미션/자유대화에서 자연스럽게 키/몸무게를 질문할 수 있다.
2. 아이의 명확한 답변에서 키/몸무게 값을 구조화 추출할 수 있다.
3. 불확실/비현실적 값이 공식 기록으로 들어가지 않는다.
4. 아이 발화 값은 pending candidate로만 저장된다.
5. 부모 성장정보 모달에 신규 candidate가 표시된다.
6. 부모 `[반영]` 시에만 공식 `growth_measurements`에 저장된다.
7. 부모 `[무시]` 시 공식 기록에 반영되지 않는다.
8. 공식 기록 source가 부모 직접 입력과 부모 확인 아이 발화를 구분한다.
9. 부모 승인 전 성장도표/BMI/백분위 공식 계산에 사용되지 않는다.
10. 아이 화면에 성장 비교 정보가 노출되지 않는다.
11. RLS가 부모 전용 정책을 만족한다.

13. 기존 친구되기 엔진/미션/자유대화/별 게이지에 회귀가 없다.
14. 대표 E2E QA가 모두 PASS 한다.
