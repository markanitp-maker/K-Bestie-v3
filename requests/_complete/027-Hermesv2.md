김비서와 Claude Code의 양방향 업무 제어 구조를 만들려 한다.

핵심 요구사항은 두 가지다.

1. 대표님이 Discord에서 김비서에게 새 업무 지시를 내리면,
   김비서가 그 지시를 현재 진행 중인 Claude Code 세션에 전달하고,
   Claude Code가 같은 세션의 맥락을 유지한 채 지시를 받아 실행해야 한다.

2. Claude Code가 작업 중 대표님 판단이 필요해 질문하면,
   김비서 Discord에 질문을 보내고,
   대표님 답변을 김비서가 다시 원래 Claude Code 세션에 전달해
   Claude Code가 자동으로 작업을 재개해야 한다.

중요:
- 단순히 파일에 inbox/outbox를 쓰는 방식만으로는 안 된다.
  실행 중인 Claude Code가 새 지시를 실제로 읽고 다음 행동으로 이어가야 한다.
- AskUserQuestion 화면만 띄우고 멈추는 방식도 안 된다.
- 대표님이 직접 Claude Code 채팅창에 매번 붙여넣지 않아도 돼야 한다.
- 기존 앱에서 열어 둔 Claude Code 세션과, 앞으로 김비서가 관리할 새 세션을 구분해서 설명해라.
- 외부 지시를 쉘 명령으로 그대로 실행하면 안 되며, 작업 지시 텍스트로만 안전하게 전달해야 한다.
- 운영 배포, DB 변경, 비용 발생, 실계정 데이터 변경 등은 기존 승인 규칙을 유지해야 한다.

먼저 코드 수정은 하지 말고 아래만 조사·답변해.

A. 현재 Claude Code CLI에서 가능한 실제 제어 방식
- --resume
- --input-format stream-json
- --remote-control
- stdin 기반 대화형 세션
- 다른 가능한 공식 방식
각 방식이 “이미 열려 있는 앱 세션”과 “김비서가 새로 시작하는 관리 세션” 중 어디에 가능한지 구분해.

B. 위 요구를 만족하는 권장 아키텍처 1개
- 김비서
- Discord
- Claude Code 세션
- 지시 큐
- 질문/답변
- 상태 보고
흐름을 단계별로 설명해.

C. 실제 구현 전제조건
- Claude Code를 어떤 방식으로 시작해야 하는지
- 현재 열려 있는 세션을 전환할 수 있는지
- 전환 불가라면 대표님이 한 번만 해야 하는 행동이 무엇인지
- 세션 충돌·동시 작업·답변 오배달 방지 방법

D. 10분 내 가능한 최소 PoC
- 새 지시 1건을 김비서→Claude Code로 전달
- Claude Code가 수신 확인을 Discord로 보고
- Claude Code 질문 1건에 대표님 답변을 다시 주입
- 작업 재개를 확인
이 네 단계를 실제 검증하는 방법을 제안해.

기술 로그만 나열하지 말고, “가능 / 불가능 / 필요한 전환 / 대표님이 할 일”을 명확하게 결론으로 답해.
