# Request 큐 운영 규칙

이 디렉터리의 작업에서는 아래 규칙이 다른 일반 작업 규칙보다 우선한다.

1. 상태가 `미진행`, `작업중`, `대기중`, `실패`, `완료` 중 하나로 바뀌는 즉시, 다른 작업을 계속하기 전에 `_dashboard.md`를 먼저 갱신한다.
2. `_dashboard.md`에는 루트 `requests/`에 실제로 남아 있는 미완료·작업중·대기 항목만 표시한다. 완료 항목을 계속 표시하지 않는다.
3. 작업 완료 시 김비서 Discord 보고 결과가 `sent`인지 먼저 확인한다. 두 번 실패하면 완료로 처리하거나 `_done`으로 이동하지 않는다.
4. 김비서 보고가 성공한 완료 항목은 `_done/`으로 이동하고 `_log.md` 맨 위에 검증·배포·잔여 이슈를 기록한다.
5. 완료 파일의 원본이 Git 추적 대상이고 `_done/`이 Git 제외 대상이면, 원본 삭제를 같은 작업에서 반드시 커밋하고 원격 저장소에 푸시한다. 로컬 이동만으로 완료 처리하지 않는다.
6. 완료 처리 직후 다음을 확인한다.
   - 완료 파일이 루트 `requests/`에 남아 있지 않다.
   - `_done/`에 보관본이 존재한다.
   - Git 추적 대상이었던 원본은 `git ls-files requests`에 남아 있지 않다.
   - 루트 큐 파일 목록과 `_dashboard.md` 항목이 일치한다.
7. 완료 근거가 없거나 `_done` 보관본과 내용이 다른 파일은 임의로 삭제하거나 이동하지 않는다.
