## 2. 원본 데이터 확보 경로

질병관리청 국민건강영양조사 홈페이지 → 성장도표 → 성장도표 다운로드 →
`소아청소년 성장도표 기본자료`(2017, 등록일 2025-01-02)의 첨부파일 **`성장도표 데이터 테이블.xls`**.

- 화면 경로: <https://knhanes.kdca.go.kr/knhanes/grtcht/main.do> → `성장도표 다운로드`
- 내부 목록 API: `POST /knhanes/grtcht/dwnld/findWsiGrtChtDtList.json`
- 내부 다운로드 API: `POST /knhanes/api/file/download.json` `{"type":"GC","dtlSn":7,"flSn":2}`
  → 응답의 `downUrl` 로 실제 파일 다운로드(세션 쿠키와 Referer 가 필요하다)
- 저장 위치: `docs/growth/kdca-2017-source/kdca-2017-growth-chart-data-table.xlsx`
  (원본 그대로. 파일명만 ASCII 로 바꿨다. `md5 7d715ef7f5e675e510fa270a22bc8046`, 376,581 bytes)

블로그·커뮤니티·상업 사이트 값은 사용하지 않았다. 외부 성장 계산 라이브러리도 추가하지 않았다.

## 3. 가공 방법

`node scripts/growth/build-kdca-2017-lms.mjs` 로 원본 xlsx → `lib/growth/standards/kdca-2017/lms.generated.ts`
를 재생성한다. 외부 의존성 없이 Node 표준 `zlib` 로 xlsx(zip)를 직접 해제한다.

원본 시트 구조(실측):

```
A열 성별(1=남, 2=여) / B열 만나이(세, 연 경계 행에만 값이 있다) / C열 만나이(개월)
D열 L / E열 M / F열 S / G열 이후 백분위수(3rd…99th) 및 ±SD 값
```

- **L·M·S 만** 옮긴다. 원본 표기값을 반올림·가공 없이 그대로 쓴다.
- 백분위수 열은 옮기지 않는다. 같은 LMS 산식으로 재현되므로 중복 저장하지 않는다(요청서 §3-11).
- 추출 결과: 연령별 신장 남 228 / 여 228행(0~227개월), 연령별 체중 남 228 / 여 228행(0~227개월),
  연령별 체질량지수 남 204 / 여 204행(24~227개월).
- 공식이 제공하지 않는 월령(예: 228개월, BMI 24개월 미만)은 키 자체를 만들지 않는다.
  보간·외삽하지 않는다(요청서 §5).

## 4. 계산 규칙

### 4-1. 월령 (완전 경과 월수)

```
months = (측정연도 - 출생연도) × 12 + (측정월 - 출생월) - (측정일자 < 출생일자 ? 1 : 0)
```

공식 성장상태 측정계산기가 돌려주는 `diffMth` 와 완전히 일치한다(실측):

| 생년월일 | 측정일 | 공식 diffMth |
|---|---|---|
| 2016-08-18 | 2026-08-18 | 120 |
| 2016-08-18 | 2026-08-17 | 119 |
| 2016-08-31 | 2026-09-01 | 120 |
| 2016-09-01 | 2026-08-31 | 119 |
| 2016-02-29 | 2026-02-28 | 119 (윤년 생일을 2/28로 당겨주지 않는다) |
| 2016-02-29 | 2026-03-01 | 120 |
| 2016-01-31 | 2026-02-28 | 120 |
| 2016-12-31 | 2026-01-01 | 108 |

30일·30.4일로 나누는 근사 계산은 쓰지 않는다. (공식 산출프로그램 SAS 코드의
`agem = int((M_date-B_date)/2626560)` 은 도표를 만들 때 원시자료 표본을 묶는 규칙이며,
개인 측정값 판정에 쓰는 규칙은 위 완전월령이다.)

### 4-2. 백분위

```
L ≠ 0 : z = ((X/M)^L - 1) / (L·S)
L = 0 : z = ln(X/M) / S
백분위 = Φ(z) × 100      (소수 첫째자리로 반올림해 표기)
```

Φ 는 Hart(1968)/West(2005) 배정밀도 근사(오차 ~1e-15)를 쓴다.

### 4-3. BMI

`BMI = 몸무게(kg) / (키(m))²` 를 **소수 첫째자리로 반올림한 뒤** 그 값으로 백분위를 조회한다.
공식 계산기도 같은 순서다(실측 근거):

- 여아 120개월 165cm/40kg → 공식 BMI 14.7 / 백분위 7.1.
  원값(14.6923…)으로 계산하면 7.0 이 되어 공식과 어긋나고, 반올림값(14.7)으로 계산하면 7.1 로 일치한다.
- 여아 119개월 140cm/40kg → 공식 20.4 / 84.2. 원값(20.408…) 계산 시 84.3.

같은 측정일에 키와 몸무게가 함께 있을 때만 계산한다. 서로 다른 날짜의 값을 결합하지 않는다.

### 4-4. 공식 판정 라벨과 임계값

공식 계산기 출력 실측으로 확정했다. 임의 임계값을 만들지 않았다.

| 지표 | 구간 | 공식 라벨 | 실측 근거 |
|---|---|---|---|
| 연령별 신장 | 3백분위 미만 | 저신장 | 2.9 → 저신장 |
| | 3 이상 97 이하 | 정상범위 | 3.1 → 정상범위, 97.0 → 정상범위 |
| | 97 초과 | (표시 없음) | 97.2 → 라벨 없음 |
| 연령별 체중 | 5백분위 미만 | 저체중 | 4.9 → 저체중 |
| | 5 이상 | (표시 없음) | 5.1 → 라벨 없음 |
| 연령별 BMI | 5백분위 미만 | 쇠약증 | 4.0 → 쇠약증 |
| | 5 이상 85 미만 | 정상범위 | 84.5 → 정상범위 |
| | 85 이상 95 미만 | 과체중 | 85.3 / 94.9 → 과체중 |
| | 95 이상 | 비만 | 95.2 → 비만 |

공식 계산기의 체중 라벨 원문은 `저체중\n(Underweight)` 이다. 화면에는 `저체중` 으로 표기한다.

## 5. 공식 계산기 대조 결과

오라클: `POST https://knhanes.kdca.go.kr/knhanes/grtcht/findMeasClcltData.json`
(payload `{"sex":"1|2","hgt","wgt","hdDmt","birDt","measDt"}`, `sex` 는 1=남 / 2=여)

- 대표 fixture 20건을 `lib/growth/growth.test.ts` 에 그대로 박아 두었다(남/여, 저·중·고 백분위,
  판정 경계 전후, 월령 경계, 윤년, BMI 미제공 구간, 만 18세).
- 결과: 월령·백분위·판정·BMI 전부 일치.

### 유일한 차이와 그 원인

공식이 공개하는 데이터 테이블은 L·M·S 를 **소수 4자리로 반올림**해 싣는다. 공식 계산기는
반올림 전 내부값을 쓰는 것으로 보이며, 그 차이는 백분위로 환산해 약 **0.0002%p** 다.
따라서 참값이 표시 반올림 경계(…95)에 걸리는 아주 좁은 구간에서만 표기가 0.1 어긋난다.

| 케이스 | 우리 계산 | 공식 표기 | 공식 판정 | 우리 판정 |
|---|---|---|---|---|
| 여아 120개월 151.1cm | 96.949806% → 96.9 | 97.0 | 정상범위 | 정상범위 |
| 여아 120개월 151.3cm | 97.149761% → 97.1 | 97.2 | (표시 없음) | (표시 없음) |

공개된 데이터로는 이보다 좁힐 수 없다(공식은 4자리까지만 공개한다). 허용오차를 임의로 넓히지 않고
`lib/growth/growth.test.ts` 의 "표시 반올림 경계에서의 차이는 0.1 이내이며 공식 판정을 바꾸지 않는다"
테스트로 원인·크기·판정 영향 없음을 고정했다.

## 6. 서비스 대상 연령

내친구 케이는 초등학생(초1~초6, 한국나이 8~13세) 서비스다. 만나이로는 만 6세~13세가 정상 범위이며
`lib/growth/consent.ts` 의 `ELEMENTARY_AGE_MONTHS`(72~167개월)로 관리한다. 이 범위는 공식 기준
지원 범위(신장·체중 0~227개월, BMI 24~227개월) 안에 완전히 들어간다. 여유 범위를 벗어난 생년월일은
저장을 막지 않고 "확인해 주세요" 안내만 띄운다.
