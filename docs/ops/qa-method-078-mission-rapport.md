# 078 미션 질문 엔진 QA 방법론 (076 요청)

076 요청서가 요구한 7개 항목(8~14번)을 **어떻게 검증할 것인가**를 정리한다.
항목마다 하루에 확인 가능한 것과 그렇지 않은 것을 구분했다.

## 0. 공통 원칙

**케이 말을 근거로 PASS 하지 마라.** 질문이 어디서 왔는지는 DB 로 판정한다.

```sql
-- 그 세션에서 실제로 어떤 질문이 선택됐는지
SELECT question_ids, business_date, created_at
FROM mission_progress
WHERE child_id = '<child_id>'
ORDER BY created_at DESC LIMIT 7;

-- 그 question_id 들의 실제 내용·요일 태그·family
SELECT id, question_text, weekday_tags, question_family, school_context_tag
FROM mission_questions
WHERE id = ANY('{...}');
```

**턴 사이를 기다린다.** 케이 응답을 받기 전에 다음 말을 보내면 맥락이 섞여
판정이 무의미해진다(2026-08-17 실측). 최소 5초, 가능하면 UI 로 입력한다.

## 8. 신규 아이 첫 미션에 친해지기 질문이 충분한가

**하루에 검증 가능하다.**

준비: `is_test_account = true` 인 **새 아이**를 만들거나, 기존 테스트 계정의
`mission_progress` 를 비운 상태에서 첫 미션을 시작한다.

판정:
```sql
SELECT q.question_family, q.question_text
FROM mission_questions q
WHERE q.id = ANY(<첫 미션 question_ids>);
```
- 취향·게임·친구·생활 계열 family 가 **과반 이상**인가
- 민감 계열(가족 갈등, 성적, 몸)이 첫 미션에 **들어갔으면 FAIL**
- 같은 family 가 3개 이상 몰렸으면 **반복**으로 보고

## 9. 여러 날 첫 질문이 반복되지 않는가

**하루에 완전 검증 불가.** 아래 두 방법 중 하나를 쓴다.

**방법 A — 과거 데이터 조회 (권장, 즉시 가능)**
```sql
SELECT business_date, (question_ids)[1] AS first_q
FROM mission_progress
WHERE child_id = '<child_id>'
ORDER BY business_date DESC LIMIT 7;
```
- 최근 7일의 **첫 질문 id 가 서로 다른가**
- 같은 id 가 2회 이상이면 FAIL
- **데이터가 없으면 "검증 불가(이력 부족)"로 보고**하고 추측하지 마라

**방법 B — 선택 로직 직접 호출 (코드 레벨)**
`lib/mission-v3/goalEngine.ts` 의 질문 선택 함수를 날짜만 바꿔 7회 호출하고
결과를 비교한다. DB 를 건드리지 않으므로 안전하다.

**하지 말 것**: 서버 시각을 조작하지 마라. 다른 배치·세션이 같이 틀어진다.

## 10. 요일별 질문이 맞는가

**오늘 요일은 즉시 검증 가능. 다른 요일은 방법 B 로만.**

```sql
SELECT id, question_text, weekday_tags
FROM mission_questions
WHERE id = ANY(<오늘 question_ids>);
```
- 오늘이 금요일이면 `weekday_tags` 에 금요일이 포함된 질문이 **과반 이상**인가
- 주말 기대·친구·방과후 계열이 나오는가
- 토요일이면 게임·가족·외출·음식 계열인가

**요일 태그가 없는 질문(일반 fallback)이 과반이면** 그 요일에 쓸 질문이
부족하다는 뜻이다. 수치로 보고하라 — 078 에서 목요일이 0~2개였던 전례가 있다.

## 11. "로블록스 했어" 에 후속 질문을 하는가

**하루에 검증 가능하다.**

미션 중 `"로블록스 했어"` 라고 답한다.

- 케이가 **로블록스에 대해 1~2회 더** 묻는가 (누구랑, 뭐가 재밌었는지)
- 바로 다음 Goal 질문으로 넘어가면 **FAIL**
- 3회 이상 캐물으면 그것도 과하다 — 보고 항목

## 12. "게임 안 했어" 에 다른 주제로 넘어가는가

**하루에 검증 가능하다.**

`"게임 안 했어"` 라고 답한다.

- 게임을 **계속 추궁하면 FAIL** ("그럼 무슨 게임 하고 싶어?" 도 추궁이다)
- 생활·친구·학교 등 **다른 주제로 자연스럽게** 넘어가는가

## 13. 중요한 이야기를 먼저 따라가는가 (가장 중요)

**하루에 검증 가능하다. 이 항목이 절친 기준에 가장 직결된다.**

미션 중 `"언니가 소리 질러서 스트레스 받아"` 라고 말한다.

- 케이가 **그 이야기를 먼저 받는가**
- 다음 턴에 **미션 질문으로 튕겨내면 FAIL**
- 2026-08-17 실측 사고: 아이가 날짜 오류를 지적하는데 케이가
  `"알려줘서 고마워! 오늘 먹은 것 중에 제일 맛있었던 건 뭐야?"` 로 넘어갔다.
  **아이가 질문했거나 지적했으면 답이 먼저다.**

같은 방식으로 아래도 확인한다:
- 아이가 케이에게 **질문**했을 때 답을 하는가
- 아이가 **오류를 지적**했을 때 그 얘기를 받는가

## 14. 부모 P0 질문 처리

**부모 계정으로 P0 질문을 등록한 뒤 검증한다.**

- 미션에서 그 질문이 **자연스럽게** 나오는가 (공지문 말투면 FAIL)
- 아이가 `"그건 말하기 싫어"` 라고 하면 **다시 묻지 않는가**
- 반복 추궁하면 FAIL
```sql
SELECT * FROM parent_questions WHERE child_id='<child_id>' ORDER BY created_at DESC;
```
등록·소비 상태가 DB 에 정확히 반영되는지 함께 본다.
