# 배포 시간대 정책

- 제정: 2026-08-16 (Request 102 §5)
- 근거: 2026-08-14 Production 장애

## 규칙

**아이 사용 시간대에 Production 배포를 하지 않는다.**

```text
금지 시간대: 평일 16:00 ~ 21:30 KST
```

장애 대응 중이라도 마찬가지다. 고치려고 나가는 배포가 지금 쓰고 있는 아이의 화면을 다시 깨뜨린다.

예외는 대표 판단으로만 인정한다. 예외로 배포했다면 그 사실과 사유를 `requests/_log.md`에 남긴다.

## 왜 이 규칙이 생겼나

2026-08-14 20:08~20:55 KST, 아이가 앱을 쓰는 47분 동안 Production 배포가 3번 나갔다.

이미 로드된 클라이언트는 이전 배포의 청크 URL을 들고 있는데 그 URL이 사라지면서 동적 import가 실패했다. 결과:

- 자유대화: "케이가 이야기를 준비하고 있어요..."에서 영구 정지 (turn_count 0)
- 미션: "케이랑 접속이 끊겼네?"에서 영구 정지 (미션 세션 미생성)

서비스워커가 `/_next/static/`을 캐시 우선으로 서빙하면서 옛 청크가 캐시에 남고 새 청크만 404가 났기 때문에, 아이가 앱을 껐다 켜도 복구되지 않았다.

## 코드 쪽 대응은 별개다

Request 102에서 다음을 반영했다. 그래도 위 시간대 규칙은 유지한다 — 코드 대응은 피해를 줄일 뿐 없애지 못한다.

- `/_next/static/`을 네트워크 우선 + 캐시 폴백으로 전환
- 배포 식별자를 CLI 배포에서도 실제 값으로 주입
- 자동 복구 시 새로고침 직전 keepalive 비콘 기록
- 서비스워커 통지에서 `clientId`가 빈 경우 window 클라이언트 전체 폴백

## Vercel Skew Protection은 켜지 않는다

프로젝트 `k-bestie-v3`의 `skewProtectionMaxAge`는 현재 미설정이며, 그대로 둔다.

켜면 요청이 자기 배포로 고정되는데, 이 앱은 `/api/client-version`과 `/sw.js`로 클라이언트 버전을 스스로 관리한다. 두 경로까지 옛 배포로 고정되면 **클라이언트가 옛 빌드에 영구히 갇힌다.** Request 078(PWA 안전 업데이트)의 업데이트 감지와 정면으로 충돌한다.

켜려면 Dev에서 078 업데이트 흐름과 함께 검증한 뒤 별도로 판단한다.
