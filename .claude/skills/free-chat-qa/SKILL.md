# free-chat-qa

자유대화가 **아이 입장에서** 제대로 동작하는지 검증한다.
API 200 이나 "코드상 맞아 보임"은 근거가 아니다.

**시작 전에 `.claude/skills/_qa-common.md` 를 반드시 읽는다.**
환경·계정·실측 스키마·금지사항·보고 형식이 거기 있다.

## 이 QA 가 잡아야 하는 것 (2026-08-17 실제 사고)

```
아이: "나도 반가워"                     → 케이: "두 번 말할 정도로 반가웠나 봐"
아이: "안녕" ×4                         → 케이: (침묵)
아이: "도대체 인사 받는 게 왜 이렇게 힘드니"
아이: "반가워"                          → 케이: "언제 개학하는지 알려주면..."
```
전부 **DB만 보거나 코드만 봐서는 안 잡히는** 유형이다.

---

## 준비

1. Dev 배포가 최신인지 확인한다. 구버전 화면이 섞이면 판정이 흐려진다.
   ```bash
   git -C .worktrees/prod log --oneline -1     # 프로덕션 기준
   git log --oneline -1                        # 현재 코드
   ```
2. `QA_Child_A` 로 Dev 자유대화에 들어간다. **브라우저를 새로고침**하고 시작한다.
3. 시작 직전 세션 id 와 기준 시각을 기록한다.

Playwright 를 쓰면 `docs/ops/playwright-setup.md` 를 따른다. 음성 UI 면 **키보드 입력 모드**를 쓴다.

## QA-1. 인사 연속 (응답 유실)

**"안녕"을 연속 4번** 입력한다. 각 입력 사이 5초 이상 기다린다.

- 케이가 **매번** 답하는가? 한 번이라도 침묵하면 **FAIL**
- 4번의 응답이 **서로 다른 문구**인가? 똑같으면 FAIL (캐시 재생 의심)
- DB 로 확인:
  ```sql
  SELECT role, left(content,40), created_at FROM chat_messages
  WHERE session_id='<세션id>' AND deleted_at IS NULL ORDER BY created_at;
  ```
  아이 4건 / 케이 4건이어야 한다.

> 이 항목이 오늘 사고의 핵심이다. 서버는 200 을 돌려주는데 저장이 안 되거나
> 클라이언트가 버려서 아이가 침묵을 겪었다.

## QA-2. 맥락 중복

"안녕 케이야" → "나도 반가워" 순서로 말한다.

- 케이가 **"두 번 말했네"** 류로 반응하면 **FAIL**
- DB 에는 중복이 없어도 FAIL 이다. 프롬프트 맥락 중복이다.

## QA-3. 5턴 연속 대화 + 문맥 참조

의미상 아래를 충족하는 5턴을 진행한다. 문구는 자유롭게 정해도 된다.

1. 오늘 있었던 일 (예: "오늘 학원에서 발표했어")
2. 친구 이야기 추가 (예: "민준이랑 같이 했어")
3. 감정 표현 (예: "좀 떨렸어")
4. 구체적 사건 추가 (예: "근데 선생님이 잘했대")
5. **앞 내용 되묻기** — "아까 내가 누구랑 같이 했다고 했지?"

확인:
- 5번에서 케이가 **"민준이"를 정확히** 답하는가
- 아이가 말하지 않은 사실을 지어내지 않는가
- 엉뚱한 주제로 전환하지 않는가
- 훈계·장황한 설명이 없는가
- 다른 아이 정보가 섞이지 않는가

## QA-4. 규칙 분기가 대화를 가로채는가

첫 턴에 **"반가워"** 만 입력한다.

- 케이가 **인사에 답하는가?**
- **개학일·방학 질문이 단독으로 나오면 FAIL** — 아이가 방학 얘기를 꺼내지 않았다
- 그 외 뜬금없는 규칙 응답(공지·안내문 같은 말투)이 나와도 FAIL

이어서 **"방학이라서 학교 안 갔어"** 를 입력한다.
- 이때는 개학을 물어도 **정상**이다. 아이가 먼저 말했기 때문이다.

## QA-5. 게임으로 잘못 새는가

게임과 무관한 말을 한다. 예: "오늘 급식 맛있었어", "심심하다"

- 초성 문제(`ㄱㅊ` 같은 자음)나 끝말잇기 단어가 나오면 **FAIL**
- 게임 세션이 생겼는지 확인:
  ```sql
  SELECT count(*) FROM chosung_game_sessions
  WHERE child_id='<child_id>' AND started_at > '<시작시각>';
  ```
  **"심심하다"에 케이가 놀이를 제안하는 것은 정상**이다. 다만 제안일 뿐
  실제 게임을 시작하면(세션 생성 + 문제 출제) FAIL 이다.

## QA-6. 못 알아들었을 때

`ㅇ`, `...`, `ㅁ` 처럼 알아듣기 어려운 입력을 **연속 3번** 한다.

- 케이가 다시 말해달라고 하는가
- **3번의 문구가 서로 다른가?** 똑같은 문장 반복이면 FAIL
- 각각 응답이 저장됐는가

## QA-7. 저장 검증 (공통 검사 실행)

`_qa-common.md` §5 의 쿼리를 전부 돌린다.

- 5-1 응답 유실: `gap_sec >= 8` 인 건이 있으면 FAIL
- 5-2 turn_id 충돌: 0 이어야 함. 케이 응답 수가 아이 발화 수보다 크게 적으면 FAIL
- 저장 순서가 실제 대화 순서와 일치하는가
- `role` 구분이 정확한가
- 삭제되지 않았는가 (`deleted_at IS NULL`)

Vercel 로그에서 **버려진 저장**도 확인한다:
```bash
cd .worktrees/prod && npx vercel logs app.k-bestie.com --json | grep "SKIPPED by duplicate"
```

## 판정

`_qa-common.md` §4 의 4-Layer 로 판정하고 §7 형식으로 보고한다.

| Layer | 이 QA 에서 |
|---|---|
| Routing | 자유대화 경로로 처리됐나. 게임으로 새지 않았나 (QA-5) |
| Conversation | 문맥 유지·중복 없음·규칙 분기 미가로챔 (QA-2·3·4) |
| State | 세션이 유지되고 앞 대화를 참조하나 (QA-3) |
| Persistence | 유실·중복·순서 (QA-1·7) |

**하나라도 FAIL 이면 전체 FAIL 이다.**

## 회귀 항목 (매번 포함)

- 아이 발화 뒤 케이 응답이 **반드시** 있는가 (침묵 0건)
- 케이가 같은 문구를 연속 반복하지 않는가
- 인사에 규칙 응답이 끼어들지 않는가
- 케이가 아이 말을 두 번 들은 것처럼 반응하지 않는가

## 하지 않는 것

- 발견한 문제를 **고치지 마라.** 보고만 한다.
- Production 쓰기·배포·커밋 금지.
- 케이 응답만 보고 PASS 하지 마라. DB 를 확인한다.
