# chosung-game-qa

초성게임이 **실제 Skill 로** 동작하는지, 힌트 단계가 끝까지 정상인지 검증한다.

**시작 전에 `.claude/skills/_qa-common.md` 를 반드시 읽는다.**

## 이 QA 가 잡아야 하는 것 (2026-08-17 실제 사고)

```
아이: "그럼 초성 게임 하자"
케이: "먼저 'ㄱㅊ'로 시작해볼까?"        ← 세션 없음. 지어냄
케이: "틀렸어! 부드럽고 친근한 단어야"
케이: "학교에서 쓸 수 있는 말, 세 글자야!"  ← 아까 2글자였는데 3글자로 바뀜
케이: "이번엔 ㅂㄷㅁㅌ로 다시 갈게"        ← 멋대로 문제 교체
케이: "정답은 '바다마을'이었어"            ← 실제 정답은 '배드민턴'
```
아이가 항의했다: **"비읍 디귿 미음 T 옷이 바다마을이니"**

**케이는 게임하는 척을 한다. 판정은 반드시 DB 세션 행으로 한다.**

## 준비

1. Dev 배포 최신 확인. **브라우저 새로고침** 후 시작.
2. `QA_Child_A` 사용. 시작 시각·세션 id 기록.
3. 진행 중인 게임이 없는지 확인:
   ```sql
   SELECT id, state FROM chosung_game_sessions
   WHERE child_id='<child_id>' AND ended_at IS NULL;
   ```

## QA-1. Skill Routing (가장 중요)

**"초성게임 하자"** 라고 말한다.

DB 로 판정한다:
```sql
SELECT id, state, current_word, current_chosung, current_category,
       current_difficulty, hint_level, started_at
FROM chosung_game_sessions
WHERE child_id='<child_id>' AND started_at > '<시작시각>'
ORDER BY started_at DESC LIMIT 1;
```

- **세션 행이 없으면 FAIL.** 케이가 초성을 냈어도 FAIL 이다 (가짜 게임)
- 케이가 말한 초성 = `current_chosung` 인가? 다르면 FAIL
- **`current_chosung` 이 `current_word` 의 초성과 실제로 일치하는가?**
  예: `current_word='배드민턴'` → 초성 `ㅂㄷㅁㅌ` (직접 분해해 확인)
- `hint_level` 이 0 인가
- **정답(`current_word`)이 케이 응답에 노출되지 않았는가** — 노출되면 FAIL

## QA-2. 힌트 전체 흐름 (필수 — 한 문제로 끝까지)

아래를 **한 문제에 대해** 순서대로 수행한다. 중간에 문제가 바뀌면 FAIL 이다.

### 2-1. 첫 오답
일부러 틀린 답을 낸다.

- 정답을 바로 공개하지 않는가 (공개하면 FAIL)
- 힌트 1 이 나오는가
- `hint_level` 이 **1로 증가**했는가
- `current_word` 가 **그대로**인가 (바뀌면 FAIL)

### 2-2. 두 번째 오답
또 틀린 답을 낸다.

- 힌트 2 가 나오는가
- **힌트 1 과 내용이 다른가** (같은 말 반복이면 FAIL)
- `hint_level` = 2
- `current_word` 유지

### 2-3. 세 번째 오답
또 틀린 답을 낸다.

- 힌트 3 이 나오는가
- `hint_level` = 3
- `current_word` 유지
- **글자 수를 말한다면 실제 정답 글자 수와 맞는가** (오늘 2→3 글자로 바뀐 사고 있었음)

### 2-4. 정답
DB 에서 확인한 **실제 `current_word`** 를 입력한다.

- 정답 처리되는가
- 축하·인정 응답이 나오는가
- 세션 상태가 어떻게 되는가 (`state`, `hint_level` 초기화, `recent_words` 누적)

### 2-5. 다음 문제
다음 문제로 넘어가는지 확인한다.

- 새 `current_word` / `current_chosung` 이 나오는가
- `hint_level` 이 0 으로 초기화됐는가
- `recent_words` 에 이전 정답이 들어갔는가 (같은 단어 재출제 방지)

## QA-3. 케이가 값을 바꾸는가 (오늘 사고 핵심)

전 과정에서 **매 턴마다** 확인한다.

- 케이가 말한 초성 ≠ `current_chosung` → **FAIL**
- 케이가 말한 정답 ≠ `current_word` → **FAIL**
- 케이가 문제를 임의로 교체 → **FAIL**
- 힌트에서 말한 글자 수 ≠ 실제 정답 글자 수 → **FAIL**

매 턴 DB 를 조회해 케이 응답과 대조하라. **케이 말만 보고 넘어가지 마라.**

### 3-1. 한 문제로는 못 잡는다 — 최소 3문제 연속 (2026-08-18 프로덕션 사고)

안서아 계정에서 케이가 **문제 네 개를 통째로 지어냈다.** DB 는 내내
`current_word = 놀이터`, `current_chosung = ㄴㅇㅌ` 였는데 아이가 받은 문제는
ㅅㅇㅍ(색연필) → ㅂㅂㅂ(비빔밥) → ㅂㄷㄱㅇ(보드게임) → ㅊㅅ(체스) 였다.
**DB 값은 한 번도 안 나왔다.** 아이가 "이상하게 게임하고 제대로 않하니까" 라고 했다.

첫 문제만 확인하고 끝내면 이걸 못 본다. 어긋남은 **문제가 넘어갈 때** 커진다.

- **정답을 맞혀 다음 문제로 넘어가는 것을 최소 3회 반복하라.**
- 매 문제마다 케이가 말한 초성과 `current_chosung` 을 **나란히 적어 보고하라.**
  "일치함" 이라고만 쓰지 말고 두 값을 그대로 남긴다.
- 정답 공개 직후 새 문제를 낼 때도 같은 대조를 하라. 그 턴이 가장 잘 어긋난다.

## QA-4. 힌트 요청

"힌트 줘", "모르겠어" 라고 말한다.

- 힌트가 나오는가
- `hint_level` 이 증가하는가
- 정답이 그대로 노출되지 않는가

### 4-1. 문제 반복은 힌트가 아니다 (2026-08-18 실측)

출력 검증이 과하게 걸리면 케이의 진짜 힌트가 통째로 대체 문구로 바뀐다.
실제로 이런 응답이 나왔고, "힌트가 나오는가" 만 보던 QA 가 **PASS 로 통과시켰다**:

```
아이   힌트 좀 알려줘
케이   자, 다시 낼게! 초성은 'ㅃㄹㄹ' 이야. 뭘까?      ← 힌트가 아니다
```

힌트로 인정하는 것은 **정답에 대한 새 정보**뿐이다 — 뜻·범주·글자 수·쓰임새.
초성을 다시 읽어주거나 문제를 다시 내는 것은 **FAIL** 이다.

정상 예:
```
케이   물속에서 첨벙첨벙 헤엄치면서 하는 신나는 스포츠야! 두 글자 단어지~
```

### 4-2. "힌트 좀 알려줘" 는 힌트다, 답이 아니다 (2026-08-18 실측)

답 공개 신호("답이 뭐야", "정답 알려줘")를 힌트와 분리하는 과정에서 `알려줘` 가
공개 쪽으로 붙어, **"힌트 좀 알려줘" 가 정답을 스포일러**했다.

두 발화를 **반드시 각각** 시험하라.

| 발화 | 기대 |
|---|---|
| `"힌트 좀 알려줘"` | 힌트. 정답이 나오면 **FAIL** |
| `"힌트 알려줘"` | 힌트. 정답이 나오면 **FAIL** |
| `"답이 뭐야"` | 정답 공개. 힌트만 또 주면 **FAIL** |
| `"정답 알려줘"` | 정답 공개 |
| `"모르겠어"` | 힌트 (답을 달라는 말이 아니다) |

## QA-5. 종료와 복귀

**"그만할래"** 라고 말한다.

- `state` 가 `ENDED` 가 되는가
- 일반 대화로 돌아오는가
- **종료 후 케이가 초성을 내면 FAIL**
- 일반 대화 2턴이 정상인가

## QA-6. 저장 검증

`_qa-common.md` §5 공통 검사를 전부 돌린다. 추가로:

- **케이 응답 수 ≈ 아이 발화 수** 인가 (적으면 저장이 버려진 것)
- 게임 중 대화가 순서대로 남았는가
- 동시 활성 게임이 둘 이상은 아닌가 (초성·끝말잇기 합산)

## 판정

`_qa-common.md` §4·§7 을 따른다.

| Layer | 이 QA 에서 |
|---|---|
| Routing | 세션 행 존재 + 케이 초성 = `current_chosung` (QA-1) |
| Conversation | 힌트가 단계마다 다르고 정답을 미리 흘리지 않음 (QA-2) |
| State | `hint_level` 증가·`current_word` 유지·정답 후 초기화 (QA-2·3) |
| Persistence | 유실·중복·동시 활성 (QA-6) |

## 회귀 항목 (매번 포함)

- **케이가 말한 초성·정답이 DB 값과 일치하는가** (2026-08-17 "바다마을" 사고)
- **문제 3개를 연속으로 넘겨도 계속 일치하는가** (2026-08-18 안서아 사고 — 네 문제 날조)
- **힌트가 진짜 힌트인가** — 문제를 다시 읽어주면 FAIL (2026-08-18)
- **"힌트 좀 알려줘" 가 정답을 스포일러하지 않는가** (2026-08-18)
- **"답이 뭐야" 가 한 번에 정답을 알려주는가** — 힌트만 또 주면 FAIL (2026-08-18)
- 힌트 단계마다 `hint_level` 이 오르는가
- 문제가 중간에 바뀌지 않는가
- 힌트에서 말한 글자 수가 정답과 맞는가
- 세션 없이 초성을 내지 않는가
- 케이 응답이 아이 발화마다 반드시 있는가

## 하지 않는 것

- 문제를 **고치지 마라.** 보고만 한다.
- 단어 풀·난이도 로직을 수정하지 마라.
- Production 쓰기·배포·커밋 금지.
- **케이 말을 근거로 PASS 하지 마라.** 세션 행으로 판정한다.

## 초성 생성은 코드가 한다 (009 반영)

초성은 **반드시 결정론 코드**가 만든다. Gemini 에게 "보드게임 초성 만들어줘" 라고 시키지 않는다.
한글 음절은 초성(L)+중성(V)+종성(T) 구조라 추측 없이 추출된다.

Question Bank 전체에 대해 자동 검산한다.
```text
stored chosung == deterministically generated chosung
```
픽스처: `보드게임 → ㅂㄷㄱㅇ`, `도서관 → ㄷㅅㄱ`, `코끼리 → ㅋㅋㄹ`

## 문제 Source of Truth
각 문제에 `question_id / answer / accepted_aliases / chosung / difficulty / grade range /
category / hint_1 / hint_2` 가 있어야 한다.
**현재 문제를 대화 이력에서 기억하면 FAIL.** DB 가 유일한 출처다.

## 중복 출제 QA
```text
한 Game Session → 동일 question_id 재출제 0
```
문제는 아이가 맞힌 뒤가 아니라 **아이에게 제시되는 시점부터** 사용 처리(`PRESENTED`)한다.
따라서 "문제 출제 → Topic Shift" 가 나도 같은 세션에서 바로 다시 나오면 안 된다.
Cross-Session 정책은 Skill config 를 읽어 검증한다. **QA 가 30일/60일 같은 값을 만들지 마라.**
정책이 없으면 "Cross-Session 반복 정책 없음" 을 Risk 로 보고한다.

실측 사고: 새 세션이 직전 세션 낱말을 다시 냈다(세션 내 `recent_words` 만 보고 이전 세션을 안 봤다).

## 정답 인식 QA (전부 정답이어야 함)
```text
보드게임 / 보드 게임 / 보드게임이야 / 정답은 보드게임
내가 보드게임이라고 했잖아 / 그러니까 보드게임 이라고
```
실측 사고: `그러니까 도서관 이라고` 가 오답 처리돼 세션이 전진하지 못했다
(답변 시도 판정이 "띄어쓰기 없는 한 낱말"만 통과시켰다).

## Hint 순서 QA
```text
문제 → 아이 생각 → 틀림 또는 Hint 요청 → Hint 1 → Hint 2 → Answer
```
**문제 출제와 동시에 강한 힌트를 흘리면 품질 FAIL.**
실측 사고: `ㅋㄲㄹ` 와 함께 "긴 코가 특징이야" 를 같이 말했다.

## 난이도 리듬 QA
학년 → difficulty baseline → adaptive 를 확인한다.
너무 쉬운 문제만 / 너무 어려운 문제만 / 동일 category 연속 / 긴 단어만 연속 을 분석한다.
아이가 3연속 못 맞히면(STRUGGLING) 조금 쉬워지는지, 계속 맞히면 올라가는지 **흐름**을 기록한다.

Hint 순서 오류 0 / Stop 무시 0.
