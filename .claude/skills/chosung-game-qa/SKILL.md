# chosung-game-qa

초성게임이 **실제 Skill 로** 동작하는지, 힌트 단계가 끝까지 정상인지 검증한다.

**시작 전에 `.claude/skills/_qa-common.md` 를 반드시 읽는다.**

## 이 QA 가 잡아야 하는 것 (2026-08-17 실제 사고)

```
아이: "그럼 초성 게임 하자"
케이: "먼저 'ㄱㅊ'로 시작해볼까?"        ← 세션 없음. 지어냄
케이: "틀렸어! 부드럽고 친근한 단어야"
케이: "학교에서 쓸 수 있는 말, 세 글자야!"  ← 아까 2글자였는데 3글자로 바뀜
케이: "이번엔 ㅂㄷㅁㅌ로 다시 갈게"        ← 멋대로 문제 교체
케이: "정답은 '바다마을'이었어"            ← 실제 정답은 '배드민턴'
```
아이가 항의했다: **"비읍 디귿 미음 T 옷이 바다마을이니"**

**케이는 게임하는 척을 한다. 판정은 반드시 DB 세션 행으로 한다.**

## 준비

1. Dev 배포 최신 확인. **브라우저 새로고침** 후 시작.
2. `QA_Child_A` 사용. 시작 시각·세션 id 기록.
3. 진행 중인 게임이 없는지 확인:
   ```sql
   SELECT id, state FROM chosung_game_sessions
   WHERE child_id='<child_id>' AND ended_at IS NULL;
   ```

## QA-1. Skill Routing (가장 중요)

**"초성게임 하자"** 라고 말한다.

DB 로 판정한다:
```sql
SELECT id, state, current_word, current_chosung, current_category,
       current_difficulty, hint_level, started_at
FROM chosung_game_sessions
WHERE child_id='<child_id>' AND started_at > '<시작시각>'
ORDER BY started_at DESC LIMIT 1;
```

- **세션 행이 없으면 FAIL.** 케이가 초성을 냈어도 FAIL 이다 (가짜 게임)
- 케이가 말한 초성 = `current_chosung` 인가? 다르면 FAIL
- **`current_chosung` 이 `current_word` 의 초성과 실제로 일치하는가?**
  예: `current_word='배드민턴'` → 초성 `ㅂㄷㅁㅌ` (직접 분해해 확인)
- `hint_level` 이 0 인가
- **정답(`current_word`)이 케이 응답에 노출되지 않았는가** — 노출되면 FAIL

## QA-2. 힌트 전체 흐름 (필수 — 한 문제로 끝까지)

아래를 **한 문제에 대해** 순서대로 수행한다. 중간에 문제가 바뀌면 FAIL 이다.

### 2-1. 첫 오답
일부러 틀린 답을 낸다.

- 정답을 바로 공개하지 않는가 (공개하면 FAIL)
- 힌트 1 이 나오는가
- `hint_level` 이 **1로 증가**했는가
- `current_word` 가 **그대로**인가 (바뀌면 FAIL)

### 2-2. 두 번째 오답
또 틀린 답을 낸다.

- 힌트 2 가 나오는가
- **힌트 1 과 내용이 다른가** (같은 말 반복이면 FAIL)
- `hint_level` = 2
- `current_word` 유지

### 2-3. 세 번째 오답
또 틀린 답을 낸다.

- 힌트 3 이 나오는가
- `hint_level` = 3
- `current_word` 유지
- **글자 수를 말한다면 실제 정답 글자 수와 맞는가** (오늘 2→3 글자로 바뀐 사고 있었음)

### 2-4. 정답
DB 에서 확인한 **실제 `current_word`** 를 입력한다.

- 정답 처리되는가
- 축하·인정 응답이 나오는가
- 세션 상태가 어떻게 되는가 (`state`, `hint_level` 초기화, `recent_words` 누적)

### 2-5. 다음 문제
다음 문제로 넘어가는지 확인한다.

- 새 `current_word` / `current_chosung` 이 나오는가
- `hint_level` 이 0 으로 초기화됐는가
- `recent_words` 에 이전 정답이 들어갔는가 (같은 단어 재출제 방지)

## QA-3. 케이가 값을 바꾸는가 (오늘 사고 핵심)

전 과정에서 **매 턴마다** 확인한다.

- 케이가 말한 초성 ≠ `current_chosung` → **FAIL**
- 케이가 말한 정답 ≠ `current_word` → **FAIL**
- 케이가 문제를 임의로 교체 → **FAIL**
- 힌트에서 말한 글자 수 ≠ 실제 정답 글자 수 → **FAIL**

매 턴 DB 를 조회해 케이 응답과 대조하라. **케이 말만 보고 넘어가지 마라.**

## QA-4. 힌트 요청

"힌트 줘", "모르겠어" 라고 말한다.

- 힌트가 나오는가
- `hint_level` 이 증가하는가
- 정답이 그대로 노출되지 않는가

## QA-5. 종료와 복귀

**"그만할래"** 라고 말한다.

- `state` 가 `ENDED` 가 되는가
- 일반 대화로 돌아오는가
- **종료 후 케이가 초성을 내면 FAIL**
- 일반 대화 2턴이 정상인가

## QA-6. 저장 검증

`_qa-common.md` §5 공통 검사를 전부 돌린다. 추가로:

- **케이 응답 수 ≈ 아이 발화 수** 인가 (적으면 저장이 버려진 것)
- 게임 중 대화가 순서대로 남았는가
- 동시 활성 게임이 둘 이상은 아닌가 (초성·끝말잇기 합산)

## 판정

`_qa-common.md` §4·§7 을 따른다.

| Layer | 이 QA 에서 |
|---|---|
| Routing | 세션 행 존재 + 케이 초성 = `current_chosung` (QA-1) |
| Conversation | 힌트가 단계마다 다르고 정답을 미리 흘리지 않음 (QA-2) |
| State | `hint_level` 증가·`current_word` 유지·정답 후 초기화 (QA-2·3) |
| Persistence | 유실·중복·동시 활성 (QA-6) |

## 회귀 항목 (매번 포함)

- **케이가 말한 초성·정답이 DB 값과 일치하는가** (오늘 "바다마을" 사고)
- 힌트 단계마다 `hint_level` 이 오르는가
- 문제가 중간에 바뀌지 않는가
- 힌트에서 말한 글자 수가 정답과 맞는가
- 세션 없이 초성을 내지 않는가
- 케이 응답이 아이 발화마다 반드시 있는가

## 하지 않는 것

- 문제를 **고치지 마라.** 보고만 한다.
- 단어 풀·난이도 로직을 수정하지 마라.
- Production 쓰기·배포·커밋 금지.
- **케이 말을 근거로 PASS 하지 마라.** 세션 행으로 판정한다.
