# 음성 미션 테스트 매트릭스 (상세)

`k-bestie-voice-mission-qa` 스킬의 상세 참고 문서. 핵심 정책은
`../SKILL.md`를 먼저 읽는다.

## 턴별 입력 유형 매트릭스

최소 다음 입력 유형을 각각 검증한다.

| 유형 | 예시 | 유효 답변 | 기대 처리 |
|---|---|---:|---|
| 정상적인 관련 답변 | 질문에 구체적으로 답함 | 예 | 관련 반응, 10% 증가, 다음 질문 |
| 짧은 관련 답변 | 응, 좋아, 친구랑 놀았어 | 예 | 관련 반응, 10% 증가, 다음 질문 |
| 애매하지만 관련된 답변 | 그냥 그랬어 | 예 | 유효 처리, 10% 증가, 다음 질문 |
| 완전히 엉뚱한 답변 | 질문과 무관한 주제 | 아니요 | 1회 재질문 후 다음 문항 |
| 명시적 거부 | 말하기 싫어 | 아니요 | 1회 재질문 후 다음 문항 |
| 침묵·무응답 | 발화 없음 | 아니요 | 1회 재시도 후 다음 문항 |
| 인식 불가능 | 의미를 파악할 수 없음 | 아니요 | 1회 재질문 후 다음 문항 |

각 턴에서 확인할 항목:

- 아이 발화가 한 번만 제출됐는가(중복 제출 없음)
- STT 결과가 실제 발화와 일치하는가
- 유효·무효 분류가 정책과 일치하는가
- 케이 반응이 아이 답변 내용과 관련 있는가
- 진행률이 정확히 증가하거나 유지되는가
- 같은 질문을 두 번 넘게 재질문하지 않는가
- 다음 질문이 중복되지 않는가
- 질문 순서가 정책대로 유지되는가

## 질문 풀 검증

신규 미션 시작 시 확인:

```text
기본 질문 10개
예비 질문 10개
총 20개
```

- 기본 질문 10개 존재
- 예비 질문 10개 존재
- 동일 질문 중복 없음
- 세션에 질문 순서 저장
- 이어하기에서 기존 질문 순서 유지
- 앱 재접속 시 질문 풀이 사라지지 않음
- 9/10 상태에서도 다음 질문 존재
- 질문 부족을 연결 장애로 표시하지 않음

> 참고: 이 프로젝트의 실제 문항 데이터는 학년별로 13~17개뿐인 경우가
> 있어(2026-07-24 실측, `requests/_done/004-mission-reserve-live-e2e.md` 참고,
> 이후 콘텐츠 갭 해소됨) "기본10+예비10=20개"가 콘텐츠 부족으로 항상 보장되지
> 않을 수 있다. 이 경우 코드 결함이 아니라 콘텐츠 문제이므로 `BLOCKED`로
> 기록하고 실제 배정된 개수를 그대로 보고한다 — 억지로 20개를 만들어내라고
> 요구하지 않는다.
>
> **⚠️ 정적 사실과 동적 결과 혼동 금지(2026-07-25 v2 추가)**: 세션 시작 시
> `selected_order` 1~10은 항상 `question_role='PRIMARY'`로 고정 배정되고
> 11~20은 항상 `'RESERVE'`로 고정 배정된다 — 이건 **세션 생성 시점에 이미
> 정해지는 정적 사실**이라, 답변 처리(거부/무응답 재도전)를 단 한 번도 하지
> 않아도 항상 참이다. `selected_order===3`이 `PRIMARY`인 것을 확인했다고
> "예비 문항이 승격됐다"고 결론 내리지 않는다 — 실제 승격 여부는 반드시 그
> 문항의 `question_id`가 애초의 RESERVE 문항 중 하나로 **교체**됐는지, 또는
> RESERVE 전용 필드/이력으로 확인해야 한다. 과거 QA(`tests/qa-reserve-e2e.mjs`)가
> 바로 이 착시로 잘못된 PASS를 보고한 전례가 있다.

## 질문 순환 E2E 시나리오

### 시나리오 A — 기본 질문만으로 완료

- 기본 질문 10개에 모두 유효 답변
- 매 답변마다 10% 증가
- 10번째 답변 직후 완료

### 시나리오 B — 예비 질문 사용

- 기본 질문 일부를 거부하거나 무응답
- 기본 질문 종료 후 예비 질문으로 이동
- 유효 답변 10개가 되면 즉시 완료

### 시나리오 C — 미답변 문항 1차 순환

- 기본·예비 질문 20개 종료 시 유효 답변 10개 미만
- 미답변 문항만 추출
- 미답변 문항을 원래 순서대로 1회 재진행
- 이미 유효 답변을 받은 문항은 다시 질문하지 않음

### 시나리오 D — 최종 순환

- 1차 미답변 순환 후에도 유효 답변 10개 미만
- 확정된 최종 안내 문구 출력:
  `"더 이상 준비된 질문지가 없어서 미션을 완료할 수 없어요. 다시 한번
  질문을 진행할게요. 이번에도 답변 못하면 미션은 실패됩니다."`
- 남은 미답변 문항을 마지막으로 1회 진행
- 유효 답변 10개가 되면 완료
- 마지막에도 10개 미만이면 실패

### 시나리오 E — 이어하기

- 일부 질문 진행 후 앱 종료
- 같은 세션으로 재접속
- 유효 답변 수와 진행률 유지
- 사용한 질문·남은 질문 유지
- 현재 질문 또는 정확한 다음 질문부터 재개
- 첫 질문이나 0%로 초기화되지 않음
- 중복 차감(황금열쇠) 없음 확인

### 시나리오 F — 정상 답변 1회의 진행률 증가 (2026-07-25 v2 추가, 최우선 시나리오)

**목적**: 아이의 정상 답변 1회가 실제 진행률 증가로 이어지는지 확인한다.
이전 회귀 QA에서 케이의 응답 자체는 자연스럽고 API도 200을 반환했지만
`mission_question_history`/`mission_progress`가 전혀 갱신되지 않아 미션이
영원히 완료되지 않는 결함이 발견됐다 — 이 시나리오가 그 재발을 막는 핵심
게이트다. 반드시 완전히 새로운 세션(`resumed: false`로 서버 응답 확인)에서
검증한다(기존 세션이 우연히 남아 재사용되면 오판정으로 이어진다 — FK 제약이
있는 자식 테이블부터 순서대로 정리해야 세션 삭제가 실제로 성공한다).

검증 순서(4단계 전부 실제 증거로 확인):
1. 아이 행동: 질문 1개 표시 확인 → 정상 답변 제출 → (가능하면) STT 인식
   결과 확인
2. AI 처리: 케이의 정상 응답 생성·재생 확인
3. **서비스 상태(DB 직접 조회, 반드시 확인)**: 해당 문항의
   `mission_question_history.answer_classification`이 `VALID`로 기록되고
   `progress_awarded=true`인지, `mission_progress.valid_answer_count`가
   1 증가했는지, `updated_at`이 갱신됐는지
4. 화면: 진행률 게이지가 실제로 올라가는지, 다음 질문으로 이동하는지

이 시나리오가 `FAIL`이면 그 이후의 완료/RESERVE/재도전 시나리오는 전부
`BLOCKED`로 처리한다(진행률 자체가 안 오르면 그 위의 어떤 시나리오도 의미
있게 검증할 수 없다).

### 시나리오 G — 장애 상황(STT 실패/LLM timeout/TTS 실패/네트워크 지연)

- 각 장애 유형별 fallback 동작 확인
- 아이에게 "기억 상실", "서버 문제" 같은 아이가 이해하기 어렵거나 불안을
  유발하는 표현이 노출되지 않는지 확인(중립적이고 안심시키는 문구인지)
- 장애 후 세션·진행률이 보존되는지 확인
- 실제 장애를 인위적으로 재현하기 어려운 경우 코드 리뷰로 대체 가능하되,
  대체했다는 사실과 사유를 보고서에 명시한다(`BLOCKED`로 표기, 코드 검토만
  했다는 이유로 `PASS` 처리 금지)

## 케이 반응 검증

유효 답변을 받으면 케이는 다음 순서로 말한다:
1. 아이가 말한 내용에 맞는 짧고 자연스러운 반응
2. 다음 고정 질문 1개

금지 사항:
- 아이 답변과 관련 없는 상투적 반응만 출력
- 다음 질문을 두 개 이상 출력
- 이미 답한 질문 반복
- 아이가 답했는데 답하지 않은 것으로 처리
- 아이 답변을 임의로 왜곡
- 진행률 증가 전에 다음 질문으로 넘어가 데이터 저장 누락

유효하지 않은 답변에서는 아이를 혼내거나 압박하지 않는다.

## 상태 표시 상세 검증 항목

- 상태 순서가 뒤바뀌지 않음
- 상태가 영구 고정되지 않음
- 실제 처리보다 먼저 다음 상태를 표시하지 않음
- 실패 후에도 잘못된 상태가 남지 않음
- 다음 턴에서 다시 "듣고 있어요"로 복귀

## 부분 검증 방지

필수 시나리오 일부를 실행하지 못한 경우:
- 전체 PASS 금지
- 미실행 항목을 `NOT TESTED` 또는 `BLOCKED`로 표시
